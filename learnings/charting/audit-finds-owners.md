# The pre-handoff audit finds the owners the resolutions never named

## What was not good

Thirty resolved decisions described the loop and nobody noticed that no leaf owned the export of AKROGON_BASE, the edit that adds the GitHub close to the merged transition, the creation of LESSONS.md, or the recording of the first slot's completion in a two-slot phase. Each decision was right on its own; the gaps were between them.

## What the updated way does

Before emission, one subagent per leaf reads only that leaf and the tree prior leaves left, and asks whether every criterion can be checked there with the tools that exist at that point. Then slot B reads all eight and asks four questions only: uncheckable criterion, claim with no owner, two owners for one file, ambiguity that builds two incompatible things. Every finding is fixed in the staging tree, never in the emitted files.

## Why

A decision file settles one question. Ownership is a property of the tree, and it only appears when someone reads the tree as an implementer would, one leaf at a time with nothing else.

## How it improves the process

Cross-leaf gaps are caught in one attended pass instead of at the kickoff of the leaf that hits them, where the fix would be a hand edit to a contract the loop is already running.
