# The map is redrawn after every answer

## What was not good

The territory map was shown at the opening and once more as a coverage pass, then left alone. Open Questions were reread only when memory prompted it. After # Next Command Owner removed the driver, four Questions still described a driver until the next session touched them.

## What the updated way does

After each resolution, slot A rereads every open Question against the answer: narrow, widen with a dated coverage line, or rule out. New forks become decisions. One dated line in the resolved decision's Findings records what moved.

## Why

Operator, 2026-09-08: "The point of the territory is that we know the final destination, but the path to that destination, which means decisions, can change dynamically based on the previously made decisions and closed decisions. That has to be a part of the whole process."

The operator asked whether the territory still updates as decisions are made. Each answer changes which questions are still real, and a stale Question gets grilled against a design that no longer exists.

## How it improves the process

The map is no longer a one-time document. It is the set of open Questions, re-derived on every resolution, so a batch is always built from the current design.
