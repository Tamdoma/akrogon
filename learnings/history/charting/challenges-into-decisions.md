# Operator challenges go into the decision file

## What was not good
After the chart was written, the operator challenged two settled-looking ideas in chat: read the handoff prose from the pane tail first, and whether a driver should exist at all. Chat is lost on clear. A challenge that lives only in chat gets re-argued next session or forgotten.

## What the updated way does
Every operator challenge and every slot A counter-view is appended to the matching decision's Findings the moment it is made, dated and attributed to operator or slot. The decision stays open. The next session reads the challenge as its first input.

## Why
The decision file is the only memory that survives a clear, and a challenge is evidence, not an answer.

## How it gets improved
If a challenge does not fit any decision, that is a new fork: create the file rather than parking the challenge in the chart notes.
