# src area

## Commands

- `bun src/akrogon.ts run-check -- <argv>...` runs a command under the constructed check environment, streaming its stdout and stderr into the holder's `capture-<name>-<run>-out.log`/`-err.log` from launch and announcing them with the early `capture <name>: <out> <err>` stderr line, the pair staying live while the wrapper or any descendant holding capture-out's stdout fd lives under one shared flock on that description and `abandonedCaptures(folder)` probing each pair's lock, refusing before start an argv equal to a configured `merge_checks` entry in its parsed words, `sh -c` text or printed form and naming `akrogon verify --attempt <id>` as the route, and `verify [--sha <rev>] [--known-red]` runs the caller's configured check set on a detached fresh checkout in the worktree store — non-`full` `checks` first in config order, then `full` checks, then `merge_checks` members at once in merge scope —; both box each command in a systemd `akrogon-run-<id>` scope, each verify pass runs in its own `akrogon-verify-<id>` service in `akrogon.slice` (surviving the caller's death) whose `run <id>` the caller prints before any check line — a repeat call joins the live pass matching caller scope, caller target, tree, verify scope, command set and `compares` — and `stop-run [<run-id>]` stops the caller's own live runs, cancels a waiting one, or stops a same-scope live pass whole; `run-check` and `verify` cut the session bus (`DBUS_SESSION_BUS_ADDRESS=unix:path=/nonexistent`).
- `bun src/akrogon.ts guard <ancestors|own-modules>` refuses a checkout under foreign `node_modules`/`package.json` or a worktree with a top-level `package.json` missing its own `node_modules`; composed check commands run `own-modules` while `ancestors` runs at worktree creation through `checkLocation`; `bun run typecheck` checks the TypeScript command and tests; `bun test tests/phase.test.ts` exercises lifecycle transitions and guards.
- `bun src/akrogon.ts close <owner/repo#n> --by <text>` closes one unowned GitHub issue; `bun src/akrogon.ts config` prints effective settings and the worktree base; `bun src/akrogon.ts log <path>` prints a recorded log's bytes from a plain file or the owner's `evidence.tar.zst`, resolving the path against the current or every registered repo; `bun src/akrogon.ts pack issues/closed/<owner>|issues/chart/<chart>...` folds that folder's `*.log` files into `evidence.tar.zst` under `.closing` and the owner `.lock`, waiting for the owner's live captures to finish and refusing `inside run-check run <uuid>` when the caller runs inside that owner's own capture, refusing a closed owner whose tracked logs changed or vanished on disk, and plain `status` lists folders still holding logs or `.closing` as `Unpacked:` lines.

## Key files

- `src/akrogon.ts` validates CLI arguments and dispatches commands; `src/install.ts` plans and applies `akrogon install` links: the binary, the slice, every `skills/<name>` into each agent root, plus the listener unit when the release ships one, pruning stale links into owned or release trees, including an old herdr-app mod link (the Tasks board) left in `~/.config/herdr-app/mods`; `src/self-update.ts`'s `deployStage` replays the same plan against the new release so a deploy refreshes every link, and `install` and `deployStage` share the service calls (`linkServices`, `restartListener`) and make no `herdr` call.
- `src/state-home.ts` moves the state home out of the tool root to `~/.akrogon` (or `AKROGON_HOME`) on the first command after deploy, gated on live run records and foreign processes and committed last via the rewritten `config.yaml`.
- `src/release.ts` owns the deploy filesystem: it builds a release (`git archive`, `tar`, `bun install`) into `releases/<sha>`, flips the `current` symlink atomically, and writes the deploy record, hold and prune state; `src/rollback.ts` runs `akrogon rollback` — flip to the recorded previous release, hold the rolled-away commit and restore links through `install()`, under the same install lock deployStage takes. `src/self-update.ts` pushes record commits and fast-forwards the workspace checkout, then deploys the remote tip for the akrogon repo: deploy builds releases behind `current`, re-links through it and records failures in `deploy.yaml`, all under the install lock.
- `src/preflight.ts` verifies the configured base remote branch and local tracking ref; `src/config.ts` defines config schemas, resolves registered repositories and merges per-repo seat overrides (`seats`). `src/init.ts` initializes repositories and refuses a declared index that is not a readable non-empty file; `src/readiness.ts` owns the readiness contract schema and gap computation.
- `src/phase.ts` aggregates slot completion and enforces handoff guards; `moveGuards` also refuses a leaf's non-failed move while `abandonedCaptures` finds a pair without a non-blank `cleared-<run>.md`, naming each pair's out and err paths and the file to write, with `failed` and recovery out of `failed` left open; `src/shell.ts` holds only process helpers: subprocesses, retries, quoting and YAML writes. `src/land.ts` runs `akrogon land <slug> --attempt <id>`, the command-run green merge `mergeTurn` launches as the user unit `akrogon-land-<attempt>` (given `XDG_RUNTIME_DIR`; the unit resolves the repo's hc space itself) after claiming the applied top (`batch.owner: command`): verify, `landGates`, `landPush` and a seat-free `merged` move that stores the completed owner in `state.broadcast`, which `broadcastPass` sends to B and `broadcastPending` keeps from cleanup; a red verify, gate refusal, failed push or rebase hands the attempt to B with `wake=`.
- `src/timing.ts` defines the timing-event schema and appends to `issues/timings.jsonl` (`readTimings` and `visitOf` feed the readout); `src/timing-report.ts` implements `akrogon timing`: per-visit time decomposition from `timings.jsonl` and `log.jsonl`, plus the 20-leaf cohort gate from `merge-attempts.jsonl` and the `--flow` leaf-carried issue report from per-repository GitHub `state=all` listings.
- `src/verify.ts` checks a commit out detached, runs every command for the caller's scope — non-`full` `checks` first in config order, then `full` checks, then `merge_checks` members at the same time once the `checks` stage is green —, logs each into the leaf or holder and records one receipt in `issues/verify-runs.jsonl`; a `full` check after a red setup or non-`full` check and every `merge_checks` member after a red `checks` entry are recorded `blocked` with the blocker's exit and log and never run, while a red `full` check never blocks a `full` check; each `runOnce` body executes in an `akrogon-verify-<id>` service launched by `passOnce`, which claims or joins a key under the receipt lock using `<globalHome>/verify-passes/<id>/` records (`src/verify-pass.ts`), streams the pass's `out`/`err` and returns its `status` file code — absent means failure — while `verifyPassCommand` runs the pass, tees output into the dir and writes `status`; `--known-red` reruns the head when no completed red head run under the expected command list exists, then runs the base at the head's merge-base with the tracked default branch — the base pass skipped and judged `fail` when the merge-base tree already holds a whole-green row — and links that base run from the head's receipt through `compares`; a completed base run holding a failing test on an unreused entry no unresolved incident covers writes one `main red` notice file inside the run's locked final rewrite, records `pending` or `error` in `notice` on the base record in that same write, folds `pending` to `shown` once the file is gone and retries on the next base run for an `error` or cleared incident — a `pending` row covers while its file exists, `shown` covers and `error` never covers; a completed merge-scope run also compares its wall time (`end − start`) with the median wall time of the last 20 eligible merge runs — completed, `setup` 0, no `compares`, no `reused` or `blocked` entry, checked only from 5 — and a run more than 1.5× that normal and at least 2 minutes over prints `verify slow: <ms>m measured vs <normal>m normal; first seen at <leaf> <run>` (`; accepted as new normal` on an accepted close), stores a `slow` record on its receipt and opens an episode that pins its pre-jump normal, writes one `<repo> merge slow` notice file per episode in the same locked rewrite, recording `slow.notice` `pending` or `error`, retried by the next in-episode run when the write failed, and closes `recovered` on an eligible run back under threshold or `accepted` once the last 20 eligible runs all lie inside it, `akrogon status` printing `Slow merge: <repo> first seen at <leaf> <run>, last <ms>m vs normal <normal>m` while one is open — leaf-scope runs are never checked and `compares` runs are neither checked nor counted; `requireGreenReceipt` is the one gate the `check.review` move, the `check.repair` move into `merge`, `merged --check` stamping and direct-guards call, accepting one completed run on the head tree whose commands all exit 0 under the caller's expected list — scope is never consulted — or one eligible head row holding at least one red entry whose every red entry's names also fail the same command on a linked base run — names read by `src/flaky.ts` from the lines Bun prints: a `(fail)` title, `(unnamed) <script>` or `(unnamed)` for a `(fail) (unnamed)` line, `(script) <script>` for a failed script's `Exited with code <n>` line with wrapper chains dropped, `(no test name)` when none appear, and `(log gone)` when no log can be read, each matching only itself on the base and a `(log gone)` log never covering — a `blocked` entry needs no cover and never covers on the base since it did not run, and a base entry with exit 0 never covers.
- `src/hc.ts` is the only module that calls herdr-core (`hc`, with `HC_SESSION` pinned and the inherited terminal variables removed) and herdr-app (`HERDR_APP_HOME` set): session discovery probes each `<name>.sock` before any call (an hc call on a dead socket starts a core), the repo's space is the herdr-app document space named after the repo (`repoSpace`, memoized), plus terminal list/run/send/kill/rm, event follows, seat names, the tab id; `src/notice.ts` owns the notice file contract: one `<app home>/akrogon-notices/<id>.json` (`{"title","body","attention"}`, id `<repo>.<kind>...`) in the herdr-app home of the session holding the repo's space, written under a temporary name and renamed, which herdr-setup's `session-status` bar shows as a toast (sound when `attention`) and deletes — present is `pending`, gone is `shown`, and `removeNotice` drops a stale one. `src/seat.ts` starts a seat (`akrogon seat`, dispatch) with its labels, scope and env and proves its first task started; `src/transcript.ts` resolves and labels the harness transcript and reads its records (`transcriptRecords`); `src/listen.ts` is `akrogon listen`, the user unit that follows every live session's `akrogon=1` terminals and runs one engine pass at a time.
- `src/admission.ts` registers each run's record under `<globalHome>/runs/`, sweeps stale records and their run units, and admits at once — a matching `AKROGON_RUN` token of a live run is the nested case that creates nothing; the memory reading and spacing were dropped 2026-10-14. The one bound: a run named in its repo's `full` list writes a `waiting` record and starts only as the oldest live `full` run of the same repo, in arrival order (a `full` run under a `full` holder of the same repo is nested and writes nothing; under any other run it takes its own turn); `stop-run` moves a waiting record to `cancelled` under the same lock pair, and the record states are `waiting`, `live`, `ended` and `cancelled`. `callerScope` resolves `AKROGON_SCOPE` first — a pass service carries its starting caller's scope under that name, keeping the pass's check records owned by the starting pane.
- `src/scope.ts` names the per-leaf slice (`leafSlice`, used by `src/stop.ts`) and `akrogon-run-<id>` run units, read through `AKROGON_PROC_ROOT` (default `/proc`) and `AKROGON_CGROUP_ROOT` (default `/sys/fs/cgroup`); a seat enters its own scope under the leaf slice through the `systemd-run --scope` in its argv. `src/stop-run.ts` stops the run units live records tie to the caller's scope, or the `akrogon-verify-<id>` service of a same-scope live pass. `src/stop.ts` keeps the host-local `stopped.yaml` record and runs `stop`/`start`; dispatch, the merge queue and status read it.
- `src/evidence.ts` maps a recorded log path to its bytes (`locate`, `readMember`, `readLog`, `readLogAcross`): plain file first, then the owner's `evidence.tar.zst`; `akrogon log` and `src/flaky.ts` read through it, and `src/flaky.ts` additionally reads a recorded path outside the `issues/` grammar as a plain file when it still exists on disk. `src/pack.ts` folds an owner folder's `*.log` tree (nested and dotfiles, symlinks refused) into `evidence.tar.zst`, merging with an existing archive, refusing differing bytes for a shared member and verifying each member through `locate`/`readMember` before the plain files unlink; `completeOwner` calls it under the `.closing` marker before the `issues/closed` move and `src/pack-command.ts` calls it as `akrogon pack` on a closed owner or chart `direct/`, after a git ls-files tracked-vs-index check for closed owners; `src/flock.ts` supplies the owner `.lock`, shared by every live capture's writers and publication and taken exclusively by `completeOwner` and `akrogon pack` so both wait for live captures, and each refuses `inside run-check run <uuid>` when the caller runs inside that owner's own capture.
- `src/reconcile.ts` removes dead worktrees, scratch, run roots and unowned store leftovers each pass — `verify-*`, `batch-*` and `<slug>-u<N>` store copies go by owner state (`batch-<id>.owner` record for batch copies), a locked `.claude/worktrees/agent-*` checkout goes when its `claude agent` lock owner is dead by the `/proc` field-22 check and `git cherry` shows every commit landed on the target with no merge in the range (branch deleted by `update-ref -d` bound to the proven head; unlock then non-force remove, re-locked while still registered — an unregistered leftover keeps only its recorded remove error), unregistered leaf-named and stray entries by leaf activity, all behind live-pane and surviving-process vetoes, with leaf temp kept as `unit list unavailable` when the unit list cannot be read — stops the loaded slice of any leaf whose recorded tab is proven gone (an unfinished leaf with no recorded tab keeps its own) and unmatched empty `akrogon-l*` slices, clears failed `akrogon-run-*` units, sweeps retired locks, tmp files, dead `verify-passes/` dirs past the drain window and the retired temp root in the host step, and writes the kept reports `status <slug>` prints as `Kept:` lines under the ignored `reconcile/` state dir and `reconcile-host.json` — the host report also carries retired filesystem leftovers `akrogon leftovers` lists under `host`.

## Non-obvious patterns

- Repository identity comes from registration and the shared Git directory.
- A phase move can be committed even when later log collection fails. Phase moves reject a dirty worktree and branch changes under `issues/`; a stop into `failed` skips both, a `cause: blocked` restart skips only the dirty check, and the empty-branch refusal applies only at review handoff.
- External command retries warn once, then preserve the last failure context.
- Foreign leaves are summarized once per repo and excluded from capacity and dispatch; a seat gets one prompt per idle turn: `prompted` records the hc turn a task went in at, a send that never starts is recorded and resettled once the turn moves, and a seat ending three turns without reporting fails its leaf.
- Capacity and reconcile keep-vetoes read live hc terminals: a leaf's tab is live while a live terminal carries its `herdr.tab` label, cwd vetoes use every live session's terminals, and an unreadable session blocks launches and terminal-dependent removals. A leaf whose state still records old herdr pane ids is refused at dispatch unless merged, done or closed.
- `verify`'s pass appends its receipt before checkout, then rewrites `verify-runs.jsonl` under the same lock with its setup exit, each command's exit and log and its end — a `compares` record with an uncovered red unit writes its notice file and records `notice` `pending` or `error` in that same locked write, and the write folds every `pending` row whose file is gone to `shown` — before removing the checkout; `end` is set only after every member settled, a base record names the head run it was made for in `compares`, and a receipt matches any commit with its tree under the caller's exact expected command set at any scope, so `verify` on such a commit prints `reuse receipt <run> tree=<tree>` and runs nothing.
- `akrogon config` composes a repo's `setup` key into every printed `checks` and `advisory` command as a `flock`ed `sh -c <setup> && sh -c <command>`; printed `merge_checks` entries are the literal `akrogon verify --attempt <id>`, the route `run-check` names when it refuses their argv.
- A leaf worktree's `.env` is a written file (mode 0600) holding only declared `env:` names copied from the registered checkout; dispatch rewrites it when no tab is live and refuses a tracked path or missing ignore rule.
- `buildStack` writes a `batch-<id>.owner` record in the store before its copy, rebases the holder onto the remote base and removes resurrected retired lesson lines as a fixup commit on the top, which `merged --check` refuses a pushed range still holding.
- The `plan.synthesis` to `implement` move records each branch-changed path's blob id in state `frozen`; a later move refuses a recorded path changed or gone, or an added test-file-matched path outside the record, until the last commit touching it or a later one carries a `Test-Change` trailer naming it, and a path no commit touches needs a later trailer-only commit new since the record, not a replayed planning-era trailer.
