# Design: base-preflight

## Binding decisions, verbatim
From issues/chart/execution-readiness/forks/git-base.md, Taken 2026-09-28, operator: "go with all recommendations" (1-A 2-A 3-A 4-A)
- Q1-A: refuse with remediation that names the case: C1 no configured remote (configure it or fix `remote`), C2 remote branch absent (operator makes and pushes a first commit), C3 branch on remote but tracking ref absent (`git fetch <remote> <branch>`). Network or auth failure is reported as unproven, never as "branch absent". Reason: bootstrap would choose commit content and push for the operator, and cannot fix C1 or C3. Foreclosed: automatic first commit and push (B).
- Q2-A: one rule, run before any handoff write and again at dispatch before `ensureWorktree`, for new and reused worktrees alike. Reason: dispatch-only lets leaves reach a repo that cannot run, the #20 case. Foreclosed: dispatch only (B).
- Q3-A: every dispatch verifies the local ref `refs/remotes/<remote>/<branch>^{commit}` with no network. The remote branch (`git ls-remote --exit-code <remote> refs/heads/<branch>`) is also required at handoff and when a new worktree is created, and is queried after a local failure to pick the remediation. Reason: `next` runs on hook events, and a network call there adds latency and turns an auth hiccup into a dispatch stop; the server branch matters only when a worktree is created. Foreclosed: remote on every allocation (B, slot B's position), local only everywhere (C).
- Q4-A: a new read-only `akrogon preflight` backed by the same function dispatch calls, working with zero leaves; the chart-issues handoff runs it before any write. Reason: one rule, and no existing verb runs with zero leaves without becoming a gate on inspection. Foreclosed: check inside `status` (B), git commands in skill prose (C).

Excluded: write-proof decisions (Q1-Q3 of forks/write-proof.md) belong to leaf operation-proof; this leaf teaches akrogon no service APIs.

/home/ivan/.claude/skills/chart-issues/assets/standing-design.md, interpreted: no new secrets; a runtime remote query uses the checkout's existing Git authentication, and an auth failure is reported as unproven. No vanity tests: every test drives real git in temporary repos (a bare remote for C2/C3, an unreachable URL for the transport case). Negative cases C1-C3 and the same-named local branch/tag are mandatory. The user-visible flow is the CLI: done-criteria 1 and 5 invoke `akrogon preflight` and `akrogon next` for real with real Git fixtures, and the verification command's output is retained outside tracked `issues/` paths with its path recorded in the implementation report.

## Leaf architecture
Owned: src/config.ts or a new src module for the check, src/akrogon.ts (`preflight` verb, usage line), src/next.ts (gate before `ensureWorktree`, with remote proof when creating a worktree or classifying a local-ref failure), README.md command table, tests for the above, skills/chart-issues/assets/shapes.md Preflight paragraph.
Interface: the `preflight` CLI resolves the authoritative registered root through `requireRepo` (src/config.ts:119-122) and refuses an unregistered caller without writes; the shared checks accept the resolved `Repo`, so dispatch does not re-resolve its cwd. The checks throw a specific error carrying the case, the git command, exit status and stderr. Two single-purpose functions (local ref, remote branch) rather than one function with a mode flag. Worktree creation (src/next.ts:255) and `AKROGON_BASE` (src/config.ts:128-131 via src/next.ts:311) consume the fully qualified tracking ref, not the abbreviated `target()` name, so a same-named local branch or tag can never be the start revision. Other `target()` callers (src/phase.ts, src/sync.ts) are unchanged.
Exclusions: no fetch, no commit, no push, no status change, no clock or poll. `akrogon sync` is unchanged.
Dependencies: none.
