# Brief: log-tail

## What
New `skills/watch-issues/scripts/log-tail.ts <path>`. It reads one claude, codex or pi session jsonl and prints its last 20 tool calls, oldest first, one line per outer tool call:
`<timestamp> <tool> <target> <identity> -> <status>: <excerpt>` (A,B)
- target, shell calls: claude `Bash` `input.command`; pi native `bash` `arguments.command`; codex and pi `exec` calls list every string-literal `cmd` passed to `tools.exec_command({cmd: ...})` in source order, joined with ` ; `, and show `<expr>` for a `cmd` that is not a string literal. Log source is never executed. Codex `write_stdin` shows `session <id>`. (A,B)
- target, other tools: the first present of `file_path`, `path`, `pattern`, `url` in the call's input, otherwise empty.
- identity: `#<8 hex>` of sha256 over the full untruncated shell target, or `#-` when any command in it is `<expr>`, meaning no usable command identity; for an edit tool, `old#<8 hex> new#<8 hex>` over its full before and after text as the log records it (claude `Edit` `old_string`/`new_string`, pi native edit `edits[].oldText`/`newText` in order), so an edit followed by its inverse shows swapped hashes. (A,B)
- status: one of `ok`, `exit <n>`, `error`, `running`, `unknown`. Claude `tool_result` `is_error` gives `error`, or `exit <n>` when its text starts `Exit code <n>`. Pi native `bash` uses `details.capture.termination.exitCode`, because its `isError` is false on a non-zero exit. For `exec` output, each output block gets its own status in block order, joined with `,` (for example `exit 1,running`): `exit_code` 0 gives `ok`, a non-zero `exit_code` gives `exit <n>`, `session_id` without `exit_code` gives `running`, and a block that is not that JSON gives `unknown`, so a failure is never hidden by a pending block and an unsupported result is never shown as `ok`. A call with no result record yet gives `running`. (A,B)
- excerpt: the first non-empty line of the command's own output or error text (for `exec`, the inner `output` field, not the envelope). Target and excerpt are each cut to 120 characters, and a cut is marked with `…`. (A,B)
- reading: only complete newline-terminated records are read; an unterminated final fragment is skipped, since the seat is still writing it. A complete record that fails to parse exits non-zero naming the path and line. A missing or unreadable file, or an unrecognized format, exits non-zero naming the path. (A,B)
The format is detected from the records (pi `{"type":"session"}`, codex `session_meta`, claude records with `sessionId`). The script never judges whether a seat is stuck.
Consumes: watch-scripts-check's root test and `bun test scripts` package script, which run this leaf's tests and typecheck in the blocking `test` check. (A,B)

## Why
Tamdoma/tamdoma-framework#118: the watch judges loops (same command or edit three or more times with the same result, three consecutive errors, an edit-undo cycle) and needs the seat's history. A raw 60-line log tail measured 108-235 KB per seat, in three formats. busy-rule-log runs this script on the path observe prints. This is stage 2 of the issue's spine (`bun test scripts` in `skills/watch-issues`).
