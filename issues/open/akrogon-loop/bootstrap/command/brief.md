# Brief: command

Chart skill version: 4

## What

Build the `akrogon` command in this repo as a bun TypeScript program with the subcommands `install`, `init`, `config`, `phase`, `next`; the global `config.yaml` at the tool repo root; the herdr plugin folder whose hooks call `akrogon next` on `pane.agent_status_changed` and `pane.exited` and `akrogon next --all` at startup; and the test tree. Not in this leaf: `status` and the notification on `failed` (leaf `status`), `pull`, GitHub close and the startup `pull --all` (leaf `pull-close`); these do not exist until their leaves, no stubs. This leaf also replaces the old-shaped `issues/config.yaml` and deletes `issues/.scripts`: it writes the new config first, then removes the old files. Before the hand-verified install, the operator removes the old `~/.local/bin/akrogon` script and the old skill folders under `~/.claude/skills` that carry the new skills' names; `install` prints those removal lines and refuses to overwrite.

## Why

Every other leaf is driven by this command. The operator drives this leaf by hand so the loop is seen once before it is automated (# Bootstrap).

## Done-criteria

1. `akrogon phase <slug> <phase> [--slot A|B] [--verdict ready|nits|fix]` is one atomic operation under `flock` on `<leaf>/.lock` with tmp+rename: it records the calling slot (and verdict) in `done` for the current phase, refuses a slot already in `done`, and moves the phase only when the current phase is a legal predecessor of the target in the routing table and every slot the routing table requires is in `done`, printing `recorded` or `moved <phase>` (waiting for the peer exits zero); a stale or repeated move exits non-zero and leaves the file unchanged; `failed` to `implement` is legal for an operator restart; `merged` is terminal (test).
2. Two concurrent `akrogon phase` processes on one leaf leave exactly one winner (test).
3. `akrogon phase <slug> merged` runs under `<issue>/.lock`, detects completion of the standalone issue or of the whole epic from sibling state files, moves the finished container to `issues/closed/`, prints `issue complete <slug>` exactly from the transition that merged the issue's last leaf (also when nothing moves because the epic is unfinished), and closes no tab; the transition has one named place where leaf `pull-close` adds the GitHub close and closes nothing itself (test with a fixture tree).
4. A merge that landed without the phase written is detected by ancestry (leaf head is an ancestor of `origin/main`) and set to `merged` (test with a temp git repo).
5. `akrogon phase` appends one JSON line per move to `issues/log.jsonl` with the fields named in the design; state is written first and a log failure never reruns the move; `fix_rounds` increments on entry to `check.fix`, and a `fix` verdict that would exceed the cap moves the leaf to `failed` instead of `check.fix`, printed as `moved failed` so the caller can write the diagnosis (test).
6. `akrogon next <slug|folder|--all>` resolves the leaf from the pane's cwd (`herdr pane` lookup by `HERDR_PANE_ID` when run from the hook) or the named folder, reads the routing table (a typed constant: phase to skill, slot and concurrency; `check.review` needs two verdicts, the re-check after `check.fix` is slot A only), on a `merged` leaf closes its tab and dispatches what it unblocked within `max_active` (the tab closes from the hook, after the merge pass has ended), refuses hand-built leaves and leaves whose blocked-by is not merged, respects `max_active`, on first dispatch creates the leaf worktree and branch under `worktree_root`, creates one tab of two panes per leaf named from the slug, fills the harness launch line from config, checks the target pane idle, prompts and waits for the pane to reach `working` with the flag form herdr 0.9.0 accepts, sends blocked or unknown panes to the peer, and applies the retry policy same slot twice, peer once, then `failed`; the prompt line it sends is `<skill> <slug> slot=<A|B> phase=<phase>` (test with herdr substituted, printing the prompt it would send).
7. `akrogon config` prints the effective config (global, repo, defaults; an uninitialized checkout prints global and defaults with `repo: none`) for the repo in cwd and, inside a leaf worktree, `AKROGON_BASE` as the merge-base of the leaf branch and `origin/main` recomputed at each call; `akrogon init [--from <proposal.yaml>] [--toolkit <lang>=<runner>]` writes `issues/config.yaml` (from the proposal file or defaults), `issues/open`, `learnings/LESSONS.md` with the # Lessons header when absent, the gitignore lines for `issues/worktrees/`, `issues/seeds/` and `.lock`, the repo entry and any toolkit line in the global config; `akrogon install` symlinks `~/.local/bin/akrogon`, one symlink per folder present under `skills/` into `~/.claude/skills` and `~/.agents/skills`, runs `herdr integration install` per configured harness and `herdr plugin link`, refusing to replace a real file or folder and printing the removal line (tests for the `init` and `config` file shapes under `AKROGON_HOME`; `install` has no test and is verified once by hand).
8. The plugin links with `herdr plugin link` and its hook runs `akrogon next` on a status change of a fixture pane, checked once by hand and pasted into the leaf's review file.
9. `bun test` is green and is listed as `checks.test` in the new `issues/config.yaml`; old `issues/config.yaml` and `issues/.scripts` are gone.
