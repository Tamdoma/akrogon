- Planning probes I ran on throwaway hc 0.1.22 cores (2026-11-25, free, in `/tmp/hcprobe*`): the keep-recovery shell spawns autonomously about 1.5 s after the program's death is detected — the pid-null "parked" shape is transient and cannot be held deterministically in a default core. But the recovery shell path comes from the core's `$SHELL` (or `shell` in `~/.config/herdr-core/config.toml`): with `SHELL=/nonexistent-shell` in the core's env the terminal stays parked (`state: live, pid: null, reason: signaled, argv` rewritten toward the shell path) indefinitely, and `hc kill` + `hc rm` work on it. With `SHELL` pointing at an exiting script the terminal parks as `pid` non-null, `reason: exited` — not a loss shape the leaf cares about. `hc keep <t>` toggles keep on an existing terminal; `hc run` without `--keep` produces `keep: false`, yet production seat terminals read `keep: true` (herdr-app adoption enables it), so tests must set keep explicitly. `hc server stop` does not kill `--keep` terminal programs; a stop/start cycle produces only a sub-second transient `reason: server_stop` before reattach.

## Decisions

- **D1 — The sweep lives in `src/seat.ts`, beside `cgroupOf`** (the design's leaf architecture: "a new sweep function in the seat module"). Exported entry `sweepSeatShells(repo, leaf, seats, spare)` per the design's stated interface: `seats` is the caller-resolved `Seats` pair (`{A: Seen | undefined, B: Seen | undefined}` from `leafSeats`), `spare` is the caller-resolved set of run-writer pids. It returns one result per swept seat — `{slot, ended: {pid, comm}[], errors: {pid?, error}[]}` — and never throws: every failure inside it is caught per seat and lands on that seat's result, so `commitMove` needs no protective catch around the call and the sweep cannot break a committed move by construction (design signposts: remove the failure class, fewest moving parts). `commitMove` writes the `shell_sweep` rows from the results (it owns `appendTiming` already) and prints the warnings.

- **D2 — Sweep placement in `src/phase.ts:commitMove`.** After the `try/finally` that logs the move and appends `visit_start`, before `return announced`: `for (const warning of await sweepSeatShells(repo, announced)) console.warn(warning)`. At that point the move is saved (`saveState`) and logged (`logMove` + timing). A log-append failure throws `MoveCommittedError` before the sweep runs — the move is still committed there, so the unswept leftovers match the pre-change behavior exactly; recorded as a known limitation, not handled. Every `commitMove` caller sweeps uniformly: `phase` (operator and seat), `next`'s `mergeTurnExit` into check.repair, `start`'s recovery moves, the merge turn and the land run's `merged` move. The sweep runs for every target phase, `failed` included — leftover shells are dead weight in all of them, and the calling seat's own reporting shell survives through the ancestor spare (D6).

- **D3 — Seat resolution in `commitMove`.** After the move is saved and logged, `commitMove` resolves the repo's hc session through `repoSpace` and reads the recorded seats through the existing `leafSeats(session, repo, state)` (both already lazy/cheap), then calls the sweep. A seat with no terminal in the read is skipped silently (dispatch already owns that case). A terminal whose `pid` is null is skipped silently inside the sweep: no shell tree can hang off a dead harness, and a recovered bare shell is dispatch's problem (criterion 4), not the sweep's. A `repoSpace` or `terminal.list` failure is caught in `commitMove`'s sweep block (never escaping): it produces one error entry per recorded seat — leaf, slot and error named — written as that seat's `shell_sweep` row, plus one structured warning. That satisfies criterion 3's "cannot read a seat" case: the move stays committed, the exit is unchanged, the warning names leaf, slot and error.

- **D4 — Shell collection per seat.** Read the harness pid's cgroup path from `<procRoot>/<pid>/cgroup`, resolve the scope directory as `<cgroupRoot>/<cgroup-path>`, requiring the path to sit inside the leaf slice (the `leafSlice(repo, slug, homePath())` segment must appear) — a mismatch is a seat error, never a fallback to guessing the unit name. Collect member pids from every `cgroup.procs` file in the scope directory's subtree (delegated run scopes nest inside it), then for each member read `<procRoot>/<pid>/stat` once into `{comm, ppid, start}` (parse by `lastIndexOf(')')` — the field-22 pattern `src/transcript.ts` and `src/admission.ts` already use). A member pid is a **shell root** when its comm is in `shellCommNames` and either its ppid is the harness pid or its ppid is not a member of the scope (reparented orphan, ppid 1/2 included). Root membership is computed from the single scan snapshot; a vanished or unreadable stat drops the member (it is dying or gone — killing it is meaningless). Any member-stat read failure other than vanishing is a seat error.

- **D5 — `shellCommNames` lives in `src/seat.ts` and is imported by `src/next.ts`** for the recovered-shell predicate (one definition, both consumers in this unit; no duplication). Value per the design's Q2: `{sh, bash, dash, zsh, fish, ash, ksh, nu}`. A member process counts as a shell when its `/proc/<pid>/comm` is in the set or its argv0 basename (leading `-` stripped, read from `<pid>/cmdline` under `procRoot()`) is — the design's exact identification rule; a login shell's `-bash` argv0 is the case the strip exists for.

- **D6 — Spares.** Computed per leaf, once per sweep: (1) `leafRunWriterPids(repo, slug)` — the writer pid of every run record in `<globalHome>/runs/` with matching `repo` and `leaf` in states `waiting`, `live` or `ended` whose `writerLive` check passes — and every member pid that is one of those writers or its ancestor within the scope tree (walking the snapshot's ppid links); (2) the sweep process's own ancestor chain (`process.pid` upward through `<procRoot>` stat links until the chain leaves the scope or ends) and every member pid in the subtree of any chain pid that sits inside the scope. When the phase move is reported from inside the seat's own tool shell (the production case), that tool shell is on the chain, so it and its children survive; when the operator runs `akrogon phase` from outside, the chain never enters the scope and spares nothing. Everything else in a root tree is SIGKILLed.

- **D7 — Kill order and re-check.** Targets are the union of non-spared root-tree members. Kill parents before children (depth order within the snapshot; harness-first does not matter since the harness is never targeted). Immediately before each `kill(pid, 'SIGKILL')` re-read the target's stat: skip when the process vanished, its start time changed (pid reuse — sparing the reused pid is the correct answer, per leaf review F2 note) or its comm/scope membership no longer matches the snapshot entry. ESRCH during kill is a benign skip (already dead), never an error. After the first pass, re-collect membership and stats once: any **new** shell-rooted tree not present in the first snapshot (a shell that forked a replacement child between collection and kill — the fork-order race of leaf review F2) is killed in a second pass under the same rules. Nothing beyond two passes: a shell respawning children faster than two SIGKILL passes is the reconciliation loop's slice-stop territory, not this sweep's. Known race, accepted: a non-shell straggler forked in the kill window and reparented outside the scope is invisible to the re-collect; it holds no terminal, the window is microseconds, and the brief's "can no longer speak" test never constructs it.

- **D8 — `shell_sweep` timing row** added to the `timingSchema` union in `src/timing.ts` (strict object): `{kind: 'shell_sweep', slug, slot: 'A'|'B', phase, ended: [{pid, comm}], errors: [{pid?, error}], at}`. One row per swept seat that ended at least one process or recorded at least one error, appended through `appendTiming` inside the sweep. Seats skipped silently write no row.

- **D9 — brief/design conflict note, design wins: `readTimings` unknown-kind tolerance is NOT this leaf's change.** The leaf review's F1 (an older build reading a timings file with a `shell_sweep` row loses all timings because `readTimings` parses every line in one try and returns `[]` on any failure) was examined in the final-shape check and explicitly not taken: "that holds for every kind added before this one. It is not this leaf's change (scope)." The design's Exclusions repeat it. Recorded here for the reviewing seat so the omission reads as deliberate, per the skill's design-wins rule.

- **D10 — every proc read goes through `procRoot()`** (leaf review correction): `src/admission.ts:liveStartTime` stops hardcoding `/proc` (line 64) and `src/seat.ts:cgroupOf` (line 186) reads through `procRoot()` too. One-line changes; regression coverage comes free through the criterion-1 proof, which seeds the writer's stat only in the fake root and goes red on the hardcoded reads even before the sweep exists.

- **D11 — `src/hc.ts` schema extensions.** `terminalSchema` gains `argv: z.array(z.string()).default([])` and `reason: z.string().nullable().default(null)`; the inline foreground object schema gains `name: z.string().optional()` (probe-verified present on hc 0.1.22 in both `terminal.list` and foreground events). `Seen` picks the fields up through inference. No other consumer changes: `merged()` and the listeners never read them.

- **D12 — Recovered-shell predicate in `src/next.ts`.** `recoveredShell(seat: Seen): boolean` = `seat.state === 'live' && seat.status === null && seat.foreground !== null && shellCommNames.has(seat.foreground.name) && seat.argv.length > 0 && seat.argv[0] !== 'systemd-run'`. Composition is the point: a healthy booting seat reads `argv[0] === 'systemd-run'` (spawn_pending window and the pre-first-status shell window are both excluded); a working harness turn with a backgrounded shell reads `status: working` or `foreground.name` of the harness program; only hc's rewritten keep-recovery shell (`argv[0]` a shell path, foreground a shell, no status ever) matches. `foreground === null` fails the predicate even when argv looks rewritten — a fresh respawn can read fg-null for a fraction of a second; that detection is deferred to the next wake, never killed by mistake. Correctness priority: never kill a healthy seat; a missed detection self-heals one pass later.

- **D13 — Placement in `dispatchSlot`.** The lost-seat branch extends from `seat === undefined || seat.state === 'finished'` to `seat === undefined || seat.state === 'finished' || recoveredShell(seat)`. Everything downstream is unchanged existing machinery: `end()` (hc kill + rm — probe-verified exit 0 on both parked and spawned shapes), `startSeat` replacement with prompt redelivery, `lost` charge, `busy_since` clear, `seat_lost` timing row (its `screen`/`turn` fields read whatever the recovered shell shows — no schema change), `capacity_lost`, `seat_end` event consumption, third-loss failure. `silentEnd` and the `prompted` redelivery paths are unreachable for a recovered shell (turn 0 vs prompted turn 1), so no guard interaction. `observeBusy` upstream already passes null-status terminals through untouched. The predicate is evaluated identically for slot B through the same shared loop — no slot-specific code.

- **D14 — No change to `allocate`, `clearBusyNotices` or the hc listener.** A recovered terminal is only ever observed inside `dispatchSlot`'s read; seats are never re-allocated while one is recorded, and the listener's event set already covers the replacement seat's first turn.

- **D15 — Fake proc/cgroup seeding for the criterion-1 proof.** The sweep test drives the real `akrogon phase` CLI with `AKROGON_PROC_ROOT`/`AKROGON_CGROUP_ROOT` pointed at a seeded tree (established seam: `fake-proc.ts`, `leaf-slices.test.ts`). Real processes are spawned as the shell trees (real pids, real killability), but their `/proc` entries in the fake root are hand-written so parentage, comm and scope membership are exactly the designed scenario — including entries that lie about parentage (a reparented orphan shows ppid 1) and entries absent for real pids that must read as outside-the-scope. A small wrapper `bash -c 'echo $$ > <pidfile>; exec bun src/akrogon.ts phase ...'` runs the CLI: `exec` keeps the wrapper's pid, so the test seeds that pid's fake stat with a ppid inside the spared shell tree, proving the caller-chain spare end-to-end. `sliceCgroup` nesting (`akrogon.slice/akrogon-l<hash>.slice/<scope>`) is replicated in the fake cgroup root with `cgroup.procs` at the scope level and in one nested delegated scope.

- **D16 — hc fixture additions for criterion 4.** Tests call `hc keep <address>` on the seat terminal after first dispatch (production seats get `keep` from herdr-app adoption; the strict fake herdr-app does not reproduce that, so the test sets it explicitly — this is environment setup, not product behavior). The parked shape uses a core started with `SHELL=/nonexistent-shell` in `coreEnv` (probe-verified: the terminal then parks `pid: null, reason: signaled` forever instead of respawning). The spawned shape uses a default core: SIGKILL the stand-in pid, wait for the bash respawn (`pid` non-null, `foreground.name` `bash`, `argv[0]` the shell path), then run the pass.

- **D17 — Shim rewrite for the spawn_pending case.** `spawn_pending` cannot be reproduced deterministically on hc 0.1.22 (it is the core's initial-spawn window, milliseconds long). The negative proof rewrites the terminal's `reason` to `spawn_pending` at the hc boundary: `tests/hc-shim.sh` gains an opt-in `HC_SHIM_REWRITE_REASON=<address>:<reason>` hook that patches the field in `hc get --json` and `terminal.list` replies for one terminal. This is the smallest real boundary available: the product code's schema and predicate consume exactly what hc would emit, and the pass under test is the real engine. The same mechanism rewrites nothing for the positive cases.

## Condition checks (decisions vs criterion conditions)

- C1 "after a committed phase move" — D2: placement after `saveState` + `logMove`. Case in proof: the CLI prints `moved implement` and the sweep's effects are visible in the same invocation.
- C1 "every recorded seat" — D3: both A and B records swept. Case: only seat A exists in implement (one-seat phase) — the row carries `slot: 'A'`; the B-record case is exercised by seeding a stale B seat record into state (a legitimately recorded seat of a prior two-seat phase) whose terminal is gone — silent skip, no row, no error.
- C1 "shells whose parent is the harness or outside the scope, plus descendants" — D4 root rule. Cases: direct harness-child `bash` with `sleep` child; grandchild shell nested two levels; orphaned shell whose fake ppid is 1. All die.
- C1 sparing (a) — D6 chain walk. Case: the CLI's own pid is faked as a child of a shell inside one target tree; that tree survives whole.
- C1 sparing (b) "live or still publishing" — D6 + `ended`-state record scan. Cases: three records (waiting/live/ended states) each naming a writer pid inside a different target tree — all three trees survive; a `cancelled` record and a record of a different leaf naming trees that then die; a record whose writer pid is dead (start-time mismatch) spares nothing.
- C1 sparing (c) — D4 root definition + D12-nothing. Case: `sleep` harness child with a `bash` child and a grandchild `sleep` — all survive untouched.
- C1 "one `shell_sweep` timing row per swept seat that had a process ended or an error" — D8. Case: exactly one row for the seat; `ended` lists the shell pids and comms actually killed; harness pid absent.
- C3 "cannot read a seat" — the missing-cgroup seat-error case. "Cannot end a process": no realistically constructible kill failure exists for own-user processes (EPERM impossible, ESRCH benign-by-design) — the warning path is proven through the read failures, and the per-seat error row shape is uniform; recorded as a proof-limitation note in the test comment rather than an invented failure injection.
- C4 "parked and spawned shapes, using hc terminal records shaped like the charting proofs P2" — D16: both shapes produced by the real core, records read through the real `terminal.list` path. The `systemd-run` negative is a live booting-window seat (delay-hook stand-in, fg shell or null, `argv[0] systemd-run`); the `spawn_pending` negative uses the D17 shim rewrite because hc 0.1.22 exposes no deterministic hold for that state — recorded here as the boundary decision the criterion's "shaped like" wording allows.
- C4 "same replacement and `lost` charge as today" — D13: literally the same code path, asserted through `lost.A === 1`, one `seat_lost` row, new address recorded, first prompt delivered to the replacement.
- Time: no calendar-dependent expectations in any proof.

## Open-for-the-plan answers

Both design questions close in the negative; no test or code is needed for either beyond what the criteria already prove.

- **Stale `busy_since` across the advance cannot post a false busy notice.** Traced through `src/next.ts:observeBusy`: a notice is written only when the seat reads `working` at that pass and `busy_since` is over an hour old (STALL_MS). After the sweep kills the leftover shell, claude reports `done` (P1) and the very next pass clears `busy_since` through the not-working branch — so a stale entry survives at most one pass in which the seat is genuinely idle, and any notice posted while the shell masked the seat was a true positive: the seat really was un-deliverable for that hour. The ordering also holds because `dispatchSlot`'s lost branch (and therefore the recovered-shell path) runs before `observeBusy` is ever reached — a recovered shell is replaced without a busy observation at all.
- **The silent-end ordering against a recorded prompt turn above 0 holds.** A recovered terminal's `turn` resets to 0 while `prompted.turn` records the turn the prompt went in at (1 for the first prompt), so `recordedPrompt.turn < seat.turn` is false and `silentEnd` never fires for a recovered shell; the lost branch is reached. Both the parked and spawned proofs (tests 6–7) exercise exactly this ordering since their seats are killed after the first prompt was delivered and recorded.
