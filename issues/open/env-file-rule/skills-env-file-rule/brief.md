# Brief: skills-env-file-rule

## What
`skills/plan-issue/SKILL.md`, `skills/implement-issue/SKILL.md`, `skills/check-issue/SKILL.md` and `skills/merge-issue/SKILL.md` each state, in one sentence in their own words, that the seat never opens, prints, appends to or writes the registered repo's env file (`.env` and `.env.*`) with any tool; a script that needs values runs as `bun --env-file=<file> <script>` and prints results, never values; and a variable's presence is checked by name the same way, with a script that prints `present` or `absent` per name. `skills/plan-issue/SKILL.md:57` (origin/main) is rewritten so the credential check is that by-name script instead of a look into `.env`. `skills/AREA.md` names the rule once as an invariant of every phase skill. The existing missing-value stop (`akrogon phase <slug> failed --reason "<missing <VAR> blocks <criterion>; see <artifact>>" --slot <A|B>`) is untouched. No other prose, no code, no new file.

## Why
An implement seat appended a credential to the env file with the bash tool and then inspected it with `cat`, `tail`, `sed` and `awk`; one output escaped redaction and the credential sits in the seat's session log (Tamdoma/akrogon#22, owned by pi-extensions leaf `env-guard-hooks`). The skills told seats to check credentials "in the registered repo's gitignored `.env`", which reads as permission to open it. The enforcement lives in pi-extensions; this leaf makes the skills say the rule so a refusal is never a surprise and the plan check no longer opens the file. Verified 2026-09-19 with bun 1.4.2 and a synthetic file: `bun --env-file=.env -e '<script>'` prints `present`/`absent` per name without printing a value.

## Done-criteria
1. Each of the four phase skills contains one sentence stating the rule (never open, print, append to or write the env file with a tool; `bun --env-file=<file> <script>`; results not values; presence by name), placed next to that skill's existing missing-value stop sentence (plan :29 and :57, implement :31 and :41, check :25, merge :25 on origin/main). `skills/AREA.md` names the rule once.
2. `skills/plan-issue/SKILL.md` no longer tells the seat to check a credential "in the registered repo's gitignored `.env`"; it names the by-name presence script in the form `bun --env-file=.env -e '<script printing present/absent per name>'` or an equivalent file script.
3. Within the five owned files, no sentence tells a seat to `cat`, read, open, edit or append to `.env`; the implementation report lists every literal `.env` match under `skills/` and marks the ones outside the five files (`chart-issues/SKILL.md:47`, `chart-issues/assets/standing-design.md:11`, `broadcast-issue`'s `~/.config/akrogon/env`) as out of scope and unchanged.
4. `bun test` and `bun run format` pass; `tests/command-reference.test.ts` and any skill-prose test still pass unchanged.
