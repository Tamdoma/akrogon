## Leaf architecture
- Owned: skills/chart-issues/SKILL.md (Open's seat-record sentence), skills/chart-issues/assets/questions.md (Blind peer exchange), skills/chart-issues/scripts/peer-ask.ts, peer-wait.ts, which prints every outcome line (A,C), peer-restart.ts, and their tests.
- Outcome lines stay JSON objects with every current field; the session is one added field. Consumers: A reading outcome lines per questions.md, which copies `exchange` verbatim into a peer-wait rerun; the added field must not change `exchange`. peer-wait reads the post-exchange roster so direct reruns carry the session too (A,C).
- peer-restart state lines keep `seat`, `pane` and state values; the added session is the one herdr shows after start, or none when herdr shows none or the pre-restart session, since codex keeps the old id until an exchange (A,C). Consumer: the Open rule's seat-record append, which today waits for `herdr agent list`.
- The idle-wait chain is skill text only; `herdr agent wait` exit codes are unchanged (proof: forks/levers.md, a timed-out wait exits 1 and stops the chain).
- The live runs hold model, effort and harness version equal on both sides; the timeout case runs outside them (A,B,C).
- Exclusions: SKILL.md's post-compaction re-read instruction, chart-usage.ts, door-reset's handover (Tamdoma/akrogon#101 leaf door-reset), harness settings, rebuttal session type.
