# Design: pause-dispatch

## Binding decisions, verbatim

### Boundary (issues/chart/repo-pause/forks/boundary.md)
Operator 2026-10-08: `1a | 2a`
- 1a: a pause freezes every automatic action for the repo, including merged-tab close, temp cleanup and owner completion (broadcast, source close); the first pass after unpause does them. Reason: one rule, every skipped step is idempotent. Foreclosed: 1b keep cleanup while paused.
- 2a: `--resume` is always automatic and paused; operators force a pass with `next --all` or a target. Foreclosed: 2b manual --resume bypass with a startup marker.
Binding with the agreed findings above: paused paths are the four herdr events, startup --resume, mergePass after an automatic pass, mergeWake after akrogon phase and dependent starts from automatic passes; manual next <target>, typed bare next and --all run in full with cascades and never clear pause; the pause write takes the global lock and each automatic start/prompt re-reads pause inside its locked section; classification by event JSON or --resume, never HERDR_PANE_ID or leaf count; a skipped automatic pass exits 0.

### Control (issues/chart/repo-pause/forks/control.md)
Operator 2026-10-08: `1 - Then what's the difference between pause and park? | 2a | 3a |`, then after the explanation: `1a`
- 1a: `akrogon pause` / `akrogon unpause` take no argument and act on the registered repo of the current folder (requireRepo, like park, incl. worktrees). State lives in a separate schema-validated, gitignored file under globalHome(), keyed by registered repo name; missing file = nothing paused, invalid file = error; written under the global lock with the rename writer; idempotent, prints the repo and resulting state. Foreclosed: 1b repo-key argument; storage in config.yaml or issues/config.yaml (both tracked).
- 2a: unpause clears the pause, then runs one startup-style pass scoped to that repo (allocated or merged leaves, cleanup, merge pass, with existing dependent cascades). Reason: closed seats have no pane left to fire an event, so the model-swap flow needs unpause to relaunch. It never starts a leaf that had no tab, worktree or merged phase except through the existing dependent cascade. The clear is reported separately from any pass error. Foreclosed: 2b clear only.
- 3a: `akrogon status` annotates paused repos only, beside the repo heading, incl. empty repos, --charts and targeted leaf status; phases, blockers, queue and capacity unchanged. Foreclosed: 3b active/paused on every repo.

Exclusions: none; this is the only leaf of the chart.

Proof is the smallest test at the CLI boundary: `akrogon pause|unpause|next|phase|status` run against isolated registered repos (tests/helpers.ts) with the fake herdr (tests/fake-herdr.ts), asserting herdr calls made or not made, state files and exit codes, never prose wording. Criterion 5 is proven with two real CLI processes sharing the global lock (A,B): (a) hold an automatic pass at a barrier before its final locked launch section (including the merge dispatch outside the main next lock, src/next.ts:1332,1115), let the real `akrogon pause` finish, release the pass, and show no allocation, agent start or prompt follows; (b) hold an automatic launch while it owns the lock, start `akrogon pause` concurrently, show pause does not acknowledge until the lock is released, and show later automatic work is suppressed. A fake may provide barriers but never writes pause state outside the command. Each new behavior shows one deliberate break turning its test red (for example removing the pause check from one automatic entry). No live herdr run is required.

## Leaf architecture
- Owned: CLI wiring in src/akrogon.ts (`pause`, `unpause`, no positionals); a small pause-state module (read/parse once with zod, write with the existing rename writer in src/shell.ts under the global lock at `<globalHome()>/.lock`); the automatic-dispatch gate in src/next.ts (hooked passes, `--resume`, automatic mergePass and mergeWake, re-check at each locked start/prompt section); the merge wake call site after `akrogon phase` (src/akrogon.ts:75 / src/next.ts:1141); src/status.ts paused marker; .gitignore entry for the state file; tests under tests/; docs/guide (next.md, cheat.md, and wherever park is described).
- Interface: `akrogon pause` and `akrogon unpause`, no arguments, repo resolved with requireRepo(cwd) as `akrogon park` does (src/park.ts:50). State file under globalHome(), gitignored, keyed by registered repo name. Missing file = none paused.
- Classification (A,B): `--resume` is always automatic; an explicit target, path or `--all` is manual and ignores an inherited `HERDR_PLUGIN_EVENT_JSON`, as src/next.ts:1232 already does; a no-input `next` is automatic only when it carries a plugin event, otherwise manual even with `HERDR_PANE_ID`; the merge wake after a phase move is automatic. Never classify by `HERDR_PANE_ID` or leaf count.
- Unpause pass: the startup `--resume` selection and cleanup scoped to the one repo, then its merge pass; it is operator-initiated, so it runs after the clear and is not itself gated.
- Excluded: no change to `akrogon park`/`unpark`, to dependency eligibility (src/turn.ts), merge-queue order or capacity; no change under `issues/`; no plugin change unless the gate cannot be expressed in the command.
