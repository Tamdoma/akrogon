# Brief: watch-timer

## What

`watch-issues` runs the same watch from a claude, codex, pi or agy conversation. Start runs one check and starts one timer, `skills/watch-issues/scripts/timer.ts`, as an hc child of the watcher terminal, pinned to the watcher's harness process; the timer sends `watch-issues tick timer=<address> pid=<pid> due=<n> <root>` to the watcher every 20 minutes, one due at a time after the previous turn ends; stop kills and removes the verified timer. The mechanical steps (start, stop, tick verification, receipt) are scripts in `skills/watch-issues/scripts/`; the skill runs them. Claude Code cron (CronCreate, CronList, CronDelete), the "needs Claude Code cron" refusal and the 7-day expiry are removed from the skill and the docs. Live runs on real claude, codex, pi and agy watchers show today's Claude watch behaviors, except continuation after a compaction, which stays a skill-text rule (design, Held disagreements). (B)

## Why

Today the watch runs only in Claude Code: in pi it answers "This watch needs Claude Code cron, so no watch is running." The skill folder is linked into every harness, so the operator wants one script and one delivery path for all of them, with no regression from the Claude-only watch.

## Done-criteria

1. Start from a watcher terminal in the repo's resolved hc session runs one check (`akrogon status` at `<root>`) and leaves exactly one live terminal named `<prefix>-watch`, labelled `akrogon.watch-timer=<repo>`, whose parent is the watcher and whose argv runs `skills/watch-issues/scripts/timer.ts` with the watcher's harness pid and start time, also when that check finds the repo paused; no cron tool is called. The harness process is the watcher terminal's foreground process, and start refuses and starts no timer when that process is not an ancestor of the start step. (B,C)
2. A second start while one verified timer is live runs its check, as today's start does with a job present, reports that timer and starts none; with more than one labelled terminal, or a `<prefix>-watch` name held by an unlabelled or unverified terminal, start and stop report them, run no check and change nothing. (B,C)
3. Each interval with no check running, the watcher receives `watch-issues tick timer=<address> pid=<pid> due=<n> <root>` and runs one check, setting the timer's label `akrogon.watch-due=<n>` before that check; with no open leaves the watch keeps running; a root containing a space works through start, tick and stop.
4. Dues that fall due while a check runs are each delivered after the previous turn ends and each runs its own check, none merged into a running turn; a due whose receipt label does not appear, whose send hc reports not started, or whose watcher turn does not advance within one interval is resent once, then dropped while later dues continue, so a lost send never stalls the timer. (B)
5. Stop from the watcher or any other terminal in the session kills and removes the verified timer and reports it; a repeated stop reports already stopped; a start after stop starts a new timer, and a tick naming the old timer's address runs no check and reports no watch.
6. A tick without a live verified timer at its address whose parent is the receiving terminal (an old `/watch-issues tick <root>` cron prompt, a tick with no `timer=`, a tick after stop) runs no check and starts no timer; a tick whose `due=` is not greater than the timer's current receipt runs no check; (B,C) a tick whose `pid=` differs from the receiving agent's harness process stops the watch and runs no check.
7. The timer exits without sending and frees the name when the pinned harness process exits or is replaced, when another program is in the watcher terminal's foreground, when the watcher terminal finishes, or when the watcher's resolved transcript path changes: on claude and agy `/clear` ends the watch with no further tick; an agent that exits, whether it was the terminal's program or was launched from a shell, leaves no tick text in that terminal afterwards, apart from the held-draft limit of design item 4. Codex and pi `/new` is the stated limit of design item 4. (B,C)
8. A check on a paused repo reports paused and acts on nothing, and its due still counts delivered.
9. Start is refused, with no check run and no timer started, when `HC_TERMINAL_ID` is unset or the watcher is outside the repo's resolved session.
10. The skill and docs/use/watch-while-away.md docs/reference/skills.md and docs/pictures/watch-loop.svg describe the watch for all four harnesses, name the stated limits of design item 4, say that a compaction summary before a tick is not a reset, and no longer mention Claude Code cron, CronCreate, CronList, CronDelete or an expiry.
11. Live runs with real claude, codex, pi and agy watchers in the throwaway hc session show, on each harness, the start check and timer (1), a second start (2), a tick check with its receipt and a root containing a space (3), every unpaused check on the registered root's waiting stand-in leaf running `akrogon next` for it (the Judge waiting rule), (C) two dues during a busy check each running their own check (4), stop, repeated stop and restart with the old tick refused (5), an old cron tick refused (6), claude and agy `/clear` and, for codex and pi, the recorded outcome of `/new`, and an agent exit from a shell (7), a start on a paused repo that still starts the timer and a later paused check (1, 8); (B,C) each live session uses its own registered root and log, one session after another because the e2e tier holds one hc session (`akr-e2e-watch`) and refuses a second tier while one is live.
