# Design: agent-worktrees

## Binding decisions, verbatim
From issues/chart/leftover-worktrees/forks/auto-remove.md, round 1, 2026-10-16, operator `1a | 2a | 3a`, plus the final-shape check (slots/final-check-B.md, final-check-C.md):

- Scope (A,B,C): only Claude Code agent worktrees. An operator's own unmanaged worktree stays kept and listed, because a fresh one (clean, no commits) passes every git test and must not be deleted. Foreclosed: any unmanaged worktree; path match alone.
- 1a: a lock in Claude Code's exact form `claude agent agent-<id> (pid N start T)` counts as released only when /proc/N/stat is absent or its field 22 differs from T. Every other lock, and a matching live owner, is honored. Unknown format: kept. Reason: Claude always locks its agent worktrees and the lock names its owner (the parent session), so a dead owner is proof, not a guess. Foreclosed: honor every lock (nothing would ever be removed); ignore locks when the tree is clean.
- 2a: removable when `git status --porcelain` is empty (tracked changes and untracked files block, ignored files do not), no rebase/merge in progress, HEAD on a branch other than the default branch, and every commit in `<target>..HEAD` is on the target as the same commit or the same patch (`git cherry <target> HEAD` prints no `+`), with no merge commits in that range. Missing target, git error, detached HEAD: kept. Foreclosed: ancestor only (keeps rebased work, the reported case); ignored files block (keeps every worktree with installed packages).
- 3a: after the worktree removal succeeds, delete its branch with `git update-ref -d refs/heads/<branch> <proven head>`, bound to the proven commit; never the default branch. A branch that moved since the proof stays: it is in use, not a leftover. Foreclosed: keep the branch; by-name `git branch -D`.
- Binding avoidance: existing process/owner veto and pane veto run first; unlock, then non-force `git worktree remove` (git re-checks tracked changes and untracked files); on removal failure re-lock with the original reason so the worktree is left as found; the removed record keeps the head sha.
- Off route: branch-only leftovers; operator worktrees; other harnesses' worktrees.

## Leaf architecture
- Owned surfaces: src/reconcile.ts and src/admission.ts (exporting the existing field-22 reader only) (C). In src/reconcile.ts, the registered-worktree loop where an out-of-root registered path is kept as `unmanaged worktree` (`for (const path of registered.keys())` inside the per-repo reconcile). Agent worktrees live at `<repo>/.claude/worktrees/agent-*`, outside the store, so they reach that branch today without a lock check. The new rule runs there before the `unmanaged worktree` keep; everything not eligible falls through to today's keep unchanged.
- Identification needs all three (C): path exactly `<repo.root>/.claude/worktrees/agent-<id>`, lock text matching Claude's form with the same `agent-<id>`, and the dead-owner test. Lock parse: exact regex on the `locked` text from the existing porcelain parse (`WorktreeRow.locked`). Owner liveness reuses the field-22 reader in src/admission.ts (`startTime`/`liveStartTime`, today module-private); export it rather than writing a second reader. Open for the plan: `liveStartTime` rethrows non-ENOENT errors; decide whether a permission error is kept (must not remove).
- Removal: reuse `removeWorktree(path, false, rule)` for its process/owner veto and `worktreeRemovable`, adding the pane veto `livePaneInside` (as `dropChecked` does) and the default-branch and cherry checks. `git worktree remove` refuses a locked worktree without force, so unlock immediately before the non-force remove and re-lock with the original reason on failure. Open for the plan: `removeWorktree` adds its own keep entries on failure; the re-lock must happen on every failing path after unlock, and keep reasons must stay today's wording where today's checks fire.
- Target: `target(repo)` in src/config.ts (`<remote>/<default_branch>`), the local tracking ref as last fetched. No fetch is added. The proof is against that captured ref: a ref behind the remote only makes more commits look missing (kept); a remote history rewrite of the default branch could leave commits in the stale ref that the remote no longer has. Accepted limit: akrogon never force-pushes the default branch (B).
- Branch: after a successful remove, `git update-ref -d refs/heads/<branch> <row.head>`. A moved or missing ref is the chosen keep and is silent. Open for the plan (B): tell that case apart from other `update-ref` failures (ref lock, permission, I/O) and surface those through the pass's existing error reporting, not as a keep entry on the removed path (src/leftovers.ts drops entries whose path is gone).
- Consumers of changed state: `removedWorktrees` (record shape unchanged, rule name e.g. `ended agent worktree`), `akrogon leftovers` (reads kept entries; unchanged), end-of-pass `git worktree prune` (runs when anything was removed; unchanged).
- Exclusions: leaf, verify, batch and worker worktree rules; the `locked worktree` keep for every other lock; operator worktrees (tests/reconcile.test.ts 'operator worktree outside managed roots is kept as unmanaged' stays green).
