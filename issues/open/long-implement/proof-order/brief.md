# Brief: proof-order

## What
Three seat-A proof rules in `skills/implement-issue/SKILL.md`, applying at implement end (the paragraph at line 54, including its opening "After the last implementation unit, with every worker worktree removed") and after every check.fix repair (the paragraph starting "Do required work for Fixes only"). A slow run is any live run, or a proof whose plan.md size (`skills/plan-issue/SKILL.md:57`) is hours or unknown. (A,C)
1. Cheap proof first: before the first slow run, A runs every `checks` command and every done-criterion proof whose prerequisites are valid and which needs no slow or live result, whatever its own size. Checks and proofs that need a slow run's output run after it, and the existing blocked-check and final-proof rules stay (standing-design slow-run rule). (A,B,C)
2. Overlap, delegated mode only and not on the final allowed repair round: while a slow run is in flight, A may start a unit or repair in a worker worktree when it does not consume the run's result, edits nothing the run reads and shares none of its test resources. An overlap wave starts from the lane's committed HEAD. Pending lane commits, cherry-picks and any landing wait until the slow run returns. A then reruns the changed stages and their consumers under the existing slow-run rerun rule. In inline mode and on the final allowed repair round, A waits for the run. (A,B,C)
   `skills/implement-issue/worker-protocol.md` is amended to match: line 11's before-wave commit clause keeps its rule outside overlap; line 11's closing clause and line 25 ("criterion proof and every `checks` command belong to A after the final worker") allow independent proof to overlap workers under this rule, while the final passing proof and checks run after every worker commit lands and every worker worktree is removed, before `akrogon phase`. Workers still run only their brief's changed-test command. (B,C)
3. Wait on exit: A waits on a slow command's exit and status. When a wait returns before the command has exited, A waits again. A never sleeps a fixed interval and then reads the log, and treats the exit status as the result, never a quiet log. The wording names the behavior and no harness command or tool. (A,C)

## Why
Tamdoma/akrogon#51, emdash-launch: after workers finished, A spent 154m on live proof. `framework:verify`, which needs no live result, first started 114m after the last pick, and its two defects cost two more 12m runs at the end. A polled with 42 `sleep` calls covering about 104m. One measured overshoot: run ended 13:25:09, noticed 13:27:19. In check.fix, repair workers and the live rerun ran one after the other. Evidence: issues/chart/long-implement/slots/proof-tail-merged.md.
