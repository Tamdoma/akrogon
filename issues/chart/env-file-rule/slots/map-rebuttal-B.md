- **D1/Q3 turns access prevention into a blanket text-match rule and attributes it to both slots.** My recommendation was to reject supported direct-access operations, not every bash command mentioning a protected path (`map-B.md`, C2/K3–K5 and Pitfalls). For example, searching source documentation for `.env` or printing a missing-variable instruction names the file without opening it. The merged rule would reject those operations even though seed #22 prohibits reading/writing the credential file, not discussing its path. Keep the supported-operation contract explicit and add harmless-reference negative tests alongside the forbidden-access cases. A `--env-file=` token is likewise not sufficient to approve an entire compound command containing another forbidden operation.

- **The minimum-length exemption is neither my recommendation nor a settled protection contract.** The merged Pitfalls attributes “minimum length” to B, while `map-B.md`, C3/K6, distinguishes empty/common nonsecret configuration from secrets and leaves classification as a decision. A short password remains a secret, so silently skipping it contradicts D1's promise to replace every exact protected value. Exclude empty values, settle which values are protected, and define explicit behavior when a protected short value would make substring replacement excessively destructive. Include a short synthetic secret test rather than introducing an undocumented length-based disclosure exception.
