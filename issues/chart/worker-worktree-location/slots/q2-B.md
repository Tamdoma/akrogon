# Q2: smallest deterministic push, independent B

Recommend one stateless, single-purpose creator inside `skills/implement-issue/scripts/`, paired with the worker-protocol instruction to use it for every **new delegated leaf worker**. It computes the path, creates the detached worktree at the leaf's committed HEAD, and prints the absolute path for subsequent spawn/inspection/removal. This makes the normal action deterministic without a new akrogon verb, lifecycle state, hook or pi policy. It cannot force compliance if the seat deliberately bypasses it.

## Proposed narrow creator contract

Example proposed interface, not an existing command:

```text
bun <installed-implement-issue-folder>/scripts/create-worker.ts <slug> <unit-number>
```

- **C1 · Inputs and caller.** Run from B's leaf checkout. Parse the slug/unit arguments once, resolve the registered repository with existing helpers, and verify that the caller's worktree root is the configured leaf path for that slug. This prevents running the helper from registered main and silently selecting main's HEAD. No lifecycle state needs writing or worker registry is needed.
- **C2 · Deterministic action.** Compute `resolve(repo.root, repo.config.worktree_root, slug + '-u' + unit)`. Resolve the leaf's committed HEAD explicitly, then invoke `git worktree add --detach <absolute-worker-path> <leaf-commit>`. Do not accept a caller-supplied destination or arbitrary start revision. B remains responsible for committing pending edits before the wave, as today (F4).
- **C3 · Return and failure.** Print only the created absolute path to stdout on success; Git diagnostics belong on stderr. Use argument arrays rather than generated shell text. Reuse command error context (`src/shell.ts:7-14`, `:17-23`, `:48-51`). Refuse an occupied destination without `--force`, overwrite, reuse or deletion. Preserve a failure's actual state for inspection.
- **C4 · Consumption.** The protocol tells B to retain this one returned path and copy it unchanged to the worker sub-brief/spawn cwd and later inspection/removal. Do not ask the model to recompute it. No generic print/create/remove mode flags or allocator lifecycle are needed.
- **C5 · Exceptions already taken.** Standalone does not call the helper. A retained worker, including one at the old nested path, resumes from its recorded path under the existing recovery rule. Creation failure is not permission to invent an alternate directory. This preserves Q3 rather than adding automatic migration.

The helper can import akrogon's config/shell functions from the same installed repository tree. F2 establishes that tree exists under the supported symlink installation. This is deliberately a leaf-only helper: standalone's skill-local/no-config behavior is unchanged. Use the installed skill path for normal seats, and the development checkout's script explicitly for implementation verification. No global package installation is needed.

Git provides detached worktree creation at the supplied commit and standard removal; the helper fixes the caller's arguments rather than adding its own worktree state model. [Git worktree manual](https://git-scm.com/docs/git-worktree).

## Practitioner challenges

- **R1 · “You still rely on the agent invoking it.”** Correct. O2 deterministically performs the normal workflow, but is a soft push, not an enforcement boundary. Making bypass impossible requires mediating creation/spawn across every harness, which is outside the requested small mechanism. Do not claim that a script “activates itself.”
- **R2 · “Is this secretly an allocator?”** It performs one creation operation using Git's existing metadata. It must not gain a worker registry, unit-number allocation, state.yaml fields, cleanup daemon, pane creation or retry/fallback locations. Input identity, root resolution and Git invocation are enough.
- **R3 · “Why create instead of merely printing?”** Printing fixes one calculation while leaving creation and commit selection manual. Creating eliminates that extra model-written command for a small increase in code. The path result then becomes evidence of the actual completed action.
- **R4 · “How do you verify the helper rather than its wording?”** Use real temporary repositories to exercise default/custom/absolute stores, a leaf HEAD ahead of main, paths containing spaces, wrong caller checkout and occupied destinations. Invoke via a skill-directory symlink too. Verify returned path, detached HEAD and unchanged existing work on refusal. Retained and standalone flows should never enter this creator. No text-matching rule tests or live worker spawns are needed to validate path creation.

Choose O2 plus its canonical protocol invocation. Do not add O3, O4 or O5 initially. If the operator requires rejection even when the helper is ignored, that is a separate enforcement requirement and should be stated explicitly before expanding into pi or dispatcher policy.
