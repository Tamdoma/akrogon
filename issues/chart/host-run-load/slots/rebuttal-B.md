# Seat B disagreements

- R1. Detail 5 exempts full suites under a non-full parent. `run-check --name outer -- akrogon verify` gives the child a valid token even though `outer` holds no full slot (`src/run-check.ts:158,223`). Admission bypasses all checks for that token (`src/admission.ts:89-92,142-144`). Thus a marked full verify command overlaps another holder. This nesting already has a fixture (`tests/run-permit.test.ts:197-219`). Inherit exemption only from a parent holding the full slot. A full child of a non-full parent must acquire it. Add that case beside the planned full-under-full test.

- R2. Details 2–4 free capacity before the previous suite's processes necessarily stop. Normal completion marks the record ended before stopping its unit (`src/run-check.ts:242-244`). On wrapper death, PID liveness fails immediately, while the guard removes the record before stopping the scope (`src/admission.ts:86-87`, `src/scope.ts:80`). A waiter can consequently start during old Chromium/workerd cleanup, violating the one-full-run bound. Stale sweeping cannot repair this after the record has disappeared (`src/admission.ts:115-123`). Retain retiring holder identity until its unit drains, including after wrapper death, and test that a queued full command cannot start while a killed holder's descendant remains alive. Merely testing that SIGKILL eventually unblocks the queue misses this overlap.
