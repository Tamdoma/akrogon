# Slot C leaf review: run-release

Disagreements only.

- F1. release-rollback cannot work the first time it is needed, and its hold is not honored by the release it rolls back to. Criterion 3 runs "the previous release's own entry point with `rollback`" (release-rollback brief.md:12), but when the first rollback-capable release is the bad one, the previous release is release-deploy's code, which has no `rollback` verb; the test in release-rollback design.md:18 builds both releases from code that already has the verb, so it cannot catch this. Same defect for the hold: design.md:25-29 has the deploy stage read the hold, but after a rollback the running deploy stage is the previous release's, written before the hold record existed, so the next trigger redeploys the bad commit and criterion 2 fails in exactly the first real use. release-deploy's brief and design contain no hold reading at all (its design.md:13 excludes Q4). Exact fix: add to release-deploy brief.md as criterion 8: "8. The deploy stage reads a hold record in the state home naming one commit and never builds or flips to that commit while it is main; with no hold record it deploys as today." and in release-rollback brief.md replace criterion 3 with: "3. Rollback works when the current release cannot start: the manual pointer flip named in README (rename a temporary link to the previous release over `current`) switches releases with no akrogon code running, and README names that command."
- F2. release-rollback criterion 5 (brief.md:13) requires an error "naming the file and field it cannot read", but no surface this leaf owns can produce that error: its owned surfaces are `src/akrogon.ts`, the release module and README (design.md:22), while the strict parse that would fail is bare `globalSchema.parse(...)` in `readGlobal` with no file naming (src/config.ts:206, schema at :23-30), and `src/config.ts` belongs to state-home's surfaces. As written the criterion also cannot be tested with the design's two same-code releases (design.md:18), whose schemas are identical. Exact fix: add `src/config.ts` (`readGlobal` error wrapping only) to release-rollback design.md:22 owned surfaces and replace criterion 5 with: "5. With a state home `config.yaml` carrying a key the running release's schema rejects, the rolled-back command exits non-zero with an error naming that file and the rejected key, and changes no state."
