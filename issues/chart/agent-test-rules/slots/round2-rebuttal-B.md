1. **F1 · External provenance alone is not the criterion bar.** `round2-merged.md:4,17` and `round2-A.md:30,36` treat a criterion or real sample as sufficient authority for an expectation. Require a separately justified outcome/invariant and its realistic consequence as well. An invented criterion remains invented, and authentic output can contain a bug.
   Evidence: `skills/check-issue/SKILL.md:55` makes named scenarios block irrespective of realistic source. `issues/closed/leaf-readiness/readiness-contract/review-B.md:13-17,23` shows green tests explicitly expecting incorrect behavior. `round2-B.md:64,66` requires both justified expectations and behavioral value. The merged criterion question must retain that substance, not reduce it to “where do values come from?”

2. **F2 · “Never from running the code under test” is too absolute.** `round2-A.md:30,36` would exclude useful relational properties whose expected intermediate value comes from a first invocation. Ban using current behavior as the definition of correctness, not computing values within a test of an independently justified relationship.
   Evidence: [David MacIver, 2026-03-24](https://antithesis.com/blog/2026/hegel/), “What's property-based testing?”, uses `once = to_title_case(s)`, `twice = to_title_case(once)`, then compares them. The justification is idempotence, not an independently supplied literal output. `skills/chart-issues/assets/standing-design.md:11` also permits replay of recorded real output. Provenance and correctness justification are distinct requirements.

3. **F3 · Do not require every fake reply to match a recorded real reply.** `round2-A.md:31` and the unresolved difference at `round2-merged.md:12` conflate positive outside-stage replay with negative fault injection. Keep recordings for the former and allow justified synthetic failures at the latter boundary, with the target code executing real.
   Evidence: `skills/chart-issues/assets/standing-design.md:11` expressly permits handwritten negative/edge inputs. `issues/closed/leaf-readiness/failure-log/review-B.md:13-30,45-48` uses fake Herdr failures through the real public CLI to expose missing persisted delivery, with regression `f376eca` and fix `39cb4c0` giving 0/2 → 2/0. No captured production notification failure was required.

   Evidence: commit `2dd1106554851d48ef7c15a4aade9074deea96dc` removes only the invalid `/var/tmp/akrogon-` prefix assertion while retaining containment, existence and 0700 checks. `issues/closed/long-implement/proof-order/implementation/report.md:3,8` records the blockage and deletion. [Chromium's February 18, 2026 discussion](https://groups.google.com/a/chromium.org/g/chromium-dev/c/mI_FaAL4DeM/m/xlSl7brtAQAJ), David Baron's A/B example and Jeffrey Yu's reply, establishes that individually redundant tests can lose coverage when removed together. Include false/obsolete deletion and collective retained-protection review explicitly.
