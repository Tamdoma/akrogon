Scope: today's 7 charts (jev-classifier, base-red, loop-counts, failed-cause, fresh-consultants, usage-windows, door-handover). "Context-tokens" below = sum over a seat's calls of that call's context size (input including cached), so cost ≈ calls × average context, as in common.md. ## 1. Findings

F1. Session floors differ by harness. A fresh codex consultant's first call is 20,676-20,715 input tokens in every session today (01a148d2, 01a14954, 01a14962, 01a14a89 rollouts, first `token_count`). A fresh pi consultant's first call is 5,956 tokens (pi logs 01a1494d-bde8, 01a14962-a839, first assistant `usage`). A fresh claude A call is ~58k (common.md). Everything loaded after the floor is briefs, process text, and tool output, re-read on every later call in the session.

F2. Long sessions tax every later chart. In the shared morning B session (01a148d2), average context per exchange rose from 62k (jev map) to 217k (failed-cause rebuttal); the same 4-call rebuttal shape cost 381k context-tokens early (jev, 07:54) and 860-870k late (base-red/failed-cause, 08:53-08:55). The pi long session started today at 212-247k context (autopilot leftovers), so its 5-call leaf-final-check cost 1.21M context-tokens. It was then cleared (context fell to 8.7k at 07:48, again 78k→32k at 08:37), which is why pi's measured fresh-consultant gain is small (F3).

F3. Fresh-per-chart impact is already measured. Average context per call vs base-red: B −46.1% (fresh-consultants) and −57.3% (usage-windows); C +4.8% and −21.8% (`issues/closed/usage-windows/usage-spans/implementation/report.md:37-51`). C's weak result matches F2 (its "long" baseline had been cleared) and F5 (fresh pi makes more calls and reads more). Even fresh, a consultant reaches 112-141k context by a chart's last exchange (door-handover B leaf-review averaged 130k), because one chart's own reads add 60-110k of material.

F4. Calls per exchange by type (27 codex + 18 pi chart exchanges parsed): opening map 9-19 calls codex, 19-28 pi; fork notes 4-10; leaf review 5-10; rebuttal 4-5. Rebuttals are 33% of codex chart context-tokens (11 exchanges, 6.33M of 18.9M, mean 575k each) and 22% of pi's (7 exchanges, 2.55M of 11.8M, mean 364k each), yet a rebuttal exchange reads almost nothing new: exactly 3 tool calls (read brief, read merged, write return) and 3-14kB of tool output in every rebuttal I inspected (01a148d2 turns at 07:54, 08:23, 08:28, 08:44, 08:53, 08:55; 01a14962 turn at 10:29). All of a rebuttal's cost is warm context.

F5. Same brief, pi makes far more calls than codex. Map: fresh-consultants B 10 calls / 513k vs C 23 calls / 1.48M; usage-windows B 9 / 437k vs C 28 / 1.42M. Whole chart: fresh-consultants B 30 calls vs C 39; usage-windows B 18 vs C 41. Pi fresh also re-reads files inside one session: `questions.md` three times in one exchange (full `cat`, then `sed 70,210`, then `sed 40,105`, on a 56-line file), and `chart-usage.ts` in overlapping ranges (1-430, 300-520, 1-470) across exchanges (pi log 01a14962-a839). The long pi session read each file once (45 `read` calls today, no file read in 3+ turns) because it relied on warm context.

F6. What consultants read. First exchange of a session: the brief, INTAKE, the fork file, the whole `chart-issues/SKILL.md`, the whole `assets/questions.md`, often whole `assets/shapes.md`, plus the live surfaces the brief names. Map-turn tool intake is 145-333kB per consultant (codex 01a148d2 map turns 278kB and 333kB; fresh 186kB, 165kB; door 177kB; pi fresh 274kB, 218kB). Later fork/leaf exchanges read the brief, the fork, and selected sources (5-10 calls, 20-100kB). Codex tool outputs over 30kB are 50-58% of all tool-output bytes in each session, and the largest outputs cluster at 41-43kB, i.e. at the truncation cap (148d2: 17 of 87 outputs >30kB, 640kB of 1,236kB). Truncated text is paid for, not read, and slices get re-read later: door-handover B `cat` INTAKE+SKILL+shapes+questions in one call (40,542B out at a 26k-token cap), then re-read the same files by `sed` ranges in later exchanges.

F7. Briefs are not the cost. All brief files in the 7 charts total 51,183B (~12.8k tokens read once each), average 7.3kB per chart; rebuttal briefs are 350-650B; the prompt that sends a consultant to a brief is 79-255 chars. Briefs are mostly pointers (fresh-consultants map brief: 14 absolute paths), with 2-4 operator sentences repeated verbatim from INTAKE in map briefs (jev 4, fresh 2 long sentences also present in INTAKE). B and C copies of the same brief are 94% identical across 16 pairs; each consultant reads only its own copy, so the duplication costs A, not the consultants. Consultant returns are bigger: 240,457B across 7 charts (maps up to 17.3kB), and merged files 51,378B. A return's full text is generated inside a heredoc/patch tool call, so it also stays in the writer's own context for the rest of the session.

F8. Process text sizes. Chart-issues skill: `SKILL.md` 33,523B (~8.4k tokens) = Shared context ~0.3k, Open ~1.5k, Drain ~0.5k, Take ~1.8k, Handoff ~1.5k, Direct route ~1.5k, Autopilot ~1.2k, footer ~0.1k. Assets total 42,373B (~10.6k tokens): `questions.md` 14,282B (operator-questions head ~1.1k tok, Research ~0.4k, Blind peer exchange ~2.0k at lines 44-53, Optional measurement ~0.1k), `shapes.md` 22,366B (Leaf architecture ~1.3k tok, Preflight ~1.5k, epic/issue templates ~0.8k), `standing-design.md` 5,725B. `SKILL.md:19` stages asset reads for A ("Read questions before an operator round, shapes before creating a chart or handing off, standing design when preparing leaf designs"), and `SKILL.md:6` bans re-reading a file already read in the thread. No equivalent staging is given to consultants, who load all of it up front (F6).

F9. Harness-injected text per consultant session. Codex: `base_instructions` 21,420 chars, developer `<skills_instructions>` 19,021 chars listing every skill, multi-agent developer text 2,671 chars, and the AGENTS.md instructions as a user message, 11,314 chars (first records of rollout 01a14954). Pi: system preamble 10,872 chars; the long pi session also carried a 12,571-char skills section, the fresh pi sessions carry none, which matches the 5,956-token floor (F1). Claude side: `~/.claude/CLAUDE.md` 10,882B plus `~/.claude/rules/haiku.md` 3,155B (~3.5k tokens total); the same ~11k chars reach codex/pi consultants as the AGENTS/preamble text. Of ~30 listed skills, today's consultants touched chart-issues, herdr, watch-issues, learn-issues, seed-issue, and those as files named in briefs, not via the skills list.

F10. Parts a typical chart never uses. All 7 charts: no `direct/` folder (SKILL Direct route, ~1.5k tok, and shapes Direct attempt unused), no epic (epic template unused). `standing-design.md`, Leaf architecture, and Preflight matter only at leaf-drafting, the last exchange. `questions.md` operator-questions head and Research parts are A-facing; a consultant needs only Blind peer exchange (~2.0k tok of the 3.6k file), which 7 of today's briefs point to by section name while consultants `cat` the whole file anyway. `haiku.md` (789 tok) concerns claude subagent routing; no consultant today was claude.

F11. Cost was partly invisible. Every `USAGE.md` in the 6 charts with a pi seat says "seat C: usage unmeasured (unknown harness pi)" (e.g. `base-red/USAGE.md:34`), hiding 0.85-3.30M context-tokens per chart (table above). The 3 morning USAGE files also double-count the shared B session over overlapping legacy windows (B input 10.87M, 8.80M, 10.10M at `base-red/USAGE.md:28`, `loop-counts/USAGE.md:28`, `failed-cause/USAGE.md:28`). Both are already fixed by the usage-spans leaf (report above measures pi calls and average context).

F12. Warm-session noise turns are pure tax. Example in the session listed for jev's B seat (01a144f9): an "FYI, no task now" message cost 1 call at 123,140 context for 5 output tokens. No such turn appears in the 7 charts' own exchanges; every consultant prompt today named a brief.

## 2. Cuts that keep the process the same

Percentages are of one median chart's consultant context (~3.7M). Cuts overlap (a fresh chart's rebuttal is already cheaper, so C2 saves less after C1); do not add them.

C1. Restart both consultants at every chart activation, including multi-chart openings and resumed charts (the peer-restart built today; the morning pass shared one pair across jev + base-red + loop-counts + failed-cause). Saving: for the 2nd and later chart in a shared session, ~1.3-1.9M consultant context-tokens per chart (~35-50%), from B's measured −46% to −57% average context (F3) and the per-exchange growth in F2; zero for the first chart. Process stays the same: same briefs, returns, and records; only the session boundary moves, and blind independence is stronger, not weaker. What it could break: orientation reads repeat per chart (already counted in the fresh measurements), and a consultant loses cross-chart memory the door may have silently relied on. Verify: `chart-usage.ts` output per chart (calls, average context per call per seat) for the next multi-chart pass vs base-red, the same check the usage-spans report ran.

C2. Run each rebuttal in a restarted consultant session, with the consultant's own return file added to the brief's read list (today: "Read only …-merged.md", e.g. `base-red/slots/red-notice-rebuttal-brief-B.md`). Saving: a rebuttal then costs ~4 calls at floor+brief+merged+own return ≈ 100k (codex) or ~45k (pi) instead of the warm mean 575k / 364k (F4): ~300-475k saved per rebuttal exchange, ~0.6-0.9M per typical chart with one B+C rebuttal pair (~20%); less (~200-330k each) if C1 is already applied. Process stays the same: same brief text plus one read, same disagreement-only return file; the rebuttal's job is to check merged against its own written notes, and both are files. What it could break: a consultant may hold evidence in memory that its return file only cites by file:line; a fresh rebuttal must re-open a cited source to dispute a point (allowed, costs a read) or might miss a disagreement it would have caught warm. Verify: run one fork's rebuttal both ways once and compare the disagreement lists; then track rebuttal cost per exchange in `chart-usage.ts` output and consultant logs.

C3. Briefs name line ranges for process text, and the note definition is read as an excerpt, not whole files. Mechanism: briefs give `sed -n '44,53p' questions.md` for Blind peer exchange and section ranges for SKILL/shapes when they are live surfaces; extend the `SKILL.md:19` staging rule to consultants (shapes and standing-design only at leaf review). Saving: avoids loading ~7-10k tokens of process text a consultant does not need yet (F8/F10: SKILL Direct route + Handoff detail ~3k, shapes Leaf architecture + Preflight + templates ~3.5k, questions non-blind parts ~1.6k), taxed on the session's remaining ~20-40 calls: ~150-350k per consultant, ~0.3-0.6M per chart (~8-16%). Process stays the same: identical text, loaded at its stage instead of up front. What it could break: a wrong or stale line range hides a rule the consultant needed (today's charts are about charting itself, so SKILL.md was also the live surface; for those, ranges must cover the sections under study). Verify: grep new consultant logs for whole-file `cat` of SKILL.md/shapes.md/questions.md; average context per call should fall with the same returns.

C4. Add a standing line to consultant briefs: batch independent reads in one tool call, and do not re-read a file already read this session unless it changed (the consultant form of `SKILL.md:6`). Aimed at pi, whose exchanges use 2-3x codex's calls for the same brief and re-read files in-session (F5). Saving: halving fresh pi's map calls (28→~14) and dropping in-session re-reads saves ~0.5-0.9M on a fresh-consultants/usage-windows-style chart (~15-25% of the chart's consultant total; ~30% of pi's share). Process stays the same: same files read, fewer round trips re-reading the growing context. What it could break: batching commands into one call tempts one huge combined output that truncates (F6); keep per-command output caps. Verify: calls per exchange and per chart in `chart-usage.ts` (it now counts pi) against today's 39-41 for pi.

C5. Briefs set a tool-output discipline for the map exchange: scripts print summaries and counts, `rg -n` locates before any `cat`, no whole-file `cat` over ~15kB without a range. Saving: map intake is 145-333kB (F6) and 50-58% of codex tool bytes ride in >30kB, often truncated, outputs; if 15-25% of map intake is truncated-or-reread waste, that is ~10-15k tokens of lasting context per consultant, ~0.2-0.4M per chart (~5-11%), partly overlapping C3. Low confidence on the fraction. Process stays the same: maps still cite file:line; evidence is read in slices. What it could break: a map misses context outside the slices it chose. Verify: tool-output bytes per map exchange in the logs, and no drop in merged-map forks raised from consultant-only evidence.

C6. Small, for completeness. One shared brief file per exchange with slot letter and return path in the prompt (already done for the jev and shared morning maps) instead of near-identical B/C copies (F7), and map briefs drop the operator-verbatim block that INTAKE, read in full anyway, already carries. Consultant saving ~0 (each reads one brief either way); A saves writing a second 0.35-3.4kB copy per exchange plus its own context tax, well under 1% of consultant cost. Same for F12: fold FYI notes into the next brief file and never spend a warm-context call on a no-task message (~70-220k saved per occurrence). What it could break: a prompt must carry the correct per-slot return path, as the single-brief maps already do. Verify: brief files per exchange in `slots/` drops to one; no consultant writes another slot's return.

## 3. Large cuts that would change the process (out of scope, flagged)

P1. Drop the rebuttal round. Saves all rebuttal context, 22-33% of consultant cost (~0.9-1.3M per median chart, F4), but removes the consultants' check on A's merged file. C2 keeps the round and takes most of its token cost.

P2. One consultant instead of two. Saves ~half of consultant context (~1.8M per median chart) and removes blind triangulation, which is the point of the B/C pair.

P3. Cheaper model or lower effort for rebuttal or leaf-review exchanges. Token counts stay, dollar cost per token falls; changes who judges disagreements. All of today's consultant sessions ran high effort.

P4. Shorten the global instruction text itself (~11k chars reaching every session in all three harnesses, F9) or start codex consultants without the 19k-char skills list. The list costs ~4.8k tokens on every codex call (~150-190k per consultant session); pi fresh shows a consultant works without it when briefs name files. This changes what a consultant can discover on its own, so it is an operator harness decision, not a chart-process cut.

P5. Split SKILL.md so A loads Direct route / Autopilot / Handoff text only in those modes or stages (~2.7-4.2k tokens × A's 36-110 calls per chart ≈ 0.1-0.4M A context per chart, using common.md's A figures). Same text, staged loading, but it restructures the skill file A works from; A's side is another slot's focus.
