D2. Factual overstatement in the Q5 example and in K-calls. levers-rebuttal-common.md:12 says an exchange with k peers "today costs 1+k" A calls, and map-merged.md:15 says questions.md requires the idle wait "as separate A calls today". peer-ask already prompts every peer in one call: skills/chart-issues/assets/questions.md:46 repeats `<pane> <return-file> "<text>"` per peer in the same step and runs each prompt and wait "in the same call". What sits outside is the pre-prompt `herdr agent wait` per peer (same line), which A can chain inside one Bash invocation or split across several. Today's count is therefore not fixed at 1+k. My line was narrower: extend existing bundling to "idle-wait plus ask" (map-C.md:85). If the leaf's done-criterion asserts 1+k as the baseline, it can pass on paper while removing fewer calls than claimed. The criterion should name the absorbed work (pre-prompt idle waits, seat-record reads) and measure A calls per exchange before and after on the same exchange count.

D3. Dropped guard on K-restore. map-merged.md:17 and the Q1 lean (levers-rebuttal-common.md:8) both state the rule as "read only what the restored copy lacks", with no changed-content condition. map-C.md:112: "prefix matching must compare content, not filenames", because skills changed mid-session today. If the file changed after the restore snapshot, reading only the tail leaves A running a mixed-version SKILL.md with no signal. The leaf-reads rule and its proof need the changed-file case: when the current file differs from the restored prefix beyond the 20k truncation, re-read in full.

D4. Wrong saving unit, K-output. map-merged.md:16 prices projection at "~1-3% of A each event". None of the three cited sources says per-event at that size: map-A.md:26 says "~1-3% A" for the lever, map-B.md:51 measures one exact case at 0.87% of base-red A, map-C.md:102 says ~0.9-1.5% "of a chart apiece" for the two roster dumps. Read literally, "each event" multiplies past every source. Correct unit: roughly 1% per event, 1-3% per chart across events.

What the lean loses is the only in-chart detector for two named failure modes of the leaves being built: seats drifting back to whole-file reads after range rot (map-C.md:179 relies on fork-boundary readings to expose it), and a seat going unmeasured again as pi did. If it stays off route, leaf-reads should not claim the reading rule holds after adoption, only that it held during its proof.
