# Brief: lean-exchange

## What
The chart-issues door spends fewer tokens per chart with every operator-facing step unchanged. Two changes:
- Consultant reading rule (assets/questions.md, Blind peer exchange): a consultant reads process text by named section for the current step, locates before reading, batches independent reads with bounded output, and reads content it already holds at most once per session; unread sections, changed content and content lost to compaction may be read, and the full source stays allowed when it is the subject of the work.
- One A call per exchange step: every pre-prompt `herdr agent wait` runs chained before `peer-ask.ts` in the same shell call, so no prompt is sent unless all waits passed and a timed-out wait reruns the whole chain; the chained waits, the sequential 5-second prompt timeouts and the collection budget together fit under the command timeout the harness gives that call (A,B). Every peer-wait outcome line, whether printed under peer-ask or on a direct peer-wait rerun, carries the session `herdr agent list` shows for that pane after the exchange (A,C), and `peer-restart.ts` prints each `restarted` seat's new session, or none while herdr still shows the pre-restart session (A,C); the door appends seat entries from those lines instead of a separate `herdr agent list` read.

## Why
A chart's spend is calls times the context each call carries; door seat A is 51-87% of it and every extra A call re-reads A's whole stock (issues/chart/token-spend/slots/map-merged.md). Consultants read whole process files every step, and A spends separate calls on idle waits and roster dumps. Operator request 2026-10-17: cut tokens without changing anything on the operator's end and keep the blind multi-model takes and rebuttals.

Live-run repair scope and final proof (A,B): an in-branch fix stays within the locked decisions, adds no feature and changes no acceptance rule, and gets a fail-first test in the owning code's tests; a fix to the skill text or scripts reruns both measured runs, and the final evidence is valid at the final commit.

## Done-criteria
1. A live autopilot run of the same small handed item runs on the branch skill and on the base skill side by side, each with its own scratch repo, panes and log, with the same seat kinds (claude A, codex B, pi C), models, efforts and harness versions, and fresh seat sessions at the start of each run (A,B). On the branch, total distinct model requests times context across all seats, as `chart-usage.ts` reports for each run, is lower than on the base.
2. In that branch run, each exchange step whose returns arrive within the first peer-ask budget costs A one tool call from the pre-prompt idle wait to the collected returns, with budget reruns counted separately (A,B,C), and A runs no separate `herdr agent list` call for seat records after a restart or an exchange; the report names the base run's calls for the same steps.
3. In that branch run, consultants read process text by section and do not re-read unchanged content they already hold; the report shows the consultants' read calls on both runs.
4. A thinking reviewer comparing both runs finds the branch keeps each seat's independent findings, dissent, rebuttal disagreements, late corrections and complete chart records, and the same operator-facing output shape (rounds, footers, records, pane layout).
5. In a separate exchange outside both measured runs (A,C), when one peer's pre-prompt wait times out, no peer is prompted, the chained call exits non-zero, and a rerun of the whole chain prompts each peer once.
6. Every peer-wait outcome line carries the session `herdr agent list` shows for that pane after the exchange, including a fresh codex session that was null before the prompt; `peer-restart.ts` prints the new session for each `restarted` seat and none when herdr shows no session or the pre-restart one (A,C). Existing outcomes, signals, the `exchange` object and exit codes are unchanged.
