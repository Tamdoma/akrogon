# Rebuttal C to after-merge-merged.md

R1. Fact precision, history line. "6640ab5 (2026-10-14 17:46 ...)" is the author time (17:46:13+02:00 = 15:46Z). Read that way, the 17:01Z stacked merge ran after the drop, which contradicts the conclusion that `closableMembers` closed those members. The commit landed on main at 19:32:55+02:00 = 17:32Z (`git log --format=%cd --date=iso-strict 6640ab5`; 2a1a11f and efabd59 carry the same committer time, so the three were rebased in together). `akrogon` is a symlink to `src/akrogon.ts` in the main checkout, so the running code at 17:01Z was pre-6640ab5. D's conclusion stands; the doc should cite the landing time, not the author time.

R2. Fact wrong, Q1 gap (b): "the member's dependents never dispatch" overstates it. A merged leaf with its tab already closed still gets `dispatchLeaf` -> `completed` -> `dispatchDependents` from any `--all` or `--resume` sweep (`src/next.ts:844-855` sweeps merged leaves first, `:872-874` dispatches dependents on `completed`, `:772-776` returns `completed` for merged) and from a targeted pass on the member (`:1382-1399`). herdr startup runs `next.sh --resume`. So the gap is a delay until the next sweep or targeted pass, not a lost dispatch. Same correction for gap (a).

R3. Missing pitfall, final-shape `.owner` option. Today a copy with no `.owner` file is kept, not removed (`src/reconcile.ts:414`, reason `no .owner record`; framework's kept report shows one such run dir). buildStack creates the copy with `createSparseWorktree` before any owner write can happen, so a builder killed in that window, or a copy made by code that predates the owner file, has no owner and is kept for good under the same rule. The option needs to state that a `batch-*` copy with no `.owner` is removable once nothing names it, and that buildStack writes `.owner` as its first action after the worktree exists.
