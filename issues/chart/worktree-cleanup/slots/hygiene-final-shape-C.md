# Final-shape check C: store hygiene draft

Host facts 2026-10-15 19:40 local, main f3557d8, read-only.

D1. Stopping the leaf slice at `merged` kills the process doing the merge. Seat B runs the transition itself: `akrogon phase <slug> merged --slot B --check --attempt <id>` (`skills/merge-issue/SKILL.md:43`), and the live record agrees (favicon-audit's `merge -> merged` line carries the holder's slot B session). Seat B's shell is inside the leaf slice by construction: `allocate` closes any pane whose shell is outside its scope (`src/next.ts:429-443`) and `adoptShell` moves the shell pid into `<slice>-p<pane>-<pid>-<start>.scope` under the leaf slice with `StartTransientUnit` (`src/scope.ts:122-150`), so every descendant, the agent and every akrogon command it runs, sits in that slice (the F4 scope `akrogon-l59cce9a60bec-pwApYX-880797-...` is exactly such a pane scope holding seat command shells). A `systemctl --user stop <leafSlice>` issued from `commitMove` (`src/phase.ts:140-188`) or anywhere in `phaseCommand` sends SIGTERM to the phase process, the agent and the pane shell. Lost with it: `completeOwner` (`:162`) if the stop comes first, the `logMove` and `visit_start` writes in the `finally` (`:170-179`, so `issues/log.jsonl` never gets the `merged` line), the holder's `mergeWake` (`src/akrogon.ts:86`, so the next holder waits for a later hook), and seat B's last turn. For a stacked merge the member stops do not self-kill (other slices), only the holder's does. Fix: issue the stop from `reconcile`, which runs in `akrogon next` launched by the herdr plugin outside every akrogon slice (herdr's cgroup is the terminal `app-Hyprland-...scope`), never from the phase process; skip a slice that contains the current process, since a seat may run `akrogon next <slug>` itself (compare `/proc/self/cgroup` as `callerScope` does, `src/admission.ts:115-124`); and only once the leaf's tab is gone (after-merge 2a closes it in the merge path), so a seat still finishing is not cut.

D2. Failed leaves fall through both Q2 rules. Leaf-owned items go only when the leaf is `merged`; a failed leaf's temp and its `<slug>-*` entries are owned, so they are not "unowned", and they stay until a merge that may never come. Today reconcile removes a finished leaf's temp, merged or failed, once its tab and panes are gone (`src/reconcile.ts:425-440`, a77c260), and scratch-copy-removal 3a keeps "today's guard" for a failed owner's workers, which still removes a clean one. The draft must say `merged` or `failed` for leaf temp, and keep 3a's failed-owner guard for workers.

D3. "Retired lock files" must be matched by exact name. Two locks in the same git dir are live: `akrogon-verify-runs.lock` (`src/verify.ts:85-86`, taken under every verify record write) and `akrogon-install.lock` (`src/self-update.ts:254`). Deleting a live flock file breaks the exclusion, since the next taker opens a new inode while the holder keeps the old one. `~/.akrogon/run.lock`, `framework-tests.lock`, `.git/akrogon-base-runs.lock`, `issues/.lock` and `runs/last-start` have no writer in src today (grep), so those names are right.

D4. "So its leftover processes end" is not true for Chrome. A browser a seat or check starts lands in its own `app-com.google.Chrome-<pid>.scope`, outside the leaf slice (`learnings/history/2026-10-13-chrome-escapes-cgroup.md`). Its profile under the leaf temp or a `<slug>-*` folder (the `emdash-conversion-ufix-b/.fix-b-evidence/chrome-profile` shape) then stays by the fd check with no clearing fact named. The kept reason should name the holding pid, so "what clears it" is that process ending.

D5. Q3 names "the post-merge pass", which does not exist: `mergeWake` runs `mergePass` only (`src/next.ts:1196-1210`) and the hook-pane path never reconciles (`src/next.ts:1461-1500`). Reconcile runs on targeted, `tab_closed`, `--all`, `--resume` and unpause. If the slice stop and the sweep are meant to follow a merge at once, either after-merge 2a's merge-path close carries them or `mergeWake` must call reconcile; otherwise they wait for the holder's `tab_closed`.

D6. Missed leftover: 51 `akrogon-l*.slice` units are loaded and active on this host with no scope inside (`systemctl --user list-units 'akrogon-l*'`). A slice stays loaded until stopped; `reset-failed` does not touch an active empty slice. The one-time clear needs `systemctl --user stop` of every `akrogon-l*.slice` whose leaf is merged or failed, and the per-merge stop in D1 keeps new ones from piling up.
