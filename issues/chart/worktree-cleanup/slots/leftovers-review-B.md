# Slot B: leftovers review

**F1 — Hidden `state.batch` can require an operator.** `src/leftovers.ts:10–13` hides every `state.batch` entry. The producer assigns that reason merely because a batch record exists, before checking whether the leaf failed (`src/reconcile.ts:289–297`), and also protects the batch directory by that record (`src/reconcile.ts:381–383`). A failed holder whose candidate landed deliberately retains its batch at `src/next.ts:986–989`. The required recovery is `akrogon phase <slug> merge`, printed at `src/next.ts:879–885` and documented at `docs/guide/merge.md:52`. The existing scenario at `tests/batch-dispatch.test.ts:202–228` confirms the failed state and record remain until that command. Thus a stopped, operator-dependent path disappears from leftovers indefinitely.
**Exact fix:** distinguish batch retention awaiting operator recovery from a progressing batch in the kept report, and leave the recovery reason visible. Do not classify every `state.batch` record as in-use. Extend the existing failed-landed-holder scenario to assert its retained path appears in leftovers before the recovery command.

**F2 — A successfully closed tab is shown as needing a person.** `src/reconcile.ts:245–249` closes a merged leaf's own tab successfully, then records `live pane inside` when the owner is still open. `src/leftovers.ts:13` displays that reason. For a clean worktree with no foreign pane, this is an intentional automatic cleanup delay. A later pass reaches removal at `src/reconcile.ts:255–259` after the owner closes, with the tab-closed event itself invoking reconciliation at `src/next.ts:1438–1453`. No person needs to remove the path or close that already-closed tab.
**Exact fix:** give successful own-tab teardown awaiting the next pass a distinct temporary reason and hide that reason. Check for foreign panes before classifying it as temporary, retaining the visible `live pane inside` reason for a real foreign occupant. Add coverage for leftovers immediately after successful automatic tab closure and for a genuine foreign pane that remains.

**F3 — A report read failure becomes a successful `no leftovers`.** The new command calls `readKept` at `src/leftovers.ts:41` and prints `no leftovers` at `:44` for an empty result. The reused reader catches every read, JSON and schema error and returns an empty array (`src/reconcile.ts:26–32`). An existing report that becomes unreadable or invalid is therefore indistinguishable from a successful empty cleanup report. This catch predates the change, but the new command inherits its false empty result.
**Exact fix:** let a genuinely absent report return an empty list, but propagate permission, I/O, JSON and schema errors with the report path. Add a CLI assertion that an existing invalid report fails instead of printing `no leftovers`.

**F4 — The changed test still describes the removed plain-status behavior.** `tests/reconcile.test.ts:99–100` says kept worktrees are reported by plain `akrogon status`, while the test now invokes `leftovers` at `:113` and `:118`.
**Exact fix:** change that comment's plain-status reference to `akrogon leftovers`, retaining the separate `status <slug>` statement.
