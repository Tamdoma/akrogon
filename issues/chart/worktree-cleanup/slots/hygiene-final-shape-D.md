# Final-shape check: Store hygiene (Slot D)

1. **Stopping `leafSlice(repo, slug)` on the `phase: merged` transition — or running `reconcile` in `mergeWake` ("the post-merge pass") — kills the merge process and holder Seat B mid-turn (`src/akrogon.ts:66-88`, `src/phase.ts:154-187, 629-635, 737-745`, `src/next.ts:429, 1192-1208, 1481-1489`, `src/reconcile.ts:245-259`)**:
   - **Evidence**:
     - In the normal merge flow, **holder Seat B** runs `akrogon phase <slug> merged --slot B --attempt <id>` inside its Herdr pane (`holder.state.pane.B`, tab `holder.state.tab`), which `adoptShell` (`src/next.ts:429`, `src/scope.ts:128-166`) placed inside `leafSlice(repo, holder.slug)`.
     - After `commitMove` writes `phase: 'merged'` to `state.yaml` (`src/phase.ts:154`), that **same `akrogon phase` process inside `leafSlice(repo, holder.slug)`** still has to run:
       1. `completeOwner(repo, leaf, true)` (`src/phase.ts:162`), which closes GitHub/Linear sources (`:214-219`) and renames `issues/open/<owner>` to `issues/closed/<owner>` (`:224`);
       2. `logMove` and `appendTiming` (`src/phase.ts:173-179`);
       3. `mergeWake(readGlobal(), committed.repo, committed.to)` in `src/akrogon.ts:86` (`src/next.ts:1192-1208`), which runs `selfUpdate(repo)` (`:1200`) and `mergePass` (`:1203`, building and dispatching the next merge batch).
     - After `akrogon phase` exits 0, Seat B's agent (`claude`/`codex`/`pi`) still has to finish its turn and emit `pane_agent_status_changed` (`idle`), which triggers `akrogon next` (`src/next.ts:1481-1489`) to call `closeMergedTab(owner.repo, rediscovered, await panes())`.
     - Consequence of two rules in the draft:
       - **Draft line 5 ("When a leaf ends (phase `merged`), stop its leaf slice")**: Calling `systemctl --user stop <leafSlice(repo, slug)>` inside `commitMove` / `phaseCommand` kills the caller `akrogon phase <slug> merged` process itself (and Seat B) before `completeOwner`, `logMove`, `selfUpdate`, and `mergePass` run. Moreover, stopping the slice only on the transition event misses already-merged leaves on the host today (`browser-socket-runtime`, F4, whose slice `akrogon-l59cce9a60bec.slice` is still running).
       - **Draft line 15 ("Runs in every reconcile pass (..., the post-merge pass)")**: Today `mergeWake` (`src/next.ts:1192-1208`) does **not** run `reconcile`. If `reconcile` is added to `mergeWake`, `holder.state.phase` is already `'merged'` and `completeOwner` (`src/phase.ts:224`) has already moved the leaf to `issues/closed/<owner>` (`open === false`), so `mergedWorktree` (`src/reconcile.ts:245-259`) will call `closeTab` and `removeMergedWorktree` on the holder's own tab and worktree **while `mergeWake` and Seat B are still running inside that tab**.
   - **Fix**:
     - Stop `leafSlice(repo, slug)` (`systemctl --user stop <leafSlice(repo, slug)>`) **only when the merged leaf's tab closes** (`closeMergedTab` at `src/reconcile.ts:113-119` right after `herdr tab close`) **and in `reconcile` for any `merged` leaf whose tab is not live** (`!tabLive(panes, leaf.state.tab)` or after `closeTab` succeeds), guarded by checking that `/proc/self/cgroup` is not inside `leafSlice(repo, slug)`.
     - Do not run `reconcile` on the holder inside `mergeWake` while the holder's tab is still open (stacked members' tabs are closed by the merge path per `after-merge-remainder` 2a, and the holder's tab is closed by `src/next.ts:1489` once Seat B goes `idle`, which fires `tab_closed` -> `reconcile`).

2. **Contradiction with `scratch-copy-removal` 1a (`batch-*` owner record) and live `run-check` / `self-update` under Q2 (`src/batch.ts:115`, `src/run-check.ts:132, 154-198`, `src/self-update.ts:63`, `src/reconcile.ts:410-428`)**:
   - **Evidence**:
     - **`batch-*` owner record (`scratch-copy-removal.md:42`, 1a)**: `buildStack` writes an owner record (`pid`, `boot_id`, `started`) before `git worktree add` creates `batch-<id>`. `buildStack` runs in `mergeTurn` (`src/next.ts:1078`) before any merge seat is dispatched — when **no leaf of the repo may have a live tab or a slice with a running unit** — and between git commands (or when paused in the 1a done-criterion *"a paused build survives a second pass plus reconcile"*), no child process holds `cwd` or an open fd inside `batch-<id>` or its owner file. Under draft line 11 ("Unowned items ... no slug match ... deleted when no leaf of that repo is running"), `reconcile` deletes a sibling `batch-<id>.owner` file (or `batch-<id>` before registration completes) and then force-removes the paused `batch-<id>` worktree because its owner record is gone.
     - **`run-*` directories in `run-check` (`src/run-check.ts:154-198`)**:
       1. `checkedRun` creates `runRoot` (`leafTemp(repo, slug)/run-<rand>`) and writes `runRoot/.owner` (`:159-162`), then enters `withAdmission` (`:178`). While held waiting for a slot, the `akrogon run-check` process's `cwd` is the worktree/checkout (not `runRoot`) and `out.log` is not opened until after the child exits (`:75`), so **zero processes have `cwd` or an open file inside `runRoot`**. When invoked from the checkout (`slug === 'checkout'`, `src/run-check.ts:132, 176`), the unit runs in `akrogon.slice` (not a leaf slice) and `leafTemp(repo, 'checkout')` has **no slug match**. Because draft lines 10–12 omit `.owner` (`!ownerDead(owner)`), `reconcile` would delete a held `checkout` `run-*` directory when no leaf is running.
       2. Conversely, for an active leaf, draft line 10 says `leafTemp(repo, slug)` with everything in it is *"Deleted when the leaf is `merged`"*, which would stop reaping dead `run-*` directories (`ownerDead(owner)`, `src/reconcile.ts:424-427`) while a leaf is still active (accumulating hundreds of MB per `run-check` across rounds).
     - **`selfUpdate` (`src/self-update.ts:63, 107-108`)**: uses `leafTemp(repo, 'self-update')` (no slug match) during `akrogon next --all` / `--resume` (`src/next.ts:1369`) when no leaf slice may be running.
   - **Fix**:
     - Preserve the `.owner` liveness check (`!ownerDead(owner)`, `src/reconcile.ts:109-111`): never delete a `batch-*` owner record or `run-*` directory whose `.owner` is live (`!ownerDead(owner)`), plus a short creation grace (e.g. 60s) on a `run-*` directory in the narrow window between `mkdtempSync` (`src/run-check.ts:154`) and `writeFileSync(..., '.owner')` (`:159`).
     - Continue deleting dead `run-*` directories (`ownerDead(owner)`) inside any `leafTemp` on every reconcile pass (`src/reconcile.ts:424-427`), even while the leaf is active.
     - Keep `leafTemp(repo, 'checkout')` while any child `run-*` is kept, and keep `leafTemp(repo, 'self-update')` while it is a registered worktree or has a live process/cwd.

3. **Regression on `failed` leaves' `leafTemp(repo, slug)` (`src/reconcile.ts:432-441`)**:
   - **Evidence**: Today `src/reconcile.ts:432-441` deletes `leafTemp(repo, slug)` when a leaf is `merged` **or `failed`** (`const finished: boolean = leaf.state.phase === 'merged' || leaf.state.phase === 'failed'`) once no live tab, pane, or live `run-*` remains (`ensureLeafTemp` at `src/next.ts:462` recreates it if the failed leaf is resumed). Draft line 10 restricts `leafTemp(repo, slug)` deletion to `merged` only, leaving `failed` leaves' temp dirs on disk and in kept reports.
   - **Fix**: Delete `leafTemp(repo, slug)` when the leaf is `merged` **or `failed`** (and its slice has no running unit, no live tab/pane, and no live process/`run-*`), while store entries `<slug>-<anything>` wait for `merged` (matching `scratch-copy-removal` 3a).

4. **`akrogon next --all` inside a repo (`src/next.ts:1401-1411`) and `tab_closed` (`src/next.ts:1441-1445`) do not reconcile every registered repo**:
   - **Evidence**:
     - Draft line 15 states cleanup *"Runs in every reconcile pass (`akrogon next`, `--all`, `--resume`, `tab_closed`, ...) for every registered repo, including repos with no open leaves"*.
     - In `src/next.ts:1401-1411`, when `akrogon next --all` is run from a directory inside a registered repo (`current !== null`, e.g. `/home/ivan/Work/infra/akrogon`), it only calls `reconcileRepos([current], invocation, false)` (`:1410`), skipping the other 10 registered repos; and in `src/next.ts:1414-1428` (`--resume`), `active` filters out paused repos, and `tab_closed` (`:1441-1445`) only calls `reconcile(owners[0].repo, ...)`.
   - **Fix**: Have `reconcileRepos` in `--all` (even when `current !== null`) iterate `registeredRepos(global, invocation).repos` (including repos with 0 open leaves) and run the host-wide cleanup step inside `reconcileRepos` and `tab_closed`.
