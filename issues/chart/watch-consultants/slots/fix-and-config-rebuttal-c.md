# Rebuttal: fix-and-config — slot C

- **Q1 — A's `worktreeStore(repo)` path for base-fix worktrees:** `worktreeStore(repo)` holds leaf worktrees inspected by cleanup/leftover sweeps. Consequence: placing `watch-fix-<case-id>` there risks sweep interference or false leftover alerts while the consultant works; putting the detached worktree under the case folder (or `/var/tmp`) keeps it isolated and tied to case reconcile/cleanup.
- **Q2 — B's advise-only leaf fixes:** Contradicts Lock 2 S2 (2b explicitly authorizes consultant edits and commits in a worktree), and as B notes, `src/next.ts` `promptFor` does not inject external case notes into a leaf seat's prompt. Consequence: a leaf that already failed its 2-cycle recovery cap repeats the same failing seat pass unless the consultant can commit the fix in the idle worktree and resume at `check.review`.
- **Q3 — A/B leaving `commitMove` unchanged for stale `batch`:** B's cited test covers a *landed* candidate (`candidate !== undefined`), which C explicitly preserves; A's framework log succeeded only because `akrogon next` happened to run while the leaf was still `failed` (`reconcileBatch` cleared `batch` when `inMerge === false`). When a watch consult finishes and runs `akrogon phase <slug> merge` before `next` runs on `failed`, `src/phase.ts` `commitMove` keeps `batch` (`applied: true, owner: 'seat', candidate: undefined`), `src/next.ts` `reconcileBatch` returns early for `inMerge && candidate === undefined`, and `mergeTurn` re-dispatches seat B on the stale pre-fix `attempt`/`top`. Consequence: `failed -> merge` becomes race-dependent unless `commitMove` clears `batch` when `leavingFailed && recorded.batch?.candidate === undefined`.
- **Q4 — A/B no S3 pre-filter:** Launching a paid consultant on an unambiguous S3-only reason (e.g. `Missing: <ENV_VAR>` or spend cap reached) adds latency and paid launches with zero chance of an S3-free fix. Consequence: pre-filter only unmistakable S3-only reasons while still consulting on ambiguous/runtime-check reasons.
- **Q5 — A/B top-level `consultant:` key & A's `--attention` on absent config:** Top-level `consultant:` deviates from Lock 1 ("following the existing `slots:` + `harnesses:` convention"), whereas `slots.consultant` fits `globalSchema.slots` and `effectiveConfig` directly. A's `--attention` notice on absent config also conflicts with `consult-loop` `## Taken` items 6 & 11 (`--attention` only for S3 needs); use a non-attention notice once per watch.
- **Q6 — minor misattribution:** C did not ask to add the consultant address to `stop.ts` output; C asked whether to keep `stopped <timer>` unchanged so existing `stop.ts` tests stay green.
