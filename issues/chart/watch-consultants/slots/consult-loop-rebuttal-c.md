# Rebuttal: consult-loop — slot C

- **Q1 — A's `failed`-only trigger:** Under `skills/merge-issue/SKILL.md` `### Shared endings`, a base-red merge verify moves the leaf `merge -> check.fix`, not `failed`. Consequence: waiting for `phase=failed` lets a base red (like `INTAKE.md`'s Bun break) churn multiple `check.fix`/`merge` passes before consulting.
- **Q1 — A's "one consult holding all notify-class leaves":** Bundling unrelated failed leaves in one consult violates Lock 2 S1 ("one consult per root cause") and mixes diagnoses. Consequence: one leaf's S3 stop or context bloat stalls unrelated failures; watch pre-grouping (skipping leaves with failed `blocked=` prerequisites) avoids this.
- **Q2 — misattribution on first ask & B's "not argv":** C did not drop launch `--task` (only rejected argv-only inline prompts without a brief file). Dropping `--task` on `src/seat.ts` `startConsultant` loses `firstTask`'s 60 s start proof and risks dropping sends to booting non-`agy` harnesses (`hc --skill` Delegate a task). Consequence: either keep `--task` carrying the brief pointer (which `agyTask` already delivers via `hc send`) or build wait-then-send start proof into `startConsultant` itself.
- **Q3 — A's unlimited replacement on crash/silent stop:** S4's no-give-up rule applies to a working consultant, not a crashing loop. Consequence: unlimited restarts burn paid launches forever during an outage, expired login, or broken harness config; replace once then notify (`akrogon notice --attention`).
- **Q4 — A's `reason+phase`-only re-consult gate:** Without base SHA and leaf HEAD (and a 2-consult no-advancement cap), a fluctuating error string (timestamps/run IDs) with zero commits re-consults infinitely, while a real fix hitting the same error string is falsely blocked. Consequence: key progress on failure signature + base SHA + leaf HEAD.
- **Q4 — B's "park visibly" on deadlock:** `skills/watch-issues/SKILL.md` does not authorize `akrogon park` on deadlock, and parking without an attention notice hides the tie from the operator. Consequence: leave the leaf in `failed`, record both peers' views, and send `akrogon notice --attention`.
- **Q5 — A's "drain as today, no timer change":** With S4's unbounded wait, `skills/watch-issues/scripts/timer.ts` `poll` queues one due per 20-minute boundary in `dues[]`. Consequence: a multi-hour consult unleashes a burst of redundant back-to-back check turns once idle; coalescing unsent (`sent === null`) dues in `timer.ts` prevents bursts without touching `tick.ts`.
