# Blind notes: consult-loop — slot C

## Q1 Trigger and grouping
- **Pick:** Trigger on every S1 notify-only failure class (`phase=failed` on human prerequisite/defect/unknown, `failed` at the 2-cycle cap or unreadable `issues/log.jsonl`, and base-red merge failures including repeated `merge -> check.fix` bounces citing a base red). Pre-group same-tick failures in the watch: skip leaves whose `blocked=` prerequisite is failed, cluster remaining failed leaves sharing failure phase and root cause by judgment over `failure.reason`, `review-B.md`, and failing command/owner, consult once on the cluster (anchor on the unblocked/merge-head leaf), then re-observe after acting so any still-failing leaf opens a new consult. Reason: honors S1 ("one consult per root cause") without brittle string matching and catches base reds that `merge-issue` routes to `check.fix`. Cost: one pre-read of `review-B.md`/`issues/log.jsonl` per failed leaf in a tick.
- **Rejected:** Exact-string `reason` matching (splits identical causes carrying leaf-specific SHAs/paths/run IDs); one consult per failed leaf without grouping (violates S1 and spawns redundant consultants on a base red or blocker chain); triggering strictly on `phase=failed` (misses base reds bouncing `merge -> check.fix` under `skills/merge-issue/SKILL.md` `### Shared endings`).
- **Evidence:** Direct code (`skills/watch-issues/SKILL.md` `## Judge`; `skills/watch-issues/scripts/observe.ts` `formatLeaf`; `skills/merge-issue/SKILL.md` `### Shared endings`, 2026-11-21); Lock (`forks/signposts.md` `## Taken` S1, 2026-11-21).
- **Pitfalls:** Consulting a leaf blocked by a failed upstream leaf -> exclude leaves with a failed `blocked=` prerequisite until upstream resolves; over-grouping distinct bugs -> re-observe after acting and treat any remaining red leaf as a separate root cause.
- **Unasked:** What threshold makes a `merge -> check.fix` bounce count as a base red before it reaches `phase=failed` (e.g. two leaves failing the same base check, or one leaf after a confirming `--known-red` record in `review-B.md`)?

## Q2 Exchange
- **Pick:** Keep per-consult files outside git under `<globalHome>/watch/<repo>/consults/<consult-id>/` (`brief.md`, `turn-<n>-consultant.md`, `turn-<n>-watch.md`) and send every ask, reply, and follow-up over `hc send` as a short pointer naming the file path, consult ID, turn number, and a one-line status/question, always stamping the resolved literal watcher address (never `$HC_TERMINAL_ID`). Brief carries grouped leaf slugs, exact paths (`state.yaml`, `brief.md`, `design.md`, worktree, `review-B.md`, verify log), prior consult summary if any, S3 stop list, and required return fields (root cause, agreement/question, commits/pushes made, recommended watch move or S3 stop). Reason: satisfies `Never: Edit state.yaml, worktrees or issues/`, avoids dirtying `repo.root`, and makes every turn's body reliably readable even if `hc wait` returns before PTY text renders. Cost: small directory management outside git.
- **Rejected:** Files inside `issues/` or `repo.root` (violates `Never`, dirties checkout, and risks `src/phase.ts` `requireNoIssueFiles` refusals); full context/answers inline in `hc send` only (fragile quoting/newlines, triggers `hc` draft waits, and risks losing reply text if `hc wait` wakes before next-turn input); argv-only first ask without a brief file (inconsistent with `src/seat.ts` `agyTask`, which already delivers via `hc send`).
- **Evidence:** Direct code (`skills/watch-issues/SKILL.md` `## Never`; `src/config.ts` `globalHome`; `src/phase.ts` `requireNoIssueFiles`; `src/seat.ts` `agyTask`; `skills/chart-issues/SKILL.md` `## Open`; `hc --skill`, 2026-11-21); Lock (`forks/signposts.md` `## Taken` S4, 2026-11-21).
- **Pitfalls:** Literal `$HC_TERMINAL_ID` in brief routing replies back to the consultant -> resolve and write the live literal address; late/stale reply from a prior consult -> verify sender address, consult ID, and turn number; secret leakage -> forbid `.env` reads/values in brief and replies.
- **Unasked:** Should old `<globalHome>/watch/<repo>/consults/<id>/` folders be retained indefinitely as the audit archive or pruned by age/count?

## Q3 Wait and liveness
- **Pick:** Stay in the tick's turn looping `hc wait --children any --timeout 180 --json` with no total time cap (S4), reading child state only from wait JSON (never `hc get` between waits). On `reason: message` or consultant turn advancing to `idle`/`done`, inspect the expected turn reply file; if the consultant stopped silently without writing it, nudge once via `hc send`. On a second silent stop, `error`, or unexpected exit (confirming the watch timer child is still live in wait JSON, since `watch-issues stop` kills both), read screen (`hc read`), `hc kill`+`hc rm`, and replace the consultant once with the same brief plus failure note; if the replacement also fails, close it and run `akrogon notice --attention`. On `blocked`, read screen, never use `--force` or answer dialogs, close the consultant, and notify operator. Reason: matches `questions.md` `## Blind peer exchange`, avoids tick races mid-consult, and prevents infinite waits on dead/wedged consultants while honoring S4's no-give-up rule for working consultants. Cost: other leaves wait until the consult finishes.
- **Rejected:** Ending the turn to wait asynchronously (splits one consult across ticks, risks overlapping consults/mutations on the same leaf, and requires new invocation routing in `SKILL.md` `## Invocations`); polling with `hc get` + sleep (consumes hc child news so `hc wait` sleeps until timeout); infinite restarts on crashes (burns paid launches if auth/network/harness is down).
- **Evidence:** Direct code (`skills/chart-issues/assets/questions.md` `## Blind peer exchange`; `skills/watch-issues/scripts/tick.ts` `main`; `hc --skill` Talk, wait, and collect results; `hc wait --help`, 2026-11-21); Lock (`forks/signposts.md` `## Taken` S4/S5, 2026-11-21).
- **Pitfalls:** `hc wait` `reason: message` text arriving only at next turn -> consultant writes its turn file BEFORE `hc send` (and verify harness delivery before handoff); `watch-issues stop` waking wait on child exit -> check timer liveness in wait JSON and exit quietly if stopped; `hc get` swallowing child news -> forbid `hc get` on the consultant during the wait loop.
- **Unasked:** When a consultant hits `blocked` on a harness permission prompt (not an S3 credential stop), should the watch kill it immediately or leave the pane open for the operator to inspect?

## Q4 Loop end and disagreement
- **Pick:** Enforce a per-root-cause progress gate (no global watch cap per S5): record each consult's signature (anchor leaf, `failure.cause@phase`, failing check/error, base SHA, leaf HEAD) in the Q6 durable index; allow a subsequent consult on the same root cause only if real progress occurred (new base SHA, new leaf HEAD, or changed failure cause/phase), and stop consulting + notify (`akrogon notice --attention`) if the same signature recurs without progress or after 2 consecutive consults fail to advance it. On peer disagreement, allow up to 2 evidence-backed challenge turns over `hc send`; because peers are equal, only mutual agreement acts — any S3 stop by either peer or persistent deadlock after 2 challenges closes the consultant, records both views, and notifies the operator. Reason: honors S5 (no total cap, equal peers) while preventing infinite paid loops on unfixable failures. Cost: requires comparing SHAs/signatures against the durable index before launching.
- **Rejected:** No per-root-cause stop rule (infinite paid loop every 20 minutes on an unfixable failure); a global consult cap per watch (violates Lock 2 S5); letting watch or consultant unilaterally override on disagreement (violates S5 "both the watcher and the helper are equal").
- **Evidence:** Lock (`forks/signposts.md` `## Taken` S3/S5, 2026-11-21); Direct code (`skills/watch-issues/SKILL.md` `## Judge`; `skills/watch-issues/scripts/observe.ts` `formatLeaf`, 2026-11-21).
- **Pitfalls:** Compaction erasing consult history and restarting an infinite loop -> read prior signatures from the durable Q6 index outside git; endless polite debate between equal peers -> hard 2-challenge-turn tie-break to operator notice.
- **Unasked:** Should an operator pushing a new commit to `main` or the leaf branch automatically re-enable consulting on a previously stopped root cause (naturally handled if keyed on base + leaf SHAs)?

## Q5 Queued ticks
- **Pick:** Coalesce unsent dues in `skills/watch-issues/scripts/timer.ts` `poll` so at most one unsent due (updated to the latest `dueCount`) waits behind any in-flight sent due while the watcher is `working`; leave `tick.ts` unchanged (`due <= receipt` already accepts a skipped higher `due`). Reason: with S4's unbounded wait, a multi-hour consult would otherwise unleash a burst of stale back-to-back ticks, yet keeping one pending due ensures other leaves are checked immediately once the consult finishes. Cost: ~5 lines in `timer.ts` and updating any timer test that asserts draining multiple queued dues.
- **Rejected:** Draining every queued due after a long consult (fires redundant consecutive turns burning tokens and risking duplicate actions); dropping all missed dues while working (delays checking other healthy leaves by up to 20 minutes after a long consult).
- **Evidence:** Direct code (`skills/watch-issues/scripts/timer.ts` `poll`; `skills/watch-issues/scripts/tick.ts` `main`, 2026-11-21); Lock (`forks/signposts.md` `## Taken` S4, 2026-11-21).
- **Pitfalls:** Coalescing an in-flight `sent !== null` due breaks resend/receipt logic -> only coalesce entries with `sent === null`; stale receipt refusal -> verified `tick.ts` only refuses `due <= receipt`.
- **Unasked:** Do existing `skills/watch-issues/` tests assert multi-due draining (needing a cited `Test-Change:` trailer)?

## Q6 Record
- **Pick:** Persist each consult outside git under `<globalHome>/watch/<repo>/consults/`: one human-readable `<timestamp>-<id>.md` (root cause, grouped leaves, SHAs before/after, consultant recipe/address, peer exchanges/disagreements, commits/pushes, `akrogon phase` moves, S3 stops) plus one append-only JSONL line in `index.jsonl` (machine-readable for Q4's progress gate across compactions), and emit a non-attention `akrogon notice` when a consult pushes to `main` or moves a leaf (`--attention` only for stops/deadlocks). Never write into `issues/log.jsonl` or the repo checkout. Reason: gives the operator a complete post-absence audit trail without breaking `src/log.ts` `readLog` or `Never: Edit ... issues/`. Cost: small per-repo folder under `~/.akrogon/watch/`.
- **Rejected:** Appending consult rows to `issues/log.jsonl` (crashes `src/log.ts` `readLog` because `logSchema.parse` requires move fields across `phase`, `status`, `timing`, and watch cycle counts); conversation transcript / 5-line reply only (lost on compaction, poor auditability for autonomous `main` pushes); `akrogon notice` only (ephemeral toasts cannot back Q4's cross-compaction signatures or full reasoning).
- **Evidence:** Direct code (`src/log.ts` `readLog`, `logSchema`; `src/config.ts` `globalHome`; `src/akrogon.ts` `notice` case; `skills/watch-issues/SKILL.md` `## Never`, `## Reply`, 2026-11-21).
- **Pitfalls:** Dirtying git or breaking `log.jsonl` -> isolate all consult files under `globalHome()`; secret leakage -> forbid `.env` values in records and notices; discoverability -> print the consult record path in the watch's reply and notices.
- **Unasked:** Should `akrogon status` print a one-line summary or pointer when unreviewed watch consults landed while the operator was away?
