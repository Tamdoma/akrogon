# consult-loop proposed final shape (A's pick under autopilot), for one focused check

Changes from A's notes after the rebuttals are marked [changed].

1. Trigger: a consult starts only for a leaf in `phase=failed` that the Judge today only notifies on (human prerequisite or defect class, `failed=unknown`, recovery cap). No trigger on `merge -> check.fix` bounces. Reason: S1 names today's notify cases; framework issues/log.jsonl 7550-7551 shows the real Bun base red went `merge -> check.fix` (11:34:26) then `check.fix -> failed` (11:35:29), so the base case reaches `failed` through the existing path. Dissent B,C (rebuttals): a base red may churn check.fix passes first.
2. [changed] Grouping: one case per root cause. The watch picks an anchor leaf (an unblocked leaf first, never one whose `blocked=` prerequisite is failed) and the case attaches other failed leaves when the peers explain how the same defect caused each; the grouping and its reason are recorded in the case (model choice, no text match). After a fix, the watch re-observes; a leaf still red stays in the same case unless the peers find a different cause, which opens a new case (B).
3. Case folder outside git: `<globalHome>/watch/<repo>/consults/<case-id>/`. `brief.md` holds the literal watcher address, case ID, anchor and attached leaves with observe lines and paths (state.yaml, brief, design, review-B.md, worktree, verify log), the S3 stop list and the locks; never `.env` values.
4. [changed] First ask is the start verb's `--task` pointing at `brief.md` (keeps the 60 s start proof, C). Every later message either way is `hc send` naming the case ID and a file in the case folder; the sender writes the file before sending. Reason: `hc --skill` says a message "arrives as your next input, possibly late", so the body may reach a non-claude watcher only after its turn; the file is read inside the turn on the wake. Dissent B: a short complete answer could travel in the message alone.
5. Wait: in-turn `hc wait --children any --timeout 180 --json` loop with no give-up time; child state read only from the wait JSON, never `hc get` on the consultant between waits; a wake whose sender or case ID does not match the open case is recorded and ignored.
6. [changed] Liveness: a silent stop gets one nudge naming what is missing. A second silent stop, an error, an exit or `blocked` (its dialog is never answered, no `--force`) closes that consultant (`hc kill` + `hc rm`, screen saved to the case) and starts one replacement on the same case; a failing replacement ends the case with `akrogon notice --attention` (an outage or login is S3) (C).
7. [changed] Stop mid-case: the timer's exit seen in the wait JSON means the watch is ending; the watch reconciles the case (reads the remote tip and leaf states, records any commit or push already made), closes the consultant, starts no successor, and reports (B).
8. [changed] Loop end and re-consult gate: a case ends on a verified fix, an S3 stop, or no permitted check left. A disagreement is settled by the smallest permitted check that tells the two predictions apart (B); with none left, both views are recorded, the leaf stays `failed`, and `akrogon notice --attention` names the case (C). A closed case stores its signature (anchor `failure.cause@phase`, failing command, base SHA, each leaf HEAD); no new case opens while the signature is unchanged (mechanical); after a change the watch judges whether it bears on the recorded blocker and records the reason (B).
9. A fix stands on evidence: the repo's configured `checks` green on the pushed tree, fast-forward push, no S3 stop crossed.
10. [changed] Queued ticks: `timer.ts` `poll` keeps any sent due and at most one unsent due, updated to the latest number, while the watcher works; `tick.ts` unchanged since it accepts a higher due (B,C).
11. Record: the case folder is the record (`case.md` for people, signature and status machine-readable beside it), opened before any work is authorized and reconciled on restart (B); its path is in the watch reply; a non-attention `akrogon notice` on each push to main or leaf move, attention only for stops (C); never rows in `issues/log.jsonl`; case folders are kept, no pruning.
