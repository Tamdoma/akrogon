## Forks

- **Q1. What proves two leaves need the same repair?** Options are a provisional group the peers confirm against a common failing command, revision and cause, or separate diagnoses until one verified fix accounts for both. A matching reason can hide two defects. Different messages can come from one broken base. Keep unresolved leaves visible and reopen the diagnosis if a leaf stays red after the fix. `skills/watch-issues/scripts/observe.ts` (`formatLeaf`) supplies phase, cause and free text. `skills/merge-issue/SKILL.md` (Shared endings) supplies command, output, base and tested head.
- **Q2. What proves a consultation finished?** Options are an attributed hc reply carrying the result, or an attributed reply pointing to durable evidence. Send the helper the watch's literal return address, affected slugs and phases, failure evidence, relevant brief or decision, current grant and stop boundaries. Ask for diagnosis, affected leaves, exact actions already taken, commit and check evidence, and remaining work or the specific operator decision. A late reply needs matching to the current case before acting. `src/seat.ts` (`startConsultant`, `firstTask`, `agyTask`) passes the first task in argv for non-agy harnesses. Preserve hc send for the first question as well as subsequent exchanges.
- **Q3. Who writes where while a fix is in flight?** For a leaf-local defect, choices are a consultant commit in the idle owner's worktree or a separate repair commit handed to the owner for integration. For a proven base defect, choices are a checked fast-forward push from a clean worktree based on the configured remote tip or landing a dedicated fix leaf through the normal merge path. A live owner can edit concurrently, and pushing from a failed leaf's branch can publish unrelated work. A remote advance requires retesting the integrated change. `skills/merge-issue/SKILL.md` (attempt solo, Shared endings), `src/phase.ts` (`moveGuards`, `transition`).
- **Q4. What releases each affected leaf?** Options are to resume once its proven shared fix is reachable on the configured target, or also require a leaf-specific reproduction to pass first. A local commit alone cannot unblock other leaves. Reobserve each leaf, verify its blocker and required seats, resume a still-failed leaf with `akrogon phase <slug> <failure.phase>` without `--slot`, then run `next`. If phase succeeded but dispatch failed, read current state before retrying. Ask how to recover the original phase when the failure record is missing. A merge red may already be in `check.fix` with A working. `src/phase.ts` (`transition`, `moveGuards`), `skills/merge-issue/SKILL.md` (Shared endings).
- **Q5. Which seat interactions gain an exception?** Options are peer messages only, with leaf seats continuing through existing dispatch and steer rules, or evidence-backed instructions to a blocked leaf seat. Spell out authority for busy-seat notify-only cases as well as failed leaves. Neither peer can grant a login, spend, host change, history rewrite or decision change. An agy startup permission prompt is distinct from a leaf asking for an operator decision. `skills/watch-issues/SKILL.md` (Judge, Never), `src/seat.ts` (`agyTask`).
- **Q6. Who keeps the operator's record when the helper exits?** Options are a watch-authored decision and outcome in the watch conversation, or a durable per-cause record maintained by the watch and linked from its reply. The consultant supplies evidence for either. A transcript alone makes cross-restart deduplication harder. A second record needs a defined location outside protected lifecycle state or a narrow write exception. Capture disagreement and the actual remote revision, including a push that succeeded before the reply was lost. `skills/watch-issues/SKILL.md` (Reply, Never), `skills/watch-issues/scripts/tick.ts` (`main`, timer receipt).
- **Q7. How does an older installation acquire the machine recipe?** Options are a global `slots.consultant` or a separate global consultant field using the existing slot schema. For an absent entry, choose a migration that writes the default or require configuration on first use while ordinary leaf and chart commands still work. Validate the harness template when applicable. Some installations lack an agy template. The real-machine N2 edit is authorized after landing. Preserve chart callers' explicit harness flags and existing repo/issue A/B overrides. `src/config.ts` (`globalSchema`, `repoSchema`, `seats`), `src/akrogon.ts` (seat case).
- **Q8. Which consultant survives a completed case, a stop, or a watcher replacement?** Reusing the same helper saves startup but carries old decisions. Replacing it per case needs evidence the former one exited before starting another. Use a watch-specific name and verify repo, role, parent and live address before any cleanup. Chart doors already own `<prefix>-slot-<x>`. Explicit stop currently removes only the timer. A parent-terminal exit and a watcher process or transcript replacement inside a surviving terminal are different events. Decide whether an in-flight fix drains or stops at a safe point, and who reconciles a commit or push made just before stop. `src/hc.ts` (`consultantName`), `src/seat.ts` (`startConsultant`, parent with `outlive: false`), `skills/watch-issues/scripts/stop.ts` (`main`), `timer.ts` (`readWatcher`, `poll`).
- **Q9. What should happen during and after an indefinite wait?** Options are to drain every queued timer fire after the answer or coalesce elapsed fires into one fresh observation. Today each boundary creates a due item, held while the watcher works. A check-in while the peer works is no reason to give up. A silent completed turn, crash, blocked dialog or failed delivery warrants a different response. Decide when to nudge, when to reconcile the previous attempt before replacing it, and how peers resolve disagreement with fresh evidence. A timer is also a child, so identify whose event woke the wait. `skills/watch-issues/scripts/timer.ts` (`poll`), `tick.ts` (`main`), `hc wait --help`, `skills/chart-issues/assets/questions.md` (Blind peer exchange).
