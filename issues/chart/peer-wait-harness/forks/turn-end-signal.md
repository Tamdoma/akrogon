# Turn end signal

## Question
Q1. When herdr shows a non-Claude peer idle and no return file exists, what does peer-wait report: `failure` only on an end signal proven for that harness (claude transcript, pi hook authority, codex rollout) with every other kind waiting out the budget; never `failure` on idle for any non-Claude kind; or today's 10-second rule?

Q2. A peer with no proven end signal that has really stopped returns `budget` on every rerun, and the door reruns at once on `budget`. What stops that: the door reports to the operator after a set number of idle budgets with no `working` seen, or the door keeps rerunning until the operator steps in?

Earlier wording, kept for the record: Q1 asked keep waiting / per-harness signal / herdr agy fix upstream; Q2 asked whether `done` (taken as process exited) still gives `failure`. That Q2 rested on a wrong premise: herdr `done` is Idle not yet seen (A,B,C).

## Taken
- Operator 2026-10-15: `1a | 2a`. `failure` only on an end signal proven for that harness; a kind with no proven signal never fails on idle; after one idle `budget` for such a kind the door stops and asks the operator.
- Reason: fast, correct failure for the harnesses in use and no false failure for any other kind; a stuck unproven wait reaches the operator after one budget instead of looping.
- Foreclosed: never failing any non-Claude kind on idle (1b); today's 10-second rule for every non-Claude kind (1c); rerunning budgets until the operator steps in (2b); an agy turn reader and an upstream herdr agy fix (Off route).
- Final shape 2026-10-16 after the final-shape check ([draft](../slots/signal-final-shape-draft.md), returns [B](../slots/signal-final-shape-B.md), [C](../slots/signal-final-shape-C.md)):
  1. peer-wait's turn check returns open, ended or unproven per peer, read from `herdr agent list`. claude: transcript check unchanged. pi: ended on herdr `idle`/`done` only while `agent: pi`, `agent_session.source: herdr:pi` and `screen_detection_skipped` is literally `true`; the list schema keeps `screen_detection_skipped` as `z.boolean().nullish()` and `source` optional; anything else unproven (B F1). codex: the rollout `~/.codex/sessions/*/*/*/rollout-*-<session>.jsonl` (exactly one match); peer-wait records the rollout boundary (byte length) before the prompt is sent and binds only a `task_started` written after it, at the first grace check where one is found, holding and retrying until then; ended on that id's `task_complete` or `turn_aborted`; no session, zero or several matches, or no `task_started` after the boundary: unproven (B F2, C F4). Every other kind, agy included: unproven.
  2. After the existing 10 s grace with no return file and no `working`: ended gives `failure`; open or unproven keeps waiting; the deadline gives `budget`. `idle` and `done` are handled alike. `agent_status` stays in the schema and is re-read at each grace check; `blocked` gives the `blocked` outcome (C F3).
  3. Identity is re-read at each grace check. A kind change is an error for every kind; a session change from one non-null value to another is an error for claude and codex; for pi a session change is ignored while herdr:pi hook authority holds, and loss of that authority makes the peer unproven; a session null at start and set later is adopted; an agent gone from the list is the existing `No herdr agent on pane` error (C F1).
  4. The exchange identity (kind, first session, codex boundary, bound turn id) carries across `budget` reruns, so a rerun binds the same turn (B F3); the carrying form is open for the plan, for example a CLI argument echoed in the outcome line.
  5. The outcome line gains `signal: proven|unproven` (B F4, C F2). chart-issues questions.md rule: an outcome `budget` with status `idle` or `done` and `signal: unproven` is reported to the operator before any rerun, and the operator's answer decides; every other `budget` is rerun at once, as today.
  6. Tests extend the existing fake herdr and peer-wait fixtures: per-pane status persisted across `agent wait` and `agent list`, list entries with session `source`, `kind` and `screen_detection_skipped`, a scripted session change, a mixed pi/codex fixture where codex has `screen_detection_skipped: null` (B F1), a codex rollout holding an older completed task before the boundary (B F2), and a temporary HOME with fixture claude and codex session files. No machinery leaf.
