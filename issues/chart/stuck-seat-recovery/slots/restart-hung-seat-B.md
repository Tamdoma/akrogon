- **F2 · Remove the shared-dialog race before building recovery around it.** Pi documents parallel tools and nested cancellation in `D/extensions.md:115`, and sequential execution for shared mutable state at line 134. `subagent_spawn` supplies no sequential execution flag (`S/tools.ts:148`). - **F3 · #32 is a different immediate defect.** A child has already existed and its shutdown misses a deadline (`S/manager.ts:1098`, `:1125`). Both involve asynchronous work that cannot settle, but removing the held blocked claim does not resolve #35, and fixing confirmation concurrency does not retire #32's uncertain child. Keep fault-status ownership with pi-extensions rather than treating every blocked seat as restartable.
- **F4 · Silence cannot prove permanent failure.** An observed process exit proves that process ended. An owner event identifying an irrecoverable operation, or a demonstrated lost resolver with no remaining completion path, can establish a specific failure without elapsed time. An exited subprocess alone does not prove its parent is hung: the parent may still be handling its result. A static screen, unchanged transcript, `working`, or an unacknowledged Esc cannot distinguish an indefinitely stuck live tool from a slow one without a deadline or additional causal evidence. Herdr's Pi lifecycle authority does not independently infer progress from screen silence (`H/website/src/content/docs/agents.mdx:42`). Its `agent wait` observes statuses, not completion of a particular turn, and may return immediately on a current matching status (`H/website/src/content/docs/cli-reference.mdx:305`). Receiving a timeout is evidence of exceeded policy, not proof of deadlock.
- **F5 · The locks and the watch need explicit reconciliation.** `A/issues/chart/seat-stall-detection/forks/no-akrogon-detector.md:22` forbids elapsed triggers and explicitly accepts permanently invisible silent stalls at line 23. The later correction retains the conditional one-hour notifier (`A/issues/chart/stall-notifier-removal/forks/delete-notifier.md:24`). It is not a restart authorization or guaranteed wakeup. Akrogon's plugin runs on startup and pane events (`A/plugin/herdr-plugin.toml:7`), so total event silence supplies no new invocation. Separately, the operator-started watch already uses a 20-minute cron, with a seven-day expiry (`A/skills/watch-issues/SKILL.md:16`). Do not introduce a new daemon, disguise a deadline as an event, or assume this watch runs forever. No-clock fault recovery and time-based silence recovery are different promises.
- **F6 · Herdr can launch, but has no documented stop/restart operation.** The command surface is `H/website/src/content/docs/cli-reference.mdx:284`. `agent start` requires the existing pane's shell to own the foreground, with no agent or other command running (`:301`). Sending Ctrl+C is terminal input (`:309`), not confirmed process termination. `pane release-agent` releases reporting authority, not the process (`:241`). `pane process-info` exposes shell PID, foreground group, and process metadata (`H/src/api/schema/panes.rs:441`), but no process birth identity. A safe stop implementation therefore needs a process-ownership primitive, with stable process identity and confirmed exit. Reusing the documented CLI alone does not supply it.
- **F7 · Killing only Pi can leave writers alive.** Children use in-process SDK sessions (`S/child-session.ts:1`), but worker shell supervisors are detached process groups (`S/worker-shell.ts:184`). Their script executes the command *before* reading the parent pipe (`:10`), so losing that pipe need not interrupt a running command. Normal retirement kills the owned group and waits for exit (`:124`, `:142`). Explicit daemon/setsid escapes are outside even that guarantee (`:156`). A parent PID kill or foreground-group kill cannot establish that every child writer stopped. A restart must use established containment/ownership to stop all owned writers, or refuse relaunch when ownership is unknown. Parent-only legacy seats cannot be retroactively declared safely contained.
- **F8 · Durable work survives; execution state does not.** Preserve the existing worktree, branch, dirty files, leaf phase, completed slots and peer. Akrogon already validates and reuses worktrees (`A/src/next.ts:230`). A killed process loses unsaved buffers, live tool continuations, in-memory approvals (`S/manager.ts:274`) and manager ownership state. Persisted session history can survive, but it cannot restore those objects. Pi supports an exact session path or ID (`D/cli.md:89`), while `--continue` selects the newest session for the project (`:85`), potentially the other seat. Fresh sessions lose conversational context unless given durable artifacts and the old transcript reference. Neither fresh nor resumed sessions roll back completed external side effects.

## Safe restart contract

These are required properties of the proposed verb, not claims about an existing command.

1. **R1 · Claim exactly one recovery.** Bind repo, leaf, phase, slot, pane, session and stable process identity to the evidence. Coordinate with `next`'s existing lock (`A/src/next.ts:682`). Reject changed ownership, finished slots, legitimate human approval, and unresolved prior recovery. Record a durable attempt before stopping so simultaneous watch/event calls cannot both relaunch. Do not hold the shared lock through an unbounded shutdown.
2. **R2 · Stop the owned execution, preserve the pane.** One cooperative abort, then bounded termination and escalation through the process owner if authorized. The existing watch's ten-second wait is a possible grace policy, but its default settled statuses include blocked, so require explicit idle/exit evidence and the same identity. Confirm all owned writers are gone and the shell is foreground before launch. If containment is incomplete, notify and stop recovery. Do not use `pkill pi`, close the pane, or clear reporting authority to simulate exit.
3. **R3 · Relaunch the current phase once.** Re-read durable phase/done state after stopping because the seat may have finished just before termination. Reuse configured harness/model/effort (`A/src/next.ts:220`), normal start/readiness, and canonical phase routing (`:422`, `:431`, `:458`). Preserve prompt-delivery reconciliation (`:423`, `A/src/session-file.ts:40`). Do not transition through `failed` merely to restart: `A/src/phase.ts:95` resets done, verdict, prompt and attempt state. Add the chosen recovery context to phase reentry and reconcile partial external actions before repeating them.
4. **R4 · Bound recurrence independently of delivery.** Allow one automatic restart per leaf/phase/slot until meaningful recovery is established. Persist the consumed attempt across watcher restarts and new session IDs. A delivered prompt is not recovery: current dispatch resets delivery attempts at `A/src/next.ts:361`. Repeated hangs notify with cause and stop instead of producing a restart loop. Amend `A/skills/watch-issues/SKILL.md:40` and its kill prohibition at line 49 only to permit this verb. Keep arbitrary watcher kills and answers to permission prompts forbidden.

### Q1 · May silence trigger recovery even though it cannot prove a deadlock?

This changes the most other choices. #35's “no session writes for N minutes, esc ignored” necessarily uses elapsed time. Keeping the earlier lock allows recovery of known failures, but cannot satisfy general unattended recovery from silence.

Research: **operator**, #35 and the 2026-09-18 locks, read 2026-09-28. **better-than-training**, Herdr status/wait contracts in F4–F5. Erlang supervision also separates child termination from bounded shutdown, rather than treating a live process as proven dead (source S3).

- **A (recommended)** Explicitly allow a bounded silence policy in the existing operator-started watch, plus finite stop/exit waits. Keep the no-new-daemon rule. Start with the existing one-hour scale, measured from the current operation's last persisted activity rather than total busy age, then one abort with a ten-second grace. Inspect the current operation and exempt a known human prerequisite or a deliberately authorized longer wait. This makes the unattended intent attainable while admitting false positives.
- **B** Retain the no-clock lock. Recover only from identity-bound terminal evidence or an owner-reported irrecoverable operation. Accept that unreported live hangs can wait forever.

Pitfalls: One hour is a proposed operating policy anchored to the existing notifier, not a measured safe latency. Log activity can continue during useless work, while useful work can be silent. Missing session telemetry means unknown evidence, not automatic eligibility. Option A works only while the explicitly started watch is alive. It changes the prior lock and needs an operator answer.

### Q2 · May the watcher stop and relaunch a qualifying seat without the operator?

The current skill expressly forbids killing a process. Permission to send Esc does not include forced termination, and a restart must not erase unfinished work or create a second writer.

Research: **operator**, #35 requests an absent operator and replacement watcher. **better-than-training**, F6–F8 and the akrogon paths in R1–R4. **practitioner**, Featonby's AWS retry experience requires accounting for side effects before retrying (S2).

- **A (recommended)** Yes, only through one akrogon recovery verb implementing R1–R4. It owns stop, confirmation, state re-read and phase reentry. This gives the watcher one auditable action rather than shell-level kill decisions.
- **B** Notify only. The operator diagnoses ownership and restarts. This preserves the current prohibition but does not meet #35's unattended outcome.

Pitfalls: New process containment may be needed before an arbitrary hung seat is safely restartable. Do not promise that a new akrogon command alone solves this. Restart also does not fix the reproducible approval bug. Genuine outside-root questions remain human prerequisites unless separately preauthorized.

### Q3 · Should phase reentry start a fresh session or resume the exact interrupted one?

Both preserve the worktree. They differ in conversational context and the chance of carrying a damaged pending-tool conversation forward.

Research: **better-than-training**, `D/cli.md:85`, `A/src/session-file.ts:11`, and F8. **practitioner**, Justin Young's agent-harness work uses durable progress and Git state to let a new session continue (S1).

- **A (recommended)** Fresh session for the same current phase, with the old transcript path, recovery reason and instruction to inspect existing work before acting. Preserve the old session file. This avoids treating in-memory tool state as resumable and makes reentry explicit.
- **B** Resume the exact captured session file and append recovery context. This retains more reasoning, but requires checking Pi's interrupted-tool reconstruction and the selected harness's session contract before delivery.

Pitfalls: Fresh reentry costs context and may repeat side effects unless reconciled. Exact resume does not restore child handles, approvals or external commands. Never use project-wide `--continue` for two seats sharing a worktree. Launch templates must honor the selected policy rather than inherit conflicting session flags.

## Challenge check

The strongest challenge to automatic restart is incomplete ownership: detached writers may outlive the harness, so the stopped parent is insufficient evidence for safe reentry. The strongest challenge to the detection recommendation is that the operator previously chose permanent silence blindness. Neither limitation can be settled by calling a timeout “proof.” Repairing the approval race removes this particular failure class with fewer moving parts, but it does not make general unattended recovery possible under an absolute ban on clocks.
