- `brief.md:11` and `design.md:12-13` define a failure as dropping only “that consultant” and continuing with the rest, but the required reverse close-all sequence can make several seats unusable before one command fails. For example, if C closes and B close fails, C is gone and B is stale; if the first split fails, every consultant is gone. The remaining seats therefore cannot always continue. Fix: define the failure result from the reported state: under autopilot retain only consultants that completed a fresh start, and drop every supplied seat that is closed, failed, or still carries its pre-restart session; attended mode still stops and reports. Add failure tests asserting the resulting active/dropped seat set at each close, split, and start point.

- `design.md:21` says the fake already answers `pane process-info` for argv capture and supports the required failure tests, but `tests/fake-herdr.ts:319-331` always returns `foreground_processes: []`, and its close handler has no scripted failure (`tests/fake-herdr.ts:333-337`). Criterion 1 cannot seed/read launch argv and criterion 2 cannot exercise close failure with that fixture. Fix: explicitly require and own fake fields for foreground process records and a scripted close failure, then test that the restart script selects the foreground-process-group leader's argv and preserves `argv.slice(1)` as separate arguments.

- The command interface omits two literal `process-info` rules needed to build the promised commands. `process-info` exposes a foreground process-group id and a process array (`tests/fake-herdr.ts:323-330`), while `design.md:28` only says “argv[0]” and never says which process; the established split command requires `--cwd <root>` (`assets/questions.md:46`), but neither `brief.md:4` nor `design.md:25-28` defines where `<root>` comes from. Fix: specify that the launch record is the foreground process whose `pid` equals `foreground_process_group_id`, fail before closing if exactly one cannot be found, and either pass the registered root as an argument or state that the script's cwd is the root and use it for every split.

- `design.md:29` leaves open whether the command waits for idle, although the binding decision already says restart after every prompted turn is collected (`design.md:6`). Herdr idle is not proof that a peer turn ended, which is why `peer-wait.ts:293-310` uses a grace period and harness signal; conversely, a return file can finish collection while Herdr still says working (`peer-wait.ts:291`). Fix: remove this plan choice and make “all prompted exchanges collected” a caller precondition in the skill. The restart command must not substitute an idle wait for that condition.
