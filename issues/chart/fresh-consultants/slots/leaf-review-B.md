- **F1 · Batch failure contradicts “drop that consultant and continue”.** `brief.md:4,11-12` closes all peers before recreating them and stops every later step on one error. Example: C and B close successfully, then B's split fails. C is also gone, although Q3 drops only B. A failed close of B after closing C has the same problem. `design.md:12,25` supplies neither a usable remaining C nor a recovery interface. **Exact fix:** settle and record the batch failure rule before handoff. With the specified global stop and no retries, return a per-seat state for every input, preserve already completed replacement mappings, and let autopilot continue only with seats whose restart completed. Explicitly decide what happens to every remaining seat, including untouched old panes and closed-but-not-recreated peers. Dropping all incomplete seats is one concrete implementation, but broadens Taken Q3 and needs a final-shape correction. Add a criterion covering a failure after another consultant was closed, not only isolated operation failures.

- **F2 · Dropped seats get reassigned letters.** `design.md:25` derives letters from argument order starting at B, while `brief.md:12` excludes dropped consultants and `skills/chart-issues/SKILL.md:37` preserves a replaced session's seat letter. If B was dropped and C remains, the next call labels C as B. That changes attribution and can treat the dropped seat as revived. **Exact fix:** make original seat identity an explicit input, for example `peer-restart.ts <A pane> <seat> <pane> [<seat> <pane>...]`, and preserve those letters in output, names and subsequent seat entries. Define layout by active input order independently of original letters. Cover a C-only restart after B was dropped.

- **F3 · Identical launch argv can restore the context being removed.** `brief.md:4,10` promises empty context while replaying every argument unchanged, and `design.md:9,28` makes that replay binding. Local `codex --help` documents `resume` and `fork`; local `pi --help` documents `--continue`, `--resume`, `--session`, `--session-id` and `--fork`. Replaying a resume launch can reopen the original history. Initial prompt/file arguments can also replay old work automatically. **Exact fix:** record the supported fresh-launch contract explicitly. Reject history-restoring or work-submitting launch modes before any pane is closed, with an actionable error, and preserve argv unchanged only for supported fresh launches. If those modes must be supported, settle the conversion to a fresh launch recipe instead of leaving it to the implementer. Add an observable criterion that such input cannot silently restore old history. This requires reconciling the unconditional argv-copy wording in Taken Q2.

- **F4 · The process-info selection rule is missing.** `design.md:28` assumes one harness argv, but the actual response has `result.process_info.foreground_processes[]`. Read-only `herdr pane process-info --pane w8:pRY` returned three processes: pi, exec_bridge and codex-code-mode-host. `tests/fake-herdr.ts:319-328` returns an empty array, so the existing fixture cannot establish which argv the script must use. **Exact fix:** specify the selected process and validate all launch recipes before the first close. For the proven local layout, select the entry whose `pid` equals `foreground_process_group_id`, require it to identify the expected harness, and fail before mutation if that condition is not met. Carry the literal response schema and a multi-process fixture into the contract. Do not choose the first entry or concatenate process arguments.

- **F5 · Immediate seat append is invalid for fresh Codex.** `brief.md:12` requires a new seats.yaml entry for each restarted seat, but `readiness.yaml:12` says Codex has no session until its first turn. The existing reader requires a nonempty session (`skills/chart-issues/scripts/chart-usage.ts:7-11`), and the restart output has no session (`design.md:25`). **Exact fix:** distinguish immediate pane replacement from session recording. Keep the new pane mapping immediately, then re-read `herdr agent list` after the first real exchange and append the same-letter entry once the real session appears, before measurement. Preserve prior entries and chart open time. State that neither null nor a placeholder session is written. This fits the owned SKILL.md seat-record surface and does not require changing #100's reader.

- **F6 · Seat-only agent names collide across doors.** `brief.md:4` specifies a lowercase seat name and `design.md:25` illustrates `slot-b`. Herdr names are unique among live agents, and `tests/fake-herdr.ts:227-234` rejects a name already attached to any other live pane. Two doors both using `slot-b` would therefore fail after the second door has closed its consultants. **Exact fix:** specify a lowercase name unique to the door and seat, check during the pre-close read that no agent outside the replacement set holds it, and use that exact name when starting. Include an unrelated live agent with the default-looking seat name in the success criterion so preserving unrelated panes does not cause avoidable destructive restart failure.
