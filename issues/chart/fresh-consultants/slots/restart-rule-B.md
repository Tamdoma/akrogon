# Restart rule · blind notes B

Evidence checked 2026-10-17. Short paths below are relative to `skills/chart-issues/` unless stated otherwise.

## Q1

- **Pick:** restart before a chart's first consultant work and after returning from work on another chart. Keep context through that chart's exchanges. An uninterrupted pause or A's compaction alone does not justify another restart. Cost: launch time and re-reading the current chart after a switch.
- **Reject:** once per door leaves cross-chart context growth intact. Every exchange repeatedly discards relevant fork context and adds launches. Resuming a prior session would restore the accumulated context this change removes.
- **Evidence:** operator-placed #99 intake describes growth across three charts (`issues/chart/fresh-consultants/INTAKE.md:23`). Primary code/instructions: `SKILL.md:47` permits chart switching while one waits. `assets/questions.md:48-50` already requires self-contained briefs carrying the current question and locks.
- **Pitfalls removed:** collect the open exchange before closing any pane (`assets/questions.md:46`). On chart re-entry, send current records and operator corrections in the next brief, not an extra warm-up message. Do not restart a consultant already dropped for the session (`SKILL.md:139`).
- **Missing question:** where does the shared opening map belong? It precedes individual chart work and can deliberately cover several intakes. Define one fresh start for that exchange, then chart-boundary restarts, rather than repeatedly restarting while the same joint exchange is open.

## Q2

- **Pick:** close + split + start for the named consultant seats, including supplied consultant panes, as the operator explicitly chose. Preserve seat letters, harness, known launch arguments and repository cwd while replacing pane/session IDs. This is a narrow exception to the old supplied-pane rule and must be written as one. Cost: the supplied consultant terminal is replaced and its placement can change.
- **Reject:** ending a process in place introduces an unproven stop/readiness protocol and contradicts the selected mechanism. Restarting only door-created panes leaves supplied consultants carrying old context, including the supplied seats in this intake. `/clear` plus warm-up is explicitly rejected.
- **Evidence:** operator tier: `issues/chart/fresh-consultants/INTAKE.md:58-64`; `gh issue view 99 -R Tamdoma/akrogon --comments` reports successful close/split/start for codex and pi, both with no arguments. Prior lock: `issues/chart/chart-peer-panes/forks/peer-panes.md:18`. Primary CLI: `herdr agent start --help` accepts arguments after `--`, requires a shell, and confirms detected readiness. `SKILL.md:25` supplies the split layout.
- **Pitfalls removed:** replace only the designated consultant panes, never A or unrelated panes, and check the other-door ownership exclusion before closing (`SKILL.md:139`). Keep the launch recipe before deletion. Use lowercase, nonconflicting names and replace stale pane references. Preserve existing seat-session history (`SKILL.md:37`). Do not promise unchanged surrounding geometry when deleting supplied panes in arbitrary layouts.
- **Missing question:** how are supplied launch arguments and runtime model/effort choices recovered? `herdr agent list` supplies identity, not a complete replay recipe (`scripts/peer-ask.ts:12-21`). If unknown, obtain the missing recipe once before closure. Do not silently substitute defaults or reuse resume flags that restore the old context. The no-argument restart proof does not establish preservation of arbitrary settings.

## Q3

- **Pick:** on a failed restart step, report the exact operation and known remaining panes, stop further restart steps, and request operator recovery. Do not prompt the old session, retry the whole sequence, or silently drop a seat under a new failure category. Keep the existing first-Codex-turn unproven behavior for this change. Cost: a missing first return can consume one full budget before attended escalation, or two idle/unproven budgets before the existing autopilot drop.
- **Reject:** treating restart errors as successful replacement hides lost seats. Unbounded retries can close newly created panes or duplicate agents. Adding first-turn fail-fast detection is useful but not necessary to remove stale context, and needs a new proven binding rule. Null session alone does not prove an empty rollout, so setting every null boundary to zero is unsafe.
- **Evidence:** primary code: `scripts/peer-ask.ts:66-75` seeds session/boundary null on a fresh Codex start; `scripts/peer-wait.ts:143-154,187-208` adopts session without inventing a boundary. `:291` accepts an actual return file. Existing lock explicitly permits unproven waits (`issues/chart/peer-wait-harness/forks/turn-end-signal.md:43-47`), with the autopilot exception at `SKILL.md:139`. The restart comment proves successful returns, not fast missing-file failure.
- **Pitfalls removed:** preserve the same exchange across budget reruns and keep non-null identity-change rejection. Never set a late-discovered boundary to the current file length because the actual turn may already precede it. Distinguish launch readiness from session-ID availability. Fake Herdr currently invents an immediate session on every start (`tests/fake-herdr.ts:238`), so it cannot establish real fresh-Codex timing.
- **Missing question:** should restart failure itself become a new autopilot drop condition? My pick preserves today's listed drop conditions. Expanding them is a separate explicit policy choice, not an automatic consequence of calling restart.
