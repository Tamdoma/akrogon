## Practitioner questions and pitfalls

Research read 2026-10-01. These are mechanism references, not a recommendation to adopt another build system.

- **P1 — Commit status is not computation caching.** GitHub Check Runs attach a run to `head_sha` with status/conclusion, but this does not declare all test inputs or automatically cache the computation. Ask whether the desired object is acceptance evidence or restored task output. [GitHub Checks API](https://docs.github.com/en/rest/checks/runs).
- **P2 — Cross-commit caching needs declared inputs.** Bazel actions declare commands, inputs, outputs and environment, with action-result metadata and content-addressed outputs. Its docs warn about source mutation during execution and untracked external tool versions. Inference here: arbitrary shell strings cannot safely gain Bazel-style reuse from a tree hash alone. [Bazel remote caching](https://bazel.build/remote/caching).
- **P3 — Affected tests require dependency knowledge.** Nx hashes source/dependency files, configuration, dependency versions, runtime values and arguments, then caches tasks independently. Ask who owns the transitive affected-area relation. Akrogon should use the repo’s verified changed-test command, rather than infer coverage from filenames. Framework’s current `test_changed` requires a base but runs unchanged parity/contracts commands (`F/issues/config.yaml:11`). [Nx caching](https://nx.dev/docs/concepts/how-caching-works).
- **P4 — Environment and lockfiles are inputs.** Turborepo hashes global/task inputs including relevant lockfile changes, declared environment and arguments. Inference here: check name + SHA is insufficient when config commands, `AKROGON_BASE`, runtimes, `.env`, installed dependencies, ignored fixtures or external services change. Do not log secret values. Checks with unresolved mutable outside inputs cannot claim reproducible reuse. [Turborepo caching source](https://github.com/vercel/turborepo/blob/main/apps/docs/content/docs/crafting-your-repository/caching.mdx).
- **P5 — Reused exit 0 may omit required artifacts.** A later command may need generated files, a browser trace or runtime state that a prior result does not restore. Decide whether a check is proof-only or supplies outputs before skipping execution. Keep interruption, nonzero exit and missing logs distinct from success. Specific reviewer concerns may force reruns with a reason. Test functional eligibility and refusal cases, not exact agent prose.
