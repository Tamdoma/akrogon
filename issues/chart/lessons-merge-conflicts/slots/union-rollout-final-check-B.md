- **The plumbing sequence must pin one base commit per attempt.** Step 1 separately reads the tree, attributes blob and commit parent through mutable `origin/main`. If another session fetches after `read-tree origin/main` but before `commit-tree -p origin/main`, the new commit can have the newer remote commit as its parent while carrying the older tree. Its push is then a valid fast-forward that silently reverts the intervening remote changes outside `.gitattributes`. Evidence: the proposed sequence uses `origin/main` independently at each operation, while `write-tree` serializes the temporary index populated by the earlier `read-tree`. A fast-forward check establishes ancestry, not preservation of the parent's files. After fetching, resolve `origin/main` to one commit ID and use that exact ID for the tree, attributes lookup and parent. Rebuild from a newly pinned ID on the single retry, and verify before pushing that the parent-to-new-commit diff changes only `.gitattributes`. This is a defect in the proposed sequence, not an observed repository corruption.
