## Safety boundary and implementation shape

- **R1 — Fresh work is indistinguishable from abandoned work without ownership.** A new unlocked worktree at main passes ancestry and status before its worker starts. A live agent can also work from a parent cwd with no file currently open. Pane and /proc vetoes remain mandatory, but they are not completion evidence. Resolve Q1 before treating D1/D4 as an implementable automatic-removal rule; otherwise keep the candidate through the existing leftovers path.
- **R2 — “Clean” must include local-only content.** Current status is plain `--porcelain` (`src/reconcile.ts:194-196`). For the new unmanaged rule, request untracked files explicitly and include ignored files; local Git configuration must not hide data. Preserve ignored credentials, notes, submodules, nested repositories and worktree-specific state unless their disposability is proved. This can retain installed dependencies too; that is the cost of no data-loss assumption. Do not stash dirty work to make it removable or delete existing stashes.
- **R3 — Unknown and detached histories stay conservative.** A remote-only topic ref is not the configured default branch. A detached HEAD may qualify only through the same default-target ancestry and completion proof; detached unique commits must remain. Existing coverage retains unreachable detached work (`tests/reconcile.test.ts:190-204`). Missing target, Git error, unborn HEAD or uncertain ownership means keep, not force.
- **R4 — Reuse guards without widening scratch exceptions.** Route a new eligible candidate through the non-force worktree path, preserving Git-operation checks (`src/reconcile.ts:199-202`), process/owner vetoes (`:507-535`) and pane-inventory vetoes (`:842-859`).
