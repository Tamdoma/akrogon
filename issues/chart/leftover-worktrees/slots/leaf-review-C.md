# Slot C leaf review: agent-worktrees

Disagreements only.

- F1. Nothing in the brief or the architecture actually limits the new rule to Claude Code agent worktrees by path, although the binding scope does (design.md:6 "only Claude Code agent worktrees", foreclosing "path match alone", which makes the path one leg of the identification). Criterion 1 (brief.md:10) and the Lock parse paragraph (design.md:17) identify a candidate by lock text alone, and the Owned surfaces paragraph places the rule in the outside-root branch of the registered loop (design.md:16), which every registered worktree outside the roots reaches (src/reconcile.ts:762-767). An operator worktree anywhere on disk whose lock reason happens to match the regex, set by hand with `git worktree lock --reason` in that shape naming a dead pid, would be unlocked and removed under a literal reading, which is exactly the general-unmanaged scope all slots rejected. Exact fix: in brief.md criterion 1 and design.md Lock parse, add the path leg: "whose path is `<repo>/.claude/worktrees/agent-<id>` for the repo being reconciled, and whose lock reads …", so lock text, path and the pid test must all hold.
- F2. The architecture edits a file its Owned surfaces do not list: design.md:17 exports `startTime`/`liveStartTime` from src/admission.ts, where both are module-private today (src/admission.ts:50-57), but design.md:16 lists only src/reconcile.ts, questions/SKILL text and tests as owned. Exact fix: add "`src/admission.ts` (exporting the existing field-22 reader only)" to the Owned surfaces sentence in design.md:16, so the collision audit and any parallel leaf touching admission see the claim.
- F3. The git operations have no carried proof: readiness.yaml has `proofs: []` and design.md never cites the fork's recorded git proof, yet the leaf's core external operations are `git worktree lock/unlock`, the porcelain `locked` line, `git cherry`, and a compare-and-delete `git update-ref -d <ref> <oldvalue>` whose mismatch behavior no recorded proof covers (the fork proof proved add-with-lock, refusal and unlock-then-remove, not re-locking an existing worktree after a failed remove, which design.md:18 requires, and not update-ref). Exact fix: add the existing proof to readiness.yaml `proofs:` with `record: issues/chart/leftover-worktrees/forks/auto-remove.md`, and record one throwaway-repo proof before handoff for the two unproven calls in the exact forms the leaf uses: `git worktree lock --reason "<original reason>" <path>` on an already-created unlocked worktree, and `git update-ref -d refs/heads/<branch> <wrong oldvalue>` exiting non-zero with the branch unchanged.
