# Map C — herdr-app panels for an agent fleet

Sources and tiers used below: operator = INTAKE verbatim words. Better-than-training = files read today (`~/.config/herdr-app/AGENTS.md` Layouts/Mods sections, `herdr.d.ts`, shipped mod code, omarchy-customizations README/install.sh/herdrapp, `akrogon config`, live `hc ls/get`, herdr-app 0.1.12 / hc 0.1.17). Practitioner = Herdr's shipped-mod authors' own patterns in that code, gpui-kit types. Model-knowledge = lazygit/VS Code SCM/tmux comparisons; I ran no web searches, only local greps, so treat those as unverified memory.

## Forks

### D1 Where the files live and how they reach every session
- O1 Edit live in `~/.config/herdr-app` only. Fastest, no git history, install.sh overwrites it later. Rejected.
- O2 Edit in `~/Work/omarchy-customizations/herdr-app/` (git, source of truth today), copy/symlink into the live home to test. Recommended. Note: that repo is not akrogon-registered (only its `varhop/` subdir is), so this work cannot be normal akrogon leaves. It needs the direct route in that repo, or registering it first. Decide at handoff, not during build.
- Delivery facts that constrain everything: shipped mods/layouts are replaced whole on every app start, edits get moved to `<name>-edited` (AGENTS.md Layouts). install.sh:296-328 copies every `mods/*/` dir but only layouts `flat` and `board`, by name. So new mods flow automatically; a renamed/new layout does not unless install.sh's list changes. Sessions: `herdrapp` symlinks personal files (anything not in `installed.json`) into each session home on launch, so a new mod reaches infra/personal/mdconsultingny on next launch of that session, not while it is already running. `workspace.panels` in shared.json is copied only when a session is created, so existing sessions keep `["files","changes"]` until someone edits their shared.json.
- Later risk: every clone is frozen at clone time. `agents-by-tab` is cloned_from agents 0.1.9 and flat from main 0.1.7, app is already 0.1.12. Each new clone adds a file the operator must diff after Herdr updates (README says this explicitly). Keep clone count minimal.

### D2 Clone vs new, per item
Clone with `mod.clone` (records cloned_from, rewrites the mod's own asset paths and overlay names), never hand-copy. Files' code points at `mods/files/*.svg`, so a hand copy silently keeps using the shipped icons.
- A1 Changes scopes: clone `changes` (one clone).
- A2 Files markdown/filter/recent: clone `files` (one clone).
- A4 Tasks: new mod, no clone. But the panel buttons live in shipped `tabs` (`mods/tabs/main.js:97-98` renders only files and changes buttons, gated by `shared("workspace.panels")`). Adding a "Tasks" button means cloning `tabs` too (third clone), or giving the panel stack its own header mod, or opening Tasks only by key. The prefix mod is already operator-owned and has `f` for Files (`mods/prefix/main.js:59`): adding a Tasks key there is free. Recommendation: clone tabs only if a visible button is required; otherwise panel stack child `tasks` + prefix key + `layout.select`. This is the clone most likely to be regretted, because tabs also owns per-space panel memory (`mods/tabs/main.js:22-45`).
- A5 Needs-you: new mod, or extend operator-owned `agents-by-tab`/`board`. Board already has a Needs-you column in the board layout. Extending `agents-by-tab` avoids a new sidebar block in flat; a separate mod keeps the inbox logic out of a 447-line clone. Recommendation: separate small mod, collapses to nothing when empty (see D8 sizing problem).
- A6 Decision strip: new mod.
- A8: layout JSON only, no clone (see D9).

### D3 Which layouts get the work: flat, board, or both
Live shared.json says layout `flat`, but install.sh switches to `board` on install and the README says "the installer selects it". Board has no sidebar at all, so A5 and A8 do not exist there; the right panel stack exists in both with the same ids. Doing both doubles every layout edit and every visual check. Recommendation: ask the operator which layout is daily; build for that one, and add the panel-stack child to the other only if it is still used. Retiring board removes a whole class of divergence.

### D4 A4 Tasks: data source and leaf-to-terminal jump
`log.jsonl` alone is not the feed the intake describes:
- It is per repo (11 registered repos today), and framework's is 2.3 MB, over `readTextFile`'s 1 MiB cap (herdr.d.ts readTextFile). Reading needs `exec` with tail/jq-style trimming, or reading each leaf's `issues/open/<slug>/state.yaml` (src/state.ts:128) plus a tail of the log for last merges. Current phase/slot/worktree/busy_since live in state.yaml, which a mod must parse itself (no YAML library in gpui-kit; the file is flat, a small parser is feasible but brittle).
- O1 Mod parses files directly (watchFolder per repo `issues/`). No akrogon change. Breaks when state.yaml or phase names change, and akrogon's own history shows phases do get renamed (src/routing.ts:23).
- O2 Mod execs `akrogon status` / `akrogon config` and parses output. Today `akrogon status` prints human text, no JSON flag. Parsing human text is worse than parsing the files.
- O3 Ask akrogon for one stable machine output (e.g. `akrogon status --json`) as a separate small leaf in the akrogon repo, and the mod consumes only that. Recommended long-term; it puts the schema contract in the repo that owns it. Short-term v1 can read state.yaml + log tail, but the charter should name O3 as the settling move, or accept O1 knowingly.
- Repo discovery: parse the repos map from `akrogon config` output, or hardcode nothing and read akrogon's config file. Hardcoding 11 paths in the mod will rot.
- "Red past normal": normal is undefined. Options: fixed per-phase minutes the operator picks; percentiles computed from each repo's own log history (self-calibrating, more code, weird for new repos); busy_since from state.yaml (measures slot busy, not phase age). A false-red board trains the operator to ignore it, which is worse than no red. Recommendation: operator picks per-phase thresholds at interview; show age always, color only past threshold, using `theme().blocked`, not a hard red.
- Jump to a leaf's terminal: today state.yaml `pane: {A, B}` holds old-herdr pane ids and akrogon still dispatches to old herdr, so most leaves have no herdr-app terminal at all. O1 match `panes().cwd` against state.worktree (or `~/.akrogon/worktrees/<repo>/<slug>`): works for any terminal sitting in the worktree, no akrogon change, ambiguous when A and B share a worktree (they do: pick the agent pane, else first). O2 match slug in tab name: depends on naming discipline. O3 after the akrogon herdr-app port: labels `herdr.space`/`herdr.tab` plus ideally an `akrogon.leaf=<repo>/<slug>` label, read via `terminals()`; that contract belongs to the herdr-app epic, this work should only state the need. Recommendation: O1 now, row shows no jump affordance when nothing matches, O3 later. Also scope: a session window only sees its own core's terminals, while the files are global, so rows from other sessions will legitimately have no target.

### D5 A5 Needs-you: question text and reply
There is no mod API to read terminal text or type into a terminal. `agents()` gives status/app/title only; `terminals()` gives the agent's report, and live `hc get` shows that report carries a short `msg` from the agent (a summary, not the question). So question text can only come from:
- O1 `hc(["read", addr])` via exec: the visible screen. While an agent is blocked, history reads return only the screen anyway (hc --skill). Screens are wrapped (t15 is 59 cols), and blocked often means a menu (permission dialog, picker), not a text question. Three harnesses, three screen shapes, each changes on harness updates.
- O2 Read each harness's own transcript files: precise last-message text, but three parsers, and nothing maps a terminal to a transcript (`hc get` has no agent session id; the herdr-app intake lists this as an open hole).
- O3 Show report `msg` + title + a jump button, no question body. Honest, but then A5 adds little over the existing agents list, toast, and board Needs-you column.
Reply: the only path is exec `hc send`. `hc send` refuses a blocked terminal unless `--force`, and `--force` can answer a permission dialog, which hc's own skill text warns against using to bypass a permission decision. Menu-blocked agents need `hc keys`, not text. Recommendation: split A5. V1 = inbox list (blocked + done-unseen) with program icon, report msg, age, click focuses (`agent.focus`). Reply box only after a probe captures real blocked screens from claude, codex, pi, agy and shows which are text-answerable; any send uses `hc send --if idle` semantics, never silent `--force`. If the probe shows menus dominate, drop the reply box entirely.

### D6 A6 Decision buttons: detection
The operator uses at least three code shapes in the wild: `1a | 2a | 3b`, `a1 - note | a3 - note`, `go 01b`, plus this system's D1/O1/F1 style. Options:
- O1 Regex over `hc read` history of the focused idle/done agent. False positives from code and diffs on screen, line wrap chopping codes, options spread across paragraphs. Needs fixture screens to tune, and will still misfire.
- O2 A small convention agents already almost follow: options end the message as a block of lines starting with the code. Parser only trusts a trailing block of 2+ coded lines after the last blank line. Removes most false positives without changing any agent config. Recommended as the detection rule, stated in the shared communication rules so agents converge on it.
- O3 Transcript parsing per harness: same mapping hole as D5 O2.
Sending: clicks build the reply text, shown as an editable preview before send (free-text suffixes like `a1 - use the other name` must stay possible, or the strip handles only part of real replies). Send via exec `hc send <addr> --if idle`. One wrong auto-send to a working agent costs more than the strip saves, so no send-on-last-click without the preview step. Placement: a fixed-px layout block leaves an empty gap when no options are detected; a floating block sizes to content and renders nothing to hide, but floats over the terminal's input area at the bottom. Probe both with `herdr-app shot`.

### D7 A1/A2/A3 panels: shared folder, scopes, commit
- Commit button: remove it. Selected-files commit means staging UI in 368px, fights agents who commit their own work and use the same index, and stays dangerous in the main checkout where akrogon writes `issues/*.jsonl`. Removing it removes the failure class (F3). VS Code SCM and lazygit stage per file/hunk (model-knowledge), but that is a full git client, not a side panel's job here.
- Branch vs main scope: define as merge-base diff (`git diff <default>...HEAD`) or it shows other people's merged work as yours. Default branch: akrogon config says main, but panels must work in any repo; use the repo's own default (origin/HEAD, else main, else master) and disable the scope when on that branch. Recent commits scope: a commit list where picking a commit shows its diff is a second navigation mode; keep it read-only list+diff or it grows into a log viewer.
- Worktree picker (A3) in both clones duplicates the picker UI and the `git worktree list` logic in two frozen clones. Better: one shared key, e.g. `setShared("panel.folder.<spaceId>", path)`, written by whichever panel's picker is used, read by both, with "follow focused pane" as the cleared state. The shipped `worktree` mod already parses `git worktree list` (mods/worktree/main.js repoOf/list code): copy that parsing shape, not the space-creating actions. Akrogon worktrees under `~/.akrogon/worktrees/<repo>/<slug>` are linked worktrees, so they appear in the list from any checkout of the repo. But from a door pane in repo X, worktrees of repo Y never appear; that is correct behavior, say so in the UI by naming the repo.
- Open as pane: `pane.split {mod, props}` needs the clones to accept `props.folder`/`props.file` and stop following the focused pane when props are set. Today both mods ignore props and always follow focus (files/main.js location(), changes/main.js location()). This is a real mode split inside each clone; keep it as one early branch in location(), not scattered flags.
- A2 details: markdown via `TextView.markdown` (gpui-kit.d.ts:20709) with a raw/rendered toggle, because tables and wide code in 368px will sometimes read worse rendered. "Changed recently" needs mtimes; files' directory listing script returns only name+kind, so either extend the script (stat per entry, slower on big trees) or derive recent from `git log --name-only` plus status marks it already computes. Filter: filter the already-loaded tree entries, do not add a recursive walk (the mod caps at 500/folder, 5000 total on purpose).

### D8 What "beautiful, same theme" means concretely
- Colors only from `theme()` names (chrome, surface, raised, hover, selected, border, muted, dim, accent, working/blocked/done/idle, ansi*). No hex. The Omarchy hook rewrites `themes/omarchy.json` on theme-set, so any hard hex or brand color is wrong after the operator's next theme change. Alpha suffix on a theme color (board's `color + "26"`) is the existing pattern.
- Logos: already solved by the program table. `Program` gives icon/tint/tile/color (herdr.d.ts Program), and shipped mods all draw it the same way: tint → `svg(icon)` in a text color, else `image(icon)` full color (mods/agents/main.js:66-68, same in pane and board). Use that helper shape everywhere; never hand-map app strings like "claude-code" to files. `icons/` is Herdr-written, do not add files there; a missing logo is a `programs.json` entry pointing elsewhere. Decision for the operator: tinted glyphs in foreground/muted keep the flat look; full-color logos or program.tile backgrounds read more as "logos" but bring non-theme colors into every row. Show both in a shot and let him pick once, for all surfaces.
- Metrics to copy so new panels look native: 42px panel headers, 28px rows, 13px base text, 11-12px dim secondary, rounded 7-10, 1px border in t.border, hover t.hover, selected t.selected, native spinner (`svg(...).spin(900)`) or `.frames`, never a timer-driven redraw (AGENTS.md: a mod redraw redraws the whole window). Flat layout has radius 0 and gap 0 panes; panels keeping rounded(10) cards like shipped files/changes is the current mixed look, keep it consistent with them, not with the panes.
- Done-criterion, not taste: `herdr-app check` passes, no `<name>.error`, and a `herdr-app shot` PNG reviewed at zoom 1 in the current Omarchy theme, in both a busy state and an empty state.

### D9 A8 Spaces smaller + scrollable
The shipped spaces mod already scrolls: its list is `flex_1().min_h(0).overflow_y_scrollbar().mode("always")` (mods/spaces/main.js:375). The real problem is sizing: in flat, `sidebar-lists` gives spaces and agents weight 1 each with min 90, so spaces always takes half the sidebar and shows few rows. Fix in layout JSON only: give spaces a fixed px height (or smaller weight, e.g. weight 1 vs agents 2-3) with a min that still shows ~4 spaces; the internal scrollbar then does what the operator asked. No mod clone needed. Risk: too small and the space drag-reorder and machine headers get cramped; collapsed rail (<160px) rendering must be checked in a shot. If the operator actually means spaces in the picker or board layout, this whole item changes, so confirm in interview which surface he meant.

## Pitfalls over the work's lifetime
- P1 Clone drift on every Herdr update. Removed by D2 (fewest clones) and a done-criterion: README in omarchy-customizations lists each clone with cloned_from version, updated in the same change.
- P2 Screen-scraping (A5 question, A6 options) breaks on harness UI updates. Contained by isolating parsers in their own module file inside the mod folder with fixture screens, and by degrading to "show nothing" (A6) or "msg + jump" (A5), never to a wrong send.
- P3 akrogon state/log schema changes break A4 silently (a board that shows stale phases is worse than none). Removed by D4 O3 contract, or interim: the mod shows its data's age/source repo count so breakage is visible.
- P4 Performance: hidden mods keep timers and watchers running (AGENTS.md Mods). A4 watching 11 `issues/` trees plus files/changes 10s polls can redraw the window constantly. Rules: watchFolder only (no poll) for A4, ≥60s timer just for age text, board's 30s is the fastest existing example. Git reads keep the shipped READ flags (`--no-optional-locks -c core.fsmonitor=false`) or every refresh triggers the next via .git writes (changes/main.js comment at READ).
- P5 Sending text to the wrong agent/state (A5/A6). Removed by `--if idle`, explicit target address captured at render, and re-checking status at click; addresses change on restart (hc intake finding), names do not.
- P6 Multi-session confusion: mods are linked into all sessions but `hc` exec hits the session the window belongs to, and shared.json is per session. Tasks rows and inbox entries must be read as "this session's terminals, all repos' files"; done-criterion includes opening a second session and checking nothing errors or double-sends.
- P7 `HC_SESSION` is undocumented and a Herdr update could change it (README Sessions). Nothing in this work should add new dependence on it beyond what herdrapp already does.
- P8 Layout edits can be undone by clicks state in `layouts/.state/` (a deliberate file edit wins, per AGENTS.md, but panel hidden/active are clicks). "Tasks shown by default" must be tested from a fresh .state, not just the operator's current one.

## What is wrong, unneeded, or missing in the intake
- F1 "Spaces must scroll vertically" — already true in the shipped mod; the defect is sidebar sizing (D9). Charting a scroll feature would build the wrong thing.
- F2 A4 "fed by issues/log.jsonl via watchFolder" — insufficient and partly impossible (1 MiB read cap, current phase lives in state.yaml, 11 repos). Needs D4's decision.
- F3 A5 as written assumes question text and reply-typing APIs exist. They do not; only `hc read`/`hc send` via exec, with the blocked-send restriction. A5 must be split (D5).
- F4 A4 "shown by default" conflicts with per-space panel memory in the tabs mod: a space remembers its last panel, so "default" can only mean for spaces with no stored choice, unless the work overrides stored choices. Operator to pick.
- F5 Missing: existing sessions' shared.json `workspace.panels` update, prefix key for Tasks, and install.sh layout list if any layout is renamed. Without these, work appears in the main window and silently nowhere else.
- F6 Missing: board layout's fate (D3). Right now installer, README, and live shared.json disagree about which layout is primary.
- F7 Missing: remote-machine spaces. Files/Changes support `on: machine` throughout; Tasks/Needs-you/akrogon data are local-only. Say local-only in each contract instead of discovering it.
- F8 Unneeded risk: "Recent commits" as a full scope in A1 and selected-files commit both push the panel toward a git client. The operator's actual flows (agents commit, operator reviews branch diff) need branch-vs-main and working tree; commits can be a thin read-only list or dropped at interview.

## Questions a practitioner would ask first
- Q1 (GPUI/native, practitioner: shipped mods) Which rows can exceed a few hundred (files tree, diff, tasks across repos) and therefore need `v_virtual_list` like changes' diff does, instead of plain children?
- Q2 (terminal multiplexers, model-knowledge) tmux/zellij keep status to one line and never steal the terminal's bottom rows where the program's own input lives: does the A6 strip resize terminals every time it appears (layout block) or cover them (floating)? Terminal resize reflows every agent's screen.
- Q3 (git UIs, model-knowledge) lazygit and VS Code SCM both separate staged/unstaged and never `git add -A` from a button: is any commit action in scope at all here (D7 says no)?
- Q4 (agent dashboards, better-than-training: board mod exists) The operator already has a board layout with status columns and a board mod using program icons: what does A4/A5 show that board does not (akrogon phase vs agent status), and should board's card code be the visual base for Tasks rows?
- Q5 (operator) Which harnesses must A5/A6 work for on day one: claude, pi, codex, agy, all via the same screen scrape, or is claude+pi enough?
- Q6 (operator) In A4, is a leaf with no live terminal (normal today, pre-port) still a useful row, or noise? And per-phase red thresholds: what numbers?
