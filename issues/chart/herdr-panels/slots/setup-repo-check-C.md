# Setup-repo check C — disagreements with the proposed shape

## Wrong steps

- F1 `omarchy hook install theme-set <repo>/omarchy/apply-herdr-app-theme` does not link; it copies. `/usr/share/omarchy/bin/omarchy-hook-install` ends with `cp -- "$HOOK_FILE" "$HOOK_PATH"` (verified 2026-11-03), and the installed copy at `~/.config/omarchy/hooks/theme-set.d/apply-herdr-app-theme` is a real file. Every edit to the hook in the repo silently does nothing on that machine until someone reruns `install`. Either document "rerun `install` after editing the hook" in README, or install a one-line stub that execs the repo path (the only shape where the repo is actually the source of truth).
- F2 Step 5's write probe tests the wrong files. `app.zoom_in` writes `view.json`'s zoom (AGENTS.md "The files": `view.json` = zoom, per-window state), not `settings.json` — and `settings.json` is a copy anyway, so nothing the probe touches is a link. It cannot answer "does herdr-app replace a linked file when it writes." Per "The files" + "Changing things safely", the app writes view/shared/data/seen; layout and keys.json files are only moved aside by the escape hatch. So either drop the probe and record the residual risk, or probe a genuinely linked path.

## Missing customizations — none found, one judgment call

- F3 Source completeness checks out: six mods, two layouts, keys.json, herdrapp, theme script, README are everything personal (`personal_paths` in herdrapp; `installed.json` shipped list read today). `programs.json` does not exist live; `themes/omarchy.json` is generated by the hook; live `settings.json` differs from source only by the installer-added `font`/`font_size` keys (read both files today). Nothing missing.
- F4 `settings.json` copy-not-link is defensible (Settings screen writes it; the Omarchy `jq` font edit must land on a real file) but two consequences are unowned: (a) any Settings-UI change — sounds, telemetry, appearance, zoom — never reaches the repo, silent drift; (b) copy-when-absent means an existing `settings.json` lacking `"theme": "omarchy"` never gets it, so on a migrated machine the theme hook runs but nothing uses the theme. Alternative worth deciding explicitly: link it — `herdrapp` already links `settings.json` into every session home (`personal_paths` prints it; session homes show `settings.json -> main home` links that work), which is evidence the app tolerates the file being a symlink.

## Risks the shape does not remove

- F5 Escape hatch breaks the links it touches: `ctrl-alt-shift-escape` sets the shown layout and `keys.json` aside as `*.reset-<time>` (AGENTS.md "Changing things safely"). With symlinks, that moves the links; the home then has no `keys.json` or `flat.json` until relinked. `install` being idempotent covers repair, but say so: "after an escape-hatch reset, rerun install."
- F6 Same class, smaller: `layouts/.state/` click-state and per-mod `jsconfig.json`/`gpui-kit.d.ts` are written into linked paths. `.state` is a sibling directory in home, unaffected — but the app writes `jsconfig.json` and `gpui-kit.d.ts` inside every linked mod folder (present in all six today, verified). The `.gitignore` covers these; confirm it also covers any future `*.error`/`*.old-*`/`*-edited` names that could land inside repo dirs.
- F7 `git subtree split -b herdr-setup-split` leaves a long-lived branch in omarchy-customizations; delete it after the pull or it rots beside the real repo.

## Convention notes (not violations)

- F8 Shape matches AGENTS.md "Layouts and mods other people made" (a shareable layout = `layouts/` + `mods/` folder). RECIPE.md + preview.png + `herdr-layout` topic are only required for herdr.dev listing; a private setup repo may skip them — but if the repo is public and the operator wants it discoverable, they belong.
- F9 README updates are content edits, not path edits: `README.md:4` "copies these files into ~/.config/herdr-app" (now links), `:36` "The installer sets the terminal font" (moves to install.sh's jq step — keep the sentence accurate), `:52` "The installer selects it" for board (removed by the plan). All three become false if only paths are touched.
