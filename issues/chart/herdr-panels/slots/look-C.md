# Look of the new panels — seat C notes

Facts verified 2026-11-03: herdr-setup/layouts/flat.json (live copy identical, diffed today), shipped changes/main.js:169-204 and agents-by-tab/main.js:66-68, herdr.d.ts theme():251-257, knownAgents():33, AGENTS.md "Programs", "The files", "UI". Theme = omarchy (settings.json, generated by the hook, colors are derived tokens).

## Q1 — Panel shape at 368px and full width

**Pick.** Same chrome both widths: the existing card shape — `rounded(10)`, `border_1` in `t.border`, `bg(t.background)`, 42px header with bottom border, 28px rows, 13px base text (changes/main.js:179-189, the shape the operator already approved). At full width the panel keeps identical padding and row heights; content columns that make sense widen (diff/code panes in Changes get `flex_1`, two-line Tasks rows widen the detail line). No new chrome, no max-width centering tricks.
Reason: "the underlying theme has to stay the same" + "I like what they are today" = the panel looks like the panel. `panel` is a fixed `{"px":368}`, `resizable:false` column on `background: "canvas"` (flat.json), so the card border/radius is its chrome — keep it at both widths or the full view reads as a different surface.
Cost: a full-width card floats in a lot of canvas; the border keeps it a coherent surface. Long detail lines still truncate (`.truncate()` like tabs/main.js does) — never wrap into three-line rows.

**Rejected.** R1 Full-width = edge-to-edge, radius 0: makes it look like a different layout (board has that look; flat doesn't). R2 Wider paddings/fonts at full: two metrics to maintain, breaks "same" at a glance. R3 Constrain full-width content to a readable column (e.g. 120ch centered): diffs and Tasks rows want the width; the shrink button exists for narrow reading.

**Pitfalls.** `panel-body` stack: new blocks `tasks`/`needs-you` must keep the same root shape as `files`/`changes` (rounded(10) + border_1) — copy changes' root builder, don't invent a card. At full width the card's `rounded(10)` needs the same margin behavior as at 368 — verify in the P1 shot.

## Q2 — Harness logos matching the Agents list

**Pick.** Reuse the exact draw shape of agents-by-tab: `icon(p, size, color)` → `p.tint ? svg(p.icon).size(n).text_color(color) : image(p.icon)` (agents-by-tab/main.js:66-68), same size as the Agents list uses for its rows (14px). Source of `Program`: for a live seat, the seat terminal's `program` (terminals()/panes()); for a seat not running or the kind only, `knownAgents()` once at init, matched by `key`/`match` to akrogon's harness name (`claude`, `codex`, `pi`, `agy`→`antigravity` if the table spells it so — verified live: t2v reports `app:"antigravity"`, t2t `app:"pi"`). Cache the Program per harness; if no match, no logo (never a hand-mapped icon path — AGENTS.md "Programs": the table owns icons).
- Tinted glyph in the row's `t.dim`/`t.muted` (Agents-list style), not `program.tile`/full color: round 2 A8 settled "logos already identify harnesses, no names added" — the Agents list draws tinted glyphs, so panels do the same to stay one visual language.
- Two-seat row (Tasks): `A <logo>` · `B <logo>` pairs on the detail line — seat letter stays because A/B is an akrogon concept the logo can't carry; logos still say which harness each seat is (config `slots.a.harness` → Program).
Cost: `knownAgents()` is async (Promise) — resolve once at mod init, render rows when it lands; an unmatched harness shows the seat letter alone.

**Rejected.** R1 Full-color logos/tiles per row: round 2 already decided against harness *names* for that reason's twin — tiles are louder than the Agents list and bring non-theme colors in. R2 Skip logos when no live terminal: the seat kind is still meaningful (Tasks shows seats that haven't started). R3 Ship own logo files in the mod: icons/ is Herdr-written (AGENTS.md "The files"); a missing harness is a programs.json entry, not a mod asset.

**Pitfalls.** `knownAgents({on})` asks the shell — on machines without the harness `installed:false`; don't let that hide the logo (installed ≠ icon exists; icon comes from the table regardless). Probe: one `herdr-app shot` with claude+pi+antigravity rows beside the Agents list, same theme, zoom 1.

## Q3 — Top bar: Tasks / Needs you buttons, ⤢/⤡, narrow windows, badge

**Pick.**
- Buttons: `panelButton("tasks","Tasks",<icon>)` / `panelButton("needs-you","Needs you",<icon>)` in the tabs clone, same `h(26) px(8) gap(5) text_size(12)` shape as Files/Changes (tabs/main.js:86-92). Each new mod ships its own icon svg (`mods/tasks/tasks.svg`, `mods/needs-you/needs-you.svg`) — tabs clones reference by path like it does for files/changes (`mods/files/file.svg`). Icon shapes: Tasks = list/checkbox glyph, Needs-you = hand/bell glyph — picked to read at 14px in muted.
- ⤢/⤡ lives in the panel header (inside the card, right end of the 42px header), not the tabs bar: it belongs to the panel surface and stays visible in full width where the tabs bar is still there. 26px square button like `tab-new`.
- Narrow window: the tabs bar already scrolls its tab list and the buttons are `flex_none` — buttons never collapse; the tab strip eats the squeeze first (tabs/main.js: tab-scroll `flex_1` + `overflow_x_scrollbar`). Keep that: no label-collapse logic — four short labels don't overflow until the window is narrower than usable anyway.
- Needs-you count badge: yes, small dim number in the button label (`Needs you 2`) when the list is non-empty — it's the one button whose count answers "is it worth opening"; keep it `text_size(11) t.dim`, no red dot (a blocked agent already has sound+toast; a badge-dot would double-report).
Cost: badge needs the mod's count at render — Needs-you computes it from agents() each render anyway; tabs clone needs the same count → share via `setShared("needs-you.count")` written by the mod, or compute cheaply in tabs from `agents()` (agents() is free, live). Prefer the compute — one source, no key contract.

**Rejected.** R1 Collapse labels to icons at a width threshold: adds a mode switch for a case the scroll already handles; four buttons × ~90px ≈ 360px — tabs scrolls before that. R2 Badge with red/dot styling: reports blocked twice (toast + badge) and uses `blocked` for a non-blocking semantic. R3 Toggle in tabs bar: the button must exist when the panel is full-width too — a tabs-bar control is far from the surface it resizes; panel header keeps it adjacent.

**Pitfalls.** `workspace.panels` gate: buttons render only `enabled.includes(id)` — `tasks`/`needs-you` must be added to each session's shared.json (already a named step). Icon files must exist before check runs or `svg(path)` fails visibly — done-criterion: herdr-app check + shot shows both buttons with icons.

## Q4 — Theme tokens for red, pills, tags, alerts

**Pick.** Map akrogon semantics to the tokens mods already use:
- Red (real blocks only): `t.blocked` — failed leaves, prompt delivery errors, Missing, deploy failed, unreadable repo, alert lines; after the port, a seat `blocked` on a prompt. `blocked` already means "needs you" everywhere (agents-by-tab status, changes' merge-conflict `t.blocked` at :190).
- Phase pills: match the CLI's phase colors to the palette — plan `ansi4` (blue=34), implement `ansi3` (amber=33), check `ansi5` (magenta=35), merge `ansi2` (green=32), failed `blocked`, parked `dim` (status.ts phaseColor). These are derived tokens that exist in `theme()` even when the omarchy colors map doesn't list them (verified: omarchy.json colors omit them, `theme()` still exposes ansi0..15 and the status colors per herdr.d.ts:251-257).
- Slow merge alert: `ansi3` amber, distinct from `blocked` (final: "amber, not red").
- Neutral tags (stopped, holder/queue place, busy): `t.muted`/`t.dim`; queue place `t.muted`, `land` `t.accent` (operator action pending = accent).
- Rows/cards: `bg(t.background)`, hover `t.hover`, selected `t.selected`, header border `t.border`, alert section on `t.surface` or plain rows with `t.blocked` text.
Missing token: an `error`/`danger` distinct from `blocked`. Today `blocked` serves both ("needs you" state and "failed"), which is fine *here* because both meanings are "stop and look" — but if a future "informational error" appears, it has no token. Don't invent one: no hex, and round-2's look lock says theme stays as-is; if a second severity is ever needed it goes in the theme, not the mod.

**Rejected.** R1 `ansi1` (red) for real blocks instead of `blocked`: `blocked` is the semantic name; ansi1 is a palette index — semantics survive theme changes better. R2 `accent` for alerts: accent means "operator's current context" (focused pane border), not "problem". R3 Tint backgrounds of alert rows (blocked+alpha): the board's `color+"26"` pattern exists but for full-width rows it competes with selected/hover; text-color signaling is quieter and enough.

**Pitfalls.** Tokens like `blocked`/`ansi3` may be *derived* when the theme omits them — done-criterion: shot in current omarchy theme shows failed/slow-merge distinctly; also re-shot after a theme change (hook rewrites themes/omarchy.json on theme-set).
