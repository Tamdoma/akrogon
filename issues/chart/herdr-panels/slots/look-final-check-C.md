# Look final check C — defects

- F1 "pill in the stage-pill style" conflates two different shapes. The stage pill is a foreground word on a stage tint; for the Needs-you count the "stage word" position is replaced by a bare number, so the pill shows `2` in foreground on a red tint (or neutral tint) with no stage color inside the text. That reads as a filled alarm badge, not a stage pill, and at 12% alpha the tint barely tints behind a numeral. It's also the one place `ansi1` is spent on a *non-block semantic*: "an agent is blocked" is a needs-you state, not a real block — overloading the reserved red trains the operator to stop reading `ansi1` as "something actually failed". Fix: keep the agreed count rule but draw it `dim`/`muted` numeral, colored only by a 6px `ansi1` dot when a blocked row exists (same dot primitive the pill uses), or accept that "pill style" here means tint-only and say so. Minor, but it's the one badge seen on every glance.
- F2 "a second press brings the terminal back" (L3) under-specifies what `ctrl-b t`/`ctrl-b y` do while the panel is open on a *different* view. `ctrl-b t` settled as toggle-on-Tasks; `ctrl-b y` "through the same open/close routine". Pressed while Files shows: does it switch the open panel to Needs you, or close? The toggle routine (`layout.select` + `layout.show`) implies switch-to-Needs-you; pressing the same key while Needs-you already shows closes. State that branch explicitly — "the one open/close routine" is named but the while-other-view-open behavior isn't, and the two plausible reads differ (switch vs close).
