# Slot B leaf review

- **F1: Self-closing commands need a binding outcome before handoff.** `design.md` → `Leaf architecture` leaves the same-owner pack deadlock as an open planning question and suggests showing that no entry point runs under the shared lock. That case already exists: `tests/close-pack.test.ts` → `run-check refuses owner-root holders before running and after completion` runs `akrogon phase root-racer merged` inside a run-check holding that owner. The case `run-check refuses closed and closing owners at start and right before publish` does the same for a leaf holder. Both expect owner completion followed by the outer wrapper's late publication refusal. `src/phase.ts` → `completeOwner` packs and moves the owner synchronously. With the new lifetime lock, completion waits for the enclosing command, while that command waits for completion. Keeping all current behavior and introducing this wait are incompatible for these cases. **Concrete fix:** make the self-close/self-pack outcome binding. The smallest option is to refuse the same-owner completion/pack before it waits for exclusive access, retain emitted evidence, and explicitly exclude successful self-completion from the promise that refusal behavior stays unchanged. Add an observable no-deadlock/refusal criterion and include the entry points needed to enforce it in ownership. If successful self-completion must remain supported, choose its different ownership/lifetime design at charting rather than asking the planner to invent it. **Evidence:** the named test cases; `src/run-check.ts` → `checkedRun`, `ownerRefusal`; `src/phase.ts` → `completeOwner`; `/home/ivan/.claude/skills/chart-issues/assets/shapes.md` → `Preflight and validation` requires binding decisions to have a home and criteria to be achievable within ownership.

- **F2: Criterion 6 and reader ownership name interfaces that do not exist.** `brief.md` → `Done-criteria` names “akrogon log listings” and “review evidence lookups.” `design.md` → `Leaf architecture` directs the implementer to find check-log matchers in evidence, verify and unspecified review-evidence code. `src/evidence.ts` → `readLog`, `readLogAcross`, `readMember` resolve an explicit path and return bytes. `src/akrogon.ts` → the `log` command dispatches to those readers, with no listing or completion-classification interface. `src/verify.ts` → `runOnce` constructs receipts from completed `checkedRun` results, rather than discovering results from holder filename matches. The draft therefore forces a guess about which new reader behavior or machinery is required. **Concrete fix:** narrow criterion 6 to the actual observable authority boundary: partial paths have names distinct from completed logs, remain readable through the existing log reader, and never produce a completed check result or reusable verify receipt. Remove invented listing/review-reader ownership. If another automatic consumer really exists, name its file and function and the exact behavior that must change. **Evidence:** the named functions and command dispatch; `/home/ivan/.claude/skills/chart-issues/assets/shapes.md` → `Leaf files` requires actual consumers for altered state, and `Preflight and validation` requires observable criteria within ownership and existing proof machinery.
