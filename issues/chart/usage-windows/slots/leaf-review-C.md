- The Claude call boundary is underspecified and the obvious implementation is wrong. `brief.md:10,12` says records are filtered by spans and calls are distinct `message.id`s, while `design.md:38` says to replace the existing window membership test. The existing code filters assistant records before grouping (`skills/chart-issues/scripts/chart-usage.ts:142-171`), so a streamed response crossing an edge would be counted from an incomplete subset or counted in both adjacent charts. Exact fix: state that Claude records are grouped across the full session first, assign the whole call to the span containing that group's final record timestamp, use the complete group's final counters/max output, and add a fixture whose repeated `message.id` straddles a span edge.
- `<until>` is only specified as the end of an open span (`brief.md:4,10`; `design.md:7,37-41`), leaving closed spans free to extend past the CLI cutoff. That breaks the existing interface where `<until>` excludes later records (`skills/chart-issues/scripts/chart-usage.ts:347`; `tests/chart-usage.test.ts:248-275`). Exact fix: define every effective span as its intersection with `(-∞, until)`, including closed spans, and add a test with a closed `to` later than `<until>` plus a later span wholly after `<until>`.
- The Pi criterion counts every assistant entry carrying usage (`brief.md:15`), but the binding decision excludes zero-usage errors (`design.md:8`; `issues/chart/usage-windows/forks/window-and-calls.md:28`). Exact fix: define the literal exclusion, for example a Pi assistant with `message.isError === true` and all usage counters zero, and add a fixture assertion that it contributes neither a call nor tokens. Nonzero usage on an error must still count.
- Pi drops the binding reasoning field. The source fixture explicitly carries `message.usage.reasoning` (`design.md:35`) and the decision says reasoning stays separate (`design.md:8`), but `brief.md:15` maps only the four Claude token names. Exact fix: require and test a separate `reasoning_output_tokens` line mapped from Pi `usage.reasoning`, while keeping it out of context and not adding it again to `output_tokens`.
