# Fork notes, slot C: door-address

## Q1. Where the door takes its address from

Pick: `$HC_TERMINAL_ID`, read at the moment of each use. One defining sentence goes into the `## Open` inside-hc paragraph in skills/chart-issues/SKILL.md, which already reads the variable for the inside-hc test: the door's address everywhere in the skill and its assets, meaning every `<door address>` and `<A address>`, is `$HC_TERMINAL_ID` read at use, never an address carried in a compaction summary, a brief, the Mode record or seats.yaml. Use moments are each `herdr-consultant-column` call including `--save` and `--restart`, each brief write where the report step address is baked into the file, the `door-reset.ts` argument and start prompt in assets/handover.md, the `transcript.ts` argument for A itself, and the handover continuation check in `## Handover`, where "the prompt names its address" then means the prompt address equals the fresh session's own `$HC_TERMINAL_ID`. seats.yaml A entries are written from the same read at the existing append points and stay a usage record, never an input to any command.
Cost: a brief is a file, so its report step freezes the address at write time. A door whose terminal changes after the brief is written and before collection still gets reports sent to the old address. That path needs an operator restart of the door session mid exchange, which orphans the consultants anyway, and collection by return file already covers it under the Collecting rule.

Rejected: a recorded value from seats.yaml or the summary, because that is the exact stale source in the report, and seats.yaml is stale by design during an exchange since its lookups wait for collection to finish. A recorded value checked against the environment at each use, because the recorded copy holds no truth the environment lacks, so the check adds a comparison step at every site to learn which copy to ignore. Reading the address once at Open and keeping it in context, because context is what compaction rewrites, and the carried copy is again the failure mode.

Evidence: [process text, skills/chart-issues/SKILL.md `## Open`, read 2026-11-16] the inside-hc test already reads `$HC_TERMINAL_ID` live and the same paragraph then uses a bare `<door address>` for the column helper with no source named. [process text, assets/questions.md `## Blind peer exchange` Asking, 2026-11-16] every brief ends with `hc send <door address>` and no source is named there either. [process text, skills/chart-issues/SKILL.md `## Open` seat record paragraph, 2026-11-16] seats.yaml address entries append only after collection because the resolver's `hc get` consumes child news, so the record can lag a whole exchange. [probe, free, 2026-11-16] a shell inside an hc terminal on this machine prints `HC_TERMINAL_ID=t1xy`, so the live value reaches agent shells with no hc call at all. [report, INTAKE #138, unverified] the summary and seats.yaml both carried t1tm while the live door ran in t1xr.

Pitfalls: an agent can still write an old address from its summary into a brief without ever running a shell read, since the brief is authored as text. Nothing mechanical stops that, and the chart documentation path has no mechanical check. The Q2 verification is the backstop for the column call, and for briefs the Collecting rule already treats a missing report as a nudge and then a drop only when the return file is also missing. A second pitfall is harnesses whose shell tool runs outside the terminal environment, where `$HC_TERMINAL_ID` could be unset inside the tool while the session sits in hc. The existing Open test would already fail there today, so the pick adds no new exposure, and the door falls back to its outside hc line.

## Q2. The "door not in a tab" exit rule

Pick: the rule changes in one place. A column helper exit saying the door is not in a tab is logged once and the round continues only after one verification: the address just passed equals `$HC_TERMINAL_ID`, and `hc get` on it answers with a live state. When the passed address differs from the environment value, the door reruns the helper once with the environment value and only then treats a repeat exit under the log and continue rule. When the environment value itself does not answer live, the exit is no longer the harmless case and takes the existing line for any other non-zero exit, a check-in for A. The verification reads the door's own terminal only, so the rule against `hc get` on child consultants between waits is untouched. The helper lives in herdr-setup and stays unedited under signpost 2a, so its one message for two causes is worked around on the door side, with a seed owed to herdr-setup if the operator wants the causes split at the source.
Cost: one extra `hc get` on the door itself, only on the failure path of a layout call. The genuinely tabless live door still gets one log line and no layout, exactly as today.

Rejected: keep the rule unchanged and rely on Q1 alone, because the report shows the failure is silent and cosmetic until the operator spots it, and any second stale path, a copied brief template for example, brings it back with no signal. Make the exit a stop or a check-in in all cases, because the column is layout only, the consultants still work, and stopping charting over window geometry inverts the priorities the original rule got right. Fix the helper message in herdr-setup from this chart, against the akrogon only reach in the signposts.

Evidence: [process text, skills/chart-issues/SKILL.md `## Open`, 2026-11-16] the exit is recorded once and the round continues, while any other non-zero exit is already a check-in, so the pick routes the dead address case into a line that exists. [process text, assets/questions.md `## Blind peer exchange` Waiting, 2026-11-16] the `hc get` news consumption warning is about a parent reading a child consultant, not a door reading itself. [report, INTAKE #138, unverified] the helper prints the same message for a finished terminal and a tabless live door, and rerunning with the live address laid the consultants out correctly.

Pitfalls: `hc get` answering live does not prove the terminal sits in the tab the helper searches, since the helper's tab notion comes from the herdr document, outside this repo. A live door in a space or session the helper does not search would verify as live and still exit, landing in log and continue, which is the correct outcome for a layout step. What removes the reported harm is only the mismatch rerun, and the pitfall to name in the leaf is that verification proves liveness, not tab membership.

## Questions the fork does not ask

N1. Supplied consultant addresses go stale the same way when the operator restarts a supplied consultant into a new terminal between door sessions. Their asking rule reads status through `hc get <address>`, so a finished address reads as a consultant that never becomes idle. Does any rule make the door tell a dead supplied address apart from a busy one?

N2. Briefs already written with a dead address exist in live charts, the framework one in the report included. A brief is not edited during an exchange under questions.md, so does the fix leave those to file collection once, or is correcting a report step address a permitted brief edit?

N3. The door outside hc can still run with supplied consultants under `## Open`, and their briefs end with an `hc send` to a door address that does not exist. What is their report step supposed to be, or is file only collection the unstated rule there?

N4. The compaction summary is the vector that carried the dead address. Should the door's own summary writing habit be told to keep hc addresses out of summaries entirely, since every address in them is a stale copy waiting for a restart?
