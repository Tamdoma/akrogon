# Fork notes, slot C: blocked-prompts

## Q1. Removing the claude question tool, and by what route

Pick: akrogon code, per harness kind, in `harnessArgv` (src/seat.ts). It already appends per kind argv for pi (`--session-id` with a fresh UUID). For kind `claude` it appends one more element: `--disallowedTools=AskUserQuestion`. The equals form is deliberate, because `startSeat` and `startConsultant` append the task as the next positional element after harness argv, and the space form takes a variadic tool list that could read the task as a tool name. The change covers leaf seats and consultants, since both build argv through `harnessArgv`. It does not touch operator started sessions. Done claim needs one N1 throwaway claude haiku probe proving the tool is unavailable in session, not only that the flag parses.
Cost: consultants lose AskUserQuestion too. Their question channel is the parent question path over hc, so nothing they rely on goes away. A claude seat that needs a decision now has exactly one route, `phase failed` with cause `blocked`, which is slower than a dialog and leaves a record.

Rejected: the machine config harness line, because it lives in ~/.akrogon/config.yaml outside the repo, drifts per machine, cannot be covered by a repo test, and spends needs row N2 on something code can own. An appended `--settings` permissions deny, because the template already passes one `--settings` flag and the merge behavior of a second one is unobserved. Skill text telling seats not to ask, because a present tool gets used under pressure and text is not removal.

Evidence: [code, src/seat.ts `harnessArgv`, read 2026-11-16] per kind argv append exists for pi today. [probe, free, 2026-11-16] `claude --help` lists `--disallowedTools <tools...>`, and both `claude --disallowedTools=AskUserQuestion --version` and the space form parse and print the version. Parsing is not proof the tool disappears in session, which is why the probe above is owed. [code, src/state.ts `failureSchema`, 2026-11-16] cause `blocked` already exists as the recorded ask-human path.

Pitfalls: a future claude version renaming the flag or the tool breaks every claude seat start at argv parse. The template lines already carry version sensitive flags with the same exposure, and `firstTask` surfaces a dead start in the first pass, so the failure is loud and early rather than a silent return of the dialog. The nastier variant is a silent rename of the tool only, which reopens the dialog with no error anywhere. The N1 probe script kept as a leaf proof is what would catch it on re-run, and nothing automated re-runs it. That limit is stated plainly.

## Q2. Who acts when a leaf seat is blocked

Pick: the controller, split by kind, in `dispatchSlot` (src/next.ts) where the not idle or done early return sits today. The branch runs when `seat.status.state` is `blocked`, and both sub-cases first check a notice gate: id `noticeId(repo.name, 'blocked', slug, slot)`, acted on only when `noticeState` for that id is absent. `observeBusy` already sets `busy_since` for blocked seats, and when the seat leaves working and blocked its cleared branch also removes this blocked notice beside the busy one, so one act happens per blocked episode with no new state field.
Permission kind, and only for harness kinds in one named set in src/next.ts, `PERMISSION_RELEASE`, starting as `new Set(['agy'])`: send one enter through `keys()` in src/hc.ts, then write the notice with attention false, title `Blocked leaf: <repo>/<slug> seat <slot> permission prompt released`, body the status `msg` when present. The harness kind comes from `seats(global, repo, leaf.path)` in src/config.ts for the slot, the same lookup `startSeat` uses. Claude joins the set only when an N1 probe shows its real permission screen and that one enter selects yes. Codex and pi stay out until a probe shows a prompt screen at all.
Question, auth, unknown kind, or a harness outside the set: no keys. Write the same notice id with attention true, title `Blocked leaf: <repo>/<slug> seat <slot> needs you`, body the status `msg` when present and the `screen()` text when it is not. To stop double notification, `observeBusy` keeps tracking `busy_since` for blocked seats but skips its 60 minute busy writeNotice when the status state is blocked.
Cost: the controller gains a prompt answering power it never had, bounded to one enter per episode on probed harnesses. Every act writes a notice, which is the audit the operator reads in the morning.

Rejected: the watch skill reading and answering, because it wakes on a 20 minute cron instead of the listener wake, its own hc calls are the ones the classifier denied in the report, and an LLM judging screens is the most parts version of this fix. Immediate attention notice for permission kinds too, with no release, because a template leakage permission prompt on a launched seat then still stalls the leaf all night, which is the reported harm. That option is the fallback per harness whenever a probe shows enter is not a reliable yes. Release for every harness without probes, against hard limit C L7 as carried.

Evidence: [code, src/seat.ts `agyTask`, 2026-11-16] one enter on `blocked` with kind permission is already the shipping behavior during agy first task delivery. [code, src/listen.ts `onLine`, 2026-11-16] a blocked status already enqueues a wake, so the controller path reacts in seconds with no new trigger. [code, src/next.ts `observeBusy`, 2026-11-16] blocked counts as busy for `busy_since`, and the busy notice waits out `STALL_MS` at 60 minutes with attention false. [carried observation, fork carries, A 2026-11-16] `hc get --json` surfaces kind for a blocked terminal while `msg` did not appear for the synthetic value, so the body falls back to screen text.

Pitfalls: enter selects the highlighted default, which a harness could set to the safe answer No on some dialogs, and the seat then sits blocked with its one release spent until the operator reads the notice. The notice gate makes that visible instead of looping keys into the tab. A permission prompt during the `firstTask` start proof for a non agy kind times out the 60 second proof and records a delivery error, and the release only lands on a later wake, so a first task can still start unconfirmed once. Template drift is the lifetime risk: the release argument rests on launched seats running with permissions already skipped, and if a machine template drops that flag, the controller starts releasing real permission decisions. The named set plus the per episode notice is the bound that keeps that readable.
