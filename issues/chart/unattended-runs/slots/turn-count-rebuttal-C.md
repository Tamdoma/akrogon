# Rebuttal, slot C: turn-count

R1 (Q1 double charge). The merged C line understates the risk and B adds a field it does not need. A throw between the counting write and a successful `deliver` leaves `prompted[slot]` old and `seat.turn` unchanged, so the next pass counts the same turn end again. Throws there are real, since `send` raises `HcError` and src/seat.ts `agyTask` already handles its unavailable kind. A's guard, clearing `prompted[slot]` in the counting write, closes this with no new field, so B's persisted `counted_prompt` cursor is an unneeded part. C accepts A's guard over its own accept line.

R2 (Q2 hung run). A's "let the wait feed the 60-min busy notice" does not happen with current code. `observeBusy` in src/next.ts clears `busy_since` whenever the seat status is neither working nor blocked, and a seat waiting on a background run is idle, so no busy clock ever runs for it. B's completion wake couples every run-check run, verify stages included, to a following `next --wake` pass. The listener queue is single flight, which bounds duplicate passes, but the coupling still makes the cheapest check queue controller work. The `STALL_MS` age bound on the run record needs neither.

R3 (Q3 shape). C changes its pick. The window shape alone allows unbounded paid starts across windows, three starts per 10 minutes all night, and the #137 transcripts end on an api-request record, so each start spends a paid first call. A's shape, a per phase visit loss count failing at 3, bounds that spend the way attempts always have. C now prefers A's shape with the agreed resets. Two disagreements stand inside it. B's cause `blocked` reuses the seat reported human prerequisite cause from src/state.ts `failureSchema` for a controller detected seat loss, which muddles the watch skill's reason based recovery classes. B's `lost_seat` identity field guards a double charge that the global lock already prevents, since dispatch passes serialize under the global home lock as seen in `phaseWake` and `seatCommand` in src/next.ts, and `startSeat` records the new address before any later pass can see the old seat again.

R4 (Q4 evidence). One thing is missing from the C line. The `delivery_error` shape has no exit code or signal fields and `seatDeliveryErrorSchema` is a strictObject, so it cannot carry the two facts #137 actually lost. Whichever home wins, `terminalSchema` in src/hc.ts must first parse the `exit_code` and `signal` fields A observed, and the record shape must carry them. Against B: keeping the terminal when the evidence write fails blocks the replacement start to protect a log line, and reconcile teardown in `endSeats` has no such gate today.

R5 (Q5 migration). Against B's lazy marker. `attempts_rule` is a permanent state field bought for a one-time reset, and the reset also forgives leaves whose old counts came from real turn ends on the redelivery path, not only from starts.
