Dispatch should run `flock <akrogon-install.lock> sh -c <setup>` and call `guard(worktree, ['own-modules'])` (`src/guard.ts:guard`) in-process.
- **Q2 (`slots/map-merged.md`)**: Lists D's "skipped while a seat is live" alongside C's "never while a seat in the worktree is working" without surfacing that `live` in `src/next.ts:allocate` (`liveSeat(found.A) || liveSeat(found.B)`) is `true` for *idle* live seats too, which breaks M4's post-restack refresh (detailed in Q2 below).

## 3. Under Q1b, can a stale marker coincide with a sibling seat working in the same worktree?

**Yes — four concrete paths produce a missing or stale marker while seat A is `live` and `working` in the worktree (so an unguarded setup for seat B would run a wiping `npm ci` right under A):**

1. **Config `setup` changed on `main` mid-leaf (`selfUpdate` / `akrogon sync`)**: Leaf L in `pi-extensions` starts with marker `setup = S1`. While seat A is `working` in `implement`, another leaf lands an edit to `issues/config.yaml` changing `setup` to `S2`, and `src/self-update.ts:moveCheckout` advances `repo.root`. Seat A calls `akrogon phase L check.review --slot A` mid-turn -> `src/next.ts:phaseWake` reads `S2` from `repo.root/issues/config.yaml`, sees `marker (S1) !== S2`, and `dispatchLeaf` starts seat B while A is still `working`.
2. **Release rollout onto an in-flight leaf**: Leaf L already has seat A `live` and `working` in `implement` when the akrogon release introducing the marker deploys via `selfUpdate`. Seat A calls `akrogon phase L check.review --slot A` -> `phaseWake` finds **no marker** in L's worktree while A is still `working`, and `dispatchLeaf` starts seat B.
3. **Manual `akrogon seat <slug> B` while A is working**: Operator runs `akrogon seat L B` (`src/next.ts:seatCommand` -> `allocate`) while seat A is `working` in L and the marker is absent (pre-upgrade) or stale (config changed).
4. **Mid-turn `node_modules` removal with the `package.json`-without-`node_modules` extra trigger**: Seat A is `working` and runs `rm -rf node_modules && bun install` (or `npm ci`, which deletes `node_modules` before extracting). A concurrent `next --wake` or `phaseWake` during that window sees `package.json` without `node_modules` while A is `working`.

**How to close all four cleanly (with Q1b + Q2b)**: Check `busy = seatBusy(found.A) || seatBusy(found.B) || leafHasLiveRun` in `allocate`/`ensureWorktree` (`seatBusy(t)` = `liveSeat(t) && t.status?.state !== 'idle' && t.status?.state !== 'done'`).
- If the marker is **valid** (the 99.9% case on `implement -> check.review`), setup is not needed and B starts immediately while A finishes its turn.
- If the marker is **missing or stale** and `!busy`, run setup once in `ensureWorktree` before `saveState` and before the `for (slot)` loop (covers fresh creation, adoption, recreation, and `merge -> applyTop -> check.repair` where seats are live-and-idle).
- If the marker is **missing or stale** and `busy` is `true`, **defer** (return waiting / do not run setup and do not launch B while A is mid-turn): as soon as A finishes its turn, `hc` emits a `turn` event, `src/listen.ts` queues `next --wake`, now `!busy` holds, setup runs safely with no working seat, and both A and B dispatch cleanly. (For `seatCommand` invoked manually while a sibling is working and setup is stale, refuse loudly naming the busy sibling seat.)
