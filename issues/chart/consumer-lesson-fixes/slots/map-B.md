# #141: Workers can pop a sibling’s stash

**Reproduced.** With Git 2.56.1, I made two detached worktrees in a temp repo. U1 stashed a tracked edit. U2 ran an ordinary `git stash pop` and received U1’s edit. Enabling per-worktree config and giving U2 its own setting did not isolate the ref. Worker protocol “Launch and return” creates these worktrees with a Git command run by A, not a worker-specific akrogon launcher.

**D1. Remove the shared ref or tell workers not to use it?** Prefer a private local clone per delegated leaf worker, detached at the lane’s committed SHA. It isolates normal Git commands in every harness without changing stash for the registered checkout. A WIP-commit instruction is cheaper but leaves the demonstrated swap reachable. A shell alias or harness hook misses ordinary invocations. A hook that rejects a stash-ref write is too late for an apply that reads a sibling’s stash.

**D2. How does a result come back?** Fetch the returned commit from the worker before cherry-picking it. A SHA alone no longer suffices. In my temp probe the clone could stash without changing the lane’s empty stash, and A fetched and cherry-picked the detached commit locally without a network remote. Do not push worker refs into the consumer’s remote.

**Q1. What assumes the worker shares the lane’s Git directory?** Akrogon’s `currentRepo` matches the common Git directory, so commands requiring a registered repo will not recognize a clone from its cwd. Check actual worker commands, repo-local config/hooks and any targeted tests that depend on checkout identity before locking the clone design. Keep lifecycle commands in A’s registered lane. Do not silently register clones or copy credentials to make tests pass.

**Q2. Who owns unfinished edits?** “Failure ownership” retains a worker on conflict or interruption. A missing path, occupied path, dirty clone, private stash, failed fetch or failed pick is not permission to delete work. A clone is not a `git worktree remove` target. Keep the existing occupied-path refusal and verify reconciliation for unregistered worker directories and recovery for previously retained linked workers. Do not run a resumed worker against a shared stash while claiming isolation.

**Proof and Retire.** Replay the two-worker failure with distinct tracked edits using the chosen creation path. Each pop must restore only its own edit, the lane’s existing stash must survive, and an unpushed worker commit must land on the lane. Read the conflict/resume and cleanup paths against that topology. No paid seats. The cited worker lesson can retire under today’s rule if the shared-ref mechanism is gone on all affected paths, including resume. Prose alone does not qualify. Leave standalone/inline runs and the registered checkout’s autostash alone.
