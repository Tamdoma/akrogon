## Q2. Context between turns?

1. Pick: retain each named peer's existing session and harness compaction behavior. Add no fixed context ceiling, forced per-fork compaction or reset cadence. Bound newly supplied context by the current exchange's job. A supplies intake, current Question and carries, related fork paths, locks and verbatim corrections for blind notes. Rebuttals receive the merged notes. Final checks receive the proposed shape and correction. Link existing evidence rather than copying the whole map or prior exchanges into each brief. A peer reads relevant linked detail when needed, reusing unchanged material already read. Cost: old history remains until harness compaction, so this supplies no hard bound on resident context and no proven saving. It also depends on good carries and targeted retrieval.

2. Rejected: reset each fork. Fresh startup has a measured cost and loses continuity. Reset between notes and rebuttal is particularly undesirable because a peer needs its independent position to detect misattribution. Reject forced compaction each fork or at an invented token threshold. Neither has a measured quality or cost result here. Reject repeatedly loading the entire map and transcript. Preserve access to evidence without requiring wholesale reloads. Do not describe short file prompts as clearing accumulated history.

3. Evidence: operator-placed measurements, read 2026-10-06, `forks/peer-packet.md:16-18`: C's later cache-read charges were $1.60, 12% of its bill. A fresh C session's startup cache write was about $0.90 before work, against $0.64-0.90 for a measured later notes turn. B took 1-3 minutes across context sizes, with dollars unmeasured. These observations do not establish that larger context caused slower turns or that resets save money. Primary local instructions, read 2026-10-06, `skills/chart-issues/SKILL.md:6` and `assets/questions.md:48,50`: reuse unchanged reads, resume from chart context after compaction and preserve the distinct blind/rebuttal/final-check exchange.

Practitioner evidence, read 2026-10-06: Anthropic's Applied AI team, including Prithvi Rajasekaran and Jeremy Hadfield, describe their Claude Code experience in [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents). They recommend references and targeted retrieval, with compaction preserving important decisions, and warn that aggressive compression loses subtle context. Justin Young reports long-running Agent SDK experiments in [Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents): compaction alone was insufficient, and durable progress artifacts supported continuity. Both favor recoverable state. Their emphasis differs between conversational continuity and independent coding sessions. For this attended chart, existing chart and peer files support recovery without introducing a new restart protocol. Neither source demonstrates chart-specific savings.

4. Pitfalls: a carry omits a dependency or operator correction. Preserve material locks and verbatim corrections with links to their owning forks, allowing the peer to inspect source detail. Compaction loses the peer's dissent. Retain the peer's own notes and rebuttals as recovery evidence, without exposing another peer's blind work. A compact brief becomes A's argument instead of shared context. Preserve the current exclusion of A's draft, Findings and other peer work. Linked files change after earlier inspection. Re-read changed material rather than applying the unchanged-file reuse rule. Claimed savings exclude startup, compaction or repeated tool reads. In proof-of-saving, compare total per-fork usage and time through final checks, plus decision coverage. Savings from this pick remain unmeasured.

5. Missing question: none required for this choice. If a physical context ceiling is wanted, the unresolved question is whether a particular harness-supported compaction or reset strategy preserves dissent and costs less across the entire fork. The current measurements cannot answer it.
