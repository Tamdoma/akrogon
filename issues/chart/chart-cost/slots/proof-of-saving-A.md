# proof-of-saving, A's notes

- Pick: each chart records its own usage. At open the door writes one line per seat in CHART.md with pane, harness kind and session id from `herdr agent list`. Before the handoff review the door runs one script that reads those sessions from the chart's start time and appends a short Usage block to CHART.md: per seat minutes of work, turns, output tokens, cache read and write tokens, recorded dollars where the harness records them, the first (map) turn on its own line, the model and effort found in the transcript, and the count of operator rounds and of restatement requests as counted by the door. Comparing charts is then reading Usage blocks, normalised per operator round. Reason: the chart keeps its own cost, so proof needs no later search and no model or price is written into the skill. Cost: one script to build and keep working against two harness transcript formats, and one call per chart of a few hundred tokens.
- Rejected: measuring by hand when asked (today's cost, and sessions must be found by search). A price table for B's dollars (hard codes models and prices). Recording model and effort by hand at open (the transcript already holds them). A per-fork breakdown in the script (needs fork boundaries the transcript does not mark; per-round normalisation is enough).
- Evidence: forks/proof-of-saving.md Carries; herdr agent list output and the cost-state record, inspected 2026-10-06.
- Pitfalls: a transcript format change breaks the script. Removed by the script failing with the file and field it could not read, and the door recording "usage unmeasured" with that error, never blocking handoff. A session that spans two charts. Removed by reading from the chart's recorded start time to the script's run time. Charts of different size compared raw. Removed by per-round figures. Three charts being too few to separate noise. Not removed: the Usage blocks accumulate and the comparison is redone when more exist.
