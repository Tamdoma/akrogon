## Defects and conflicts

### D1 — item 5 as written leaves a permanently false `busy` flag (the common case)

Item 5 scopes busy *writes* to the current phase's required slots. But `busy_since` survives phase moves — `commitMove` preserves it except for `failed`/`merged` (`src/phase.ts:commitMove`, read 2026-11-25) — and clearing happens only inside `observeBusy` when the terminal is *read* and no longer working (`src/next.ts:observeBusy`). The common case: the door is busy as A through `implement`, the leaf moves to `check.review` where only B is required, A is never read again, and status shows `busy A <hours>` for the leaf's whole review and merge lifetime — a false signal in the exact column this fork exists to make truthful. Lifecycle never hits this because its dispatch observes every recorded seat each pass. Fix, one clause in the same item: writes still scoped to required slots, but every recorded seat is *read* so a seat no longer working gets cleared. Cost of not fixing: the busy display lies for most of the leaf's visible life.

### D2 — item 13 accepts a regression that a zero-cost write removes entirely

Verified the mechanics: with no `state.frozen`, `requireFrozenCitations` never runs, and since `requireTestChangeCitations` covers only M/D/T test files, **added** test files escape the citation gate entirely for direct leaves (`src/phase.ts:moveGuards`, `requireFrozenCitations`, `requireTestChangeCitations` — read 2026-11-25). The item's factual claim is true — nothing is lost against today's direct-guards, which never checked it — so this is not a deception, but it is a permanent weakening of the merge-gate contract against a lifecycle leaf, chosen while a zero-cost exact match exists: the creation verb writes `frozen: {}` (and `frozen_cited: []`) into the initial state. At creation the branch is unmodified, exactly as at the `plan.synthesis -> implement` move where lifecycle writes the same record (`frozenRecord` on an unchanged tree yields `{}`), so the gate then runs with precisely lifecycle semantics — every added test file needs a `Test-Change:` trailer, everything else unchanged. The shapes' state.yaml template already has the door writing initial state, so this is two lines in the door's write, not a mechanism. What breaks if the item stands as written: direct leaves can land uncited test additions that any lifecycle leaf would be refused for, and the divergence is invisible in status — discovered only when someone reads the diff at merge.

### D3 — item 12's deletion destroys the attempt's evidence, unlike any lifecycle disposition

On abandon or growth-stop-to-lifecycle, item 12 deletes the leaf's owner folder. Under item 10 the review files live in the leaf folder (B uses the lifecycle check-issue task, which writes `review-B.md` under `leaf=`), as do `implementation/report.md` and the run-check logs published under `<leaf>/implementation` (`src/run-check.ts:leafTarget` targets that path — read 2026-11-25). Deleting the folder erases all of it. Every lifecycle terminal disposition preserves evidence: failed leaves persist and are packed, merged owners move to `issues/closed` intact. The chart keeps only brief, design and reason. What breaks: the post-mortem trail for the exact attempts most likely to need one (abandoned or growth-stopped work), and the growth-stop handoff loses the evidence the lifecycle planner would use to decide what to keep. Fix options: `akrogon pack` the owner into the chart before deletion, or move the folder rather than delete. If the evidence loss is deliberate it should be named in the shape like item 13's was.

### D4 — item 16's one-shot send leaves its failure semantics unstated, and the two readings diverge materially

"Sends the existing broadcast prompt once when it reads idle or done, recording `prompted.B` on a started send and `delivery_error.B` otherwise" does not say what later passes do with a recorded `delivery_error.B`. The lifecycle answer exists and is non-obvious: at most one send per turn, then the error is *resettled as delivered* once the seat's turn advances — never a resend (`src/next.ts:dispatchSlot`, the `error.turn >= seat.turn` settlement — read 2026-11-25). Copying that is one behavior; retrying every pass is another (a queued duplicate prompt if the first did land); never retrying is a third (a broadcast lost to one transient send failure, with `broadcast pending` clearing only by the door's item-17 vigilance). The ack's meaning changes with the choice, so the shape should name it; the smallest correct copy is lifecycle's settlement rule verbatim.
