# Fork blind notes: slot C — direct-visible / direct-leaf

## Q1. What record carries a direct-route attempt so `akrogon status` shows it like a lifecycle leaf?

### Pick
**Q1a** — A real leaf under `issues/open/<owner>/<slug>/` whose `state.yaml` carries one optional marker field (`direct: true`), created by one akrogon verb (leaf folder with `brief.md`, `design.md`, `state.yaml` at `implement`, unlocked sparse worktree under `worktreeStore`, `.env` emitted, recorded `worktree` and `seat.A`/`seat.B`, no `tab`).

- **Reason**: Satisfies the operator lock ("tracked like a lifecycle leaf", "`akrogon status` shows it exactly like a lifecycle leaf: its phase, its seats and its runs", "broadcasts on landing like a lifecycle leaf") and signposts `1a`, `3a`, `6a` in one stroke. Because `issues/open/<owner>/<slug>/state.yaml` is the single source of truth read by `src/status.ts`, `src/run-check.ts`, `src/verify.ts`, `src/config.ts`, `src/log.ts`, `src/timing.ts`, `src/timing-report.ts`, `src/turn.ts`, `src/land.ts`, `src/phase.ts`, and `src/reconcile.ts`, direct work automatically gains the full status table row, `akrogon status <slug>`, `akrogon status --json` (panel/board + recent `merges`), automatic worktree-based `run-check`/`verify` attribution (including `-u<N>` workers and `leafSlice`), serialized `mergeQueue` participation, `log.jsonl`/`timings.jsonl` history, and zero migration for existing records. It also makes direct-to-lifecycle handoff on growth stop trivial (the leaf folder, brief, design, and worktree already exist in place).
- **Cost**: Every command path that starts, prompts, renames, closes, kills, or counts a seat or tab must honor `state.direct === true` so the command never spawns a new tab or harms the door/reviewer terminals. Exhaustive path audit:
  - **`dispatch` (`src/next.ts` `dispatchLeaf`, `dispatchSlot`, called via `resumeRepos`, `sweep`, `phaseWake`, `nextCommand`)**: Observe live busy/blocked on recorded seats (via direct `hc` terminal lookup, never `leafSeats`), run `completeOwner` when `phase === 'merged'`, clear notices on `failed`, and **stop before `allocate` and `dispatchSlot`** when `state.direct` is true. Never start a seat, never send a phase prompt, never call `end()` on a finished seat, and never charge `attempts` or `lost` toward `failed`.
  - **`allocate` (`src/next.ts` `allocate`, plus `seatCommand`)**: Refuse/bypass for `state.direct === true` so it never checks `capRefusal`, never mints `state.tab = leafTab(...)`, and never re-runs worktree/env setup during dispatch or broadcast. `akrogon seat <slug> <A|B>` (`seatCommand`) must refuse a direct leaf outright.
  - **`reconcile` (`src/reconcile.ts` `reconcile`, `reconcileHost`, `leafSeats`, `endSeats`, `closeLeaf`, `closeMergedTab`, `closeTabOf`, `endFinishedSeats`, `mergedWorktree`, `sliceKeepReason`, `reconcileNeedsPanes`, `broadcastInProgress`; plus `src/next.ts` `landedWake`)**: `state.direct` must stop `endSeats`, `closeLeaf`, `closeTabOf`, `closeMergedTab`, and `endFinishedSeats` from ever killing/removing recorded terminals or closing any tab. Keep `leafSeats` restricted to `akrogon.leaf`-labelled owned seats so no teardown path can accidentally kill door/reviewer terminals. `reconcile` still safely removes the unlocked merged/failed worktree, deletes the branch, cleans `leafTemp`, and stops the empty `leafSlice` (only `run-check` and `land` run in `leafSlice`; door and consultant processes sit outside it).
  - **`stop` (`src/stop.ts` `stopLeaf`, `stopCommand`, `startCommand`)**: `stopLeaf` must skip `endSeats` for `state.direct === true` (never killing the door or reviewer), while still stopping `leafSlice`, cancelling `run-check` runs, and stopping active `land`/verify pass units. `stopCommand --all` (which currently filters `tab !== undefined || batch !== undefined`) must decide whether to include active `direct` leaves (at least when in `merge` / running checks, without touching door/reviewer terminals).
  - **`renameTabs` (`src/next.ts` `renameTabs`) and `src/phase.ts` (`renameTab`, `announceFailed`, `commitMove`)**: `state.direct` leaves `state.tab` undefined and explicitly guards `renameTabs`/`renameTab` so the door's tab is never renamed (even on `failed` or recovery).
  - **`status unnamedTabs` (`src/status.ts` `unnamedTabs`)**: Skip `state.direct` (and `state.tab` stays undefined) so `status` never prints `tab unnamed` for the charting tab.
  - **`activeCount` (`src/next.ts` `activeCount`, feeding `capRefusal`)**: Exclude `state.direct` from `unfinished` and `seated`. Without this, the session-refused fallback (`seated` checks `tab !== undefined || worktree !== undefined`) would count a direct leaf's recorded `worktree` against global and repo `max_active`.
  - **`broadcastPass` (`src/next.ts` `broadcastPass`)**: Must NOT call `allocate` or `dispatchSlot` for `state.direct` (calling `allocate` would mint `state.tab` and recreate a removed worktree; calling `dispatchSlot` would miss `leafSeats` and invoke `startSeat`, opening a new tab). Instead dispatch directly per Q3a.
  - **`park` (`src/park.ts` `running`)**: Checks `tab !== undefined || worktree !== undefined`, which already safely refuses to park an active direct leaf with a worktree.

### Pitfalls (and what removes each)
1. **Reconcile or `stop` killing the charting door or reviewer terminal, or closing/renaming the charting tab (catastrophic)**:
   - *Removed by*: Never setting `state.tab` on a `direct` leaf; guarding `dispatchLeaf`, `allocate`, `seatCommand`, `renameTabs`, `phase.ts:renameTab`, `unnamedTabs`, `endSeats`, `closeLeaf`, `closeTabOf`, `closeMergedTab`, `endFinishedSeats`, and `broadcastPass` on `state.direct`; keeping `leafSeats` strictly for `akrogon.leaf`-labelled seats; adding unit tests asserting zero `hc kill`/`hc rm`/`tab.close`/`tab.rename`/`startSeat` calls for a `direct` leaf across `next`, `reconcile`, `stop`, `phase`, and `landedWake`.
2. **Phantom open leaf after abandoning a direct attempt (growth stop -> abandon / `Held`)**:
   - *Removed by*: Providing an abandon/clean step (either in the direct verb or via `direct-route.md`) that removes the worktree, deletes the branch, and removes the `issues/open/<owner>/` folder when abandoning an unmerged direct leaf so no abandoned leaf lingers in `akrogon status`.
3. **Duplicate display between `akrogon status` and `akrogon status --charts`, or stale `CHART.md` stage**:
   - *Removed by*: Updating `CHART.md` `Direct attempt` to point to the leaf slug/folder (same as a handoff) and marking `Closed <date>` (or `Held <date>`) when the leaf lands or is abandoned; `akrogon status` shows the leaf table, `--charts` shows the chart table, matching lifecycle handoffs.
4. **Session-refused `activeCount` charging a direct leaf against `max_active`**:
   - *Removed by*: Excluding `leaf.state.direct === true` from `unfinished` and `seated` in `src/next.ts` `activeCount`.
5. **Dual-layout drift between `<chart>/direct/` and `<leaf>/implementation/`**:
   - *Removed by*: Moving direct `plan.md` to `<leaf>/plan.md` and `report.md`/logs to `<leaf>/implementation/` (keeping `src/evidence.ts` `locate` and `src/pack-command.ts` support for historical `issues/chart/<chart>/direct` intact per signpost `6a`).

### Questions the fork does not ask
1. **What should the creation/management CLI verb look like, and what happens on Abandon and Lifecycle Handoff?** Specifically: should one verb (e.g., `akrogon direct open|seat|handoff|abandon` or `akrogon direct ...`) handle (a) creating the leaf + worktree + `state.yaml` at `implement`, (b) updating `seat.B` when the reviewer changes, (c) converting a direct leaf to a normal lifecycle leaf at `plan.synthesis` on growth stop (clearing `direct` and `seat`), and (d) cleaning up the open leaf folder + worktree + branch on abandon?

## Q2. Who lands a direct attempt?

### Pick
**Q2a** — The command lands it: a ready review moves the leaf to `merge`, and the existing `mergeQueue`, `mergeTurn`, and `akrogon land` verify, gate, push, close sources, move the owner to `issues/closed`, and record `state.broadcast`. `skills/chart-issues/assets/direct-route.md` landing steps 5–9 and `skills/chart-issues/scripts/direct-guards.ts` are removed.

- **Reason**: Eliminates an entire duplicated landing stack (prose + `direct-guards.ts`) that has already drifted from `src/land.ts`. Direct work enters the repo's single serialized `mergeQueue` instead of racing concurrent lifecycle pushes on `<remote>/<default_branch>`, and automatically inherits crash-safe restack + `reconcileBatch`, `mainRedCover` + Taken-8 base pass + flaky reruns + slow-merge tracking, `retiredLessonsPresent` / `removeRetiredLessons`, `refuseAbandonedCaptures`, exclusive-locked log stripping + `closeSources` + `issues/closed` archival in `completeOwner`, `reconcile` worktree/branch cleanup, and atomic `state.broadcast` handoff. Matches signpost `1a` and the operator's simplicity/clarity/elegance instruction.
- **Cost**: Requires closing five concrete gaps between what the direct route provides today and what `mergeTurn` + `akrogon land` + `phase` need from a leaf:
  1. **Leaf folder, contract files, and `plan.md`**: Today direct writes no leaf files (`docs/use/quick-fix.md` `## What it skips and what it keeps`) and puts `plan.md`/`report.md` under `<chart>/direct/`. The land run and completion pipeline need: `issues/open/<owner>/<slug>/state.yaml` (with `sources` populated so `completeOwner` calls `closeSources`), `brief.md` and `design.md` inside the leaf folder (because `completeOwner` moves `issues/open/<owner>` to `issues/closed/<owner>` and `broadcast-issue` reads the briefs from `closed=`), and `<leaf>/plan.md` + `<leaf>/implementation/report.md` (which `status` and `check-issue` reference).
  2. **Receipts (`leaf`-scope pre-review, `merge`-scope during land)**: Today direct skips `leaf`-scope verify and only runs `akrogon verify --holder <chart>/direct` (`merge` scope) at landing step 5.3. Under `src/phase.ts` `transition`, moving `implement -> check.review` (and `check.fix -> check.review`, and edited `check.repair -> merge`) enforces `requireNonEmpty` and `requireGreenReceipt(..., 'leaf')` (fast `checks` only), so A runs `akrogon verify` in the leaf worktree before moving to `check.review`. `akrogon land` then runs `verify(..., attempt)` (`merge` scope) and `landGates` (`batchGuards` + `moveGuards` + `recordTested`) itself. Note `state.frozen` is undefined when starting at `implement`, which `moveGuards` already skips cleanly while still enforcing `requireTestChangeCitations`.
  3. **`check.review` slots and repair-phase routing**: Today `src/routing.ts` `requiredSlots('check.review', 0)` returns `['A', 'B']`, so a direct leaf (where only B reviews) would stall in `check.review` waiting for slot A on round 0, and `status --json` `waits_on` / `timing-report` would expect two slots. `requiredSlots` must return `['B']` for `direct` leaves even when `fix_rounds === 0`. Furthermore, `src/routing.ts` routes `check.review` verdict `fix` to `check.repair` (slot `B`, legal `next`: `merge | check.fix | failed` — not `check.review`), while `land.ts` `repairExit` and `next.ts` `mergeTurnExit` always move failed merges to `check.repair` with `merge_exit`. Direct leaves need `check.review` (`fix`) to route to `check.fix` (slot A repairs and returns to `check.review` for B's re-check, incrementing `fix_rounds`), and when `land` exits to `check.repair` with `merge_exit`, the door handles `check.repair` (moving `check.repair -> check.fix` when code/conflict edits need B's re-check, or `check.repair -> merge` for a non-edit recovery).
  4. **Worktree adoption and unlock state**: Today `direct-route.md` step 1 creates the worktree with `git worktree add --lock --reason "<chart-folder> direct"` and does not emit `.env`. `batch.ts` (`buildStack`, `applyTop`/`move`) expects `state.worktree` at `<worktree_store>/<slug>` on clean branch `refs/heads/<slug>`; `reconcile.ts` refuses to remove locked worktrees (`keepLocked`); `phase.ts` `refuseWorkerWorktrees` rejects leftover `-u<N>` worker worktrees before phase moves. The creation verb must create the worktree unlocked via `createSparseWorktree` + `writeLeafEnv`/`emitEnvFile`, record `state.worktree`, and clean any `-u<N>` workers before moving phases.
  5. **Door handback after asynchronous `akrogon land`**: `mergeTurn` launches `akrogon-land-<attempt>` asynchronously and `dispatchLeaf` does not prompt the door for `direct` leaves. The door needs a deterministic way to learn when landing reaches `merged` (to write the pushed SHA and `Closed <date>` in `CHART.md`), `check.repair` (to read `merge_exit` and repair within `fix_rounds`), or `failed`.

### Rejected options

### Pitfalls (and what removes each)

### Questions the fork does not ask
1. **When `akrogon land` exits a direct leaf to `check.repair` (`red`, `gate`, `conflict`, `dirty`), should slot A (the door) or slot B (the reviewer) own `check.repair`?** In lifecycle leaves, `check.repair` belongs to slot B (`src/routing.ts`), who fixes minor reds/conflicts or escalates to `check.fix` for A. In the direct route, B is a review-only consultant (`skills/check-issue/SKILL.md` `## Standalone review`: "commits nothing") and A owns edits and conflict resolution (with B re-checking). Deciding whether `check.repair` on a `direct` leaf accepts slot A (door inspects `merge_exit` and escalates to `check.fix` or returns to `merge`) avoids awkward slot-flag mismatches.
2. **Does the door wait for `akrogon land` to finish before starting the next chart in autopilot, or move on and let `land` finish in the background?** Waiting guarantees `CHART.md` gets `Closed <date>` + SHA immediately and any `check.repair` exit is handled in the same chart context, at the cost of blocking the door during `merge_checks`. Moving on pipelines multiple charts, but requires a wake back to the door when `land` finishes or exits to `check.repair`.

## Q3. How do the seats and the landing broadcast run without a new tab?

### Pick
**Q3a** — `state.seat` records `A = { session, address }` (the door's terminal) and `B = { session, address }` (the reviewer's terminal). The command observes busy/blocked directly on those terminals like any seat, and `broadcastPass` sends the `broadcast-issue` prompt only to the recorded `B` while it is live and `idle`/`done` (using `hc send --if idle`), never calling `allocate` or `startSeat` and never opening a tab. The door rewrites `state.seat.B` when the reviewer changes.

- **Reason**: Matches the operator lock ("run in the charting door's current tab (not a new tab) by the current charting slot A, with whichever slot is the reviewer", "`akrogon status` shows it exactly like a lifecycle leaf: its phase, its seats and its runs", "broadcasts on landing like a lifecycle leaf") and pairs seamlessly with Q2a. Because `akrogon land` runs asynchronously through `mergeQueue`, having `commandMerged` write `state.broadcast` and `broadcastPass` deliver it to `B` guarantees broadcast happens even if the door compacted, moved to the next chart, or closed — directly resolving the operator's `INTAKE.md` doubt that direct landings were not broadcasting. Reuses existing `state.seat`, `state.busy_since`, `state.broadcast`, `broadcastPending`, and `state.prompted.B` with zero new broadcast-ack verbs, and automatically inherits any busy-detection improvements from `seat-turn-idle` (#157).
- **Cost**:
  - `observeBusy` for a `direct` leaf must resolve `state.seat` directly via `hc` (`terminal(ref.session, ref.address)`, treating `not_found` as absent) instead of `leafSeats` (which filters by `akrogon.leaf` + `akrogon.seat` labels that door and operator-supplied or `slot-d` consultant terminals do not carry).
  - `broadcastPass` gains a small `direct` branch that skips `allocate` and `dispatchSlot` and calls `send(ref.session, ref.address, prompt, { if: 'idle' })` only when `B` is live and `idle`/`done`, recording `prompted.B` on `started: true` or `delivery_error.B` on failure (never calling `startSeat` or `end`).
  - The door must update `state.seat.B` (via a small command flag/verb) whenever the reviewer terminal is restarted or swapped.
  - `src/reconcile.ts` `broadcastInProgress` must check turn completion so a reused `B` terminal working on later charts does not hold old worktree/slice cleanup forever.

### Rejected options
- **Q3b (door sends the broadcast itself and marks it sent through a command; recorded seats are display-only)**:
  - Breaks asynchronous/queued landing (Q2a): if `akrogon land` finishes minutes later while the door is busy, compacted, or exited, the broadcast is delayed or silently dropped until the door notices and runs both `broadcast-issue` and a new "mark broadcast sent" command.
  - Introduces a second broadcast mechanism and an extra CLI command to acknowledge broadcast, keeping the special-case door-sender prose in `skills/broadcast-issue/SKILL.md` and `direct-route.md`.
  - Leaves `state.seat` static/display-only: `observeBusy` never runs, so `akrogon status` and `status --json` never show live `busy A <dur>` / `busy B <dur>` or fire `blocked` notices — failing full parity with lifecycle leaf rows.

### Pitfalls (and what removes each)
1. **Race between `broadcastPass` sending to `B` and the door sending `B` the next chart's prompt**:
   - *Removed by*: Sending the broadcast with `send(..., { if: 'idle' })` so `broadcastPass` never collides with an active charting/review turn, AND updating the door's asking step (`questions.md` / `direct-route.md`) so after a direct leaf enters `merge` the door checks `hc get <B>` (or waits for `B` idle) before its next ask to `B` instead of relying solely on `B`'s cached last wake, preventing a spurious `started: false` fatal error.
2. **`broadcastInProgress` permanently blocking worktree/slice cleanup when `B` is reused for later charts**:
   - *Removed by*: Updating `broadcastInProgress` (`src/reconcile.ts`) to return `false` once `prompted.B` is an object matching `t.address` and `t.turn > prompted.B.turn` (proving the broadcast turn itself finished, even if `B` later went `working` on another chart).
3. **False `busy A` / 1h stall notices when the door works on other charts while a direct leaf sits in `check.review` or `merge`**:
   - *Removed by*: Scoping `observeBusy` for `direct` leaves to the phase's active slots (`requiredSlots` — e.g. `A` in `implement`/`check.fix`, `B` in `check.review`/`check.repair`, neither in `merge`), clearing `busy_since` on inactive slots so unrelated charting work in the door terminal never shows as `busy A` on a leaf waiting in `check.review` or `merge`.
4. **Broadcast stranded silently if `B` dies/exits before delivery**:
   - *Removed by*: Keeping `broadcastPending(state) === true` (shown as `broadcast pending` in `status` and `status --json`), surfacing a dead/missing `seat.B` on a `broadcastPending` direct leaf in `leafAttention` (`red: true` in `status --json`) and `status`, and allowing the door or operator to rewrite `state.seat.B` to a live consultant so the next `broadcastPass` delivers it.
5. **Delayed `busy_since` updates when `A` (or an operator-supplied `B`) lacks `akrogon=1` and `listen` does not wake on `status: working`**:
   - *Removed by*: Calling `observeBusy` (via `phaseWake` or the direct creation/phase calls) whenever a direct phase starts or transitions (at creation `A` is already `working`, so `busy_since.A` is recorded immediately); for `B`, if the door transitions to `check.review` and then prompts `B`, either triggering a lightweight wake after sending or observing on `next --wake`/`next --resume` (door-created consultants already carry `akrogon=1`, so `listen` wakes on their `blocked`/`turn`/`finished` events automatically).

Should `status` read the live harness/name or leave `seats` as repo defaults, or record a display label/omit "Seats for the next agent start" for direct leaves?

Should `commandMerged` (for all leaves, or direct leaves) omit `state.broadcast` when `repo.config.broadcast === undefined`?
