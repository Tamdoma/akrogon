# Leaf review C, plan-condition-cases, 2026-10-26

- F1 Traced-reason escape with no home: criterion 1 lets a condition a decision can reachably break get a case "or the traced reason it cannot break", and neither the brief nor the design names where that trace or reason is recorded, or what makes it enough. `## plan.synthesis` maps each criterion to an observation in `plan.md`, but criterion 1 does not put the condition check, the case, or the reason into that mapping, so a planner who misses a write inside a helper on an earlier loop iteration can record nothing and add no case, and `## check.review` has no skipped condition to judge. That is the recorded D2 failure shape. (better-than-training: draft `brief.md` `## Done-criteria` criterion 1, draft `design.md` `## Binding decisions, verbatim` 1a and `## Case`, `skills/plan-issue/SKILL.md` `## plan.synthesis`, 2026-10-26)
- F2 "Same run" does not reach criterion 2: criterion 1 requires the case "in the same run" without saying one product process or invocation in which the decision's state persists. Criterion 2 requires a later call "in the same process" for the lookup case. A planner can satisfy criterion 1's wording with two calls in one test run but separate processes, where a per-process memo resets and the case catches nothing. (better-than-training: draft `brief.md` `## Done-criteria` criteria 1-2, draft `design.md` `## Case` D3, 2026-10-26)
- F3 Criterion 2's walk-through cases do not force the recorded breaks: the lookup case does not say the later call is for the same root or path as the failed lookup, and the recorded plan already had a test calling `commonDirectory` on four distinct paths that caught no memoization. The two-repo case names the arrangement, a write between the shared read and the second use, but no expected result such as a fresh read for the second repo, so a case can contain the write and still not fail when the stale list is used. (better-than-training: draft `brief.md` `## Done-criteria` criterion 2, draft `design.md` `## Case` planned proofs, 2026-10-26)
- F4 Red demonstration has no procedure at planning: criterion 1 and decision 2a require each condition case "shown red by breaking that condition", but `## plan.synthesis` commits the tests before any product code and the violating decision exists only as plan text on the base, where nothing is reused and the case is green. Neither the brief nor the design says what a planner temporarily breaks, that the break is discarded before the test commit, or where that red is recorded apart from the red for the missing new behavior. As written, a planner can drop the base-green case for failing the red-first rule.
