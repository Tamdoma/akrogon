# Leaf review, caller-display, slot B

## D1. The design's consumer list misses the suite's display exposure: `tests/isolation.ts` pins the runtime dir but carries no rule for the other three display names, and nothing else in the leaf does either

Fact: the leaf makes `DISPLAY`, `WAYLAND_DISPLAY` and `XAUTHORITY` propagate through every `constructedEnv` boundary, including into akrogon's own merge verify, where the whole suite runs inside `checkedRun` payloads. Once that happens, the suite process inherits the operator session's display values (the verify service carries them per criterion 3), and `tests/helpers.ts` `cli()` spreads `process.env` unfiltered into every CLI subprocess, so in-process tests that drive run-check or verify now have display values flowing into nested payloads with no pinning and no scrubbing anywhere in the harness. `tests/isolation.ts` (the bun preload) exists exactly for this failure class — it pins `HOME`, `TMPDIR` and `XDG_RUNTIME_DIR` so suite behavior is host-independent — yet the design's consumers section registers the suite only for `XDG_RUNTIME_DIR` ("Because the suite always sets it, a run-check payload inside a test now carries it") and says nothing about the other three names: no owned surface, no `Open for the plan` entry.

Evidence: `better-than-training` — `tests/isolation.ts` setEnv block and `tests/helpers.ts` `cli()` env construction (`...process.env` spread), read 2026-11-25; the propagation path is the leaf's own criterion 3 plus `constructedEnv`'s copy semantics in `src/run-check.ts`, read 2026-11-25.

Consequence: from the first merge after this leaf lands, akrogon's own verify runs its suite with the operator's display session present where the suite previously never had it. Any test that asserts or depends on payload env content then passes or fails depending on who launched the verify (desktop seat vs ssh shell vs listener-started land) — the host-dependent suite behavior the preload exists to prevent, reintroduced through three new names. The repair is one line of design surface and a small preload change (pin or unset the three names beside the `XDG_RUNTIME_DIR` pinning), but the design as written does not own it, so the plan has no license to do it and the leaf would land without it.

Everything else in the draft holds against what I checked: the systemd version arithmetic is correct (probed man pages on this host, systemd 262, 2026-11-25: `--expand-environment` added in 254, `UnsetEnvironment=` in 235, so the host-support inference stands); `--setenv=NAME=` with an empty value assigns empty rather than passing through (probed live 2026-11-25, `DISPLAY=` in the service env while the manager holds `:0`), so the blank rule is implementable as written; the never-both invariant follows from the existing `env[name] !== undefined` filter in `launchPass`; `runUnitArgv`'s blank/missing branches are already covered by the named run-units test; the criteria are observable results, not test-file or count shapes; and the exclusions match the settled binding decisions.
