# Leaf review: caller-display, slot C

## Disagreement 1: `brief.md` Done-criterion 4 makes a false claim about `docs/reference/config.md`'s current `pass_env` row

- **Fact**: `brief.md` Done-criterion 4 states: "`docs/reference/config.md`'s `pass_env` row no longer presents display variables as something a repo must list." Currently `docs/reference/config.md` never mentions display variables at all; its `pass_env` row reads: `| pass_env | Names of environment variables check commands get from your shell, with no .env copy. Default empty. |`.
- **Evidence**: Tier 1 (source read, 2026-11-25): `docs/reference/config.md` (`pass_env` row and surrounding `env`/`pass_env` notes), `issues/chart/run-check-display/slots/leaf-draft/caller-display/brief.md` (§ What item 4, § Done-criteria item 4).
- **Consequence**: That clause is already trivially satisfied on `origin/main` before any edit, so an implementer could leave `docs/reference/config.md` untouched while meeting criterion 4 (contradicting `brief.md` § What item 4 and `design.md` § Leaf architecture owned surfaces). Rewrite the clause positively — e.g., "`docs/reference/config.md`'s `pass_env` row notes that the four display variables are already forwarded by default and remain valid if listed."

## Disagreement 2: `design.md` § Leaf architecture leaves the `-p UnsetEnvironment=` flag form open while `brief.md` and `design.md` § Binding decisions lock one flag per name

- **Fact**: `design.md` (§ Leaf architecture, Consumers) says `Open for the plan: the exact -p spelling, one flag per name or one space-separated value.` Meanwhile, `brief.md` § What item 2 (`-p UnsetEnvironment=NAME for each it lacks`), `brief.md` § Done-criterion 3 (`launched with UnsetEnvironment= for each`), `design.md` § Binding decisions Q2 (`-p UnsetEnvironment=NAME for each it lacks`), and `design.md` § Leaf architecture Owned surfaces (`adds -p UnsetEnvironment=<name> for each of the three non-runtime display names`) all already specify one flag per name.
- **Evidence**: Tier 1 (source read, 2026-11-25): `issues/chart/run-check-display/slots/leaf-draft/caller-display/brief.md` (§ What item 2, § Done-criteria item 3) and `issues/chart/run-check-display/slots/leaf-draft/caller-display/design.md` (§ Binding decisions Q2, § Leaf architecture Owned surfaces and Consumers).
- **Consequence**: If the planner takes the `Open for the plan` invitation and emits a single space-separated `-p UnsetEnvironment=DISPLAY XAUTHORITY WAYLAND_DISPLAY`, it contradicts the binding decision (`-p UnsetEnvironment=NAME` per missing name) and `brief.md` Done-criterion 3 (`UnsetEnvironment= for each`). Remove the `Open for the plan` choice in `design.md` to match the locked per-name flag form (or explicitly allow both forms in `brief.md` and `design.md` § Binding decisions).
