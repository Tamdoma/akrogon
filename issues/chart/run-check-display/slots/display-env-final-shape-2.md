# display-env, final shape after the first check (A's pick, 2026-11-25)

Changes relative to display-env-final-shape.md are marked [K1]..[K4]. Unchanged text is not repeated: Q1 list and rules, [C3], done-criteria 1, 2, 4, 5 and the headed-proof note stand as written there.

[K1] (C problem 1, adopted) Land: `launchLand` emits `--setenv=NAME=<value>` for `DISPLAY`, `XAUTHORITY`, `WAYLAND_DISPLAY` when its caller has the name and nothing otherwise, so a land started by a listener that began before the desktop exported its display inherits the user manager's values, as today. Reason: akrogon-listener.service is `WantedBy=default.target` with no graphical-session ordering (default.target active 13:58:14, graphical-session.target 13:58:17 on 2026-11-24 on this host); unsetting there would strip the display framework's merge verify inherits today (signpost 6a).

[K2] Verify: `launchPass` keeps set-or-unset: `--setenv=NAME=<value>` when its caller has the name, `-p UnsetEnvironment=NAME` when it does not. A verify run by a person or seat sees exactly its caller's display, like run-check. A merge verify inside a land has the land process as caller, so it carries what the land carries.

[K3] (C problem 2, D F1, adopted) Blank rule: a name the caller holds with an empty value counts as held at every door and is passed as that empty value (`--setenv=NAME=`), matching run-check's `constructedEnv` (`!== undefined`). Only an undefined name is absent. "Never --setenv=NAME= with an empty value" is replaced by "never synthesized". The generic `launchPass` loop already emits `--setenv` only for defined names; the unset is emitted only for undefined display names, so one name never gets both, including when a repo lists it in `pass_env`.

[K4] (D F2, adopted) [C1]'s reason is scoped: excluding `XDG_SESSION_TYPE` keeps Chromium's default platform choice on X11; a command that selects Wayland itself still gets the Wayland pair. B's final-check P1 (session type re-injected by the inner run scope) refuted: `env -i PATH=/usr/bin XDG_RUNTIME_DIR=/run/user/1000 DBUS_SESSION_BUS_ADDRESS=... systemd-run --user --scope env` prints only the given names plus INVOCATION_ID, and a run-check payload from a caller holding `XDG_SESSION_TYPE=wayland` printed none (direct/check-probe-a-sessiontype-1795569364709-270540.log), 2026-11-25. A scope runs with the env it is handed; the payload env is constructedEnv's.

Done-criterion 3 now reads: With the caller holding the three non-runtime names (one of them blank), the verify pass unit and the land unit are launched with `--setenv` carrying each caller value, blank included; with the caller lacking them, the verify pass unit is launched with `UnsetEnvironment=` for each and the land unit with neither `--setenv` nor `UnsetEnvironment=` for them; `launchLand` carries one `XDG_RUNTIME_DIR`. Proof: own test reading the launched argv through `FAKE_SYSTEMD_RUN_LOG`.
