# Control rebuttal — Slot B

1. Target: I retain the recommendation for no-argument pause/unpause resolved from the current registered repo. `src/park.ts:47` already uses `requireRepo`, and `src/config.ts:188` resolves subdirectories and worktrees through the shared Git directory. The intake describes changing seats in the repo being worked on, so this meets the request with the existing command convention. A required repo key is a valid operator choice if control from outside the repo matters, but adds a lookup and can target a different repo from the current workspace. Present that tradeoff instead of assuming global targeting is required.

2. Unpause: I retain clear-only. Temporal separates unpause from immediate trigger (https://python.temporal.io/temporalio.client.ScheduleHandle.html, checked 2026-10-08). Boundary Taken says the first pass after unpause performs deferred work, not that unpause must run it. A's scoped startup-style pass is coherent but must expose its dependent cascade: `src/next.ts:1272` selects allocated/merged leaves, while completion calls `dispatchDependents` (`src/next.ts:1151`), which can allocate previously unstarted dependent leaves. Therefore “reject a full repo sweep that starts unstarted leaves” does not mean A's option starts no unstarted leaves. It also needs distinct results for a successful clear followed by a failed dispatch. Clear-only avoids that combined operation, with the explicit cost that absent panes need a manual next pass or later startup/event.
