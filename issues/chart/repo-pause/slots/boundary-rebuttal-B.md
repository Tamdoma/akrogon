1. Cleanup: I still recommend keeping established completed-work maintenance while suppressing automatic starts and prompts. The intake asks to pause dispatch. Freezing owner completion and cleanup extends that boundary and leaves completed resources until a later pass. `src/next.ts:618` handles owner completion, `src/next.ts:678` closes merged tabs under existing batch guards, and `src/next.ts:687` retains worktrees when the owner is still open. I retain the recommendation that explicit manual --resume bypasses pause and plugin startup carries an automatic marker. Always treating --resume as automatic is a narrower interface choice that the operator can select, not an existing caller invariant.

3. Pause acknowledgement: re-reading pause at each launch point is insufficient unless the read and launch serialize with the pause write. `src/next.ts:1332` runs mergePass outside the main next lock, and merge preparation has separate critical sections (`src/next.ts:928`, `src/next.ts:981`). An automatic path can read unpaused, then pause can succeed, then the path can launch. The merged pitfall should require the final check and start/prompt to share the pause command's coordination boundary, or explicitly allow an in-flight launch after acknowledgement. My recommendation remains no new automatic starts/prompts after successful pause acknowledgement.
