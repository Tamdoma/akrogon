# Boundary notes, slot A (written before reading boundary-B)
Q1 pick: a pause skips every automatic pass for the repo, whole: hooked passes (pane/tab events resolve to a leaf owner, src/next.ts:1286,1305), startup `--resume` (next.ts:1270, plugin/herdr-plugin.toml:10), the mergePass after those passes (next.ts:1332), mergeWake from `akrogon phase` (src/akrogon.ts:75), and the dependent dispatch inside them. Merged cleanup and owner completion wait too; the first pass after unpause does them. Explicit operator `next <target>`, bare `next` typed by the operator (no HERDR_PLUGIN_EVENT_JSON) and `--all` run in full, cascades included. Reason: one rule ("automatic = skip"), nothing lost because every skipped action is idempotent and redone by the next pass. Cost: a merged leaf's tab stays open until unpause.
Rejected: events-only (startup resume and phase-driven mergeWake would still launch, the report's goal fails); allowing cleanup while paused (a second rule for little gain, and completeOwner runs broadcast and source close).
Evidence: better-than-training, Kubernetes CronJob `.spec.suspend` (kubernetes.io/docs/concepts/workloads/controllers/cron-jobs, read 2026-10-08): suspend stops new runs, does not affect started Jobs. Argo CD auto-sync docs (argo-cd.readthedocs.io/en/stable/user-guide/auto_sync, read 2026-10-08): manual sync always works with automation off. Both match "automatic stops, manual works, running agents untouched". Practitioner search: no first-hand write-up on pausing a per-project agent dispatcher found.
Pitfalls: check the pause inside the global lock (next.ts:1245) so a queued close event cannot launch after pause; a hooked pass must still exit 0 (no error) when it skips; manual command run inside a herdr pane carries HERDR_PANE_ID but no event JSON, so the gate keys on the event JSON or `--resume`, not the pane id.
