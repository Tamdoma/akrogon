# Rebuttal on budget-shape — Slot C

- **Q2 lock (`withAdmissionLock` is not host-exclusive):** `src/admission.ts` `withAdmissionLock` acquires `globalHome()/admission.lock` in `'shared'` mode and locks only `runs/locks/<slice>` exclusively. Two concurrent leaves in different slices or repos run inside `withAdmissionLock` simultaneously, creating a TOCTOU race on the host daily ceiling. Reservation needs one exclusive host lock (e.g. `globalHome()/budget.lock`), acquired and released before `withAdmission` so it never nests with `admission.lock`.
- **Q2 record (`budget.jsonl` under `globalHome()` over `timings.jsonl`):** Summing `check_start` across `global.repos` breaks on three live facts in `src/timing.ts`: (1) this repo's `issues/timings.jsonl` is already 5.0 MB, and `readTimings` JSON-parses and Zod-validates every line of every repo on each reservation; (2) `readTimings` catches any parse/read error and returns `[]`, silently zeroing a repo's usage instead of failing closed; (3) `appendTiming` swallows write errors, and per-repo timings miss unregistered or `--holder` runs. One small, fail-closed `budget.jsonl` in `globalHome()` (added to `state-home.ts` `copiedEntries`) avoids all three.
- **Q4 grants (pick discriminated/standing schema over A's drop and B's quote-N1):**
  - Against A ("no per-leaf grant"): `skills/implement-issue/SKILL.md` (`## implement`, `## check.fix`), `skills/check-issue/SKILL.md` (`## Shared context`, `## check.review`, `## check.repair`), and `docs/reference/checks.md` read per-leaf `grants[].fixtures[].cleanup` and `absence_check` to clean `$HOME` trust entries, session records, and `hc` state (especially on abandoned captures). Dropping the entry strands fixture cleanup.
  - Against B (keeping `approved` and quoting N1): `INTAKE.md` (`## Agent findings`) item 5 explicitly names harness auto-mode classifiers refusing agent writes of operator approvals not backed by operator words in that session. Having chart door A write `approved: { by: operator, answer: "..." }` per leaf re-triggers that classifier; a standing variant omitting `approved` (e.g. `authority: standing` + fixtures/cleanup/stop_line) keeps cleanup while never forging an `approved` block.
- **Q6 minutes (`AKROGON_SESSION_MINUTES`):** Agree `run-check` must not SIGKILL the run scope (that skips cleanup), but leaving `session_minutes` unexported forces every live test to hardcode `15` or re-parse `~/.akrogon/config.yaml`. Exporting `AKROGON_SESSION_MINUTES` alongside `AKROGON_SESSIONS` in `src/run-check.ts` `constructedEnv` is one line and keeps one source of truth.
- **Q8 home (pick `skills/lifecycle-rules.md` over `standing-design.md`):** `skills/implement-issue/SKILL.md` and `skills/check-issue/SKILL.md` (`## Shared context`) both load `lifecycle-rules.md` directly on every pass, whereas `standing-design.md` is a charting asset only referenced indirectly via `design.md`. Because all four `skills/*/lifecycle-rules.md` are symlinks to `skills/lifecycle-rules.md`, putting S5's floor there gives one canonical file that every lifecycle seat actually reads, with `standing-design.md` pointing to it.
- **Q1 scope ownership:** Putting standing scope only in repo prose (`skills/lifecycle-rules.md`) lets a repo commit widen standing scope without operator edits to `~/.akrogon/config.yaml`. Keeping the operator's verbatim scope text in `config.yaml`'s `approved.answer` (with `harnesses` as the account list) preserves operator ownership without extra config fields.
- **Q7 stop:** Pick `failed` over B's self-clearing wait (avoids new scheduler/wait machinery in `src/next.ts` `dispatchLeaf` and `src/timing.ts` `waitReasonSchema`), with ceiling refusal deduplicating any host ceiling notice per window so concurrent leaves do not flood notices.
- **Q5 concession:** Dropping my per-leaf fallback when the config key is absent; A/B's single-path refusal naming `~/.akrogon/config.yaml` is cleaner under S6 (non-standing external grants keep their own per-leaf path regardless).
