# Final-shape check on budget-shape — Slot C

1. **Item 8 contradicts S5 O1 and its own wording-only clause (De Morgan inversion):** `forks/signposts.md` `## Taken` S5 O1 allows skipping a fresh run when the property was seen green on current model-facing inputs **or** the change cannot reach it. Negating that requires **and**, not **or**: Item 8's *"needed only when no recorded green on the current model-facing inputs covers the property, **or** the seat records why the change can reach it"* triggers a fresh run on every wording-only edit to a model-facing file because the first disjunct is already true, contradicting its own fourth clause. Fix: *"needed only when no recorded green on the current model-facing inputs covers the property **and** the change can reach it (or the seat cannot show why it cannot)"*.
2. **Item 2 & 9 — env spoofing and pre-refusal budget burn (`src/config.ts` `repoSchema`, `src/run-check.ts` `checkedRun`):**
   - `src/config.ts` `repoSchema` `superRefine` keeps a `constructed` set (`AKROGON_BASE`, `AKROGON_RUN`, etc.) that refuses repos declaring constructed vars in `env`/`pass_env`. Without adding `AKROGON_SESSIONS` and `AKROGON_SESSION_MINUTES` to `constructed`, a repo's `pass_env` can inject `AKROGON_SESSIONS` into an unreserved `run-check` and bypass Item 9.
   - In `src/run-check.ts` `checkedRun`, `ownerRefusal` and `failedRefusal` execute before `withAdmission`. If reservation happens before those checks (or before validating `--sessions` as a positive integer), a refused run on a `failed` or `closed` leaf burns `n` sessions without launching anything. State that reservation runs only after `refuse()`, `merge_checks` refusal, `ownerRefusal`, and `failedRefusal` pass.
3. **Item 4 leaves required non-blank `grantSchema` fields unspecified (`src/readiness.ts` `grantSchema`, `tests/chart-shapes.test.ts`):** Keeping `grantSchema` unchanged keeps both `approved.date` and `bounds` as required non-blank `text` (`z.string().trim().min(1)`). Specify what standing grants put in `approved.date` (e.g. `paid_budget.approved.date`) and `bounds` (e.g. non-count operational bounds or `"governed by ~/.akrogon/config.yaml paid_budget"`) so the door and `skills/chart-issues/assets/shapes.md` `### readiness.yaml` do not guess or fail `readinessSchema.parse`.
4. **Item 9 / L2 leaves which `tests/e2e/` entry points require `AKROGON_SESSIONS` unspecified:** Four e2e files launch paid harness sessions (`tests/e2e/kinds.e2e.ts`, `tests/e2e/watch-stop.e2e.ts`, `tests/e2e/watch-consults.e2e.ts`, and `tests/e2e/watch-live.e2e.ts` for `claude|codex|pi|agy`), whereas `watch-live.e2e.ts`'s `AKROGON_E2E_KIND=standin` cell, `window.e2e.ts`, and `notices.e2e.ts` are free. Name those four paid entry points (explicitly excluding `standin`) so L2 does not guess or break free stand-in runs.
