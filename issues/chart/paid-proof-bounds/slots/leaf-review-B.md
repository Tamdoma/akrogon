1. **F1: A fixture change can require a fresh call.** Design architecture 5 says, "A head or fixture change alone reruns consumers against saved output." `fresh-run-need.md` Taken 1a explicitly includes "input data" among model-facing inputs whose change requires a fresh paid call. A fixture can be that input data. Limit this sentence to changes outside the stage's model-facing inputs. The current re-record sentence at `skills/chart-issues/assets/standing-design.md:15` also lacks input data and instructions/templates, so architecture 3's "The re-record triggers ... stay" leaves the Taken input set incomplete. Put the complete input set in the edited rule.

2. **F2: Missing and unknown inputs need the Taken decision path.** Architecture 3 says "a missing recording, reruns consumers against saved output," which cannot run when that output is missing. Taken 1a permits a fresh call for a missing or unreliable recording only when the grant covers it, otherwise the blocker stop. It also says, "An unknown input is investigated, never a silent reuse; then a grant-covered fresh call or the blocker stop." That unknown-input rule is absent from both drafts. State these paths in the published rule rather than requiring unavailable saved output or leaving unknown inputs to the old restart rule.

3. **F3: The slow/live edit leaves the broad full-run requirement intact.** Architecture 4 adds only "under the recorded-output rule above" and the design says surrounding sentences are untouched. `skills/chart-issues/assets/standing-design.md:16` still says "when unsure it restarts from a trustworthy point" and "a clean full run is required only when reuse cannot be shown or fresh start, order or whole-run behavior is under test." Taken 1a explicitly requires narrowing the restart and final-commit clauses for model stages and using "the smallest fresh affected interaction, not automatically a whole run." The unchanged full-run requirement still forces an entire run when a recording cannot be reused, even if only one interaction needs refreshing. Include those clauses in the owned edits and preserve current-head proof through real consumers.

4. **F4: The added condition covers all live proofs instead of model/outside refreshes.** Architecture 6 changes "B runs planned live proofs itself" to require "when the plan's rerun trigger requires a fresh call." The current sentence at `skills/check-issue/SKILL.md:81` covers live proofs generally, including real deterministic consumers. Taken 1a requires deterministic stages, consumers and checks to run real on the current head. Qualify only fresh model/outside calls, while retaining B's responsibility to run the real consumer proof against saved output.

5. **F5: The provider-cap revisit trigger is dropped.** The design reduces limit-mechanism 2a to "no provider-side hard stop now." Its Taken decision also says, "one proven paid launch past a written bound reopens a provider-side cap or a separate capped key, with that launch as evidence." Shrunk 1a explicitly says "2a stands." Carry that trigger as a binding decision without implementing a cap.

6. **F6: Open framework leaves lose their explicit next-launch stop.** The design carries fresh-run-need 2a only as "open framework leaves are not swept, and a locked criterion stands until the operator amends it." Taken 2a also says such a leaf has no covering grant, so "its next paid launch stops as an operator blocker," after which the operator grants runs or amends the criterion. Carry this disposition alongside the exclusion. Preserving a locked full-run criterion alone does not establish authorization for its next paid launch.
