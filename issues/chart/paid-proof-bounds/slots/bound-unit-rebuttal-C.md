# Rebuttal: bound-unit (slot C)

- **O2 is not "the same arithmetic in different words."** Runs × a written fan-out gives the same ceiling only if the fan-out is a hard, still-true maximum and every launch belongs to a named command. A's separate line for other paid launches is a second allowance, and direct probes are exactly how seats added spend outside named proofs on 2026-10-18 (INTAKE Observation: probe sessions and delayed relaunches). Sessions must be the only ledger; runs remain planning labels inside it.
- **One phase owner does not settle parallel spend.** Initial check.review has two blind seats working at once, so "the seat that owns the phase's proof" names two owners unless A's further line — review seats never launch — is also taken. That line deletes the review seats' current authority to rerun a check for missing evidence or a specific concern (check-issue check.review), converting every such case into an extra repair round. Disjoint reserves or zero, set in the plan, bound both seats without removing that authority.
- **B's no-refund rule changes the unit.** Charging the whole envelope forever makes the bound count reserved slots, not paid sessions, so a run stopped after two sessions can exhaust a leaf that never spent the rest. Where the runner's durable record gives an exact launched count (`SessionRecord`s, `sessions: N` in `run-satellite-live-replay.ts`), unlaunched reserve should return; only an unreadable count keeps the full reserve charged. Launched sessions never refund under either reading.
- **Probe-only grant clarification:** merged "Who sets the number" can read as a separate allowance. In my position it is not: sessions spent under a probe-only approval are the starting consumption inside the final leaf grant's lifetime total, shown as charting use at handoff. A second approval sets the total; it never resets the count.
