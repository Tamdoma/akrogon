- F1 Missed copy of the deleted scoping, and the design proof cannot catch it. - F2 Taken fresh-run-need requires the slow/live bullet edit to "narrow the restart and final-commit clauses for model stages". Design point 4 only adds "under the recorded-output rule above" to one sentence. Left standing in standing-design line 16: "when unsure it restarts from a trustworthy point", "the final proof must be valid at the final commit", and "a clean full run is required only when reuse cannot be shown or fresh start, order or whole-run behavior is under test" (live interaction also missing from that property list). Final proof at the final commit still forces a fresh model stage at the last commit after a deterministic fix, which is the behavior this chart exists to stop.

- F3 Design point 3 misstates the missing-recording case: "a change outside the model-facing inputs, or a missing recording, reruns consumers against saved output and never starts a fresh paid call on its own". With no recording there is no saved output to rerun consumers against. Taken has two separate rules: a fresh call is allowed when "the recording is missing or unreliable", and "a missing recording never falls back to a paid call on its own" (so it needs a grant or the blocker stop). Brief criterion 3 also lists a missing recording as a fresh-call case. As written, point 3 cannot be implemented without guessing which half applies.

- F4 The unknown-input rule is dropped. Taken: "An unknown input is investigated, never a silent reuse; then a grant-covered fresh call or the blocker stop." The design's binding summary omits it and no edit point writes it. The current rerun sentences the design edits around say "counting an unknown dependency as changed" (implement-issue line 67, check-issue line 93), and design point 6 adds only "replays its saved output unless the plan's rerun trigger for that stage fired". An input whose status is unknown is left between silent reuse (trigger not known to have fired) and a fresh rerun (unknown counts as changed), with no investigate-or-block step.

- F5 The smallest-interaction limit is dropped. Taken: when the named property needs a fresh run, "it is the smallest fresh affected interaction, not automatically a whole run". The design binding summary repeats it, but no edit in points 3 to 7 writes it into any skill, and no brief criterion checks it. Point 7's shapes refusal only rejects a criterion that does not name its property; a criterion that names one can still demand a whole fresh run.

- F6 The model-facing input set is never written, and one design sentence contradicts it. Taken defines the set: "prompt, instructions or templates, model pin, settings, input data, tool or provider contract, output contract". Design point 3 says standing-design's re-record triggers stay; line 15 lists only "a prompt, model, settings, output shape or outside call", with no input data. Design point 5 then says "A head or fixture change alone reruns consumers against saved output", but a fixture can be the model stage's input data, which under Taken requires a fresh call. Taken also requires the plan trigger to name "the model-facing input set, the recording and the real consumers"; design point 5 and brief criterion 4 keep only the inputs and drop the recording and the real consumers.
