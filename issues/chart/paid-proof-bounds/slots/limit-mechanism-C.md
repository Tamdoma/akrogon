# Blind notes: limit-mechanism (slot C)

## 1. Pick, reason, cost

**Pick: the limit is a written grant rule. Akrogon builds no counter.**

The mechanism already exists end to end and only its wording has a hole. `grants` already records approval, operations, billing effects, and "repeat and recovery bounds" (chart-issues, `## Take`, the `Each leaf's grants…` paragraph). `src/readiness.ts` `grantSchema` already carries `bounds` as text (line 46), and both seat skills already have a stop path for anything outside a grant. What failed on 2026-10-18 was classification and reuse wording, not missing machinery: paid read-only sessions fell through "live-change" / "before mutating" into `proofs[]` with `grants: []`, and the reuse sentence authorized "reruns … without asking again" with no instruction to count against `bounds`. Where a written bound did exist (media-range-live's Cloudflare grant), the seat stopped correctly (INTAKE.md, Suspected cause). Seats follow written bounds; unbounded leaves were the ones with no grant at all.

The pick in one contract sentence: **any provider-metered operation (billing or quota effect, read-only included, launched directly or transitively through a runner) needs an operator-approved grant before its first call, and a grant is reusable only while operation, target, identity, effects, and the remaining repeat bound all match; exhaustion is an operator blocker, and probes or delayed relaunches to a reset draw on the same bound.**

One allowed companion, not a second mechanism: where the launched tool itself offers a native per-session cap (today only Claude Code: `--max-budget-usd`, `--max-turns`), the grant may name that flag in `operations` as a per-launch guard. The grant stays the leaf-total authority; akrogon gains no accounting code.

Concrete sentence changes under this pick:

- chart-issues `## Take`, grant paragraph: "one scoped live-change grant" → a scoped grant for every outside effect, provider-metered operations included, read-only included. "before the first mutating proof" → before the first covered call, which includes the door's own metered operation-proof under the preceding paragraph. Final sentence: "a new or different mutation" → a new or different covered operation, or any launch past the repeat bound, needs new approval.
- chart-issues `## Take`, operation-proof paragraph: add that `proofs[].limits` states what a probe does not prove and never authorizes spend; a metered operation needs a covering grant.
- chart-issues `## Handoff`: "each leaf's recorded live-change grant confirmed" → each grant, billing included, confirmed. In the live-run review line, add the authorized total across the bound (per-attempt sessions × permitted attempts) next to the existing per-run estimate, and split the existing disclaimer: the *estimate* stays information-only (proof-cost lock), the *grant bound* in readiness is binding.
- implement-issue `## Shared context`, grant reuse sentence: delete the blanket "without asking again"; "before mutating" → before a covered call, compare operation, target, identity **and remaining bound**; record attempts consumed in the pass artifact; anything past the bound, probes included, is outside the grant and takes the existing stop.
- check-issue `## Shared context`: same reuse sentence, same change. Its operator-only definition ("a live-mutation authorization") → a grant authorization or bound increase. `## check.repair`: B runs planned live proofs "under the grant reuse rule" → only while bound remains; an exhausted planned proof is an operator-only item, never `Handed to A`, because A holds no larger bound.
- The identical reuse sentence also lives in plan-issue and merge-issue (found by the opening map's search). All copies change together or the rule leaks through planning and merge seats.

Deleted: the words "live-change" as the grant gate (2 places), "before mutating" / "before the first mutating proof" (all copies), and unbounded "without asking again" (all copies). Deleted code: none, because none is added — no schema change, no state field, no counter, `bounds` stays operator-written text. The proof-cost foreclosure of "any enforced budget, timer or numeric gate" is not reopened: nothing numeric is enforced by the command; the number lives in an operator-approved grant the seats already must obey.

Cost of the pick: enforcement is seat-followed, not mechanical. A disobedient or miscounting seat can still overspend once. I accept that, with an explicit revisit trigger in §4, because every mechanical variant either cannot see the spend or costs more machinery than the defect (see §2).

## 2. Rejected options, each with reason

- **Akrogon attempt ledger in `run-check`.** Gives false assurance. The expensive launches are nested: framework scripts spawn `claude -p` inside `launchSkillSessionAsync` (framework `.claude/workflow/scripts/lib/session-trace.ts`, spawn at line 163), one top-level command hides hundreds of sessions, printed `checks`/`verify` runs are exempt from `run-check`, and the 2026-10-18 seats also used direct shell calls and `sleep`-relaunches outside it (INTAKE.md, Observation). A counter would need a grant ID linking `proofs[]` (today none), atomic consumption across parallel A/B/worker/merge seats, and crash semantics for "billed but killed before decrement" — new lifecycle state to guard a hole that is three sentences wide. It also reopens the proof-cost lock head-on.
- **Akrogon token/USD counter from provider logs** (e.g. aggregating `~/.claude/projects` JSONL, as the opening map recount did). That is after-the-fact measurement, not prevention; attribution by `cwd` is fragile; subscription usage is quota/credits, not the USD estimate; and codex and pi seats produce different logs again. Useful as an audit if prose ever fails, wrong as the mechanism.
- **Provider-native cap as the sole mechanism** (`claude --max-budget-usd` on every launch). It caps one invocation, not a leaf: each rerun gets a fresh cap, resumed-conversation totals do not count, spend can pass the cap, and it is a client-side estimate that can differ from the bill (Anthropic CLI reference, §3). Codex (`codex-cli 0.163.0 --help`) and pi (`pi --help`) expose no budget flag at all (checked locally 2026-10-19), so it cannot cover the other harnesses' seats. The framework launch site is also outside this chart's repo. Kept only as an optional grant-named guard.
- **Keep proof-cost status quo (visibility only).** Disproved by the intake: the handoff line existed and 82% of a day's 1.33B input tokens still came from proof/replay reruns until the account limit stopped four leaves (INTAKE.md, Observation/Urgency).

## 4. Pitfalls, with what removes each

- **P1. Prose miscounts across passes and parallel seats.** A and B, workers, `check.repair`, and merge all draw on one leaf bound; a fresh pass after compaction may not know what was spent. Removed by: every pass artifact records the grant and attempts consumed so far (already required in my §1 sentence change: "records the grant reference, results" gains the running count), and check seats treat a proof run past the bound as a defect against the grant, not a Nit. Residual risk is real but bounded; revisit trigger: one *proven* launch past a written bound reopens the counter option with evidence, instead of building it preemptively.
- **P2. The chart door spends before any grant exists.** `## Take` mandates one real call per named external operation before handoff — for a `claude -p` operation that probe is itself paid, and under autopilot the door answers its own review while grant approval stays operator-only. Removed by: my Take change moves grant approval before the first covered call, and the door's probe counts as the first attempt against the bound.
- **P3. Exhaustion becomes a quiet waiver.** A seat out of bound could hand a red criterion onward as accepted, or split one proof into many small sessions to fit under an attempt count. Removed by: exhaustion takes the existing operator-blocker stop with the criterion still red (the Handoff line's "never waives a criterion" already says this and stays), and transitive launches count toward the bound — the unit itself is the sibling `bound-unit` fork, which must not define "attempt" so loosely that splitting wins.
- **P4. Native cap overshoot on a subscription identity.** Framework proofs run on the operator's Claude login, where the binding ceiling was a monthly spend limit in credits, while `--max-budget-usd` is an API-dollar estimate that can pass the cap. Removed by: never let the native flag *be* the bound; the grant counts attempts/sessions (unit per sibling fork), the flag is an optional per-launch guard with headroom per Anthropic's own warning.
- **P5. Already-open framework leaves with `grants: []`** (CHART.md Fog). Retro-editing their readiness files is new paperwork per leaf. Removed by: the rule bites at next launch — a seat on such a leaf finds no covering grant and stops as an operator blocker, one leaf at a time, only if it actually launches a paid proof. No sweep.

## 5. Questions this fork does not ask

- Q-C1. Does the operator want the only true hard backstop, which sits outside akrogon entirely: a provider-side spend limit (Anthropic workspace Spend Limits) or a separate API key/quota for proof sessions, so even a runaway seat cannot consume the main account's monthly limit? No akrogon text or code can substitute for it; it is an operator account action the chart should name or explicitly decline.
- Q-C2. When a bound is exhausted mid-leaf, who raises it and who edits `readiness.yaml` — operator edits the grant bounds text directly, or the door re-approves a widened grant? The unblock path should be one named action, or every exhausted leaf invents its own.
