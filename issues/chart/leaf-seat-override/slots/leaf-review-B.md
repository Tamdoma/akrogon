## index-seats

- **R5. Criterion 2 asks for a seat where none exists.** Malformed YAML or an unknown top-level front-matter key can fail before any `a`/`b` seat is identifiable. Require the file path and parse/schema reason for those failures, and the seat when a failure belongs to one. Also replace “a quoted value” with “a decoded value containing a quote character.” YAML `model: 'opus'` parses to `opus` and passes the prescribed schema. Evidence: draft `index-seats/brief.md:14`, `index-seats/design.md:41-42`. The lock requires no quote characters in values, not a ban on YAML string delimiters (`issues/chart/leaf-seat-override/forks/visibility.md:29`).

## subagent-seat-model

- **R6. The real-run criterion can pass without a subagent.** “Every assistant row with parent_tool_use_id” is satisfied by an empty set. Require at least one assistant row belonging to the requested general-purpose subagent, then check every relevant row's model. Otherwise a successful parent-only answer can count as routing proof. Evidence: draft `subagent-seat-model/brief.md:14`, `subagent-seat-model/design.md:11-13`. The recorded proof establishes an actual subagent, and standing design requires a real invocation proving the named property (`skills/chart-issues/assets/standing-design.md:9-10,14`).

- **R7. Criterion 1 mixes the outcome with a required test implementation.** “A test in the blocking checks builds the argv…” is expressly excluded from done-criteria by `skills/chart-issues/assets/shapes.md:151` (“never a test file, assertion or test count”). State the observable result instead: substituting the chosen model in the tracked Claude template produces valid settings JSON selecting that model with FORCE enabled. Keep the proposed offline argv test in the design as its proof. Evidence: draft `subagent-seat-model/brief.md:13`, `subagent-seat-model/design.md:21,27`. This preserves the selected proof boundary without turning the test itself into the acceptance outcome.

## door-seat-capture

- **R8. The door contract omits restrictions its writer must follow.** The design copies the whole-seat decision but excludes strictness and gives only a valid example. A door agent implementing this leaf alone is not told to document nonblank-after-trim values, the ban on quote characters in decoded values, or rejection of extra fields. Command enforcement after handoff does not teach the door to emit valid inputs before state becomes dispatchable. Carry visibility Q3 into this design and require shapes to state the complete accepted shape. Evidence: draft `door-seat-capture/design.md:11,19,29-37`, `door-seat-capture/brief.md:13`; binding strictness is in `issues/chart/leaf-seat-override/forks/visibility.md:29`. `skills/chart-issues/assets/shapes.md:167` requires self-contained designs, and `skills/chart-issues/assets/standing-design.md:16` requires the writer to know the checker's rule.

- **R9. Publishing the door before its consumer is ready is not safe.** The design calls ignored settings acceptable, but an explicit operator choice would then be written and silently ignored by the current resolver. These changes have disjoint code surfaces and can be developed in parallel, but the new door behavior must not become active before `index-seats`. Record and enforce that delivery order, or make the dependency explicit if the lifecycle has no narrower merge-order mechanism. Evidence: draft `door-seat-capture/design.md:41`, `door-seat-capture/state.yaml:6`; current `src/config.ts:60-64` resolves only repo/machine seats and `src/next.ts:253` consumes those seats. An explicit answer does not make an unsupported configuration take effect.
