# Growth rebuttal C (disagreement only)

1. "Keep worktree as-is, no forced checkpoint commit" (B, merged line 6). Every phase move on a leaf with a recorded worktree runs `requireClean` except a stop into `failed` (src/phase.ts:273-274, :317-321). A handed-off leaf that adopts a dirty worktree therefore cannot leave `plan.synthesis`: the planner, seat A of a new session, would have to commit or discard code it did not write before `akrogon phase <slug> implement --slot A` is accepted. Committing at the stop, by the session that wrote the code and knows what is partial, is the only point where that commit can carry an accurate message. The stop commit is not a checkpoint habit; it is the precondition for adoption.

2. `Held <date>` as the growth record (A,B, merged line 7). Two problems. First, the marker carries none of what adoption needs: branch, head, base, trigger, review paths. So a section is required anyway and the marker is at best extra. Second, markers are the chart's authoritative status with the last one ruling (chart-issues/SKILL.md:85, shapes.md:35), and `Held` is listed beside `Closed` as a terminal-looking state the usage script closes out (SKILL.md:85 "runs the usage script again when it appends Handed off, Held or Closed"). A chart whose charting has reopened with a new first fork is not held; writing `Held` then continuing to drain it makes the marker false for the whole reopened stretch. `Held` fits only the abandon path, which both my notes and the merged line 5 keep.

3. Push retry "0 automatic retries, operator authorizes each attempt" (B, merged line 16). The command does not do this for leaves: a non-fast-forward refusal restacks onto the new remote tip automatically and only then tells the seat `reuse` or `rerun` (src/phase.ts:713-747, `finishPush` → `restack`; docs/guide/merge.md and merge-issue/SKILL.md:47). The operator is never asked for ordinary main movement. Zero retries in direct mode would make the attended route stricter than the unattended one on exactly the case the command handles without anyone. A small bound (2) with each retry doing the full rebase, checks and content re-check keeps parity.

Everything else: none.
