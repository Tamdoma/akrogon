# Slot B growth rebuttal

F1. I reject automatic lifecycle adoption justified by slug matching and ensureWorktree reuse. That function supplies Git allocation behavior, not a judgment that existing code satisfies a new plan. Slug uniqueness protects names, not execution ownership. Automatic reuse can expose partially implemented direct changes to a normal leaf before the chosen plan says what to retain. Keep the lifecycle transition attended, identify the sole successor, and explicitly decide which commits become candidate implementation. Normal initial planning must still run, with debate selecting plan.positions rather than always plan.synthesis. Evidence: src/next.ts:263-292 checks/reuses Git worktrees; skills/chart-issues/assets/shapes.md:251,259 defines initial phases and command-owned progress; skills/check-issue/SKILL.md:39 reviews against the plan and contract. Whole-diff review later does not authorize bypassing that contract earlier.

F2. I reject deleting the direct branch as the default escalation step, and I reject a mandatory WIP commit as the stop condition. Preserve actual committed and uncommitted work first. An interruption may leave failing experiments or an incomplete operation, and a checkpoint commit does not establish readiness. Deletion or selective adoption needs a concrete operator-approved continuation/disposal decision after inspecting the evidence. The taken cleanup-before-Closed rule concerns completed delivery, not erasing unfinished held work. Evidence: issues/chart/direct-mode/forks/container.md:19-23; src/phase.ts:256-271 permits recording a failure before clean-worktree guards at :273-277. A scoped optional checkpoint is possible, but it must not block the stop or destroy the original working state.

F3. Held and a Direct attempt section are complementary, not mutually exclusive choices. Use Held as the existing authoritative unfinished marker and record branch, head, dirty state, review and successor pointers alongside it. Reopening a fork must not accidentally make the retained direct attempt executable again. Define “no new direct attempt while a live branch is owned” separately from resuming the same explicitly authorized attempt. Evidence: skills/chart-issues/assets/shapes.md:35 makes the last marker authoritative; :75 requires newly open questions to remain open. A section alone does not currently change the status marker parsed by src/status.ts:305-309.

F4. The merged repair definition omits blocking landing-check failures. Those may require an A repair even after B initially returned ready/nits. Count that repair pass under the same allowance, with B reviewing the repaired result, rather than giving it unlimited free iterations because no preceding B fix existed. Recording the first fix reserves the next round, while an interrupted pass resumes that same numbered round. A new B fix after its completed re-check opens another round. Evidence: issues/chart/direct-mode/forks/landing.md, Taken Q1 requires checks and merge_checks before push; skills/merge-issue/SKILL.md:63 routes red merge checks to repair. Lifecycle's counter increments at a particular handoff (src/phase.ts:151,301), so the direct definition must explicitly cover its different control flow.

F5. I retain zero automatic push retries. Two refusals is a valid alternative operator choice, but the contract must state that this means the initial push plus one reintegration attempt, with fresh checks and conflict review as required by the taken landing rule. It must not mean two free repairs or repeated pushes of an unchanged stale candidate. Remote contention is independent of defect repair. Evidence: issues/chart/direct-mode/forks/landing.md, Taken Q1; skills/merge-issue/SKILL.md:47,65. On either chosen bound, preserve the branch after exhaustion and let the operator authorize recovery.
