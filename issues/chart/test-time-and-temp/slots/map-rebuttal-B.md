Keep the existing stop for an unfulfillable criterion (`skills/implement-issue/SKILL.md:34`), record the actual blocker, and make a base probe conditional on what it can establish. C's failure-name subtraction cannot waive a red required check under the current lock. Remove `(A,B)` from the unconditional base-run/main-attribution proposal.

2. **R2: “delete only where the worktree is removed” does not have my agreement.** `src/next.ts:559-565` returns before removing a worktree while its leaf remains under `issues/open`. `src/phase.ts:141-146,169-172` keeps the completion owner open until its siblings merge. A completed leaf can therefore retain large scratch copies while unrelated sibling work stalls indefinitely. My recommendation was cleanup after each merged leaf's seats and descendants stop, even when its worktree remains for the owner. Put temp deletion after confirmed process shutdown and before the open-folder early return, with required evidence already saved. Preserve failed-leaf scratch for recovery. Remove `(A,B,C)` from the worktree-removal-only lifetime claim.

3. **R3: F8 establishes that one worktree-side path is too long, not that `/var/tmp/akrogon/<repo>/<slug>` is always short enough.** `src/state.ts:37,40` and `src/config.ts:8,18` impose no maximum length on slug or repository identity. The measured 93-byte socket path has limited spare capacity. I accept a shorter disk-backed root, but the contract still needs bounded directory naming, for example a fixed-length digest of repository identity and slug, and proof using the actual Chromium socket suffix. Otherwise the proposed location preserves the socket-length failure for longer valid names. This is necessary path design, not a new operator setting.

4. **R4: OS aging is not an orphan detector.** The proposed 30-day sweep can age files belonging to a retained failed leaf or a long-lived active leaf. The cited [systemd temp guidance](https://systemd.io/TEMPORARY_DIRECTORIES/), read 2026-10-01, explicitly distinguishes age-based deletion from process lifetime and recommends locks to protect live directory trees. Choose the retention contract explicitly: either protect active/retained scratch from aging, or state that diagnosis expires and require evidence to be saved before expiration. Do not promise both indefinite failed-leaf retention and unqualified OS aging. Disk placement and automatic managed-leaf teardown remain supported.
