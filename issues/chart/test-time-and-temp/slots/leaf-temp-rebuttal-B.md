# B disagreement-only rebuttal

1. **R1: Keep the bounded derived path, but change its ownership and identity scheme.** A single 0700 `/var/tmp/akrogon` parent belongs to whichever user creates it first. Ownership checks then prevent every other user from using it. Also, eight hex digest characters give only 32 bits of leaf identity when readable prefixes coincide. The cited `src/next.ts:428` uses 24 hex characters, not eight, and names an agent rather than storage subject to recursive deletion. Use `/var/tmp/akrogon-<uid>/<32hex>` instead. Even a ten-digit UID keeps TMPDIR at 60 bytes, inside the measured 62-byte limit. This removes the shared-user parent problem and makes the full directory name the stronger identifier without another field or knob. Encode the hashed components unambiguously.

2. **R2: Immediate deletion after `closeMergedTab` does not establish safe shutdown, so the stated `(A,B,C)` agreement is too broad.** `src/next.ts:552-556` establishes only that the tab-close command returned. `src/next.ts:744-753` accepts a merged B event without requiring idle/done, and `cleanupRepos` at `642-646` visits every merged leaf without checking seat activity. Adding recursive scratch deletion there can destroy files still used by B's report/broadcast or surviving workers. The merged map acknowledges the race but leaves it in the recommended contract. Keep cleanup before the open-owner early return, but first prove the actual shutdown boundary and prevent an active merged seat from being swept. An existing race is not authorization to add destructive deletion behind it.

3. **R3: “Files in use stay” is not established by age timestamps, and I did not concede that protection requires a new daemon.** A process can still need a named file it has not recently touched. The cited [systemd guidance](https://systemd.io/TEMPORARY_DIRECTORIES/), re-read 2026-10-01, explicitly warns about long-running software and recommends directory locks to protect entire live trees. Creating the top-level directory on dispatch does not refresh every descendant. I accept that stopped failed scratch may expire and durable evidence must live elsewhere. Active protection remains unresolved. My round required a probe of an existing lifetime owner and rejected inventing a guardian daemon. Replace the claimed concession with that unresolved probe, and do not promise safety from timestamp aging alone.

4. **R4: Tests should not allocate in the production scratch root.** `tests/helpers.ts:12,33,44` provides an isolated fixture root and AKROGON_HOME, with cleanup of the fixture tree. The proposed fixed `/var/tmp/akrogon` escapes that isolation. Hashing the fixture root reduces name collisions but does not contain effects or guarantee cleanup after interruption, precisely the residue problem under discussion. Inject the temp root internally for tests, with no public setting. Keep one controlled real-root launch/socket probe as integration evidence rather than making ordinary command tests write to production storage.
