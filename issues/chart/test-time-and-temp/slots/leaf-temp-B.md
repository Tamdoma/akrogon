### 1 · Where should the leaf temp folder live without breaking Chromium socket paths?

Linux pathname sockets have a 108-byte address field, including room for the terminating null. A short root alone does not solve unlimited repo/slug length (`src/state.ts:37,40`). The carried map measured an actual Chromium socket at 93 bytes for one `/var/tmp/akrogon/<repo>/<slug>` example.

Research: operator · `INTAKE.md` #49 and `slots/map-merged.md` F8, read 2026-10-01 · large dependency copies exhaust tmpfs inodes, and the worktree-side candidate exceeds the measured socket limit · changes my earlier location recommendation to a short disk root with bounded names. Better-than-training · [unix(7)](https://man7.org/linux/man-pages/man7/unix.7.html), read 2026-10-01 · `sun_path` is 108 bytes on Linux · require the complete socket pathname, not merely TMPDIR, to fit. [systemd maintainers' temp guidance](https://systemd.io/TEMPORARY_DIRECTORIES/), read 2026-10-01 · persistent storage suits large scratch, and shared world-writable namespaces need safe creation · require a private user-owned parent.

- **1a (recommended):** Use `/var/tmp/ak-<uid>/<32-hex-id>`. Derive the fixed-length ID from an unambiguous encoding of canonical Git common-directory identity and leaf slug. Create the user parent privately, verify ownership and reject an unsafe existing parent. Derive the same path on resume and cleanup without another state field or operator setting. This bounds names while keeping storage outside tmpfs and the Git worktree.
- **1b:** Use a random short directory under `/var/tmp` and record its path in command-owned state. Safe short creation is straightforward, but allocation, saved-state consistency, recovery and deletion now depend on another state field.
- **1c:** Keep readable `<repo>/<slug>` directory names under `/var/tmp` or the worktree. Reject: valid identities still exceed the socket budget. Adding slug limits would change an unrelated public contract.

Pitfalls: the chosen prefix plus maximum UID spelling plus ID plus Chromium's actual generated suffix must fit within 107 pathname bytes. Verify against the installed Chromium before handoff. A digest is a directory identifier, not security protection. World-writable parent preoccupation and symlinks must not cause reuse or deletion of another user's path. Tests need an internal injected root so they never touch production scratch, not another public config key. Consumers that hardcode `/tmp` remain framework-owned.

### 2 · When should scratch be deleted, and how long should failed scratch survive OS aging?

Remove a merged leaf's scratch after its seats and descendants stop, even if siblings keep its worktree. `cleanupMerged` currently returns early for leaves still under `issues/open` (`src/next.ts:559-565`), while owner closure waits for siblings (`src/phase.ts:141-146,169-172`). Neither a phase transition nor an idle label proves all processes stopped.

Research: operator · `INTAKE.md` #49 and `slots/map-rebuttal-B.md` R2/R4, read 2026-10-01 · residue survives completion, but phase clearing threatens continuing sessions · cleanup belongs to stopped merged-leaf teardown. Better-than-training · `src/next.ts:642-651,744-753` and `src/phase.ts:114-126`, read 2026-10-01 · existing sweeps retry cleanup and merged-idle hooks close the tab after phase recording · extend both completion paths without waiting for owner closure. [systemd maintainers' temp guidance](https://systemd.io/TEMPORARY_DIRECTORIES/), read 2026-10-01 · aging can delete live trees, while BSD directory locks protect a subtree until their owning process exits · separate active protection from failed diagnostic retention.

- **2a (recommended):** Prompt merged-leaf cleanup, no phase wipe. Protect scratch while processes actually use it with a directory lock held by their existing lifetime owner, then let ordinary OS aging reclaim abandoned or stopped failed scratch. Failed scratch is best-effort diagnostic material, not indefinitely retained evidence. Persist the failure logs and required artifacts in the leaf first. This removes normal residue and leaves crash cleanup to the existing OS mechanism without another timer.
- **2b:** Prompt merged-leaf cleanup and indefinite retention for failed scratch. Exclude the managed subtree from OS aging with a confirmed system tmpfiles rule. This preserves failed scratch without a persistent lock holder, but requires system setup and an explicit disposal owner for abandoned failed/orphan folders. It cannot promise automatic orphan reclamation.
- **2c:** Clear only when the worktree is removed, or after every phase. Reject: the first retains completed scratch behind stalled siblings, and the second can delete live harness files.

Pitfalls: 2a needs a real launch-boundary proof that the directory lock survives across seat/worker lifetimes and releases on termination. A lock held only by the short-lived `akrogon next` invocation is insufficient. Do not invent a guardian daemon to make the option work. If the existing lifetime owner cannot hold it, 2a is not ready for handoff and 2b remains an explicit operator choice. A failed leaf with still-running diagnostic processes remains protected until those processes stop. OS aging is timestamp-based, not a guaranteed 30 days after failure, and extracted files can carry old timestamps. Cleanup must occur only after shutdown is confirmed, before the open-owner early return, and retry visibly through the existing sweep on failure. A base-copy worktree must be removed with Git before deleting its containing scratch, so common-directory worktree metadata does not outlive the files. Never delete scratch inside `phase ... merged` while B is still using it for its report or broadcast.
