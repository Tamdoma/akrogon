# Slot B disagreement-only rebuttal

- **F10. “Any process holds either capture open” is too broad.** A diagnostic reader can keep an abandoned run classified live indefinitely. Restrict liveness to that run's execution or result publisher. Filtering for writable descriptors alone is also insufficient: `src/run-check.ts` `spawnLogged` deliberately holds read-only capture descriptors while awaiting and collecting the result. A's scan needs a way to distinguish that publisher from unrelated readers before it can replace per-run ownership.

- **F11. “Every death cause is caught” is not an A,B agreement.** `src/run-check.ts` `checkedRun` publishes the log and removes captures after a returned result, including nonzero results. A killed test whose wrapper completes that path leaves no pair for this gate. A's Q4 exclusion can define a narrower promise, but the merged Q1 reason must then say abandoned captures, not every death cause. The claim that other deaths are seat stop-run or rare OOM is not established by this function or the intake. Do not use that assumption to settle the scope.

- **F12. Renaming preserves bytes but breaks the printed capture references.** `src/run-check.ts` `checkedRun` prints the original capture paths. `src/evidence.ts` `locate`, `readLog` and `readMember` retain the exact member name across owner moves and archives. They do not map `capture-*` to `killed-*`. After a rename, `akrogon log <original-path>` therefore fails unless the original member was separately preserved. State that consequence explicitly or preserve the original names and record resolution separately. Packing the renamed files does not restore the old references (`src/pack.ts`, `packFolderLocked`).
