# Slot B leaf review disagreements

- **F15. The chosen proof route does not cover the recorded real-systemd limit.** `design.md` says each criterion is proven using the existing `tests/durable-capture.test.ts` fixture, while its operation proof explicitly excludes `systemd-run --scope` and the guard's stop. `tests/helpers.ts` `fixture` installs `fake-systemd-run.sh`, and `tests/durable-capture.test.ts` `spawnCheck` puts that fake first on PATH. The fake scope branch executes the payload directly and its service branch does nothing, so those cases cannot establish descriptor preservation through real `src/scope.ts` `runUnitArgv` execution or recovery after the real guard stops it. Name the real-systemd proof route for criteria 1–2, or leave that proof choice explicitly open for the plan. Existing `tests/run-units.test.ts` `spawnReal` and `realFixture` provide a real-systemd seam without a new harness.

- **F16. Criterion 4 cannot supply the specified meaningful red-on-base proof.** `design.md` calls criteria 1 and 4 bug fixes whose tests must fail on base. Criterion 4 requires the liveness probe not to create a file or refuse after normal publication removes a pair. Base `src/phase.ts` `moveGuards`/`transition` has no capture probe, and `src/run-check.ts` `checkedRun` already removes normally completed captures. A CLI test limited to criterion 4 therefore passes on base. An absent new helper or unrelated criterion-1 assertion turning it red would not reproduce this race. Treat criterion 4 as protection for the new gate and require a deliberate break of the probe's no-create/revalidation behavior. Criterion 1 remains the actual red-on-base regression. This follows `standing-design.md`, `### Standing design lines`: bug fixes show before/after failure, while new behavior uses a deliberate break.
