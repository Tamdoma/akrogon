# Final-shape check (slot C): run-scratch

## P-a to P-d (code & live facts)

- **P-a (second `run_root` vs single `leafTempRoot`):** Switching `leafTempRoot()` (`src/config.ts:375`) as one root would move **seat `TMPDIR`** (`src/seat.ts:298`, kept for the leaf's whole open lifetime by `src/reconcile.ts:1202`) and **`self-update` rebase worktrees** (`src/self-update.ts:75`) into RAM. Keeping `run_root` separate is right — **but do not mirror `<repo hash>/<leaf hash>/run-*` under `run_root`**. Run roots are no longer tied to leaf tabs; a flat `<run_root>/run-<uuid>` layout saves 14 bytes on Chrome's 107-byte socket limit (`src/config.ts:372`) and avoids duplicating the ~100-line per-repo leaf-temp tree walk in `src/reconcile.ts:1140-1238` (an orphan backstop becomes a 10-line flat `.owner` scan).
- **P-b (`rm -rf` in `startRunGuard`, `src/scope.ts:70`):** Safe *only* with the right command order. Today line 70 ends with `exec systemctl --user stop ${base}.scope`:
  1. `rm -rf` **before** `stop` races live child processes still writing into `runRoot` (leaving files or `ENOTEMPTY`).
  2. `rm -rf` **after `exec`** never runs. Drop `exec`: run `systemctl --user stop ${base}.scope; rm -rf -- ${quote(runRoot)}; rm -f ${quote(recordPath)}`.
  3. On normal exit, `run-check.ts:423` stops the guard before `wpid` dies, and `rm -rf` on an already-deleted unique `mkdtempSync` dir is a harmless no-op. One catch: if `refusal.json` lives inside `runRoot`, a guard surviving a failed `stopRunUnits` would delete the refused root (see D1/D3 below). Also, if `stopSlice` kills the leaf slice while the guard is mid-`rm -rf` on slow disk, cleanup truncates — putting the guard in `akrogon.slice` avoids that.
- **P-c (`memory.peak` in D4):** **Proven live race.** On this host, a scope under `akrogon-l<hash>.slice` sits at `<cgroupRoot>/user.slice/user-<uid>.slice/user@<uid>.service/akrogon.slice/<slice>/akrogon-run-<id>.scope/memory.peak`. Because `runUnitArgv` sets `CollectMode=inactive-or-failed` (`src/scope.ts:45`), systemd destroys the cgroup directory and unloads the unit asynchronously as soon as the command exits — live probe showed both `memory.peak` and `systemctl --user show <unit> -p MemoryPeak` return `GONE` / `[not set]` within 100 ms of exit. Reading it in `run-check.ts` after `await spawnLogged(...)` (`:415-424`) will silently miss under load; nested runs (`:406-411`) have no scope at all. Reading it race-free requires reading `/sys/fs/cgroup$(...)/memory.peak` *inside* the scope before its last process exits.
- **P-d (rollback safety):** Both `globalSchema` (`src/config.ts:23`) and `verifyRunSchema` (`src/verify.ts:53,69`) are `z.strictObject`, and `deployStage` deploys only `origin/main` tip (`src/self-update.ts:241-243`).
  - **Config trap:** If the operator adds `run_root:` to `~/.akrogon/config.yaml` while `deploy.yaml`'s `previous` is still the pre-chart release, `akrogon rollback` (`src/rollback.ts:22-38`) succeeds on the new release and then **every subsequent command on `previous` crashes in `readGlobal()`** (`Unrecognized key: "run_root"`). Either ship a schema-accept release first (before setting `run_root:` or writing `memory.peak`), or wait until a later release advances `previous` past the schema commit before setting `run_root:`.

## Concrete break / evidence-loss / residue scenarios in D1–D4

1. **D1 + D3: publish-refused `runRoot` pins multi-GB test trees in RAM (`src/run-check.ts:358-364,463`).** On late `ownerRefusal` (`:428-438`), `refused = true` skips `rmSync(runRoot)` so `refusal.json` + `out.log` survive — leaving the entire finished run's tmpfs tree (up to 1.6 GB) pinned in RAM until manual cleanup. Fix: write `refusal.json` + `out.log` into disk `leafTemp/refused-<run>/` and *always* delete `runRoot`.
2. **D1: `AKROGON_EVIDENCE` breaks `.gitignore` and pollutes `git status` (`src/init.ts:71-77`).** `.gitignore` only ignores `**/*.log`, not `evidence-*/**`. Non-log files (`.png`, `.json`, traces) show as untracked files in the registered checkout and block/pollute `sync` and `self-update`. Add `issues/open/**/evidence-*/`, `issues/parked/**/evidence-*/`, and `issues/chart/*/direct/**/evidence-*/` to `.gitignore` in `src/init.ts:71-77` (and existing repos).
3. **D1: `pack` / `status` leave residue or crash on `evidence-*/**` (`src/pack.ts:61-65,104`, `src/pack-command.ts:15-20,122`, `src/status.ts:435`).**
   - `pack.ts:104` only calls `unlinkSync` on files — empty `evidence-<check>-<run>/` dirs (and subdirs) stay behind in `issues/closed/` forever.
   - `pack.ts:63` throws `Log is a symlink` on any symlink — a test copying a symlink into `AKROGON_EVIDENCE` crashes `completeOwner` (`src/phase.ts:391`) right after merge!
   - `pack-command.ts:15,122` and `status.ts:435` only scan `**/*.log` — a folder with only `evidence-*/` files is invisible to `Unpacked:` and skipped by `akrogon pack`.
4. **D1: `AKROGON_EVIDENCE` env stripping & lock ordering (`src/run-check.ts:63-77,373-381,428-439`, `src/config.ts:88-101`).** `constructedEnv` drops uncopied vars: reserve `AKROGON_EVIDENCE` in `config.ts:88` and inject it in `checkedRun`. Create the dir *inside* `flockHold(owner/.lock, '-s')` after `ownerRefusal` (`:375`) so it cannot race `packFolderLocked`, clean it up on late `ownerRefusal` (`:429`), and remove it in `finally` if recursively empty (not just top-level).
5. **D3: `AKROGON_LEAF_TEMP_ROOT` test override vs `run_root` (`src/config.ts:375`).** If `~/.akrogon/config.yaml` sets `run_root`, test fixtures that only override `AKROGON_LEAF_TEMP_ROOT` (and not `run_root`) would unexpectedly write into the configured `run_root` unless `AKROGON_LEAF_TEMP_ROOT` (or a non-default home key) takes precedence over `run_root`.

## What to cut or merge to make it smaller

1. **Cut D4 (`memory.peak` in receipt) from `run-scratch`.** It is the *only* piece touching `verify-runs.jsonl`, forcing a 2-release schema rollout and a cgroup-v2 `CollectMode` race / wrapper epilogue — and on disk-backed runs `memory.peak` mixes RSS + page cache anyway. Re-add only if a later chart actually needs automatic sizing data.
2. **Flatten `run_root` layout** to `<run_root>/run-<id>` (scoped by `homeKey()` if non-default) instead of mirroring `<repo hash>/<leaf hash>/` in `reconcile.ts`, and move refused logs to disk `leafTemp/refused-<run>/` so tmpfs `runRoot` has one unconditional cleanup path.
3. **Skip adding tmpfs/RAM detection code to `src/init.ts`** (`src/init.ts:33-95` is per-repo init, not machine setup): keep the `run_root` suggestion in the `init-akrogon` skill prose rather than adding OS/mount probing code to `init.ts`.
