1. **F1: “Wait for idle” needs a bounded, explicit readiness contract.** `herdr agent wait <pane> --until idle` can miss a ready background seat, whose status is `done`. Omitting `--until` also accepts `blocked`, and omitting `--timeout` waits indefinitely. Evidence: `/home/ivan/Work/infra/herdrdev/herdr-patched/docs/next/website/src/content/docs/cli-reference.mdx:292,305-307,351`. Specify `herdr agent wait <pane> --until idle --until done --timeout 10000`, then re-read the same pane/session and confirm its normal input editor before prompting. Timeout, blocked, unknown, changed session, or renewed work means notify, not another Esc or blind prompt. A matching status alone does not establish that the interrupt completed or that the editor is empty.

2. **F2: Esc does not uniformly produce an empty normal prompt across the three harnesses.** Pi's Esc handler invokes `restoreQueuedMessagesToEditor({abort:true})`, which puts queued steering/follow-up messages plus existing editor text into the editor before aborting (`/home/ivan/.pi/agent/extensions/tamdoma-subagents/node_modules/@earendil-works/pi-coding-agent/dist/modes/interactive/interactive-mode.js:2253-2258,3615-3632`). Herdr submits text plus Enter without clearing that editor (`/home/ivan/Work/infra/herdrdev/herdr-patched/src/app/api/agents.rs:101-106`), so the correction can be combined with restored instructions. Claude's [interactive-mode documentation](https://code.claude.com/docs/en/interactive-mode) gives Esc both interrupt and dialog-dismissal behavior and documents queued messages. Codex's [upstream interrupt change](https://github.com/openai/codex/commit/70a0b1eef87c4fd1398ffc77776033e5efafa645) explicitly changes output-free interruption from prompt restoration to a blank composer, and its `bottom_pane/mod.rs` tests show Esc dismissing popups without interrupting. That change does not establish the installed version's behavior. Require a same-version interruption/readiness test for each enabled harness, including queued text and open dialogs. After Esc, verify the normal editor is empty before sending the single correction. Do not silently erase restored operator input.

3. **F3: Parent interruption does not establish child interruption or correction.** In the installed pi subagent implementation, cancelling `subagent_wait` cancels only the wait (`/home/ivan/.pi/agent/extensions/tamdoma-subagents/tools.ts:182-188`). Its abort handler rejects the wait without cancelling children (`manager.ts:1313-1318`), while child steering and cancellation are separate operations (`manager.ts:499-503`, `tools.ts:208-215`, under that same extension directory). A parent can therefore become idle while its looping child continues. Parent-screen judgment is usable only when it exposes the child's actual repeated actions and identity. Require the corrective prompt to name that child and direct the parent to inspect and correct it through its own child controls, then verify child-level behavior. Parent readiness or receipt alone is not resolution. If the screen cannot establish the child evidence or outcome, notify rather than claiming all-harness child coverage.

4. **F4: “No attempt, no state write” is not guaranteed by avoiding direct akrogon calls.** Esc can generate `pane.agent_status_changed`, which invokes `next.sh` (`/home/ivan/Work/infra/akrogon/plugin/herdr-plugin.toml:13-15`). The current dispatcher ignores only the `working` status event and dispatches the owning leaf on other status events (`src/next.ts:582-585,633-638`). Once the two-minute prompt grace expires (`src/next.ts:178,355-360`), this path can charge an attempt and issue a lifecycle prompt before the watcher sends its correction (`src/next.ts:371-372,399-420`). The delivery leaf explicitly retains event-triggered passes and changes accounting to failed deliveries, with success resetting attempts and updating delivery state (`issues/closed/seat-prompt-delivery/one-attempt-per-pass/brief.md:4,10-15`). Its exact-text, post-offset session check does **not** mistake a distinct plain-text correction for the lifecycle prompt. The defect is concurrent dispatch and accounting, not matching the correction itself. Record a concrete coordination dependency or narrow the promise to “the watcher itself does not write accounting.” A skill-only fresh read cannot guarantee that the event pass will not intervene between Esc, readiness observation, and correction.
