# Slot C leaf review: worktree-keep-rule

Disagreements only. Code lines are from the review checkout at `/home/ivan/.claude/jobs/6a0d8d81/tmp/lw`.

- F1. Brief criterion 3 (brief.md:12) claims removals this leaf cannot deliver on its own. It says a finished `verify-<run>`, `<leaf>-u<N>` of a merged or failed leaf, and unrecorded `batch-<attempt>` copy "are still removed by a pass" without the guards that decide today: `removeWorktree` refuses on uncommitted changes, rebase/merge markers and unreachable commits (src/reconcile.ts:158-177), a live pane blocks the candidate paths, and the force-removal of exactly these kinds at unreachable or dirty states is scratch-copy-removal's, excluded in this design (design.md:44) while state.yaml has `blocked-by: []`. Worse, calling every unrecorded `batch-<attempt>` finished is false once scratch-copy-removal's builder owner record exists: a running build whose attempt no leaf records yet is live work, and the two leaves explicitly may land in either order (design.md:41). Exact line I would write instead: "3. Finished akrogon worktrees that pass today's guards (clean, reachable, no rebase or merge in progress, no live pane inside) are still removed by a pass: a merged leaf's own worktree, a `verify-<run>` copy whose record ended or whose owner is dead, a `<leaf>-u<N>` worker of a merged or failed leaf, and a `batch-<attempt>` copy no leaf records and no live builder owns; force-removal past those guards stays scratch-copy-removal's."
- F2. The kind patterns in criteria 1 and 3 and design.md:31 do not define the names with no matching record or owner: a `verify-<run>` with no verify record, a `batch-<attempt>` whose suffix matches no attempt, and a `<name>-u<N>` whose prefix is no leaf slug. Name alone cannot make them "known finished" under Taken item 1 (forks/removal-rule.md Taken 1), and today's code removes the no-record verify copy by falling through (src/reconcile.ts:524-545), so the implementer must guess whether the new rule keeps or removes each. Exact line I would add after design.md:31's fallthrough rule: "A name that matches a kind's pattern but has no matching record or owner leaf (`verify-` with no verify record, `batch-` with no recorded attempt and no builder record, `-u<N>` whose prefix is no leaf slug) is not a known kind: it is kept as `unmanaged worktree` like any other registered worktree."
- F3. Brief criterion 4 (brief.md:13) requires every removed entry to carry its branch, but most finished kinds have none: verify and batch copies are created detached (src/verify.ts:152, src/batch.ts:116) and delegated workers are detached worktrees (skills/implement-issue/worker-protocol.md:11), so their `git worktree list --porcelain` blocks (the read design.md:33 takes branch and head from) contain `detached` and no `branch` line. The report schema as specified cannot be filled for exactly the removals criterion 3 lists. Exact line I would write instead: "4. After each pass the repo's reconcile report lists every registered worktree that pass removed, each with path, branch (none for a detached worktree), head commit and the rule that removed it, and lists none when the pass removed none; `akrogon leftovers` still reads a report written before this change."
- F4. The store-sweep late contract does not fully match the removal-rule Taken: its host step can still delete a registered worktree without `git worktree remove`. Brief criterion 2 has the host step delete `~/.akrogon/worktrees/<name>` for a name that is no registered repo (store-sweep brief.md:13), while criterion 7 and the design Corrections say a registered worktree inside a store is removed only when known finished, only through plain `git worktree remove` and never when locked (store-sweep brief.md:18, design.md Corrections "Registered worktrees"). Nothing in either text stops the host step from deleting an unregistered repo's whole store directory with a live, even locked, registered checkout inside it; the host step has no Repo object for that repo to run `git worktree list` against (store-sweep design.md Leaf architecture, Coverage). It stays deliverable with one added line in store-sweep brief criterion 2: "an unregistered repo's store directory is deleted only when it contains no worktree directory (no entry holding a `.git` file); one that does is kept and listed by `akrogon leftovers` instead." With that line, the rest of the late contract matches the Taken and leaves store-sweep deliverable: What and criterion 8 now name `akrogon leftovers` (brief.md:4,19), criterion 7 carries the registered-worktree rule and confines `<slug>-<anything>` to unregistered entries (brief.md:18).

No disagreement with brief criteria 1, 2 and 5, the design's lock-first and fallthrough shape, the report-reader compatibility handling in design.md:36, or state.yaml (`plan.synthesis`, debate no, source Tamdoma/akrogon#94 on the single leaf).
