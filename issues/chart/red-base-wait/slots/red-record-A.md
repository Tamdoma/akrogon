# Red record, slot A notes

## Q1 entry identity and clearing
- Pick: one entry per failing unit (comparison Taken's unit: runner/stage/file/suite/full name) under its command, args and scope, with first-seen and last-seen target sha, first reporting leaf, comparison record path, and notice/seed delivery fields. One repo file, additive, written under the existing mutation lock. An entry clears per unit when a later completed comparison (any seat, leaf or merge) shows that unit passing on its target side at a sha descended from last-seen; other units of the same command stay. Clear and update re-read the entry inside the lock and compare identity before writing (lesson 2026-10-10-red-main-hold-stale-clear). No clock, no poll: clearing rides on runs that already happen. Reason: the record no longer gates anything (waiting-leaf Taken), so it only dedupes notices and seeds; a per-unit entry matches comparison granularity. Cost: an entry can outlive its fix until the next run touching that command; status shows last-seen sha so staleness is visible.
- Rejected: per-command entry (hides a second red test under the same command, against B F6); clear on merge of a fix leaf (merge is not proof of green; the fix may be wrong or environment-only as in #77); operator-only clear (manual chore with nothing gating on it).
- Evidence: better-than-training: src/hold.ts:10-21,59-60 (one command, last write), src/phase.ts:857-884 (notice once per hold write, 'hold notice failed' warning), read 2026-10-10. Practitioner: Chromium sheriff doc keeps a per-test failure list cleared by a green builder run, not by commit (sheriff.md, read 2026-10-10).
- Pitfalls: a base-side green caused by environment change outside git (#77) clears correctly because it is a real run; a base-side unverified result never clears (comparison Q2).

## Q2 fix ownership
- Pick: the seat that creates a new entry runs seed-issue once for that entry (one seed per newly red unit group of the same command and target), and the entry stores the returned issue URL or covering report URL. seed-issue's own duplicate lookup (skills/seed-issue/SKILL.md:67) folds a second reporter onto the first report. The operator notice names the entry and the seed URL. Fixing stays ordinary chart/leaf work. Reason: today C8 was fixed twice because nothing named an owner; a seed is the existing intake path and dedupes by body. Cost: one more external call per new red; a seed for a false red (C8 was environment) still needs triage.
- Rejected: notice only (repeats C8 double fix); auto-create a fix leaf (skips charting, akrogon does not open leaves without the door).
- Pitfalls: creation under the lock must not wait on gh; record the entry first, then seed outside the lock, then write the URL back with revalidation. A failed seed is recorded as failed on the entry and retried by the next seat that joins the entry (no timer).

## Flaky ownership (comparison R4)
- Pick: flaky (red then green on retry) stays in the leaf's comparison record and report only, not in the red record. Reason: the red record means red on main; load flakes are owned by merge-load-flakes (#69, off route). Cost: repeated flakes across leaves are not aggregated here.
