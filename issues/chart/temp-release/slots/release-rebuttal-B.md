- **R1 — “An idle shell has no children yet, so nothing escapes” is false.** Herdr starts an ordinary shell before adoption (`herdr/src/pane.rs:1424–1442,1943`). Its available-shell check examines the foreground group (`src/platform/mod.rs:214–224`, `linux.rs:237–239`), not absence of background/startup children. Moving the shell does not move existing descendants. Require a launch barrier before child creation, or another verified containment mechanism. One successful throwaway-pane test cannot establish that invariant. [Kernel cgroup migration rules](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html).

- **R2 — Scope creation must finish successfully before agent start, not merely return a D-Bus reply.** Adoption is feasible in principle and moving cgroup membership does not change the PID/session that Herdr tracks. Permissions are conditional: migration inside the user manager's delegated tree can work directly. Crossing from a login/terminal scope outside that tree requires the system manager's permitted attachment path. systemd implements that request, so this is neither an unconditional permission failure nor an unconditional success. `StartTransientUnit` queues a start job, while actual PID attachment can fail later. Wait for successful job completion, verify the same live shell's destination membership, then submit the agent command. Refuse launch on failure. Herdr submits that command to the existing shell (`src/app/agents.rs:195–215`). Evidence: systemd [cgroup.c](https://raw.githubusercontent.com/systemd/systemd/main/src/core/cgroup.c), `unit_attach_pids_to_cgroup` and its system-bus attachment path, [dbus-manager.c](https://raw.githubusercontent.com/systemd/systemd/main/src/core/dbus-manager.c), `method_start_transient_unit`, and [scope.c](https://raw.githubusercontent.com/systemd/systemd/main/src/core/scope.c), `scope_enter_running`.

- **R3 — “Name derived … never stored” and active-name exclusion drop B's execution identity requirement.** B required a durable generation and retirement record outside scratch. Once a scope stops, its reusable name cannot distinguish an old queued cleanup from a replacement execution. Preserve the actual run identity, successful exit receipt and retiring state. Serialize stop, evidence preservation, deletion and replacement admission. Missing units alone are not exit proof. Evidence: `release-B.md` D1/D2 and A1/A2, `src/next.ts:339–341,777–794`, and systemd's [scope lifecycle](https://raw.githubusercontent.com/systemd/systemd/main/src/core/scope.c).

- **R4 — Weaker cleanup for legacy panes contradicts confirmed release.** B explicitly required verified migration/restart or a visible unresolved-release error, with scratch retained when ownership cannot be proved. Tab-close cleanup cannot account for an already-detached daemon. Nor does shell adoption contain work subsequently launched through another manager or another Herdr pane. Ordinary detached children forked *after* successful adoption remain contained, but those other launch paths need their own ownership acknowledgement. Evidence: `release-B.md` D2/D3, `framework/.claude/browser-core/scripts/cdp-core.mjs:2416–2420`, and the kernel rule cited in R1.

- **R5 — “Logs referenced by path under scratch are disposable (B)” overstates B's position.** B required preserving selected logs needed to assess a failure, or explicitly marking old paths disposable while retaining sufficient contents. Existing names/tails are not automatically sufficient for every failure. Evidence: `release-B.md` A3 and `skills/check-issue/SKILL.md:57`.

- **R6 — I still disagree with A's failed-tab retention default (2b).** B's 2a stops the execution after committed failure evidence and command completion, retaining code and reports. Keeping failed agents alive until operator action postpones the requested RAM release indefinitely. Evidence: INTAKE's operator request, CHART.md:4's every-outcome destination, and `src/phase.ts:48–84` showing failed currently only notifies/renames.
