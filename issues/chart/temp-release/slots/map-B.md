# Temp release: independent territory map B

Keep owned per-leaf scratch on `/tmp`, shorten its path for the actual nested browser socket, and delete it when its owning processes have stopped. Returning every process to plain system tmp would preserve the same backing filesystem while losing the boundary needed for deletion. The largest observed temp tree is outside the leaf boundary, so changing akrogon's folder alone cannot reclaim most current usage.

## Material forks, ordered by reshaping power

### 1 · What counts as release, and which states release scratch?

A phase value alone does not establish that every scratch user stopped. This fork revisits the prior explicit choice to retain failed-leaf scratch.

- **1a (recommended): release processes, then delete owned scratch for merged, failed, parked and closed leaves.** Preserve required evidence in the authoritative leaf folder before release. Stop the leaf's seats and owned child jobs, confirm exit, then remove its scratch immediately. A vanished tab also permits cleanup for an unfinished leaf once its owned jobs are confirmed stopped. Resume starts with fresh scratch. Treat lost tabs as a recovery event, not proof that the leaf completed.
- **1b: keep the current merged-only deletion.** Failed/parked scratch remains until redispatch or the age sweep. This preserves scratch for investigation but fails the operator's prompt-reclamation goal.
- **1c: delete immediately on state transition or tab-close request.** Reclaims visible files sooner but can interrupt another seat or child and leave open-file memory behind. Not recommended.

Recommendation reason: a single ownership/lifetime rule handles normal completion and abandonment. Event hooks provide prompt cleanup; a catch-up pass handles missing events. The catch-up must resolve parked/closed owners too. If a process is deliberately retained for investigation, that leaf has not released yet and its scratch is still in use.

### 2 · Who owns temp outside the subtree?

Most observed usage cannot be reclaimed by akrogon's current deletion function.

- **2a (recommended): contain managed writers, clean at the writer's lifetime boundary.** Fix framework browser-runtime paths to remain short and owned, preserve effective TMPDIR in child launches, and use documented harness-specific controls where the actual managed harness requires them. Akrogon deletes its own leaf subtree after release. Framework tears down its own browser/test resources promptly. Legacy/shared Claude sessions remain operator/session-manager owned until inactivity and ownership are established.
- **2b: make akrogon sweep shared `/tmp/claude-1000`, `page-measure-*` and `bc-sb-*` patterns.** This could reach more bytes but the pattern supplies no reliable leaf owner and can include active sessions. Not recommended.
- **2c: clean only akrogon's existing subtree and leave other writers unchanged.** Small scope, but cannot meet the broader reclamation goal and leaves the demonstrated bypasses in place.

Recommendation reason: make ownership follow the producer. Do not add an arbitrary shared-directory registry or global sweeper to compensate for writers with known lifecycle boundaries.

### 3 · Keep per-leaf TMPDIR, shorten it, or use plain system tmp?

The current default already uses the same `/tmp` filesystem as plain system tmp. The remaining demonstrated path hazard is nesting and socket length.

- **3a (recommended): keep per-leaf ownership on `/tmp`, shorten the basename and validate the complete consumer path.** A concrete candidate is the existing 12-hex repo/slug hash without the readable slug prefix. Under `/tmp/akrogon-1000/<hash12>`, the same page-measure socket example is 101 bytes. With a 10-digit uid it is 107 bytes, leaving no margin for longer consumer components. Validate actual supported browser IDs and socket construction before handoff rather than claiming a universal guarantee. Reconcile old scratch only after its owners exit.
- **3b: remove the leaf override and use plain system tmp.** Shorter paths help the socket, but every consumer again scatters files through a shared namespace. Storage speed does not improve solely because a directory component disappeared, and release cleanup loses its reliable boundary.
- **3c: keep the current basename and give browser sockets a separate short owned runtime.** Preserves recognizable leaf names and can fit the browser path, but needs separate ownership and cleanup for that runtime. Prefer this only if shortening the existing subtree cannot meet the supported consumers' needs.

Recommendation reason: retain the deletion boundary while removing the proven nested-path constraint. Hash-only naming was previously foreclosed in leaf-temp, so 3a is an explicit reopened choice supported by new consumer-path evidence, not a silent restatement of the old lock. Do not move the whole leaf back to `/var/tmp` without new measurements.

## Pitfalls and unresolved measurements

- **P1: stale launch settings.** Existing panes, child environments and old-root scratch need explicit migration after shutdown. Merely updating the akrogon source does not update a running process.
- **P2: evidence lifetime.** Existing reports cite `/var/tmp` logs that disappear on cleanup. Persist evidence needed for review before release. Do not retain the entire fixture or dependencies just to keep a log tail.
- **P3: detached children and races.** No-tab is not established as no-descendant. A lost tab can also redispatch the same leaf (`src/next.ts:793`), so cleanup must precede new allocation and must never race a new owner of the same derived path. Failure to stop an owned child is a reported incomplete release.
- **P4: age-sweep mismatch.** The prior documented seven-day operator loop names `/var/tmp/akrogon-<uid>`, whereas the current default is `/tmp`. Actual operator-script coverage was not read and is unverified. An age sweep is a recovery backstop, not immediate release. Do not silently restore old live-tree retention protections that the operator previously declined.
- **P5: active growth.** Per-leaf paths give ownership, not quotas, and cannot prevent a live suite from consuming the shared tmpfs. The observed 335M leaf root was changing while the fleet resumed. No active growth limit or measured cache-off regression is established. Add neither a quota system nor automatic disk fallback without a separate evidenced need and decision.
- **P6: path budgets.** Check full byte length, not just TMPDIR or character count. The proposed 107-byte worst case has no extra room and does not prove compatibility with other runtimes or platforms.
- **P7: false causal conclusions.** A page closing after a 300-second timeout is a consequence of termination, not proof of the initial stall's cause. Base-red evidence isolates leaf changes, not tmp settings when both runs share them.
- **P8: destructive scope.** Never purge shared Claude trees, unrelated browser profiles or OS caches as leaf cleanup. No cleanup was performed in this map.

Before claiming a speed fix, obtain one named test's effective launch settings, full socket/runtime path, wall time, result and temp byte/inode changes under a fresh seat. Compare the current shortened owned path against plain `/tmp` with otherwise identical command, version, cache setting and concurrency. If the socket failure disappears, that establishes the path fix, not all capture timeout causes. This map proposes the comparison but does not run tests or create experiment files.

## Proposed split and real dependencies

- **S1: akrogon release lifecycle and short leaf paths.** Deliver cleanup after owned-process release across merged/failed/parked/closed/lost-tab cases, with catch-up, fresh resume and durable evidence preserved. Confirm park/close integration and process shutdown guarantees before handoff. This changes the prior failed-retention and naming decisions explicitly.
- **S2: framework browser/test temp ownership.** Fix the demonstrated hardcoded browser runtimes and complete socket budget, ensure producer teardown waits for owned process exit, and preserve isolation. It can proceed alongside S1. Moving its runtime into the new leaf path depends on a settled path budget, not on file overlap.
- **S3: shared harness/legacy temp ownership.** Identify inactive Claude sessions and the actual launch controls for managed harnesses. Legacy session cleanup belongs to its owner, not arbitrary akrogon glob deletion. This is independent of S1 and S2, but reclaiming the current 9.5G depends on this ownership determination.

The old test-time-and-temp chart overlaps directly in location, naming, release and age policy. Leaf-readiness overlaps only where effective launch environment and source selection must match proofs. Neither its grants nor credential-storage choices are reopened here. General affected-test scheduling remains outside this temp-release change.
