# Release — independent round B

Recommend **1a: release every outcome through a recorded process scope, confirm that scope is empty, then delete the owned scratch**. A tab disappearing is a trigger to reconcile that run, not proof that its processes exited. Keep the taken short path. Do not retain failed scratch for diagnosis by default.

## Question

Q1. What ends a leaf execution, and what evidence permits deleting its scratch when it merges, fails, parks, closes, or loses its tab?

The operator asks to free RAM as soon as a leaf releases. CHART.md:4 already specifies deletion after process exit, whatever the outcome. The meaningful remaining choice is the strength of that exit guarantee and the ordering around completion, diagnostics and redispatch.

## Options

- **1a — All outcomes, confirmed process ownership and exit. Recommended.** Establish a Linux cgroup scope for each execution before its seats can run. Record its identity outside scratch. Stop the execution, wait for the scope and its descendants to contain no live processes, preserve the required evidence, then remove the derived leaf folder. Detached processes remain accounted for. This needs a launch integration with Herdr or an equivalent supervisor. It is not available in today's akrogon state or Herdr close response.
- **1b — All outcomes, trust Herdr tab close plus PID/session checks.** Smaller akrogon change. Herdr already attempts shutdown and waits for a session PID snapshot. However, detached browser daemons, processes forked after that snapshot and shutdown timeouts escape the claimed guarantee. A structured Herdr shutdown result would improve this, but a result based only on today's snapshot would still be incomplete. Choose this only if the operator explicitly accepts best-effort release instead of the chart's process-exit condition.
- **1c — Merged-only deletion, retain failed scratch until restart/manual sweep.** Closest to current behavior and the reopened prior lock. Keeps disposable logs available longer, but leaves failed executions consuming memory and makes retention depend on another dispatch or an age sweep. Does not meet this intake.

Reason for 1a: the consumer actually creates detached processes. Process containment removes the need to reconstruct ownership from vanished panes, process names, cwd or temp-file paths. This is a real dependency of a complete exit guarantee, not a reason to introduce quotas, another temp root, a periodic sweeper or a new park mode.

## Verified current behavior

- **F1 — Merged cleanup has two deletion routes, neither confirms exit in akrogon.** `src/next.ts:606` closes the recorded tab when it still has panes. `cleanupMerged` at :614 waits for that command, deletes scratch immediately only when no live tab was found, and removes a closed owner's worktree/branch at :617. The `tab_closed` branch at :777 deletes scratch for phase `merged`, then calls dispatch at :793. Scratch removal itself is recursive unlink followed by `git worktree prune` (:599). A no-tab result is treated as permission to delete.
- **F2 — Failed is a dispatch stop, not a process stop.** `src/phase.ts:109` saves the transition, :114 announces it, and :124 appends the move log. `announceFailed` at :48 notifies and renames the tab. It does not close it. `src/next.ts:571` returns waiting for failed leaves. Operator recovery alone can resume failed state (`src/phase.ts:180`).
- **F3 — Park is not an active-leaf shutdown command.** `src/park.ts:22` calls a leaf running whenever it has a recorded tab **or worktree**, regardless of live processes. :54–56 refuses those explicit park requests and skips them for `--all`. Accepted requests rename issue folders at :67. Keep that restriction in this fork. Parked leaves are absent from normal discovery (`src/next.ts:121` searches open and closed), so a future parked cleanup cannot rely solely on a tab-close hook finding its owner.
- **F4 — Closed is a folder location, not a separate phase.** `completeOwner` moves an owner to `issues/closed` only when all its leaves are merged (`src/phase.ts:133–167`). Closed merged leaves remain discoverable and are swept. `akrogon close` is different: `src/pull.ts:204–207` closes a source issue and prints its delivery reference. It does not change a leaf state, close its tab or remove scratch. The release Findings' blanket claim that closed leaves retain scratch is therefore too broad for the supported closed-folder path.
- **F5 — Tab disappearance can replace an execution without waiting for its descendants.** For a nonterminal leaf `tab_closed` calls dispatch (:793). `allocate` removes existing scratch if no matching live tab exists (:339–341), then creates a new tab and seats (:359–390). Failed leaves do not redispatch. Missing events are another reason this must also be reconciled by allocation/startup, not only hooks.
- **F6 — No persistent OS process ownership exists today.** `src/state.ts:35–58` stores tab, panes, worktree and agent-session delivery metadata, with no PID, PGID, kernel session ID, cgroup or execution generation. `src/shell.ts:74–84` parses pane identity/status without OS process fields. Agent session identity is not a Linux process session. Herdr has `pane process-info`, but its shell PID and foreground group are not a list of every descendant.

Merged phase alone is too early to kill B: `skills/merge-issue/SKILL.md:49–53` requires broadcast after the phase invocation. The current hook at `src/next.ts:808–816` merely excludes blocked/unknown agent-status events. It does not explicitly require idle/done and can accept working or unrelated events. Release must implement the actual finish condition. Idle/done is permission to begin shutdown, not proof that every process exited. An explicit operator stop or vanished tab can interrupt unfinished final work, but that interruption must be recorded instead of asserting it completed.

## Confirming exit

**D1 — Capture ownership at launch.** Have the process supervisor place the leaf's two pane shells and subsequently launched processes into a scope identified by registered repo, slug and a unique execution generation. One scope or two seat scopes is an implementation choice, but every scope for that generation must be empty. Record the scope handles and release progress durably in authoritative leaf state before executable work starts. Continue deriving the short scratch path from repo/slug, as the taken lock requires.

Herdr creates the shell, not the akrogon CLI process. Wrapping only `herdr tab create` in `systemd-run` would scope the client, not the server-spawned pane. A launch hook or a gated seat-shell launcher must establish scope membership before the shell can fork work. Moving an already-running shell later misses descendants created earlier. This is the real launch dependency to settle during handoff. The local host has cgroup v2 (`stat -f /sys/fs/cgroup`), but user-manager access and the launch integration were not exercised in this read-only round.

**D2 — Stop and observe the owned scope from outside it.** Ask the supervisor for graceful shutdown, use a finite stop deadline, and escalate remaining owned processes to KILL. Require `cgroup.events` to report `populated 0` for the whole execution subtree, with new launches/migrations into that retired scope prohibited. Reap owned direct children through their supervisor. If a deadline expires, ownership is unresolved, or membership could have escaped through another launcher, record a release error and retain scratch. A missing scope pathname alone is not a receipt of successful retirement.

Do not kill the shared Herdr server, unrelated user services, or an attached operator browser. A request to an existing browser is not ownership of that browser. Tasks that intentionally delegate execution to another service must either keep that service invocation under the execution owner or provide a separate termination acknowledgement. A cgroup handles ordinary fork, double-fork and setsid. It is not a security sandbox against same-user code deliberately launching work in another unit.

**D3 — Today's PID information cannot reconstruct this after a tab vanishes.** Herdr's process-info can supply a live shell PID and foreground group for diagnostics. Persisting only those IDs still misses detached children and requires PID-reuse protection. `kill(pid, 0)`, `kill(-pgid, 0)`, a parent exit event, an empty `pgrep`, or scanning open filenames cannot prove every leaf descendant exited. Do not inspect process environments to infer ownership. Already-running executions without launch ownership need an explicit restart/migration with verified shutdown, or a visible unresolved-release error. Do not pretend adding fields now retroactively accounts for old children.

## Redispatch, recovery and evidence

- **A1 — Serialize retirement and allocation.** Under the existing global lock, re-read authoritative state and record the old execution as retiring. All dispatch paths, including explicit next, resume, tab-close and operator recovery, respect that record. Run shutdown outside the retiring leaf's scope. Do not hold the global lock while waiting for an agent that still needs it to finish its phase/log. Reacquire it to confirm the same generation is retiring, commit the exit receipt, preserve evidence and delete. Only then clear its pane/tab allocation and admit a replacement generation. If shutdown fails, keep the release record for reconciliation.
- **A2 — Reject stale work by generation.** A queued hook or delayed cleanup for an old tab cannot delete scratch after a new generation has begun using the same hash path. Duplicate events/retries finish the same retirement idempotently. A crash after confirmed exit but before deletion must resume cleanup, not allocate over it. Do not clear ownership handles before the exit/deletion receipt is durable.
- **A3 — Preserve selected evidence outside scratch.** Existing skill rules already require lasting material in the authoritative leaf folder. Before requesting failed phase, seats save the command, results, base/head and required diagnostics there. After shutdown, preserve any additional explicitly required logs before deletion and record the final release result. Current red-on-base review requirements save both log paths plus failing names/tails (`skills/check-issue/SKILL.md:57`), but paths into deleted scratch are not durable logs. Either copy the selected logs needed to assess that failure or mark those paths disposable and keep sufficient contents in the review. Do not archive caches, browser profiles or the whole scratch tree. Keep reports resolvable after the owner folder moves.

`src/log.ts:8–32` records transition identity, commits, diff and agent session. It does not capture test output or shutdown success. Cleanup evidence must not overwrite the original failure reason or invent a successful lifecycle transition.

## Pitfalls and challenge check

- **R1 — Premature self-termination.** Killing a seat during its phase command can interrupt move logging or completion work. The release controller must live outside the leaf scope and wait for required committed work, especially merge broadcast.
- **R2 — Calling missing identity success.** Neither no recorded PID nor no live pane proves zero descendants. Unknown ownership is a release error, including legacy executions and supervisor restarts.
- **R3 — Snapshot races and PID reuse.** Repeated PID/session scans reduce some leaks but do not close the launch/fork gap or track setsid. Use supervisor-owned run identity, not bare stale PIDs.
- **R4 — Uninterruptible tasks.** KILL delivery can precede actual exit. If the scope remains populated, do not delete or redispatch. Report the surviving ownership and pending cleanup.
- **R5 — Stale cleanup deletes a new run.** The short path is stable across retries. Its deletion needs the old generation's retirement receipt plus serialization against current allocation.
- **R6 — Failed recovery loses code.** Free scratch, retain the failed worktree and artifacts. Do not reuse merged-only force-worktree removal for failed/parked cases.
- **R7 — Park and close semantics drift.** Preserve current park validation and source-close behavior. Neither a GitHub issue closure nor a directory rename proves an execution exited.
- **R8 — Shared processes and outside writes.** Release stops only the leaf's owned execution. Do not sweep `/tmp/claude-1000`, hardcoded `/tmp/bc-*`, shared Chrome sessions or unrelated tmp roots. This fork cannot promise all machine RAM or all tmpfs usage disappears.
- **R9 — Evidence retention recreates the cache problem.** Preserve selected proof material on disk, not an unbounded backup of scratch. Reports must distinguish durable copied logs from disposable old paths.

Strongest challenge to 1a: a scope integration is more work than deleting on every tab-close event, and Herdr already tries to terminate session processes. The consumer's detached daemon is the counterexample that makes that cheaper option insufficient. If this dependency is rejected, state the weaker guarantee explicitly through 1b rather than claiming confirmed release.
