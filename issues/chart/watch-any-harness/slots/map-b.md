## Forks that affect the design

- **Q1. Where does the judgment run?** Keep the invoking conversation, or start a dedicated terminal running the selected harness and end it with the invoking agent. The first preserves the model, permissions, replies and intervention history. The second can use a fixed address with keep disabled, but must establish equivalent settings and where the operator reads replies. A fresh agent per tick would lose the two-retry and one-steer-per-seat history. See `skills/watch-issues/SKILL.md`, Judge.
- **Q2. What binds delivery to the original program?** Compare a parent-bound timer using address-based `hc send` with delivery over an hc attachment held from start, or to a dedicated non-kept agent. `hc schema` says attachment loss ends its stream even on keep. `terminal.send` accepts status but no expected process identity, and can wait for an unfinished draft. A pid/transcript check followed by send leaves a race. Test replacement *during* delivery. Do not assume a raw attachment preserves send’s draft and blocked-dialog protections.
- **Q3. How does a busy watcher receive every due check?** Let the harness queue each tick if it demonstrably submits separate turns, or count due ticks in the timer and deliver one at a time on idle. Dropping or combining dues changes an existing guarantee. Backlogged checks must yield to stop, exit and visible resets. `src/hc.ts` functions `send` and `waitFor` report turn/status, which alone cannot prove which check ran.
- **Q4. What makes a second start lose before it can touch a leaf?** Use hc’s unique live name in the repo’s resolved session, or claim a process-held lock keyed by the registered repo. A lookup followed by an unguarded launch races. Resolve aliases to the same repo. A timer name is session-local and bounded to 32 characters. A lock needs discoverable owner information so a second terminal can report or stop the right watch. See `src/hc.ts` functions `run` and `resolveSpace`, and `src/flock.ts` function `flockHold`.
- **Q5. Which terminals may stop the repo’s watch?** Accept stop from any terminal for the registered repo, or require the owner and report its address to everyone else. Specify when stop succeeds if delivery already started, what happens to an executing check, and how a delayed tick from a previous watch is distinguished after immediate restart. A tick must never create a timer.
- **Q6. What exact prompt reaches each harness?** Compare one ordinary instruction naming the installed SKILL.md and action with harness-native explicit skill invocations over the same delivery path. Claude’s E2E uses `/watch-issues`. Installed Pi docs specify `/skill:watch-issues` with trailing arguments. Probe Codex’s `$watch-issues` and agy’s slash expansion in their interactive prompts, including an hc-tagged send. `src/install.ts` function `planSkillLinks` installs four roots but no agy-specific root. Confirm agy loads the installed skill without a test-only link.

## Regression inventory

| Current behavior | Required check on the shared path |
| --- | --- |
| Start | From the registered repo inside hc, acquire ownership, run one immediate check, report the recurring watch. Outside hc, refuse without claiming a watch. |
| Repeated start | The locked behavior supersedes today’s check-before-lookup. Same-terminal, cross-harness and simultaneous starts report the winner and produce just one initial check. Legacy ambiguous matches must never trigger arbitrary deletion. |
| Tick | Every 20-minute due tick produces one judgment in the right repo. Observe an actual timer-originated tick. A direct invocation must never create a second timer. Preserve the current wall-clock cadence unless the contract chooses a different first deadline. |
| Queued ticks | Hold one check open across two deadlines. Count two later, separate checks using actual status calls per turn. Also stop with ticks pending and verify none arrives after stop succeeds. |
| Stop | Stop the selected watch, report already stopped on repetition, and allow an immediate clean restart. Leave seats and unrelated terminals alone. |
| Clear/new | On visible reset, stop before delivering another tick, including when the operator typed an intervening prompt. Compaction continues the same watch. Test each harness’s actual reset. State the accepted Pi limit wherever the running session exposes no change. |
| Paused repo | Start while paused still arms the timer. A paused tick reads status and performs no leaf action. Resume and observe a later check run normally. |
| Expiry and empty repo | Remove the seven-day deadline and its message. Cross the old limit with a controlled clock. An empty inventory leaves the watch running. |
| Session loss | Exit the agent, replace it with a kept shell, and end the hc session. No tick may reach the successor. Release ownership so a new start succeeds. |
| Judgment and reply | Preserve Observe/Judge/Never/Reply, including blocked leaves, retry caps, notify-only cases, one steer per seat per watch, error re-observation and the five-line reply. A scheduling proof alone does not exercise these actions. |
