# Proposed final shape: timer-design (A's autopilot pick, 2026-11-20)

Corrections against the merged notes are marked [C].

1. Checks run in the conversation that started the watch (Q1a).
2. `skills/watch-issues/scripts/timer.ts` runs as an hc child of the watcher terminal (`hc run --bg --no-notify --rm`, default parent), started by the skill from its own tool shell. At start it pins the harness process {pid, start time} by walking ancestors from its caller to the process whose parent is the terminal's root (or the root itself), and the watcher's transcript path when the resolver knows it. Before every send it exits without sending when the pinned process is gone or changed, or the transcript path differs from a path pinned at start. [C] A path first seen after start is latched but recorded as weaker (it may be a successor's). (Q2a, Q3b)
3. [C] Residual race, stated limit: the agent exits while hc holds a send behind an operator's unfinished draft. Outcomes: a bare shell receives a line it cannot run; a new agent in the same terminal gets the tick as its first prompt and stops the watch. The leaf's E2E holds a send on a draft, exits the agent and records what the terminal received. No `hc events` abort and no `--if idle` (it refuses `done`, which claude, pi and agy report after a turn).
4. Reset limits, stated: pi `/new` (no path), codex `/new` until its new rollout appears, and any reset followed by an operator prompt on those two. The skill's first-prompt rule stays for every harness.
5. Busy: the timer waits until the watcher's status is idle or done, then sends. [C] When at least one due passed while waiting, one tick goes right after the watcher becomes ready; two or more passed dues collapse into that one tick. This replaces the e2e's two-queued-ticks assertion with "a due that passed during a check yields one check right after it"; recorded as a deliberate change (B dissents).
6. One per repo: the timer's hc name is `<prefix>-watch` (repo prefix from akrogon config) with label `akrogon.watch=<repo>`, in the repo's resolved session. Start claims the name before the immediate check; a taken name reports the live timer (address, parent) and runs only that report. Stop from any terminal in the session kills and removes the one labelled timer it finds; zero reports already stopped; several are reported untouched. § Never gains this single carve-out. A watcher outside the repo's resolved session, or with no `HC_TERMINAL_ID`, is refused.
7. Tick text for every harness: `watch-issues tick timer=<address> <root>` ([C] root last, so a root with spaces is the rest of the line), sent with akrogon's `src/hc.ts` send helper from the timer's own terminal (untagged). The skill runs a check only when a live terminal at `<address>` carries `akrogon.watch=<repo>` and has this terminal as parent; otherwise it reports no watch and runs nothing (this refuses old Claude cron ticks and late ticks after a stop or restart). The first-prompt stop applies only after that check passes.
8. agy: `src/install.ts` planSkillLinks adds `.gemini/config/skills`, linking every akrogon skill there like the other roots. [C] A's reading of signpost 5a: the operator's words name where the script goes and do not forbid one install root; without it agy cannot run the skill in a normal repo (1a, 6a). Flagged for the operator in the pass-end line.
9. No expiry; Claude cron text (CronCreate, CronList, CronDelete, 7-day) is removed from the skill and docs.
10. Test-only env `WATCH_TICK_SECONDS` overrides the 20-minute interval, like `OBSERVE_AKROGON`.
