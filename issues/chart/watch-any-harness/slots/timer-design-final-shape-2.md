# Proposed final shape 2: timer-design (A's autopilot picks plus operator S1/S2, 2026-11-20)

Batched corrections since final shape 1, marked [C2]: final-check defects B F1/C 2, B F3, B F4, B F5 accepted; operator S1 and S2 (forks/signposts.md Correction 2026-11-20).

1. Checks run in the conversation that started the watch (Q1a).
2. [C2] Start runs a synchronous step in the watcher's own tool shell (`timer.ts start ...` or the plan's equivalent) that identifies the harness process among its own ancestors (the terminal's root when the harness is root; the root's child on the ancestor chain when the harness was launched from a shell; the plan settles the rule against `src/transcript.ts` seat lookup and the codex case B observed: root codex, tool shell's parent = root), reads its start time and its transcript path when the resolver knows one, and passes them as arguments to the timer started with `hc run --bg --no-notify --rm` (default parent = the watcher terminal). The timer is not an OS descendant and never walks ancestry itself.
3. Before every send the timer exits without sending when the pinned process is gone or has a different start time, or the resolved transcript path differs from the pinned one. A path first seen after start is latched and stated as weaker. (Q2a, Q3b)
4. [C2] Stated limits (operator S2a and 2a): a tick hc holds behind the operator's unfinished draft may land in the shell left behind when the operator exits a shell-hosted agent in that window; pi `/new`; codex `/new` until its new rollout appears; a reset followed by an operator prompt on those two. The skill's first-prompt stop stays for every harness.
5. [C2] Busy (Q4d): the timer counts dues. When at least one is pending and the watcher's status is idle or done, it sends one tick, then waits until the watcher's hc turn has advanced and it is idle or done again before the next pending due. Stop, agent exit, replacement or reset discards pending dues. [C2] Stated limit (B F4): an operator prompt submitted between the readiness read and the send merges that tick into the operator's turn; the turn advance still counts it delivered.
6. [C2] One per repo: the timer's hc name is `<prefix>-watch` (repo prefix from akrogon config) with label `akrogon.watch-timer=<repo>` (a key distinct from the removed `akrogon.watch`), in the repo's resolved session. Start claims the name before the immediate check. A terminal is treated as the repo's timer only when name, label and its argv running `skills/watch-issues/scripts/timer.ts` all match; a name held by anything else is reported as a conflict and nothing is touched. Stop from any terminal in the session kills and removes only a verified timer; zero verified reports already stopped; several are reported untouched. § Never gains this single carve-out. A watcher outside the repo's resolved session, or with no `HC_TERMINAL_ID`, is refused.
7. Tick text for every harness: `watch-issues tick timer=<address> <root>` (root is the rest of the line), sent with `src/hc.ts` send from the timer's own terminal (untagged). The skill runs a check only when the terminal at `<address>` is a verified timer (item 6) for the repo whose parent is this terminal; otherwise it reports no watch and runs nothing (refuses old Claude cron ticks and late ticks after stop or restart). The first-prompt stop applies only after that check passes.
8. [C2] agy (operator S1): `src/install.ts` planSkillLinks adds `.gemini/config/skills` as one more root, linking every akrogon skill the same way as the other roots, with the same stale-link and conflict handling.
9. No expiry; Claude cron text (CronCreate, CronList, CronDelete, 7-day) is removed from the skill and docs.
10. Test-only env `WATCH_TICK_SECONDS` overrides the 20-minute interval, like `OBSERVE_AKROGON`.
