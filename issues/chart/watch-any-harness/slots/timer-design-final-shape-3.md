# Proposed final shape 3: timer-design (delta on final shape 2, 2026-11-20)

Items of slots/timer-design-final-shape-2.md stand except as changed here. Changes marked [C3], from final-check-2 B F7, B F8, C 1 (accepted) and B F2, B F4 (A's reading and stated limits).

3. [C3] The timer checks its pin on every poll, both while waiting for readiness and right before a send: it exits (pending dues discarded) when the pinned process is gone or has a different start time, when the terminal's current foreground process is neither the pinned process nor one of its descendants (`hc get --json` `foreground.pid`; covers a suspended harness with another program in front, B F8), when the watcher terminal is finished, or when the resolved transcript path differs from the pinned one. So an agent exiting during the wait ends the timer and frees the name (B F7).
4. [C3] Stated limits: the S2a race now reads "a tick hc holds behind the operator's unfinished draft may land in the shell left behind, or in a program the operator starts there within that hold, when the operator exits a shell-hosted agent in that window" (A's reading of S2a, flagged to the operator; B F2). A prompt the operator submits between the readiness read and the send merges with the tick and the due counts delivered (B F4; stated, as no hc receipt names the task a turn ran).
6. [C3] Stop and start count live terminals in the repo's resolved session carrying label `akrogon.watch-timer=<repo>` first: zero reports already stopped (start then claims the name); more than one reports every match untouched; exactly one is verified (hc name `<prefix>-watch` and the terminal's own top-level argv from `hc get --json` running `skills/watch-issues/scripts/timer.ts`) before stop kills and removes it or start reports it. A `<prefix>-watch` name held by an unlabelled or unverified terminal is reported as a conflict and nothing is touched (C 1).
