# Final-shape check: shell-sweep, slot D

Scope: only corrections K1 to K4 in forks/shell-sweep.md section "Taken", checked against akrogon and hc 0.1.22 as they exist on 2026-11-25. Probes today: full `hc get --json` over every live agent terminal on this host; K3's predicate evaluated over the 8 leaf-seat terminals among them. Scratch dirs from an abandoned git-lock probe were deleted; that probe produced no usable evidence and nothing below rests on it.

## K1 (SIGKILL, no wait, under the global lock): no defect

Nothing in the killed set needs a graceful exit that a contract depends on: a move reaches commitMove only after `requireClean` passes (`src/phase.ts:moveGuards`), so a leftover shell holds no uncommitted work the move accepted, and run-check capture holders are spared separately under K2. No wait under the lock matches the lock's existing tenants; the sweep's hc reads are bounded by the same deadline as every hc call (`src/hc.ts:hc`, HC_DEADLINE_MS), and commitMove already does session work on that path (notices, tab rename in `src/phase.ts:commitMove`'s follow-ups). Killing both roots and descendants with SIGKILL has no ordering requirement.

## K2 (roots, sparing, timing row): one minor defect

Defect: the new `shell_sweep` timing kind lands in a closed union. `src/timing.ts:timingEventSchema` is a discriminated union on `kind`, and `src/timing.ts:readTimings` parses every line with it inside one try that returns `[]` on any failure. From the first `shell_sweep` row in a repo's timings file, any older akrogon build reading that file gets no timings at all (status first-prompt times via `src/status.ts`'s use of `readTimings`, and `src/timing-report.ts`), not just blindness to the new rows. The wake path is already hardened against this (`src/timing.ts:wakeRow` skips kinds outside its set), so dispatch is unaffected, and the window in practice is a manual proof with a worktree build before install, or a later rollback to a build predating the kind. It does not block the pick; the leaf should make `readTimings` skip unknown-kind lines the way `wakeRow` does, in the same change, so this class stops recurring per added kind.

The rest of K2 checks out. The root rule's "parent is the harness pid" uses `Seen.pid`; on every current leaf seat probed today (8 terminals, A and B, claude/pi/codex), `pid` equals `foreground.pid` and the launch chain is `systemd-run` execing through `env` to the harness with no forking shim (`src/seat.ts:startSeat`), so tool shells are direct children of that pid. The two-level claude bash chain hangs off one such root. The live-run spare is buildable as written: run records carry the wrapper's pid (`src/admission.ts` record creation, `pid: process.pid`), already liveness-checked with start time in `src/admission.ts:liveRuns`' helpers. Start-time recheck has working precedent in `src/transcript.ts:procStart`.

## K3 (two lost shapes, schema, predicate placement): no defect

The predicate fires on zero of the 8 live leaf seats probed today (all status non-null, foreground the harness, `argv[0]` `systemd-run`), and no live terminal on the host currently has a null pid. The spawned shape cannot fire during a normal launch: the transient foreground chain is `systemd-run`, `env`, harness, never an interactive shell, and `argv[0]` is `systemd-run` for every startSeat launch (`src/seat.ts:startSeat`). The parked shape's kill-and-replace was exercised in my throwaway-core probe, 2026-11-25: `hc kill` then `rm` on the pid-null `server_stop` terminal succeeded, which is all dispatchSlot's existing `end()` needs (`src/hc.ts:end`). The schema additions match hc's emitted fields as observed in the same probes (`argv`, `reason`, `foreground.name` all present in `hc get --json` output). Confining the predicate to dispatchSlot's lost branch leaves `allocate`'s liveness and `src/reconcile.ts:broadcastInProgress` untouched, as taken.

## K4 (keep-off rejected): no defect

The premise reads true in ~/.config/herdr-app/AGENTS.md, terminal panes section: terminal panes are kept (`keep: true`) by their machine's core, and a lost terminal "gets a shell in its last folder, with the same address; its original command is never run again." Nothing in the taken Q3a relies on akrogon owning the flag: with keep on, the two K3 shapes apply; with keep off, a lost agent ends `finished` and today's lost path already covers it. Either way no mechanism is left without an owner.
