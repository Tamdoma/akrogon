# Leaf review: seat-turn-idle draft handoff, slot D

Read as implementer and against shapes.md sections "Leaf files" and "Preflight and validation" plus standing-design.md. Binding source: forks/shell-sweep.md section "Taken" with its final-shape check (as copied into the draft design), forks/seed-decision.md. Five defects; code checked 2026-11-25 at this checkout.

## F1. Criterion 2's publishing-window spare cannot be built within the listed owned surfaces

Brief criterion 2 spares a subtree holding a run-check "still publishing its log after its payload ended", and the design's final-shape check defines that as any run record of the leaf in `waiting`, `live` or `ended` state whose writer is alive, naming `src/admission.ts:writerLive`. As the code exists:

- `src/admission.ts:writerLive` is a module-private const, not exported. So are the record schema, `readRecord`, and the runs directory.
- The only exported listings cannot see the publishing window. `src/admission.ts:liveRuns` returns only `live`/`waiting` records that are live. `src/admission.ts:lineRuns` admits an `ended` record only when it is `full` or a land record; an ordinary leaf run-check record in `ended` state (which is exactly what the record holds while `src/run-check.ts:checkedRun` publishes, after its inner `admission.end()` writes `ended` in `src/admission.ts:withAdmission`) is invisible to both.

So the spare needs a new admission export (a writer-alive listing across those states, or `writerLive` plus a listing), but design section "Leaf architecture" owned surfaces lists only `src/phase.ts`, `src/seat.ts`, `src/timing.ts`, `src/hc.ts`, `src/next.ts`. As written, criterion 2 cannot be met without either editing an unowned surface or duplicating admission's record format in the seat module. Fix at the door: add `src/admission.ts` to owned surfaces with the new export named, or restate the spare in terms an existing export supports (which would reopen the Taken's final-shape correction, so it is the former).

## F2. The design names two inconsistent proc/cgroup boundaries, so criterion 1's stated proof cannot be built as written

Design section "Leaf architecture" resolves the seat scope "from `/proc/<pid>/cgroup`" and requires it to sit under `leafSlice(repo, slug, home)`, while the start-time re-check must "read through `procRoot()`", and the standing-design interpretation says the tests use "a cgroup tree under `AKROGON_CGROUP_ROOT` and a proc tree under `AKROGON_PROC_ROOT`". With real child processes, a literal `/proc/<pid>/cgroup` read returns the test runner's own cgroup, never a `leafSlice` scope, so the require fails before any kill set exists; with everything read through the fake roots, the scope line as written is not what runs. The codebase has both patterns today and they differ: `src/seat.ts:cgroupOf` reads `/proc` directly, while `src/scope.ts:procRoot` and `src/scope.ts:cgroupRoot` exist for redirected trees and process scans elsewhere go through them (`src/reconcile.ts` enumerates `procRoot()` and reads scope membership under `cgroupRoot()`). The design must state one coherent route: which reads go through `procRoot()`, how a scope path read from a proc entry is resolved under `cgroupRoot()` to read membership, and which facts (comm, parent, start time) come from the same tree the tests fabricate. As written, the implementer must silently deviate from one of the two design lines to make criterion 1's "own test with real processes at the `/proc` and cgroup boundary" exist.

## F3. `shell_sweep` row granularity is incoherent for a two-seat leaf

Taken Q2 and brief criterion 1 both say each sweep appends one row naming "the leaf, the slot" and the ended pids. A committed move sweeps every recorded seat, up to two slots, in one sweep. One row per sweep cannot name a single slot for a two-seat sweep, and the design's sweep interface ("returns the per-slot result for the timing row", design section "Leaf architecture") points at one row per slot instead. Criterion 1 as written is uncheckable for the common two-seat case: an implementer must guess whether one row carries both slots somehow or each swept seat gets its row. Existing timing rows with a slot are per-slot (`src/timing.ts` prompt kind), so per-seat rows are the consistent reading, but the brief must say so.

## F4. Readiness proof records state a command and a result the cited records do not support

- Proof 1's `command` passes `--holder issues/chart/seat-turn-idle/direct`, a relative path. `src/run-check.ts:leafTarget` refuses a non-absolute holder, so the command as recorded in readiness.yaml could not have run; the charting record (forks/shell-sweep.md section "Charting proofs", P1) shows the placeholder `<chart>/direct` and a run id, so the proof happened, but the readiness entry is not the command that ran.
- Proof 2's `result` adds a parked variant "pid null and reason signaled before a shell spawns". The cited record (P2 in the same Charting proofs section) records only: after SIGKILL, live with foreground bash and rewritten argv; after core stop, pid null, foreground null, reason `server_stop`. No `signaled` parked read is in that record. Criterion 4's parked shape does not depend on the word `signaled`, so nothing downstream breaks, but the readiness entry overclaims its own source.

## F5. The standing-design interpretation's fail-first claim is false for criterion 2

Design section "Standing design" states: "The bug-fix rule applies: each criterion's test fails on the current base and passes after." Criterion 2's observable is that certain processes survive the sweep. On the current base there is no sweep, so every named process survives and a test of criterion 2 alone passes before the change. It only gains a failing-first form conjoined with criterion 1's kills in the same scenario. As written, the design asserts a per-criterion property one criterion cannot have; the plan will either quietly conjoin them (then the design sentence should say so) or write a criterion-2 test that was green on the base and proves nothing by the leaf's own stated rule.
