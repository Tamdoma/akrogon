# red-exit proposed final shape (A's autopilot pick, round 1)

Sent for one focused check. Lines marked [new] add a mechanism or change the contract beyond the merged notes' agreed lines.

1. A red verify, a gate refusal, a rebase conflict or a dirty worktree in the merge turn moves the leaf `merge -> check.repair` by the command, clears the batch, records the attempt, and stores a small exit record (reason, red run id or refusal text or base) carried in the check.repair prompt and cleared on leaving `check.repair`. The next leaf's turn starts in the same pass. No seat is prompted for a leaf in `merge`; the seat-owned merge path (solo turn, seat `merged` in merge, `wake=` prompts) is removed, which removes D1 and D2.
2. [new] Push: a non-fast-forward refusal is restacked by the command as today; a second refusal clears the batch and leaves the leaf in `merge` at its place. Any other push error (fetch worked, push failed, candidate not on main) moves the leaf to `failed` with git's stderr as the reason. B's standing dissent: keep the holder and send a notice, because an auth or branch-rule error would fail each queued leaf after one suite.
3. In `check.repair`, B judges the red from the kept log and the leaf's diff and may run the narrowest failing command through `akrogon run-check`; never a full suite (routing already makes `akrogon verify` leaf scope there and `--attempt` refuse). An untouched-diff red that B judges not the leaf's fault returns to `merge` unchanged; a second red on the same unit goes to `check.fix` (existing rule, moved into the check.repair text). merge-issue, lifecycle-rules, check-issue and watch-issues text change in the same leaf as the command.
4. [new] `check.repair -> merge` skips the green leaf receipt when the leaf's HEAD equals the evicted top (the red run's `sha`); with edits it still needs one (today's rule).
5. [new] `akrogon flaky` keeps seeing flakes under 5a: a test red on one leaf's merge run and green on that leaf's next merge run, with the leaf's own commits unchanged between them, counts as one flip (today flips need the same tree, which a rebase changes). How "own commits unchanged" is read is open for the plan.
6. [new] Return place: a leaf's first return to `merge` after its first entry keeps its first `merge_stamp`, whatever the path (`check.repair`, `check.fix`, `failed`); from the second return on it gets a new stamp. Counted from `log.jsonl` moves into `merge`, no new state field. Reverses the operator's 2026-10-05 merge-turn Q3 "3a" (new stamp on every move) whose stated reason, batches, was removed in 6e7a33ff.
7. [new] Main-red cover: the land run accepts a red head in the first turn, with no rerun, no base run and no seat, when every failing unit is a named test title (never `(script)`, `(unnamed)`, `(no test name)`, `(log gone)`) that is an unresolved red on main from a completed base run at or before the head's merge-base. A covered unit resolves when a later completed run on landed main passes that command, or fails it without that unit and with only named failures. No `flakyLines` exclusion (C's standing dissent). A nameless main red is not covered and goes to `check.repair`.
8. [new] First observation: when a returning leaf's land run fails a named unit that its previous exit run also failed, the land run runs the base pass in that turn through the existing known-red branch of `verify`, in the line, one suite at a time. C's two-distinct-leaves trigger is not taken (C's standing dissent).
9. Not taken, recorded: framework `full: [verify]` to close `verify --holder` beside the line; a leaf receipt limited to non-`full` checks for edited returns; showing active covers in `akrogon status`; gates before verify.
