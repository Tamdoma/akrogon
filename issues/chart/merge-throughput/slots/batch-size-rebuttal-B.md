# Batch-size rebuttal, Slot B

- F1: The framework exit ratios are not a measured per-leaf pass probability. Adding unlogged red splits can lower an attempt-success ratio, but green batches also emit multiple merged exits. Neither ratio estimates the independent p used by the simulations. The merged notes correctly acknowledge splits but then use “today's pass rate” to select policy. Evidence: `src/phase.ts:474-477` emits a move for each carried member, whereas `:788-799` splits without moving phase. Keep the empirical ratio separate from the model parameter.

- F2: The simulations establish conditional results, not that O1 loses or O2 wins on this repository. Independent failures, equal run length and an endless queue omit the recorded BASE/interaction failures, dependency priority, finite repair cap and changing repair yield. The merged notes do not say whether A simulated B's full-window-only growth and frozen retry membership. Publish that distinction and count all failure/narrowing runs before applying A's O1 threshold to B's proposal. Evidence: the merged Evidence section lists the simulation assumptions; `src/next.ts:1017-1020` selects followers anew, while `src/phase.ts:795-796` stores only a limit. B's frozen membership changes that behavior.

- F3: A wrong culprit is not harmless work moved entirely off the merge turn. The actual defect stays queued and can reject the next full batch. Meanwhile an innocent leaf spends the approved repair budget and can eventually fail terminally after repeated wrong nominations. A green exact-command rerun establishes that the accusation did not reproduce on that candidate, not that the remaining batch will pass. Evidence: the merged O2 and P1 explicitly count the nominated leaf under bounce-counting 1a; its own simulation allows wrong nominations. The choice needs an explicit innocent-leaf protection policy and must include the actual culprit's subsequent failed gates. Higher leaves per gate run alone does not establish equal quality or completed-work throughput.

- F4: O2's unnamed-failure rule mechanically blames the holder without evidence. A red stack does not identify its cause. The command can attribute a rebase conflict because `src/batch.ts:58-70` returns the conflicting branch. It has no equivalent attribution result from the full gate. Keep an evidence-based nomination optional if chosen, but an unknown aggregate failure needs mechanical narrowing or another explicit diagnostic path, not an assumed holder defect. This also preserves the meaning of the counted repair cap.

- F5: O2 cannot “rebuild with existing code” after ejecting an arbitrary member without new authorization and batch reconciliation. Current `src/phase.ts:770-783` authorizes only the holder with its current attempt. Moving a carried member to check.fix through that attempt needs a dedicated command-owned operation, atomic restore/ejection, stale-attempt invalidation and next-holder selection. Holder versus follower is still material to recovery, even if it stops determining which suspect is named.

- F6: P2 assumes the ejected leaf is the rightful owner of an interaction defect. Two changes can each satisfy their own contract yet conflict in combination. Choosing one as the repair owner can be valid, but “that is now its real defect” does not follow from a red aggregate. Record the conflicting contract and explicitly assign the integration repair instead of treating a selection as causal proof. Evidence: the merged P2 describes a failure occurring only together; `src/batch.ts:42-76` composes branches but does not judge which contract is wrong.

- F7: Default 8 and a new repo-config key are ungrounded in these notes. A's simulations compare cap 8 against other policies but do not compare caps or include size-dependent setup/conflict/run cost. Existing `src/next.ts:1020` limits followers, so “8” also needs total-size semantics. Present 8 as a proposed starting choice with its exposure cost, not as “no size tuning” or an established optimum.
