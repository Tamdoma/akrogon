# Systemic map, slot C

## Loops

- L1 Reinforcing, proofability ratchet (chart-issues -> plan-issue -> implement-issue): a done-criterion must be an observable result and the handoff audit asks how each clause is proven (akrogon skills/chart-issues/assets/shapes.md:386). Standing design then says every criterion gets the cheapest sufficient test (standing-design.md:10), plan-issue requires a test for every criterion no checks command already proves, and requires a case for every condition a plan decision can break (plan-issue/SKILL.md:51-53). Implement-issue then runs the planned tests instead of writing them and treats tests as locked (implement-issue/SKILL.md:56,63). A quality promise therefore gets rewritten until a command can return exit 0 or 1: a count, a share, an excerpt match or a text string. Once written, that proxy is the cheapest thing for the next chart to copy.
- L2 Reinforcing, phase closure (framework orchestrator): a batch phase closes only when every unit has a complete current outcome or accepted residue (framework .claude/workflow/orchestrator/parallel.md:123). Uncertainty has no complete state of its own, so designers route it through a failed unit, a checker finding and operator residue triage. The serp fork record shows this conversion step by step: only a gate-bound checker problem covered a unit at close, so THIN_READ had to become a script gate (issues/chart/serp-wireframing/forks/stops-locks-trust.md:47,60). The model's judgment was not the input to that decision; the close machinery was.
- L3 Reinforcing, writer/checker mirroring (standing design): "Writer and checker share one rule definition" and a model-judged check is tested with one known-acceptable and one known-unacceptable case (standing-design.md:18). To make writer and checker agree, the rule is written in the most mechanical form both can apply identically. A nuanced rule ("is this evidence enough for this page?") cannot survive that format, so it becomes `thin_min_usable_page1`, "more than half", 50 characters.
- L4 Reinforcing, recorded replay (standing design + capture drivers): model stages replay one recorded run, with fresh calls only on changed model-facing inputs (standing-design.md:15). Replay needs a deterministic way to advance and compare, so drivers reach for exit codes, finding codes and output text. Latest case F3 is this loop in pure form: the driver advanced by matching the model's obligation wording, and broke when the same session wrote the same fact without the prefix (wireframe-skill-revamp/implementation/report.md:68).
- L5 Reinforcing, lesson-to-guard (learn-issues + lesson rule): a lesson retires only when its mechanism is removed, refused loudly, or covered by a running mechanical guard (akrogon skills/chart-issues/lesson-rule.md:8), and learn-issues sorts a still-reachable pattern as Checkable when a command could detect it as a fixed pattern (learn-issues/SKILL.md:21). The only rewarded way to close a lesson is therefore to build a guard. Judgment lessons can only stay active or be transferred by an operator-approved diff, so they accumulate as prose nobody is bound by.
- L6 Balancing on paper, arriving too late (check-issue): check-issue already rejects tests of prose wording outside literal contracts and calls wording coupling a Nit (check-issue/SKILL.md:51). But the same paragraph says a scenario a done-criterion names always blocks (check-issue/SKILL.md:59). By review time the proxy is inside the locked brief, design and plan, so the balancing rule can only demote the test that proves it, not remove the gate the criterion demands.
- L7 Balancing that never fires (agent-latitude check retirement): block ledger plus operator review was designed to retire checks that block valid work (agent-latitude/forks/check-retirement.md Taken 1-2). It records hook and contracts-verify blocks. A leaf's own script gate, a planned test and a capture driver are none of those, so the newest class of false blocks produces no ledger line and no review ever starts. The review itself is a standing operator duty with no trigger in the lifecycle (agent-latitude/CHART.md Pending steps).
- L8 Reinforcing, local-fix memory: each episode is fixed inside its own chart and recorded as a lesson or a kept-with-reasons list, while the lifecycle rules that produced it stay untouched. The next chart then re-derives the same proxy from the same standing text. This is the loop that connects the evidence below.

## Gaps

- G1 No classification point: no step in chart, plan or check asks whether a criterion is mechanical (a fact a program can know) or judgment (quality, relevance, sufficiency, similarity, intent). Both kinds currently take the same road to a script test.
- G2 No complete-outcome shape for judgment in batch phases: a model decision recorded with a reason is not currently a first-class complete unit outcome, so designers keep inventing failed units and checker findings to make phases close (L2).
- G3 No false-block accounting for leaf-owned gates and tests: implementation reports record runs and costs, but no cause label exists outside the agent-latitude pilot, so a gate that only ever blocks valid work looks identical to a guard that catches defects.
- G4 No cross-repo lesson route: framework lessons about akrogon lifecycle behavior have no path into the akrogon skills that generate the behavior, short of an operator-filed seed.

## Fix

- X1 Akrogon, `skills/chart-issues/assets/standing-design.md` (leverage point: the rule every leaf design must interpret). Delete the sentence "A model-judged such check tests one known-acceptable and one known-unacceptable case at target size" from line 18 and add in its place: "Mechanical checks decide only what a program can know without judging the work: presence, parse and schema, identity and reference resolution, state, security, spend and destructive effect. A quality, relevance, sufficiency, similarity or intent call is made by the model doing the work, recorded with its reason and the evidence it weighed; its proof is the recorded run plus a reviewer's verdict on the outputs. No count, share, similarity score, keyword or output-text match stands in for that call unless an operator-named literal contract defines the value itself." Scope the writer/checker-shared-rule sentence in the same line to mechanical rules. Why: this removes the license L3 gives every designer to mirror a judgment as a checker.
