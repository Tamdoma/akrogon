# Slot B: systemic diagnosis

The recurring cause is not a lack of instructions to prefer judgment. The lifecycle turns an approved local proxy into an observable criterion, then makes the proxy and its tests hard to remove. Earlier exceptions are stored as case-specific history, while the next chart can create a different proxy without applying the same principle. This is an inference from the rule and case evidence below, not a claim that one line caused every incident.

## Loops

- **L1 — Reinforcing: proxy becomes contract.** A quality or evidence problem enters a chart → `questions.md:27` asks for a step that removes each pitfall → a threshold or stop appears as a proposed remedy → `shapes.md:265-267` converts it to an observable done-criterion → `plan-issue/SKILL.md:39-43,51-53` requires a test for it → `implement-issue/SKILL.md:38,52,56` locks the design and executes planned cases → `check-issue/SKILL.md:37,51,59` and `merge-issue/SKILL.md:33,43` enforce that contract and green checks. A proxy is now mistaken for the quality itself. None of these steps by itself says all quality must be scripted; the chain fails to ask whether the criterion's judgment was converted into the proxy.
- **L2 — Reinforcing: a false stop causes more scaffolding.** THIN_READ stops prep → triage/acceptance, capture handling, tests and reruns are added to navigate it → their own failures generate further repair. The observed plan has the gate, answer and driver (`framework/issues/open/serp-wireframing/wireframe-skill-revamp/plan.md:30,44,140,211`). The 2026-11-17 amendment removes that loop (`plan.md:215-226`); the plan records five cases used before it and three re-recordings planned. Do not infer all five failed for the same reason.
- **L3 — Reinforcing: past failures become permanent stops.** `akrogon/skills/chart-issues/lesson-rule.md:5-9` encourages checkable mechanisms to be seeded and retires a lesson only on removal, loud refusal or blocking guard on every path. `standing-design.md:12` keeps every test guarding a real regression; `check-issue/SKILL.md:51` requires a source to delete an assertion while a new test needs none. Together these favor preserving or adding a mechanical barrier. The instruction does allow removal and agent-judged transfers; the asymmetry is that a possible wording-only problem is a Nit until a valid instance fails.
- **L4 — Reinforcing: scope and history reset.** Chart handoffs preserve fork locks and the next leaf implements them (`chart-issues/SKILL.md:59,77`; `plan-issue/SKILL.md:47`). Prior issues solve their own named checks and close, while a later chart may not carry a cross-domain principle. `check-issue/SKILL.md:43,49,51` excludes active lessons from review and downgrades wording coupling that has not failed today to a Nit; its final wording ban expressly names akrogon tests, not framework product tests. This is a reachable gap, not proof that those reviewers knowingly ignored #389.
- **L5 — Balancing: genuine incident, then operator correction.** An expensive false halt or a narrow agent-flow failure surfaces → the operator challenges the gate → the current chart amends/removes it → local flow improves. F3–F5 were removed by `framework/issues/open/serp-wireframing/wireframe-skill-revamp/design.md:438-449`. Earlier #389 led to actual removed gates (H1–H3). This loop requires the harm to escape before it acts.
- **L6 — Existing balancing, too weak for this case.** `standing-design.md:7,10-12` says no vanity tests, cheapest sufficient proof, delete false expectations; `check-issue/SKILL.md:49-51` needs a real consequence and rejects akrogon prose/output-wording tests. These are useful safeguards, but the same review also preserves criterion compliance and calls non-failing wording coupling a Nit. The question “is a script making a model-quality decision?” is not required at criterion creation or at framework review.

## Missing balancing loop

- **G1** Before a criterion, check, gate or capture transition is locked, a thinking reviewer traces its input → asserted fact → real downstream failure. If the assertion decides meaning, relevance, originality or sufficiency of model output, delete the proxy and assign the decision to the relevant agent. A reviewer may block an invalid mechanical gate on that basis even before a lucky valid wording has actually failed. Use observable structural and literal interface checks for missing files, invalid schemas, unresolvable references, actual functional/security/accessibility constraints and spend. A threshold remains valid when it is the literal user policy or a measured functional boundary; do not ban numbers categorically.
- **G2** Put that boundary in the chart contract and planning/review steps, where new constraints enter, not in a new regex or a separate approval queue. Under autopilot, the same agents apply it without a new operator stop. The review of generated work judges substance, not one canned sentence; no positive/negative wording oracle is necessary.
