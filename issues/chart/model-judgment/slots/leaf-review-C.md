# Leaf review, slot C

Disagreements only.

## F1. The leaf's own plan pass is still ordered to write tests for criteria 1 to 3

- Evidence: this leaf runs under the installed old text until the next release link, which the design's Leaf architecture consumer note states for doors. Current plan-issue `## plan.synthesis` maps each criterion to a command that observes it and writes a red-first test for each criterion no existing test proves, with no exception. The design's Current interpretation says no test is written for criteria 1 to 3, but `Open for the plan: none` never tells the planner how to record that departure, so the planner must either invent prose tests (against the brief's owned files and "no test is added") or silently skip a rule of its own skill. Current check-issue `## check.review` then blocks on a criterion with no test.
- Fix: replace "Open for the plan: none" with one binding plan instruction: beside criteria 1 to 3 the planner records observation = both reviewing seats reading the report, command = none, no test, case or red-first commit, under this design decision and the prose-test rejection; criterion 4 alone carries the test proof. Review then judges the missing test against that recorded design decision.

## F2. The design carries two opposite binding answers for an in-flight proxy

- Evidence: the design's Signposts section, copied verbatim, records 5a as "a proxy named in an existing brief is routed back as a wrong criterion, not enforced". Its Final shape W5 and W6 adopt the opposite later pick: the earliest seat reads the criterion in record/choice form in place. Nothing in the design states which binding text wins.
- Fix: add a correction note directly under the Signposts section: the proof-form and review fork picks supersede 5a's routed-back wording with the recorded reading, and the signpost text is retained verbatim for provenance only.

## F3. Implement-issue's Standalone and Direct order rule is a missed site in an owned file

- Evidence: implement-issue `## Standalone` says its only test rule is order, tests from the brief first and committed, and `### Direct form` follows the same order rule. That "only" makes the section self-contained, so W7's clauses in `## implement` do not reach it. Brief criterion 1's site list names implement and check.fix but not Standalone or Direct, so a direct-route chart with a model-choice criterion would still be ordered a committed test for the choice before code.
- Fix: add Standalone and Direct to W7 and criterion 1's site list: the tests-first order covers mechanical behavior and the record; the choice is recorded in the report and, on the direct route, read by B under W6. Or name Standalone an explicit exclusion with its reason in the design. Direct cannot be excluded that way, since B already reviews it under check-issue.

## F4. W7's removal exception does not clear the locked-decision stop for a design-named gate

- Evidence: implement-issue `## Shared context` ends the pass `failed` when a fix needs a locked decision changed. W7 lets A remove an existing gate in its own commit, but never says that removal is not a locked-decision change when the gate is named in the leaf's design as existing behavior. W5 carries that exact clause for the recorded reading; W7 and the design's W1 slow-run scoping cover acceptance rules in one slow-run case only.
- Fix: add to W7, matching W5: removing a sourceless proxy under the standing-design line is not changing a locked decision; a gate whose value has a named source is never removed this way.
