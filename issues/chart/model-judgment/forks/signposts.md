## Question

1. Who must show a call has one right answer before a script may decide it?
   - 1a (recommended) The proposer of the script names the single-right-answer source (a literal contract, a schema, a granted bound in the operator's own words). Without one, the call is the model's. Under autopilot the door never invents a number on model output.
   - 1b A script is allowed until a reviewer shows the call is a judgment.
   - 1c The door may also name a bound under autopilot with a recorded reason.
   - Steers: the standing-design line's exception clause, the handoff audit refusal, the autopilot pick limits, Fix versus Nit in review, every fork that proposes "a small limit". (B S2, C Q1)
2. How is a model's choice proven?
   - 2a (recommended) Split record from choice. The record (choice, reason, evidence weighed) gets function checks only: it exists, keys valid, reason not blank. The choice itself has no expected value in any test; the review seat reads it on a run the leaf already makes or a recording it already has. A judgment never triggers a paid call by itself.
   - 2b One dedicated recorded real run per judgment criterion.
   - 2c A known-good and known-bad pair at target size.
   - Steers: the proof sentence in standing-design, plan entries for judgment criteria, the recorded-output fresh-call list, paid grants. (draft 2, B S3, C Q5, framework D rebuttal)
3. When may the review seat block on a recorded judgment?
   - 3a (recommended) Only when it names a concrete harm on the recorded evidence: a fact the evidence contradicts, a missed required input, a broken function, a keep-list breach. A different taste is a Nit. No operator stop follows a judgment disagreement.
   - 3b The reviewer's reading always wins and is a Fix.
   - 3c Disagreements go to the operator.
   - Steers: check-issue verdict wording, repair-round use, convergence forks. (B S1, C Q2)
4. What does the lens cover?
   - 4a (recommended) Every artifact that decides pass, fail or the next step: tests, done-criteria, product runtime gates, capture drivers, operator stops and the door's own autopilot picks.
   - 4b Tests and done-criteria only.
   - Steers: the wording of every rule line, whether autopilot.md joins the touched files, the leaf split. (B S5, draft 3)
5. What happens to proxies that already exist?
   - 5a (recommended) No sweep. The lens applies when work next touches one: a seat that hits an existing proxy blocking valid work removes it in its branch with the reason under the existing deletion line, the review seat judges the removal, keep-list checks are never removed this way, and a proxy named in an existing brief is routed back as a wrong criterion, not enforced.
   - 5b New charts only; existing briefs keep their criteria.
   - 5c Active sweep this session.
   - Steers: wrong-criterion routing, lesson seeding as removal, whether implement-issue is touched, scope. (B S4, C Q4)
6. Which calls stay the operator's?
   - 6a (recommended) Only what the operator alone can grant or know: spend, destructive or public effects, security, credentials, and any call the operator named as theirs in the intake or signposts. Never a per-item quality stop.
   - 6b The operator also keeps taste, brand and public claims by default.
   - 6c Whatever a seat marks sensitive.
   - Steers: operator steps as pitfall removers, per-item stops in the audit, autopilot limits. (C Q3)
