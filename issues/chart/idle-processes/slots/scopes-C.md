# Seat scopes and bus cut — C

## Pick: keep the scopes, change the bus cut from seat-wide to run-only
- Keep per-pane scopes. Remove `DBUS_SESSION_BUS_ADDRESS=unix:path=/nonexistent` from seat placement (src/next.ts:481-482); keep the cut that run-check/base-run already force in their constructed environment (src/run-check.ts:56). Revisit blanket cut only if measurement below shows direct (non-run-check) browser escapes are material.
- Challenge to the operator: scopes were not the speed merge by themselves. The host-wide permit landed 12:46-12:52 and the slice/quota/seat-boxing stack at 13:09 (git log 6968997, 63ad6ea, f0c7f88), then CPUQuota stayed until 51f9a67 (21:11). Removing scopes conflates identity/grouping with the two mechanisms that actually queued or throttled work.

## Speed and reliability evidence
- A pane scope carries no CPU or memory settings of its own: adoption passes only PIDs, Slice, TimeoutStopUSec and SendSIGHUP (src/scope.ts:69-84), and live user-manager properties for a leaf slice/scope are unset/infinity. The only resource values are on the parent `akrogon.slice`: CPUWeight=20, MemoryHigh=64G, MemoryMax=96G today (systemd/akrogon.slice:5-9). Any speed cost from containment is therefore weight/memory policy or the one-time allocation work, not a per-command scope tax. Adoption happens in `allocate` before agent start, with an up-to-5 s placement poll only when a pane is outside (src/next.ts:510-528).
- Seat-scope's own measurement 2 ran boxed at 239 s and its Taken reason was no added waiting (issues/chart/host-test-load/forks/seat-scope.md Taken); the quota rerun at CPUQuota=1600% was 256-265 s (ceiling-values Taken). My live 5 s sample after the quota drop saw the slice use 18.2 cores with host 20.4/32 busy and zero added throttled periods, which is inconsistent with scope grouping capping today's work; timings stay confounded because permit, quota, WIP and workload all changed the same day.
- CPUWeight still can cost speed, but only when non-akrogon work actually competes: systemd weights are proportional shares, not reservations (systemd.resource-control(5), local systemd 262). Removing scopes to escape weight 20 is the blunt version of changing one number. If a trial is wanted, raise the slice weight (or relax MemoryHigh) at runtime first and keep attribution; do not delete the identity plane to change a tuning value.
- The bus cut's proven cost is reliability, not CPU: `gh auth status` succeeds normally (token in keyring) and fails immediately under `DBUS_SESSION_BUS_ADDRESS=unix:path=/nonexistent` (live test 2026-10-13); `~/.config/gh/hosts.yml` has no oauth_token, so the original file-storage prerequisite is not in effect. 04577a4 restores the bus only for akrogon's own direct git/gh argv through `run()` (src/shell.ts:83-101). It does not cover a seat shell's own `gh`, busctl, keyring or portal calls. Direct git currently survives only because the global credential helper itself prefixes the real bus address.
- Scope adoption is a real but bounded reliability surface: an unreadable/outside restored pane is closed or the leaf is skipped (src/next.ts:436-445,510-526). That can lose a pane session once per restore/recreate; I found no "cannot read scope" failures in issues/log.jsonl/open-leaf artefacts today.

## What each option breaks or invites
- Remove scopes + cut ("yesterday"): restores seat auth/tools, but breaks `akrogon stop`'s only kill (stop the leaf slice, src/stop.ts:51-53), breaks run-units' recorded launching-pane authority and per-run reservations under the leaf slice (issues/open/concurrent-checks/run-units/brief.md:4,17), and makes this chart's census guess from cwd/cmdline instead of reading leaf cgroups. It also does not unbox existing panes: scopes live while any member process lives (systemd.scope(5)), so rollout means closing/recreating every leaf tab anyway.
- Remove scopes, keep cut: worst combination — auth stays broken and containment/attribution is gone.
- Keep scopes + seat-wide cut unchanged: preserves containment for raw seat commands, but keeps the direct-gh/D-Bus-tool failure class indefinitely and depends on an operator credential change that evidence shows has not stuck.
- Keep scopes, run-only cut (my pick): official checks keep the containment that prevents Chrome self-scoping into app-*.scope (the mechanism the cut exists for), because run-check forces it per run. The accepted leak is a browser launched *outside* run-check (raw targeted tests, ad-hoc dev-browser): it can escape the leaf slice, so memory admission and idle census will undercount it until framework's browser-dies-with-run lands. That residual must be written down in host-test-load limit-boundary/seat-scope, not discovered later.

## Measurement that would change the pick
- One leaf, two otherwise identical solo runs of framework:verify:core and akrogon `test`: boxed today vs unboxed shell, quota already off, slice weight/memory temporarily neutral. If unboxed is >5% faster with scope properties neutral, scopes themselves cost something I have not found and removal is right. If restoring the seat bus creates new app-*.scope Chrome units or orphan roots during ordinary (non-run-check) seat work, reinstate the seat-wide cut or replace it with a D-Bus filter that denies org.freedesktop.systemd1 only.
