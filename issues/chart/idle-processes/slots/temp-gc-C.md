## 1. Where temp lives

- **Disk, at A's `/var/tmp/akr-<uid>` root.** systemd's own guidance is size-based, not folklore: /tmp for smaller size-bounded files, /var/tmp for everything else, honoring $TMPDIR (systemd.io/TEMPORARY_DIRECTORIES, read 2026-10-14). Build trees and browser profiles are the "everything else." `/var/tmp` here is root btrfs (`findmnt -T /var/tmp`), hot files still serve from page cache, and the root keeps the socket budget: leaf path 31 chars vs 27 today, inside Chromium's measured 62-byte TMPDIR limit (issues/chart/test-time-and-temp/forks/leaf-temp.md Findings). My earlier `~/.akr` proposal buys 2 chars and puts scratch in home snapshot/backup space for no gain; /var/tmp also already has the operator's tmp-sweep loop and 30-day tmpfiles ageing as backstops (`/usr/lib/tmpfiles.d/tmp.conf`: `q /var/tmp ... 30d`).
- What this could break: disk-backed browser profiles may be slower on cold cache (the unverified 2026-10-02 claim — settle it with the benchmark in §5, not by assertion); large deleted-but-open files now consume disk inodes instead of RAM (btrfs allocates inodes dynamically, `df -i /` — the September inode exhaustion was a tmpfs property and is the one thing disk removes outright); a leaf paused >30 days can lose scratch to tmpfiles ageing, already accepted in leaf-temp Q3.
- Keep one root for both seat TMPDIR and run roots (`src/config.ts:267-275`, `src/run-check.ts:151`). Splitting media by producer (RAM for browsers, disk for builds) cannot be expressed through the single TMPDIR the tests actually read, and per-producer env plumbing is the complexity the operator keeps rejecting.

## 2. Who deletes what — ownership first, collector as backstop, not the reverse

- Ownership already deletes most temp when it is allowed to finish: run-check removes its run root in `finally` (`src/run-check.ts:199-201`), page-measure removes its runtime dir in `closeBrowser` (framework `page-measure.mjs:392-396`), scratch-writer-isolation removes each `w-*` root in finally (framework `scratch-writer-isolation.test.ts:445,468,527`). Every survivor class from the overnight census is a *killed* owner: tool-timeout SIGKILL, pattern-killed runner, dead seat. So the collector's job is exactly "owner provably dead," not "old."
- Recommended collector design: extend the reconcile sweep that already exists (`src/reconcile.ts:401-447`) rather than a new daemon — it already runs on every next pass, already knows `.owner` pid/boot records, and already removes dead-owner `run-*` roots. Add the top-level rule: a top-level entry in a leaf temp dir is collectable only when **no process in that leaf's slice references it** (cwd, open fd, or cmdline/env path under it) **and** it was already unreferenced at the previous pass — two-pass confirmation, no renaming. Run roots keep the stronger existing rule (dead `.owner` ⇒ delete immediately).
- "Live" must never be deleted: any entry referenced by a live process in the leaf slice (including a browser whose `--user-data-dir` or profile path sits under it), any `run-*` whose owner pid/boot/start is live, any entry younger than the two-pass window. Age alone never suffices — systemd's own guidance warns ageing deletes live files not recently touched (systemd.io/TEMPORARY_DIRECTORIES, "Automatic Clean-Up"), and a build tree can sit untouched for an hour while its owner compiles elsewhere.
- What the collector must not do: kill processes. An ownerless browser (ppid = user manager) is a process-lifetime bug (framework browser-dies-with-run, akrogon run-units), and deleting its profile dir under it corrupts it without stopping it. The collector reports orphans to the census; stopping them is stop-run / slice stop, a different verb with an explicit operator or lifecycle trigger. Zombies likewise: already dead, only their parent reaps them (wait(2)); the collector ignores them.
- The new-tab wipe removal stays: with the collector keyed on dead owners, a blanket wipe on allocation is both unnecessary and the one path that can delete a live detached run's files (`src/next.ts:466` pre-fix). Reconcile after dispatch in the same pass (`src/next.ts:1585,1596,1614`) is soon enough for a new seat.

## 3. Framework producers to fix at the source

- Scratch git repos: `createScratchRepo` offers `cleanup()` (framework `harness/scratch-repo.ts:17-31`) but most of ~20 call sites never call it (grep `createScratchRepo` vs `.cleanup()` in `.claude/hooks/tests`). Make the harness register its roots and remove them in a process-exit/`afterAll` hook inside the harness itself, so call sites cannot forget; csp-spine's repeated ~216 MB roots (my overnight census) are this class.
- `bunx` installs: Bun documents that bunx checks for a locally installed package first and otherwise uses its global cache (bun.sh/docs/pm/bunx, fetched 2026-10-14). Call the fixture's own installed binary instead of `bunx astro` / `bunx wrangler` (e.g. `dev-build-astro/test/emdash-kit/site/src/emdash/local-dev.ts:82`), so no 134 MB workerd copy lands in TMPDIR per run. Where bunx is intentional, it belongs in the shared on-disk Bun cache, not per-leaf temp.
- Build trees (`site-*` 0.9 GB, `cfm-*` 0.8 GB in the census): stop copying whole sites per case; build once per test file into one root and reflink-copy (`cp --reflink=always`, free on btrfs until modified) or hardlink immutable inputs. This only works on disk — another reason the root move matters.
- Fixed paths: `/tmp/swi` is a deliberate short canary parent and cleans its `w-*` children per case (scratch-writer-isolation.test.ts:75-78,445) — keep the behavior, but the canary should follow TMPDIR unless the point is catching writers that ignore it; `/tmp/ftf-logs` is a seat-invented log path, already covered by the skills' "$TMPDIR, never a fixed /tmp/<name>" line — no code fix, it dies with the seat that made it. Page-measure's `/tmp` fallback (`.claude/skills/_shared/libraries/page-measure.mjs:363-368`) triggers only when TMPDIR would overflow the socket path; the 31-char disk root keeps it dormant.

## 4. A's unlanded change

Land it (root to /var/tmp, wipe removed), with two amendments: name the root for the existing sweep or teach the sweep the new name — the operator's `~/.local/bin/tmp-sweep` 7-day loop iterates `/var/tmp/akrogon-<uid>/*`, not `akr-<uid>`, so as written the new root escapes every existing backstop until OS 30-day ageing; and ship the §2 reconcile extension in the same leaf or the next, because without it the change converts a bounded RAM problem into an unbounded disk accumulation (the pre-2026-10-01 failure shape, minus the RAM pressure). Legacy `/tmp/akr-1000`: one-time door cleanup after verifying owners, as the brief accepts; do not teach reconcile two roots permanently.

## 5. Done proof

- Storage: a framework test_changed run with TMPDIR under the new root shows `df -T` btrfs for its run root and the akrogon.slice `memory.stat` shmem does not grow with its temp writes, while the same run on /tmp does; Chromium A/B: the deploy-core gate-wiring lane (the original hang site) 3× on each root, p95 wall time and zero hangs on disk required to keep the move.
- Collector: in a scratch leaf, plant (a) a dead-owner run root, (b) an unreferenced top-level tree, (c) a tree held open by a live sleeper process in the slice; one reconcile pass removes (a), marks but keeps (b) on first sight and removes it on the second, and never touches (c); a detached run-check's `akrogon-io-*/out` (created per `src/shell.ts:34`) survives a concurrent redispatch.
- Producers: after a full framework test_changed, the leaf temp root contains no new top-level entries beyond the run root that run-check removes; repeated runs show flat `du` for the root.
- Soak: one normal day at max_active 12 with `du` on the new root and slice shmem sampled morning/evening; disk root growth bounded by live leaves' working sets, shmem no longer tracking temp volume.

**Recommendation: disk root at `/var/tmp/akr-<uid>`, ownership cleanup first (tests and run-check already delete their own), reconcile extended into a dead-owner-only collector with a two-pass rule for unowned top-level scratch, age-based tmp-sweep only as the 7-day backstop — land A's change with the sweep-name fix, and do not build a standalone GC daemon.**
