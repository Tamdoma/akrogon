# Temp GC rebuttal, slot D

No misstatement of D's file in G1 to G6 or K1.

- **K2 deletes live browser profiles.** Its liveness test is "no process in that leaf's slice references it". Test Chrome and Chromium start in their own `app-*.scope` units outside the caller's cgroup (`learnings/LESSONS.md:33`, `learnings/history/2026-10-13-chrome-escapes-cgroup.md`, evidence from `coredumpctl -F COREDUMP_CGROUP`). The bus cut that keeps Chrome inside applies only within `run-check` (`src/run-check.ts:56`); seats got their bus back in `4e2752c`. So a bare seat run's `page-measure-*` or `playwright_chromiumdev_profile` dir is held by a process K2 cannot see, and two one-minute passes delete it under a running browser. Age-based K1 cannot do this because a live profile is written continuously.
- **K2's reference test has a second blind spot: idle handles.** A test that `mkdtemp`s a scratch repo and spawns `git` per step holds no fd, no cwd and no cmdline reference between spawns, and the entry is not in any process env (env carries the leaf dir, not the entry). Two consecutive passes a minute apart can both land in such a gap for a slow suite. Scanning `cwd`, `fd/*` and `environ` of every slice process (967 processes at 07:35, overnight-C Q1) every minute is also the heaviest read in the system for the least certain answer.
- **"One-minute cadence" is new machinery the merge does not count.** Reconcile runs only inside `next` passes (`src/next.ts:1581-1600`); no akrogon timer exists (`systemctl --user list-timers` shows none, `systemd/` has no `OnCalendar`). K2 on one minute needs a timer unit plus a reconcile entry that is safe to run every minute concurrently with hook-driven `next`. K1 reuses the timer that already exists (`tmp-sweep.timer`, hourly at `:15`).
- **A's lean inverts the 10-01 ownership decision without new evidence.** leaf-temp Q3 Taken: expiry lives in the operator's `tmp-sweep`, "no akrogon code", and an akrogon-owned sweep was foreclosed. The merge keeps the age sweep only as a "multi-day backstop", which is exactly the configuration that let `/tmp/akr-<uid>` pile up (skipped at `tmp-sweep:15`). The fix is the age, two hours not seven days, not a second collector with a weaker liveness signal than mtime.
