# Temp GC rebuttal C (disagreement only)

- R1 A's lean changes K2's safety case, it does not merely run it more often. Two unreferenced sightings one minute apart do not prove a top-level tree is dead: a test can create its scratch root at module scope, hold only the path in memory while other cases run, and use it minutes later (framework `.claude/hooks/tests/batch-lane-fixtures.test.ts:27` creates `scratch` at load; subprocesses use it as cwd only when a case runs, :34). In that interval no cwd/fd/cmdline necessarily names the entry. My K2 text had the same latent gap at next-pass cadence (`slots/temp-gc-C.md:18`), but a guaranteed one-minute cadence makes hitting it likely instead of incidental. The rule needs both sightings **and** a minimum first-seen age — or creator/generation death — before deletion; pass count alone is not a lifetime proof.
- R2 The lean also imports K3's machinery without naming it. Reconcile runs inside `next` dispatch passes (`src/next.ts:1583-1614`), after self-update and dispatch work; nothing in akrogon invokes it every minute. Getting a one-minute cadence therefore needs a new timer/oneshot verb (K3's vehicle), not "K2 on a cadence", and it must not be implemented by timer-driving `akrogon next`, whose other effects are dispatch and self-update. If the operator wants that cadence, cost it as the timer build B scoped, with R1's time floor added.
- R3 G6/A's lean treat tmp-sweep as the backstop, but no leaf in either option owns updating it: it is the operator's `~/.local/bin/tmp-sweep`, whose /var/tmp loop still names only `/var/tmp/akrogon-$(id -u)/*` today. Until that file learns `akr-<uid>`, the new root has only OS 30-day ageing behind the collector, so "tmp-sweep as backstop" is an unowned operator step, not a shipped property of the change.
