# peer-ask review, slot D

Reviewed `peer-ask-diff.patch` in the wt-ask worktree. `tsc --noEmit` clean, prettier clean. `bun test tests/peer-wait.test.ts` fails the same two grace-period tests on main and on the worktree under bun's 5 s default (they need the configured `--timeout=30000`), so not caused by this change.

- **Fix. A signal-killed `herdr agent prompt` exits 0 with no outcome line.** `peer-ask.ts:23-26`: `prompt.exitCode` is `number | null` (`bun-types/bun.d.ts:7965`); when herdr dies by signal (the 5 s `--timeout` path on a wedged pane, or SIGTERM from the harness tool timeout) `exitCode` is `null`, `null !== 0` enters the branch, and `process.exit(null)` exits 0. A then reads a zero exit as success with neither a JSON outcome nor a return file, and the rule "A ends its turn only for ... a non-zero script exit" never fires. The wait that the change exists to guarantee was skipped silently. Exit with a fixed non-zero code when `exitCode` is `null`.

- **Fix. The parallel form hides a failed prompt.** `questions.md:46` now says "peers prompted in one step run one peer-ask each in parallel within a single foreground command" and gives no command. The only single foreground shape is `bun peer-ask.ts B ... & bun peer-ask.ts C ... & wait`, and bare `wait` returns 0 whatever the jobs returned. Concrete: C's `herdr agent prompt` fails `agent_blocked`, `peer-ask.ts:25` exits 1, B finishes `done`, `wait` exits 0, A reads B's file, C's brief is never answered and the "non-zero script exit" rule has nothing to key on. Either prescribe the shape with per-job status capture (`wait $pidB; wait $pidC`) or have one peer-ask call take several `<pane> <return-file>` pairs and exit non-zero if any prompt failed.

- **Fix. No test for the new script.** `tests/fake-herdr.ts:229` already implements `agent prompt` with `promptScript`, so the three contracts peer-ask adds (prompt failure exits non-zero before any `agent wait` call, existing return file refused, prompt then wait in one process) are provable with the `setup()` fixture in `tests/peer-wait.test.ts:20-49`. The diff adds none, and the null-exit defect above is exactly what the first test would have caught.

- **Nit. `parseBudget` exits the process from a library function** (`peer-wait.ts:142-149`). Harmless today because both callers are CLIs, but it makes the function untestable in-process and inconsistent with `waitForReturn`, which throws. Throw and let `main`'s catch print.
