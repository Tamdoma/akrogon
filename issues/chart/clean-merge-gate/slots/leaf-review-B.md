- F1: **Cleaning dirty worktrees is a mechanism change, not a restatement.** `issues/chart/clean-merge-gate/forks/gate-tree.md:21-22` permits `git clean -fd` only after a clean-status check. `clean/brief.md:4,12` removes folders regardless of dirty state, and `clean/design.md:11` substitutes a selective filesystem operation. That changes both the mutation boundary and mechanism. Solo B's outstanding-work contract (`origin/main:skills/merge-issue/SKILL.md:51`; `src/batch.ts:123-124`) explains why the chosen rule needs correction, but does not authorize the correction. Fix: obtain an explicit answer approving selective removal in dirty worktrees, or preserve the clean-status condition and settle how solo B cleans after committing.

- F2: **The proposed dry-run selection cannot meet the at-any-depth criterion.** `clean/design.md:11` selects folder entries listed by `git clean -nd` and rejects those containing files. Git may list an entire untracked parent directory containing a file and an empty child. Rejecting that parent does not discover its empty child, although `clean/brief.md:4,10` requires removing empty folders at any depth. Fix: after the mechanism decision, define traversal that finds eligible empty descendants while preserving files, ignored paths and repository boundaries. Include the concrete case `untracked-parent/keep.txt` plus `untracked-parent/empty-child/`. Do not claim that filtering Git's parent entries supplies the required traversal.

- F3: **The cleanup Why states an unproved historical cause as fact.** `clean/brief.md:7` says the old leaf passed because those folders existed in its long-lived worktree. The original intake explicitly says that removed worktree was not inspected (`issues/seeds/63-merge-gate-passed-in-the-leaf-worktree.md`, Suspected cause), and `gate-tree.md:11` records the disagreement. Framework `264cc2f5b` proves the missing-directory dependency and its fix, not the old run's exact filesystem or executed test path. Fix: state the confirmed fixture defect and that leftover directories could hide it, preserving the historical evidence limit.

- F4: **Persisted PSI baselines can become invalid across a reboot.** `pressure/brief.md:4,10-12` requires non-negative differences and specifies omission only for old batches or absent PSI. Baselines persist on the batch (`pressure/design.md:22-23`; `origin/main:src/state.ts:42-58`). A resumed batch after reboot can have counters greater than the new boot's counters. Subtraction becomes negative, while clamping to zero would fabricate a valid measurement. Fix: specify a detectable invalid-baseline rule, its visible disposition and a same-boot measurement condition. Add a counter-decrease case. Do not leave the implementer to invent silent clamping or a permanent merge blocker.

- F5: **A new PSI read can fail after the push has already succeeded.** `pressure/brief.md:4` puts end reads inside appendAttempt. `origin/main:src/phase.ts:479-481` calls it after successful push, before state/completion moves. The draft covers absent PSI but does not define unreadable, malformed or partially available resource files. Throwing there can leave a pushed attempt without its record or completed state. Fix: decide and document how telemetry acquisition failures preserve merge bookkeeping while surfacing the error, or move acquisition before the irreversible operation with an explicit failure policy. Specify the same policy for start reads. The implementer must not invent a catch-all success-shaped fallback.
