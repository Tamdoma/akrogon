# Blind notes C: fork equality-rule (chart sync-identical-ignored)

## 1. Pick

Keep the guard in shared `integrate` (`src/sync.ts`) and add one narrow exception inside its existing collision filter. An ignored path stops being a collision only when all of these hold:

1. The path matches an incoming-tree entry exactly. Ancestor and descendant shape collisions never qualify.
2. The path is not in the replayed set (`git log incoming..HEAD --name-only`) and is not a directory of any incoming or replayed path. A replayed path's final and intermediate content is not the incoming blob, so no pre-move comparison against incoming proves the replay safe.
3. Same type and mode: the incoming `ls-tree` entry is a blob, and local `lstat` gives the same git mode, meaning regular file 100644 or 100755 by the owner executable bit, or symlink 120000. Directory, gitlink, fifo and every other local type refuse.
4. Same blob: for a regular file, `git hash-object -- <path>` equals the incoming blob id, which is the comparison `moveCheckout` already uses for equal colliders. For a symlink, the readlink target hashed as a blob (`git hash-object --stdin`) equals the incoming blob id. Never run `hash-object` on a symlink path, because it follows the link.

Any failed or erroring check (missing file, unreadable file, filter error, unparseable tree entry) stays a collision, so the current refusal error and message keep covering every non-identical case.

Reason: `integrate` is the only point that runs before both destructive moves, `syncCommand`'s `git rebase --autostash` in the operator checkout and self-update's `moveCheckout` (`git read-tree -m -u`). Both engines silently overwrite a differing ignored file, so the guard cannot move into either engine's failure handling. The exact-match, type-and-mode, blob-equal rule proves the move writes what is already on disk in git's own terms, and it reuses the one equality primitive the codebase already has instead of adding a second definition of "same content".

Cost: `integrate` needs the incoming entry's mode and blob id per exact-match candidate (per-candidate `ls-tree` lookup, only for ignored paths that already collide, 28 in the reported case), plus an `lstat` per candidate. `hash-object` applies the path's clean filters, so "identical" means identical blob after the repo's own text and filter rules, not raw bytes in all cases.

## 2. Rejected options

- **Remove the ignored check from `integrate`, rely on self-update's `moveCheckout`, add a sync-only comparator.** `moveCheckout` does not protect ignored files at all: its `read-tree -m -u` succeeds silently over a differing ignored file so its equal-collider fallback never runs, and that fallback's dirty set (`ls-files --others --exclude-standard`, no `--ignored`) excludes ignored paths anyway. This option needs a new guard in self-update plus a second one in sync, which is the duplication the carry warns against.
- **Per-route comparators with the shared check deleted or kept.** Two equality definitions that can drift, and self-update's route runs `moveCheckout` in `integrate`'s `after` hook, after the push, which is too late to refuse with the current error shape.
- **Raw byte equality instead of blob equality.** Stricter than git: a CRLF file under a `text` attribute that git considers unmodified would still refuse. It also needs new byte plumbing, because the shell helpers move strings (`stdout` read as utf8, `stdin` a string), or in-process blob hashing with object-format detection. New mechanism to reject files git itself calls identical.
- **Blob equality without the mode check.** Same bytes with local 644 against incoming 100755 hash equal, and the move silently chmods the file. The destination says refuse when mode differs.
- **Blob equality without the type check, using `hash-object` on whatever is there.** `hash-object` follows symlinks, so a symlink to a file with matching content would pass as a regular file and be replaced by one. Type loss is exactly what the destination refuses.
- **Extending the exception to replayed paths by comparing against HEAD or another final tree.** Replay passes through intermediate commits. The existing replay tests track a path and then remove it, so a file equal to the intermediate blob is still deleted by the later replayed removal. No single comparison proves that safe.
- **Deleting the identical ignored files in `integrate` and letting the move recreate them.** Same outcome as the exception, plus akrogon itself deleting operator files. The move engines already overwrite identical files cleanly, so the delete adds a destructive step for nothing.
- **Regular files only, symlinks always refuse.** Smaller, and covers the reported case, but the destination's type wording covers a same-target symlink, and the `lstat` branch needed for the type check makes the symlink case one comparison more. Cuttable if leaf scope needs trimming, at the price of one false-refusal class.

## 4. Pitfalls

- **Replayed local commits.** The exception compares against the incoming blob, but a replayed commit can overwrite or delete the path after the incoming step. Removed by excluding every replayed path and every path that is a directory of an incoming or replayed path from the exception, keeping today's refusal there.
- **Symlink passed to `hash-object`.** It follows the link, so a symlink can pass as a regular file or crash the comparison. Removed by `lstat` first, and comparing the readlink target as blob content only when the incoming mode is 120000.
- **Mode-only difference.** Hash equality ignores the executable bit, and both engines silently apply the incoming mode. Removed by requiring the `lstat`-derived git mode to equal the incoming `ls-tree` mode. Under `core.fileMode=false` this can false-refuse, which fails safe.
- **Filters and line endings.** `hash-object` runs the path's clean filter, so raw bytes that differ only by CRLF or filter expansion count as identical, and checkout may write the canonical form. Removed as a surprise by stating the rule as blob equality in the leaf, since the repo's own attributes define that equivalence. Not removed as raw-byte preservation, and a lossy custom clean filter remains the one case where blob-equal files can hold different raw bytes.
- **Special and non-blob types.** A directory, fifo, device or submodule gitlink at the path, or a tree or gitlink in incoming, has no blob comparison. Removed by qualifying only blob entries against regular-file or symlink local types and refusing everything else.
- **Race between check and move.** The ignored file can change after hashing and before the rebase or read-tree overwrites it, under the same global lock the guard already runs in. Not removed by this rule, and not widened much, since a file created after the ignored listing has the same exposure today. Removing it would need the move itself to compare, which neither git engine does for ignored paths.
- **Vanished or unreadable candidate, failing filter.** Any error while stating, hashing or looking up the tree entry must not crash sync with a new error shape or pass the path. Removed by treating every lookup or comparison failure as a collision under the existing refusal.
- **Binary content through string helpers.** Comparing file bytes through `command` stdout or string stdin would corrupt non-utf8 files. Removed by comparing blob ids only, which are hex strings, and testing with a binary identical file.
- **Path quoting.** Existing tests use a collision path with brackets, a glob star and a newline. Removed by keeping `-z` listings and literal pathspecs for the per-candidate lookup, and keeping that existing test path in the new identical test.

## 5. Questions the fork does not ask

- Q1: Should a successful move print the adopted paths? The ignored local copies silently become tracked files. The destination says move, but nothing about telling the operator which local paths were adopted.
- Q2: Is the non-ignored untracked identical file in scope another day? Git refuses that move itself even when bytes match, so `akrogon sync` still fails there with a git error instead of moving. Same operator symptom, different owner, currently outside the destination.
- Q3: Does `moveCheckout`'s existing equal-collider fallback need the same type and mode gate? It compares hashes with no `lstat`, and fails closed on symlinks only because `hash-object` errors or mismatches. Touching it widens this leaf, but after this change the codebase holds one strict equality in `integrate` and one loose one in `moveCheckout`.
