# Leaf review C: identical-ignored (disagreements only)

- Missing criterion for an equal path that is also a shape collision through replayed paths. The brief's exemption conditions are exact incoming entry plus "no replayed local commit touches it", and design.md Leaf architecture repeats that pair, while the Settled paragraph also says ancestor and descendant shape collisions keep the refusal. No criterion pins the overlap of the two rules, in either direction: ignored `collision` equal to an incoming tracked `collision`, with a replayed add-then-remove of `collision/file` (the candidate is a directory of a replayed path and is not itself in the replayed name set); and ignored `collision/file` equal to incoming, with a replayed add-then-remove of `collision` (a replayed ancestor). An implementation that exempts on exact-plus-not-replayed alone, dropping the directories and ancestor checks for exempted candidates, passes all four done-criteria as written, then hits a mid-rebase conflict on those inputs instead of the pre-move refusal with an unchanged checkout, which is the settled behavior. Evidence: both rows already exist in the replay half of the ignored-collision matrix in `tests/sync.test.ts` at HEAD (`['collision', 'collision/file']` and `['collision/file', 'collision']`, replay source tracking then removing the tracked path in local commits); they become this case by also tracking the ignored path in incoming with equal bytes, type and mode, which no existing or proposed criterion does. Criterion 3 covers a replayed commit touching the exact path only, so it does not catch this.
