- R1. The replay exclusion needs to cover path overlap, not just membership in the replayed set. `design.md:29` grants the exemption to an exact incoming entry “not in the replayed set”, while criterion 3 only names a commit touching “that path”. Example: incoming tracks `collision/file`, the ignored local `collision/file` matches it exactly, and local commits add then remove a regular file at `collision`. The incoming leaf is not a member of the replayed set, but replay touches its ancestor. The current guard checks every ancestor against the union of incoming and replayed paths (`src/sync.ts:105–120`), and the design's settled decisions require ancestor/descendant collisions to retain that refusal. Make the exemption explicitly conditional on no exact, ancestor or descendant replay overlap, and give this equal-incoming/replayed-ancestor case a done-criterion. The retained replay shape tests have no equal incoming entry, so they cannot catch an exemption that bypasses this protection. Standing design requires a criterion for a new consequential edge-case test.

- R2. Criterion 1's unconditional “bytes are unchanged” promise is stronger than the selected comparison and unchanged Git move commands can establish. Example: incoming blob and ignored regular file both contain LF bytes, with matching mode, no replay overlap, and an applicable `text eol=crlf` attribute. The raw hash matches, so the specified guard permits the move, but Git can materialize CRLF bytes during checkout. Git documents both checkout line-ending conversion and smudge filters that replace blob bytes in the worktree ([gitattributes](https://git-scm.com/docs/gitattributes), checked 2026-10-19). B's original notes already recorded this distinction under R3: raw equality proves equality with the committed blob, not unchanged worktree representation after checkout. This is separate from the acknowledged concurrent-writer limitation. Resolve the contract before handoff: either explicitly limit the unchanged-byte guarantee to cases without checkout transformations, while recording normal Git transformations as a limitation, or obtain a decision covering transformed output. The implementer should not silently add filter handling or switch to filtered equality, which the binding decision forecloses.
