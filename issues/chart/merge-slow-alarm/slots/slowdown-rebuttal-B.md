# Slot B rebuttal

- **F1. Q1 applies the reference-cohort exclusions too broadly to the run being evaluated.** Excluding reused or blocked runs from the normal avoids cheap reference samples. Excluding them from detection can miss real merge cost. `runOnce` can reuse one green command while freshly running another expensive member. It can also spend a long time in a failing sequential stage and then mark later members blocked. Both runs consumed wall time, but the proposed rule makes them invisible to the alarm. Separate reference eligibility from evaluation eligibility. Evaluate a completed head's measured duration against the established reference even when its workload is partial, and label that distinction. **Evidence tier: better-than-training**, `src/verify.ts:runOnce`, `reuseSource`; **model-knowledge**, consequences of those execution paths. My original exclusion recommendation concerned the normal cohort, not a blanket exemption from evaluation.

- **F2. Q2's proposed middle does not yet preserve an unresolved slowdown.** Storing a comparison and first-run ID on flagged records preserves historical evidence, but does not stop the rolling median from absorbing the increase. With twenty roughly 6-minute samples followed by eleven roughly 21-minute samples, the next comparison's median is roughly 21 minutes. That run is no longer flagged, and Q4's latest-run status condition clears even though the slowdown never recovered. An active episode must keep using its pre-jump reference, or another explicitly chosen recovery rule must prevent this false clearing. This can still be derived from receipt history without a new file. **Evidence tier: model-knowledge**, direct calculation using Q1's last-20 median and Q4's visibility condition; **better-than-training**, the sustained step recorded in framework history already inspected for the opening map. Historical origin storage alone does not satisfy the persistence concern attributed to B.

- **F3. Q2's “notice fires once at episode start” loses failed deliveries.** Q4 stores notification failure, but no later event is specified to retry it. If the first send fails, the entire plateau can remain unannounced. Reserve and record delivery separately from detection, and let a later completed merge run retry an undelivered episode without creating another episode. **Evidence tier: better-than-training**, `src/verify.ts:noticeCovers`, `newRedUnits`, `sendMainRedNotice`: the existing main-red mechanism deliberately treats `error` and dead-process reservations as uncovered so a later observation can retry. This needs no new watcher.

- **F4. Q4's status proposal does not establish merge-seat visibility.** A readable status line is useful, but the notes supply no step that makes the merge seat read it. `broadcastPass` dispatches B with completion-owner context, while command-owned land can finish without B observing verify output. A watch/operator read is not evidence of a merge-seat read. Specify how the warning reaches B's existing handoff or pass, or require and prove a status read there. Also retain the first affected run/leaf on that surface while the episode remains unresolved, rather than showing only the latest run's flag. **Evidence tier: better-than-training**, `src/next.ts:broadcastPass`, `landedWake`, `src/land.ts:land`; **model-knowledge**, the missing delivery step in the proposed flow.

- **F5. “Host load false alarms: harmless because the flag never fails a merge” understates the consequence.** Nonblocking false alarms still consume operator attention and can make repeated warnings less useful. Recorded duration includes checkout/setup and admission waits, so a warning cannot distinguish code cost from host contention by itself. Accept false positives explicitly, show measured/reference durations, and keep “first seen at” attribution. Do not claim that leaving merge success unchanged removes the alert-quality tradeoff. **Evidence tier: better-than-training**, `src/verify.ts:runOnce` starts its receipt before checkout and awaits `checkedRun`; `src/run-check.ts:checkedRun` awaits admission; **model-knowledge**, operator-attention consequence of false alarms.
