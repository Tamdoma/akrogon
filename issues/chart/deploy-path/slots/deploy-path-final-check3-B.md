F1 Setup is not serialized with updates. shape3:10 releases the global lock before installation/link reconciliation (:11). Two triggers can therefore run bun install concurrently, or a second pull can change package.json/bun.lock while the first install is running. The first can then report `deployed old..new` for a revision whose setup was overtaken. Existing configured setup already uses the shared Git `akrogon-install.lock` (src/config.ts:256-260), which this shape does not include. Bind serialization across pull, install and link reconciliation, coordinated with that existing setup lock, and report the revision actually reconciled. Keeping the global lifecycle lock released during installation is fine, but it needs a separate update/setup lock covering the whole sequence with a defined lock order.
