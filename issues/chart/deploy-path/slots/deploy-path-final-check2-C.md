# deploy-path focused check 2, slot C

Defects in shape 2, with evidence at HEAD (root at origin/main, f3199df).

D1. Item 7 is wrong: plugin events do not run an akrogon pass. plugins.json events are `next.sh` with no `--all`. A hooked `next` with no input selects work by the hook pane's owning leaf (src/next.ts:1518-1521, `paneOwners`) and returns when no leaf owns the pane (`if (owners.length === 0) return;`, :1521); a `tab_closed` event does the same by tab (:1495-1498); a status change to `working` returns before anything (:1437). So a framework seat event touches framework only, and the chart door's pane (direct route, no leaf) touches nothing. Only startup `next --all` / `--resume` (:1466-1472, :1478-1493) and a manual `akrogon next --all` or `next` from the akrogon root reach the akrogon repo when no akrogon leaf is active. Consequence for item 6: lifecycle akrogon merges are covered (mergeWake runs mergePass for the landed repo, :1287-1296, whose mergeTurn fetches at :1028), but direct-route pushes, by-ancestry completions with no live akrogon seat, and other-machine landings are deployed only at herdr startup or by hand. Fix inside 1c: run the akrogon self-pull step in every hooked `next`, before the pane/tab selection returns, keyed on the toolRoot identity rather than on `touched`. It is one fetch of one repo per event, and the early `working` return at :1437 can stay.

D2. Item 2 "re-run install's skill-link routine" has no separable routine. `install()` (src/install.ts:9-53) computes links, throws on conflict (:42-44), creates links, then runs `herdr integration install <kind>` for every harness and `herdr plugin link` (:51-52). Called from `next` as written it would throw out of the pass (contradicting item 3) and re-run two herdr commands on every pull. The leaf must split the link step out and catch its conflict error into the printed line.

D3. Item 1's fetch does not exist on every akrogon pass. The "existing fetch" at :882 runs only inside `reconcileBatch` for a leaf with a batch record, and :1028 inside `mergeTurn` after the reconcile loop; `mergeTurn` runs from `mergePass` only for touched repos (:1560). With D1 fixed, the self-pull step needs its own `git fetch <remote>` rather than relying on a prior fetch, or the ancestor test compares against a stale tracking ref and skips.

D4. Item 5 lock scope. `bun install --frozen-lockfile` under the global `.lock` (same lock as every `phase`, `pause`, `park` call, next.ts:1448, pause.ts:49, park.ts:51) blocks every seat command for the install's duration on each pull that moved HEAD. Cheap when unchanged (a few hundred ms) but not free on a lockfile change. Acceptable, but say it; or hold the lock for the pull and release it before the install, since the install only touches node_modules.
