# Slot B disagreements: deploy-path

Read only deploy-path-merged.md in this pass. Evidence citations below refer to code inspected in the preceding blind-notes pass, origin/main at 2d9beca unless labelled local.

- F1 Immediate switching is not established safe by atomic release directories (merged:5,15). An immutable resolved source root can preserve one command process's imports. It does not pin a seat's later skill reads or subsequent `akrogon` invocations. Dispatch passes a skill name and reuses existing sessions (src/next.ts:552-564,573-589). Plugin scripts invoke the global command by name (plugin/next.sh:3, plugin/pull.sh:3). A seat can therefore retain old instructions, read a new subroutine, and finish with a new phase command. The cited deployment pattern addresses file activation, not this agent contract lifetime. Keep immediate switching as an option needing proof of these boundaries. My recommendation remains completed-pass drain plus fresh sessions, or explicit version pinning if the operator rejects drain delay. Do not present “without a drain” as already proven.

- F2 Additive-optional state fields do not establish old/new writer or rollback compatibility (merged:15,25). The local old command increments fix_rounds only on check.repair -> check.fix (local src/phase.ts:151), while today's delivered merge-throughput contract requires every merge bounce to count (issues/chart/merge-throughput/CHART.md:9). Those are different semantics even if both commands parse the same YAML. Old seats may also carry instructions predating new attempt/hold rules (origin/main skills/merge-issue/SKILL.md:35-37,65). Required proof covers schema acceptance, preservation of new fields, transition authorization and counter/hold semantics across both versions. A rollback pointer cannot undo completed transitions. Replace the blanket additive-optional guarantee with a demonstrated compatibility requirement and a stop/recovery decision when it fails.
