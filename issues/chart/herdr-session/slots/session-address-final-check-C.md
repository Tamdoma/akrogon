# Final-shape check, seat C: session-address

Defects and missing pieces only, checked as an implementer against current source, 2026-10-24.

- D1. 2c's opening sentence and its parenthetical disagree on scope, and an implementer must guess. The sentence conditions all stored-id use on "tab label equals the slug or a member pane cwd is inside the leaf worktree"; the parenthetical names only `src/next.ts:395` and `:383`. Applied literally everywhere, the condition breaks two consumers: phase renames the tab to `<slug> failed` (`src/phase.ts:108`) and renames it back on recovery (`src/phase.ts:162`), so the label is not the slug at exactly the moments phase must use the id; reconcile's `tabLive` (`src/reconcile.ts:255`) is a keep-veto, and adding label/cwd corroboration to it weakens the veto (a live tab whose pane cd'd out of the worktree reads dead, then slice stop and worktree removal follow). The record needs two named classes: consumers that get session-scoping only, and consumers that also get corroboration. Unclassified today: dispatch `pane get` (`src/next.ts:584`), phase rename, reconcile tab closes (`src/reconcile.ts:387,720`).

- D2. The `tab_closed` owner match cannot satisfy 2c as written and the shape is silent on it. Owners are matched by `state.tab === event.data.tab_id` with no other arm (`src/next.ts:1432-1435`), and the closed tab no longer exists, so there is no label or member cwd left to corroborate. Either record event-session scoping for this route now, or record an explicit deferral to cross-session-reads. As written, this consumer either violates the recorded rule or the implementer invents the exception.

- D3. The 2c guard has no stated key for "inside the leaf worktree" on a first allocation, and no rule for unknown pane cwd. The existing helper `inWorktree` tests against recorded `leaf.state.worktree`, which is undefined until `ensureWorktree` saves it; a guard built on it before that point matches nothing and silently passes. The record should state the guard runs on the path `ensureWorktree` returns (allocate already computes that expected path for its match at `src/next.ts:390-402`). Pane cwd is nullable in the schema (`src/shell.ts` paneSchema) and `inWorktree` returns false for null, so a foreign live pane with unknown cwd is invisible to the guard; the worktree criterion claims detection without saying whether unknown cwd passes or refuses.

- D4. "Outside the repo's workspace" is not decidable from the pane list the shape names. Panes carry `tab_id` only; workspace membership lives on tabs (`workspace_id`, optional in `src/shell.ts` tabSchema). The guard as recorded ("list panes in every running session") cannot tell a same-session pane in a different workspace from one in the repo's workspace. The record needs the per-session tabs join (pane to tab to workspace) and a statement that same-session, other-workspace counts as outside.

- D5. The resolution point dropped out between the merged notes and this shape. Q3 says resolve once per repo per invocation but never says when. Allocate's first stored-id uses — recorded-pane filter and scope close (`src/next.ts:373-383`) and the tab list (`:388`) — run before today's workspace lookup at `:407`. An implementer who resolves where the lookup sits now keeps the original defect for those calls. The record should state resolution happens before the first pane or tab list in allocate, and by the same rule in the other entry paths that reach stored ids without allocate (hook ownership, reconcile, phase, land's wake).

- D6. The Himne fix names no session and rests on unproven label casing. "Creation of a workspace labelled Himne" does not say in which session the operator creates it, and exact match then ties Himne work to that session permanently; the record should name the session or state the operator chooses it at creation. Whether herdr preserves the capital H in a workspace label is unproven (`herdr workspace create --help` today shows `--label <TEXT>` with no case statement). Cheap to settle at creation: the created session's `workspace list` must show label exactly `Himne`, and that belongs in the record as the check.
