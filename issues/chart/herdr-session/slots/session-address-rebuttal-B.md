# Seat B disagreement-only rebuttal

1. “Derive self-heals and the old session's objects are new/unrelated” is not established. A workspace label moving to Y does not prove the leaf's seat in X exited. The report describes live work in the wrong session. Allocation's label+cwd alternative also does not validate its stored-ID arm: `src/next.ts:393-398` accepts `tab.tab_id === leaf.state.tab` independently of cwd, and `src/next.ts:373-383` can close a recorded pane before tab matching. Removing these unsafe arms is necessary but does not prevent a second paid seat when X still runs the first. I retain the saved-session recommendation. A derive-only design must instead specify how it proves unique existing ownership across sessions before replacement and how it handles an unavailable possible owner. “Re-match repairs moves” cannot stand as the proof.

2. Matching an inherited socket to session-list paths proves which server that socket names, not which server emitted a hook. The intake's failure input is a valid socket inherited from the wrong process. C's proposal may work for a hook launched directly by the emitting server, but that boundary needs a real provenance proof before it can replace recorded session qualification for closed-tab ownership (`src/next.ts:1429-1435`). Do not generalize a directly injected hook environment's authority to arbitrary background jobs or inherited HERDR_PANE_ID. This remains a cross-session-reads dependency of the derive-only pick.
