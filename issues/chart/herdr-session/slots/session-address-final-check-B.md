1. Q2's corroboration is too weak. A slug label alone cannot authorize reuse or recorded-pane closure. The existing alternative requires both slug label and a member cwd inside the expected worktree (`src/next.ts:393-398`); changing that to either condition admits unrelated same-label tabs. Require the accepted tab to belong to the resolved workspace and have worktree ownership evidence, and require each recorded pane to belong to that accepted tab before it can be acted on. Session selection alone does not establish workspace ownership. Otherwise an existing tab outside the repo workspace can be reused without ever reaching the before-create guard.

2. The proposed guard does not yet cover all earlier consumers. `dispatchLeaf` observes stored pane IDs before allocation (`src/next.ts:719-723`), `ownsPane` accepts a recorded ID independently of cwd (`src/next.ts:159-160`), and closed-tab ownership uses bare IDs (`src/next.ts:1429-1435`). State explicitly that corroboration applies before every stored-ID use, not just allocate's two named arms. For a closed tab, the contract must specify proven emitting-session origin and owner qualification because no live member cwd remains. These details can be settled in cross-session-reads, but must remain explicit prerequisites rather than implying Q2 already makes those paths safe.
