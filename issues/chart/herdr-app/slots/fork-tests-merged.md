## Corrections (A, 2026-11-07, from C,E probes)
- A real throwaway core is cheap: `hc server start`, `hc run --bg`, `hc server stop` about 13 ms each in a scratch session (C,E; B confirmed isolation and cleanup). The core is a plain child of the starting shell, no systemd unit (C).
- A stand-in program gets real status and turns: hc reads status only from OSC 7501 (`\e]7501;state=working\e\\`, fields `state`, `kind`, `msg`, `progress`, `id`; herdr-core `crates/herdr-core/src/status.rs:45-57`), and a shell script printing it got `reported: true`, `turn: 1`, and `blocked` with `kind=question` (C,E). A's pitfall "a stand-in cannot prove turn-based delivery" is wrong.
- Traps found: any `hc` command, even `hc server status`, starts a new core after a stop, so absence cannot be checked by calling hc (B,C,D); the socket path must fit 107 bytes (C); hc panics on a closed stdout pipe (C); `doc.get` on a fresh core returns `{value: null, version: 0}` (D).
