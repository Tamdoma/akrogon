## Q1 Fakes

Pick: a real hc core per fixture, in place of `fake-herdr.ts`: `fixture()` starts `hc server start` with `HC_SESSION=ak<pid><n>` and scratch `XDG_RUNTIME_DIR`/`XDG_STATE_HOME` under the suite root, strips `HC_TERMINAL_*`/`HC_SCOPE`, and stops it on teardown; a stand-in agent program (today's `fake` harness in `tests/helpers.ts:65`, made a 30-line script) that emits 7501 `working` when a line arrives, does the scripted thing (write a file, `hc send $parent "done"`, block with `state=blocked:kind=permission`, exit, or stay silent), then emits `done`; and one small fake `herdr-app` with captured JSON for `ls`, `status`, `do tab.rename`, `do pane.focus` and the closed-window socket error, refusing any call a test did not plan (today's `fake-herdr.ts:524` rule). Reason: the port's risk is the hc contract itself (turn counters, `started`, events `seq`/`missed`, `wait` reasons, parent notes, `<hc>` wrapping, exit codes 3/7/9/10/11), and a fake would be a second copy of that state machine, drifting per hc release, while the real core costs 13 ms and is swept by `tests/isolation.ts`'s subreaper like any child. The window has no headless mode, so herdr-app stays a fake. Cost: tests need hc installed (`hc --version` ≥ 0.1.18 asserted once, failing clearly), and a few more ms per call than the bytecode fake.

Rejected: a strict fake `hc` with captured JSON (D-style): 500 lines again, the listener's only input (`hc events`) would be tested against a stream the fake invents, and captured JSON goes stale silently; a fake at the engine's hc module boundary: skips argv building, JSON parsing and the strict schema, which is where identity Q1's boundary test lives, and breaks today's pattern of driving the real binary path through `cli()`; real hc for everything including the window: no headless `herdr-app`.

Evidence: practitioner: libtmux's pytest plugin starts a real tmux server per test on its own socket (`Server(socket_name="libtmux_test<n>")`, killed and unlinked in teardown, 0.55.1 fix for leaked sockets; libtmux.readthedocs.io/pytest-plugin, github tmux-python/libtmux issue 661, read 2026-11-07); no source found for faking a multiplexer CLI. Live: probe above; `hc --skill:255-256` ("Tests need their own `HC_SESSION` and scratch XDG paths"); schema README Events table (herdrdev/herdr-core `schema/README.md`, lines 113-178); `tests/isolation.ts:1-60` (subreaper, scratch HOME, bundles), `tests/helpers.ts:132-150` (fake herdr fixture shape to replace), `tests/AREA.md` (real units already in `run-units`, `leaf-slices`).

Pitfalls: (a) 107-byte socket path: the fixture puts `XDG_RUNTIME_DIR` at `<suite root>/r` and asserts the length (design). (b) Teardown calls nothing after `hc server stop`; a test cut at the 30 s cap leaves a core that the subreaper sweep kills (design, existing). ## Q3 Porting

Pick: each leaf ports the tests of what it changes, and the engine leaf, first by 6a, also lands the shared substrate (fixture core start/stop, stand-in agent, fake herdr-app) because it is the first user and the substrate is small; the final sweep leaf, after the recorded tier-2 run, deletes `tests/fake-herdr.ts`, the herdr halves of `fake-proc.ts` and `helpers.ts`, `HERDR_PANE_ID` setups, `OBSERVE_HERDR` fixtures and the herdr fixtures under `skills/watch-issues/scripts/fixtures/`.
