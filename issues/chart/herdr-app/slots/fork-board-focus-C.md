## Q2 Shape

Pick: `agent.focus {terminal}`, as herdr-setup's board does (`mods/board/main.js:37`) and as herdr-app's own agent navigation does (`agent.next`/`agent.prev`/`agent.focus` are one family, AGENTS.md Commands). The producer adds per seat `address` (hc address, or null when the leaf records no live seat) and `session` (the hc session name the address lives in), and one `focus: "A" | "B" | null`: the seat named by the first attention fact when it names one (`A prompt <code>`, a delivery error, a failed seat), else `waits_on[0]`, else the busiest seat, else null. The board's row body runs `run("agent.focus", { terminal })` for that seat when the leaf's `session` is the window's own (read from `appHome()` as `session-status` does) and the address is non-null; otherwise it does what it does today, `pinFolder(row.folder, "files")`. No seat has a pane: `agent.focus` still shows the agent (sub-agents and parked terminals belong to their tab without a pane; the app shows them, `terminal.peek` style), which is the "jump to where the problem is read" the direction asks for; an ended or unrecorded seat has `address: null` and falls to Files. Reason: one command the app already uses for exactly this, the judgment of which seat lives in the producer next to `attention` and `waits_on` (3a), and the fallback keeps today's behavior so a click never does nothing. Cost: three JSON fields; the expanded row keeps its Files links (`main.js:286`), so the folder is one click further than today.

Rejected: `pane.focus {terminal}`: "prefers the first visible layout terminal block showing that address, then its model pane" and fails when none shows it (AGENTS.md Commands, Panes), so the no-pane case needs a second path; `agent.focus` has none. Board-side seat choice from raw facts: duplicates the producer's judgment in JavaScript and drifts from `attention` wording. Click does nothing when the seat has no pane or the session differs: a dead click on a problem row is worse than today's Files pin. Per-seat icon clicks: a new control the direction did not ask for; the one-row-one-jump rule keeps rows calm (1a, 2a).

Evidence: `herdr-app commands` (`agent.focus` args `terminal` required, about "Show an agent (sub-agents too)"; `pane.focus` args `pane | terminal`); AGENTS.md Model ("Sub-agents … belong to their parent's tab without a pane; the `agents` mod shows them, `terminal.peek` opens one, `terminal.keep` gives one a pane"); `herdr-setup/mods/session-status/main.js:8` (session from `appHome()`); identity Taken Q2 (address qualified by session in state; a report from an address no longer recorded is ignored). Practitioner (searched 2026-11-07): KanVibe (web kanban over tmux/zellij, a terminal page per task), dev-3.0 (hovering a card shows the live terminal), claude-code-kanban (observation only, click opens detail); none better than herdr-setup's own board, which is the local precedent and already uses `agent.focus`.

Pitfalls: (a) `agent.focus` on a terminal that reports no status (a backgrounded Claude, INTAKE "backgrounded door reports no status"): unknown whether the app treats it as an agent; probe before handoff with `herdr-app do agent.focus --terminal <bash terminal>` in a throwaway session, and if it refuses, the board uses `pane.focus {terminal}` for `status: null` seats, Files when that fails. (b) Addresses are per core: the `session` check removes a jump to the wrong window's `t15` (design). (c) The producer's `focus` must agree with the shown reason: the board test asserts the focused seat equals the seat named in `attention[0]` for every delivery-error and failed-seat fixture (leaf done-criterion). (d) `exec("akrogon", ["status", "--json"])` runs with the window's environment, where `HC_SESSION` may be unset for `default`: the producer resolves session by space name (identity Q1), so the field is filled either way (existing design).
