## Q1. Scope of the start-only code rule

Reason: removing deterministic dispatch would introduce a coordinating agent or a different execution model, contrary to the unchanged-workflow carry. 2. Rejected: applying the rule literally to every engine call. This is a valid reading of signpost 1a, but it cannot preserve today's engine by a transport substitution. An agent would have to perform actions the engine currently performs. That adds a recipient, permissions, turn scheduling and recovery responsibilities. Do not hide this change behind the name “port.”

4. Pitfalls and removals:

   - A second coordinator alongside the existing state machine. Removal: retain the existing phase/queue authority and delete old peer orchestration, rather than introducing another agent to duplicate it. Existing `src/phase.ts:408` already rejects repeated slot completion.

## Q2. Listener, installation and restart ownership

1. Pick: one systemd user listener per selected hc session, with its listener code, unit and installation/upgrade owned by akrogon. It subscribes to hc events and invokes the existing engine against explicit repo/session ownership. Crash handling wakes watch-issues instead of restarting agent tasks itself. Herdr-setup owns only substrate gaps proved missing, as the carry requires. Reason: listener and engine must upgrade together. Cost: a resident process, explicit core/socket environment, and a tested activation/reconnect sequence.
2. Rejected options:
   - App mod as sole listener: lifecycle would depend on window/layout lifetime. `~/.config/herdr-app/AGENTS.md`, **Mods**, says removing a copy ends its tasks, and layout changes can start fresh copies.
   - Herdr-setup owns akrogon's domain listener: splits engine deployment from its event adapter and permits incompatible versions. Keep generic core patches there, but keep akrogon routing with its engine.
   - One listener per repo: adds independent consumers and installation instances despite the existing host-wide engine lock. No inspected requirement needs that duplication.
   - No resident listener or a periodic polling replacement: contradicts the crash-listener/no-polling carries. Watch cron remains the existing separate workflow, not a substitute event bus.
3. Evidence:
   - Practitioner: Supervisor maintainers document event consumers becoming busy, retry after listener failure, and oldest-event loss when a listener buffer fills. This is concrete supervisor implementation experience, not an hc guarantee. [Events, notification protocol/error conditions](https://www.supervisord.org/events.html), read 2026-11-06. It supports proving failure/reconnect behavior before trusting a stream.
   - Better-than-training: installed `/usr/share/man/man5/systemd.service.5.gz`, **Restart=**, read 2026-11-06, recommends on-failure for long-running services and documents start-rate limits. This supports supervision of the listener process, not automatic replay of agent work. [Official manual](https://www.freedesktop.org/software/systemd/man/262/systemd.service.html#Restart=).
   - Better-than-training, inspected local surfaces: `plugin/herdr-plugin.toml:7` and :10 provide startup pull/resume. `src/install.ts:145` already reloads user systemd units. `src/self-update.ts:270` updates installation links and :278 reloads units. `systemd/akrogon.slice:1` is a slice, not an existing listener service. `hc events --help` advertises filtering, but no replay cursor.
   - Operator: `issues/chart/herdr-app/forks/engine-shape.md:13` requires crash detection plus watcher repair, and puts missing substrate capabilities in herdr-setup. That does not require moving akrogon's existing release responsibilities there.
4. Pitfalls and removals:
   - Events missed at startup or disconnect. Removal: subscribe before one catch-up pass, retain events arriving during that pass, and prove reconnect in an isolated core. Reuse resume's existing scope, which excludes never-started leaves (`src/next.ts:1697`, :1705). This is event-driven catch-up, not periodic polling. If current hc cannot support the required sequence, patch it in herdr-setup before promising it.
   - Concurrent or repeated wakes launch duplicate work. Removal: use the current global lock (`src/next.ts:1666`) and current phase/seat/delivery authority, then prove two overlapping completion events produce one task. The lock alone only serializes calls and does not prove duplicate suppression.
   - Self-update kills a listener's child while deployment is incomplete. Removal: activate/restart only after completed release installation and outside a protected mutation, with an upgrade-during-event done-criterion. Verify the resident process now uses the new release. A symlink flip or daemon-reload alone is insufficient.
   - A default-session listener acts in infra, or its restart kills seats. Removal: explicit HC_SESSION/socket routing, no inherited agent terminal identity, and a proof that listener restart preserves unrelated fixture seats. Leaf parenting is settled in lifetime, not guessed here.
5. Missing questions: who receives crash reports when the operator's watch agent is absent or blocked, and what makes that absence visible? Also distinguish one-time startup pull from reconnect catch-up. Reconnecting an event stream should not automatically become another repository update or agent-task retry.

## Q3. Success advancement

1. Pick: a turn-end/status event wakes ordinary next-seat dispatch, as today. The event is a readiness wake, never success evidence. Durable phase/slot completion authorizes progression, and explicit slot messages remain required communication. Keep the existing merge-specific wake. Do not add a second generic dispatcher inside phase. Reason: phase is called while its seat still works, including transitions that reuse that same seat. Cost: event loss must be covered by the Q2 reconnect/startup proof, and an incomplete turn does not advance simply because phase returned.
2. Rejected options:
   - Phase dispatches directly, listener handles crashes only: a plan-to-implement transition reuses A while A is still working. Current dispatch refuses that busy target. Supporting this choice needs deferred work or a later readiness wake, which restores the event path it claimed to remove.
   - Both generic direct dispatch and turn-end dispatch: adds two normal-success paths without a demonstrated need. It may wake B before A's final turn work finishes and requires cross-path duplicate suppression. Keep the existing narrow merge behavior rather than expanding it into all transitions.
3. Evidence:
   - Practitioner: the Supervisor event model separates process state-change notifications from application-specific communication events. [Event Types](https://www.supervisord.org/events.html#event-types), read 2026-11-06. Treating process readiness as separate from durable application success is my inference, not a claim that hc behaves identically.
   - Operator: `issues/chart/herdr-app/forks/engine-shape.md:14` requires explicit communication and unchanged workflow. A status transition cannot replace the requested report.
   - Better-than-training, inspected code: `src/routing.ts:35` and :36 assign both plan.synthesis and implement to A. `skills/plan-issue/SKILL.md:59` runs phase then prints its footer and stops. `src/next.ts:765` refuses busy targets. `src/phase.ts:223` saves the new phase before its caller's turn ends, and :207 clears prompt records for that new phase.
   - Better-than-training, inspected code: `src/akrogon.ts:96` wakes only merge work after a committed phase. `src/next.ts:1358` confirms mergeWake's scope. `src/next.ts:1608` ignores working-status hooks and :1755 handles the later terminal event. `observeBusy` at :231 clears busy records on idle, while :247's age threshold only drives a notice, not proof of completion.
4. Pitfalls and removals:
   - done/idle advances a leaf that never committed its required work. Removal: consult the existing phase/done/verdict state, not the status word. `src/phase.ts:444` already waits for every required slot. Preserve that authority and verify a no-phase turn does not advance.
   - A committed phase stalls on same-seat reuse. Removal: chart-time approved probe of plan.synthesis to implement in A, then implement to review, plus a leaf criterion covering the complete event-driven path and the unchanged merge wake. Test through the listener, not by manually running next afterward.
   - Questions, interruption or a replaced seat look like successful turn-end. Removal: route blocked/error/crash events to their existing watcher/human path, bind events/reports to the current terminal instance, and prove that a late report cannot advance its replacement. Do not infer a crash solely from long working status.
5. Missing question: where does the leaf's explicit hc completion message go when its dispatcher is a systemd program rather than a parent agent? Settle the report recipient and whether the report gates advancement before finalizing Q3. Do not quietly replace the own-report finish signal with hc status, or add a parser that demands exact prose.
