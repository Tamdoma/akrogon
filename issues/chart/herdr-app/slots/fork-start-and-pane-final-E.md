### Q2 + Q2b — `doc.set` "touching only that tab's name" cannot work when `herdr-app` is closed (and races adoption when open)

1. **`herdr-core` (`hc`) never creates tab entries in `herdr-app`'s document.** Only a running `herdr-app` window (`AppWindow::tend_terminals` → `start_adoption` → `AppWindow::adopt` → `flush_documents`) reads `herdr.space`/`herdr.tab` labels and inserts `{ id: "<tabId>", name: "", layout: ... }` into `spaces[].tabs[]` (`AppWindow::adopt` passes `""` as `name` to `Tab::new`).
2. **When `herdr-app` is closed at start time, `<tabId>` does not exist in `doc.get` (`spaces[].tabs[]`).** Even when `herdr-app` is open, `hc run` returns before async `start_adoption` (`terminal.read` + `terminal.keep` RPCs) flushes the new tab via `doc.set`. Thus Q2b's `doc.get` + `doc.set` "touching only that tab's name" has no tab object to rename when closed, and races `start_adoption` when open; if skipped when closed, `herdr-app` later adopts the tab with `name: ""`.
3. **Side effect if `doc.set` upserts the tab entry before adoption:** `tend_terminals` only runs `start_adoption` when `Model::pane_of(term_id)` is `None`. Pre-populating `layout: { type: "block", terminal: "<termId>" }` in `doc.set` makes `pane_of` return `Some`, so `herdr-app` skips `start_adoption` and never calls `terminal.keep` on `<termId>` (which Q1 relies on `herdr-app` rather than `hc run --keep` to do).
4. **Required probe / adjustment:** Either wait for `<tabId>` to appear in `doc.get` when `herdr-app` is open and define how closed-window tab naming works without breaking adoption, or upsert the tab in `doc.set` and verify in the throwaway probe—both with `herdr-app` open and with `herdr-app` closed at start time—that the tab shows `name == <slug>` and seat B still splits into it.
