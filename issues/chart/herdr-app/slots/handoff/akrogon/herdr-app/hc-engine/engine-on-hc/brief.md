# Brief: engine-on-hc

## What

akrogon's engine runs on herdr-core (`hc` 0.1.18) and herdr-app (0.1.13) with today's behavior kept:

- one hc module in `src/` with a closed command list: start, prompt with its guards, status read, event follow, `doc.get`, kill, close a finished leaf's tab, herdr-app's `tab.rename` and window check, and the app home function;
- identity: a repo's space found by name across running hc sessions through `doc.get`, a two-letter prefix per repo in the registry, seat names `<prefix>-<slug>-<a|b>`, akrogon labels on every terminal;
- one start function exposed to skills as one new CLI verb: consultants and direct reviewers start with `--parent` from the caller's `HC_TERMINAL_ID` and the caller's `herdr.space` and `herdr.tab` labels read from `doc.get`, so they join the door's tab (B,C,E; P11); leaf seats parentless, wrapped in `systemd-run --scope` in their leaf slice with the leaf env and the Claude child-session variables cleared, first task in argv (agy: trust question answered, then the first task by `hc send`), proven on hc events within 60 s; a tab per leaf by labels, named by `tab.rename` when the window is open;
- delivery: later tasks by plain `hc send` to idle or done seats, turns recorded as `prompted`, silent stops re-prompted with the third failing the leaf;
- one transcript resolver in `src/` that saves the path on the terminal's label;
- a systemd user service `akrogon-listener.service`, installed by the deployer from deploy-listener-ready, replacing the herdr plugin: subscribes to `hc events`, runs `pull --all` then `next --resume`, runs `next` on turn end, blocked and exit of akrogon terminals, single-flight, and sends watcher wakes to a live `akrogon.watch=<repo>` terminal;
- `akrogon phase` runs `next` for its own leaf; rollback across the cutover refused; a state file with old pane ids refused as "state predates hc";
- the herdr plugin (`plugin/`) deleted (operator 1a; deploy-listener-ready's deployer unlinks it from old herdr, last) and old herdr calls in engine paths deleted, except today's notice sends, which stay until notices-on-hc, and the `src/shell.ts` exports `skills/watch-issues/scripts/observe.ts` and `tests/fake-herdr.ts` still import, which stay until watcher-on-hc and herdr-sweep (B,E);
- the two-letter repo prefix read from the top-level `prefixes:` map, required for dispatch and unique, with registration refusing a duplicate (B,C,D,E);
- leaf states written before the switch stay readable when the leaf is merged or done, wherever its folder is (the deployer and engine leaves stay in this open epic until it completes), with no hc call made on their old identifiers; only a leaf with live seats or work recorded on old pane ids is refused (D,B);
- a seat restart, `akrogon stop` and a merged tab close end a terminal with `hc kill` then `hc rm`, so a finished terminal leaves no name or pane behind (C);
- each new CLI verb gets its row in `docs/reference/commands.md` (E);
- the real-core test fixture, the OSC 7501 stand-in agent and the strict fake `herdr-app` land here.

Consumes from deploy-listener-ready (blocked-by): a deployer that skips the plugin link and unlinks the old plugin for a release without `plugin/`, links, enables and restarts `systemd/akrogon-listener.service`, and a config schema that already accepts `prefixes:`.

## Why

akrogon is moving from old herdr to herdr-core and herdr-app with the same workflow (signposts 1a, 2a, 6a). The engine is ported first so every later leaf runs on it, which also proves it. Its merge is the switch (forks/cutover.md).

## Done-criteria

1. On a real throwaway hc core with the stand-in agent, the start verb starts a leaf seat named `<prefix>-<slug>-<a|b>` (cut plus 4 hex only above 32 characters) with the akrogon labels, no parent, the terminal's `pid` the harness, `/proc/<pid>/cgroup` inside the leaf slice, the leaf env set, and the first task in argv; it records `prompted` from the first `working` or turn ≥ 1 within 60 s; a stand-in that never works stays running and the start reports "started, not confirmed" with the address and screen; a stand-in that exits fails the start. Proof: own tests in the `test` check.
2. A seat started from a core whose environment carries `CLAUDECODE`, `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_EXECPATH`, `CLAUDE_CODE_MESSAGING_SOCKET`, `CLAUDE_CODE_MESSAGING_TOKEN`, `CLAUDE_CODE_SESSION_ATTENDED`, `CLAUDE_PID`, `CLAUDE_EFFORT` and `CLAUDE_CONFIG_DIR` shows none of the first ten and keeps `CLAUDE_CONFIG_DIR` in `/proc/<pid>/environ`, and its `pid` is the harness. Proof: own test in the `test` check; the real Claude seat writing its transcript is part of criterion 9.
3. The listener subscribes to `hc events` before its catch-up pass, runs `pull --all` then `next --resume` at start, runs `next` once per turn end, blocked or exit of an akrogon-labelled terminal and never for an unlabelled one, runs one pass at a time with queued wakes folded into one, and catches up after its event stream ends. Proof: own tests in the `test` check on a real core.
4. One prompt per seat per turn: when `akrogon phase` runs `next` for its leaf and the seat's turn-end event arrives, the idle turn is prompted once; a seat whose turn moved past `prompted` without a phase move is re-prompted, and the third such prompt moves the leaf to `failed` with "seat <x> ended <n> turns without reporting"; any phase move resets the count. Proof: own tests in the `test` check.
5. Later tasks go by `hc send --json` only to a seat whose status is `idle` or `done`; `started: false` records `delivery_error` and nothing is resent while the turn is unchanged, and a later pass that sees the turn moved resettles it as delivered; a first send refused with `kind: unavailable` is sent again on the seat's next status event within the 60 s start budget. Proof: own tests in the `test` check.
6. A repo's space is found by name through `doc.get` across running sessions with the window closed (the fixture core's document seeded by `doc.set` from a recording the window tier captures) (C); none, several or unreadable refuse with today's reasons; registration refuses a duplicate prefix and dispatch refuses a repo without one, naming `prefixes`; a test pinned to `hc schema` fails when the `doc.get` or session shapes change; the first-switch inventory (merged deployer and engine leaves with old pane fields inside the open epic, closed leaves with old fields, blocked leaves with none) reads cleanly and triggers no hc call on old identifiers, while a leaf with live work on old pane ids is refused (D,B). Proof: own tests in the `test` check.
7. In a throwaway herdr-app session: with the window open, a started leaf's seats show as one tab named after the slug with B as a split beside A, and the active tab and focused pane are unchanged; with the window closed longer than the start's pane wait, start returns with the labels set, the seats stay alive, and after the window opens the next engine pass names the tab (`<slug> failed` for a leaf that failed meanwhile); a failed rename leaves the seat running and `akrogon status` shows the tab unnamed; the app home function's answer agrees with `herdrapp session list --json`; a merged leaf's tab is closed by `herdr-app do tab.close` (C); a consultant started by the verb from a door terminal joins the door's tab, and one started from a door in no tab gets only the space label and shows as its own tab (B,C,E). Proof: attended window tier (live, free), artifact path in the report; the call sequence is also covered by the strict fake `herdr-app` in the `test` check.
8. The listener is restarted only after a deploy fully completes: a self-update triggered through the listener on a throwaway release home deploys, writes its record, and only then restarts the listener. Proof: own test in the `test` check.
9. For each of claude, codex, pi and agy, a real seat started through the start verb in a throwaway session has its first task confirmed, a later send delivered with the turn advancing, its report arriving by `hc send`, and its transcript path resolved and saved on its label (claude from the open `tasks` handle under the seat's `TMPDIR`, codex the newest rollout it holds, pi from its argv id, agy its open sqlite file); the agy seat in a new folder answers the trust question once, counts its first task as turn 1, and writes a file outside its cwd unattended under `--mode auto`; the Claude seat writes its transcript. Proof: attended paid per-kind tier, logs kept, under this leaf's grant.
10. `akrogon status` shows whether the listener is live and whether a watcher terminal is live, as information only. Proof: own test in the `test` check.
11. With a live terminal labelled `akrogon.watch=<repo>` running an agent, a lost or exited seat, a seat replaced by a keep shell, a blocked seat, a leaf moved to `failed` and a 60-minute busy deadline each send one `/watch-issues tick <root>` by `hc send`, with one wake in flight per repo; with no such terminal nothing is sent and dispatch runs unchanged; two live matches are reported. No `herdr` call remains in engine paths (`src/next.ts`, `src/phase.ts`, `src/reconcile.ts`, `src/scope.ts`, `src/log.ts`, `src/shell.ts`) except today's notice sends and the `src/shell.ts` exports `observe.ts` and `tests/fake-herdr.ts` import; the deployer's plugin conditional, with the `herdr integration install` loop inside it, stays for the sweep (B,C); `plugin/` is gone from the release.
