## Q2: box before executing the harness

- D2 pick: put `systemd-run --user --scope --quiet --collect --expand-environment=no --slice=<leaf slice> ... -- <harness argv and first task>` inside the one start helper's terminal argv. Retain the current stop grace and SIGHUP policy where applicable. Use the hc PTY directly, with no extra shell, pty or service layer. systemd's scope job completes before the harness executes, so the harness never starts unboxed. Cost: a native systemd transaction at launch and a probe for each harness integration.
- This replaces adoptShell and its 50 ms scope-read loop (`src/next.ts:625-630`). The native scope-start transaction is the synchronization point. Do not add no-block, an external wait loop or post-start PID adoption. Scope setup failure exits before the harness runs, and the existing start/exit event handling reports failure. No unboxed fallback.
- Rejected: move hc's pid after start. The direct-argv first task can already execute and fork before adoption; moving just that PID cannot recover escaped descendants (S4). A PID/start-time check prevents reuse mistakes but cannot remove this launch race. Rejected: wrapping in a transient service. It changes parentage, environment and terminal behavior that hc owns.
- Evidence: practitioner S1/S2, then source S3 and kernel S4; `src/scope.ts:147-184`, `src/next.ts:624-635`; session-id Taken requires pid-first lookup. Date: 2026-11-06. The v262 source confirms in-place exec despite the manual's loose wording.
- Pitfall/removal: the wrapper disrupts hc status, transcript lookup or harness argv parsing. Live done criteria for Claude, Codex, Pi and agy: first task starts, later send works, OSC/status reports remain correct, hc's pid becomes the harness PID, and the shared resolver finds the right transcript. The stored launch argv includes the known wrapper, so resolver/config code must not assume argv[0] is the harness. Use the existing foreground fallback only for its permitted case.
- Pitfall/removal: raw task dollars are expanded by systemd. Keep expand-environment=no and argv arrays through every layer. A task containing dollar expressions, quotes and newlines must arrive unchanged. No shell command string.
- Pitfall/removal: exact old paneScope naming rejects valid new scopes. Remove pane-ID assumptions from membership checking. Validate the already-owned terminal's PID/start identity and its expected leaf-slice ancestry on normal engine passes. Let systemd allocate a unique transient scope name rather than inventing a second identity registry.
- Missing question: are harness wrappers themselves guaranteed to exec? systemd's exec is proven, but a persistent shell/daemon wrapper could still invalidate pid-first transcript lookup. The per-kind launch probe must cover the actual configured executable, including Codex's daemon mode.
