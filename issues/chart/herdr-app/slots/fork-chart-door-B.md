Its lead routes tagged messages with reply correlation; a missing reply gets one reminder, and restart retains conversation records and queued mail without blindly replaying the first task. Its extension's newSession message opens a fresh recipient session with that message as its first prompt. It separates per-process identity from human-readable agent names. I found no practitioner proof of a safe self-clear plus bootstrap sequence across hc's three supported reset harnesses.

The send API describes paste/Enter and the quiet-input rule, not an atomic reset-and-resume or cancellation on later operator input.

## Q1: consultants, collection and the safety net

- D1 pick: start/restart through the chosen start command; first task in its argv, later tasks by plain hc send. Keep native parent child-notifications enabled. They replace the wait script's failure wakeups while explicit reports plus the current exchange's nonempty return file establish completion. No hc wait --children, foreground/background peer-wait, sleeps, collection polling or new message bridge.
- Each brief carries the exact report command targeting the door's current address, the seat letter and a fresh absolute return path. The brief and path identify the exchange. Accept a report only from that seat's current qualified address and for that pending path, then read its actual content. A turn-end note is a cue to check, never an answer or proof of success. No extra exchange UUID is needed when the path is unique.
- When a child stops without both pieces, inspect once and apply delivery Q4's one nudge naming what is missing; the second silent stop drops it for the session with kind/model recorded. If it is still working, retain the missing-piece state until the native end note permits the send. No forced nudge into a dialog, prompt replay on started false or dropped-seat resurrection. Keep completed returns from a dropped seat; ignore and record its later returns.
- A does its own work while consultants work. When useful independent work is exhausted, end the turn with the exchange still explicitly pending and continue on hc input. Replace the old rule that A must keep its turn open to wait. Neither yielding nor a timeout completes the exchange. A cannot merge missing returns or perform handover while an exchange is uncollected.
- Remove peer-create.ts, peer-ask.ts, peer-wait.ts, peer-anchor.ts and peer-restart.ts after the replacement works end to end. Their shell ancestry, transcript-turn parsing, output receipts and idle-grace loops do not survive as renamed hc wrappers. Start owns creation and placement; plain hc kill plus the same start owns restart, using the recorded launch recipe, never the previous task from hc get.
- Keep chart-usage.ts, ported to transcript paths, and direct-guards.ts. They perform retained chart functions rather than multiplexing or waiting. Shared native status/path resolution belongs to the already chosen src boundary, not another skill-side API layer.
- Cost: progress depends on a real child/report signal rather than repeated check-ins. A terminal stuck working forever has no success/failure inferred from silence. Native failure notifications and delivery's silent-stop rule are essential coverage, not optional decoration; the watcher remains optional and cannot be made a prerequisite.
- Rejected: kept hc wait safety net, because this fork is explicitly judging it against the no-waiting direction. Rejected: reports alone with child notifications disabled, because a blocked/crashed consultant can never report. Rejected: treating file existence, idle/done or a native completion note alone as a consultant answer. Rejected: adding a duplicate listener-to-parent forwarder when native child notes already cover the event.
- Evidence: operator `forks/signposts.md:68,72`; delivery Q4 and start-and-pane Taken; S1 first, then S3/S4; repo `skills/chart-issues/scripts/peer-ask.ts:33-84`, `peer-wait.ts:253-335`, `SKILL.md`, Open/Take/Autopilot; `assets/questions.md`, Blind peer exchange. Date: 2026-11-06.
- Pitfall/removal: native parent news and automatically typed child notes may have different coverage. Before handoff, prove ordinary silent turn-end, blocked, error and exit each wake a working and idle parent without hc wait. Also prove a report arriving before the child's final idle state is collected once. If a required event is not pushed, fill that native hc notification gap in herdr-setup rather than claiming peer-wait has already been replaced.
- Pitfall/removal: reused names or files admit an old result. Test a delayed old-address report after restart, an earlier exchange's path, file without report, report without file, duplicate report and a genuine second silent stop. Only the current exchange counts and the stop bound is enforced.
- Missing question: are supplied peers already hc children of this door after the required chart-entry restart? A pre-existing terminal with a different parent does not send this door its native parent notes, and parent is not a mutable label. Preserve the supplied-peer contract explicitly rather than assuming all supplied addresses satisfy D1.

## Q2: reset A and resume the handover

- D2 pick: preserve an in-place fresh conversation in A's existing terminal, with reset and the handover start prompt treated as one ordered native operation. It retains the operator's pane and the consultants' parent address. Claude uses clear, Codex/Pi new as today, but a single pasted reset command is only the reset half of the requirement.
- This is NOT established by current hc send documentation. Do not turn the question's “delivered when its turn ends” into a proven guarantee. Before choosing an implementation, prove deferral until A's current turn ends, reset completion and delivery of the exact start prompt into the new conversation, including queued operator input. If ordinary native sends cannot provide that sequence, signpost 3 assigns the missing reset-and-kickoff capability to herdr-setup. Do not hand off a promised operation without that capability and its observations.
- Preserve today's queue-point cancellation: a real operator instruction after the handover was queued supersedes it before reset/kickoff proceeds. hc's quiet-input rule only postpones typing and holds keys; it does not establish this cancellation. Unknown/unreadable current conversation evidence cannot authorize a reset from an older saved transcript path.
- Before queuing, finish every consultant exchange, write the outgoing records, close the span, and append the unconsumed handover to the next chart's Mode record with the remaining work, surviving/dropped consultants, signposts path and verbatim active operator instructions. Keep the existing attended/autopilot trigger rules. A presented question, compaction and pass end do not reset A.
- Fresh A's first prompt must name the current terminal, handover time, next chart, absolute chart folder and skill path. It matches the latest unconsumed Mode entry before consuming it and records the appropriate continuation, fresh A transcript path and first span. A random fresh session or a late duplicate bootstrap cannot resume autopilot. An accepted handover continues the logical door run; it does not silently lose or broaden its handed list or revive lost consultants.
- Delete the old detached polling door-reset.ts after a native equivalent is proven. In particular, do not preserve its 500 ms reads, ten-minute wait, separate new-session confirmation loop or Codex “Reply OK” paid probe as the new runtime design. A new reset helper in skill text would need an explicit exception to signpost 1a; it is not already authorized by renaming the file.
- Cost: native reset-and-kickoff is a real unresolved capability/proof obligation, not merely replacement syntax. It may require herdr-setup's update-safe patch path. The simpler-looking two-send recipe is not ready to promise until it passes the same operator-input and fresh-context tests.
- Rejected: blindly self-send clear/new then bootstrap immediately. Native input queue ordering and fresh-session application are unproven, and operator text can arrive between them. Rejected: a successor door launched as another terminal as the default. It changes the operator's location and retiring old A can kill its consultant children; avoiding that adds lifecycle/transfer machinery. Rejected: use compaction or same-session continuation as an automatic fallback for a supported reset harness. Those do not satisfy the current fresh-session handover contract. Unsupported kinds retain today's explicitly supported behavior until scoped otherwise.
- Evidence: practitioner S2 supplies a complete native operation, not proof about hc; S3 shows the missing guarantee; better-than-training `skills/chart-issues/SKILL.md`, Handover/Autopilot; `scripts/door-reset.ts:139-248,251-285`; session-id and start-and-pane Taken. Date: 2026-11-06.
- Pitfall/removal: reset succeeds but the new A never receives its entry. Disposable per-kind done criteria: different conversation/path, same hc address, exactly one bootstrap, correct next chart and signposts, inherited logical mode, preserved consultants until chart-entry restart, and no unrelated terminal affected. Do not count mere command exit or a changed screen as proof.
- Pitfall/removal: input or duplicate delivery replays a consumed handover. Probe operator input after queue and before reset, operator input between reset and kickoff, blocked input, unknown path, duplicate kickoff and stale Mode entry. Cancellation must be explicit in the log, and no second reset is guessed. These observations must precede old-code deletion.
- Missing question: which actual native mechanism delivers the start prompt after reset while preserving operator supersession? If none is currently proven, this fork needs that named substrate prerequisite before it can be declared settled.

## Q3: gates, records and remaining text

- D3 pick: replace the environment gate with the actual hc terminal context, resolve the repo's target session through identity Taken, and use qualified addresses for ownership. HC_TERMINAL_ID is a context indicator, not proof that an arbitrary supplied address belongs to this door. Preserve supplied-pane ownership constraints and do not recreate the old /proc shell-ancestry anchor in a new helper.
- Use chart-folder briefs/returns from the beginning, per the current intake direction. Remove the obsolete temp-only pre-chart exchange rule in questions.md/Open and its transfer/cleanup choreography. Every exchange gets a finished immutable brief and distinct return path. Preserve blind reads, agreeing-seat attribution, the one rebuttal and focused mechanism-correction checks.
- seats.yaml records the seat letter, hc session/address, derived name, kind and actual launch recipe needed for restart; its session field is the transcript path from the shared resolver. Append a new conversation for the same letter on reset, keep earlier paths for usage, preserve opened and spans, and mark unknown usage unmeasured. No requirement that a session ID or path exist before a seat can start.
- Port mode/handover records, fresh-session comparison and “continue autopilot” rules to the same path/address identity. Unknown current path never proves the same conversation. Keep the explicit handover continuation route separate from a new independent door run. A record alone does not grant a new session authority to consume any open chart.
- Sweep the linked SKILL.md/assets as well as scripts: HERDR_ENV/HERDR_PANE_ID/HERDR_SOCKET_PATH, old agent-list session fields, chained waits, fixed 65/35 ratios, restart-in-the-same-pane claims, nullable session exclusions, old drop/budget rules and cross-door ownership keyed only on pane IDs. The chosen 50/50/equal-consultant layout and replacement addresses supersede those old mechanisms; their safety purpose stays. Gate autopilot on hc context, not a mandatory watcher.
- Cost: records/schema tests and usage fixtures change, while chart content, approval boundaries and recovery bounds remain. Remove only obsolete Herdr mechanisms, not direct-route guards, the chart interview, authorization rules or measurement accounting.
- Rejected: a blind HERDR_ to HC_ substitution, bare address/name as identity across cores, preserving a native session-ID requirement, moving operator-supplied panes as a convenience, and importing template-driven task delivery contrary to delivery Taken. Do not scrape old task argv to construct a restart recipe.
