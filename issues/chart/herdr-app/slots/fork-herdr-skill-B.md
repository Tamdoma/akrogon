## Q1: shape and update correctness

- D1 pick: one small real SKILL.md in herdr-setup/skills/herdr, with portable name: herdr and a concise description. Link the containing skill directory into discovery homes. Its body routes program/agent work to hc --skill, window operations to herdr-app --skill, and layout/mod work to the relevant sections of ${HERDR_APP_HOME:-$HOME/.config/herdr-app}/AGENTS.md. This retains the app's live documentation as the source without copying its 951-line authoring guide into every invocation.
- Description scope: use for actual hc runtime context, incoming hc communication and explicit Herdr requests. Put the runtime trigger first so truncation does less damage. The body verifies native context before control, distinguishes terminal addresses from pane IDs, and tells agents to consult installed --help for exact syntax. It does not contain a second catalogue of commands or duplicate akrogon's workflow rules.
- Live manuals supply tool behavior; the selected akrogon workflow still supplies its authorization, collection and lifecycle policy. For example, this chart's chosen hc wait and reset helper remain valid exceptions. Do not copy a generic “never wait” rule into the global skill or let a manual example override delivery Taken's direct-argv choice.
- Cost: a short routing file to maintain, plus on-demand manual reads. A loaded conversation can retain older instructions after an app update; no symlink forces a model to forget cached guidance. Fresh sessions and explicit re-reading at changed-tool boundaries must be tested.
- Rejected: SKILL.md directly symlinked to AGENTS.md. The target has no portable name/description frontmatter, is regenerated, and mainly documents app authoring rather than agent coordination. Rejected: prepending frontmatter to app-owned AGENTS.md. The next app start overwrites it. Rejected: generated manual copies refreshed by an updater. That introduces another refresh dependency and another place stale commands can survive.
- Evidence: operator signposts 5a/3 and INTAKE awareness direction; S1–S5; repo src/install.ts:25-48. Date: 2026-11-07.
- Pitfall/removal: a named session resolves the default app's files. Use the already resolved HERDR_APP_HOME when present; absence means the app's documented default location, not an error fallback. Test default and a named session with distinct app homes. A missing requested guide is reported rather than silently substituted with a copy from another home.
- Pitfall/removal: updates leave a stale or invalid skill. Done criterion: the wrapper remains a valid discoverable skill after app startup rewrites AGENTS.md and after independent hc/app updates; the manuals reflect the installed binaries. No custom synchronization daemon, generated copy or write into the app's generated guide.
- Missing question: is the short routing wrapper accepted as the intended “content from AGENTS.md”? It is the portable way to read the live source, while a literal link is not the same thing as a valid skill manifest.

## Q3: runtime awareness

- D3 pick: skill metadata is necessary discovery, not sufficient proof of “aware every time”. For the literal all-hc-sessions requirement, have herdr-setup wire a minimal native startup-context integration for each supported harness, gated by HC_TERMINAL_ID. It injects a short instruction identifying this as an hc terminal and pointing at the canonical herdr skill before the first task, including manually started hc agents and fresh conversations after clear/new. Global CLAUDE.md and AGENTS.md stay untouched.
- Extend an existing hc/harness startup integration if it already provides this context; do not install a second equivalent hook. Native hooks/extensions are the place for conditional startup context. Claude/Codex have SessionStart additionalContext; Pi has native extension context injection; agy's shipped SessionStart contract has injectSteps. These contracts are implementation leads, not proof that the installed versions and current hook settings already provide awareness.
- The startup notice is context only. It neither authorizes delegation or control nor runs hc commands. Outside hc, the integration emits no Herdr startup content and has no side effects. A quoted hc tag can make the skill relevant but is not proof of local runtime identity. Explicit Herdr questions outside hc may load documentation; they do not authorize acting on a guessed focused session.
- Akrogon-created leaf seats, consultants, direct reviewers and the door's reset continuation use the same startup mechanism. Do not add a duplicate startup preface if that integration already supplies it. If the operator instead selects metadata plus an explicit first-task instruction only for akrogon starts, say clearly that manually started hc sessions then rely on model selection; it is a narrower guarantee.
- Cost: minimal per-harness integration/configuration and installed-version probes. A global skill alone is smaller, but cannot honestly guarantee automatic loading. No permanent model call, polling loop, copied 951-line prompt or edits to global instruction files are needed.
- Rejected: “description loaded = body followed”, hc tags alone as runtime proof, unconditional global rule text, or adding only an akrogon first-task preface while claiming every hc-launched agent is covered. Also reject per-turn reinjection of the complete manuals; only small awareness context needs to persist/reappear at the harness's proper boundary.
