2. Producer fields: `address` plus `session` on each seat is one field too many and a cross-session plumbing job the window already does for free. Every akrogon terminal carries `akrogon.repo`, `akrogon.leaf` and `akrogon.seat` labels (identity Q2), and `terminals()` exposes every core terminal of this window's core "as `hc ls --json` describes it (address, … labels, state)" (`herdr.d.ts:209-212`). So the mod resolves the target in two native lookups: the live terminal whose labels match the row's repo, slug and the producer's `focus` seat, then the pane whose `terminal` is that address. The producer emits `focus: "A" | "B" | null` only; the judgment stays in the producer beside `attention` and `waits_on`, the lookup is the mod's, as `model.js:1-3` already divides them. This removes the address collision by construction (labels are checked in this window's own core, so a same-numbered `t7` from another session never matches), removes the session field and the window-session read, and makes an ended or unrecorded seat fall to Files because no live labelled terminal exists, without a null-address convention. E's "bare address plus a space check" is the same instinct with one more field than needed.
