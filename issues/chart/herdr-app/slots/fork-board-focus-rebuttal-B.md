# B: board-focus rebuttal

- F1 “Ended seat → Files (all)” and “address null when no live seat” misstate my pick. A finished terminal with an inspectable pane still gets focused for its scrollback. Files applies when the target is unavailable or has no inspectable pane. The proof must distinguish those cases rather than require every ended seat to open Files.
- F2 A `panes()`-only gate was not my pick. The native guide says pane.focus prefers a visible layout terminal block, while panes() lists model panes only. Availability must respect that distinction if such a block is the displayed target. Current-core membership and ownership still need checking independently of a bare address match.
- F3 “First shown problem” must govern selection before checking whether any delivery error exists. leafAttention emits missing-input facts before delivery errors, so a row can display a non-seat problem while also carrying a secondary A/B error. That row gets no invented problem seat. Compute the primary problem and its optional seat together, preserving producer ordering.
- F4 I have not proved that agent.focus requires status registration. I prefer pane.focus because the requested target is a pane/terminal and agent.focus also selects the focused-agent layout content. Treat no-status agent.focus behavior as a probe question, not a verified limitation attributed to me.
