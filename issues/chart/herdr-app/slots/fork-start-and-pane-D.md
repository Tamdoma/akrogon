## Q1. Lifetime: which agents outlive the terminal that started them?

Pick: Leaf seats start with `--no-parent --keep`. Consultants and direct-route reviewers start as normal children of their door (default `die_with_parent`, parent gets hc's cannot-report notes). Nobody akrogon starts uses `--outlive-parent`.
Reason: closest to old herdr, where panes belonged to the server and no client or engine process ending could kill a leaf seat. Leaf seats have no agent parent to report to: advancement is `phase` plus the listener (engine-shape Taken). `--no-parent` must be explicit because the starter varies by call path: the systemd listener is not a terminal (no parent anyway), but `phase` running `next` executes inside seat A's terminal, so a default-parent start would make seat B a child of seat A and kill B when A's tab closes. Consultants mirror the old peer panes in the door's tab: door agent process crash leaves the terminal and the children alive (intake test 4), door terminal death ends them. Cost: parentless leaf seats send their blocked/error/exit notes nowhere, so listener plus watcher coverage must be total, and reconcile/stop own explicit cleanup by label and recorded address.
Rejected: `--outlive-parent` with a real parent (the parent, possibly seat A, still receives notes and sees the seat in `hc wait --children`; two mechanisms where zero parents is exact). Default parenting for leaf seats (parentage depends on who happened to run `next`; the A-parents-B case above). Consultants parentless or outliving (orphans after the door closes, names stay taken, reports have no reader; kill-and-restart assumes door ownership).
Evidence: operator/intake (children survive door agent crash, die with door terminal unless outlive; tests 2026-10-30); better-than-training: `hc run --help` (`--no-parent`, `--outlive-parent`, `--keep` semantics), live `hc get t6f` showing `parent: t15, die_with_parent: true, keep: true` for a consultant, engine-shape Taken (phase runs next from a seat's turn), read 2026-11-06.
Pitfalls: (a) A blocked parentless seat waits silently if the listener is down. Removed by engine-shape's liveness in `akrogon status` plus watcher; never by giving the seat a fake parent. (b) Core restart with `--keep` returns a shell where an agent was. Removed by listener/watcher rule carried from identity: live terminal, foreground shell, agent expected = crashed seat; never auto-resend. (c) `akrogon stop` must kill by recorded address/name after the ownership check, not by parent. Leaf done-criterion.
Not asked: should `--keep` also be set on consultants (live t6f already has `keep: true` via pane adoption), so a core restart returns their panes as shells for the door to restart into, or is a vanished consultant cleaner?

## Q2. Leaf tab and seats

Pick: Option (a). Allocate mints one tab id per leaf, stores it (identity Taken), and starts each seat when first needed with `hc run --no-parent --keep --label herdr.space=<resolved space> --label herdr.tab=<tab id>` plus the akrogon labels; B's later arrival lands beside A. The tab is renamed to the slug with `tab.rename` in the same pass when the session's window answers; when it does not, the tab stays unnamed and every allocate pass retries the rename until `doc.get` shows the slug.
Reason: (a) is the only option that works with the window closed, which is the normal case for listener/phase dispatch while the operator is away, and core-side creation does not take focus the way app commands that show a new tab do. The name is display only; identity is tab id plus labels plus cwd checks. When the window is closed nobody can see the unnamed tab, so deferred naming loses nothing. Starting B on first need matches hc's model (a terminal is its program; there is no empty shell pane to pre-split as old allocate did at `src/next.ts:604-613`). Cost: B's arrival shrinks A's pane mid-leaf (old flow split before A started), the minted tab id format is an upstream assumption, and leaf env (`AKROGON_BASE`, `TMPDIR`, `GIT_EDITOR`, `src/next.ts:569-582`) has no `hc run --env` flag (checked `hc run --help`), so start prefixes argv with `env K=V …`, which the harness-argv check in `launch` (`src/next.ts:294-302`) must account for.
Rejected: (b) `tab.new` (needs the window; no env and no no-focus argument, `herdr-app commands` 2026-11-06; the staying-open shell and app-side `--task` bypass `hc run` first-message proof, and seat B needs a second split path, so two start mechanisms). Naming by `doc.set` (writing the whole opaque app document for a cosmetic field that only matters when a window is open, against the public `tab.rename`; version conflicts make it safe from corruption but not worth a write path). Pre-starting B as an idle shell at allocate to preserve the old split timing (a shell is not a seat; typing the harness into it later via `hc send` loses first-task-in-run delivery, the proven path).
Evidence: operator/intake (visible pane at start, no-focus leaf tabs labelled by slug today); better-than-training: `src/next.ts:569-592, 604-613`, AGENTS.md "The model" (unknown space/tab label id becomes a new tab; adoption enables keep), `herdr-app commands` for `tab.new/tab.rename/terminal.keep`, live `doc.get` showing tab ids `tb<32 hex>` and names, all 2026-11-06.
Pitfalls: (a) Minted ids may need herdr-app's exact `tb…` format, and label adoption might make the new tab the space's active tab, which the operator sees on next switching to that space. Removed by probe before handoff in a throwaway session: mint, start A then B window-closed, read the doc for tab tree, focus and active flags. (b) Both seats started in one pass race into the tab in either order (B left of A). Removed by design: start A, verify it is in the doc's tab tree, then start B; order verified, not assumed. (c) The `env` prefix hides the harness as argv[0] from hc program detection. Removed by the same probe: `hc get` must show the agent app and OSC status through `env`.
Not asked: when B first appears days into a leaf, is A's pane shrinking acceptable, or should the tab be born with A at 50% width (weights set for a second pane that does not exist yet)?

## Q3. Consultant column: equal heights, and restart into the old spot

Pick: Equal heights are the operator's stated rule, so they are guaranteed, not accepted away. Flow: start consultants unlabeled as door children, `terminal.keep` the first right of A and each next down from the previous (retry until the pane shows), then equalize by setting the column children's `size.weight` equal (and A vs column to 1:1) through `doc.set`: read doc and version, change only those weights, write with the version, re-read and retry bounded times on `conflict`, verify from a fresh `doc.get`. This write lives in akrogon's hc module behind the same strict-schema, schema-pinned test identity Taken already requires for `doc.get`. A single consultant restart reuses the same logic: kill, start under the same name, keep down from its predecessor (right of A if it is first), equalize, then verify column order from the doc; if order is wrong, park all consultants and re-keep them in naming order, then equalize again.
Reason: halving splits cannot give equal heights with naming order for 3, 5, 6 seats (fork question; live doc today shows this session's four consultants at weights 0.61/0.50/0.42/0.47 and A vs column at 0.66/0.34, `doc.get` 2026-11-06, i.e. neither equal nor 50/50 without a write). `doc.set` is a public core API with compare-and-swap by version (`hc schema`: "Write an opaque JSON document … if its version still matches", conflict error), so a concurrent operator drag causes a retry, not a clobber. Placing the write in akrogon's hc module conflicts with a strict reading of signpost 3 (gaps in herdr-setup), but `doc.get` already landed in akrogon by identity Taken, and this helper's only caller is akrogon's start command; the operator should confirm this reading. Cost: akrogon now writes an upstream-owned document shape; an upstream format change must fail loud via the schema test, and if equalize fails the seat stays started and visible with a degraded report, never killed over cosmetics.
Rejected: accept unequal for odd counts (the operator asked for equal heights twice, intake 2026-11-03; silently delivering 50/25/25 reopens a settled rule). Keep-order tricks alone (work only for some counts and fight the naming-order rule). A herdr-setup helper binary that akrogon start shells to (a runtime cross-repo dependency on every consultant start, version skew, and herdr-setup has no such mechanism today; if the operator insists on signpost 3 here, the helper must be installed and version-checked by akrogon install, which is the same dependency with extra steps). A herdr-setup mod setting weights (mods live in the window and have no pane-weight API either; it would `exec` hc connect to do the same doc.set from a worse home). Restart by park-and-replace of the whole column every time (unaffected consultants briefly lose their panes, against the never-without-a-pane rule; keep it only as the order-repair fallback).
Evidence: operator (A 50%, consultants stacked in order, equal heights, intake carries); better-than-training: live `doc.get` tab tree weights above, `hc schema` doc.set version/conflict semantics, old `peer-create.ts:28-42` equal heights by split ratio (no ratio argument exists in herdr-app, `herdr-app commands` pane list), intake keep races and restart-loses-placement findings, all 2026-11-06.
Pitfalls: (a) `terminal.keep --place down` from a middle consultant may nest a split instead of inserting into the column, so single restart lands in the wrong tree shape. Removed by probe before handoff (restart C of B,C,D in a throwaway session; read the doc tree), whose result decides whether re-place-all is the main path. (b) doc.set racing the app's own writes during a drag. Removed by version CAS plus bounded retry and weight-only edits. (c) Focus: keep acts on the focused pane while the operator types in A. Removed by done-criterion: focus is read before, restored after, and order is verified from the doc, so a mid-placement click is detected and re-placed, not silently wrong. (d) Upstream changes the tree shape. Removed by the schema-pinned test; equalize failure is a loud degraded line from start, and the fix is one boundary module.
Not asked: does the equal-height rule apply when the operator hand-resizes a consultant pane mid-chart (does the next start/restart stomp the operator's drag back to equal)? My assumption: yes on any start or restart in that tab, no at other times.

## Q4. One start command: inputs, guarantees, callers

Pick: One implementation in the engine's hc module, exposed as `akrogon start` for skill text. Inputs: role (`--leaf <repo> <slug> <A|B>`, `--consultant <repo> <letter>`, `--direct-reviewer <repo>`), cwd (leaf worktree or repo root), harness selection resolved inside start (leaf: config slots plus harness template as today, `src/config.ts:27,190-194` and `launch` at `src/next.ts:294-302`; consultant/reviewer: kind argv from the seat record passed by the caller, since agy has no config harness entry yet), leaf env where relevant, and the first task text (required). It prints one JSON line per seat (name, address, session, tab, `first_message`, placement state), the `peer-create.ts:20-30` output shape. Guarantees, each verified before the success line: derived name (identity Taken) with a finished same-name holder removed only if its labels match, else refusal; labels set (constant filter label plus repo/leaf/seat); parentage per Q1; codex argv refused without `--no-daemon` (hc manual) rather than silently rewritten, with the sandbox network flag owned by config templates (config fork), not argv surgery; first task inside `hc run` and `first_message.sent` read back from `hc get`, a false reported with its reason and never blindly resent; pane visible (leaf: terminal present in the minted tab's doc tree; consultant: pane in the door tab in naming order, weights equalized or degraded reported; focus restored). Callers: engine allocate/dispatch internally, the chart door for consultants, the direct route for its reviewer. Nothing else in akrogon starts an agent; the watcher never starts, only steers live seats.
Reason: signpost 1a allows code exactly here, and the intake already asks for a start helper that owns naming, labels, pane and argv "so it cannot be skipped by a door that forgets". One implementation means the keep-retry, equalize and first-message checks exist once for engine and door. Cost: `akrogon start` is a new public verb whose output becomes a contract for skills, and start concentrates every hc quirk, so its fake in tests must model keep-pending, `name_taken` and `first_message.sent: false`. Its guarantee stops at "terminal live, task submitted, pane visible": it cannot promise the agent is working (a startup popup can still swallow the turn, intake), so readiness is reported as observed status, not success.
Rejected: raw `hc run` sequences in skill text (the intake's repeated hand-placement failures are exactly this). Separate engine and door start code (placement and naming logic diverge; Q3 logic would exist twice). hc templates (`hc templates` is empty here, templates are machine-global config baking in a model, outside akrogon's versioned config). A start command that also sends later tasks and waits (scope creep against 1a: sends and waits stay plain `hc` in skill text for agents, and engine prompts go through the hc module). Start silently fixing argv (rewriting a caller's recorded consultant argv makes seats.yaml a lie; refuse and name the missing flag).
Evidence: operator (signpost 1a, start helper owns the pane rule, intake); better-than-training: `src/next.ts:294-302, 786-809` (today's start with 30s timeout and failure record), `peer-create.ts` spec and emit shape, `hc --skill` (first task in run, check `first_message.sent`, read before resend; codex `--no-daemon`), `hc run --help`, all 2026-11-06.
Pitfalls: (a) Claude Code auto mode refused a hand-run full-access codex start (intake 2026-11-05); `akrogon start` from a door may hit the same classifier. Removed by operator step: a permission rule for the start command, decided in the config fork, and start never asks the harness for more access than its recorded argv. (b) `first_message.sent: false` from a trust dialog: start reports it, caller reads the screen with `hc read` and resolves before any resend; done-criterion includes this path per harness in probes. (c) Start called twice for the same seat (phase wake plus listener) double-starts. Removed by the name/recorded-address checks: a live terminal with the derived name and matching labels is a successful already-started line, not a second start. (d) The 30s-style start timeout versus slow first paints: start waits with `hc wait` semantics for the launch task to advance, bounded, and reports status instead of polling reads in caller skill text.
Not asked: is restart a start-command verb (`akrogon start --restart` doing kill, remove finished, start, re-place as one verified step) or a composition the door performs (plain `hc kill`, then start)? The placement verification in Q3 makes me lean verb, but that widens 1a's "start step" by a kill.
