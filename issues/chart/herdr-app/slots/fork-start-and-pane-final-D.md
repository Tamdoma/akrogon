# Final-shape check start-and-pane: slot D

Two objections, both on Q2/Q2b as written.

1. Naming may run before the tab exists in the document. Q2b writes the name "when it mints a leaf tab" by `doc.get` plus versioned `doc.set`, retrying on version conflict. That assumes core-side label adoption puts the minted tab into the `herdr-app` document immediately, including with no window running. Nothing proven so far shows who performs adoption or when: identity's `doc.get` probe only read pre-existing spaces in a windowless session, it did not create a tab there. If adoption happens in the app when a window next connects, the naming read finds no tab to name and conflict-retry never engages. Missing probe and mechanism: in a throwaway session with no window, start a seat with a minted tab label and read the document until the tab appears (or prove it appears only at window start); start must retry on tab-not-yet-present, not only on version conflict, and the record must say what a naming timeout does under Q4 (kill the agent as failed placement, or report degraded), because Q4's kill is stated for placement failure and naming is not clearly placement.

2. The "no focus change at start" half of Q2 has no probe. The listed probes prove the tab and name show, and that a running window does not overwrite the write. Neither proves that label adoption plus the `doc.set` doc event leaves the running window's focused pane and active tab unchanged. Add that observation to the already-open-window probe case, since a visible-but-activated new tab would pass the recorded probes while breaking the Taken shape.
