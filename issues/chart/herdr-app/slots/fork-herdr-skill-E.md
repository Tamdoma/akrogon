## Q3. Awareness: skill description + `<hc>` / `HC_TERMINAL_ID` gate vs extra injection

1. **Pick:** The skill list's `description` (injected into every session's system prompt across all four harnesses) plus `SKILL.md`'s hard gate (`HC_TERMINAL_ID` set, incoming `<hc from=...>` tag, or explicit `herdr-app` customization request) is sufficient, with no changes to global `CLAUDE.md`/`AGENTS.md` and no extra prompt prefix injected by akrogon's start command.
   - **Reason:** Every harness (`claude`, `codex`, `pi`, `agy`) loads every installed skill's `name` and `description` into the system prompt at session start (`pi/docs/skills.md:43`, `skill-creator/SKILL.md:56`, `agy-customizations/SKILL.md:85`). Do not use merely because a task could benefit from a background terminal, delegation, or parallel work. Requires HERDR_ENV=1"` (`~/.claude/skills/herdr/SKILL.md:3`). Writing the new `description` to name `<hc from=...>` messages, `$HC_TERMINAL_ID`, `hc`, `herdr-app`, delegating/messaging sibling terminals or agents, and editing spaces/tabs/panes/layouts/mods makes every agent in `herdr-core` aware of it on match, while `hc` itself includes `reach="hc send <addr> when done or stuck"` in `<hc>` tags (`hc --skill:117`) and akrogon's own skills/briefs already state their exact `akrogon`/`hc` commands.
