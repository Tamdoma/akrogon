## Q1. Lifetime

1. Pick: leaf seats are started with `--no-parent` (and the engine's hc module strips `HC_TERMINAL_ID`, `HC_TERMINAL_SOCKET`, `HC_SCOPE` before every call, identity Taken), so a seat never belongs to the terminal `akrogon phase` or `next` happened to run in; consultants and direct-route reviewers are children of their door and end with it. Keep is not a choice: labeled terminals get core keep by adoption (AGENTS.md "Adoption also enables core keep"), so after a core loss a seat becomes a shell at the same address, which the listener reports as a crash for the watcher (engine-shape carries). Reason: old herdr panes belonged to the server, so a leaf outlived every process; `--no-parent` is that. A door's helpers died with its pane in old herdr too (peer panes in A's tab). Cost: a parentless seat sends hc child notes to nobody, so the listener is the only ear (lifetime fork).
2. Rejected: (a) default parentage: `terminal.run` defaults the parent to the caller (`hc schema` `caller`: `HC_TERMINAL_ID`), so B started by `next` inside A's shell dies when A's phase ends; seen in spirit by the intake (children die with a killed parent terminal). (b) `--outlive-parent` for consultants: an orphaned consultant after the door closes spends money with nobody to report to. (c) `--outlive-parent` for direct reviewers only: the intake test 4 shows a crashed door's Claude leaves the terminal and children alive; only closing the pane kills them, an operator act.
3. Evidence: `hc run --help` (`--parent`, `--no-parent`, `--outlive-parent`, `--keep`), `hc schema` `terminal.run` (`die_with_parent` ignored, `caller`), intake tests 3 and 4 (2026-10-30), AGENTS.md "The model" (adoption enables keep; a lost terminal gets a shell with the same address), `src/next.ts:581-592` (tab created by the engine, not by a seat). Practitioner: searched tmux and zellij orchestrators for lifetime rules, found none beyond "detached sessions survive the client" (tmux reference, 2026-11-06), which is the `--no-parent` case.
4. Pitfalls: P1 a seat accidentally parented to a door or seat terminal: removed by the start command always passing `--no-parent` for leaf roles and a test asserting `parent: null` in `hc get`. P2 keep turns a crashed agent into a shell that looks live: removed by the listener rule "foreground is a shell where an agent is expected" (engine-shape) and a probe (`hc kill -9` the harness process, observe `hc get`).
5. Question not asked: who kills a leaf seat at `akrogon stop` and on reconcile (today `pane close`, `src/next.ts:547`, `reconcile.ts:405-428`)? The engine's hc module, `hc kill` then `hc rm`, by name plus address check.

## Q2. Leaf tab and seats

1. Pick: (a). The start command mints a tab id in herdr-app's form (`tb` + 32 hex, as `doc.get` shows) and starts A with `--label herdr.space=<space> --label herdr.tab=<minted>`; B later carries the same two labels and lands beside A, which is today's split right. The tab's name comes from a small herdr-setup mod that renames a tab whose terminals carry `akrogon.leaf=<slug>` to that slug (mods see `terminals()` labels and run `tab.rename`, AGENTS.md "The herdr module"). Reason: `hc run` with labels is the only start that sets the seat's name, labels and parent (identity Taken), works with the window closed, and leaves naming to the app side where lock 3 puts gaps. Cost: a tab shows its number until a window is open; one mod in herdr-setup.
2. Rejected: (b) `tab.new --name --argv --task`: needs the window, has no `name` for the terminal (names are fixed at `hc run`, so leaf seat names are impossible), unknown parent, and `first_message.sent` is not recorded for an app-started task. (c) engine runs `tab.rename` itself: a second window-bound path in the engine, retried every pass until a window answers. (d) engine writes the tab name through `doc.set`: a whole-document CAS write in herdr-app's private format from akrogon code; lock 3 says herdr-setup, and a write race with the app loses structure ("newest accepted document wins, no merging").
3. Evidence: AGENTS.md "The model" ("An id Herdr doesn't know becomes a new space or tab (unnamed: Herdr's names)"; adoption works for terminals "you start yourself"); `herdr-app commands` 2026-11-06: `tab.new` args name, space, folder, argv, task; `tab.rename` id, name; `terminal.keep` terminal, place; `pane.split` has direction, pane, argv, mod, no size; `src/next.ts:581-592,604` (today: tab labelled slug, `--no-focus`, B split right); intake 2026-11-03 (labels place panes side by side in arrival order). Practitioner: none found for label-driven adoption; tmux scripts create the window then `rename-window`, the same two steps.
4. Pitfalls: P3 adoption of a new tab focuses it and steals the operator's keyboard (today `--no-focus`): probe before handoff, `hc run` with a fresh `herdr.tab` while typing in another tab; if it focuses, the mod that names the tab also `tab.settle`s or re-selects the previous tab, else a `herdr-app feedback`. P4 a minted id collides with an existing tab: removed by generating 32 random hex and checking `doc.get` for the id before use. P5 the operator closes the leaf tab by hand: `tab.closed` today; on hc the terminals end (`finished` events) and the listener runs `next`, which treats a dead recorded address as today's closed pane. P6 B arrives left of A or in a new tab when A's pane is zoomed: probe once.
5. Question not asked: should the leaf tab be `tab.settle`d after merge instead of closed (`closeMergedTab`)? Closest to old is close; keep close.

## Q3. Consultant column

1. Pick: consultants start as plain children without `herdr.*` labels, then the start command places each with `terminal.keep --place right` (first) or `down` (next), retrying until `herdr-app ls` lists the pane, in the proven balanced order; then a herdr-setup helper (`herdrapp pane-weights <tab> --equal`, built on `doc.get`, edit `size.weight` of that column's children, `doc.set` with the read `version`, retry on conflict) sets equal heights for any count, and the same helper reorders the column's children to naming order, which is how a restarted consultant returns to its old spot. Reason: the operator ruled 50/25/25 out ("33% each"), herdr-app has no weight command, and the live document already holds the column as one list with per-child weights (`doc.get` today: column `sf7abdcb` with t6c 0.61, t6d 0.50, t6f 0.42, t6g 0.47 under A 0.66 / column 0.34), so order and weight are both representable. Cost: one herdr-setup script writing an unpromised format; it edits only weights and child order of one column, verifies by a second `doc.get`, and fails loudly on anything else.
2. Rejected: (a) unequal accepted: contradicts operator words. (b) halving order only: equal for 2, 4, 8 seats only (intake 2026-11-06). (c) wait for a herdr-app feature: no date; file `herdr-app feedback` anyway so the helper can be deleted later. (d) labels at start: side by side in arrival order (intake). (e) restart by kill and keep without the helper: the pane lands under the focused pane, not its old spot (intake "Every seat restart lost its pane placement").
3. Evidence: `hc schema` `doc.set` (name, value up to 1 MiB, `version` from `doc.get`, CAS), `doc.get` live read 2026-11-06 (shape above), AGENTS.md "The model" (structural commands fail while the layout is unavailable; newest accepted document wins), intake 2026-11-03 and 2026-11-06 findings (keep is pending and racy, ~2 s settle, 4 equal by order, 3 never), `peer-create.ts:33-46` (old herdr had `--ratio`, so equal heights were one argument). Practitioner: tmux separates placement from normalization (`split-window -l 50%`, then `select-layout even-vertical`; tmux reference and tmux source, read 2026-11-06), the same two-step the helper does; zellij and wezterm results not found.
4. Pitfalls: P7 `doc.set` version conflict with the app's own write during a drag: removed by CAS retry three times and giving up with a message, never overwriting without the latest version. P8 herdr-app changes the document shape: removed by a strict schema on the read, refusing to write anything it did not fully parse, and a test pinned to a recorded `doc.get`. P9 keep race after a restart: removed by the retry-until-listed loop already proven. P10 a consultant re-placed while the operator types in A: `pane.focus` moves focus; removed by the helper ending with `pane.focus --terminal <A>`.
5. Question not asked: does the operator want the column rule for direct-route reviewers too (same tab as the door, right column), or a tab per reviewer?

## Q4. One start command

1. Pick: `akrogon start` (the one piece of hc code 1a allows) takes repo, role (`leaf <slug> <A|B>`, `slot <letter>`, `review <n>`), the seat kind, the first task, and cwd; it reads the argv template from `harnesses:` (`src/next.ts:294-303`, so codex sandbox flags live in config, config fork), builds the name by the identity rule, the labels (constant filter, `akrogon.repo/leaf/seat`, plus `herdr.space`/`herdr.tab` for leaf roles), pins `HC_SESSION` and strips terminal selectors, runs `hc run --bg --name ... --cwd ... --label ... [--no-parent] -- <argv> "<task>"`, then checks `hc get <name>`: `first_message.sent: true`, `state: live`, status `working` or `turn >= 1` once (no loop); then places the pane (leaf: nothing more; consultant or reviewer: keep in column, retry until listed, weights helper); prints one JSON line `{name, address, created_ms, tab, pane, first_message}` and exits non-zero naming the failed step with `hc read` of the screen attached. `--replace` does kill, wait for `finished`, `hc rm`, then the same run and placement. Callers: the engine's dispatcher calls the same function; door and direct review call `akrogon start ...` from skill text. Cost: one command with three roles; a door cannot start a seat any other way.
2. Rejected: (a) hc templates (`~/.config/herdr-core/templates`): argv would live outside the repo, and the intake wants the report line in the brief, not in a template. (b) `hc wait`-based readiness loops: the first task in `run` is hc's own rule; a failed `sent` is read, not resent (manual). (c) separate scripts per caller (today's `peer-create`, `peer-restart`, engine code): three places to forget a pane, which is what the intake records three times.
3. Evidence: `hc --skill` "Delegate a task" (first task in run, `first_message.sent`, do not blindly resend), intake 2026-11-03 (`ready` check, late reports, `--if idle` refused), 2026-11-05 (codex sandbox network flag), `src/next.ts:788-800` (today's start: name, kind, pane, timeout), `peer-restart.ts:47-48` (old herdr freed a name about a second after exit; hc frees it at `finished`, intake test 3).
4. Pitfalls: P11 `sent: true` with the prompt stuck in an input box or a popup (intake): removed by the `turn >= 1` or `working` check and a non-zero exit with the screen. P12 a restart under the same name before hc marks the old one `finished` (`name_taken`): removed by waiting on `hc wait <name>` after `hc kill`, then `hc rm`. P13 the command run from a seat's shell inherits that seat's env (`AKROGON_BASE`, `TMPDIR`): removed by the command building the env from config as `allocate` does today (`src/next.ts:567-578`).
5. Question not asked: does `akrogon start` also own `akrogon stop <name>` (kill, rm, release the slot) so the closed verb list of the hc module stays in one file? I would say yes.
