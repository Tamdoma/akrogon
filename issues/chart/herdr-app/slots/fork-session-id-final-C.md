# session-id final check, C (2026-11-06)

The path form works: no reader needs the id itself. `chart-usage.ts` uses the value only to find the file (`locate`, lines 130-148; claude and codex branches treat it as an id, pi as a path) and to print a label (line 642), so `locate` collapses to "the value is the file" for every kind; `log-tail.ts` already takes a path; hc labels are free-form strings (`terminal.label`, `hc schema`), so a path fits. Three points on the record:

1. Lookup order. "`foreground.pid` then `pid`" picks the wrong transcript when the seat's foreground is a nested harness run as a tool (a `claude -p` or `codex exec` child holds its own `tasks` or rollout fd). Read `pid` (the program hc started) first and only fall to children when it holds no transcript; `foreground.pid` never comes first.
2. Claude derivation. `/tmp/claude-<uid>/<enc cwd>/<id>/tasks` to `<projects root>/<enc cwd>/<id>.jsonl` must use the same projects root `chart-usage.ts:132` uses (`CLAUDE_CONFIG_DIR`, else `~/.claude`); probe at handoff: the derived file exists for a seat started in a worktree cwd (the encoding of `/home/ivan/.akrogon/worktrees/...` matched on this machine, `~/.claude/projects/-home-ivan--akrogon-worktrees-...`).
3. Skill text. `skills/chart-issues/SKILL.md` lines 39, 137 and 147 speak of session ids and compare them (same id continues after compaction, a different id starts attended); the comparison holds on paths, since `/clear` and `/new` change the file, but the wording and the "never with a null session" rule move to the path form in the chart-door leaf.
