# Fork notes chart-door: slot D

## Q1. Consultants: create, ask, collect; what replaces peer-wait; which scripts survive?

Pick: All peer-* scripts die. Create and restart go through the start verb (start-and-pane Taken: consultants are the door's hc children, restart is the door's `hc kill` then the same start, weights helper only on roster change). Ask is one plain `hc send <name> "You are slot <X>. Read and follow <brief path>"` per seat after the brief file is written, with the send's returned turn and the seat's current address noted in seats.yaml as the exchange identity. Collect is by artifact at every door wake: a seat counts only when its return file for this exchange exists and its report came from its current address (delivery Taken Q4). The safety net replacing peer-wait is hc's own child notes plus one bounded collection wait: consultants are the door's children with notifications on, so a child that blocks, errors, or exits types a note into the door without any script; the door does its own merge work between sends and may end its turn with exchanges open, woken by reports and notes as new input. Only at a hard collection gate (before a restart, handoff, or handover, the points where today "every prompted exchange is collected" is required) and only when the door has no other work left does it run one foreground `hc wait --children any` at a time, artifact-checking after each return; a `timeout` return is a check-in that triggers a screen read of any still-missing seat, then the delivery nudge or drop. Surviving scripts: `chart-usage.ts` (session-id path inputs), `direct-guards.ts` (untied to herdr), and a rewritten `door-reset.ts` (Q2). `peer-anchor`'s job becomes skill-text checks the start verb already anchors: the door's own terminal is `$HC_TERMINAL_ID`, and before any send or kill the door's target must be a seat-record name whose `hc get` parent is that address.
Reason: this is exactly how this session already ran (my own evidence: every round arrived as one `hc send` pointer from t15, I reported with `hc send t15 "done D: <path>"`, and the door's turn count advanced on those reports), and the one failure it produced, E's silent stop, was a finished turn with no file, which no wait can distinguish from success and the artifact check catches by construction (INTAKE 2026-11-06). Peer-wait's 347 lines existed to prove a turn ended per harness kind (claude transcript, pi authority, codex rollout boundaries); hc turns plus return files make that proof unnecessary, and its budget-outcome vocabulary (`done|blocked|failure|budget`, `signal: proven|unproven`, verbatim exchange reruns) is replaced by delivery's reported/silent-nudged/dropped. Cost: if a child ends a turn silently and hc posts no note for an ordinary turn end, the door learns only at its next wake or collection wait, never mid-thought; and "A stays in its own turn while a peer turn is open" (questions.md) inverts — the door now visibly idles between send and reports, which the agents list explains by its working children.
Rejected: keeping a standing `hc wait --children` as the normal collection loop (the door's foreground command is then a timed block that a harness can move to background on message arrival, as Claude Code already did in intake testing, and it burns the door's turn doing nothing the messages do not). Nothing beyond reports (a child that crashes or blocks without reporting then depends on the operator noticing; child notes exist precisely for cannot-report cases, `hc --skill`). Porting peer-wait's per-kind end signals to hc transcripts (rebuilding the machine the substrate deletes; turn plus artifact is the proof now). A slim peer-ask wrapper for symmetry (signpost 1a: plain hc commands in skill text; a wrapper would only forward argv).
Evidence: operator clarification (no polling/waiting, `<hc>` messages); better-than-training: my own session as ak-slot-d (briefs by send, reports by send, `hc ls` parent t15, 2026-11-06), E's silent stop (INTAKE), `skills/chart-issues/scripts/peer-create.ts`, `peer-ask.ts`, `peer-wait.ts`, `peer-anchor.ts`, `peer-restart.ts`, questions.md peer rules (read 2026-11-06), `hc --skill` child notes and wait semantics, delivery/start Takens.
Pitfalls: (a) hc may post no note for an ordinary silent turn end, and `notes = false` in `~/.config/herdr-core/config.toml` disables child notes and `<hc>` wrapping entirely (`hc --help` settings line). Removed by probe per kind (a child told to end its turn without reporting: what reaches the parent?) and by an Open gate that detects `notes = false` and says the door cannot run consultants under it. (b) The door ending its turn with exchanges open can look finished to the operator. Removed by the door's last line before ending naming the outstanding seats and return files, as the printed footer already requires state to be named. (c) Queued duplicate wakes after collection re-run artifact checks; harmless by construction, bounded by the same coalescing the watcher took (several wakes, one check). (d) Operator-supplied consultant terminals (not door-created) cannot be kill-restarted by the door without ending a terminal it does not own, where peer-restart restarted the agent inside its pane. Removed by rule, stated in Q3: supplied terminals are used as-is and never restarted by the door.
Not asked: may the door start its own read-only sub-agents (not consultants) while waiting, and do their child notes get confused with consultant signals? The artifact rule makes them harmless, but the fork never says whether non-consultant children are in bounds for a door.

## Q2. A's own reset at handover

Pick: `door-reset.ts` survives, rewritten on hc events, same outer shape as today: old A appends the handover Mode entry, spawns the helper detached, and ends its turn. The helper follows `hc events --terminal <A>` until A's turn ends, re-checks the transcript for operator input after the queue boundary (the superseded rule, one read at turn end and one last read before sending, not a poll loop), types the reset command as keystrokes with `hc keys <A> / c l e a r enter` (kind map unchanged: claude `/clear`, codex and pi `/new`), follows events until the session-id resolver on A's pid returns a different transcript path, then `hc send`s the start prompt, each step appended to the handover log as today. Fresh A finds the handover exactly as today: the start prompt names its terminal, the handover time, the next chart, its absolute folder, and this skill's absolute path; it continues only when the latest Mode entry is that unconsumed handover and its own current transcript path differs from the path old A recorded in it, appends the continue entry, records its seat by transcript path, and opens its span.
Reason: handover's guards are the point of the current 295-line script and they all still matter: reset only after the bound turn provably ended, operator input after the queue point cancels, start prompt only after a new session proves the reset took (`door-reset.ts` child flow, read 2026-11-06). Keeping them in a detached helper preserves every behavior while swapping herdr pane reads for `hc events`/`hc get` and herdr prompts for `hc keys`/`hc send`. Sending the slash command by `hc send` from the helper cannot work (wrapped as `<hc>` chat it never executes, intake), while keystrokes are terminal input regardless of sender. A stays in the same terminal throughout, so consultant parentage, tab layout, labels, and report routing never change. Cost: one script survives the port with real sequencing logic, and `hc keys` typing a slash command is sensitive to the harness input box holding leftover text, which the helper must check (`hc read` shows an empty prompt at turn end) before typing.
Rejected: A sends itself `/clear` then the start prompt with two self-sends (own sends do arrive unwrapped, intake-tested, but the ordering against an operator message queued in between is harness queue behavior, unproven per kind, and once queued nothing can recheck the superseded boundary — the exact failure door-reset's last check exists to stop; it also has no actor left to prove a new session before the start prompt, so a clear that did not take feeds the start prompt to old A in its old context). A successor door started fresh (consultants are the old terminal's children and die with it; leaving the old terminal open as a shell keeps them alive but their reports then type into a terminal with no door session, and moving A breaks the operator's chart tab). Same-session handover for all kinds (handover exists to bound A's context per chart; only kinds without a reset command keep same-session, as today).
Evidence: better-than-training: SKILL.md `## Handover` (entry shape, superseded rule, fresh-A matching rule, supported kinds), `door-reset.ts` (detached child, turn-bound and confirm bounds, identity and operator-input checks), INTAKE (wrapped `/clear` does not execute; own-terminal sends unwrapped; codex `/new` turn miscounts), `hc keys --help`, `hc events --help`, read/run 2026-11-06.
Pitfalls: (a) Codex `/new`'s own short turn miscounted waits in intake testing. Removed by confirming on transcript-path change, never on turn numbers, as the pick does. (b) The helper typing into a pane whose input box holds an operator's half-typed line sends garbage. Removed by the empty-prompt screen check plus the superseded recheck immediately before typing. (c) The helper outlives a door that gets killed mid-reset. Removed by the log file: each step is appended before it is taken, so an operator or fresh A can see exactly how far it got, as today. (d) Handover under autopilot must not wait for a human at any step; the helper's only waits are event follows with the existing bounds (10-minute turn bound, 60-second confirm) becoming event deadlines, after which it logs and stops, leaving the next operator or watcher message to find a stated state.
Not asked: after a handover to a chart whose folder old A created, fresh A writes seats.yaml on entry (today's exception), but the charter-folder-at-open rule from the intake now wants the folder complete at open; the fork never reconciles which rule wins for handover-created folders.

## Q3. Gates and records beyond the named swaps

Pick: The named swaps stand — `HC_TERMINAL_ID` present and `hc get $HC_TERMINAL_ID` answering replaces `HERDR_ENV=1` everywhere it gates (peer creation, autopilot start), with the same outside-hc sentences and single-slot continuation; the temp-path rule is deleted and the chart folder with `seats.yaml` is created at Open (intake rule). Beyond those, the herdr-tied text that changes: requested consultant geometry becomes the start Taken's (A left 50%, column in naming order, equal heights by the herdr-setup helper), replacing the 65/35 text in SKILL.md and questions.md; named supplied panes become operator-supplied consultant terminals, addressed by name or address, used as given, never moved, and — the one behavior cut — never restarted by the door (context reset applies to door-created consultants only, since restart is now kill plus start of a terminal the door owns); every outcome-line rule keyed on peer script output (`restarted` lines, exchange session fields, `budget` reruns, "idle does not prove collection") is rewritten onto start's output line, the send's returned turn, and the artifact rule, with collected never inferred from status alone; seat entries append on address or transcript-path change instead of session-id change; the Mode record's session-id uses and the same/different-session continuation after compaction compare transcript paths through the resolver on A's own terminal, with an unknown current path never counting as the same conversation (session-id corrections). What does not change: spans, open time, names and letters, drop rules, the signposts and handoff machinery, `akrogon pull` at open.
Reason: each item is a straight substrate translation of a rule whose purpose survives; only supplied-terminal restart has no equivalent, because restart changed from "new agent process in your pane" to "new terminal", and applying that to a terminal the operator supplied destroys their session to satisfy a bookkeeping rule. Naming that cut explicitly in the skill text is cheaper than a mechanism (asking a supplied consultant to restart itself cannot work: a slash command from the door arrives wrapped). Cost: an operator who supplies long-lived consultant terminals must restart them by hand between charts if they want empty contexts, and the skill must say so at Open when peers are supplied.
Rejected: keeping the temp-path rule for pre-folder work (the operator already ruled the folder exists from open; two record homes was the complexity). Treating `HC_TERMINAL_ID` presence alone as the gate (a copied environment variable in a plain shell passes while no core answers; peer-anchor existed for exactly this class). Recording a pane id beside the address "for layout" (panes are views, re-read from the document when needed, identity Taken). Letting the door restart supplied terminals by killing and recreating them under the same name in the same spot (the original terminal and its scrollback are the operator's; recreation also steals the name).
Evidence: better-than-training: SKILL.md Open/Handover/Autopilot sections (gate at line 27 in current text, supplied panes, seat record, mode continuation), questions.md peer geometry and wait rules, session-id corrections (path wording moves to this fork), start Taken geometry, INTAKE chart-folder-from-open rule; read 2026-11-06.
Pitfalls: (a) A stale `HC_TERMINAL_ID` naming a finished terminal passes the presence test. Removed by the `hc get` half of the gate. (b) Old chart folders on disk hold seats.yaml in pane/session form; the door reading them after cutover must treat them as historical (usage reads paths-or-ids as session-id's corrections already require for chart-usage) and never as live addresses. (c) The direct route's reviewer is a door-started consultant for record purposes (name still open from the identity fork); its seat entry and collection follow the same artifact rule or its silent stop has no catch. (d) Renaming the gate leaves `HERDR_ENV` strings in brief templates and fixtures elsewhere in the repo; the final sweep's no-herdr-wording done-criterion (cutover fork) is what catches stragglers, not this fork's edits alone.
Not asked: when the operator supplies consultant terminals, who owns their pane geometry — the start Taken's column rule was written for door-created panes, and neither fork asks whether the door may even suggest placement for supplied ones. My pick: never moves them, as today.
