## Q1. Which hc session and space, and how does the engine find it?

1. Pick: the repo's hc session is one config line (`repos.<name>.session`, default `default`), and the space is found by name the way `resolveSession` finds a workspace by label: `herdr-app ls` of that session (`HERDR_APP_HOME` and `HC_SESSION` set as `herdrapp` does, `bin/herdrapp:60-62`), one space whose `name` equals the repo name; several or none refuse with the same reasons as today (`src/shell.ts:379-425`). The space id is then written as `herdr.space` on every akrogon terminal, so once one terminal of the repo is live the engine reads the id from `hc ls --label akrogon.repo=<name>` and no longer needs the window. Reason: this is the old shape (label lookup, refuse on ambiguity) with the session enumeration replaced by one config field, because `herdr-app ls` answers only through an open window (`herdr-app --skill` "Inspect before acting") while old `workspace list` answered from the server. Cost: one new key per repo in `~/.akrogon/config.yaml`, and the first leaf of a repo needs the window open once.
2. Rejected: (a) Enumerate sessions through `herdrapp session list --json` and `herdr-app ls` each: closest in shape, but every pass needs every session's window open, and `herdrapp` is a herdr-setup script, which would make the engine depend on herdr-setup. (b) Space folder match: wrong today, shifted by one (`herdr-app ls`, map-merged corrections). (c) akrogon mints its own stable space id (`hc run --label herdr.space=<minted>` creates a space, AGENTS.md "An id Herdr doesn't know becomes a new space"): elegant for a fresh machine, but duplicates the seven spaces the operator already named; keep as the rule for a repo with no space, not as the lookup. (d) One hc session per repo: splits the operator's windows, rejected by every map.
3. Evidence: code `src/shell.ts:379-425` (search running sessions, match label, refuse duplicates), `src/next.ts:521-523` (session and workspace id feed every call); command 2026-11-06: `herdr session list` shows `default`, `infra`, `mdconsultingny`, `personal` running; `herdr --session infra workspace list` shows labels `akrogon`, `framework`, `portal`, `portal-old`, `pi-extensions`, `blepsis`, `website`, `lens`, `varhop`, `herdr-setup`; `herdr-app ls` in `infra` shows spaces `akrogon`, `framework`, `portal`, `extensions`, `blepsis`, `pricing`, `herdr-setup` (note `extensions`, not `pi-extensions`, so one space name already differs from its repo name and would need a rename or a config override); `ls ~/.config/herdr-app-sessions` = `infra`, `mdconsultingny`, `personal`. AGENTS.md "The model": labels `herdr.space`, `herdr.tab` place a terminal; a named space keeps its name. Practitioner: trusty-mpm and a codev PR (read 2026-11-06, docs.rs and github.com) both derive job identity from the project and store the mapping, after random or spec-only names collided across projects; neither discovers the project from the multiplexer.
4. Pitfalls: P1 space renamed by the operator, lookup fails: removed by the label path (live terminals carry the id) and a `space unknown` wait reason in `akrogon status`, as session refusals print today. P2 two spaces with the repo's name (a worktree space nests under its repo, AGENTS.md `worktree` mod): removed by refusing on duplicates, the old rule. P3 window closed when a repo's first leaf starts: removed by the wait reason and by the engine never blocking other repos on it. P4 `extensions` vs `pi-extensions`: operator step, rename the space or set `space:` in config.
5. Question not asked: should the engine create the tab with `herdr.tab=<minted id>` on `hc run` (the app makes the tab, then `tab.rename` to the slug), or with `tab.new --name <slug>` (which also starts a shell pane the leaf does not want)? Belongs to start-and-pane, but identity must say which id state stores: the minted id works with the window closed.

## Q2. What does leaf state store?

1. Pick: `session` (hc session name), `space` (id), `tab` (herdr.tab id, same field as today), and per seat `seat.A = {name, address, started_ms}`, with `prompted.A = {address, turn}` replacing the agent session id and `delivery_error.pane` becoming `address`. Labels on every seat terminal: `akrogon=1` (the listener's constant filter), `akrogon.repo`, `akrogon.leaf`, `akrogon.seat`, plus `herdr.space`, `herdr.tab`. Reason: name is what a restart reuses, address is what `pane.focus --terminal` and stale-report refusal need, `turn` is hc's own counter and replaces the session-file byte offset for "did my prompt start a turn". Cost: a state schema change with no migration (cutover drains open leaves, map fork 14).
2. Rejected: (a) address only: changes on restart (intake test 3), so every restart edits state. (b) name only: `pane.focus` and the stale-report check need the instance; `hc get <name>` resolves it but a replaced seat under the same name would pass. (c) keeping an agent session id field: hc has none (`hc get t6d --json` lists `name`, `labels`, `parent`, `foreground`, `status`, `turn`; no session), decided in fork session-id.
3. Evidence: `src/state.ts:99-102` (`tab`, `pane`, `prompted`, `prompted_at`), `src/next.ts:704-713` (`prompted` and `PROMPT_GRACE_MS` guard keyed on session id), `:788` (agent name `akrogon-<24 hex of pane id>`), `src/reconcile.ts:222-275,405-428` (every keep and close decision keys on `state.tab` and pane cwd inside the worktree: both survive, cwd comes from `hc get` `foreground.cwd`), `src/status.ts:161-199` (prints busy and delivery per seat, no ids); `hc ls --help` (`--label` repeatable, all must match); `hc run --help` (`--label`, `--name`).
4. Pitfalls: P5 a seat restarted by hand under the same name is not the recorded address, so a `done` from it is refused: removed by the engine updating `address` whenever `hc get <name>` differs and the leaf's `turn` moved (design part), with the stale check on address plus `started_ms`. P6 `where` label (`akrogon / c-akrogon`) looks like an identity but is app-written (low confidence on its owner): removed by never reading it. P7 `herdr.seen` and other app labels change under the engine: removed by reading only `akrogon.*` and `herdr.space`/`herdr.tab`.
5. Question not asked: does `seats.yaml` (chart door) take the same `{name, address, started_ms}` shape so one reader serves board-focus and USAGE? I would say yes, one shape.

## Q3. Names

1. Pick: consultants `<prefix>-slot-<letter>` as the intake binds; leaf seats `<prefix>-l<12 hex of repo/slug>-<a|b>`, the hash the slice already uses (`src/scope.ts:13-14`, `akrogon-l<12 hex>`), 18 characters; the prefix is a per-repo config field, not derived from the name. Reason: 2 of the operator's own prefixes are not the first two letters (`fw` for framework, `hs` for herdr-setup, intake), and slugs run past the 32-character name limit (`technical-seo-audit-contradictions` is 34; 1501 closed leaves measured, several over 27), so a readable slug cannot fit `<prefix>-<slug>-a`. The slug stays readable in `akrogon.leaf` and in the tab name. Cost: a leaf name is not human-readable in `hc ls`; `hc ls --label akrogon.leaf=<slug>` is the lookup.
2. Rejected: (a) `<prefix>-<slug>-a` with truncation: two slugs sharing 27 characters collide silently. (b) derive prefix from the first two letters: contradicts the operator's `fw` and `hs`. (c) append the door address to consultant names to allow two doors on one repo: the intake rule is binding; a second door on the same repo gets `name_taken` from hc (intake, framework door) and the helper prints the live owner's `parent` so the operator closes one or passes another prefix.
3. Evidence: `hc run --help` (1-32 of `a-z 0-9 - _`, unique among live terminals); intake "Consultant names" (`ak-`, `fw-`, `hs-` in use); `src/scope.ts:14` (existing 12-hex leaf hash); `src/next.ts:788` (old agent names were already hashes); command 2026-11-06 slug length measurement; all measured slugs match `[a-z0-9_-]`.
4. Pitfalls: P8 two registered repos configured with the same prefix: removed by `akrogon config` refusing duplicate prefixes (leaf done-criterion). P9 a finished terminal under the name is not `live`, so restart works, but `hc ls --all` shows both: removed by `hc rm` of the finished one in the restart step. P10 a killed seat's name reused while its process lingers (kill escalates, `hc kill --help`): removed by waiting for `state: finished` before `hc run`, probe once per harness.
5. Question not asked: who assigns a prefix for the ten repos registered today? One operator step at cutover, written into `~/.akrogon/config.yaml` next to each repo path.
