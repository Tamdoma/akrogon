Drop the log tail and judge busy seats from the screen (screen-only is today's degraded path: `hc read` on a working seat returns only the visible screen, while the transcript carries structured tool calls; the watcher's steer (esc, re-prompt) would rest on weaker evidence, a workflow change in substance). ## Q2. For kept features, how is a seat's session id or transcript known?

Pick: At start, per harness, inside the one start command. Claude: append `--session-id <fresh uuid>`; pi: append `--session-id <fresh id>`; both recorded in start's output line and stored per seat. Codex (no choose flag): snapshot-diff capture: list `~/.codex/sessions` rollout files (respecting `CODEX_HOME`, as `chart-usage.ts:142`) before `hc run`, and after delivery proof (delivery Taken: working/turn within 60 s) list again; if exactly one new `rollout-*-<id>.jsonl` appeared and its first records' cwd equals the seat's cwd, record that id, otherwise record unknown. Agy: unknown (no choose flag in `agy --help`, only `--conversation` to resume an existing one; and no akrogon transcript parser exists for it today). Start refuses a harness argv that already carries resume/continue/session flags instead of layering a second session selector on it (the ban list precedent in `skills/chart-issues/scripts/peer-restart.ts:56-57`).
Reason: choosing the id is exact knowledge with zero searching, and both flags are first-class (`claude --help`: `--session-id <uuid>`; `pi --help`: `--session-id <id>` "creating it otherwise", checked 2026-11-06). Locating transcripts then reuses the existing finders nearly unchanged: claude `<id>.jsonl` under projects, codex `rollout-*-<id>.jsonl`, pi suffix `_<id>.jsonl` (`src/session-file.ts:17`; chart-usage's pi branch today expects a path and needs the id search instead). The codex capture is a set difference with a uniqueness and cwd check, so its failure mode is "unknown", never a wrong id; engine and door starts are serialized per seat, and snapshot state is per start invocation. Cost: start grows per-harness knowledge (the place 1a allows code), codex capture depends on rollout file timing and location, and a fresh id must be minted per incarnation because both chosen-id flags reuse an existing session if given the same id.
Rejected: find-afterwards by cwd and start time as the general mechanism (two seats of one leaf share a worktree cwd; concurrent same-kind seats make newest-file guessing wrong in exactly the parallel case, and a wrong transcript fed to the watcher's steer is worse than no transcript). Snapshot-diff for claude/pi too instead of choosing (strictly weaker than an offered flag). A herdr-setup patch to expose the id (agents do not report a session id through OSC status, so hc has nothing to expose; a patch would mean hc scraping harness files, the rejected heuristic in a worse home, and herdr-setup has no binary patch mechanism per the map corrections; an upstream `herdr-app feedback` ask is the right channel). Recording the transcript path once and never the id (usage and log both print ids, and paths embed dates that the id finders already handle).
Evidence: better-than-training: harness `--help` runs 2026-11-06 (above; codex has `resume`/`archive` by id but no start-time choose flag, agy `--conversation` resume only); `chart-usage.ts:130-149`, `src/session-file.ts:11-31`, `observe.ts:157-175`; model-knowledge: transcript-scanning usage tools exist for claude/codex session folders, but they attribute by file, not by live seat, which is the part needing the id.

## Q3. What does a kept feature do when the id is unknown?

Pick: Each feature does what it already does on a miss, stated per seat, never substituted. Chart usage: the seat is listed unmeasured with the reason (unknown harness, no id captured, or transcript not found), the outcome is partial, and the handoff proceeds. Watcher: observe prints `log<seat>=-`, the watcher judges the busy seat from `hc read` and reports `no log`, with the steer bar unchanged (a read failure alone never justifies a steer). `log.jsonl`/`timings.jsonl`: `session: null`, as the schemas already allow. seats.yaml: the entry is keyed by seat, name, and address with session absent; a missing session never blocks a restart (the old "never with a null session" seat-entry rule, SKILL.md:29, was herdr-shaped and is dropped with the substrate). No feature falls back to finding a transcript by cwd/time guessing.
Reason: every one of these degraded paths already exists and is exercised today (agy seats, a stopped session yielding no pane at `src/log.ts:40-46`, pi entries `resolveLog` cannot place). Keeping them preserves signpost 2a's no-fallback rule in the right sense: unknown is a stated outcome, not a second mechanism quietly producing numbers. Cost, stated plainly: codex seats regress from measured (old herdr reported codex ids) to measured-only-when-capture-succeeds, and agy stays unmeasured, so chart usage under-reports whenever those kinds carry a chart; the figure is a floor, and the review lines must say so per seat, as they already do for errors.
Rejected: estimate usage from turns or elapsed time for unknown seats (a fabricated number at a price decision point). Block start or handoff until the id is captured (usage never blocked before; a codex capture miss would stall real work over accounting). Watcher steers from a best-guess transcript (acting on another seat's tool calls can stop a healthy seat). Retry capture on every later pass until found (the snapshot window has passed; later search is the rejected cwd/time heuristic with extra steps).
Evidence: better-than-training: SKILL.md:73 (partial outcome continues), watch-issues SKILL.md Busy rule (`log=-` judge from visible screen, report no log), `src/log.ts:21,51` and `src/timing.ts:31` nullable session, `chart-usage.ts:572-596` per-seat error collection; read 2026-11-06.
Pitfalls: (a) "Unmeasured" becomes routine for a whole kind and nobody notices the feature died (a harness update moves its session folder). Removed by a usage/observe done-criterion in the port leaves: a real claude, codex, and pi seat each resolve to their transcript, and a kind that stops resolving shows as an error line per seat, which the handoff review prints. (b) A codex capture that succeeds at start but whose rollout is later archived by the operator (`codex archive`, in `codex --help`) makes usage report a missing file at handoff. Accepted: reported as missing with the path detail, same as today. (c) Watcher loop judgment on screen-only seats (agy leaf seats) has less history because `hc read` while working returns the visible screen only. Removed only by the existing higher bar for steering; recorded as the known cost for agy seats until a transcript source exists.
Not asked: does the operator want agy transcripts hunted down at all (its conversation storage is uninspected in this repo), or is agy's exclusion from usage and log tail accepted permanently rather than as a port gap?
