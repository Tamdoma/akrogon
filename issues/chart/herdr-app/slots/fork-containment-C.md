## Q2. How: wrap at start
1. Pick: wrap. The start command's argv is `systemd-run --user --scope --quiet --expand-environment=no --unit=akrogon-l<12 hex>-<hc address>.scope --slice=<leaf slice> -p TimeoutStopSec=5 -p CollectMode=inactive-or-failed -- env K=V ... -- <harness argv> "<task>"`, the same shape as check runs (`src/scope.ts:43-60`); the unit name takes the hc address (permanent per core, `hc schema` Terminal.address), so a restart never collides with an abandoned scope. The box exists before the harness runs, so every child inherits it; verification is one read of `/proc/<pid>/cgroup` ending in `/<leaf slice>/<unit>` after the start proof (today's `inOwnScope` test, `src/scope.ts:205`), no loop, no retry. `adoptShell`, `paneShell`, `paneScope` and the 5 s poll go. Reason: fewest parts (no busctl, no pid migration, nothing akrogon moves), no polling, and the thing that could go wrong with a move (B's risk: migrating the wrong pid, which in the holder cgroup could be the core itself) cannot happen. Cost: the `hc get` address is needed before the argv is built, so the start command mints nothing itself; it is known only after `hc run`. So the unit name uses the hc name instead (`<prefix>-<slug>-<a|b>`, identity Q3, unique among live terminals) plus `created_ms`... simpler: `--unit=akrogon-l<hash>-<seat name>-<random 8 hex>.scope`; the record keeps the unit name for the sweep and for `stopRunUnits`.
2. Rejected: move after start with `hc get` pid (today's mechanism, but under hc it is a pid migration out of the holder's cgroup, children started in the first second stay behind, it needs busctl and the poll loop, and a wrong pid is the core); `terminal.run` with a `scope`-like option (hc has none); boxing by `hc`'s own `HC_SCOPE` (that variable is hc's terminal selector, not a cgroup).
3. Evidence: better-than-training, `src/scope.ts:43-60,147-208`, `src/next.ts:618-636`, `man systemd-run`, `systemctl --user show hc-hold-105b0ede.service` (`KillMode=process`: the holder's stop never killed seats anyway, so leaving its cgroup changes no shutdown behaviour), 2026-11-06.
4. Pitfalls: exec versus fork (P1 above); `systemd-run` missing from the holder's PATH (removed: absolute path is not needed, the holder is a systemd user service with the login PATH, `hc --skill` "Programs get the login session's environment"; e2e covers it); codex's own sandbox inside a scope (probe P2: a codex seat with `-s workspace-write` runs a command and reports by `hc send`); an OOM kill looks like a silent exit (removed: hc keeps `exit_code` and `signal` on the finished record, the listener's `finished` event wakes `next`, and the restart path is today's; the journal line names the scope); the unit name reaching systemd's length limit (removed: hash plus a 32-char name is well under 256).
5. Question: none.
