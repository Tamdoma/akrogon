## Q1: replacement fakes

- D1 Pick: one small scripted command-fixture implementation exposed as test-only `hc` and `herdr-app` binaries. Keep ordinary CLI/engine tests going through the production hc module, subprocess environment, JSON parsing and errors. Supply captured real responses/event frames, explicit failures and expected mutations. Unknown commands fail. Cost: capture upkeep and porting the existing fixtures.
- O1 Reject a fake only at the hc module boundary as the main fixture. It bypasses the very environment stripping, endpoint selection, argv and response decoding this migration changes. Pure decision functions can be tested directly without another fake runtime.
- O2 Reject a real core for most regression cases. Slow-start, missed events, malformed responses, partial delivery and races need deterministic fault injection. Repeated real daemon lifetimes add cleanup and timing work without making those cases easier to prove.
- E1 Practitioner: [libtmux's testing guide](https://libtmux.git-pull.com/api/testing/pytest-plugin/usage/) uses private real servers and owned teardown, including distinct servers for restart/multiple-server tests. This supports real integration fixtures, not replacing deterministic fault tests with live servers. Better-than-training, local: `tests/helpers.ts:133` injects command binaries through PATH; `tests/isolation.ts:65` bundles them; `src/shell.ts:230` owns subprocess/JSON parsing. `hc schema` and the run/events help show the new protocol differs from old herdr.
- R1 Shared mistakes in fake and production schemas: capture JSON independently from real hc/app and validate it through the production boundary. Do not import production schemas to construct successful fake replies, as `tests/fake-herdr.ts:11` does today. Test malformed/missing fields, permitted null status and actual hc `error.kind`, not the old result envelope/error code.
- R2 Recreating the 524-line terminal simulator: the fixture returns planned facts and records calls, rather than implementing pane geometry, process adoption or agent lifecycle. Assert ownership, accepted task count and effects. Avoid freezing incidental read order/counts. Unplanned mutations and unconsumed required effects fail.
- R3 A fake that falls through to installed binaries: fixture selection must be explicit and unexpected calls must fail. Keep fake state private per fixture. Preserve current suite isolation, including subprocess environment isolation under concurrent files (`bunfig.toml:4`, `tests/isolation.ts:50`).
- Q1a Missing question: which externally observed responses/event frames are the minimum contract corpus, and which calls have ordering that matters? Name these with the engine module instead of snapshotting every field and call.
