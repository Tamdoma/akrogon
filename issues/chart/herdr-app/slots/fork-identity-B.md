# Identity: independent notes B

Read 2026-11-06. Picks preserve existing session discovery and state-based ownership where the substrate supports them. Engine-shape Taken is binding, including direct phase dispatch plus event coverage. No terminals changed or paid probes run.
Practitioner research found concrete tmux naming failures and Supervisor's distinction between supervisor, configured process and current process instance. No published hc deployment matching akrogon was found. Their experience informs the choices, not hc guarantees.

## Q1. Repo to session and space

1. Pick: keep automatic discovery across running sessions, matching the registered repo key to an exact named space, like today's workspace-label match. Resolve to an explicit core/session and space ID for that invocation. Each repo has one owning space across running sessions. Never infer ownership from the focused window or a displayed folder. Cost: discovery still needs a supported read of every relevant core's space model. A concrete window-independence gap below must be closed before this choice is promised.
2. Rejected options:
   - Caller HC_SESSION alone: works for a door already in its repo, but not systemd merge work or an engine handling several repos/sessions. It changes existing cross-session routing.
   - New mandatory per-repo session/space configuration: adds machine-specific setup and stale bindings when spaces are recreated. No inspected requirement makes that simpler than existing discovery once the read gap is fixed.
   - Terminal labels alone as initial space discovery: no akrogon terminal exists before a repo's first launch. Labels identify managed terminals after placement, but do not locate a pre-existing empty repo space.
3. Evidence:
   - Practitioner: tmuxinator user rogeriopvl reported that reusing a project name attached to the first existing session instead of making the intended new instance. This is a first-hand naming failure, not hc evidence. [Issue 206, 2014-02-19](https://github.com/tmuxinator/tmuxinator/issues/206), read 2026-11-06. Discovery must resolve the actual owning instance rather than assume a requested name creates one.
   - Operator: `issues/chart/herdr-app/forks/signposts.md:62` favors the existing working behavior. `src/shell.ts:404` matches the repo name exactly, :418 rejects multiple matches, and :419 rejects unknown uniqueness. Preserve those semantics rather than selecting the first match.
   - Better-than-training, live: `herdr session list` returned running default/infra/mdconsultingny/personal and stopped netreachconsulting. `herdr workspace list --session infra` returned akrogon, framework and other named workspaces. `herdrapp session list --json` returned running default/infra/mdconsultingny, stopped personal. These are separate substrate inventories, not interchangeable lists.
   - Better-than-training, live: `herdr-app ls` returned akrogon at folder /home/ivan and framework at the akrogon checkout. This independently confirms folders cannot route repos. `/home/ivan/Work/infra/herdr-setup/bin/herdrapp:62` supplies session/app-home pairs.
4. Pitfalls and removals:
   - A running core has no window. Observed: with inherited HC_TERMINAL_SOCKET/ID/SCOPE unset, `HC_SESSION=mdconsultingny hc ls --json` returned three terminals, while the matching app-home `herdr-app ls` failed “no Herdr window” / connection refused. Removal: prove a public core-backed space read before handoff, patching a missing CLI surface in herdr-setup if necessary. `hc schema` documents doc.get; neither its herdr-app document shape nor an engine-ready invocation was proved here. Do not substitute direct docs.json access or silently skip unreadable cores.
   - A session override still reaches the caller's socket. Removal: the engine's session boundary explicitly controls HC_SESSION and corresponding app home and removes inherited terminal/socket/scope selectors when targeting another core. The read-only mdconsultingny observation above used exactly that separation.
   - Duplicate or renamed spaces change the destination. Removal: exact-match/ambiguity behavior stays as today, with fixtures for zero matches, duplicate names in different cores and an unreadable running core. A rename does not silently become a new ownership rule.
5. Missing question: must discovery work with the app window closed, while the core and listener remain alive? Engine-shape's lifetime strongly suggests yes. The live counterexample makes this a prerequisite capability decision, not an implementer assumption. Also explicitly bound discovery to local configured sessions unless remote execution is requested.

## Q2. Persistent leaf, seat and delivery identity

1. Pick: persist the native leaf tab ID and each current seat's hc terminal address, qualified by owning session/core identity. Derive the stable seat name from its logical key rather than storing another authoritative copy. Put a common `akrogon=1` marker plus full repo/leaf/seat ownership labels on every leaf launch, alongside herdr.space/herdr.tab. The listener can filter `hc events --label akrogon=1`; non-leaf launches retain the marker/repo and their own role identity. Store delivery acknowledgement and its native turn baseline separately from terminal identity. Cost: a small new state shape and explicit replacement binding, while labels supply declared ownership for discovery/reconciliation.
2. Rejected options:
   - Names only: they deliberately survive kill/restart, so a delayed report cannot identify which incarnation sent it.
   - Addresses without core/session qualification: t7 can name different terminals in different cores. A reset/wiped core is also not the previous core simply because its session is still called infra.
   - Persistent pane ID or copied status/label dictionaries as additional authorities: the pane is a view of a terminal, and the core already owns live facts. Focus by terminal address. Keep the tab grouping because existing cleanup and allocation operate on a leaf tab.
   - Turn or harness session ID as terminal identity: turn is a readiness counter and native transcript identity serves different consumers. Resolve transcript/accounting support in its own fork.
3. Evidence:
   - Practitioner: Supervisor's own API separately exposes getIdentification for multiple supervisor instances and getProcessInfo with group/name, start time and pid. Its implementation treats configured names and current process facts as different data. [Supervisor API, Status and Control / Process Control](https://www.supervisord.org/api.html), read 2026-11-06. Applying that separation to hc is my inference.
   - Better-than-training, native schema: `hc schema` describes Terminal.address as this terminal forever on this core, CoreInfo.id as permanent until state is wiped, and Terminal.turn as increasing when status leaves working. `hc server status --json` actually returned core.id, so the core qualifier has an observed read path. These do not make turn a task ID or successful-work receipt.
   - Better-than-training, live: `hc ls --json` returned t6c/name ak-slot-b/parent t15/turn 4, but that CLI entry omitted labels. `hc ls --json --label herdr.space=<observed-akrogon-space>` selected seven actual members. Thus native label filtering works, but listing output must not be parsed as full get metadata. Use the observed get schema for ownership facts.
   - Better-than-training, inspected code: `src/state.ts:95` stores tab and :99-102 store seat/delivery fields. `src/next.ts:591` saves grouping before seats; :708 binds prompting to an agent session. `src/reconcile.ts:419` restricts cleanup to the repo workspace and :428 checks worktree membership. `src/status.ts:640` currently exports seat configuration, not runtime terminal targets.
4. Pitfalls and removals:
   - Replaced seat's late message advances the new seat. Removal: accept its report against the recorded current address/core and current phase/exchange, with an isolated replacement/late-report proof. Native name uniqueness is not a generation check.
   - A kept terminal contains a recovery shell under its old address. Removal: treat that as interrupted work, not a healthy seat. `hc --skill`, **Status, recovery, and cleanup**, explicitly says keep restores a shell without replaying the command. Replacement-run identity depends on the lifetime decision below.
   - Wrong-tab cleanup after a move or manual reuse. Removal: preserve existing repo/tab/worktree ownership checks at the external-data boundary, now backed by native labels and current terminal membership. Runtime status should export the qualified current terminal for board focus, not reconstruct a target from a model name.
   - Persistence races launch. Removal: a leaf criterion interrupts launch between terminal creation and state save, then proves one labeled owned seat is reconciled without creating or killing an unrelated seat. No polling or legacy ID interpretation is introduced.
5. Missing question: will leaf recovery always replace the terminal, or may it restart a harness inside the same kept terminal? If the latter, address alone does not identify the harness run. Settle the supported run identity in lifetime/delivery before promising stale-report rejection. Also define when a repo moved to another core relinquishes its old ownership.

## Q3. Names and collisions

1. Pick: preserve consultant names `<repo-prefix>-slot-<letter>` and their restart reuse. Permit one live chart door per repo per hc session under that naming rule. For leaf seats, retain today's opaque `akrogon-<24 lowercase hex>` shape, but hash an unambiguous full logical tuple (role, registered repo key, leaf slug, seat) rather than a disposable pane ID. This is 32 characters and stable across terminal replacement. Cost: leaf names are not readable, so full identity stays in labels and tab presentation. The native name claim handles concurrent starts.
2. Rejected options:
   - Raw repo/slug/seat concatenation or blind truncation: concatenation has no fixed 32-character bound, and truncating it can collapse different logical identities.
   - Hashing the terminal/pane address: changes the logical seat name on every replacement, defeating same-name restart and lookup.
   - Auto-suffixing an occupied consultant name or quietly adding a chart suffix: changes the binding naming rule and can create a second live owner instead of detecting a collision. A name owned by another task is a refusal, not permission to kill it.
   - Two simultaneous same-repo doors sharing the fixed consultant names: the core cannot assign one live name to two terminals. Supporting parallel doors requires an operator change to the naming rule, not an implicit helper feature.
3. Evidence:
   - Practitioner: tmuxinator's maintainers explicitly provide a separate session-name argument to avoid collisions when reusing one project definition. [README, Starting a session](https://github.com/tmuxinator/tmuxinator#starting-a-session), read 2026-11-06. That is a real solution when parallel instances are wanted. Here the operator already fixed the consultant naming shape, so concurrency needs a separate decision.
   - Operator: INTAKE.md **Consultant names** fixes ak-slot-b/fw-slot-b and same-name restart. Its 2026-11-03 name_taken observation establishes that names are core-wide. `issues/chart/herdr-app/forks/signposts.md:62` favors preserving behavior without extra machinery.
   - Better-than-training: `hc run --help` specifies names unique among live terminals, 1-32 characters a-z/0-9/-/_. `src/next.ts:788` already uses akrogon- plus 24 hash characters, although its input is the old pane ID. `src/init.ts:58` rejects duplicate registered repo keys, which supplies the existing logical repo namespace.
4. Pitfalls and removals:
   - Two distinct repos share the same two-letter abbreviation. Removal: do not claim initials are unique. Compare native name ownership with full repo/role labels and refuse a conflict. The operator must settle the prefix assignment rule below before a helper can derive names reliably.
   - A rare leaf hash collision or an occupied foreign name is mistaken for an existing seat. Removal: the start/reuse boundary compares the full logical ownership tuple after a native name conflict. Mismatched ownership is a visible refusal. No random suffix/retry policy is needed.
   - A restart races a second door. Removal: use the native live-name claim, retain current terminal ownership in the seat record, and prove concurrent requests cannot create two accepted owners. Never preempt an existing seat because its status is idle.
5. Missing question: where does the canonical repo-prefix assignment come from? “Two letters” is not a complete algorithm: akrogon→ak and framework→fw are the settled examples, and different repos can collide. Choose an explicit mapping/assignment rule, and confirm whether same-repo parallel chart doors are actually required. Do not invent either behavior in the implementation.

Most urgent prerequisite: a supported space-discovery read when a core has no app window. The observed mdconsultingny core already exhibits this condition.
