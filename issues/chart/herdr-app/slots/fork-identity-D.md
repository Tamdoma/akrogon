## Q1. Which hc session and space does a repo's work go to, and how does the engine find it?

Pick: Keep the old discovery shape exactly (operator correction: closest to old herdr wins). The engine searches every running hc session, and in each session every herdr-app space whose name equals the repo name; exactly one match is required, otherwise refusal naming searched, stopped, unreadable, and duplicates, mirroring `resolveSession` (`src/shell.ts:379-428`). A session here is herdrapp's unit: `default` plus each `~/.config/herdr-app-sessions/<name>`, running when its core socket exists (herdr-setup `bin/herdrapp:50-55,167-202`); akrogon's hc module enumerates this itself and never shells to herdrapp. Resolution returns hc session name, app home, and space id, memoized per process like `repoSession` (`src/shell.ts:337-349`). Every hc/herdr-app call then carries explicit env for the resolved session (`HC_SESSION`, `HERDR_APP_HOME`, with caller's `HC_TERMINAL_SOCKET/ID/SCOPE` removed), the env equivalent of the old `--session` prefix (`src/shell.ts:226-228`).
Reason: live use is already multi-session with repos grouped by client: old herdr `infra` holds akrogon/framework/portal/… workspaces while `mdconsultingny` repos sit in their own session (`herdr session list`, `herdr workspace list --session infra`, run 2026-11-06), and herdrapp mirrors the same session names (`herdrapp session list`, 2026-11-06). Discovery by name was the old contract and works. Cost: the old failure modes carry over (per-session probing with a deadline, unreadable session refuses everything), plus one new one: `herdr-app ls` needs a running window per session, where old `workspace list` needed only the server.
Rejected: one shared hc session for all repos (forces the operator's client-grouped windows into one; a workflow change disguised as simplification). One `HC_SESSION` per repo (old model was session per client group, workspace per repo; per-repo sessions explode windows and listeners). Pinning session and space id in akrogon config (new config to maintain, space ids are opaque hashes, breaks when the operator moves a space; the correction says keep discovery). Finding the space by its folder (proven wrong, shifted by one, map-merged corrections). Finding it by `akrogon.repo` labels alone (cold start: a repo with no akrogon terminal yet has nothing labeled; labels verify a resolution, they cannot create the first one).
Evidence: operator (correction 2026-11-06 in forks/signposts.md Taken); better-than-training: `src/shell.ts:337-428`, herdr-setup `bin/herdrapp:2-6,58-63`, live `herdr session list` / `herdrapp session list` / `herdr-app ls` (spaces akrogon, framework, portal…, with names `ak-slot-b` etc.), my env `HC_SESSION=infra`, `HERDR_APP_HOME=~/.config/herdr-app-sessions/infra`, all 2026-11-06.
Pitfalls: (a) Core running but window closed: `herdr-app ls` may fail where old resolution succeeded. Removed by probe before handoff; if it fails, design: resolve space id from the `herdr.space` label on already-labeled terminals via `hc ls` (no window needed) and require the window only for a repo's first placement (start-and-pane fork). (b) Operator renames a space (including rename to "", which reverts to a folder-derived name) and resolution stops mid-leaf. Same flaw as old workspace labels; removed only partly, by refusal text naming the space it searched for, never by guessing. (c) A new herdrapp session created after install has no listener unit (engine-shape Taken). Removed by done-criterion: `akrogon status` lists sessions hosting repo spaces that have no live listener. (d) Caller's own `HC_TERMINAL_SOCKET` silently pins hc calls to the wrong core (intake probe method had to unset it). Removed by the explicit-env rule in the pick, tested with the engine invoked from a terminal in a different session.
Not asked: two sessions could each hold a space with the same repo name on purpose (work and test copies). Old code refused duplicates; is refusal still wanted, or should a config pin be the escape hatch for that one case only?

## Q2. What does leaf state store for a leaf and its seats?

Pick: State stores the smallest stable set: `tab` = herdr-app tab id; `term: {A, B}` = deterministic hc terminal names (Q3), replacing `pane`; `born: {A, B}` = each seat terminal's `created_ms` at start, the instance discriminator; `prompted` becomes the `turn` count observed for the seat when the prompt was recorded, still paired with `prompted_at`. Labels are never stored; the start command sets `akrogon.managed=1` (constant, so the listener has an equality filter), `akrogon.repo`, `akrogon.leaf`, `akrogon.seat` on leaf seats, and every later pass verifies name + born + labels + `herdr.tab` == stored tab + cwd inside the worktree before prompting or killing, the mirror of today's tab-ownership checks (`src/next.ts:555-559, 693-702`; reconcile's tab vetoes `src/reconcile.ts:222-225`). Pane id is re-read from `herdr-app ls` by terminal when something needs it (board focus, close).
Reason: names survive restart (intake: use names, addresses change), tab id is still needed to close a finished leaf's tab and to veto worktree removal when terminals are gone, born+turn replace the two jobs `agent_session` did for identity (same-incarnation check and prompt grace, `src/next.ts:762-770`) without scraping harness session files. Cost: two id systems (hc name, app tab) must agree on every pass, and turn semantics differ per harness, so the delivery fork must probe turn behaviour per kind before grace logic is trusted.
Rejected: hc address (`t6f`) as primary key (changes on every restart; every reader grows a stale-address path). Herdr-app pane id as primary key (the pane is a view: park and re-place change it while the terminal and its agent live on). Storing session name and space id as truth (operator can move or rename; old code re-resolved every pass and validated, keep that). Labels only, no state (finished terminals vanish from `hc ls`, and reconcile needs the tab record precisely when nothing is live). Keeping `prompted` as an agent session id from per-harness file lookup (four upstream format bets; session-id fork owns that rejection).
Evidence: better-than-training: `src/state.ts:99-106` current fields, `src/next.ts:581-592` tab labelled with slug, `src/next.ts:788` old invisible hash name, `hc get t6f` live output showing `name`, `created_ms`, `turn`, labels `herdr.space/herdr.tab` and no session id, 2026-11-06; `hc events --help` label filter is equality-only, 2026-11-06 (hence the constant `akrogon.managed=1`).
Pitfalls: (a) Operator closes the leaf tab and a new tab later gets the slug name: stored tab id is dead. Removed by keeping the old match rule: tab by stored id or by name == slug inside the resolved space, refuse multiples, validate members (`src/next.ts:555-559`). (b) Turn resets to 0 on a restarted terminal, so `prompted` turn compares across incarnations. Removed by pairing it with `born`: a different born means not prompted. (c) A finished terminal holds the seat's name and restart hits `name_taken` (17 hidden finished seen in `hc ls`). Removed by start done-criterion: `hc rm` a finished same-name terminal only after its labels match this repo/leaf/seat; a foreign holder is refused, never removed. (d) Labels are mutable by anyone (`hc label`), so a mislabeled terminal could be prompted or killed as a seat. Removed by the agreement check in the pick (name + born + labels + tab + cwd), never labels alone.
Not asked: who removes finished leaf terminals so names free up and `hc ls` stays readable, reconcile or the start command? And do consultants get `akrogon.managed=1` too (my pick: no, they are door children, so the listener should not wake leaf passes for them; they still get repo/seat labels for the door's own listing)?

## Q3. How are names built and kept unique?

Pick: One deterministic builder in the start command. Consultants stay exactly `<prefix>-slot-<letter>` (intake). Leaf seats are `<prefix>-<slug>-<a|b>`, truncated to 32 chars; when truncation cuts the slug, the name is `<prefix>-<slug start>-<4-char hash of repo/slug>-<seat>` so two long slugs sharing a start still differ. With a 2-letter prefix that leaves 27 chars of slug untouched, or 22 plus hash. Uniqueness for leaf seats is therefore by construction (repo, slug, seat). For consultants, if the name is held by a live terminal whose parent is not this door, the start command refuses and names the holder; no silent suffix. The repo prefix itself needs a defined source, which does not exist today: my pick is a per-repo `prefix` set at init/registration, defaulting to the repo name's first two lowercase letters, with registration refusing a prefix another registered repo already uses.
Reason: deterministic names are what make kill-and-restart, rediscovery, and refusal of late reports work without stored addresses; readable names matter now because hc names are operator-facing in `hc ls` and the sidebar (the old `akrogon-<hash of pane>` name at `src/next.ts:788` was invisible). Slugs already fit the hc charset (`src/state.ts:88` regex). Two doors on one repo in one session also contend for the same chart folder, so refusing is the safe reading of a likely operator error; a second door can use another hc session. Cost: parallel doors on one repo in one session are unsupported, and a `prefix` config field is a small new thing, forced by the fact that the prefix is not derivable (`framework` -> `fw` is initials of frame+work, not first letters; live consultants are `ak-slot-*` while nothing in `src/config.ts` or `~/.akrogon/config.yaml` defines `ak`, checked 2026-11-06).
Rejected: hash-only names (unreadable; restart-by-name and operator triage die). Random suffixes (state must store them, and a lost state write orphans the seat). Full repo name instead of a prefix (repo names reach 20 chars, `mdcny-ghl-data-pulls` in `~/.akrogon/config.yaml`, leaving nothing for the slug; also mixed case like `Himne` needs sanitizing). Silent suffix on consultant collision (briefs, report lines, and skill text address seats by the intake pattern; a suffixed seat is reachable only by whoever recorded the suffix). Sharing the existing consultant terminal across doors (shared context across charts, exactly what kill-and-restart exists to prevent). Solving collisions with per-repo sessions (rejected in Q1).
Evidence: operator/intake (consultant naming, restart under same name, name collision across doors producing `fw-slot-b`); better-than-training: `hc run --help` name rule 1-32 `[a-z0-9-_]`, live `hc ls` names `ak-slot-b/c/d/e`, `src/state.ts:88`, repo list in `~/.akrogon/config.yaml`, all 2026-11-06; model-knowledge: truncate-plus-hash-suffix under a fixed length budget is the standard pattern (Kubernetes 63-char names). No practitioner source found (no web from this seat).
Pitfalls: (a) A repo rename or prefix change orphans live names built from the old prefix. Removed by operator step in the cutover/rename path: prefix is fixed once registered; changing it while leaves are open is refused. (b) Hash-truncated names are hard to type from memory in `hc send`. Accepted cost, bounded: only slugs over 27 chars truncate; done-criterion lists the builder's output for the longest current slug in tests. (c) A consultant name stuck held by a finished-but-not-removed terminal after door crash. Removed by the same start rule as Q2 (rm finished holder after parent/label check, else refuse). (d) Two repos with the same default prefix in one session (portal and pi-extensions both default `pi`/`po` - near misses exist) make leaf names collide only if slugs also match, but consultant names collide outright. Removed by the registration refusal in the pick.
Not asked: what is the direct-route reviewer's name (it is a B-like seat but not a chart consultant and not a leaf seat)? And should leaf seat names include the owner (epic) for readability in `hc ls`, or is the plain slug enough since slugs are already unique per repo?
