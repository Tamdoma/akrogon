# Cross-leaf kill, slot A (before reading B, C)
- Seats live in per-pane scopes under a per-leaf slice akrogon-l<hash>.slice (src/scope.ts:13-19, adoptShell :52-88). Every process a seat starts, including run-check and its Chrome, is in that leaf's cgroup. So "only my leaf's processes" is already a kernel boundary; pkill -f ignores it.
- Orphans: SIGTERM to `bun run test:changed` ends bun, but Chrome children (detached browser trees, own process groups) live on; the cgroup still holds them. In the sweep, `systemctl --user stop sweep-4-*.scope` killed all 155 at once (sweep-results.md). Cgroup stop is the only reliable "kill the whole run".
- Options: (a) skill rule "never pkill -f; kill by pid you started". Cheap, voluntary, seats already improvise (two pkills today). (b) run-check starts every run in its own transient scope under the leaf slice (systemd-run --user --scope --slice=<leaf slice> or StartTransientUnit like adoptShell) and records the unit; `akrogon run-check --stop <name>` (or akrogon stop-run) stops that unit; run-check stops it itself on signal/exit, so a killed waiter or timeout never leaves Chrome. (c) deny pkill/killall in seat tools: harness-specific, bypassable, and blocks legit own-pid kills.
- Pick b plus a. b removes the problem class (orphans and wrong-target kills) for the printed path; a covers the rest. Breaks later: one more transient unit per run (unit-name collisions handled by run id); a seat that bypasses run-check still has only pkill.
- Skill lines: implement-issue, worker-protocol, check-issue name the stop command next to the run command.
