# Kill rebuttal C (disagreement only)

- R1 Bus is settled, not a differ. Proof T7 tested the exact seat condition (`DBUS_SESSION_BUS_ADDRESS=unix:path=/nonexistent`): busctl StartTransientUnit fails, the same call with the bus address set on that one subprocess works, and `systemctl --user stop` exits 0 and kills the process via the manager's private socket (issues/chart/host-test-load/proofs.md:65-73). So seat-side stop needs no new control path; only unit creation does, and the shipped pattern sets the bus address per subprocess (src/scope.ts:88). What T7 does not cover is a D-Bus library call from a seat process (proofs.md Limits), which neither design needs.
- R2 Unit type: I still disagree with B's transient service as the default. It moves execution under the service manager as parent (man systemd-run: service mode runs "with the service manager as its parent process"; scope mode is executed by systemd-run itself "and will thus inherit the execution environment of the caller"). That reworks what run-check currently gets for free from being the parent: constructed env and cwd, file-captured stdout/stderr, stdin handling and direct exit status (src/shell.ts:38-46, src/run-check.ts:60-66). B's advantage is real but narrow — cleanup when the wrapper is SIGKILLed after the main process later exits — while a hung main process under either unit still needs stop-run. Scope plus stop-on-handler, stale sweep and stop-run covers the observed cases without changing the exec model; if the service form is chosen anyway, systemd-run's IO/exit/signal semantics need their own proof before handoff, which the merged notes do not carry.
- R3 Correction to Found (C) as merged: `pkill --cgroup <own scope>` does not work with the unit name. The match is on the full cgroup v2 path from /proc/self/cgroup (man pkill --cgroup): a read-only check now gave 89 matches for the full path vs 0 for the scope basename. Any skill line or leaf test that encodes the merged shorthand will silently match nothing.
