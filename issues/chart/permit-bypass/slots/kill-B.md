# Slot B: cross-leaf kill

## Current boundary
F1. Seats are boxed for resource accounting and group stopping, not signal isolation. Leaf identity hashes repo/slug into a slice; each pane shell gets its own scope keyed by pane/PID/start time, adopted before use (src/scope.ts:13/:17/:53/:71; src/next.ts:509). Same-UID signal permission does not depend on cgroup membership, so another leaf remains reachable by pkill ([kill(2)](https://michaelkerrisk.com/linux/man-pages/man2/kill.2.html)).
F2. Existing `akrogon stop <leaf>` records the leaf stopped, then stops its entire slice, including seats and their runs. It is an operator-level leaf stop, not “stop this duplicate check” (src/stop.ts:51/:56/:64). Stopping a pane scope is narrower than a leaf but still terminates that seat and all its work (src/scope.ts:71/:75).
F3. Seats and constructed check children receive a dead session-bus address. A normal seat-side systemctl stop/new transient-unit call therefore cannot be assumed to work; exposing unrestricted user-bus access would undo the chosen bus cut (src/next.ts:482; src/run-check.ts:56; forks/guarantee.md, Taken). No run-specific cgroup or delegated cgroup.kill interface is created by run-check (src/run-check.ts:149/:181; src/shell.ts:38).
F4. The scratch `.owner` records wrapper PID, boot ID and wall-clock start, not child PID/PGID or kernel PID start time. A UUID goes into timing records, but no stop-by-run command consumes it. The permit sidecar does validate holder PID/start/boot, but describes the permit owner, not its descendant tree (src/run-check.ts:157/:163/:175; src/permit.ts:68/:100). These records are not a safe existing “kill my run” API.
F5. spawnLogged uses ordinary Bun.spawn through spawnCaptured, with no dedicated process-group creation or signal forwarding in this path. Killing one recorded PID is not tree cleanup; a negative PGID would only be safe after explicitly creating and recording an owned group, and can still miss descendants that leave it (src/run-check.ts:65; src/shell.ts:38/:77; kill(2) above).

## Why browsers survived
F6. Correct the count's scope: sweep-results.md records 155 surviving Chrome processes across sweep-4-1 and sweep-4-2, two minutes after the four top-level changed-test runs exited 143. It does not establish 155 leftovers from one run. Stopping the sweep scopes subsequently removed them (slots/sweep-results.md, final bullet).
F7. The name match selected runner processes, not every descendant. Framework run-test-changed.ts:440 starts `bun run --sequential`; its full-run branch :431 invokes verify:core, whose package.json:168 uses --parallel. Neither inspected runner branch installs a descendant-cleanup signal handler. The sweep demonstrates failed whole-tree cleanup, not which Bun signal-forwarding edge failed.
F8. “Detached Chrome” is not established: framework .claude/skills/_shared/libraries/page-measure.mjs:309/:313 spawns Chrome without detached:true. Its explicit cleanup runs blepsis stop then child SIGTERM (:291/:392); abrupt ancestor death need not execute that cleanup. Process groups and cgroups are separate boundaries, so creating a new process group does not itself escape the recorded scope (same source; local systemd.scope(5), Description).
F9. A scope has no main process and remains alive while any member remains. Thus merely assigning a run a transient scope does NOT make its browsers die when the runner dies. A finally/signal hook alone also cannot handle SIGKILL. This is the exact lifetime gap the new design must close (local /usr/share/man/man5/systemd.scope.5.gz, Description; kill(2)).

## Options
O1. Skill rule only: immediately prohibit command-name/glob process kills and require an exact owned run identity. Cheap and useful, but no automatic cleanup on crash and no enforcement against another same-UID process. Keep it as protocol, not a containment guarantee (F1/F4/F9; fork incident evidence).
O2. Scoped “stop my run”: expose an opaque run ID, resolve it to its recorded owning seat/worker and unit, reject another owner's target, terminate only that unit with bounded TERM then KILL, and wait for emptiness. Gives the seat a concrete safe action without stopping its peer. Alone it still relies on someone requesting cleanup and cannot stop arbitrary same-UID kill syscalls (F1–F5; local systemd.kill(5), KillMode/SendSIGKILL).
O3. Run-owned transient unit: strongest cleanup option, provided supervision outlives the wrapper and notices its loss. Prefer a transient service with a tracked main supervisor, ExitType=main and KillMode=control-group, or an independently supervised scope with equivalent lifetime guarantees. A service alone does not notice an unrelated client dying: specify wrapper-loss handling, command completion and explicit cancellation separately (local systemd.service(5), ExitType; systemd.scope(5), Description; systemd.kill(5), KillMode).
O4. Deny pkill in seat tools: catches these literal incidents, but `kill`, shell builtins, Python/os.kill and other syscall callers remain. A token denylist also blocks legitimate owned cleanup without solving lifecycle ownership. Real cross-seat signal denial needs an OS security boundary beyond current same-UID cgroups, a materially larger design (F1; kill(2)).

## Pick and required protocol
D1. Combine O2+O3 with O1 now; do not choose O4 as the guarantee. Run ownership removes the need for name searches, and supervised unit cleanup removes orphan dependence on agent behavior. This is lifecycle containment, not restoring the removed serial permit (F2/F9; forks/guarantee.md, Taken).
D2. The unit must stay under the owning leaf slice, preserve its ceiling and leaf-stop behavior, and launch the workload inside the unit before it can spawn descendants. Keep the bus cut in workloads and provide only a narrow control path that validates the caller's actual seat/run ownership, not a caller-supplied slug or cwd. This requires an explicit control-plane design/proof, not telling seats to restore DBUS_SESSION_BUS_ADDRESS (F1–F4; src/stop.ts:52).
D3. Include base-run, nested checks and workers in ownership: stopping a nested run must not kill a parent or sibling, while owner death must clean its descendants. Persist cancellation/exit status and logs before scratch removal; a cancelled run is incomplete, never passing proof. Raw commands outside the managed path retain only pane/leaf cleanup, which must be stated as the residual (src/permit.ts:93; src/run-check.ts:181/:199; check-issue/SKILL.md:65).
