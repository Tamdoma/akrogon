# Cross-leaf kill — C

## 1. Boxing today, and what a seat can already stop

- Box: at allocate, each pane shell is adopted into its own transient scope under a per-leaf slice (src/scope.ts:53-90, src/next.ts:510-570), named from pane id + shell pid + start time (src/scope.ts:17-19). Scope properties are TimeoutStopUSec=5s and SendSIGHUP=yes (src/scope.ts:79-84). Descendants inherit the pane cgroup; the bus cut stops Chrome escaping into app-*.scope (limit-boundary Taken). There is one scope per pane shell, not per run: seat, agent, workers, tests and browsers of that pane all share it.
- Run identity today is unusable for killing: run UUID exists only in memory and timings (src/run-check.ts:163,175); `.owner` in runRoot holds the run-check pid but runRoot is a random temp dir deleted on exit (src/run-check.ts:152-159,199-201); the permit sidecar holds one holder pid host-wide (src/permit.ts:18-26,100-112) and the permit itself is being removed (guarantee Taken). None of these pid handles reaches the run's children.
- Existing stop path is wrong granularity and wrong caller: `akrogon stop` stops the whole leaf slice (src/stop.ts:53-56), killing both seats and the shell, and is an operator-shell command (host-test-load stop Taken). No seat-facing run stop exists.
- What works today without new code, unused by skills: a seat can read its own scope from /proc/self/cgroup and restrict any kill to it — procps pkill has `--cgroup <name>` (man pkill, read 2026-10-13) and `-A` (ignore ancestors, which alone would have stopped both seats killing their own `bash -c` shell, whose command line contains the pattern). `systemctl --user stop <unit>` works from inside the bus cut (host-test-load seat-scope Taken, proof T7), and scope stop already killed the sweep orphans (sweep-results.md) because cgroup membership survives reparenting.

## 2. Why 155 Chrome survived a killed test:changed

- Signals do not propagate down a process tree. `pkill -f run-test-changed.ts` signalled only processes whose command line matched: the selector, wrappers, and the pkill caller's own shell (forks/cross-leaf-kill.md Carries). The selector was blocked in spawnSync on the lane child; its death orphans that lane, which reparents to the user manager and keeps running, browsers included (sweep-results.md: scopes still held Chrome 2 min later).
- No run-owned process group exists to signal instead: Bun.spawn is called with no detached/setsid option (src/shell.ts:38-46), so a run shares its pane shell's process group — kill(-pgid) would kill the seat. run-check also registers no signal handlers (grep: no SIGTERM/SIGINT handling in src/run-check.ts or src/shell.ts), so on SIGTERM its finally blocks do not run and its child gets nothing; with stdin ignored and stdout to files (src/shell.ts:38-44) the child does not even get a hangup.
- The surviving browsers were the class with no parent-death lifeline: page-measure launches system chromium directly (`spawn(binary, --headless=new ..., page-measure.mjs:309-311` in framework) and cleanup is an explicit closeBrowser call in JS that never runs when the lane is SIGTERMed. Playwright-driver browsers usually die with their driver pipe; a standalone chrome instance does not. One survivor tree is 10-33 processes (main, zygotes, gpu, utilities, renderers), so 155 processes is roughly 5-15 orphaned browsers (framework test-cost slots/browser-C.md live sample).
- Bun's --sequential/--parallel runner changes nothing here: lanes are children of a bun runner; killing any ancestor above a lane orphans the lane either way. Bun forwarding signals to its own script children does not help once the killed process is above or beside the runner.

## 3. Options and pick

- O1 Skill rule only ("never host-wide pkill -f; use --cgroup/pid-tree"): zero build, and repeats the proven failure shape — two different leaves reached for host-wide pkill within 17 minutes on 2026-10-13 (cross-leaf-kill.md Carries), under valid pressure (a stuck/duplicate run and no handle to stop it). It also leaves orphan cleanup to seat diligence. Rejected as the mechanism; kept as one rule line in §4.
- O2 `akrogon stop-run`, a thin command over O3's scopes: derives the caller's leaf slice and pane from /proc/self/cgroup, refuses anything outside it, finds the caller's run scope, and `systemctl --user stop`s it. A seat gets one obvious safe verb; naming another leaf is impossible through it because identity comes from the caller's own cgroup, not an argument. It is not a fence (same-UID seat can still pkill by hand, O1's residual) — it removes the reason to.
- O3 Per-run transient scope (pick, with O2 on top): run-check puts its command in a new scope under the leaf slice, named from leaf + run UUID (naming pattern src/scope.ts:17-19), via the same StartTransientUnit call adoptShell already makes (src/scope.ts:59-88, bus address set per subprocess at :88 so the seat bus cut does not block it). On every exit path (normal, error, SIGTERM/SIGINT handler), run-check stops the run scope: scope stop SIGTERMs the whole cgroup then SIGKILLs after TimeoutStopUSec (systemd.kill KillMode=control-group default for scopes; man systemd.kill read 2026-10-13), which is exactly what manually cleaned the sweep scopes. Orphan owner becomes mechanical: browsers cannot outlive their run because cgroup membership does not care about ppid.
- O4 Deny pkill in seat tools: rejected. It is per-harness config (pi/codex/claude) with trivial spellings around it (kill $(pgrep), python os.kill, killall), the arms race this chart already foreclosed for PATH shims (permit-bypass CHART.md Off route). Legitimate scoped pkill also exists (§1).
- Pick breaks, named: (a) reopens permit-release's foreclosed per-run units — already reopened wholesale by guarantee Taken, but this spends it; (b) kills cross-call leftovers at every run exit, so a suite keeping a server alive across separate run-check calls (host-test-load fog-defaults accepted case) breaks — accept for check runs, or scope-kill only on abnormal exit plus sweep (below), stated in leaf design; (c) adoption race: a child spawned before adoption can fork lane processes into the pane cgroup in the gap, so the launch must enter the scope before exec (stopped-shell-then-exec trick or systemd-run --scope, man systemd-run/systemd.scope) — this needs a probe before handoff: lane command that forks immediately and orphans a grandchild, assert every descendant's cgroup is the run scope; (d) SIGKILL of run-check runs no finally — needs a stale sweep: at run-check start and at allocate, stop run scopes under the caller's own pane whose recorded owner pid+start_time (permit.ts:41-46 pattern) is dead; (e) nested run-check must join the existing run scope via an env token, with the known residual that a copied token only endangers the copier's own run (guarantee Findings, token); (f) raw `bun run test:changed` still lands in the pane scope, not a run scope — for those the stop path is the §4 scoped recipe until long-run-path makes run-check the easy route.

## 4. Skill/protocol lines that must change (with O3+O2)

- implement-issue SKILL.md Shared context + proof order (:45 wait-on-exit): add the stop rule — never signal by host-wide command-line pattern (`pkill -f`, killall); to stop a stuck or duplicate run use `akrogon stop-run` from the seat that started it; before starting a replacement run, stop the previous one; record the run id/scope printed by run-check beside any background run started under the long-run path.
- worker-protocol.md: workers signal nothing. A worker that wants its changed-test run stopped returns that as its result; only A stops runs, and only via stop-run, because workers share A's pane scope and a worker-side pattern kill cannot tell its own run from A's or a sibling worker's.
- check-issue SKILL.md rerun/comparison rules (:63-65): before a retry or base-run after an interrupted or killed check, confirm the previous run scope is stopped/empty; a check_start with no check_end plus live browsers in the leaf slice makes the next run's evidence suspect (contention from orphans), recorded as missing evidence, not a pass.
