1. Missing owned surface, and an Open question the evidence already settles: `initialize` in `src/init.ts` calls `repoSchema.parse` directly on an operator proposal file or on the existing `issues/config.yaml`. (`src/init.ts` `initialize`; `src/config.ts` `readRepo`; better-than-training; 2026-10-25)

2. Criterion 3 is not sufficient for the history it protects: timings naming retired phases must do more than parse. `visitsOf` in `src/timing-report.ts` builds a `Visit` from `visit_start` events, and `visitGaps` calls `requiredSlots(visit.phase, ...)` in `src/routing.ts`, which indexes `routing[phase]`. For a completed retired-phase visit that indexes a deleted route and throws, so `akrogon timing` crashes on the old logs in 5 repos while criterion 3 passes. Correction: name `src/timing-report.ts` in Leaf architecture with the settlement (retired phases' required slots are A+B from a historical table beside the historical enum, never live `routing` entries), and extend criterion 3: "and the timing report over such log and timing lines completes". (`src/timing-report.ts` `visitsOf`, `visitGaps`; `src/routing.ts` `requiredSlots`; better-than-training; 2026-10-25)
