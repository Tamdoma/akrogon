# Slot B leaf review

**F1 — Historical timing reports need owned behavior, not parsing alone.** `src/timing-report.ts` (`visitGaps`) calls `requiredSlots(visit.phase, visit.rounds)` for completed historical visits. `src/routing.ts` (`requiredSlots`) indexes live `routing`, whose retired entries disappear. Widening readers alone therefore leaves an undefined route lookup, while narrowing types exposes the mismatch at compile time. The design mentions this consumer but omits it from owned surfaces and criterion 3 proves only parsing. Correction: explicitly own `src/timing-report.ts`, require timing reports over completed retired-phase visits to retain their historical A+B delivery accounting without consulting live routing, and extend criterion 3 to observe successful report output. Let the planner choose the smallest implementation. Evidence: better-than-training, named functions, read 2026-10-25.

**F2 — The init question already has an answer.** `src/init.ts` (`initialize`) parses an explicit proposal or, with no proposal, the existing `issues/config.yaml` directly through `repoSchema`. Every registered config currently carries `rebuttal`, so this is an existing-file compatibility path, not merely a hypothetical old proposal. Leaving it undecided risks init failing where `readRepo` succeeds. Correction: settle that the same obsolete-key removal applies to init's parsed config input, add `src/init.ts` to owned surfaces, and extend criterion 1 to prove initializing from an existing legacy config succeeds while unrelated unknown keys remain refused. Evidence: better-than-training, `initialize` input selection and direct parse, read 2026-10-25.

**F3 — Rollback documentation is missing and criterion 6 forbids explaining compatibility.** `docs/use/roll-back-a-release.md` (Roll back with the command) describes restoring the previous release without this leaf's new data requirement. The design records that requirement only in an issue artifact. Correction: own that guide and explain that records created or saved without `debate` need `debate: 'no'` restored before the old reader can load them. Amend criterion 6 to prohibit describing debate as an available lifecycle option while permitting legacy-read and rollback explanations. Evidence: better-than-training, that guide section, `src/state.ts` (`stateSchema`), and draft design (Legacy records), read 2026-10-25.
