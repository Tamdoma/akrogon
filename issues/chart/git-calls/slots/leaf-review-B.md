# Leaf draft review B

2026-10-26. Disagreements only. Draft sources are under the assigned scratchpad handoff directory. All code evidence was inspected today.

- B8. **PID reuse protection needs an identity contract, not just fresh /proc reads.** Design, **Leaf architecture**, passes one PID through adoption and claims refreshing start time detects reuse. If that PID is recycled before adoption, deriving a new scope name from its new start time can adopt the unrelated process and then validate it successfully. Preserve the initially observed `(pid, start)` identity and reject a changed start before placement and during polling. Evidence: better-than-training, src/scope.ts `shell`, `adoptShell`, `inOwnScope`, `paneScope`; model-knowledge, the proposed flow's PID-reuse sequence. Criterion 1 needs this behavior, and the changed identity needs a home in the scope API.

- B9. **The fake startup decision has an uncovered hash consumer.** Design, **Leaf architecture**, owns tests/fake-proc.ts `shellPid`, but `expectedSlice` also calls `createHash`. Replacing only `shellPid` leaves the `node:crypto` import loaded on every fake invocation. Include `expectedSlice` in the hash replacement and preserve its digest too. Evidence: better-than-training, tests/fake-proc.ts `shellPid` and `expectedSlice`, tests/fake-herdr.ts `ownCgroup`; binding source: design **Reuse**, decision 3a. The current architecture does not fully implement that decision.

- B10. **The promised existing-log proof cannot be collected after an unchanged full check.** Design, **Standing design**, and Proof 3a require report counts from existing fake logs while forbidding proof machinery. Those logs live inside each fixture home, which `fixture().clean()` recursively deletes in test `finally` blocks. Existing test output does not publish the counts. Moreover, `.calls` omits session-list calls, and the existing `calls()` helper filters workspace discovery. Authorize and assign a minimal way to capture or aggregate raw logs before cleanup, or select another available proof method. Evidence: better-than-training, tests/helpers.ts `fixture`, tests/next.test.ts `calls` and target cleanup, tests/fake-herdr.ts `.calls-raw`/`.calls` writes, tests/fake-busctl.ts `busctl.calls` write. This blocks the specified report method, not the cleanup behavior.

- B11. **The proof contract freezes test implementation while omitting needed behavioral coverage.** Design, **Binding decisions** and **Standing design**, requires unchanged commonDirectory assertions and declares criteria 1–3 proven by existing named test files. The commonDirectory case makes four distinct cwd calls, so it does not prove once-per-root reuse or a repeated failed lookup. Boxing and delayed-adoption coverage lives in tests/seat-containment.test.ts, outside the listed owned test surfaces. State the required behavior instead of binding assertions, and allow the targeted tests needed for identity reuse and PID replacement. Evidence: better-than-training, tests/config.test.ts `commonDirectory spawns git once per call and reports failures with cwd`; tests/seat-containment.test.ts boxing, delayed-adoption and unreadable-cgroup cases; draft **Owned surfaces**.

- B12. **The blanket write prohibition conflicts with once-per-run reuse.** Design, **Binding decisions**, forbids keeping any Git answer across a write, but criterion 3 requires one successful root common-directory/remote lookup for the entire run. A multi-leaf allocation writes Git worktree metadata between uses of the root identity. Specify which writes invalidate which fact, or explicitly permit stable identity across unrelated writes. Otherwise the planner cannot satisfy both rules. Evidence: better-than-training, src/next.ts `ensureWorktree` and `createSparseWorktree`; draft brief **Done-criteria**, item 3, and design **Reuse**, Binding avoidance.
