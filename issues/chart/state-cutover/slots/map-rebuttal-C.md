# Slot C rebuttal and final-shape check: state cutover

One disagreement, on proposed final shape item 1(a).

- Item 1(a) as written ("an argv entry resolving, against its own cwd and through symlinks, to a path inside the tool root") leaves the implementer guessing which entries count, and a literal reading reintroduces the false-positive class this change exists to remove. Any token can be resolved lexically into the root: the `bash -c "<command>"` shell that launched the migrator is an ancestor, expressly not exempt in this shape, and its single command-string entry resolves inside the root whenever its cwd is the root, as does an editor or `grep` invoked with a root path argument. Measured live on 2026-10-16, seat tool calls run exactly as such `bash -c` processes with cwd in the root, so the gate could stay closed for every door-run command even with no old akrogon code running. The agreement text above it says "by what the process executes", which the item does not encode. Exact fix: replace item 1(a) with "the process executes a file inside the tool root: its argv[0], resolved against its cwd with symlinks followed, is an existing file inside the tool root, or its argv[0] is a bun/node interpreter and its first non-option argv entry, so resolved, is an existing file inside the tool root (this covers both `bun ~/.local/bin/akrogon …` measured in intake F4 and `bun src/akrogon.ts` from the root)". Items 1(b), 2 to 6 and the Q1/Q2/Q3 picks need no change.
