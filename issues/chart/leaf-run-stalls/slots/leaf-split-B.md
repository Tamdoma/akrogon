### 2 · Can several chained leaves build one logical spine stage, with its final producer owning the stage criterion?

Yes, provided every earlier leaf is independently mergeable and proven, and the final producer owns the complete stage's real wiring and acceptance. The lock says each stage has an owning leaf whose criterion puts it in the spine; it does not say that leaf must author every component of the stage (AK/issues/chart/cross-leaf-proof/forks/spine-growth.md, Taken Q1; AK/skills/chart-issues/assets/shapes.md:172). Today “conversion” aggregates six scripts under one stage label (FW/issues/chart/emdash-cms/CHART.md:50), which is a proof grouping, not evidence those scripts must share one merge boundary.

Research: better-than-training · AK/issues/chart/cross-leaf-proof/forks/spine-growth.md, Taken Q1-Q3, and assets/standing-design.md:10-11, read 2026-10-01 · the invariant is a named owner, real owned scripts/consumers, recorded-from-real outside stages and a consumer blocking spine · allow component ownership to differ from stage ownership while preserving those requirements. Research: practitioner · DORA, [Working in small batches](https://dora.dev/capabilities/working-in-small-batches/), read 2026-10-01 · useful increments must not be withheld until a larger batch is finished · earlier outputs must be usable and proven before the final stage leaf, not merely “code complete.” This supports independent upstream criteria, not a waiver of chain proof.

- **2a (recommended)** Permit chained contributors to one logical stage. The chart names each contributor's accepted output and direct consumers, and names exactly one final producer as stage owner. Every contributor has its own real output/contract proof. The stage owner depends on the required contributors, runs the complete stage through real consumer code, records its provenance, and adds it to the existing blocking spine. Only that stage-owning leaf needs the full-stage spine criterion. This is an explicit interpretation of the carried lock, not a replacement for it, and needs no new runner or state field.
- **2b** Make every independently mergeable producer a separate spine stage with its own owning criterion. This preserves the lock with narrower stage names and gives earlier chain feedback. Prefer it when those intermediate outputs already have meaningful executable stage boundaries. Cost: more stage wiring and retained inputs if decomposition would otherwise exist only to force a one-leaf/one-stage convention.
- **2c** Require one leaf to implement every component of a stage. One acceptance owner is easy to name, but an arbitrary stage label becomes a minimum leaf size and can defeat Q1 even when contributors are independently mergeable.

Pitfalls: 2a does not allow upstream leaves to skip their own proofs, label a partial stage complete, or merge an unimplemented feature advertised as usable. If an earlier leaf already owns a complete runnable stage, it must retain its spine criterion; calling it a contributor cannot evade the lock's audit. A consumer that can only prove its outcome after the final stage exists remains blocked until then. The last leaf is the producer of an accepted integrated outcome, not a separate proof-only leaf added to postpone all verification. Split into 2b's real stages if no independently sufficient upstream proof exists under 2a. No hand-written positive stand-ins for owned code, no added live-model run per merge, and no duplicate full-chain run just because files overlap.

Concrete contract probe before handoff: for a candidate split, write an output-to-consumer table, assign the final stage owner and map every criterion to an executable proof. Run upstream proof commands on their intended base and invoke each newly implemented consumer on the real upstream output when it exists. A broken producer-output shape must fail its own contract proof or that consumer proof. Run the final spine at its stage owner's final commit, with real scripts and authentic recordings where required. This is a required verification design, not a probe performed in this round. Reject a split whose purported earlier outcome cannot be demonstrated without unfinished code or a fake owned stage.
