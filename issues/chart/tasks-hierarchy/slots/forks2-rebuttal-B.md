# Slot B: disagreements with forks2-merged

- **B / R1 / Body-click expansion is no longer an equal alternative.** Direction Round 2 1b selects a click that jumps to the pane or log. Keep expansion behind its separate disclosure control. Leaving A's expand-body option as a live choice would reverse that answer. Evidence: `forks/direction.md` Round 2 1b; `forks2-B.md` D2/D3. Current `main.js:row` expands on body click, so implementation must deliberately change that behavior.

- **B / R2 / Target order must respect the problem, not merely activity.** The merged generic busy-seat-first order loses B's state-specific recommendation. A Needs you row with A working and a B delivery/failure problem should point to B's relevant live target or the diagnostic evidence, not unrelated A activity. Working rows can default to the producer-selected live target. Reject the automatic tab → Files-pin cascade: a tab is not necessarily the implicated agent, and Files showing a worktree does not read the reported problem. Files/Changes remain explicit inspection actions. Represent a diagnostic destination as an intended state when there is no relevant live pane, and show navigation failures rather than silently switching destinations. Evidence: direction Round 2 1b; `forks2-B.md` D2, O7 and R4; `src/state.ts:failureSchema` records the failure slot, and delivery errors are per-seat. Also distinguish current-host terminal/pane identities from legacy Herdr identities before navigating.

- **B / R3 / Per-table-row warning lines conflict with the chosen short run warning.** Direction 3a says keep a short warning line and skip structured fields. Splitting the table and dropping its first lines introduces a presentation-text parser and can expose multiple running/ended entries as well as the actual waiting run. `src/status.ts:lineRows` maps every run and emits waiting, running or ended; env.run is enabled when any one run waits. It is not a waiting-only row collection. Keep one quiet indicator with the full supplied text on demand. Evidence: `forks/direction.md` Taken 3a; `src/status.ts:lineRows`, env.run construction and render; `forks2-B.md` D1. Do not add new run fields to solve an option the operator already declined.

- **B / R4 / “Parked entries get no target (B)” is too broad.** B says parked entries cannot pretend to have a live seat or worktree Files target. Where the producer provides a genuine diagnostic destination, the no-live-pane state can still navigate there. The current parked payload is folder names only, so it does not supply that capability today. Preserve this distinction instead of banning any diagnostic target for parked rows or inventing one from a slug. Evidence: `forks2-B.md` D2 and R7; `src/status.ts:jsonRepo` supplies scan.parked as names. No live target is not the same claim as no possible diagnostic destination.

- **B / R5 / Scale summary must distinguish fixed spacing from fixed text and height.** The shared “Header 42 ... fixed” line misstates B: 42 is the normal minimum, and content may grow it. B scales every Tasks text role, including title, section labels and machine text. C's fixed-chrome-text option is different from keeping shipped paddings/gaps/radii. At large configured text, a hard 42 px box or rigid row-line limit can clip the scaled content. Use relative text/icon sizing, ordinary fixed spacing and content-fitting minimum heights. Evidence: locked text follows settings().font_size; `forks2-B.md` D5/O17–O19/R14; `main.js:S/render` currently scales text throughout; shipped Files/Changes provide the normal 42 px geometry, not proof that larger Tasks text fits a hard 42 px box.

Evidence is operator direction or primary local code inspected 2026-11-04, plus B's submitted notes.
