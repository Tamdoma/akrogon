# Blind map and picks: fix-shape — Slot C

## Q1: Cause vs. symptom

- **Pick:** Condition (2) — un-throttled overlap during land — is the primary akrogon **cause** (compounding framework `f5337ffb79`'s 19-job suite and `renderers/1.99.9` race). Condition (1) — nameless failures disabling `taken8Trigger` — is **neither the cause nor even a blocked cover** here: both bases (`9c9a9f63d7` via `4d22e25b`, `79ddb36cf2` via `1f854bee`) already had whole-green merge receipts, so `verify` (`knownRed` branch) would have skipped the base pass and judged `fail` anyway (`greenBase !== undefined`). The real **cost amplifier** is `skills/check-issue/SKILL.md` `## check.repair`'s mechanical "second red on the same unit" -> `check.fix` rule, which forced unrelated EmDash timeout commits onto `runner-names-unbound-route` and burned `fix_rounds`.
- **Rejected:** Treating Condition (1) as co-cause and relaxing `named()` / `taken8Trigger` — breaks locks S2 and S4 (nameless covers can mask real leaf regressions) and would have fixed 0 of the 12 reds because both bases were already green.
- **Evidence:** Framework `issues/timings.jsonl` shows 40–72 overlapping non-land `check_start` runs during the 13:54–14:40 land runs (11 `cheap` verifies in the 14:15 run alone, cpu pressure 40–69 s vs 25.3 s on the 12:46 green run with 4 overlaps); `issues/verify-runs.jsonl` shows two simultaneous `scope: merge` runs at 15:23–15:25 (`one-gate-path` land + `checkout` watch-consultant `verify --holder`) because framework has `full: []`; `src/verify.ts` `verify` (`greenBase`), `uncoveredMainRedUnits`, `src/land.ts` `land` (`taken8Trigger`); `runner-names-unbound-route/review-B.md` (`## 2026-11-22 check.repair after second merge red`).
- **Pitfalls:** Fixing only framework `renderers/1.99.9` or lowering suite jobs still leaves 40–72 seat `run-check`s and `verify --holder` overlapping land under `max_active: 12` (and `633db0ad` not counting merge leaves).
- **Unasked question:** Does `akrogon` also need to keep a second heavy repo's land run off the PC while framework lands, or is framework the only heavy suite on this host?

## Q2: Quiet-repo admission for land runs

- **Pick:** Carry `attempt?: string` (already on `LeafTarget` in `src/run-check.ts` `checkedRun`) into `AdmissionHolder` and `RunRecord` (`src/admission.ts`), and route every repo run through one `lineLock(record.repo)` admission gate (using the existing lock order `admission.lock` shared -> `locks/<slice>` -> `locks/line-<repo>`):
  - **Land run (`attempt !== undefined`):** registers `waiting` immediately (drain barrier), starts `live` only when no other `live`/`ended` run of that repo has a different `attempt` and no earlier-`since` `waiting` run of that repo has a different `attempt`. Sibling `merge_checks` sharing `attempt` run in parallel unchanged.
  - **Non-land run (`attempt === undefined`):** waits when any `live`/`ended` land run exists on that repo, or any earlier-`since` `waiting` land run exists; otherwise starts immediately (`full: false`) or uses the existing `full` FIFO line (`full: true`, preserving akrogon's `full: [test]`).
  - **Nested runs (`nested()`):** add `(record.attempt !== undefined && record.repo === repo)` so a land run's own child `run-check` (even `full: true`) nests immediately with zero self-deadlock.
  - **Starvation & cancel:** comparing `(since, token_hash)` lets leaf runs that waited during land 1 drain in one parallel burst before land 2 starts (preventing 6-leaf merge queues from stalling seats past `STALL_MS` / tool timeouts), while blocking new leaf runs arriving after land 2's `since`. `cancelWaitingRun` (`src/stop-run.ts` `stopRunCommand`) and `sweepStale` already work on any `state: 'waiting'` record.
- **Rejected:** (a) Framework `full: [cheap, verify]` — serializes `cheap` against `cheap` outside land, leaves seat `run-check`s (the bulk of the 72 overlaps) unqueued, and requires per-repo opt-in; (b) strict land-always-preempts-waiters — starves waiting seat checks across back-to-back merge queues; (c) doing nothing — fails S1.
- **Evidence:** `src/admission.ts` `withAdmission`, `awaitLineTurn`, `lineRuns`, `nested`, `cancelWaitingRun`, `sweepStale`; `src/run-check.ts` `checkedRun` (`caller.attempt`, `wait_ms`); `src/verify.ts` `runOnce` (`Promise.allSettled` on `members`); `src/stop-run.ts` `stopRunCommand`.
- **Pitfalls:** (1) Gap between `setup` and `verify` in `src/verify.ts` `runOnce`: if `verify` mints a fresh `since`, runs queued during `setup` can rush in between `setup` and `verify`; passing `record.created` (already on `PassRecord`) as a land step's queue timestamp closes the gap with no new state. (2) `merge-slow` (`src/verify.ts` `decideSlow`) measures `end - start` including drain wait; if a `--holder` verify drains for >2 min before land starts, it can trip `merge-slow` (acceptable or stamp `start` after drain).
- **Unasked question:** Should `verify --holder` (watch-consultant base verification, `scope: 'merge'`, `attempt: undefined`) wait for land as a non-land run (quiet land, zero extra config), or also claim a quiet repo itself?

## Q3: Red / nameless-timeout judgment

- **Pick:** Keep `src/verify.ts` `named`/`uncoveredMainRedUnits` and `src/land.ts` `taken8Trigger` unchanged (preserves S2 and S4 locks 3/7/8). Fix `skills/check-issue/SKILL.md` `## check.repair` ("second red on the same unit" bullet): send a second red to `check.fix` **only** when the failure is a named unit with a plausible causal link to the leaf's diff or fails its narrow retry on the rejected head; when a repeated red (named or nameless/timeout) is outside the leaf's diff (untouched test, code, helpers, config, lockfile) and clears on narrow retry, stop `failed --slot B --reason "<repeated unrelated/main flake; see review-B.md>"` instead of handing to `check.fix`, and explicitly forbid committing unrelated main-test workarounds onto a leaf branch.
- **Rejected:** (a) Allowing nameless titles in `uncoveredMainRedUnits` / `taken8Trigger` — breaks S2/S4 and cannot cover a green base; (b) unlimited unchanged returns to `merge` on repeated unrelated timeouts — loops forever burning 10 min + B tokens if a real main teardown timeout persists even on a quiet repo; (c) adding in-land reruns — breaks S4 lock 5a.
- **Evidence:** `src/verify.ts` `named`, `uncoveredMainRedUnits`, `verify`; `src/land.ts` `taken8Trigger`; `src/phase.ts` `commitMove` (`fix_rounds`); `skills/check-issue/SKILL.md` `## check.repair`; `runner-names-unbound-route/review-B.md` (F2/F3 `95cfceb3cd`/`c834d36321` unrelated commits) and `repair-round-bound/review-B.md` (main race stopped `failed` cleanly).
- **Pitfalls:** Make sure a genuine leaf-caused regression that surfaces only as `(script)`/`(unnamed)` (e.g. a leaf broke a hook/setup script in its diff or failed its narrow retry) still routes through the leaf repair split, not `failed` as main-caused.
- **Unasked question:** When B stops a leaf `failed` for a repeated unrelated timeout under Q3, does `skills/watch-issues/SKILL.md` already classify that reason as a consult case (yes: `failure.reason` naming a main/unrelated defect triggers consult)?
