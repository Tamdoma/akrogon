## Defects in Taken 1 to 6

- F1 Starve, Taken 2 (my H4 was incomplete). The land's own `full` check queues by `since` behind every `full` waiter that arrived before the hold (`lineRuns` sort in src/admission.ts). The hold stays live for that whole wait. Consequence in this repo (`full: [test]`): with three leaf suites waiting, the land waits three suites and every other run of the repo is held back for that time plus the land. Before the change those runs were free. Fix: among waiting line runs, a run carrying a live hold's attempt sorts first, in the one sort every decider reads, so two waiters never both see themselves first. Add a test: a land check starts ahead of a listed waiter that arrived before the hold.
- F2 Land overlap, Taken 1. When a hold ends, every run it held back starts within one poll. The next land's hold has a later `since`, so it does not hold them, and that land starts together with them. With leaves queued in merge (six on 11-22) every land after the first begins under that burst. Size: one run per blocked seat or worker, most under a minute. Taken 1 does not carry my P3. Fix inside this shape: none without a wait. Record it as the accepted cost and name what reopens drain: reds or higher `pressure` on lands that start right after another land ends.
- F3 Lock, Taken 4 against red-exit Taken 3. "Returns the leaf unchanged, on a repeat too" covers any unit that passes its narrow rerun. Lock 3 sends a named unit that repeats on an unchanged head to `check.fix` once the base pass found it green on main. Consequence: B can return a leaf whose named failure repeated and is green on main, because it passes alone. No 11-22 finding breaks that case, since every repeat was nameless. Fix: one clause. The repeat return does not apply to a named title on an unchanged head whose `base_verdict` is green on main. That case stays `check.fix`.
- F4 Contract, Taken 4 says "red bullets only". Three copies still say a second red takes `check.fix`: the refusal string in src/phase.ts ("Merge moves to check.repair itself; a second red takes check.fix from check.repair"), skills/merge-issue/SKILL.md `## Phase calls on a merge leaf`, and docs/reference/state-and-phases.md. Consequence: the command tells a seat the rule Taken 4 removes. Fix: reword all three to "a leaf-caused red", with the test that asserts the string.
- F5 Trap, Taken 3 against Taken 2. Status reads `lineRuns`, and so does the queue in `awaitLineTurn`. If `lineRuns` is widened to return the hold, the hold is a live record and sorts as the line's holder. Consequence: every `full` run of the repo waits behind it, the land's own `full` check included, and the land never ends. Fix: status gets its own listing and the queue keeps the `full` filter. - F6 Hold span, Taken 1 "for the whole attempt". `repairExit`, `keepPlace`, `commandFailed` and `landedWake` run `mergeWake` and `phaseWake` inside `land`. `mergeWake` launches the next land while this hold is live, and `phaseWake` may start a seat. Fix: release the hold after the last verify, gates and push, before the wakes.
