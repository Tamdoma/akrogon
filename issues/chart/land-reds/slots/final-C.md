# Rebuttal and final-shape check: fix-shape — Slot C

No misstatement of C's notes. Four concrete defects in Taken 1–4 if built as written:

1. **Taken 1 — Thundering-herd overlap on consecutive land runs (`src/admission.ts` `awaitLineTurn`, `src/land.ts` `land`):** Taken 1 skips drain AND holds back only runs whose `since` is later than the live hold (`earlier since`). On a queued merge (like framework's 6-leaf queue), every leaf `cheap` and seat `run-check` queued during land 1 has `since` earlier than land 2's hold. When land 1 finishes and `mergeWake` starts land 2 (~1 s later), every queued run from land 1 sees `hold2.since > my.since`, wakes up at once, and bursts straight on top of land 2's `bun run framework:verify` — reproducing the exact load overlap on merges 2..N. Dropping `earlier since` without draining would instead starve queued leaf checks across the whole merge queue.
   - **Fix:** Have land 2 wait for already-live runs and earlier-`since` waiters to drain before starting `verify` (one short parallel burst between lands, while arrivals after `land2.since` wait), so land 2 runs quiet without starving leaf checks.
2. **Taken 1 — Holding the land record across exit wakes breaks slice cleanup and next-leaf admission (`src/land.ts` `land`, `src/reconcile.ts` `stopSlice`, `src/next.ts` `dispatchSlot`):** `land` calls `repairExit`, `landedWake`, `keepPlace`, and `commandFailed` before returning, and those call `mergeWake` (which runs `reconcile` -> `stopSlice` and launches the next leaf's `land`) and `phaseWake` (`dispatchSlot`). If the hold record (`leaf: slug`, `slice: leafSlice(repo, slug)`) stays live until `land()` returns: (a) `reconcile` `stopSlice` sees `liveRuns()` matching the merged leaf's slice (`live run record`) and leaves a `Kept:` slice; (b) `dispatchSlot` sees `liveRuns()` matching the leaf and suppresses silent-end checks; (c) the next leaf's `land` races the outgoing hold.
   - **Fix:** Release the land hold in `src/land.ts` `land` *before* calling `repairExit`, `landedWake`, `keepPlace`, or `commandFailed`.
3. **Taken 1 & 2 — Deadlock for a nested `full` child under a non-`full` land check (`src/admission.ts` `nested`):** `nested(token, repo, full)` returns `true` only when `((record.full && record.repo === repo) || !full)`. If a repo has a `full` check and a non-`full` `merge_checks` entry (or land `checkedRun`), a nested `full: true` `run-check` inside that live land check fails `nested()`, enters the admission loop with `attempt: undefined`, sees its own ancestor's live land hold, and deadlocks forever.
   - **Fix:** Change `nested()` to allow `((record.full || record.attempt !== undefined) && record.repo === repo) || !full`.
4. **Taken 4 — Requiring "a unit red outside the land run" prevents stopping `failed` on parallel-suite main races (`skills/check-issue/SKILL.md` `## check.repair`):** In `repair-round-bound/review-B.md`, `review-capture-by-unit/review-B.md`, and `runner-names-unbound-route/review-B.md`, the `renderers/1.99.9` main race passed every single-file narrow rerun on the head AND had whole-green base receipts (`4d22e25b`, `1f854bee`). Requiring a red narrow rerun or red base receipt before taking the main-red `failed` stop forces B to return that leaf unchanged to `merge` in an infinite loop (violating S1 throughput and S2 token limit).
   - **Fix:** Allow the main-red `failed` stop when B has either a unit red outside the land run **or** concrete land-log and unchanged-main-code trace evidence of an uncovered main-caused parallel-suite race/defect that a narrow single-file rerun cannot trigger (keep the ban on unrelated leaf-branch commits and leaf-caused-only `check.fix`).
