# Slot B final-shape check: disagreements and missing pitfalls

- **F1 — Q1 line 8 needs consistent stop removal.** Deleting only the Stop paragraph leaves `/watch-issues` refusing to create a job when the removed rule is satisfied, a tick still permitted to delete through that rule, and a notice promising automatic stopping. Remove those references with the rule. Say “never self-deletes,” rather than “ends only on stop,” because session loss and seven-day expiry remain. Evidence: `skills/watch-issues/SKILL.md:16-18`, `:38`, `:45`.

- **F2 — Q2 item 1 overstates existing trigger coverage.** Self-update does not run on each Herdr pass. Hooked passes have no selection and therefore an empty `updating` list. Working-status events return even earlier. Ordinary selected passes update their selected repo, while `--all` and `--resume` cover registered repos. Specify that coverage in the contract. If syncing the hook owner's repo is intended, it needs explicit wiring at that existing event, not an assumption that line 1543 already covers it. Evidence: `src/next.ts:1523-1543`, `:1631-1647`, `:1382`.

- **F3 — Q2 item 5 misdiagnoses the normal rejection path and promises reuse too broadly.** Although the persisted batch clears its stamps, `batchPush` returns the original stamped record and `finishPush` passes that record to `restack`. Normal conflict-free record-only restacking can already reuse the result. The remaining persistence concern is an interrupted or failed recovery before restacking completes. Preserve that evidence without bypassing the existing equivalence, config, conflict and dirty-worktree guards. “A records push never costs a rerun” is too broad because the sync-eligible paths include `issues/config.yaml`, whose change correctly refuses reuse. Evidence: `src/phase.ts:614-626`, `:880-882`, `:660-669`, `:702-719`, `:784-807`, `src/sync.ts:25-30`, `src/batch.ts:74-75`.

- **F4 — Q2 items 3–4 and 7 omit incoming-tree preservation checks.** Outgoing issue-only eligibility and refusal to overwrite dirty tracked files do not cover ignored operator paths or an incoming tracked coordination lock. Retain sync's existing checks for active lock paths and ignored-file/directory collisions when applying incoming trees, including a behind-only update. Holding a lock is not a replacement for preventing its path from being replaced. Evidence: `src/sync.ts:35-75`, `:78-106`, `src/self-update.ts:50-58`.

- **F5 — Q2 items 3–4 and 6 need an explicit partial-result and recovery rule.** The remote push can succeed while the keep-local-edits checkout move is refused. Report those outcomes separately and retain the original local history and dirty edits. The checkout is then pending, not synced. Uncommitted records can cause this refusal, contrary to item 3's blanket “cause no error” claim. Also, retrying the same committed-record conflict next pass does not resolve it. Name the conflicting paths and resolution route, and leave the off-tree replay cleaned up or with an explicit recoverable owner. Evidence: `src/self-update.ts:50-58`, `src/sync.ts:122-135`, `issues/chart/night-flow/slots/keep-running-final-shape.md:14-17`.

- **F6 — Q2 item 3 overstates the release effect.** Every main push starts the framework workflow, but an issue-only change leaves the tree without `issues/` unchanged and the workflow exits without publishing a new release commit. The cost is a workflow run, not necessarily a new release. Committed-only integration remains the boundary that avoids publishing unfinished records. Evidence: `/home/ivan/Work/infra/tamdoma/framework/.github/workflows/release-branch.yml:3-5`, `:29-44`.

- **F7 — Q2 item 8 must narrow the documentation amendment.** Remove the manual sync remedy for eligible record-only ahead/diverged history. Retain the operator actions for a wrong branch, detached checkout, local code commits and overlapping unfinished edits. Item 6 explicitly retains the code-ahead skip, so deleting the ahead/diverged remedy wholesale would leave that permitted stop unexplained.
