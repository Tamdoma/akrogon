# Slot B: existing-backlog final-shape check

- **F1. The missing-tracked-file refusal blocks the required retry.** Draft :7 refuses any tracked log missing on disk. Packing itself deletes those files before their removals are staged or committed (:6, :9). If packing stops after deleting one file, or succeeds but a later migration check fails before the commit, rerunning pack sees its own deletions as missing tracked files and refuses. That contradicts retry union and the promised failed-pack recovery (log-coverage.md:29). Before refusing a missing tracked path, check whether the existing verified archive contains its member with the expected indexed bytes. Accept that already-packed state. Refuse an unexplained absence or byte mismatch. This must also work when all plaintext was already removed.

- **F2. The staging command includes unrelated changes inside each selected folder.** Draft :9 says `git add -A -- <folders>` while promising to leave unrelated pending work unstaged. A closed-owner folder also contains reports, plans and state. A chart argument is the whole chart, while the pack modifies only its direct folder (:5). That command therefore stages unrelated edits and untracked files under those roots, including chart notes and slots returns. Stage the exact published archive paths and exact successfully migrated log removals, plus the separately authorized paths in :10–11 and only the intended .gitignore changes. Inspect the resulting staged set and account for any pre-existing staged work before committing. Folder-level staging does not satisfy the stated isolation.

- **F3. The status worklist misses a failed pack after its final plaintext deletion.** Draft :8 lists only folders holding plain logs. The taken failure policy leaves `.closing` until a successful retry removes it (log-coverage.md:29). A crash after the final verified source deletion but before marker removal leaves an archive and `.closing`, with no plaintext. That folder disappears from the migration worklist despite requiring recovery. In a chart it also continues blocking run-check publication under the accepted closing guard. Include stranded `.closing` holders in the status recovery output and name the retry command, with the archive-only retry behavior from F1. A leftover closing marker must not be interpreted as completed migration.

- **F4. The execution condition excludes the assigned executor.** Draft :9 requires no chart door to be open on the repo, but :13 assigns this operation to the chart door. State that other chart/learn writers must be quiescent and exempt the door performing this maintenance step, or assign an executor that can run after that door closes. As written, the named owner cannot satisfy the stated run condition.
