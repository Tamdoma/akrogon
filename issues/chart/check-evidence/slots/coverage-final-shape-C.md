# Slot D check: log-coverage final shape

Disagreements only. Draft refers to `coverage-final-shape-draft.md` items by number.

- F1. Item 7 does not name the stream, and its model points at the wrong one. Verify's lines are `process.stdout.write` (src/verify.ts:163,170), but run-check's stdout is the child's own stdout passed through (src/run-check.ts:205), and callers parse it exactly: tests/run-check.test.ts:117 (`toBe(expected)`), :129-131 (stdout used as a path), :430 (`toBe('session|')` on a printed check from src/config.ts:318-319). A `check ...` line on stdout breaks every such caller and glues onto child output with no trailing newline (`printf %s` cases above). The line must go to stderr, where the existing meta line already goes (src/admission.ts:154, `run <id>`), with a leading newline when the child's stderr (src/run-check.ts:206) does not end in one. It must print in the `runCheck` CLI wrapper (src/run-check.ts:143), not in `checkedRun`: verify calls `checkedRun` for setup and each command and prints its own line per command (src/verify.ts:154-170), so a `checkedRun` print duplicates every verify line. Either stream breaks the whole-stderr matches at tests/check-names.test.ts:26 and tests/run-check.test.ts:428; those tests need updating as part of item 7.

- F2. Items 1 and 4 do not say who removes `.closing` for a chart. In the Taken owner flow `.closing` is written before the pack and the owner is then renamed (evidence-location.md, Taken item 3). A chart is not renamed. If the shared pack leaves `<chart>/direct/.closing` in place, item 4's refusal blocks the reopened chart's new plain logs forever; if the pack removes it, the owner caller loses its refusal between pack and rename. The draft must pin creator and remover per caller, including the pack-failure path (a failed chart pack that leaves `.closing` blocks all later direct verify/run-check writes).

- F3. Item 6 does not say which status invocation warns. Charts are only read under `--charts` (src/status.ts:399-404); plain `akrogon status` never reads `issues/chart/`. The door runs plain `akrogon status` at open (skills/chart-issues/SKILL.md:31). A warning wired into `chartRows` therefore never fires on the run meant to catch a missed pack. Pin it to plain status (the Failed/Missing scan loop at src/status.ts:381-396 is the existing plain-status warning surface) or say `--charts` and change the door's open run.

- F4. The log set differs across items. The shared pack from Taken is recursive (every `*.log` under the owner, evidence-location.md Taken item 3); items 2, 6 and 9 say "in the folder"; item 3's ignore is the non-recursive `issues/chart/*/direct/*.log`. The only writer today writes top-level files (src/run-check.ts:208), but item 9's stray hand logs can be nested, and a recursive pack would delete a nested log that was never ignored and that item 6's warning (top-level reading) never saw. Dotfiles are a second split: one tracked direct log is a dotfile (`issues/chart/system-speed/direct/.ask-B1.log`, in `git ls-files`), which glob-based and readdir-based matching treat differently. Pin one set (recursive or not, dotfiles in or out) used by pack, the status warning and the ignore line.

- F5. Item 8 as written double-wraps the main check path. The printed `checks`/`merge_checks`/`advisory` commands already are `akrogon run-check --name ...` (src/config.ts:317-319), and `akrogon verify` already writes each command's log (src/verify.ts:154-170). A seat following "any kept command output runs through `akrogon run-check --name <label> -- <cmd>`" wraps those again; a nested run-check writes 2 logs for one run (tests/run-check.test.ts:363-372). Item 8 must exempt printed check commands and verify runs explicitly.

  1. Standalone implement-issue has no config or leaf (skills/implement-issue/SKILL.md:88-92) and standalone workers run in the plain checkout (skills/implement-issue/worker-protocol.md:11). `runCheck` requires a registered repo and a leaf worktree or `--holder` (src/run-check.ts:126,141).   2. Item 8's "any kept command output" must exempt coordination commands or these steps keep hand-recorded output.
  3.
