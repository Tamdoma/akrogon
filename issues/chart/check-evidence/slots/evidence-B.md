## Q1. Where full check evidence lives

### Pick, reason and cost

D1. Keep the full evidence in the consumer repo, compressed separately per log. Keep reports and their useful excerpts readable. Give code and seats one supported way to resolve a reference and read the full decompressed log. Prefer publishing the compressed retained copy when a run ends, rather than repeatedly committing plain logs and compressing only when their owner closes. This is a storage-location recommendation, not a decision about which producers the coverage fork adopts.

Reason: readers already span later review, repair, flaky analysis and historical investigations. A clone or restored repository should contain the evidence those records cite, without depending on the originating machine or a second storage service. Per-log files preserve independent run identities and avoid a mutable archive shared by every leaf under an issue or epic. A short failure excerpt is a navigation aid, not the complete evidence.

Cost: ordinary `cat`, `rg`, Markdown file links and raw UTF-8 readers cannot read compressed contents unchanged. The reader and reference migration are part of the change. Independent compression may save less than a combined archive, retains many files, and does not guarantee a smaller Git pack. No codec or size target is selected here. The intake's 19 MB result was one combined `tar | zstd -19` stream, not a measurement of separately compressed logs or one archive per owner.

D2. A retained reference must identify a log within its repository independently of this host's checkout path and the owner's open/closed location. Preserve a way to resolve existing references during the separate backlog migration. The current absolute filename is not a portable evidence identity.

### Pitfalls and what removes them

R1. A compressed file exists but cannot be found from its old citation. Remove this by defining one portable locator/resolver used by code and seats, including closed owners, parked/unparked owners (`src/park.ts:61-68`) and a clone at a different root. Backlog handling must preserve or translate old references rather than merely rename files.

R2. Green gates are mistaken for a lossless migration check. Remove this by checking the retained object can be decoded to the original bytes and resolved by the actual reader before retiring its source. `greenRun` checks none of that today. Do not silently map corruption to an empty log or successful retrieval.

R3. A first/last-N-lines excerpt omits another failure or terminal result. Keep excerpts bounded for navigation but retain complete bytes. Keep command, tested revision, completion/exit and log identity together. Preserve both inconsistent runs, not just the green retry.

R4. Interrupted evidence is discarded because no leaf closes. The base-red lock applies to incomplete failed runs too. Storage and cleanup must retain whatever output was captured without relabelling it complete. There is a current capture limitation: `spawnLogged` appends stdout/stderr only after capture returns (`src/run-check.ts:74-76`), the kept copy is made at `:209`, and finally removes scratch at `:221`. Killing the wrapper before publication may leave only scratch captures. A location choice cannot recover uncaptured output. Carry that writer/coverage issue to the relevant fork rather than promising compression fixes it.

R5. “Lossless” is overstated as the original event stream. The existing saved log joins decoded stdout then stderr (`src/run-check.ts:74-76`), not their original interleaving. Require lossless preservation of the existing retained content. Stream-capture semantics are separate unless explicitly included.

R6. A close-time archive misses direct runs or admits concurrent writes during owner closure. Use a publication lifetime independent of issue closure for per-run storage. If the archive option is chosen, explicitly own sealing, member indexing and later additions instead of placing an uncoordinated archive operation beside `completeOwner`'s rename (`src/phase.ts:223-224`).

R7. Compression is sold as a history-size cure. Report current-tree savings separately from object-database and normal-clone sizes. Measure the chosen grouping/codec before claiming a number. The existing-backlog fork decides migration, and history rewriting stays out.
