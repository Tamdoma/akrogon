# Final-shape check C: evidence-location

Checked against akrogon main f3557d8 and host facts 2026-10-15 (Bun 1.4.3, GNU tar 1.35, zstd 1.5.7 at /usr/bin). Read-only.

1. Step 4 breaks the chart writer. `akrogon verify --holder <chart>/direct` (`skills/chart-issues/SKILL.md:108`) resolves its target to `<cwd>/<holder>` under `issues/chart/` (`src/run-check.ts:126-127`), which is not under `issues/open/`, so "refuse a target whose owner folder is not under issues/open/" refuses every chart check. Correction: refuse only a target under `issues/closed/` (and, per item 2, under an owner that is closing).

2. A log can be lost or land plain in `closed/`. The owner stays under `issues/open/` until the final rename, so a check that finishes between the disk scan and the rename (a tabless operator verify, a stacked member's late run) writes a plain log after the archive is built; step 4 does not block it, and "a retry never rebuilds from a subset" leaves it out of the archive. After the rename it sits plain under `closed/`, outside the `issues/open/` ignore, and `sync` commits it plain (`src/sync.ts:140-152` lists any untracked file under `issues/` with `--exclude-standard`). Correction: write `<owner>/.closing` before the scan; run-check refuses a target whose owner holds `.closing` or lies under `closed/`; a retry (the sites exist: `src/next.ts:773`, `src/phase.ts:780`) finding `.closing` repacks from the archive members plus any plain log present, never fewer, then verifies, deletes, renames.

3. How to pack and read without a new dependency. Bun has zstd but no tar: `Bun.zstdCompressSync(buf, { level: 19 })` and `Bun.zstdDecompressSync` exist in 1.4.3 (checked). Verified round trip on this host: `tar -cf - -C <owner> <members…>` piped into `Bun.zstdCompressSync`, written as `evidence.tar.zst`; read with `Bun.zstdDecompressSync` fed to `tar -xOf - <member>` on stdin, bytes equal to the source. GNU tar also reads the Bun-made file directly (`tar -xOf evidence.tar.zst <member>`) and `zstd -dc` lists it, so the operator's `tar -I zstd -xOf` line holds. A missing member exits tar with 2 and "Not found in archive" on stderr, which maps onto step 5's non-zero exit. Member names reach 178 chars in framework (`find issues/closed -name '*.log'`, relative to owner), above the 100-char ustar field; GNU tar handles that with its long-name entries, a hand-rolled tar reader in Bun would not. So: system `tar` for both directions, Bun for zstd; the only external need is `tar`, present on every Linux.

4. Memory on read. `Bun.zstdDecompressSync` is whole-buffer: `akrogon log` on a member of the largest owner today holds 148 MB (backlink-audit-run's plain logs sum, `find … -printf %s`) to print one file. Acceptable, but when `/usr/bin/zstd` exists the reader should stream `zstd -dc | tar -xOf -` instead. Same for the step 3 verification: `tar -xOf` per member re-reads the whole tar once per member; extract once to a temp dir and compare, then delete it.

5. Step 2 names no writer for the ignore line. `src/init.ts:67-76` appends missing `.gitignore` lines at `akrogon init` only; framework's `.gitignore` has no log line today, and until it does `sync` keeps committing plain open logs. Correction: add `issues/open/**/*.log` to the init additions and state that existing repos get it by rerunning `akrogon init` (idempotent, it filters lines already present) or by the self-update step. The 4 already tracked open logs in akrogon stay tracked until `git rm --cached` (existing-backlog).

6. Step 5 resolver needs two rules it does not state. Which repo: a recorded path from another checkout root carries no repo, so resolve the tail inside the repo of `cwd` (`requireRepo`) and, outside any repo, against every registered repo. Which owner: completeOwner's owner is the issue or its parent epic (`src/phase.ts:192-196`), moved to `issues/closed/<basename(owner)>` (`:199`), so the tail's first component after `open/` or `closed/` is the owner and the member is the rest. Logs under a nested epic (`open/<epic>/<issue>/<leaf>/…`) resolve only with that rule.

7. Minor: pack with `--dereference` or refuse symlinks, since `tar` stores a `.log` symlink as a link and the read-back then compares nothing (none under `issues/` today).

No disagreement with steps 1, 6, 7, 8.
