# Slot C final-shape check: existing-backlog

Disagreements only. Draft items numbered as in `backlog-final-shape-draft.md`. Measurements read-only, 2026-10-15.

- F1. Items 5-6 staging does not do what item 5 claims, and item 6 commits half an owner move. `git add -A -- <folders>` stages every pending change inside each named folder, not just the pack output; for a chart the named folder is the whole chart, and framework's main checkout today holds 17 modified files under `issues/chart/` unrelated to packing, so "leaving unrelated pending work unstaged" holds only outside packed folders. Item 6 is the concrete break: today `git status` shows 10 deleted paths under `issues/open/merge-batch/` (the 4 logs plus ISSUE.md, brief, design, plan, readiness, state) and the whole `issues/closed/merge-batch/` untracked (27 of the 61 untracked closed logs are this owner's). Following the draft stages the closed folder whole (item 5) and only the 4 open log deletions (item 6), committing a duplicate owner under both `open/` and `closed/`; the still-open copy can later complete into a destination that already exists (src/phase.ts:200). The draft must either require the merge-batch move already synced before the run (then item 6 is a no-op and the 4 logs pack as ordinary closed logs) or stage the entire move, not its log subset. I verified the premise itself: the 4 closed disk copies hash byte-identical to their tracked open blobs at HEAD.

- F2. Item 1 accepts folder forms but never anchors them to the registered repo root. As written, a folder argument that resolves into a leaf or verify worktree's inert `issues/` copy matches the accepted shape and would pack and delete plain logs there; untracked logs in that copy are sole copies, and the archive dies with the worktree. The command must resolve each argument against `repo.root` from the registered checkout (the root `requireRepo` returns, src/config.ts:238-256) after realpath, and refuse anything outside `<root>/issues/closed/<owner>` or `<root>/issues/chart/<chart>`. Item 5's "main checkout" is an operating instruction, not a guard the writing command enforces.

- F3. Item 5 stages `.gitignore` lines "from `akrogon init`" but no step runs init, and neither repo's `.gitignore` holds a `*.log` line today (grep, both checkouts). Running init also rewrites `issues/config.yaml`, the global config and `.gitattributes` (src/init.ts:62-85), which item 5's selective staging would leave pending without saying so. The same item commits and pushes with plain git, bypassing sync's lock, fetch and rebase (src/sync.ts:24,56,129), with no up-to-date check before packing and no stated path for a rejected push. Sequence as written cannot produce the ignore lines it stages, and can pack a stale tree whose archive commit then needs rebasing.

- F4. Item 5's verification cannot see most members. The flaky comparison exercises only red receipt logs: framework receipts name 77 unique logs against 4,460 tracked closed files, and the majority of closed logs are hand-named files no receipt names. The pack's byte-equal read-back (taken) is written and read by the same code, so a member-root naming error passes it and is caught only by reading through the resolver; "read a few cited paths" does not require even one per owner, one hand-named member, or one untracked member (the sole-copy class: 61 akrogon files). Require, before committing, at least one tracked path per packed owner read via `akrogon log` and byte-compared against `git show HEAD:<path>`, plus one chart-direct and one untracked member per repo.

- F5. Items 1 and 3 leave multi-folder failure semantics unspecified. One call takes many folders and item 3 refuses per owner, but the draft does not say whether a refusal aborts the call or continues past folders already packed and deleted, nor what exit code and output the door then acts on in item 5, whose sequence assumes one clean pass before the flaky comparison and staging. No byte is lost either way (deletes follow verified read-back), but as written the door can stage and commit a partial run while believing the worklist done; the call must refuse all folders up front or report per-folder results with a non-zero exit naming every folder not packed.

No disagreement with items 2, 4, 7 and 8 as written: the log set and refusal split in items 2-3 match today's disk (akrogon closed: 755 log files on disk = 694 tracked + 61 untracked, none ignored, none symlinked), item 7's brace list matches the 9 tracked slots files exactly, and item 8 records the dead receipts as a gap.
