# Slot B: coverage final-shape check

- **F1. Specify stderr for the new run-check receipt, at the CLI boundary.** Draft line 11 says “like verify,” whose receipt goes to stdout (src/verify.ts:163,170). run-check currently passes the child's stdout and stderr separately (src/run-check.ts:205–206), and its existing admission message goes to stderr (src/admission.ts:154). Adding the receipt to stdout changes the command's data output, breaking JSON parsing or command substitution for wrapped commands. The new “any kept command output” rule makes this especially relevant. Print the receipt to stderr in runCheck after checkedRun returns (src/run-check.ts:143), preserving the child's exit code and stdout. Do not add it inside checkedRun, which verify also calls (src/verify.ts:154,167). I found no concrete stdout parser calling run-check in the inspected src/skills, so this is a missing output contract, not a claim of an observed parser failure.

- **F2. “Any folder” can archive logs outside the resolver's supported layout.** Draft line 5 allows `akrogon pack <folder>` anywhere, but line 9 and evidence-location.md:40 recognize only owner-root archives and chart/direct archives. For example, packing `issues/open/<owner>/<leaf>/implementation` puts evidence.tar.zst there and deletes the plain check logs. The reader instead searches `issues/open/<owner>/evidence.tar.zst` for `<leaf>/implementation/<log>` and fails. This is the actual writer location (src/run-check.ts:107,114,123). Restrict pack to the supported archive roots, or explicitly specify how the reader discovers every permitted archive location before allowing source deletion. The same restriction must align the .closing location with the writer's guard.

- **F3. Shared packing must preserve the owner's closing guard through the move.** Draft line 5 says `.closing` lasts “while it runs.” That is sufficient for a reusable chart holder, but not if the shared function removes the owner's marker before returning to completeOwner. The taken shape keeps the owner guarded across packing and the move (evidence-location.md:38–39), and the rename is a separate caller operation (src/phase.ts:221–224). Clearing the marker when packing returns permits another process to publish into the open owner before the move, after the archive snapshot. State that completeOwner retains its guard through the rename, while a successful standalone chart pack releases its guard so later attempts can write. Also define failed-pack retry/release behavior instead of leaving the marker lifetime to inference.

- **F4. The blanket retained-output rule must exclude lifecycle commands that close their own holder.** Draft line 12 says any kept command output must run through run-check. merge-issue SKILL.md:69 runs `akrogon phase <slug> merged ...`, which pushes and moves the owner on completion, and :79 consumes its completion lines for broadcast. Wrapping that command to retain its output captures the leaf target before execution (src/run-check.ts:142–143), but publishes its log after the child returns (src/run-check.ts:205–209). At that point completeOwner has moved the owner (src/phase.ts:224). The taken late-writer rule must refuse this publication, so a successful completion would produce a failed wrapper and only the retained temporary capture. This command therefore needs an explicit retention route outside its own leaf's run-check publication. Do not require wrapping verify again either: its existing per-command logs and receipt already provide retained output (src/verify.ts:154–170; merge-issue SKILL.md:73). The ordinary range-diff instruction (merge-issue SKILL.md:55) can use run-check and does not itself require a hand-saved log.
