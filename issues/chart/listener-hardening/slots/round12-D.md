# Round 12, slot D: the warm-up wait races claude's /clear turn

## Q1 — Mechanism confirmed for claude; codex and pi have no working period to race with

- hc semantics, from `hc schema`: a terminal's `turn` "goes up each time the status leaves `working`", and `send` returns "the turn when the text went in". Turn is a counter of turn ends, not an identity for the turn a send started. `waitFor` (`src/hc.ts:444`) evaluates its predicate on the follow snapshot and on each status/turn event, serially (`src/hc.ts:377,398`).
- Timeline, log against both transcripts: reset keys 13:27:49.969; `/clear` is itself a little turn in claude — the new file 1ae36dec opens with the `/clear` command records at 13:27:49.944-.994 (lines 6-8) and its status leaving `working` is turn 18. The warm-up send snapshotted turn 17 at 13:27:50.174 (`skills/chart-issues/scripts/door-reset.ts:106-108`), so `t.turn > warm.turn && idle(t)` (:110-115) was satisfied by the /clear turn end 2 ms later. Code lookup ran at 13:27:50.183; the warm-up prompt record only exists from 13:27:50.221 (1ae36dec line 10) and the reply at 13:27:53.871 (line 41). The lookup could not have found the code yet. Nothing is claude-specific in the helper's mistake: it used "a later turn ended" as proof of "the warm-up turn ended".
- Codex `/new`: starts no model task; its new rollout opens only at the next prompt (live-recorded in P3, encoded at `tests/door-agent.ts:9-10`). With no `working` period, status never leaves `working`, so its turn cannot advance on `/new`. Pi `/new`: pi emits 7501 itself (builder in the pi binary), and `/new` swaps the session while the agent is idle, again with no agent run. Neither is re-verified live here (read-only; a throwaway seat check is `hc get` turn, keys `/new`, `hc get` turn), but the race needs a reset that runs as a turn, and only claude's does. The fix below removes the dependency for all three anyway.

## Q2 — Make the code sighting itself the wait condition

- Recommended: fold the lookup into the existing wait. `waitFor` already accepts an async predicate (`src/hc.ts:447,467`), so the warm-up block (`door-reset.ts:110-122`) becomes one wait whose predicate is: gone, or idle and `transcriptByCode(seat, code, resetStart)` finds the code (kept in a closure variable). Turn ends become wake-up ticks to re-check the evidence, never the success proof, so any number of stray turn ends before the reply — the /clear turn, a SessionStart-hook turn, a queued system-notification turn — cost one failed lookup each, not a wrong stop. On timeout the helper stops as `code-lookup` / `reset unconfirmed` (the accurate name for "the code never appeared within the bound"); stage order and the differing-path, label and start-prompt steps stay as they are, so the STAGES assertions in `tests/door-reset.test.ts:15` need no reshaping. Cost is a handful of extra candidate-file reads during one warm-up window; the single `DOOR_RESET_TURN_BOUND_MS` bound still applies. This is a small reshaping of code that already exists, no new files, timers, polling loops or per-harness branches.
- Rejected: settle after the keys, then take the turn baseline. It narrows the window (the known stray turn is spent before the baseline) but keeps a turn count as proof; the next stray working-to-idle cycle after the send re-opens the same race. Also rejected: claude waits on its session record's sessionId and drops the warm-up. The record has no event channel, so that is a bounded file poll plus a claude-only branch beside code lookup for pi and codex, and a changed sessionId proves the reset ran but not that the seat answers prompts, which the warm-up reply proves today for the start prompt that follows. One uniform evidence check is fewer parts than two confirmation mechanisms.
- Fake, `tests/door-agent.ts`: the reset branch (:128-133) currently only sets `pendingSwitch` and emits no status, so no turn ever comes from a reset line. For claude it must run a turn cycle like the real one: queue `status('working')`, apply the switch (open the new transcript and session record then, as real /clear already writes its command records into the new file), the same short sleep `turn()` uses (:110-121), then `status('idle')` and a turnEnd line. With inputs processed in order, the helper's warm-up send then snapshots the pre-clear turn and the /clear turn end lands next, which reproduces this incident against the old wait and passes against the new one. Keep codex and pi resets turn-less (their recorded shape), so the matrix covers both reset shapes. `noswitch` gets the same claude turn cycle without the file change, so the differing-path case also rides the new wait.
