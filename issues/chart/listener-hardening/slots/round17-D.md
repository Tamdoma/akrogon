# Round 17, slot D: S1 (delete the warm-up) attacked

## Q1 — What the outside warm-up actually protects

Three real losses, in order of weight. Everything else door A implies checks out.

- A1 Start-prompt submission is no longer provable. Today the start prompt is sent into a seat proven idle and responsive, so `send`'s `started` means something and the enter-once fallback (`door-reset.ts:148-152`) can work. Under S1 the send lands ~200 ms after the reset keys: for claude that is inside the `/clear` turn (measured ~230 ms), where the seat is already `working`, so `started` reports the pre-existing turn and proves nothing about the paste. The failure shape is the start prompt sitting unsubmitted in the new conversation's composer — the one state nobody downstream can see ("text typed but not submitted is not seen", SKILL.md:167) — with old A's context already destroyed. FIFO terminal bytes and claude's queued-prompt handling saved exactly this timing twice live (the warm-up itself is sent then today), so this is a small probability, not a certainty; but S1 makes the first unverified delivery the payload instead of a disposable canary. Cheap guard that keeps S1: reuse the existing first wait (`door-reset.ts:97`) once more after the keys — send only from an idle snapshot. For claude that waits out the clear turn; for codex/pi/agy (no reset turn) it returns at once, and byte order still puts the paste after `/new<enter>` in the input stream.
- A2 A transient self-lookup miss becomes destructive. Fresh A's continue check (SKILL.md:163) refuses on an unknown path, and under S1 that refusal happens after the reset, so a torn claude session record or an agy lock read at the wrong instant strands the seat in no chart with old A's context gone and the start prompt already consumed (re-prompting by hand recovers it; the Mode entry is still unconsumed). Today's equivalent failures stop before the reset (`transcript unknown`, `unsupported harness`, `door-reset.ts:89-91`), leaving old A intact and re-runnable. Probabilities are tiny, but the asymmetry is structural: every S1 self-check failure is post-destruction. One prose clause mostly closes it: on `-`, fresh A re-runs `transcript.ts` once (its own prompt is persisted by then, so the re-read is race-free) before refusing.
- A3 The failure record shrinks to whatever fresh A narrates. Rounds 12 and 16 were diagnosed from the staged log because the helper was a witness independent of the seat. Under S1 there is nothing post-reset left to diagnose, which cuts both ways; a failed reset (typed composer text turns `/clear` into chat, a harness update renames the command, keys land in a dialog) still ends where door A says: same-path self-check refuses, handover unconsumed, operator sees it in the conversation. I classify this as acceptable, not a blocker: the payload reached the wrong context in those cases, but the only actor who reads it is old A, whose mandated next move is the refusal itself.

Not losses, checked because the brief names them: operator input between check and send is a smaller window under S1 than today (today's input check also cannot see input typed during the warm-up turn, minutes later than the check; both designs end with byte order deciding). The watcher steer check (watch-issues SKILL.md:44) degrades safe: between reset and fresh A's first lookup the label is stale, observe resolves the live path, the comparison mismatches, and the watcher notifies instead of steering; fresh A's mandated `transcript.ts` call then relabels (`transcriptFor` relabels on change), exactly as door A's point 4 says. Usage and seat records are unchanged (both keyed on paths fresh A records itself).

## Q2 — Pi: door A's reading is correct, and as stated S1 breaks pi

Confirmed, in both directions. A pi door started with `--session-id` (only `src/seat.ts:75` mints one, at `akrogon seat` launches) is already broken end to end today: `piStart` answers from argv forever (`src/transcript.ts`, piStart/piSession), so after the helper labels the post-`/new` file, fresh A's own lookup re-derives the pre-reset file, relabels it back, and the SKILL.md:163 comparison of equal paths refuses. A pi door without `--session-id` (the hc template seats, e.g. this one: no flag in argv) works today only because the helper's label survives as the fallback; under S1 nobody sets that label, fresh A prints the stale one, and that door breaks too. Pi also offers no other process-side handle: its pid holds no session file open (checked my own seat's fds: none), so no codex-style open-file lookup exists.

Smallest fix, self-lookup only: pi injects its current session into every tool call's environment — documented (`docs/environment-variables.md:26-27` in the pi install: `PI_SESSION_FILE`, absolute path to the current session file) and live-verified in this seat, where it names exactly my current transcript. In the chart's `transcript.ts` (the script SKILL.md:163 and the Mode line already use): when the queried address is the caller's own (`$HC_TERMINAL_ID`) and `PI_SESSION_FILE` is set and exists, print it before falling back to `transcriptFor` — about three lines in one script, no src/resolver change, and it also repairs today's `--session-id` door under the current design since the same script produces the path fresh A compares (the helper's own `transcriptFor` for `pre` keeps working: argv still names the pre-reset file, which is the correct pre). The analogous names exist for the others (`CLAUDE_CODE_SESSION_ID` is read by the claude binary itself for its own session ids; `CODEX_THREAD_ID` sits in codex's tool-env snapshot list; agy formats `ANTIGRAVITY_CONVERSATION_ID=%s` into shell env) but none is needed: their self-check already resolves through the resolver. Rejected instead: finding pi's current file from outside (newest file in the per-cwd sessions folder guesses wrong whenever two pi seats share a cwd) and the code-carrying start prompt (works once, at the continuation check only, and needs a new finder mode in the script that the env var makes unnecessary).

## Q3 — If not S1, what removes the class

The herdr-era helper (`af28d63e^:skills/chart-issues/scripts/door-reset.ts`) is instructive: it confirmed the reset by polling herdr until `agent_session.value` differed (`waitNewSession`), identity pushed by each harness's own integration at session start, before any prompt — no warm-up except a codex-only check prompt, because codex's rollout opens at the next prompt. Every design since hc has been re-deriving, from outside, an identity only the seat knows for free. S1 is the first one that stops re-deriving it and asks the seat; the heartbeat (round 16) instead keeps deriving and adds a wake so the derivation eventually reads fresh data; B's handshake asks the seat but also makes it report back, which buys a staged log at the cost of a prose protocol (helper address plumbing, a model-compliance dependency, a message parser). If S1's losses above are judged too much, heartbeat is the fallback: it removes the round-16 race with no behavior change. Handshake is strictly more mechanism than either for a log S1 makes unnecessary.

## Q4 — Verdict

S1, with the pi env fix in the same change (without it S1 is a pi regression and the verdict flips to heartbeat), an idle snapshot before the start send (A1's guard; reuses `waitFor`, deletes far more than it adds), and the retry-on-`-` clause (A2). It removes: the warm-up turn and its cost, the code, `replySchema`, `answered`, the reply wait and three stages, and `transcriptByCode`/`resetCandidates` (no other callers: only `door-reset.ts:14,135,142` outside `src/transcript.ts` itself). What stays harness-specific is what must: the reset word, the input check's record shapes, and the resolver's lookup branches for `pre` and for other seats' records. Nothing in S1 depends on flush order, turn counting, or wake sources, which is the whole class rounds 12, 13 and 16 chased one layer at a time.

Verdict: S1 as amended above. It survived the attack: its concrete losses are a canary it deliberately spends the payload on (A1, guarded by the idle send) and post-destruction refusal (A2, guarded by one re-read) — not new races.
