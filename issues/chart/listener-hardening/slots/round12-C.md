## Q2: smallest fix

- Make the code the condition, not a turn count. `waitFor`'s predicate may be async (`src/hc.ts:447`: `until: (t, line) => boolean | Promise<boolean>`), so the warm-up wait becomes one call:
  `waitFor(session, a, async (t) => gone(t) || (await transcriptByCode(seat, code, resetStart)) !== null, env.DOOR_RESET_TURN_BOUND_MS)`
  replacing `door-reset.ts:109-120` (the turn wait and the separate lookup; keep the `gone` stop and capture the found path in the closure or look it up once after). The check runs on every hc event line for A, so it is event-driven, no delay, no polling, and the turn end of the warm-up reply is always an event that follows the record write. `resetCandidates` already filters to files changed since `resetStart` (`src/transcript.ts:163-176`), and for claude the session record names the new conversation from the `/clear` itself (door A saw the label already `1ae36dec` at 13:28:12; t32's record names a conversation that has no file yet), so the new file is a candidate as soon as it exists. Nothing else changes: same stages, same bound, same "same transcript" check.
- Rejected: "settle after the reset keys, then take the turn" keeps the race (the reset's flip can arrive after the settle read and before the warm-up's own flip; the gap today was 2 ms). "Session record sessionId differs" for claude works and would drop the paid warm-up turn for claude, but it adds a kind-specific confirmation beside the code path pi and codex still need (their new file appears only at the next prompt, `forks/proofs.md:25,27`); a later cost cut, not the fix for this race.
- The fake: on the reset line, `tests/door-agent.ts:124-131` should write `status('working'); status('idle')` (claude's observed behaviour) before setting `pendingSwitch`, so hc's turn moves once without a transcript record. With that, the current helper fails the way t3k did (turn wait satisfied, code absent) and the predicate version passes; no new fixture, one line in the fake.
