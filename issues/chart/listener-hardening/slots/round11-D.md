## Operator question: why old herdr worked, and the simplest shape

(1) How old herdr got it. Door A's diagnosis is right, and the claude half is verifiable. The operator's backed-up Claude settings (`~/.claude/settings.json.bak.editor:136-145`) hold a `SessionStart` hook, matcher `*`: `bash '~/.claude/hooks/herdr-agent-state.sh' session`. SessionStart fires on startup, resume and `/clear`, so the agent itself pushed its new session to herdr at the moment it changed. Pi was the same shape through herdr's own integration (`herdr integration install pi`, records with source `herdr:pi`: `~/.pi/agent/extensions/tamdoma-herdr-session-watch/README.md:3,143-146`). Herdr stored it per pane as `agent_session {kind, source, value}` and akrogon only ever read it live (`herdr agent list`): door-reset compared live values before and after the reset (`af28d63e^:skills/chart-issues/scripts/door-reset.ts:115,180,265`), and the chart skill said a fresh A "never invents one" (`af28d63e^:skills/chart-issues/assets/shapes.md:58`). One owner (the agent), one store (herdr, beside the pane), refreshed at the change, read at use. That is why it could not drift. The hc move deleted the store: hc status carries `app` and `state`, no session. `src/transcript.ts` was created in that same port (5713fd5f, 2026-11-07) and replaced a reported fact with a derivation (the open tasks folder) plus a label cached forever: two copies, neither refreshed, and the derivation turned out to name the process's first session. The hook and its settings entry are gone now (current `~/.claude/settings.json` has only moshi hooks, `~/.claude/hooks/` is empty), so there is no push channel left for claude, and akrogon must not recreate one by editing Claude settings.

(2) Fewest moving parts. Available today, O1 (this commit, once F1 lands): it reads the owner's own per-process record at lookup time. No new files, no polling, no watchers; the read happens exactly where the answer is consumed, the way `/proc` was already read. O2 is out by the never-edit-Claude-settings rule (old herdr could do it because the operator ran `herdr integration install`, herdr's own consent path). O4 only frees door-reset; observe, usage, timing and log still need the path, so the resolver survives anyway. The label: no consumer needs it as a source anymore. Log, timing and observe all call the resolver; seats.yaml stores the path as data; fresh A re-derives its own. Its two remaining uses are a record for seats whose process is gone (the fallback at `src/transcript.ts:159`, which `src/log.ts` diagnostics rely on) and the watch steer check comparing label to judged log (watch-issues SKILL.md:44), which works only because every lookup relabels on change. Deleting the label saves about three lines and costs both; keeping it as a write-through record that is never trusted while the process can speak is the right size. The real end state is O3, one step further than door A framed it: session identity belongs in hc, next to the terminal and pid it already tracks, whether hc reads the same owner record (or a future reported field) and exposes it on `hc get`. Then `src/transcript.ts` shrinks to "ask hc, locate the file", the per-harness filesystem knowledge lives with the process tracker instead of every consumer's resolver, and the label can finally go. That is upstream work in herdr-core, not a reason to hold this fix.

(3) O1 versus main: it removes complexity where it matters and adds a little where it does not. Out: the tasks-folder guess (a name that was never the conversation) and the trust-forever cache. In: one small owner file to parse, a pid-reuse check, and a folder scan (the same exactly-one-match scan pi already used). Net mechanism is smaller, and the remaining per-harness derivation in akrogon is not new complexity from this fix; it is the standing price of hc not carrying session identity. This commit pays that price in the cheapest place available without upstream changes.

Read-only throughout: no labels written to live terminals, t3k untouched, worktree clean.
