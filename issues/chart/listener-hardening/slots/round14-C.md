## Operator decision: keep the tables, add agy

Q2(c)'s neutral-proof and hc options above are withdrawn; the per-harness tables stay and gain an `agy` row. Facts below are from antigravity-cli 1.5.3 (`~/.local/share/mise/installs/antigravity-cli/1.5.3/antigravity`), its changelog, and `~/.gemini/antigravity-cli/` on disk; no agy was run.

1. **Reset command: `/clear`.** The binary's help string is "Clear conversation and start a new one"; the changelog (`agy changelog`, 1.5.x entry) says print mode now refuses `-p "/clear"` because it "reported the context cleared while nothing was cleared", so interactively `/clear` is the reset. A new conversation gets a new id: the log writes `Created conversation <id>` (`server.go:1233`, `log/cli-20261108_092926.log:135`), a new `conversations/<id>.db` and a `presence/<id>.lock` (same second, 09:29:28). Whether `/clear` passes through a status turn is not knowable from the binary (OSC 7501 states are working, waiting, done, failed, since 1.4.0); with round 13's reply predicate it does not matter.

2. **Storage.** One SQLite file per conversation, `~/.gemini/antigravity-cli/conversations/<id>.db` (journal mode WAL; 65 of 65 have a `-wal` sibling). Table `steps(idx, step_type, status, has_subtrajectory, metadata, error_details, permissions, task_details, render_info, step_payload BLOB, step_format)`; `trajectory_meta(trajectory_id, cascade_id, …)` with `cascade_id` = conversation id. Step types seen over all 65 files: 14 = user message (240; the prompt text is in `step_payload`), 15 = agent step (3244: 1816 text replies, 1428 tool calls holding `"CommandLine"`), 132 = tool output (5463), 17 = error, 23 and 101 rare. The shared `conversation_summaries.db` is an index: `conversation_summaries(conversation_id, title, preview, step_count, last_modified_time, workspace_uris, status, source, project_id, agent_name, parent_conversation_id, …, last_user_input_time, last_user_input_step_index, …)` plus FTS5 `conversations_fts(conversation_id, chunk_index, …, user_body, agent_body)`. Queries, all tested read-only with `sqlite3` and `bun:sqlite` (`new Database(path, { readonly: true })`):
   - conversation holding a code: open each candidate `<id>.db` and run `select idx, step_type from steps where instr(step_payload, cast(? as blob)) > 0` (on `4b6c381a…db` for `done agy 2`: idx 4 type 14, 5 and 7 type 15, 6 type 132). The shared index also answers `select conversation_id from conversations_fts where user_body like '%<code>%'`, but when it is refreshed is unverified (a reconcile runs at startup, `store_client.go:714`), so use the per-conversation file.
   - operator-input record: `step_type = 14 and idx > :boundary`, boundary = `select coalesce(max(idx), -1) from steps` taken at start (not a byte length: WAL writes do not grow the main file).
   - warm-up reply: `step_type = 15 and idx > :code_step` where `code_step` is the type-14 row holding the code; a tool-call 15 counts too, as a claude `assistant` record does.

3. **Transcript path and label: `~/.gemini/antigravity-cli/conversations/<id>.db`.** Today's answer, the shared `conversation_summaries.db` (`src/transcript.ts:155-156`), can never differ after a reset, so door-reset would always stop at `same transcript`. The live source: agy takes an exclusive lock on `presence/<id>.lock` for the active conversation (binary symbols `presence.Acquire`, `presence.tryLockExclusive`, `presence.Release`; the files are 0 bytes and stay after exit, 58 on disk), so the open lock in `/proc/<pid>/fd` names the conversation. One probe confirms it: a live agy under hc, `ls -l /proc/<pid>/fd | grep presence` (door A's budget, not done here). Fallbacks if the fd is not held: the process's open `log/cli-<start>.log` (last `Created conversation <id>` line) or `history.jsonl` (`conversationId` per prompt, 208 of 237 rows). Consumers that assume JSONL: `src/transcript.ts:226-232` `transcriptKind` (null for `.db`); `door-reset.ts:25-60` schemas, `:92-94` byte boundary, `:101-108` input read, `:125-131` `answered` (all line-based); `transcriptByCode` `src/transcript.ts:216-218` (`readFileSync().includes(code)` misses WAL-resident steps); `skills/watch-issues/scripts/log-tail.ts:451-458` (format from the first JSON record: a `.db` yields none, non-zero exit, the watch reports `log unreadable`, `watch-issues/SKILL.md:44`, acceptable until an agy renderer exists); `skills/chart-issues/scripts/chart-usage.ts:119` (`unknown harness agy`, usage stays uncounted, outside the handover). Fine as strings: `src/log.ts:43`, `src/next.ts:430`, `observe.ts:74-76` (exists check), `SKILL.md:163` (paths differ).
