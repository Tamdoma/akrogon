## Q2: flaws in the plan

- D1 Regex does not port verbatim. Foot's pattern (`~/.config/foot/open-path.ini:5`) uses POSIX classes `[[:space:]]`; a JS `RegExp` treats `[^[:space:]` as a class ending at the first `]`. Checked in node: the URL branch matches nothing. Rewrite with `\s`. Also the bare-word branches (`word.ext`, `.dotfile`) match on nearly every screen line of Claude Code output, so expect well over 10 hits; home-row letters give 10 hints. Plan two-letter hints (or first-letter filter) from the start and dedupe equal matches.
- D2 Soft wraps split paths. `hc read <t> --json` returns `{"complete","how":"screen","text"}` with one `\n` per screen row and no wrap marker (output on my own t6d: `"how":"screen"`, 8 rows at 38 columns). A path wrapped at the pane width arrives as two fragments. Foot matched on its own grid; here the mod gets rows only. The clean fix is upstream: herdr-core embeds libghostty, whose formatter has an `unwrap` option (`GhosttyFormatterTerminalOptions.unwrap` in `strings ~/.local/bin/herdr-core`), so `hc read --unwrap` is a small core change. Until then, join a row whose length equals the terminal width with the next row before matching (heuristic; medium confidence). Program-side truncation (`…`) is unrecoverable, same as with foot.
- D3 Visible screen only, scroll position unknown. `how: screen` is the bottom screen; `--lines N` adds history above (`hc read --help`). If the operator scrolled the pane up, the hints list what is at the bottom, not what they see. Decide: screen only (document it) or screen + a fixed `--lines`. Not tested; low confidence that the viewport offset is unavailable.
- D4 Alternate screen is fine: `hc read` returns the active screen, so vim/less give what is shown. Claude Code does not use the alternate screen.
- D5 Focus and cwd come from one call: `focused()` gives `terminal` and `cwd` (`herdr.d.ts:227`). `terminal` is null when a mod pane (sidebar, picker) has focus and `cwd` can be null. Show an error and do nothing in both cases; do not fall back to the shell's cwd or `/proc` like `foot-open-path:21-29` (that script still calls the removed old `herdr` binary, so the foot flow is broken for herdr panes anyway).
- D6 Remote panes. `hc read machine/t7` works (`hc read --help`) and `focused().cwd` is the remote folder, but `exec("code", ["--goto", p], {on: machine})` runs VS Code on the remote host with no display (`herdr.d.ts:10-13`). Open URLs locally; for files on another machine either use `code --remote ssh-remote+<host> --goto` or show "remote file" and stop. `PaneInfo` has no machine field; the space's `machine` is the source (`exec` doc).
- D7 `exec` has a 30 s limit and kills what it started (`herdr.d.ts:10`). `xdg-open` and `code --goto` return at once when a VS Code instance is running; a cold VS Code start from the CLI may still be a child at 30 s. Test the cold case once. Existence check: `exec("test", ["-e", path])` and read `code`; `readTextFile` works but reads up to 1 MiB.
- D8 Popup placement and focus. `openOverlay({kind:"popup"})` opens at the pointer by default (`herdr.d.ts`, OverlaySpec `at`); a keyboard-opened list should pass `at` or use `kind: "dialog"`. The mod must `track_focus` and `focus()` itself (`AGENTS.md:783, 913`, picker `main.js:220-240`) or the letters go to the terminal. Esc: a mod overlay closes on Esc (`herdr.d.ts` closeOverlay doc); the picker also handles `e.key === "escape"` itself (`main.js:229`).
- D9 Where the key lives. `keys.json` is already the operator's own file (link into herdr-setup), so editing it loses nothing (`AGENTS.md:473-475`). Do not also ship a `mods/link-hints/keys.json` merge (`AGENTS.md:438`); one binding in one file.
