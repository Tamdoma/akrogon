1. What gives each property, and who owns it.

- A pane on the right half at 50%: B keeps the labels it has (`herdr.space`, `herdr.tab`, `src/seat.ts:228-229`); a labelled child is adopted as a pane in that tab, not as a pane-less sub-agent (P11: three `--parent door` children with tab labels got panes). With A already shown, the second pane in a tab splits A's at 0.5/0.5 (P11's halving: 0.5/0.25/0.125/0.125 for four). That is today's placement (engine criterion 7 "B as a split beside A"), nothing new. What labels do not fix is the side when the window was closed at B's start: at open, adoption ordered a child before its parent (P11: `c1, door, c2, c3`). No herdr-app command sets a pane's weight or side after the fact (`herdr-app commands`: `pane.split`, `pane.swap`, `terminal.keep {place: right|down}` for pane-less terminals only, `layout.resize` for layout nodes, no pane resize); only a document write does, and that lives in herdr-setup (`lib/consultant-column.js:85-86` already writes "door left, column right, half each"). Owner of the side guarantee: herdr-setup, by the same mechanism as the consultant column; akrogon owns no placement code beyond labels, as today.
- Everything else the same: `--outlive-parent` (B must not end with A: `hc --skill:11` "They end when you end, unless started with --outlive-parent") and `--no-notify` (no exit or start notes typed into A: `hc run --help`). 2. When A is not live at B's start. - `hc wait --children`: a leaf A never calls it (no `hc wait`/`hc run` in `skills/implement-issue`, `check-issue`, `merge-issue`, `plan-issue`); only the chart door does, for consultants (`skills/chart-issues/assets/questions.md:60`). 4. Simplest design I would defend: `startSeat` gets `parent` from the live A (null otherwise) and `run()` adds `--outlive-parent --no-notify` whenever `parent` is set. Three literal flags, no new state field, no new herdr-app call, no new engine placement logic, no mod work for the indentation. It removes nothing yet, but it opens one removal: if the operator wants the right side guaranteed after window-closed starts, the policy belongs with the tab-order policy from round 1 K5 in one herdr-setup mod that reads the document plus parent links ("a child pane sits right of its parent; a door's children form the right column; new tabs go last") and writes once with `doc.set`. That one mod would replace `herdr-consultant-column` and the door's three call sites for it (`chart-door-on-hc` design: after every start, removal, restart) with zero akrogon calls, which is the direction the operator asked for. Without that, the honest statement is: 50% yes, right side when the window is open, herdr-app's order when it was closed.

## Part 3: remaining ways a leaf stays stuck with nothing retrying, ranked

- R1 (highest) Claude seats report `done`, and the re-prompt skips `done`. `src/next.ts:509`: `if (prompted.turn >= seat.turn || status === 'done') return;`. Live now in `infra`: door `t15` is `done` at turn 393, leaf seat `ak-herdr-sweep-a` is `done` at turn 5, consultants are `working`; Claude Code ends every turn as `done`, not `idle` (hc keeps the program's own word, `hc schema` `Status`; `hc --skill:198-200`). So the silent-stop guard (criterion 4, `tests/hc-delivery.test.ts:82-107`) only ever fires for the stand-in, which reports `idle` (`tests/stand-in.sh:22`, `idleAfter` at `:46-49`). A Claude seat that ends a turn without `akrogon phase` is never re-prompted and never failed; the leaf sits with a `done` seat until someone types. The clause dates from old herdr (`git log -S`: `0418eb5a`), where `done` was herdr-app's "finished while you were not looking"; on hc it is a turn-end word like `idle` and delivery already accepts both (`:452`). Fix: delete `|| status === 'done'` (one token); the stand-in gains a `done` mode so the existing silent-stop test runs once with `done`. Removes the class for every harness that says `done`.
- R2 A failed dispatch is retried only by luck. `startSeat` errors (`hc run` refused, pane never shown `src/seat.ts:180-184`, cgroup mismatch `:287-291`, `name_taken`) throw, `dispatchLeaf` reports and skips (`src/next.ts:1042-1045`), and the next pass comes only from some terminal's event (`src/listen.ts:79`) or a listener start (`:25`). A leaf with no seat emits no event; on a quiet machine nothing runs again. Fix in the listener where "pass failed" is logged (`src/listen.ts:33`): a non-zero pass enqueues one more `next --resume` after a delay (one `setTimeout`, no new state), so every skipped leaf is retried until it dispatches or fails for a recorded reason. Same line covers O3 of round 1 (pass failures logged only) and the "hung pass" bound (kill the child at a deadline, count it as failed).
- R3 `hc send` reported `started: null` or `false` and the seat never moves. `deliver` records `not_started` (`src/next.ts:468-481`); the retry waits while `error.turn >= seat.turn` (`:490`). hc's `started` is "whether the agent started working on it" (`hc schema` `SendResult`); a harness whose status hc cannot read gives `null` and never advances a turn, so the wait is forever. Fix: a `not_started` record older than one start budget (`START_PROOF_MS`, `src/seat.ts:38`) is a restart of the seat, not a wait; that reuses the restart path at `:441-444` instead of adding a branch. Likelihood: low with claude/codex/pi/agy (all report status), high the day a harness line in config is wrong.
- R4 The state lock waits forever. `withLock` runs `flock -x` without `-w` (`src/state.ts:362`); a hung holder (a pass stuck in an hc call without deadline, round 1 O2) blocks every `next`, `phase`, `stop`, and the listener's single queue behind it (`src/listen.ts:29-34`). Fix: `flock -w <seconds>` and a default deadline on `hc()` (`src/hc.ts:93-97` has the `timeout` option already); a lock timeout throws, the pass fails, R2 retries it.
- R5 Space resolution refusals (round 1 O1): one unreadable or closing session refuses the repo (`src/hc.ts:256-258`) and `next` skips every leaf of it (`src/next.ts:387`). Gone for test cores with the K2 isolation; it remains for an operator core that stops mid-pass (`sessions()` throws on the probe, `:131-133`). K1's "any probe error is not live" fixes the throw; the `uniqueness unknown` refusal stays for a session that answers but whose document fails to parse, which is the one case that should stop dispatch and be shown (status already prints `skipped_stopped` and `unreadable`).
- R6 Watcher-only recovery paths: a seat that ends in `blocked` (permission, question) is left to the watcher (`src/listen.ts:81-85`, `src/hc.ts:552-575`); with no `akrogon.watch` terminal live, nothing happens and nothing says so beyond the journal. Not a bug, a dependency: the needs-you notice (notices-on-hc, criterion 1 of that leaf) is what makes it visible. Rank low here because it is already a leaf.

Order of the smallest changes by value: R1 (delete one clause), R2 (one retry enqueue where the failure is already logged), R4 (two constants: lock wait, hc deadline), R3 (reuse the restart path), then Part 2's three flags.
