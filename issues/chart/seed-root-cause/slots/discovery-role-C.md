### 1 · Where does root-cause work happen: at filing, at import, or both with different jobs?

Today seed-issue bans diagnosis ("without diagnosis, recommended fixes or planning metadata", `skills/seed-issue/SKILL.md:26`), and chart-issues is the only place a cause gets checked against sources (`skills/chart-issues/SKILL.md:47`). In the #56 case the filing session held the evidence that linked the failures, but the agent filed to a repo it was not working in (Stopsol to tamdoma-framework, `issues/chart/seed-root-cause/INTAKE.md:21`), so it could suspect a cause and could not confirm one. The answer decides whether one skill changes or two, and whether a cause in a seed is treated as a claim or as a finding.

Research: practitioner · Simon Tatham, "How to Report Bugs Effectively", https://www.chiark.greenend.org.uk/~sgtatham/bugs.html, read 2026-10-05 · "The diagnosis is an optional extra, and not an alternative to giving the symptoms", and facts must be kept apart from speculation · it makes a filing-time cause legitimate only as a labeled extra. practitioner · Google SRE book, "Postmortem Culture", https://sre.google/sre-book/postmortem-culture/, read 2026-10-05 · the cause record is written after the event and holds "the root cause(s)" plural · it puts the confirmed cause in a later pass. better-than-training · ITIL problem management via secondary summaries, searched 2026-10-05 · incidents and the problem behind them are separate records, one problem to many incidents · it supports two jobs instead of one. better-than-training · `skills/chart-issues/assets/shapes.md:244-246`, read 2026-10-05 · one completion owner can already carry many GitHub identities and close them all · the import side needs a grouping rule, not new machinery.

- **1a (recommended)** Both, with different jobs. seed-issue records a suspected cause and related reports as labeled unverified context. chart-issues verifies the cause against live surfaces and groups seeds under one owner only after the operator confirms. It wins because each skill does only what it has the evidence for: the session context exists only at filing, and the destination source and grounding rules exist only at the door. Cost: two skills and `docs/guide/create.md:88` change, and closed decision D3 is partly reversed on record.
- **1b** Filing only. seed-issue produces the cause and chart-issues takes it as given. One skill changes. Cost: the cause is written by an agent that often cannot read the destination repo, and nothing checks it before it becomes the plan.
- **1c** Import only. seed-issue stays as it is and chart-issues looks for shared causes across seeds. One skill changes and D3 stands. Cost: the session evidence that linked #124 to #127 is gone by import time, and consumer repos that file but never chart get nothing, which misses the operator's "every repo that consumes Akrogon".

Pitfalls avoided: A confident wrong cause becoming the plan is removed by the door treating the seed's cause as a claim that needs its own file:line evidence, the same rule every chart claim already follows (`skills/chart-issues/SKILL.md:47`). A wrong shared cause closing unrelated issues together is removed by requiring operator confirmation before grouping, as seed matches already do (`skills/chart-issues/SKILL.md:69`). Docs contradicting the skill is removed by a done-criterion on the leaf: `docs/guide/create.md:88` and the D3 reversal are updated in the same work.

### 2 · How far does filing investigate before it posts?

The skill currently reads "only nearby context needed to understand" the statement (`skills/seed-issue/SKILL.md:26`) and never blocks thin intake (`:28`). In the #56 case the root report #128 was filed ten minutes after the last symptom, from what the session already knew, once the reporter asked (`issues/chart/seed-root-cause/INTAKE.md:46`). That same report found that one cause did not explain all four symptoms. The answer decides whether filing stays a one-minute step or becomes an investigation inside the reporter's session.

Research: practitioner · Simon Tatham, same essay, read 2026-10-05 · "Leave out speculations if you want to, but don't leave out facts" · filing may post with no cause at all, so no bound needs to guarantee one. practitioner · John Allspaw, "The Infinite Hows", https://www.kitchensoap.com/2014/11/14/the-infinite-hows-or-the-dangers-of-the-five-whys/, read 2026-10-05 · "Cause is something we construct, not find", and a forced chain of whys yields one tidy story · it argues against any bound of the form "keep going until you reach the root". better-than-training · `learnings/LESSONS.md:15,18`, read 2026-10-05 · the chart door itself has stated wrong live facts from a narrow grep and a stale checkout · more investigation in a skill with fewer grounding rules adds wrong claims, not certainty. No practitioner source was searched for on time-boxing triage specifically.

- **2a (recommended)** Session evidence only. The cause is written from what the session already saw plus the nearby context the skill already allows. Filing runs no new commands to test the cause, reads nothing in the destination repo, and writes "Not provided" when the session holds no basis. The section says what was inspected. It wins because it costs one or two rule sentences, keeps filing fast, and the #56 root report shows session evidence was enough. Cost: causes that need a fresh look stay unfound until charting.
- **2b** Session evidence plus one bounded local check. As 2a, and the agent may also open the files or rerun the command the failure itself names, read-only, in the current repo, before writing the cause. Cost: "bounded" is a judgment call that differs across harnesses, and a rerun can have side effects the skill cannot foresee in a consumer repo.
- **2c** Investigate until the cause is confirmed or declared undetermined. Closest to the literal word "discover" in the operator note. Cost: filing becomes open-ended, the agent still cannot read a destination repo it does not have, and the result reads as confirmed when it is not.

Pitfalls avoided: An invented cause filling a required field is removed by keeping "Not provided" legal, matching `skills/seed-issue/SKILL.md:28`. A guess about a repo the agent cannot read passing as fact is removed by the inspected-versus-not-inspected statement in the section. Symptoms shrinking once a cause exists is removed by the rule that Observation stays complete and the cause is an extra, with a done-criterion that a test filing with a cause still carries all five sections. Skill bloat is removed by a done-criterion that the changed skill still meets the C1 cap (300 lines, 4k tokens, 20 rule sentences) with `gh` as the only dependency.
