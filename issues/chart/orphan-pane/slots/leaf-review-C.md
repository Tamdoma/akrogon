# leaf-review: record-panes-early — slot C

## Disagreements

**D1. Criterion 1 needs per-pane box failure; fake-busctl has only global failure — the draft hides this behind "if the fakes lack it" instead of deciding.**

Evidence: `tests/fake-busctl.ts` — `busctl.fail` (the `existsSync(resolve(home, 'busctl.fail'))` branch) fails every StartTransientUnit call while the file exists; there is no per-call or one-shot variant. Criterion 1 asks for "boxing the B pane fails after its split succeeded" — with the current fake, failing the run fails `box(first)` too, so the test never reaches the B split and reproduces a different gap (unrecorded A is healed positionally via `members[0]` on bootstrap, not the #116 orphan). Existing test `busctl.fail ... stops dispatch` (tests/seat-containment.test.ts) confirms the all-or-nothing semantics. Under standing-design ("machinery is code whose job is to run proof"; "no leaf builds or extends machinery to prove its own product"), a new one-shot `busctl.failOnce` flag in the fake is machinery and would need a prerequisite leaf, while leaving `busctl.fail` set for exactly one `next` run and removing it before the next — writing the fail file, running once, deleting it — is fixture setup inside the test and proves criterion 1 fully: first run splits p2 and fails `box(second)` only if the flag is armed between the two boxes, which a global flag cannot do… so the honest options are (i) state.seed a recorded-tab leaf whose B split already happened (`state.tab` set, `state.pane` empty, a stray pane in `db.panes`) — but that skips the failing box the criterion names — or (ii) a `busctl.failOnce` fake flag.

Correction: design.md must pick one and say so. Either (ii) with an explicit prerequisite-leaf entry in `blocked-by` delivering a one-shot adoption-failure flag, or reword criterion 1 to the state the test can actually create without new fixture machinery (arm `busctl.fail`, run once, disarm, run again — this reproduces the failure when the flag is consumed by `box(second)` only if the fake supports one-shot; with the all-calls flag it cannot). Concretely the smallest sufficient fixture surgery that stays "setup inside the test": set the pane's own cgroup file back to `OUTSIDE_CGROUP` after the pass where the B split succeeded, simulating a never-adopted B — but that does not exercise a thrown `box`, so it proves the *state*, not the *cause*. As written, criterion 1 cannot be proven red-first without either a fixture flag or a narrower criterion; the draft's conditional parenthetical papers over a real prerequisite decision. Resolve before handoff.

**D2. Deleting the broadcastPass shortcut widens what runs inside `allocate` for B-live merged leaves; the draft's `Open for the plan` line names two checks but misses the third behavioral change: entry sweep and its throws now run on every pending broadcast.**

Evidence: src/next.ts `broadcastPass` — today, when recorded B is live, `panes().some(...pane.B)` short-circuits `allocate` entirely, so neither the recorded-pane scope sweep (`for (const id of recorded)` / `inOwnScope` / `pane close` at the top of `allocate`), nor `ensureWorktree`, nor the `matches.length === 0` `max_active` gate runs. After D3's deletion they all run for every `broadcastPending` leaf. Consequences beyond the two the draft names: (a) a merged leaf whose recorded B is live but `inOwnScope` returns `unreadable` now throws and the broadcast is skipped that pass — new failure surface the shortcut never had; correct under the fix (it's the sweep doing its job), but it is a behavior change worth recording, not leaving implicit. (b) `ensureWorktree` now runs for B-live merged leaves. A live B implies the recorded tab is alive (closing a tab kills its panes), so `live=true` and no .env write happens — but the worktree-mismatch guards (`Worktree path mismatch`, `Not a worktree root`, `Unrelated worktree` throws) and worktree creation when the path is missing now gate every pending broadcast; today a B-live leaf never touched them. `max_active` and `tab create` stay unreachable on this path (a live B means `matches.length === 1` via `state.tab`).

Correction: extend the `Open for the plan` bullet to "confirm the entry sweep's `unreadable` throw and `ensureWorktree`'s mismatch guards on a merged leaf whose B is live — each compared against today's skipped-allocate path; `allocate === null` and `tab create` are unreachable while B is live and need no check." No code change beyond the deletion; this is a checklist completeness fix.
