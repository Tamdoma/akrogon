# Bun cache, slot D

1. **Writers.** Bun processes loading large JS/TS modules populate the runtime cache. On Bun 1.4.5, one `bun src/akrogon.ts --help` produced 83 entries and 0.95 MiB under a fresh `XDG_CACHE_HOME/bun/@t@`, with zero entries in `TMPDIR`. Checks that run Bun can write there. So can the CLI, listener and its passes, release/self-update CLI, land and verify service wrappers, and seats or consultants that launch Bun-based tools. Each verify check goes through `checkedRun` separately. Release staging's `bun install` primarily uses the package cache. Cache files alone give no reliable breakdown of the existing footprint by caller. [Bun runtime cache](https://bun.com/docs/runtime/environment-variables#runtime-transpiler-caching) · [Bun package cache](https://bun.com/docs/pm/global-cache)
2. **Pick A1 for checked commands.** A fresh directory under `runRoot` keeps reuse among Bun processes in the same check. In nine runs per mode of the four `tests/log-reader.test.ts` tests, wall/CPU medians were **241/849 ms fresh**, **257/1,239 ms disabled**, and **245/813 ms warm**. The fresh directory held 109 entries and 1.38 MiB. This measures one file with Bun CLI subprocesses. Use the normal run teardown and remove the cache subdirectory when preserving a publish-refused root (`src/run-check.ts:470–472`, `src/reconcile.ts:1159–1170`). A shared cap adds an eviction policy for limited benefit in this sample.
3. **A1 boundaries.** Add the key to the exact allowlist test (`tests/run-check.test.ts:160–189`). Setting it after `env` and `pass_env` forwarding enforces the per-run policy and overrides any explicit value passed by a repo. The name is currently eligible for forwarding (`src/config.ts:112–139`). A1 applies to the checked command and its descendants. The already-running CLI and outer seat, listener, land and verify processes retain their own cache settings.
4. **A2 and A3.** A2 can remove exactly `~/.cache/bun/@t@` in an idle window per M8. Bun documents it as regenerable. Expect cold starts and leave `~/.bun/install/cache` alone. A3's detached head `99a256a8` is in main, the index and tracked files are clean, and no readable process cwd or file descriptor pointed into the owner folder. Removal would also discard ignored `node_modules`, `.evidence/install-prune-links/home-listing.json`, and the parent folder's debug logs, extracted scripts and `.bak` files. Confirm those artifacts are disposable before removing the registered worktree and its parent. [Bun runtime cache](https://bun.com/docs/runtime/environment-variables#runtime-transpiler-caching)
