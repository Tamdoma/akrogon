# HC drift, slot D

1. **Updates.** This host has `hc` 0.1.22. `hc update` installs the latest release and restarts the core while terminals keep running. `--version X` is a minimum. `--from FILE` selects a build. The core does not download updates on startup. The desktop app checks for its own updates in the background and can offer to update an unusable core. I found no Herdr user timer and did not identify what triggered the 07:42 update. The recent core releases were Nov 4, 7, 10, 12 and 22. Upstream calls the 0.x API a preview, tests additive OpenRPC compatibility within generation 1, and requires a new generation for intentional breaks. That test covers the request/response schema. [Core manual](https://github.com/herdrdev/herdr-core/blob/v0.1.22/crates/herdr-core/src/SKILL.md) · [App updates](https://github.com/herdrdev/herdr-app#updates-and-privacy) · [Changelog](https://github.com/herdrdev/herdr-core/blob/v0.1.22/CHANGELOG.md) · [Protocol policy](https://github.com/herdrdev/herdr-core/blob/v0.1.22/schema/README.md)
2. **Runtime contract.** Terminal and status reads, RPC envelopes, the `herdr-app` document and send replies use `z.object`, which accepts extra keys (`src/hc.ts:13–35,109–128,169–209,274–284,326–335`). The watcher has the same property (`skills/watch-issues/scripts/hc.ts:36–57`). Required fields, value types and closed enums still matter. I verified that extra terminal and nested status keys pass, while a numeric `cwd` fails. The event reader recognizes snapshots, `event` and heartbeat, so an unfamiliar top-level notification rejected the stream in a probe (`src/hc.ts:358–417`). Changes to filters, turn or status semantics could also stop dispatch and wakeups with valid JSON (`src/listen.ts:84–120`).
3. **What the pin buys.** It finds changes in six complete schema components and four entire parameter lists, down to descriptions. One component, `DocSetResult`, serves test fixtures (`tests/hc-fixture.ts:362–368,489–503`). I restored the old pin in a disposable checkout and reproduced the failure on the sole optional `docs` addition. With the current pin, all 29 tests across identity, listener, observe and delivery passed on 0.1.22. Equality cannot prove event delivery or show that production parsers accept the responses. [0.1.22 release notes](https://github.com/herdrdev/herdr-core/releases/tag/v0.1.22)
4. **Pick O4.** Remove the exact schema test and fixture. Keep the real-core behavior tests and the existing parsers. This is O2 at the point where Akrogon actually uses the contract, without a second schema to maintain. Keep hc upgrades with Herdr. An Akrogon-side client pin alone leaves the shared running core free to change. Pinning both would make Akrogon responsible for the operator's terminal service. Removing the snapshot trades early notice of an unexercised shape change for fewer false merge blocks. The focused integration tests can serve as a post-update smoke check. A real incompatibility can still reach a path that the tests missed and surface through its parser or listener retry.
