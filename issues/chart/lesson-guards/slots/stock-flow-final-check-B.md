# Focused final-shape check B

- D1: Relevance is not recurrence. `skills/plan-issue/SKILL.md:25,27` reads resources and verifies cited observations. It does not establish another occurrence of the recorded failure cause. A planner can identify a still-applicable risk without observing a new failure. Such a risk may justify intake, but the seed must preserve that distinction, not append a fabricated recurrence case or rank it as repeated failure.

- D2: The proposed trigger extends the taken 1a rather than merely applying it. Stock-flow Taken requires a same-failure-cause match before writing a lesson. Selecting an old lesson for read-first need not involve writing a lesson or matching a new observed case. `plan-issue:39` records new reusable findings, while `:25` handles resource selection. Making relevance alone trigger classification and filing is a new rule in an existing pass. It adds history-link inspection, checkability judgment, destination resolution, duplicate searches and possibly a GitHub write. `skills/seed-issue/SKILL.md:54,56,68` establishes the investigation, lookups and posting work. Reusing the pass avoids a new component but does not prove zero added time or cost. Net savings remain unmeasured.

- D3: This cannot replace exhaustive backlog treatment. It services only lessons selected by future work. Unselected already-guarded lines, judgment lessons and quiet repositories can persist indefinitely. Additionally, stock-flow 2a moves new shared lessons into Akrogon's learnings, while `plan-issue:25` reads the current registered repo's list. Consumer planning does not automatically read that separate stock. The shape needs an explicit cross-repo discovery/coverage rule before claiming those lessons drain. Adding that read has a cost too.

- D4: Filing an already-guarded lesson creates intake and attended chart work for a retirement that needs no new guard. Existing charting P3 is cheaper **when charting already has relevant coverage evidence**. It is not an automatic retirement service for every planner-selected lesson. `skills/learn-issues/SKILL.md:18-22,28` is the existing machinery that actually traces all active mechanisms, distinguishes guarded/checkable/judgment lessons and retires proven guards. Calling equivalent tracing inside planning relocates its work rather than eliminating it.

- D5: Keep 3a required while the chosen obligation is to address the existing backlog. The proposal offers opportunistic treatment, which stock-flow Taken explicitly forecloses. The operator's question does not itself authorize replacing that obligation. A one-time learn-issues pass costs investigation, leaves judgment lessons active and currently only prints seed suggestions for checkable ones (`skills/learn-issues/SKILL.md:29`). It therefore needs the selected filing behavior to be reconciled if automatic backlog promotion is required. No inspected machinery guarantees complete backlog drainage with literally no added work. Making 3a optional requires an explicit acceptance of incomplete backlog coverage, not a claim that relevance-based planning is equivalent.
