# Rebuttal: merge-reuse (Seat D)

1. **`O-cover` works, but `## Q2 one rule` omits `reuseSource` (`src/verify.ts:203-209`), which must also drop `run.scope === scope` or `verify` and `O-cover` will disagree on partial cross-scope coverage.**
   - I accept `O-cover` over `O-whole` so `merge-reuse` stays decoupled from `X2b` (`tests/verify.test.ts:1271`).
   - However, if `O-cover` drops `run.scope === scope` while `reuseSource` (`src/verify.ts:206`) keeps `run.scope === scope`, consider a repo with `checks: { c1 }` and `merge_checks: { m1 }` (`merge_covers: []`). After a green `leaf` run (`c1: 0`), `merge` verify sees `m1` uncovered and enters `runOnce` (`src/verify.ts:549`). If `reuseSource` filters by `run.scope === 'merge'`, `runOnce` re-runs `c1` instead of reusing the `leaf` entry; if `c1` then fails (`exit 7`) while `m1` passes (`exit 0`), `verify` exits `1` (red) **while `O-cover` (`requireGreenReceipt` and the next `verify`) considers the tree green** (`c1: 0` from the `leaf` run + `m1: 0` from the `merge` run). Dropping `run.scope === scope` in `reuseSource` (`src/verify.ts:206`) eliminates that disagreement.

2. **Against keeping `run.scope === scope` in `redRun` and `knownRedReceipt` (`## Q2 one rule`, B):**
   - `knownRedReceipt` (`src/verify.ts:221-243`) already requires a linked `baseRun` (`run.compares === head.run && run.sha === mergeBase` at `src/verify.ts:232`) failing the same test names for every non-green command `{ item.name, item.command }` in `verifyCommands(repo.config, scope)`.
   - Keeping `run.scope === scope` at `src/verify.ts:149, 218, 232` means that in `akrogon` (identical `leaf` and `merge` command sets), a leaf that passed `implement -> check.review` via `akrogon verify --known-red` (`scope: 'leaf'`) will have its linked pair rejected by `requireGreenReceipt(repo, head, 'merge')` (`src/verify.ts:466`), and `verify --attempt <att> --known-red` at `merge` will re-run the red head full suite on the identical `tree` and command set before running the base comparison.

3. **Against keeping `run.scope === unit.scope` in `matching` (`src/verify.ts:254-262`, C):**
   - Under Q1, when a leaf that fixes a broken test on `main` merges without a rebase, `verify` at `merge` reuses its `scope: 'leaf'` green receipt (`src/verify.ts:880-884`) and writes **no `scope: 'merge'` row** to `issues/verify-runs.jsonl`.
   - Consequently, the fix commit on landed `main` only has a `scope: 'leaf'` green receipt. In `newRedUnits` (`src/verify.ts:297-307`), resolution of a prior `scope: 'merge'` main-red notice checks `matching(green, unit)` on runs where `await onMain(green.sha)` (`src/verify.ts:303`) is true. If `matching` (`src/verify.ts:257`) keeps `run.scope === unit.scope`, that landed `scope: 'leaf'` green receipt never resolves the `scope: 'merge'` incident (`noticeCovers` at `src/verify.ts:308` stays true and suppresses future notices if the test breaks again).
