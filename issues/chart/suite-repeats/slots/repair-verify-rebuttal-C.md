# repair-verify rebuttal: seat C

Against A's pick item 1 (also gating the proof sweep on `merge`):

R1. The per-Fix proofs do not cover what the sweep covers. In `skills/check-issue/SKILL.md`, `## check.repair`, a behavior Fix gets one reproduction test shown red before and green after, and a docs or command Fix gets before/after evidence; the "planned proof B did not write" acceptance sentence sits inside the live-proofs replay clause. Only the "After repairs" paragraph reruns criteria whose inputs (helpers, fixtures, config, lockfiles) changed, including criteria no Fix mentions and interactions between B's own stacked Fix commits. A's check.fix closing rule keys reruns off each criterion's last green run on this leaf (`skills/implement-issue/SKILL.md`, `## check.fix` and the implement-end rerun rule), but B's greens are cited as run-check logs in `review-B.md`, not as the command-plus-commit proof records implement writes, so A can count a mid-repair green as final even when a later B commit changed that criterion's inputs. Adding one handoff sentence telling A to count B's commits does not give A the per-criterion green commits to count from.

R2. A's sweep is not run on B's head. check.fix opens with the Shared context refresh before reading the findings (`skills/implement-issue/SKILL.md`, `## check.fix`), which rebases the branch onto current main (`## Shared context`, refresh rule). After B's end-of-repair sweep goes, no proof runs on the exact head B handed off: a criterion turning red in A's closing sweep can come from B's repair, main drift merged by the refresh, or A's own repair, with no earlier reading to separate them. B's sweep was the attribution boundary between B's commits and everything after. Its result is also read: the newest `review-B.md` entry decides A's input (`## check.fix`). "Read by nobody" holds only for the verify receipt, not for the sweep.
