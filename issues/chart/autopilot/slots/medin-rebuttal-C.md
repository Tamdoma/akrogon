# Medin rebuttal, slot C (disagreements only)

1. **Idea 1, B's "drafts allowed, hold only the handoff" does not stop intent guessing.** Every later fork is drafted on the guessed answer, and each answer reshapes the rest (`skills/chart-issues/SKILL.md:55` at `f7baddc`). Holding at handoff presents a finished tree built on the guess, harder to reject than one held round. Fix: the intent hold stops that fork at its round and the chart moves on. Nothing downstream of unsettled intent is drafted.

2. **Idea 3 / D-b: B's "weakening only" test is judged by the agent being graded, and B's own verified source says review does not catch it.** Medin's repo at `54f1c4a`, README:318: "Review does not reliably notice an agent editing the files that…" govern it, which is why they added mechanical `protected_paths` checks, not a judgment test. Akrogon's prose mode has no protected-path machinery. Fix: the hold class is by path (chart-issues, checks config, criteria, intake, delegation record), not by A's assessment of whether an edit weakens anything. This also answers the merged open question "is B's agreement enough": on this evidence, no. Peer agreement is review, and review is the thing shown unreliable here.

3. **Idea 5 / D-c misstates C on the batch checkpoint.** The merge has "leaves built on intent-heavy picks wait for the morning (A Q-M2, C)". C did not pick a subset. Under the intent hold, intent-heavy picks are held forks, so no leaves are built on them. "Intent-heavy" would also be A judging its own picks. C's question was time-bound, not class-bound: leaves wait until the operator reviews the record, until the acceptance rate (idea 6) is measured. Fix: state D-c as trial-period checkpoint for all autopilot leaves vs after-the-fact review from the first session.

4. **Idea 4 buries the blast-radius asymmetry it cites.** Medin merges to staging and his README puts the human test there (lines 3, 10: "work lands in staging, where you use the whole release like a customer would"). Akrogon merges to main and, for akrogon itself, deploys from main. So "supports no direct overnight (A)" understates it: every autopilot lifecycle merge also lands with no human checkpoint anywhere in the system. Fix: idea 4 should name lifecycle merges, not only direct, as the uncheckpointed path. That is what makes D-c a real fork instead of a direct-route footnote.
