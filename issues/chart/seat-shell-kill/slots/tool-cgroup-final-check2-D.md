# Second final-shape check, slot D: tool-cgroup

Checked the [R] lines of `forks/tool-cgroup.md` `## Taken` only. (Record note: in the file as read, the `## Findings` and `## Taken` headings are fused into the `### Carries` list, so section-based reads for those two headings fail; the Taken text itself is intact below them.)

## Defect

1. "At most one helper waits per `t-`" is not delivered by the stated test. The spawn condition is that `akrogon/<t-name>/helper/` is not already populated. A helper is spawned by a process sitting in `akrogon/<t-name>/`, so it starts there, not in `helper/`; until it moves itself in (a step Taken never assigns), `helper/` reads unpopulated or absent. A second commitMove landing in that window (two seats advancing back to back is the F4 shape) spawns a second helper for the same `t-`. Both write the same kill, so no process is wrongly killed, but the at-most-one line and the one-row-per-helper reporting are both violated. The claim needs an atomic test, such as the `mkdir` of `helper/` itself succeeding only for the spawner that creates it, with the unpopulated-and-stale case (a dead helper's leftover dir) stated alongside it.

## Missing obligations

2. Bootstrap is the only stated creator of `tools/`, and it cannot run "before the harness can run a tool" as written. `startSeat` launches the harness first (`run()` with the task in argv) and can only create `tools/` and `akrogon/` after systemd has created the scope and `scopeEntry` has seen the harness inside it. A first tool shell that beats that mkdir finds no `tools/`, its mint fails silently under the never-fail entry contract, and that shell and its descendants stay at the scope root for their whole life, outside every later kill. The window is small (harness startup plus one model round trip against one mkdir), but Taken should not rest placement of the first shell on it: state that the entry asset creates `tools/` idempotently before minting, keeping bootstrap as the verified fast path that also serves Q6 visibility. The same gap one level down: bootstrap creates `akrogon/`, but no line assigns creating `akrogon/<t-name>/`, the relocation target. The relocating process presumably creates it; say so, since two akrogon processes from one shell can race to be first.

3. Nothing ever removes `akrogon/<t-name>/` directories. Killed `t-` dirs are removed best effort, but each tool call that ran an akrogon command leaves an empty `akrogon/<t-name>/` (plus `helper/` where a deferral happened) for the rest of the seat's life. Taken should name the remover, for example the helper as its last step after leaving the dir, or commitMove removing unpopulated `akrogon/<t-name>` dirs whose `t-` is already gone. Without a remover the accumulation is one directory per akrogon-running tool call, ended only at leaf close.
