# Rebuttal, slot D: tool-cgroup

Disagreement only. New observations R1, R2 (free) and P-pi (paid) are recorded at the end.

## 1. Q1 a against b: change my pick

B is right about the masking leak, and that changes my pick. New pick: keep a's per-tool-shell cgroups, and take b's caller treatment for the caller's own `t-` only. commitMove still kills every other `t-` of every seat immediately; for the caller's own `t-`, the relocated `akrogon phase` process (already sitting in `<seat scope>/akrogon/` under Q2) spawns one detached helper there that waits for the tool shell to exit and then writes that `t-`'s `cgroup.kill`. No systemd unit and no bus call: the helper is a plain detached child of a process that already sits outside `tools/`, and R1 proves the shape.

Why this over pure b: with one `shells/`, the caller's seat's earlier leftovers also wait for the caller shell's exit, including through a long tail after the phase call in the same command. With per-tool dirs they die in commitMove; only the still-running command's own group waits, which is the minimum that must wait. A helper failure then leaves one recorded `t-`, not a whole seat's shells. Against B's backstop: no timeout kill. The helper carries the shell's pid plus start time (already the `t-` name), so pid reuse reads as exit; and if the shell never exits the turn never ended, so the seat is genuinely working, not masked. A timeout would only convert the tail of a legitimate command into option c.

### The same-command survivor under pure a, case by case

It is a real stall of the advanced-to phase in one case, bounded in the others.

Breaks delivery: the harness masks on background shells (claude, by P1 and P1b), the child started in the same tool command as the phase call never ends on its own (the incident's poll loop shape), and the caller's slot is seated in the advanced-to phase. Then the turn ends, claude still reports `working`, no `turn` event fires, and the new prompt is never delivered. Neither bound helps: the next advance normally needs this seat's work in the new phase, which never starts, and leaf close only stops slices of finished leaves. That is the incident with a smaller trigger, and it breaks the operator sentence as written ("Leftover seat shells end when the leaf's phase advances") for exactly the shell most likely to be a phase-transition leftover.

Does not break: the child ends by itself (a finite sleep, a test run); the move is to `merged` or `failed` or into the seatless merge turn, so no prompt is owed to the caller; another caller (the other seat, the operator) commits a further move, whose kill includes the spared `t-`; or the harness does not mask on background shells (unobserved either way for codex and agy).

The incident itself is not this case (its loop started in an earlier tool command, which pure a kills). The same-command case needs one tool invocation that both backgrounds a long-lived child and calls `akrogon phase`. Narrow, plausible, and now removable for the price of one detached process that needs no unit and no bus. Pure a should not ship with it recorded as a residual when the removal is this cheap.

## 2. Q3 wiring: change my pick to per-kind (A,B,C)

C's binary inspection changed my view. My base layer was insurance against `CLAUDE_CODE_SHELL` ignoring the wrapper. C read claude 2.1.332's resolver as accepting any executable path containing `bash` or `zsh`; the wrapper is a file named `bash` that execs real bash, so there is nothing left to insure against on any observed version, and P-claude confirms acceptance end to end. Meanwhile the layer is not free on claude: with `BASH_ENV` in claude's env, every hook or MCP-spawned `bash -c` at the scope root also gets placed, widening the kill set beyond the Bash tool, beside the unobserved `BASH_ENV` Stop-hook check C found. P-claude ran fine with `BASH_ENV` set, so harm is unproven; but insurance with a nonzero price and a near-zero payout should be dropped. Withdraw the every-kind base layer: claude by `CLAUDE_CODE_SHELL` only, pi and codex by `BASH_ENV`, agy by `PATH` shim (C's live evidence: agy spawns bare `bash -c` via PATH lookup; my P-codex also showed `PATH` is dead for codex, so the shim earns nothing there).

## 3. Q4 Delegate: keep Delegate=yes

B's probes are correct and R2 extends them: on systemd 262 nothing observable differs, including a `set-property` on a live non-delegated scope with a populated child cgroup. The deciding point is B's loud-failure premise. It holds only where placement is allowed to fail loudly, and the agreed entry contract is the opposite: the asset discards output and never breaks a tool call. `startSeat` creating `tools/` can be made a loud start check, but that covers start time only; a manager that rearranges a non-delegated subtree mid-life (the one operation nobody will probe on a live host manager, an upgrade reexec) would empty `tools/` silently and return the original silent stall. One `-p` flag buys the documented promise against exactly the silent case, at zero observed cost on this host. If the door decides the documented promise is not worth a flag whose effect is unobservable today, this is the cheapest point to concede; my pick stands on the silence asymmetry, not on any measured difference.

## 4. Q6 lookup: change my pick to enumerate (A,C)

C's schema evidence decided this. `src/state.ts` `seatRefSchema` is a `z.strictObject` (verified), so a recorded unit field makes state written by a new `startSeat` unparsable by an older binary during release overlap; that is a migration hazard in substance, whatever signpost 6a calls it. Enumeration needs no schema change and reaches replaced seats' scopes. My overreach objection (a scope started by concurrent dispatch, not in commitMove's snapshot) does not survive inspection: in the call paths read, `dispatchLeaf` to `startSeat` and `phaseCommand` to `commitMove` both run under the home `.lock`, so enumeration and seat creation cannot interleave. A's filter point also stands: presence of `tools/` identifies seat scopes, with the central name parse used only for slot attribution in timing rows, which is reporting, not selection. Recorded lookup keeps one advantage (exactness with no directory read) and it is worth less than avoiding the schema hazard. My earlier ask about killing a replaced seat's `tools/` at replacement time is moot under enumeration: next advance or leaf close is enough, since a harness-less scope cannot mask.
