# Final-shape check, slot D: tool-cgroup

Checked `forks/tool-cgroup.md` `## Taken` against `## Findings` and the carried old-chart Taken. The marked Q1 deferred caller kill itself builds as written (F4). Four defects or missing obligations follow.

## Defects

1. The bare-shell restatement drops a guard from the source it claims to carry unchanged. Taken's spawned shape is "`foreground.name` in {sh, bash, ...} and `argv[0]` not `systemd-run`". The old chart's final-shape correction, which was made part of that Taken, requires "a non-empty launch `argv` whose first word is not `systemd-run`". As restated, a live terminal with an empty `argv` and a shell foreground satisfies the predicate (`argv[0]` absent is not `systemd-run`), so a seat still starting can be charged lost and replaced. Restore the non-empty condition.

2. The Reporting line cannot represent what Q1 and Q6 do. It promises "one timing row with leaf, unit" per commitMove, but Q6 enumerates every seat scope of the leaf (two seats plus any replaced seat's scope), so one row naming one unit cannot record one ordinary move. Separately, the deferred caller kill happens after commitMove returns, so that row cannot record its outcome, and Taken gives the helper no reporting obligation at all. A helper that dies before its write is then invisible, which contradicts the row's stated purpose (making entry and kill failures visible). State one row per scope acted on, and name who records the deferred kill's result (the helper itself, if it is an akrogon subcommand, or the row marking the caller's `t-` as deferred so a later populated read is attributable).

## Missing obligations

3. Nobody creates `tools/` and `akrogon/`. Q3 mints `t-` dirs under `tools/`, Q2 moves akrogon processes into `<seat scope>/akrogon/`, and Q6 identifies seat scopes by the presence of `tools/`, but no Taken line assigns creating either directory. Left to the leaf, lazy creation inside the never-fail entry asset means a seat whose `tools/` creation fails is silently invisible to Q6 forever. Taken should name the creator (the obvious one is `startSeat`, after scope entry, beside the existing scope-entry proof) for both directories.

4. Caller identity is defined only for the direct case, and the two neighbouring cases break in opposite directions. Taken says the caller is "the `t-` the akrogon process started in", read before relocation. (a) An akrogon process started by an already-relocated akrogon process begins in `akrogon/`, so it reads as an outside caller and kills every `t-` including its own ancestor tool shell's, mid-command (the rejected c outcome through the back door). The `t-` path Q3 exports into the tool shell's env is inherited through such a chain and is the identity to fall back on when the starting cgroup is `akrogon/`. (b) A caller whose `t-` belongs to a different leaf's seat (any cross-leaf move committed from a seat) gets a deferred helper armed against that other leaf's `t-`, ending its leftovers although that leaf never advanced. Taken should state both guards: fall back to the exported env marker, and apply the caller exception and helper only when the caller's `t-` sits in a seat scope of the moved leaf.

5. The entry asset is "written or refreshed by `startSeat`" while live seats read it at every tool spawn (`BASH_ENV` is sourced per shell; the claude and agy wrappers are execed per tool call). A refresh that rewrites the file in place can hand a running seat a torn asset, and a shell syntax error there breaks Taken's own "never fails the shell" line. State that refresh is an atomic replace (write aside, rename over).
