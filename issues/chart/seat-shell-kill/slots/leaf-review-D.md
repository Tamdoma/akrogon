# Leaf review, slot D: tool-cgroup-kill (draft at scratchpad/leaf/tool-cgroup-kill)

Disagreements only, as the implementer building from brief.md, design.md and readiness.yaml.

1. **The kill's placement in `commitMove` skips the committed-but-failed-follow-up path.** Design: "`src/phase.ts:commitMove`: after `saveState` and the move log, it calls the kill". In live `commitMove` the order is `saveState`, then a try block (announce, `completeOwner`) whose errors are rethrown as `MoveCommittedError`, with `logMove` and the `visit_start` row in a `finally` that can itself throw `MoveCommittedError`. A kill placed after that try/finally, which is the natural reading of "after the move log", never runs when follow-up fails, although the move is committed and criterion 1 ("After a committed phase move, every process in a `t-` ... is gone") applies. Change the line to state the kill is attempted once the move is saved, independently of follow-up and log failures (for example inside the existing `finally`, not sequenced after a possibly-throwing log append).

2. **Enumeration has no stated empty case.** The kill module lists the slice cgroup via `sliceCgroup(leafSlice(...))`. That directory does not exist for a leaf whose slice was never loaded (an operator move before any seat starts, most test fixtures). Design never says a missing slice directory is an empty result, so an implementer either lets `ENOENT` become the criterion-4 structured warning on every seatless move, or invents the rule. Add the line: no slice directory (or a seat scope without `tools/`) means nothing to kill, no warning; warnings are for failures on scopes that exist.

3. **An unlisted harness kind gets no stated wiring.** `harnesses` is `z.record(text, text)` in `src/config.ts`: kinds are operator-defined, and `harnessArgv` already special-cases kinds by name. Brief item 1 and the design wiring switch name claude, pi, codex and agy only. For any other configured kind the implementer must guess between no entry (a silent unplaced seat, against criterion 3's shape) and some default. State the default in the design, for example `BASH_ENV` with the sourced asset for every kind not otherwise listed (the gate fails safe when the shell is not bash), or make it an explicit `Open for the plan:`.

4. **Criteria 1 and 3's real-scope proofs do not reach a user manager from inside akrogon's own test runner, as described.** The standing-design section says throwaway user scopes are "free and writable as the user (`systemd-run --user --scope`)". But the leaf's tests will run under the configured `test` check, i.e. inside a run-check payload where `src/run-check.ts:constructedEnv` sets `DBUS_SESSION_BUS_ADDRESS=unix:path=/nonexistent`, and the fixture PATH puts fakes first (`tests/core-bin/systemd-run`, `tests/fake-systemd-run.sh`). A test spawning plain `systemd-run --user --scope` in that environment talks to a fake or to no bus and fails for reasons unrelated to the code under test. The design needs one line naming the reach: real-boundary tests spawn the absolute `systemd-run` with the pinned session bus (`src/scope.ts:sessionBusEnv`), in the fixture home's unique leaf slice, plus what they do when no user manager answers (fail, not silently skip, or the proofs stop proving).

5. **A named consumer does not exist, and the real one is unnamed.** "Consumers of changed state" says `src/transcript.ts` reads "the harness pid's cgroup as the scope root". `src/transcript.ts` contains no cgroup read at all (its exports resolve transcript files by session and address). The actual other reader of a process's own cgroup is `src/admission.ts:callerScope`, which derives the caller's scope from the last `.scope` segment of `/proc/self/cgroup` and feeds run records and verify rows. Relocation into `akrogon/<t-name>/` keeps that segment, so it should be unaffected, but that is the line to state and prove, not the transcript one. Replace the bullet.

6. **Owned surfaces omit the repo's behaviour records that this leaf changes.** `docs/reference/files.md` enumerates every `timings.jsonl` kind in one line; the new `tool_kill` (and `tool_kill_deferred`) kinds are not in the owned surfaces, so that list goes stale on landing. `src/AREA.md` documents each key file and command behaviour in `src/` (the stopped leaf's diff updated it for far less); a new kill module, a new CLI verb for the helper, changed `startSeat` argv and changed `commitMove` behaviour all belong there. Add both files to the owned surfaces.

7. **Helper placement is specified in the racy direction.** Design: "commitMove creates `helpers/<t-name>/` and writes the helper's pid into its `cgroup.procs` before it returns". The helper starts in the spawner's cgroup (`akrogon/<t-name>/`) and its first poll can already see the shell ended (the zombie case Taken names), write the kill and exit. The spawner then writes a dead pid, gets `ESRCH`, and under criterion 4 must warn as if the spawn failed, or guess that `ESRCH` means success. It cannot tell "helper already finished the job" from "helper crashed instantly". Change the contract so the helper moves itself into `helpers/<t-name>/` as its first step (the directory commitMove created is the claim; the helper's own timing row is the evidence it ran), and the spawner never writes another process's pid.

8. **The relocation read is the one `/proc` read not routed through the boundary.** The kill module bullet says all reads go through `cgroupRoot()` and `procRoot()`, and the helper is specified to poll `<procRoot>/<pid>/stat`, but the CLI-startup bullet in `src/akrogon.ts` says a process "whose `/proc/self/cgroup` is a `tools/t-*`" with no boundary named. Those overrides (`AKROGON_PROC_ROOT`, `AKROGON_CGROUP_ROOT` in `src/scope.ts`) are the repo's only test seam for path logic, and `callerScope` already reads self's cgroup through `procRoot()`. State that the relocation step does the same, or the implementer hardcodes `/proc` and the relocation is only testable end to end.
