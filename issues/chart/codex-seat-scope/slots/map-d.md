# Territory map, slot D: codex-seat-scope

## Cause: confirmed, with my own probe

The intake's cause is correct. My probe (2026-11-25, throwaway dir under /tmp, removed after): a `BASH_ENV` file that appends `pid`, `ppid`, `$0` and both cmdlines to a log, then `timeout 20 env BASH_ENV=<probe> codex --version` (codex-cli 0.172.0). The log got two hits: `/bin/bash /usr/share/omarchy/bin/omarchy-agent-account-exec codex --version`, then its child `omarchy-agent-account-home codex`. The same probe with `pi --version` logged nothing. So a codex launch passes through a non-interactive bash script, and bash sources `BASH_ENV` in that script shell before the real agent binary exists.

The chain in code, end to end:

- `startSeat` in `src/seat.ts` builds the seat argv: `systemd-run --scope -p Delegate=yes -- env ... AKROGON_SEAT_CGROUP=<scope> ...wiring ...harness.argv task`. For every kind other than claude and agy, wiring is `BASH_ENV=<home>/tool-entry/bash-env`.
- `placementShell` in `src/tool-cgroup.ts` (rendered by `entryTemplate`, written by `refreshToolEntry`, identical text at `~/.akrogon/tool-entry/bash-env`) moves any bash whose `/proc/self/cgroup` equals `AKROGON_SEAT_CGROUP` into `<scope>/tools/t-$$-<starttime>` and exports `AKROGON_TOOL_CGROUP`. Its only identity test is "a bash sitting exactly at the scope root with the marker set". The codex launcher bash passes that test: systemd-run has just put it at the scope root and the marker is in its env.
- `scopeEntry` in `src/seat.ts` then polls `cgroupOf(launched.pid)` for a path ending with `/<slice>/<unit>`. The seat pid now ends with `/tools/t-...`, so after `PANE_WAIT_MS` it returns `outside`, and `startSeat` ends the terminal and throws `seat outside its leaf scope`. When the poll wins the race before the launcher moves, the seat starts but lives in `tools/` unchecked (intake finding 5), which is worse, not better: see P2.
- The launcher is pid-preserving at its last step today (`omarchy-agent-account-exec` ends in `exec "$agent_binary" "$@"`, and `~/.local/share/mise/command-wrappers/bin/codex` is the mise binary). That fact matters for O3 below and cannot be assumed of the next wrapper.

Why the closed design missed this: Q3 in `issues/closed/seat-shell-kill/tool-cgroup-kill/design.md` wired "pi and codex: `BASH_ENV`" from evidence F5, which observed `BASH_ENV` firing for codex's tool shells in exec/print mode. Nobody observed it firing in codex's own launcher, because the charting probes ran the harness in print mode from a shell that was not a seat. The design's placement rule, "act only when the current cgroup is exactly the seat scope root", was meant to mean "a top-level tool shell"; at seat launch, the seat's own process is also exactly at the scope root. The lock that cannot hold as written is Q3's implicit premise that in a `BASH_ENV` seat, only tool shells are bash processes at the scope root carrying the marker. The suite missed it for the same reason: the per-kind wiring test in `tests/tool-entry.test.ts` links the stand-in names `pi` and `codex` to the sh stand-in, so no seat test has ever launched a harness through a bash script.

## D1. Where the seat's own process is told apart from a tool shell

- O1. Arm the entry only after the seat has started. `startSeat` already has the boundary: `firstTask` returns after the harness proves its first task started (`src/seat.ts`, the `started.outcome === 'failed'` check is the natural arming point for the other two outcomes). Give the seat argv one more env name holding a per-seat arm-file path (in the leaf temp, named by unit), have `placementShell` return 0 until that file exists, and have `startSeat` create it once the seat is live. The discrimination is ancestry, read by nobody: a launcher bash is an ancestor of the agent process, so it sources `BASH_ENV` before the agent can report a start; a tool shell is a descendant, so it sources after the agent exists. Holds for exec and fork-and-wait wrappers alike, for pi or any future kind whose launcher becomes a bash script, and keeps Q3's wiring, Q5's no-process-reading rule, `scopeEntry`, and the sweep untouched. What it gives up: tool shells spawned during harness startup, before the arm point, are not placed and escape the phase-move kill until leaf close. That window covers startup hooks and MCP launchers, which Q5 wants surviving by placement anyway; a long-lived leftover spawned in the first turn before the proof returns is the real, narrow loss. The `tool_kill` timing row's seen count makes a widening miss visible, as today.
- O2. Discriminate inside the entry by shell shape. Skip placement when `$0` is a script path, or when the parent is not the harness, or let only the first bash at the root claim the seat. Each variant reopens what the closed design rejected: Q5 refused a parent test at spawn ("no process is read to decide"), `$0` shape breaks the day a wrapper becomes `bash -c 'exec codex'` or a tool runs `bash deploy.sh` (the script shell then escapes), and first-come claiming lets pi's and claude's first real tool shell escape on every seat forever. These are selection rules that rot with wrapper fashion.
- O3. Move the seat back. Teach `scopeEntry` that `<scope>/tools/t-<pid>-<start>` for the launched pid is a stage, not a verdict: write the pid back into the scope root's `cgroup.procs` and keep waiting for exact entry. No entry change, no new env. It works today only because every launcher stage execs, keeping one pid from `env` to the real binary (confirmed above for mise and the omarchy script). Breaks two ways later: a fork-and-wait wrapper's agent child can be born inside the `t-` before the move-back polls (50 ms cadence in `scopeEntry`), and then the agent lives in a killable `t-` while its parent sits at the root; and during the mint-to-move-back window the seat pid is in a `t-` that a sibling seat's `commitMove` sweep can kill, since `sweepToolCgroups` in `src/tool-cgroup.ts` enumerates every scope of the leaf's slice, including one still starting. Both are races the fix would own forever.
- O4. Accept the seat in `tools/` and fix the consumers. Broaden `scopeEntry` to accept the seat's `t-`, and exempt that `t-` from `sweepScope`. The exemption needs a durable answer to "which `t-` is the seat's" available to any process that later sweeps (a sibling seat, the operator, merge): the closed design's Q6 rejected a recorded unit field and hc pid resolution for exactly this selection. Without the exemption this option is lethal, not degraded: `sweepScope` writes `cgroup.kill` to every `t-` whose `akrogon/<t>` is unpopulated, with the populated check on `tools/<t>` report-only, so the first phase move with no akrogon call in flight kills the seat's main process mid-leaf; with a call in flight, `toolKillHelper` instead waits without timeout on `toolShellAlive`, whose pid-plus-starttime identity is now the seat bash itself. Also every akrogon call the seat makes would relocate out of the seat's own `t-` (`relocateFromToolCgroup`), so the relocation, deferral and reporting machinery all start describing the seat as its own tool shell. This dissolves the uniform kill set Q5 bought.
- O5. Stop wiring `BASH_ENV` for codex. Two sub-shapes, both bad as the destination: PATH-first wrapper like agy, which F5 already refuted for codex ("a `PATH`-shadowed `bash` was never hit" in exec mode); or no entry at all for codex, which restores seat starts by deleting tool-kill placement for exactly the seats that stall watches. Either is an interim mitigation shape (N3 is the operator's version of it), not the fix, and kind-name special-casing invites the identical bug when pi's launcher becomes a bash script.

My direction: O1. It is the only option that removes the class for every bash-wrapped harness without reading processes, without a race, and without touching the sweep, relocation or `scopeEntry` semantics the closed leaf just bought.

## D2. If O1: the shape of the gate

- O1a. Gate only the sourced `BASH_ENV` form; leave the executed wrapper form (claude's `CLAUDE_CODE_SHELL`, agy's PATH `bash`) ungated. Those forms are only ever invoked as a shell for children, never as the harness launcher, so they need no protection and keep placing startup shells. `entryTemplate` in `src/tool-cgroup.ts` renders both forms from one `placementShell` call today, so this is one parameter, not a second template.
- O1b. Gate both forms uniformly. Simpler text, but claude's startup snapshot shell and agy's first tool shell lose placement for no benefit.
- Marker semantics: an unset arm-file env name must mean "place as today". Seats already running were launched without the name, and `refreshToolEntry` rewrites the shared `bash-env` file under them at the next seat start anywhere on the machine; if unset meant "never place", the fix would silently disarm tool-kill for every live seat from the first post-deploy seat start. A set-but-absent file is the only "not yet" state. Consultant seats are untouched either way: `launch` in `src/seat.ts` carries neither `AKROGON_SEAT_CGROUP` nor `BASH_ENV`, and the placement's first test already returns for them.
- Arm on `confirmed` and on `unconfirmed` (the seat is live and will be driven), never on `failed` or after the `outside`/bootstrap throws. The file lives in the leaf temp (`leafTemp(repo, slug)` is already in the argv as `TMPDIR`) under a unit-unique name, so it dies with the leaf's temp and a replaced seat never inherits its predecessor's arm file.

## Pitfalls, and what removes each

- P1. Regression proof must use a bash-script harness, or it proves nothing. The existing per-kind test in `tests/tool-entry.test.ts` passed through the whole incident because its `codex` is a symlink to the sh stand-in. The red-first test needs a stand-in whose `codex` is a `#!/bin/bash` script that execs the fake stand-in: on base, the seat start fails `seat outside its leaf scope` (or lands in `tools/`); after the fix, the seat pid's cgroup is the scope itself and a later tool bash still mints a `t-`. That is a free test at the real boundary (real hc core, real systemd-run scope, as `tests/tool-entry.test.ts` already runs).
- P2. Seats already misplaced by the race (intake finding 5) are not rescued by the fix. A codex seat that won the `scopeEntry` race under e3ec4b02 is sitting in a `t-` now; the next phase move on its leaf can kill or defer-kill it per O4's mechanics. The fix only changes future starts. Recovery is restart through the existing lost-seat path; whether any live seat is in that state is a read-only census of `<slice>/*.scope/tools/t-*` against live seat pids before landing, and it folds into N2 either way.
- P3. Deploy order is safe but asymmetric. Landing deploys automatically; new seats get the arm env and refreshed entry together because both come from the same `startSeat`. The one asymmetry is the shared entry file under already-running seats, removed by the unset-means-armed rule in D2.
- P4. The arm point must not be movable earlier by a later cleanup. Arming at bootstrap (when `startSeat` creates `tools/`, `akrogon/`, `helpers/` after `entered`) looks tidier and reintroduces the bug: `entered` fires as soon as systemd-run places the initial pid, before the exec chain reaches the launcher bash, so the gate would be open when the launcher sources. The proof that protects this is P1's test asserting the seat pid never lands in `tools/`; keep the arm write visibly after `firstTask` in `startSeat`, with the ancestry reason in a comment.
- P5. Stop and slice teardown are unaffected and must stay so. The seat stays a direct member of the scope, so scope stop, `stop.ts`, and the recovered-bare-shell predicate in `src/next.ts` (its `argv[0]` is `systemd-run` test) see exactly today's shape. Any option that left the seat under `tools/` (O4) would also have had to re-examine the bare-shell lost detection, since a bash-script harness parent reads differently there.

## Surfaces (under O1/O1a)

- `src/tool-cgroup.ts`: `placementShell` gains the arm-file test in the sourced form only; `entryTemplate` passes the per-form difference; header comment updated. No change to `ownToolCgroup`, `relocateFromToolCgroup`, `sweepScope`, `sweepToolCgroups`, `toolShellAlive`, `toolKillHelper`, `refreshToolEntry` mechanics.
- `src/seat.ts`: `startSeat` adds the arm-file env assignment beside `AKROGON_SEAT_CGROUP`, creates the file after `firstTask` for a live outcome. `scopeEntry`, `cgroupOf`, `launch`, `startConsultant` unchanged.
- `src/AREA.md`: the `src/tool-cgroup.ts` and `src/seat.ts` lines, one clause each on the arm gate.
- `tests/tool-entry.test.ts`: the bash-script stand-in seat test (P1); the direct entry-placement test now needs the arm file present (or relies on unset-means-armed, which should then be asserted explicitly so the compat rule is pinned); the per-kind argv test gains the new env name.
- `tests/tool-entry-tracing.test.ts`: untouched, it exercises the wrapper form.
- No docs or skill text names `BASH_ENV` or the entry (grep over `docs/` and `skills/` is empty), and no state record changes shape, so old records keep parsing and rollback stays as safe as the closed design left it.
- `~/.akrogon/tool-entry/bash-env` refreshes itself at the next seat start after deploy; no migration step.
