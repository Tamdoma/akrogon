# turn-release, slot A

Evidence: every move goes through `commitMove` (`src/phase.ts:105-144`); `next.ts` imports `phase.ts` (`src/next.ts:55`), so a move cannot prompt a seat without a cycle. Hook passes dispatch only the hooked pane's leaf plus dependents on `completed` (`src/next.ts:822-842`); an unowned pane returns at once (`:837`). Plugin fires `next` on every pane status change, pane exit, pane close and tab close, plus `--resume` at startup (`plugin/herdr-plugin.toml`). Dispatch failure already moves a leaf to `failed` after 3 undelivered prompts or an unreachable seat (`src/next.ts:459-482`).

Q1 1a recommended: every `next` pass ends by dispatching the current holder of each repo it looked at, and an unowned-pane hook does this for every registered repo instead of returning. Holder dispatch is a no-op when its B is busy or already prompted. Removes the "who wakes the next leaf" class: any move by any path (seat, dispatch failure, operator in a herdr pane) is followed by some pane event, and that event's pass prompts whoever holds the turn now. Cost: each hook pass reads one pane per repo with a waiting merge. 1b: wake inside each move path (merged, check.fix, failed, dissolve). Cost: one wake call per path, a missed path stalls the queue silently. 1c: operator runs `akrogon next` after moves. Cost: manual, stalls overnight.

Q2 2a recommended: no new mechanism. Dead seat: existing cap moves the holder to `failed`, which ends its turn. Busy-forever seat: `akrogon status` names the holder, operator moves it to `failed` (slot-less move, leaf-run-stalls failed-stop-race 1a). Leaving `merge` with a batch record runs one dissolve step in `commitMove`: if the batch top is an ancestor of main (`git merge-base --is-ancestor`), the batch landed, so finish the remaining moves instead of restoring; otherwise restore every member to its saved base and head, clear the record, no solo marks. 2b: `akrogon release <repo>` verb. Cost: a second way to end a turn that must do the same dissolve; adds nothing over moving the holder.

Q3 3a recommended: new stamp at the back. One rule (stamp at every move into `merge`), and under batching the returning leaf rides the next batch anyway, so the back costs about one run. 3b keep original place. Cost: a repeatedly red leaf goes to the front each time and holds everyone behind it; the stamp must survive check.fix.

Pitfalls: dissolve must check ancestry before restoring, or a landed batch whose holder died after push gets rewound. Solo marks clear on leaving `merge` (taken). Holder dispatch must refuse non-holders so a hook on a waiting leaf's pane cannot start merge work (taken guard).
