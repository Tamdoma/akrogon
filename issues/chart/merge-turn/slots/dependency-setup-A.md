# dependency-setup, slot A

Measurement (A, 2026-10-05, bun on this machine): throwaway detached framework worktree at origin/main in the scratchpad; `bun install --frozen-lockfile` reported "599 packages installed [453.00ms]", a second run "no changes [7.00ms]"; `node_modules/markdown-it` present; `du` 822M apparent (bun hardlinks from its global cache on Linux). Worktree removed with `git worktree remove --force` and pruned; `git worktree list` shows no probe. Limits: warm cache, one machine, framework only.

Q1 1a recommended: one repo key `setup` (ordered commands, e.g. `bun install --frozen-lockfile`) in `issues/config.yaml`. The command runs it (i) in `ensureWorktree` right after creating a worktree, and (ii) in the holder's worktree right before the batch check run, every time, with no lockfile comparison. Each worktree then has its own `node_modules`, so upward lookup never reaches the stale root. Running it always at merge removes the "did the lockfile change" check: unchanged lockfile costs about 7ms. New: one optional config key, two call sites. Reused: `ensureWorktree`, the command-owned batch flow. `init-akrogon` proposes the key when a lockfile exists. A setup failure is a red check, reported like one. Cost: disk per worktree (hardlinked, so small on real disk), ~0.5s at creation under the dispatch lock.
1b: config only, no akrogon code. Framework prefixes `bun install --frozen-lockfile &&` to the commands that need packages. Cost: every repo must know to do it; checks are a map run by seats in no fixed order, so the prefix goes on each command; two seats running checks at once in one worktree could race installs.
1c: keep sharing the root install and refresh it when main's lockfile changes (sync/pull). Cost: Off route already: a leaf that adds a package still fails, and refreshing the root under running checks changes their packages mid-run.

Pitfalls: leaf A that edits `package.json` during implement installs as normal work and commits the lockfile; `--frozen-lockfile` then fails loudly on a stale lockfile instead of drifting. Setup runs inside the worktree only, never in the registered checkout.
