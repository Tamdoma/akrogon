# Draft review B — disagreements

Reviewed ISSUE.md and all eight leaves' brief/design/readiness/state drafts. Common binding sections are identical across the eight designs. Findings name draft-relative paths below. Only this return file is written.

F1. All eight briefs end with a done-criterion that the repository's format/test/typecheck checks pass on the leaf head. These claim repository-wide health without naming the property no smaller check proves. The requested Preflight and validation audit explicitly rejects that form. Exact fix: remove these final done-criteria from the briefs; retain the normal required checks in the design's validation/workflow instructions. Keep the leaf-owned documentation, rendering and retargeted-check outcomes as acceptance criteria. This does not waive any normal lifecycle check. Evidence: final criterion in each brief; shapes.md Preflight and validation's repo-health and smallest-proof rules.

F2. docs-examples cannot satisfy its link contract. Brief criterion 3 requires current use and reference links for each step, but state.yaml lists only the two picture and two use leaves. Its design permits links only to its own leaf or a directly listed blocked-by leaf, so both reference destinations are forbidden even though their commits are transitively available. Exact fix: add docs-reference-commands and docs-reference-records to docs-examples/state.yaml blocked-by and name their consumed pages in What/Why. Alternatively explicitly permit transitive prerequisite outputs in the common link rule, but apply one consistent rule across designs and the map. Evidence: docs-examples/brief.md criterion 3, its state.yaml and design Link rule.

F3. New pages are explicitly allowed to link the old guide, creating work docs-start cannot own. Every design's common Link rule permits docs/guide links. docs-start criterion 5 must eliminate every such reference, while its design excludes pages owned by other leaves. If a prior leaf takes the permitted option, final deletion requires edits outside docs-start's ownership. Exact fix: forbid new pages from linking docs/guide; use existing delivered sources/skills or prerequisite-owned new pages instead. Keep guide files available only as authoring sources until final cutover. If legacy links are deliberately allowed, explicitly grant docs-start final inbound-link edits in those consumers and have each producer accept that ownership. Evidence: common Link rule/Excluded paragraphs, docs-start brief criterion 5 and split-and-checks' named-cutover responsibility.

F4. Binding decisions currently require an illegal issues/ edit and do not distinguish responsibility. Every design says all six forks bind it and “nothing is excluded”, then copies SVG Q1's instruction that “The leaf writes the concept-to-picture list into the subject-to-page map before drawing.” That map is PAGE-MAP.md under issues/chart, yet the same designs exclude every issues/ path and the audit forbids leaves owning such edits. Exact fix: identify the completed map/list as a door-owned handoff input, exclude its mutation from every leaf, and assign future necessary map changes to the door on main. Add explicit responsibility/exclusions for copied bindings whose outputs belong to other leaves, rather than declaring every output the responsibility of all eight. Evidence: all design Binding decisions openings, copied SVG Q1 and common Excluded paragraph; shapes.md Leaf files/Preflight and validation. The taken decisions themselves need not change.

F5. docs-use-finish misstates the retained rollback proof and makes text matching the acceptance result. Criterion 3 says the rollback test “reads its manual steps” from the new page and fails when a checked step disappears. The inspected test only reads documentation for two literal substrings and executes a separate handwritten TypeScript recovery sequence. The copied fact-ownership decision already records this distinction. Exact fix: state the leaf-owned result as “The canonical rollback page contains the supported manual recovery procedure, remains available when the current release cannot start, and agrees with the retained real-predecessor recovery proof.” Put the path retarget and deliberate break of the existing documentation reference in validation details, explicitly saying the literal shell block is not executed by this test. Preserve runtime recovery proof unchanged. Evidence: docs-use-finish brief criterion 3/design, fact-ownership Taken Q2 and tests/rollback.test.ts manual-steps test.

F6. Private metadata location guidance is inconsistent and machine-specific. All drafts copy the old examples Q3 sentence saying provenance stays in chart/leaf notes, followed later by the correction that these locations are public and provenance is in ignored scratch. The examples/start designs also include an absolute machine home path for that scratch file. Exact fix: explicitly mark the earlier storage sentence superseded by the privacy correction and direct both readers to the ignored provenance file relative to the registered root, resolved via akrogon config. Do not reproduce identifying provenance in public reports or designs. Keep installed skill paths where the shape explicitly requires them. Evidence: common examples binding Q3/privacy paragraphs and docs-examples/docs-start private-provenance paragraphs. No private project identity or private source commit was found in these drafts.

Exact fix: replace “path” with “personal home path or private machine/project path”, keeping generic supported paths allowed where necessary to explain the real change. Evidence: docs-start brief criterion 3 versus examples Taken Q4 and the same brief's criterion 2 requiring today's commands.
