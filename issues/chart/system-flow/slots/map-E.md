The whole system oscillates between two decoupled regimes: a human-paced, multi-round consultation door (`seeds -> chart -> open`) and an automated 2-seat leaf factory (`plan.solo -> plan.synthesis -> implement -> check.review -> check.repair -> check.fix -> merge -> merged`).

### Q3. Which reinforcing and balancing loops run?
**Reinforcing loops:**
- **R1 (Rebase-Rework Cascade):** Every `merge -> check.fix -> check.review -> merge` bounce delays landing while `main` advances; rebasing onto newer `main` invalidates shared spine recordings or contract manifests (`promotion-script` F9 after `disavow-evidence-scope` merged; `prior-disavow-lookup` spine recapture after `prior-pack-diff` merged), triggering another red merge.
- **R2 (Load-Induced Test/Subprocess Failure -> Retry Amplification):** Concurrent `test_changed` (`15.6 m` med, `6.75 h` W1) and `framework:verify` (`6.76 m` med, `11.68 h` W1) runs push host 1-min load to `20–38`, causing timeouts (`page-speed-ranking` `size-fit git init`, `promotion-script` base-run killed) that force reruns and `failed` visits.
- **R3 (Gate-Syntax Accretion):** Strict phase-exit gates create meta-rework where seats spend commits/turns satisfying gate syntax rather than product state (e.g., in `prior-disavow-lookup`, Seat B had to commit two empty `Test-Change` commits `174116da0` and `3545df5d4` just so `akrogon phase ... check.fix` would permit handing a red merge back to A).

**Balancing loops (Goal | Sensor | Correction | Does sensor see real goal?):**
- **B1 (Leaf Pre-Review Gate — `implement` -> `check.review`):** *Goal:* Catch leaf and repo regressions fast before review. *Sensor:* `akrogon verify` (`scope=leaf`, running `framework:verify:cheap`, `23s` med). *Correction:* Seat A edits in `implement`. *Sensor fidelity:* **Partially blind.** `framework:verify:cheap` (`package.json:168`) still runs 7 hardcoded suites left over from pre-`fb236ec` leaves (`test:sb-offer-forms` + 6 backlink tests) on every leaf, while omitting fast static closure checks (`validate-handoff-schema.test.ts`, `verify-single-cohort-benchmark-fixture.py`, `skills:scan`) that only run at `merge`.
- **B2 (Review/Repair/Fix Loop — `check.review <-> check.repair <-> check.fix`):** *Goal:* Correct defects quickly with independent test-expectation authorship. *Sensor:* Seat B reviewing diff, `report.md`, and `Test-Change` trailers. *Correction:* B repairs code (`check.repair`) or routes to A (`check.fix`). *Sensor fidelity:* **Broken on red-merge recovery.** `implement-issue/SKILL.md:80` tells A to run *"the narrowest command ... such as the failing test files"*, while `check-issue/SKILL.md:69` tells B to block if A used *"narrowed paths or skipped stages"*. When A follows `implement-issue`, B rejects the pass (`prior-pack-diff` F3, `promotion-script` F8 x2), forcing `1.6 h` of pointless ping-pong. Furthermore, mechanical golden/debt-list syncs (`prior-disavow-lookup` `legacy-golden/manifest.json`, `prior-pack-diff` `KNOWN_OBJECT_INPUT_DEFECTS`) are treated as "test expectation" judgments, barring B from fixing 2 lines in `check.repair`/`merge`.
- **B3 (Merge Gate — `merge` -> `merged`):** *Goal:* Keep `main` green. *Sensor:* `akrogon verify --attempt` checking `verify-runs.jsonl` (`src/verify.ts:63`) for a `scope='merge'` receipt on the current tree SHA, else running `framework:verify`. *Correction:* Push on green; bounce to `check.fix`/`failed` on red. *Sensor fidelity:* **Blind to A's identical-tree `check.fix` runs.** Because `src/verify.ts:116` hardcodes `scope = caller.phase === 'merge' ? 'merge' : 'leaf'`, when A runs the full `framework:verify` in `check.fix` on tree `T`, no `scope='merge'` receipt is recorded; 3 minutes later in `merge`, B runs the same `5.65 m` suite a second time on the exact same tree `T` (`prior-pack-diff`, `promotion-script`, `prior-disavow-lookup`).
- **B4 (Cohort Flow Sensor — `akrogon timing --since`):** *Goal:* Keep non-implement flow `F <= 35 m` median and ejections `<= 2/20`. *Sensor:* `src/timing-report.ts:103,283` (`F = merged - joined - implPrompted`). *Correction:* Operator opens flow charts. *Sensor fidelity:* **Broken when same-seat phases run in one turn.** When Seat A moves `plan.synthesis -> implement` in the same turn (`browser-lane-pool`, `deploy-test-setup`), no `prompt` event fires for `implement`, so `implPrompted = 0` and `F` falsely absorbs the entire `implement` phase while emitting bogus `incomplete prompt` gaps.
- **B5 (Operator Escalation — `-> failed`):** *Goal:* Escalate true external blockers to operator. *Sensor:* Seat A/B moving to `failed`. *Correction:* Operator intervenes (`8.0 h` W1). *Sensor fidelity:* **Historically noisy (`15` W1 visits).** `5/15` were guessed CPU/wall caps (fixed by `7092fae`), `2/15` were expired `gh auth`, and `5/15` were sibling leaves spawned in parallel whose `done_when` required consuming an unmerged sibling leaf's output (`promotion-script` needing `prior-pack-diff`; `coverage-page-inventory` needing pack-selection/inventory replay).

- **Stability risk (6 months out):** If a fix passes the narrow unit test in `check.fix` but breaks a different `merge_checks` stage, `merge` catches it. That occurred `0` times in W1 after unit reproduction.
