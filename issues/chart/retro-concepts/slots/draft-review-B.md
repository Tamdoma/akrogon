## Part 2: ideas that belong

D1. Evidence before diagnosis. Retro reads primary evidence (`issues/chart/retro-concepts/slots/source-retro-SKILL.md:13`); here the bounded equivalent is the lesson's linked history and current mechanism, not session logs. Existing history distinguishes proposed from observed prevention (`learnings/history/README.md:24–25`). Add to the skill: “Read each lesson's linked history to establish the observed failure and its mechanism. Verify that mechanism against the current code and checks before choosing an outcome. Missing evidence leaves the lesson as stays.” This preserves all binding outcomes.

D2. Inspect existing checks before suggesting new enforcement (`issues/chart/retro-concepts/slots/source-retro-SKILL.md:18`). Akrogon already wires checks through repository configuration (`issues/config.yaml:7–11`), so merely finding a test does not prove enforcement. Add: “Inspect the repository's configured checks, relevant scripts and guard call sites first. Verify that existing coverage is actually reached and covers the mechanism wherever it can recur. A defined but unwired check is evidence of a remaining gap, not already guarded.” This clarifies the existing full-coverage requirement (`issues/chart/retro-concepts/forks/adopt.md:26`).

D3. Separate mechanically checkable failures from judgement (`issues/chart/retro-concepts/slots/source-retro-SKILL.md:19`). Akrogon preserves observations and chooses checks by concrete value (`skills/plan-issue/SKILL.md:27`, `skills/chart-issues/assets/standing-design.md:10–11`). Add: “Classify a lesson as checkable only when a deterministic check could catch its evidenced failure. Judgement calls stay observations. Offer the lesson and reachable case as intake, without prescribing a check or adding a rule.” This preserves X4 and seed-issue's report boundary (`issues/chart/retro-concepts/forks/adopt.md:40`, `skills/seed-issue/SKILL.md:26`).

## Ideas that do not belong

R1. Do not import the full navigation, steering, tool-economy, no-op or information-access audit (`issues/chart/retro-concepts/slots/source-retro-SKILL.md:17`, `:20–23`). Those subjects can occur in an existing lesson, but searching for new opportunities widens this skill beyond active-lesson triage. Add: “Work only from active lessons and the evidence needed to classify them. Do not audit unrelated instructions, tooling, navigation or service access.” A session-log retrospective would change the binding scope (`issues/chart/retro-concepts/forks/adopt.md:33`, `issues/chart/retro-concepts/slots/draft/learn-issues/design.md:16`).

R2. Reject automatic check creation, coding-standard edits, global steering moves and the assumption that missing CI or a hook alone proves a gap (`issues/chart/retro-concepts/slots/source-retro-SKILL.md:18–20`, `:35–42`). They bypass offered intake, the default stays outcome or the separate-skill scope (`issues/chart/retro-concepts/forks/adopt.md:27`, `:33`, `:40`). Add: “Do not build checks, rewrite standards or steering, or file seeds in this pass. Absence of a hook or CI job alone does not establish missing coverage. Report the demonstrated gap for the operator to accept or decline.” These actions would require reopening binding decisions.
