## Forks, pitfalls and split

- D1: No behavioral fork is needed. The existing skill, shapes, questions and status code already settle the modes, record shape, copies and counts. The destination is documentation that matches those rules.
- D2: One issue with one documentation leaf is the smallest defensible split. Reader guides, file references, glossary qualifications and the existing mode figure serve the same outcome. There is no independent source-code outcome or actual dependency requiring another leaf.
- D3: Keep the navigation candidates F13–F16 proportional. Selective indexes and high-level summaries are not automatically wrong because they omit the word signposts. Use existing pages and links rather than duplicate the agent procedure.

- R1: Confusing a presented signposts round with an asynchronous wait can incorrectly park a chart or allow mapping before the operator's round is answered. Preserve the unanswered-question exception in ordinary autopilot.
- R2: A chart's local signposts file must not become an independent decision record. Corrections have an original and open-chart copies, and a later door run does not inherit an old folder's signposts as binding answers.
- R3: “A answers the forks” must not imply A grants approvals. Full autopilot also cannot drop handed charts. Chart ordering is separate from lifecycle dispatch priority, which is unchanged.
- R4: Do not change status counting, introduce new files/checks, migrate open leaves, or rewrite earlier examples. Those would expand a written-reference update beyond the session's 1c, 4a, 5a and 6a locks.
- R5: The open option-drawings leaf owns `docs/use/plan-work.md` / Answer one fork per round for its drawing sentence, plus the round-shape drawing text in questions.md. The signposts guide work can stay in Open a chart and Set the signposts. The grant-count leaf owns its named skill grant paragraphs and readiness placeholders. Proof-coverage/coverage-audit already updated the handoff proof explanation, which is unrelated and current. No dependency is created by sharing a file.

The scope is the remaining documentation mismatch, including the broader operator-answer wording where the same mode boundary is wrong. It does not reopen the signposts feature or its settled decisions.
