## failed-with-cause

- **F1 — CLI ownership is incomplete.** `design.md:22` assigns parsing `--reason` to `phaseCommand`, but strict top-level argument parsing rejects it before that function runs (`src/akrogon.ts:9-24`), and the caller passes only four arguments (`:42`). Add `src/akrogon.ts` and its flag forwarding to this leaf's ownership. Define the updated `phaseCommand`/`transition` signatures alongside `commitMove`, including how existing nonfailure callers omit the sixth parameter.

- **F2 — The prescribed transition edits do not implement an immediate stop from every active phase.** Adding routing edges and bypassing worktree guards leaves the positions destination check (`src/phase.ts:110-111`), review verdict requirement (`:120-121`), two-seat completion barrier (`:127-130`) and review destination override (`:132-140`) in place. A stop must bypass completion aggregation and review-success logic while validating its declaring seat. Add negative/edge tests for stopping from positions with rebuttal on/off, from initial two-seat review without a verdict, and with the peer unfinished, proving immediate failed state and no successful-phase advance.

- **F3 — One existing failure producer has no cause contract.** Review repair exhaustion also enters failed at `src/phase.ts:138-142`; only dispatch-attempt exhaustion is assigned a failure object in `design.md:22`. Name the cause/reason and responsible seat for repair-cap failure within the chosen `blocked | attempts` schema, or settle a schema change explicitly. Test it, plus legacy failed state without `failure`, so status and failure-attention never assume an object that an existing producer does not supply. Also specify whether recovery removes current failure/delivery state or retains it as history before the next attempt.

- **F4 — “Failed leaves never count” is not met by editing the active-leaf filter alone.** `design.md:22` names the `activeCount` filter, but when another leaf is unreadable, `src/next.ts:267-268` counts every valid leaf through `inventory.leaves.length`, including failed ones. Define exclusion in that branch too while preserving the genuinely unreadable contribution, and add a mixed failed-plus-malformed-state capacity test.

## blocked-seat-stop

- **F5 — The specified insertion point can miss the promised stop.** `design.md:22` puts detection after `observeBusy`, but that function can throw while issuing an overdue busy notification (`src/next.ts:195-202`). `dispatchLeaf` also calls it before reaching `dispatchSlot` (`:468-472`), and dependency/allocation checks precede slot dispatch (`:492-500`). A currently required blocked seat can therefore remain active when an unrelated observation or allocation operation fails. Own detection at the existing-pane observation boundary before those side effects, preserving the required/unfinished-seat filter. Test a blocked event with overdue busy metadata and failed notification delivery, and test repeated events after stopping. This need not change or remove the retained 60-minute notice for active work.

- **F6 — Terminal busy clearing is undone on the next invocation.** The failed-with-cause leaf clears fields, but `dispatchLeaf` excludes only merged leaves from observation (`src/next.ts:468`), so a still-blocked failed pane immediately recreates `busy_since` and can later trigger another busy notice (`:190-207`). Neither draft owns preventing that write. Assign terminal observation exclusion to this leaf or failed-with-cause, and test that repeated next calls leave failed busy fields empty without notices or redispatch.

## failure-attention

- **F7 — Both Herdr helper schemas are wrapped one level too deeply.** `design.md:19` passes `{ result: ... }` schemas to `herdr()`, but `src/shell.ts:93-101` already wraps the provided schema in `{ result: schema }` and returns its inner value. Supply `{ shown, reason }` and `{ tab: { label } }` to that helper. The measured CLI envelope is evidence for the outer transport, not the helper's return type.

- **F8 — Removing all references to failed_notified breaks existing saved states.** `brief.md:14` requires zero code/test references, while persisted states currently contain this defaulted field and `stateSchema` is strict (`src/state.ts:14,23`). `readState()` only strips legacy priority/slot keys (`:48-53`). Retain explicit read-boundary compatibility for the removed field and test real legacy-shaped states, rather than requiring edits to consumers' `issues/` records. Remove runtime use and serialization, not the compatibility test or parser recognition.

- **F9 — Delivery failure and recovery rename outcomes are not defined consistently.** `brief.md:4,13` promises recorded delivery outcomes but only supplies success-response reasons, then requires exit 0 after two errors. `design.md:18` persists delivery after rename, so a failed rename could also discard evidence that notification succeeded. Define and persist a distinct transport-error outcome, preserve notification results independently of rename, and test notification failure with rename success and the reverse. Also define rename failure during recovery: the phase has already left failed, so the blanket claim that the leaf stays failed cannot apply. Keeping the committed lifecycle state is separate from silently returning success on an unsuccessful attention operation. The taken decision requires visible failure and a recorded outcome, not exit 0 for transport failure.

Include the supplied seat in the skill's stop invocation and verify all dispatched phase/slot combinations, not only B implementation.
