- **F1 — Reporting a workspace token does not make it visible automatically.** Herdr `website/src/content/docs/configuration.mdx:291-300,335-353` requires adding the custom `$failed` token to the Space-row layout. The proposed setup only changes toast delivery. Include the layout change and verify the row actually renders the failure, otherwise step 2 records invisible metadata.

- **F2 — Clearing on any successful phase move loses other failures.** Two leaves can fail in the same workspace while unrelated leaves continue. A single `failed=<slug>` overwrites the first failure, and clearing it on another leaf's successful move hides unresolved failures. Recompute the workspace's failure summary from authoritative leaf state on failure/recovery and clear only when none remain. Herdr's token map is a latest-update-wins patch, not a collection (`socket-api.mdx:725-741`). No TTL does not survive a server restart either (`:739`), so specify reconstruction on an existing invocation or limit the persistence promise. `--seq` is optional, but updates must stay serialized under akrogon's lock or use an explicitly ordered sequence if sent asynchronously.

- **F3 — The workspace target is not yet fully specified.** Leaf state retains `tab`, not a workspace ID. Allocation finds a workspace by repo label for new tab placement, but can reuse an existing tab (`src/next.ts:286-290,299-315`), while akrogon's `tabSchema` currently discards workspace identity (`src/shell.ts:85`). Resolve the recorded tab's actual workspace through Herdr and retain the required field, or explicitly enforce repo-workspace placement. Also define the outcome when the tab/workspace no longer exists. Do not pass `state.tab` as the workspace argument or assume a reused tab belongs to the label-selected workspace.

- **F4 — System delivery does not guarantee an OS notification-centre entry.** Herdr documents system/terminal delivery as best effort through the current foreground attached client, with outcomes including `no_foreground_client` (`socket-api.mdx:323-332`). Change the claim to requesting system delivery and recording the actual result. A disconnected overnight session may receive no toast, and the workspace token is not an off-device push. This limitation must be explicit when replacing the rejected webhook proposal.

- **F5 — The proposed recovery command is incomplete for preserved work.** `failed -> check.fix` is absent from `src/routing.ts:35-38`, so recovery to every interrupted phase needs a routing change. Normal recovery also encounters `requireClean` and the issue-diff guard (`src/phase.ts:117-119`), so fixing an external permission alone does not make preserved dirty work resumable. Finally, `phaseCommand()` only transitions state (`src/phase.ts:164-178`), and a pending question can leave the old Pi process blocked. Define how partial work and the old session are made safe, then give the explicit redispatch step rather than promising that `phase <slug> <interrupted phase>` alone restarts execution.

- **F6 — Independent leaves continuing needs a capacity decision.** `activeCount()` excludes merged leaves but counts failed leaves with retained live panes/tabs (`src/next.ts:269-273`). The stop contract preserves those resources, so enough failed leaves can occupy every allocation slot even when independent work is ready. Qualify the promise by existing capacity rules, or explicitly own the policy for stopped attempts and still-running peers before promising that the remaining overnight run continues.
