# Leaf review, B

- F1. The criteria do not require preservation of Claude's non-settings arguments. An implementation could drop `--dangerously-skip-permissions`, `--model` and `--effort` while satisfying the five stated criteria: correct settings, refusals, unchanged other harnesses and the final AskUserQuestion exclusion. That violates the design's “parsed template with the merge applied” interface and can change permission behavior. Exact fix: add to the criteria that, for every accepted Claude form, all original non-settings argv elements remain unchanged and in their original order, followed by the existing Claude suffix. Prove that property at the same argv boundary. This covers a pre-existing key part that the settings-JSON assertions alone cannot reach.

- F2. Criterion 5 promises the AskUserQuestion exclusion occurs exactly once for every accepted Claude template, but the design says the existing unconditional append stays untouched. A valid template that already contains `--disallowedTools=AskUserQuestion` therefore satisfies the declared acceptance rules and produces two occurrences. `src/config.ts` does not prohibit that template, and `src/seat.ts:harnessArgv` unconditionally appends the flag. Exact fix: replace the global occurrence-count promise with “the existing `--disallowedTools=AskUserQuestion` suffix is appended once as the final element, preserving any original template arguments.” Keep the current-machine-template check showing one occurrence. Do not add deduplication or another refusal for this unrelated case.
