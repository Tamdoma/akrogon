# Sweep B: flake-zero

Read at flock-orphans head 51a58e44 and its base bdc34423. I ran no probe for this one. The counts are the helper's. Nothing in the repo changed.

1. Recommendation: O2, and take its deletion one step further (point 5).
2. `killTree`: list the descendants first, then kill the root, then kill the list (`tests/helpers.ts:141-150`). It is the same lines in another order. Today it asks for the children of a pid it has just killed, and gets none. That one fix covers 60 of the 72 orphans, because both run-permit cases end through `killTree` (`tests/run-permit.test.ts:163-165, :556-558`).
3. The two inner tests: the payload already writes its own pid to `pid-inner` (`tests/abandoned-capture.test.ts:72`), and `gone(pid)` exists (`:80`). After writing `release-inner`, wait for that pid to be gone before `f.clean()` (`tests/abandoned-capture.test.ts:363-368`, `tests/durable-capture.test.ts:205-210`). One or two lines per file.
4. Delete the exit handler that never runs (base `tests/isolation.ts:135-142`).
5. With the handler gone, `sweepSuite` has one caller left: its own test (`tests/isolation.test.ts:73`). The subreaper `prctl` and the `waitpid` binding exist only for that sweep (base `tests/isolation.ts:15-25, :118-133`). `killTree` no longer needs the subreaper once it lists first. So the sweep, the subreaper and the adoption test (`tests/isolation.test.ts:45-76`) can all go. `descendantsOf` stays for `killTree` and run-permit's `halt`. That is about 50 lines removed against about 4 added.
6. Why not O1: it makes that machinery live again and adds to it (+52 -16) to cover sources that three small fixes remove. It also leaves `killTree` wrong. Its sweep kills every descendant of the worker after each file, so a child that a shared module keeps across files of one `--no-isolate` worker would be killed between files. I did not find such a child today.
7. Why not O3: the known loops would keep forking 20 times a second until the run ends. That is extra load inside verify, and load is what the flakes in this chart came from.
8. Simpler native option: a process group. Spawn the root with `detached: true` (Bun 1.4.5 has it) and `killTree` becomes one `process.kill(-pid, 'SIGKILL')`. The kernel kills the whole tree at once, with no listing and no race with a fork, and it still works after the root has died. I would not take it. It needs the flag at every spawn site that feeds `killTree`. Ctrl-C on a direct run would no longer reach those children. And a child the product itself detaches (`src/listen.ts:49`) would be missed, which the listing catches.
9. Main risk: O2 fixes the three known sources and guards nothing else. A new test that leaves a child behind in a direct `bun test` run leaves it for good, as before. Boxed runs and verify end such a child with the run. If that happens again, the next step is the rule that ad-hoc runs go through `bun run test`, not a sweep.
10. Smaller risk: in `killTree`, a parent can fork a new child between the listing and its own kill. For these loops that child is a `sleep 0.05`, which ends by itself. A tree that forks long-lived children at that moment would need the process group.
