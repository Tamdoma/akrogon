**1. Soundness of O1:** Sound **only** for pure state-only predicates (`(t: Seen) => boolean`) — a `get` after the snapshot is a true post-subscription state and never merges into the sequenced queue (closing F1 and F2). Putting O1 in `waitFor` is **unsound** for `agyTask` (`src/seat.ts:146`), which is side-effecting and `line`-driven: a `missed` snapshot firing a concurrent `get` would invoke `until` in parallel without a real `line` and risk a double `send`.
**2. Simpler, more native option:** Put O1 in **`waitForTerminal` (`src/hc.ts:624-638`)**, not `waitFor` and not only `door-reset.ts`.
- Revert `waitFor` (`src/hc.ts:565-621`) to pure sequenced stream processing (zero `get` calls; seats already subscribe before `hc run`).
- Narrow `waitForTerminal` to `until: (t: Seen) => boolean` (all 8 callers in `skills/` and `tests/` already are).
- Right after `open()` returns (initial snapshot already queued, stream live), `Promise.race` `waitFor(stream, address, null, until, deadline - Date.now())` with one concurrent `terminal(session, address)` check that resolves **only** if `until(t)` is `true`, and otherwise stays pending forever (on `false`, `not_found` [F3], or its 60 s CLI timeout/error [F2], logging unexpected errors) so `waitFor` owns completion, stream errors, and deadline.
- Don't limit it to `door-reset.ts`: `watch-consults-body.ts:286` and `watch-live.e2e.ts:179,565,590,730` have the same `waitForTerminal` startup-drop gap.
**3. Races left:**
- *F4 TOCTOU:* if the core dies between `open()` receiving the snapshot and `hc get` connecting, `hc get` can still auto-start an empty core (returns `not_found`, ignored while `waitFor` rejects on `stream.ended`). Checking the stream hasn't ended before spawning `get` shrinks this to the irreducible CLI TOCTOU window.
- *Non-monotonic predicates & late `get`:* `door-reset.ts:89` catching a brief `idle` before a new operator turn is identical to pure events and still caught by `input-check` (`:95`); handle late `get` rejections after `waitFor` wins so nothing goes unhandled. (Separately, `tests/hc-fixture.ts:391-407` still carries the F1 merge-onto-`get` caveat.)
