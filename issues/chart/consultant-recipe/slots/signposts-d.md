- M1 Intentional off vs accidental missing: can an operator deliberately run watch notify-only, with no consultant agent acting on human-prerequisite blockers? (a) Yes, an explicit disabled value that missing cannot be confused with. (b) No, a working consultant recipe is mandatory wherever watch runs. This decides the schema shape and what watch does with each state, before S2's fallback question applies.
- M2 Where requiredness is enforced: (a) in the global schema, so every akrogon command refuses a config without the key, watch user or not; (b) as a preflight when watch starts, so non-watch use never breaks and the stall is caught before any leaf runs; (c) only by provisioning at install/init, leaving later hand-edits unchecked. S2 asks fail loudly vs fallback but not when or for whom it fails.
- M3 Breaking currently valid configs, and order of operations under auto-deploy: can this change make a config that parses today stop parsing on the release that lands it, and must the live config (S4) be fixed before that landing to avoid breaking the operator's installed command mid-flight? (a) Never break a parsing config; warn first, require later. (b) Break is acceptable, but only sequenced after the live config carries the key. (c) Break immediately. This steers the rollout and the N1 timing, not just who writes the key.
- M4 Missing option inside any default or seed (S2b, S4b): where do the recipe's harness, model and effort come from? (a) Copied from an existing slot (`slots.a`). (b) A fixed product default. (c) Prompted at init, never invented silently. Seeding fixes the stall but picks the model that will act unattended on blocked leaves, with cost and quality consequences no draft question owns.
- M5 The disappearance itself: this machine had a working config on 2026-11-23 and no key on 2026-11-24, cause unknown. Is proving that no akrogon config writer can drop the key (preservation covered by tests for the init and migration writers) in scope alongside provisioning, or is the loss treated as an external edit the chart ignores?
