## 1. Pick, reason and cost

**Q1: defer implementation.** The intake reports neither a missed/false loop call nor measured counting cost (`INTAKE.md:31`, `:39`). The script already supplies evidence to a watcher turn that must judge the brief and tool state. Adding counts cannot remove that turn (`skills/watch-issues/SKILL.md:42`). The missing work is more than incrementing counters: mixed results, incomplete calls and edit identity need definitions. Cost of deferral: manual counting remains, including any mistakes not yet observed. Revisit on a concrete counting error or a demonstrated recurring cost, without adding permanent measurement machinery now.

**Q2, if the door chooses to build: script computes counts AND mechanical threshold matches over the last 20 displayed entries. The agent retains the intervention decision.** Use one owner for arithmetic and the numerical predicates. A match means the stated repeat/error/inverse-edit pattern was observed, not that the seat is stuck. Keep the skill's normal-work/long-command exception and its brief/context judgment. This is narrower than “script verdict, skill keeps only on-brief and hung-tool judgment.” The latter would remove the contextual check on whether a mechanical match is a harmful loop.

No history store, new timer, classifier or additional watcher turn. Show the matching entry references and the window's coverage. Cost: patterns crossing the window boundary may be missed, and old patterns inside the window can still be resolved rather than current. Neither an empty match list nor incomplete parsing proves healthy work.

## 2. Rejected options and what they invite

- O1 **Build now as an established optimization:** reject. It has a plausible benefit, not a measured one. Harness-specific result interpretation and tests become maintained code. Synthetic count tests can prove arithmetic without proving better watcher decisions. Evidence: `INTAKE.md:31`, `:35`, `skills/watch-issues/scripts/log-tail.test.ts:168`, `:237`.
- O2 **Script verdict sufficient for intervention, agent checks only scope/hung tools:** reject. Three identical observations can be normal polling or deliberate reproduction, and undoing an edit can be a valid correction. Keep the existing “working normally, or waiting on a long command: no action” judgment (`skills/watch-issues/SKILL.md:42`). Otherwise deterministic counts invite deterministic false steers.
- O3 **Counts only, numerical thresholds remain agent-owned:** acceptable but weaker if we build. It leaves the trivial threshold comparison in prose despite code already having the data. Prefer code-owned mechanical matches plus contextual agent judgment. Do not maintain two independent threshold implementations. This refines the opening map's evidence-only position: the boundary is intervention authority, not whether code may evaluate `count >= 3`.
- O4 **Whole-log window:** reject for current scope. Resolved failures remain in later observations and can trigger a steer unrelated to current work. It also requires decisions about turn/reset boundaries. The last-20 window matches today's visible evidence (`log-tail.ts:484`, `:486`, `log-tail.test.ts:266`). This does not make file reading bounded: the script currently reads/parses the whole file (`log-tail.ts:432`, `:437`).

## 4. Pitfalls and what removes each

- R1 **“Same result” uses lossy or volatile data.** Define equality on observed result content and terminal status before display truncation, excluding only documented transport metadata. Do not compare whole envelopes with call IDs/timings, or collapse all exit-1 results together. A truncated captured result cannot prove equality of unseen output. Unsupported cases remain unclassified. Evidence: `log-tail.ts:365`, `:392`, `:421`, `log-tail.test.ts:172`.
- R2 **One wrapper counted as several errors, or unknown treated as success.** Define a counted entry and eligible terminal outcome. The existing window is outer entries, not every inner command. Mixed output needs an explicit disposition. Pending calls, expression-valued targets and unpaired results cannot silently disappear to manufacture three consecutive errors. Evidence: `log-tail.ts:286`, `:375`, `:379`, `:479`, `log-tail.test.ts:256`, `:306`, `:378`.
- R3 **Text swaps misidentified as file undo.** Require the same resolved target context, successful inverse edits and preserved multi-edit boundaries. Pi currently concatenates edit text, while Codex does not expose normalized edits here (`log-tail.ts:286`, `:317`). Report unsupported edit evidence rather than claiming parity. Decide whether parser expansion is actually in scope.
- R4 **Old evidence becomes a fresh stop.** Return entry references/timestamps and keep the current context and session check before acting. Retain one stop per seat and the next-fire notify rule. No persistent detector state is needed for the proposed bounded evidence scope (`skills/watch-issues/SKILL.md:42`).
- R5 **Passing fixtures mistaken for operational payoff.** If built, test matching and nonmatching cases across supported harnesses: changing output under identical exits, mixed/running results, unknown gaps, same text on different files and truncation boundaries. Validate the watcher-facing evidence, not an exact prose line. Existing test anchors: `log-tail.test.ts:142`, `:168`, `:188`, `:266`, `:341`, `:360`.
