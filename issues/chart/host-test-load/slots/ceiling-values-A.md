# Notes A: ceiling-values (before reading B/C)
Host: 32 threads, 123 GB RAM (free -g 2026-10-13). One run peaks 15.9 GB, load 40, 8.3 cores average (measurement 2, CPUWeight=20, MemoryHigh=48G, passed in 239 s, 0 throttled).
Pick: `akrogon.slice` as an installed user unit file (~/.config/systemd/user/akrogon.slice) with CPUWeight=20 and MemoryHigh=48G. Nothing else.
- CPUWeight=20 vs the default 100 for the desktop session: when both want CPU, akrogon gets about a sixth; when the desktop is idle, a run takes every free core and finishes as fast as now. Measurement 2 ran at this value at normal speed.
- MemoryHigh=48G: three times one run's peak, leaves about 75 GB for the desktop. Above it the kernel slows and reclaims the slice instead of killing. No MemoryMax: a hard cap kills test processes, which looks like the TasksMax crash class.
- Unit file: static, survives user-manager restarts, visible with `systemctl --user cat akrogon.slice`, and every leaf slice and pane scope named under it inherits placement. Written once by the akrogon install/link step that already reconciles skill links (docs/guide/install.md:36). Values are constants in that file, no config key.
Rejected: CPUQuota (caps a run even when the host is idle, slows every run for no gain); TasksMax (crash class, limit-boundary foreclosed); MemoryMax (kills instead of slowing); transient slice (lost on manager restart, needs create-if-missing code in every ensure).
Pitfalls: the leftover overlap accepted in permit-release can push the slice toward MemoryHigh; reclaim slows it, desktop unaffected. Seats themselves (claude, codex, pi processes) also sit under the slice, so a heavy run can slow seat UI; acceptable at weight 20. Values need one proof: a run inside the real slice passes at measurement-2 speed and `systemctl --user show akrogon.slice` shows them.
