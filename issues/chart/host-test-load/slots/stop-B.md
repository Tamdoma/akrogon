# Slot B: stop

Read-only blind notes, 2026-10-13. I read the named intake, chart and Taken decisions. I did not read other slots' stop notes or run a live stop, restart, browser or worker probe.

## 1. Pick, reason and cost

**D1: Keep pause dispatch-only. Add `akrogon stop <leaf>` to fence that leaf and stop its owned slice. Leave pi Esc unchanged.** Pause already has documented repo-wide scheduling semantics, including an explicit manual-next override. A leaf stop needs a stronger, leaf-specific fence that manual next cannot bypass.

**D2: Reuse `phase: failed` with `failure.cause: blocked`, an operator-stop reason and the interrupted phase recorded.** Persist it under the same global `.lock` used by dispatch before requesting termination. The existing failed gate prevents allocation through automatic hooks, startup resume, unpause and manual next. Resume uses the existing operator route, `akrogon phase <leaf> <active-phase>` followed by `akrogon next <leaf>`, without `--slot`. No stopped phase, suspension flag or new resume command is needed.

The stop command is operator-facing. It should not require pretending the operator is a completing A/B seat. Reuse the existing failure representation and transition bookkeeping, rather than blindly invoking the current phase CLI, which can require a slot or reject a slot already recorded done (`src/phase.ts:367-371`). Repeated stop on an already failed leaf retries termination without resetting its original failure record. A merged leaf remains terminal.

**D3: Stop the exact per-leaf slice from the taken containment identity, including every pane-generation scope still beneath it.** Derive identity from the registered repo plus leaf, not a globally ambiguous slug, current pane list or a saved seat PID. This reaches a detached browser even after its original pane has disappeared. Use the same user-manager connection selected for containment, with a synchronous stop job and read-back of the owned subtree. Its exact operation proof remains pending. Do not stop the shared `akrogon.slice` for a one-leaf request.

For bounded shutdown, propose a fixed five-second TERM grace on each pane scope, followed by systemd's SIGKILL escalation, with `KillMode=control-group` and `SendSIGKILL=yes`. The native transient-scope property is `TimeoutStopUSec=5000000`, supported by systemd v262. This adds no command flag or custom process walker. It is a proposal requiring the door's operation proof, not an observed result. Five seconds bounds the configured grace, not kernel completion for an uninterruptible task.

Keep dispatch/recovery serialized through the stop and read-back. Notifications must not precede or prevent termination after the fence is saved. Report success only when the owned subtree has no live processes, or its absence is positively established. On termination failure, leave the failed fence in place, report the actual error and permit the same stop to be retried. No automatic restart follows.

**Cost:** one command coordinating existing state and systemd ownership, plus stop proof and documentation of the operator action. Killing pane shells closes their panes. Recovery reprompts from artifacts under the Taken restore contract. Existing failed reconciliation can remove a clean worktree and dead scratch files, so this choice does not promise to preserve every temporary file. Dirty work remains subject to the existing removal refusal. Forced termination can interrupt writes. Holding the shared lock during shutdown briefly delays other dispatches.

## 2. Rejected options

- **O1: Make pause kill running slices.** This changes an established repo scheduling command into a destructive operation and still needs a separate leaf fence, because manual next explicitly bypasses pause. It also kills unrelated leaves when the operator needs to stop only one.
- **O2: Kill the slice and keep the leaf active.** Shell exit closes panes and emits Herdr events. `tab_closed` dispatches the owning leaf, and allocate can create replacement panes. Termination alone is not a redispatch fence.
- **O3: Pause the repo before killing one leaf.** It blocks automatic work for every leaf while manual next remains available. A saved failed state supplies the required narrower and stronger gate.
- **O4: Add a stopped phase or separate suspended flag now.** This duplicates existing failed-state admission and operator recovery. It becomes justified only if preserving the active visit or all temporary state is a requirement, rather than accepting existing failed cleanup.
- **O5: Change pi Esc to cancel every child.** The installed manager deliberately separates cancelling a wait from cancelling a worker. Changing that policy expands into pi-extensions and still cannot prove that detached browsers ended. The leaf cgroup stop works across harnesses.
- **O6: PID-tree, process-group, cwd or TMPDIR killing.** These are weaker ownership tests than the settled cgroup layout. They miss detached survivors or risk touching another leaf and the operator's own processes.
- **O7: Direct `cgroup.kill` as the ordinary stop path.** It supplies a useful kernel kill primitive, but bypasses the manager's normal unit-stop lifecycle and grace period. The already selected systemd ownership can terminate its member scopes without adding a second lifecycle path.

## 4. Pitfalls and what removes each

- **R1: A dying seat triggers replacement.** Save failed before any termination, using dispatch's common lock. Keep recovery serialized until stop read-back completes. Prove tab-close hooks, startup resume, unpause and manual next launch no replacement.
- **R2: The pane is gone but its browsers remain.** Target the stable owned leaf slice, including old generation scopes, instead of resolving only current A/B panes. Prove a setsid survivor and a survivor whose original shell has exited are removed, while another leaf remains running.
- **R3: Termination fails after the fence succeeds.** Keep failed state, retain ownership identity for retry and report the error. Prove retry on an already failed leaf and positive absence handling. No success-shaped handling of permission, bus or identity errors.
- **R4: A notification error prevents the stop.** Perform fencing and termination before optional notification work. `commitMove` can throw after saving state, so a wrapper that simply awaits the existing phase command and then kills is insufficient.
- **R5: The operator expects a suspended conversation and preserved scratch.** State the failed-cleanup and artifact-reprompt costs in the round. If those costs are rejected, reopen the state choice explicitly rather than hiding a new preservation flag inside implementation.
- **R6: The controller kills itself before reporting completion.** The verified operator path runs outside the target leaf slice. Calling stop from inside that slice can terminate the calling process too. Do not introduce a supervisor merely to support self-stop.
- **R7: A missing unit or an inactive slice is treated as proof of no workload.** Read the owned hierarchy and verify emptiness or actual absence. A stopped scope can be failed after escalation even when empty. Judge the live processes, not just a unit-state label.

Required proof before handoff: a disposable boxed leaf with both seats, a nested worker, a detached TERM-resistant sleeper and a waiting permit caller. Stop must fence first, terminate the complete subtree, release its permit, leave another leaf untouched and refuse redispatch through every listed entry path. Repeat stop, inject a manager failure, then recover explicitly and verify newly boxed panes. No such proof was run in this read-only slot.

## 5. Missing questions

- **Q2: Must stop preserve all worktree and scratch state, or is existing failed cleanup acceptable?** My pick accepts the latter. This changes the simplest viable state design.
- **Q3: What stop latency is acceptable while another next/phase process holds `.lock`?** Dispatch holds that lock across awaited allocation and delivery (`src/next.ts:1522-1537`). A five-second scope grace does not bound lock acquisition. Measure the contended operator path before promising an emergency response time.
- **Q4: Does the stop promise include dispatcher-owned merge preparation or standalone holder commands outside the leaf box?** `mergeTurn` runs in next (`src/next.ts:1041-1061`), and permit-release already excludes standalone holder leftovers from boxed cleanup. Killing the leaf's seats cannot undo a push or kill an unrelated external caller. Keep batch records for existing reconciliation and resolve this promise before calling stop universal.
- **Q5: What is promised during the accepted cold-restore window?** Restore Taken allows leaf seats outside their box until the startup pass replaces them. The disposable restart proof is still pending. An old slice stop cannot certify termination of processes launched outside it. This limitation must remain explicit rather than silently changing the taken restore policy.
