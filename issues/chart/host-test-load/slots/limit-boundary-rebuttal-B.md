Adopting at agent-ready can miss children started during harness initialization, even before the first prompt. Kernel cgroup migration does not move existing descendants. C's route needs proof that none can exist before adoption, or a complete transition that contains them. Keep this unresolved rather than saying the pending probe works “either way.” Source: [kernel cgroup v2](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html).

Establish a conservative measurement boundary first, then measure the isolated run and tune the final budget. Otherwise the proposed measurement can repeat the overload it is meant to prevent.
