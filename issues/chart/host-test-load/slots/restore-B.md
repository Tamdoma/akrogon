## 1. Pick and cost

**Exclude akrogon leaf tabs from cold session restoration, then let the existing akrogon startup dispatch recreate them through allocate.** Exclude the whole leaf tab before Herdr creates any shell or agent-resume plan, not just its saved harness command. Fresh allocation supplies the locked bus-cut environment, creates both panes, adopts their shells and only then starts the required seats. This keeps one owner of leaf restart and one containment entry point.

Use an explicit per-tab restore opt-out selected when akrogon creates the leaf tab. It must be stored by Herdr and checked before restoring that tab's runtimes. This is a **proposed capability**, not an existing flag in the inspected 0.9.1 surface. A small Herdr prerequisite is required, followed by akrogon's tab-create integration. Do not couple Herdr to akrogon's issue files or identify tabs merely by an agent-name prefix, cwd or display label.

**Prefer cold-restore exclusion over a new containment-aware Herdr launch path.** The latter duplicates shell adoption, environment construction and lifecycle ownership in a second launcher. A tab opt-out leaves those responsibilities in the allocate path the operator already selected.

The startup contract must include missing repo workspaces. Herdr currently drops workspaces with no restored tabs, while allocate requires an existing workspace labelled with the registered repo name. If excluding leaf tabs removes a repo's last tab, `--resume` must recreate the needed repo workspace through the existing workspace-create operation before normal allocation. This is scoped restoration of the candidates already selected by `--resume`, not a new background scheduler or permission to open every undispatched leaf. Existing workspaces are reused after identity checks.

Cost: a persisted Herdr tab policy and restore filter, akrogon tab-create adoption, and the missing-workspace case in startup recovery. After cold restore, the leaf continues from its saved phase, worktree and pass artifacts. Current normal dispatch starts a harness from configuration; it does not automatically reconstruct the previous native conversation. That context restart is an explicit cost, not deletion of saved harness files or work. Adding automatic native-session continuation would be another requirement and is not necessary for containment.

Distinguish cold restart/reboot from Herdr's live runtime handoff. A successfully imported existing shell may already retain its scope and environment. It needs identity/membership validation, not a fresh launch followed by adoption. Do not apply a cold-restore exclusion by blindly stripping live handoff runtimes. If a handoff cannot preserve the owned runtime, treat that leaf as cold-recovery work and start it through guarded allocation.

## 2. Rejected options and reasons

- **Adopt the restored seat/tree after Herdr starts it:** violates the taken pre-start boundary. Initialization children can already exist, the fresh shell does not inherit the old pane's launch environment, and a one-time descendant snapshot cannot guarantee all work is caught. This revives the live-migration option already foreclosed in seat-scope.
- **Disable only native harness resume for leaf panes but restore their shells normally:** incomplete. The snapshot does not store the original placement environment. Reusing those restored shells through allocate would not install the bus cut. It needs another replace/update path, so it buys little over excluding and recreating the tab.
- **Close restored tabs from akrogon's startup hook:** too late as an enforcement boundary. Herdr can create a pending resume and issue its command independently of that hook. Closing afterward cannot make the earlier interval contained.
- **Globally set resume_agents_on_restore=false:** affects unrelated agent panes and still restores shell runtimes without the original leaf launch environment. It is not a scoped answer and still requires extra akrogon recovery handling.
- **Persist cgroup names and reuse them after reboot:** a saved unit name is not ownership of the new shell PID. The taken seat-scope identity follows each actual shell generation and must be re-established.
- **Make Herdr reproduce akrogon's containment before every restored harness launch:** technically possible as a separate design, but adds a second implementation of the established admission/ownership boundary, control credentials and failure handling. It costs more than an explicit restore exclusion unless native conversation restoration is a required outcome.

## 4. Pitfalls and what removes each

1. **R1 — Filtering happens after a seat has launched.** Persist the tab's explicit policy and check it before creating any runtime or pending resume plan. Startup hooks may initiate recovery afterward, but must not be the mechanism that prevents the initial uncontained launch.
2. **R2 — Whole-tab exclusion removes the repo workspace too.** Add the scoped workspace-recreation step before dispatching restore candidates. Prove a repo workspace whose only tabs were leaves, as well as a mixed workspace with ordinary user tabs. Do not require another manual setup step on every reboot.
3. **R3 — Old UI IDs attach a leaf to an unrelated restored tab.** Verify repo/worktree/leaf ownership when matching current topology, not just a saved numeric tab ID. Current matches accept a tab-id equality without that extra association check (`src/next.ts:434-438`). Recreate missing leaf topology and record fresh pane IDs only after successful allocation/adoption. Do not clear unrelated panes or worktrees.
4. **R4 — Restart launches paused, failed or never-allocated leaves.** Keep startup's existing candidate selection and lifecycle eligibility. A skipped paused leaf is safe because its excluded tab launches no seat. Normal manual unpause/dispatch later follows the boxed path.
5. **R5 — The new policy is inferred from incidental names or cwd.** Set it explicitly when akrogon creates its tab and persist it as Herdr-owned tab metadata. The one manual rollout close already chosen means replacement tabs can receive the policy from creation; no scan-and-rewrite migration is needed for old tabs.
6. **R6 — Saved conversation context is mistaken for saved work.** Preserve the leaf phase, branch, working files and artifacts. Report the fresh-harness context cost. Do not add a native-session replay feature unless the operator explicitly requires it.
7. **R7 — Cold exclusion breaks live handoff.** Test the distinction between imported owned runtime and fresh restored runtime. Existing imported PID/scope/environment can be validated, while fresh leaf runtimes must be recreated through allocate. No after-the-fact migration path is introduced.
8. **R8 — Startup hook failure silently falls back to Herdr launch.** Excluded tabs remain excluded when akrogon recovery fails. Record the failure and allow a later normal next invocation to retry from existing records. Do not reopen unsafe native restore as recovery.

Required proof before handoff: a marked leaf tab performs no shell/harness launch on cold restore; an ordinary tab retains its existing restore behavior; a leaf-only repo workspace recovers; paused leaves stay unstarted; failed startup leaves no unsafe seat; fresh A/B shells receive the bus cut and adoption before any harness command; and live handoff preserves or safely declines an owned runtime. Use an isolated disposable session/snapshot and the actual selected APIs. No live restore was performed in this pass.
