# Blind notes, slot C: restore

Question: exclude akrogon leaf panes from herdr resume and let akrogon redispatch, or adopt the restored tree. Read 2026-10-13.

## 1. Pick: exclude in effect, by akrogon recreating restored panes before any prompt

Do not adopt restored trees, and do not turn herdr resume off globally. Instead, akrogon's already-taken generation check (seat-scope Taken: scope named from pane id plus shell PID and start time, read-only PID/start-time/cgroup check before agent start) gains one outcome: a recorded pane whose shell is certainly a restored one gets closed by akrogon, the pass ends, and the next pass recreates the pane through the normal allocate path, with placement env and adoption as usual. Herdr may resume whatever it likes; no resumed leaf seat is ever prompted, and no other herdr agent on the host loses resume.

Why this shape:

- A restored shell cannot be fixed in place. Resume spawns the shell with an empty extra env, identity only (`herdr/src/app/agent_resume.rs:230-235` passing `Vec::new()` into `pane_launch_env`, `herdr/src/app/ids.rs:40-56`), on top of the herdr server's own environment (`herdr/src/pane.rs:112-116` applies only the extra pairs). The original placement env, `TMPDIR`, `AKROGON_BASE`, and the bus cut, is not stored per pane and is not reapplied; restore does the same for non-resumed panes (`herdr/src/persist/restore.rs:518-526`). Moving that shell into the leaf cgroup afterwards changes its cgroup, never its environment, so its Chrome still self-scopes out. Any option that reuses restored shells, resume on or off, breaks the bus-cut half of the taken lock. Recreation is therefore required in every branch; the only question is who triggers it.
- The detection is already paid for. A boxed shell has cgroup in its pane scope, the bus cut in its environment, and the PID and start time the scope was named from. A cold-restored shell has a new PID, a cgroup under the herdr server's tree, and no cut in `/proc/<shell_pid>/environ`. Require both signals wrong (foreign cgroup and missing cut) before closing anything, so a transient read failure fails closed as a skipped pass, never as a killed healthy seat. The ensure step in `allocate` is the single place this runs, because `allocate` completes before dispatch prompts or starts anything in that pane.
- Returning "skip this pass" after closing the bad pane reuses machinery instead of adding a recreation path. Next pass, the member scan finds the recorded pane missing and the existing repair splits create a fresh pane from placement (`src/next.ts:485-490` for A, `src/next.ts:522-524` for B), adopted in the same pass. If both panes are restored, both close, the tab empties, and the next pass takes the new-tab path. `herdr tab close` already exists in the codebase for merged leaves (`src/reconcile.ts:119`); pane close is the same class of call. No state field, no generation ledger, no new verb.
- Handed-off (imported) terminals are untouched. When a herdr restart imports live runtimes, no resume plan is created (`herdr/src/persist/restore.rs:529-535`), the shell PID, start time, cgroup, and env are all unchanged because the process never died, and the systemd user scopes are independent of herdr. The check passes and the seat keeps working. Only the cold path (reboot, cold server restart) recreates.

Cost: seat conversation context is lost on every cold herdr restart or reboot, for every open leaf. This is smaller than it sounds: the restarted server already killed the mid-turn work, herdr's own resume would have relaunched the seat with a bare argv (below), and an akrogon pass is designed to resume from leaf artifacts when reprompted. There is also an unavoidable window between herdr restore and the first akrogon pass where a resumed seat sits live, unboxed, with the bus reachable. It does no test work in that window because nothing has prompted it (resume loads the session and idles; the in-process workers of the dead seat do not come back), but an operator who manually prompts it in that window is outside every barrier. That residual is named, not solved.

## 2. Rejected options

- Adopt the restored tree after the fact: rejected three times over. The env is unfixable, above. Live migration is foreclosed by name in the seat-scope Taken. And the resumed seat is not the seat akrogon configured: herdr's resume argv is bare `pi --session <path>` and `codex resume <id>` (`herdr/src/agent_resume.rs:129-131,145-147`), typed into the fresh shell as text (`herdr/src/app/agent_resume.rs:219,264-281`), dropping akrogon's model, effort, and flags (`config.yaml:13-14`: codex `-a never -s danger-full-access`, pi `-a --exclude-tools request_user_input`). Adopting would silently run passes under whichever defaults those tools resume with.
- Exclude via herdr config (`[session] resume_agents_on_restore = false`): rejected as the mechanism. It is the only switch herdr 0.9.1 has and it is global, default true, gating plan creation for every agent (`herdr/src/config/model.rs:243-255`, `herdr/src/persist/restore.rs:783-789`); there is no per-pane exclusion. Turning it off costs the operator resume for their own non-akrogon agents, and it still does not remove the need to recreate panes, because a restored plain shell lacks the placement env just the same. It remains a legitimate operator preference for shrinking the unboxed window to zero, but akrogon must behave correctly whether it is set or not, so it cannot be the load-bearing part.
- Manual tab close after every restart, as at rollout: rejected because rollout was once and restarts recur. Every reboot or herdr update would leave every open leaf's resumed seats live and hand-promptable until the operator remembers, with leaf passes meanwhile either stuck at a barrier that never explains itself or, worse, dispatched because the barrier was never wired to anything. The automatic close reuses the check the seat-scope fork already bought; the manual version saves roughly one branch of code and rents operator attention forever.
- Suppress session reporting so herdr never learns a leaf seat's session ref: rejected as not buildable in akrogon today. Plans are created from official integration reports (`herdr/src/agent_resume.rs:55-73,205-224`), and 0.9.1 exposes no per-pane opt-out on that path either. That would be a herdr change in another repo, and this fork should not wait on it.
- Do nothing: rejected by the taken locks directly. A resumed seat outside the cgroup with a live bus is the incident configuration, reachable again by rebooting the machine.

## 4. Pitfalls, and what removes each

- False positive closes a healthy working seat: shell `exec`s a new shell (same PID and start time, passes), systemd hiccups, `/proc` read races. Removed by the both-signals rule above and by treating any uncertain read as skip-this-pass, never as close. A close happens only on positive evidence of a restored shell.
- The close triggers hook passes while herdr is still restoring other panes, and allocate recreates panes against a moving target. Removed by fail-closed ordering: the ensure step already skips the leaf on any error, and a half-restored herdr produces errors or missing panes, both of which are existing skip and repair paths, retried next pass.
- Closing one restored pane while its sibling was imported alive (mixed handoff and cold in one tab). Rare to nonexistent, but closing only the bad pane and letting the repair split replace it preserves the live seat; closing the whole tab would not. Per-pane close is binding in the pick for this reason.
- A resumed seat is mid-session with an undelivered akrogon prompt recorded against its session file. Killing it and starting fresh could double-deliver or lose a prompt. Removed by existing delivery bookkeeping: resettle only applies when the live session matches the recorded one, and a fresh seat gets a fresh session, so the pass is simply reprompted from artifacts.
- Public pane IDs stop being preserved in some herdr version, so restored resumed panes appear as unrecorded extra panes in the tab and the barrier never sees them. Not removed by this fork; it is the hand-split-pane fog already in the chart. The door's restart proof must show IDs preserved on the installed herdr before handoff.
- Paused repos: automatic passes do not run, so restored panes of a paused repo sit untouched until unpause or a manual `akrogon next`. Acceptable and consistent: nothing prompts them either. Named so nobody expects cleanup while paused.

## 5. Missing questions

- How often does the installed herdr take the live handoff path versus cold restore (update restart, crash, reboot)? If cold restore is rare and handoff is the norm, the recreation cost is near zero; if every `herdr` update is cold, every open leaf loses its seats each update, and the operator may want that stated as a known cost of updating.
- Does an unrecorded pane in a leaf tab (hand-split, or a restore product if ID preservation ever breaks) get the same treatment, and who is allowed to close a pane akrogon does not own? Already chart fog; restore makes it concrete.
- Should akrogon record why a pane was closed (which signal fired) anywhere the operator will actually look after a reboot, so a tab full of fresh seats does not read as data loss?
