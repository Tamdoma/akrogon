# Rebuttal, slot C: restore
- Misquote: none. No agreed line misstated as mine.
- Agreed line I reject: none as written. My changes below are to my own positions in Disagreements 2-3, read against the other side and the low-complexity instruction.
- D1 final: stay with A,C, close and recreate in `allocate`. B's herdr prerequisite is the most complex option on the table: a persisted per-tab opt-out in another repo, plus akrogon learning to recreate a repo workspace herdr may drop when it has no tabs (`herdr/src/persist/restore.rs:401-403`; akrogon currently only errors on a missing workspace, `src/next.ts:450-452`). "Closing after launch is too late" overstates the risk on B's own evidence: `--resume` already runs at plugin startup (`src/next.ts:1552-1568`), so the first akrogon pass after a restart is the barrier pass, and a resumed seat does no akrogon work before it.
- D2 final: stay with C, leave the global toggle to the operator. Requiring `resume_agents_on_restore = false` makes akrogon's correctness depend on a herdr config line it cannot see or enforce, and costs the operator resume for every non-akrogon agent. If the door's restart proof shows a resumed seat executing anything before a prompt, I flip to A as an interim measure; that is a proof result, not a default.
- D3 final: switch to A, single signal, keeping only my uncertain-read guard. My environ check has a hole (a herdr server started with the bus cut already in its environment produces a restored shell that passes the env half while sitting in a foreign cgroup with the wrong TMPDIR, and then skips forever instead of recreating) and buys nothing, since a recorded pre-existing pane shell outside its scope has no legitimate state: its scope being stopped would have killed the shell with it. Positive foreign cgroup means close; a failed or unreadable check means skip this pass, never close. One signal, no environ parsing, fewer parts.
