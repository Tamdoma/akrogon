# Notes A: restore (before reading B/C)
Fact: every herdr-made replacement shell drops akrogon's placement env. Resume spawns with `pane_launch_env(ws_idx, pane_id, Vec::new())` (herdr/src/app/agent_resume.rs:230), respawn the same (herdr/src/app/api.rs:538). So a restored pane has no bus cut and no box, and boxing it afterwards cannot fix its env (seat-scope finding). Resume is on by default, global setting `session.resume_agents_on_restore` (herdr/src/config/model.rs:247-256), no per-pane switch. Checked herdr 0.9.1 source 2026-10-13.
Pick: akrogon only dispatches into a shell it boxed itself. The allocate ensure step treats a recorded pane whose current shell is not in its own akrogon scope (pane id plus shell PID and start time) as lost: it closes that pane and creates a fresh one through placement, which boxes it. No adoption of foreign shells ever. Plus the operator sets `resume_agents_on_restore = false` in herdr config, so no seat starts unboxed between restore and the next akrogon pass.
Cost: one extra branch in the ensure step (close and recreate instead of box). Operator's own non-akrogon agent panes also stop auto-resuming after a herdr restart. A restored akrogon seat loses its live process but its saved session and worktree remain, and dispatch restarts it.
Rejected: box restored trees after the fact (env stays wrong, Chrome escapes); herdr patch for per-pane opt-out or persisted env (second repo, more parts); rule only with resume on (resumed agents run unboxed until some akrogon pass runs, and nothing guarantees one runs soon).
Pitfalls: closing a pane the operator is typing in (only leaf panes recorded in state.pane are touched); herdr respawn flag paths (same rule covers them, any shell akrogon did not box is lost).
