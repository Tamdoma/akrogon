## Decisions

- D1: `repoSchema` gains `setup: text.optional()` (non-empty string). No change to `init`, `writeRepoConfig` or storage: the raw key round-trips through `repoSchema.parse`.
- D2: In `effectiveConfig`, when `repoConfig.setup` is set, every value of `checks`, `merge_checks` and `advisory` prints as the literal
  `flock "$(git rev-parse --git-path akrogon-install.lock)" sh -c <quote(setup)> && sh -c <quote(command)>`
  with `quote` applied to each whole string. When `setup` is absent, the values print unchanged. Composition lives only in `effectiveConfig`; every runner reads the lists from `akrogon config`.
- D3: The lock path resolves per invocation via `git rev-parse --git-path` in the caller's cwd, so a leaf worktree gets `<common>/.git/worktrees/<name>/akrogon-install.lock` — per-worktree, under the git dir, never in `git status`, removed with the worktree.
- D4: Both `sh -c` wrappers are required: the first keeps all of `setup` inside the lock (criterion 6), the second keeps `a || b` checks behind `&&` (criterion 5).
- D5: Tests run real `bun install` and `flock` at the `akrogon config` CLI boundary against a fixture git repo with a linked worktree. The fixture is offline: dependencies are `file:` packages under `vendor/`, and the worktree's `bun.lock` is generated by `bun install` during test setup (not committed into the git history — the lockfile must exist on disk but only committed files travel to a fresh worktree; see U1 note).
- D6: Deliberate break for the new-behavior rule: remove the `sh -c` grouping around the check → criterion-5 test goes red. (Alternative accepted: remove `flock` → criterion-4 red.)
- D7: Both skills gain the direct-proof rule: when `akrogon config` prints `setup`, a dependency-using proof outside the printed commands runs `flock "$(git rev-parse --git-path akrogon-install.lock)" sh -c <quoted setup>` first; this covers criterion proofs and the detached base-checkout run (the phrase "installing dependencies there with the leaf's installation method" gains the locked-setup form).
- D8: `init-akrogon` proposes `setup` only when a committed lockfile exists in the repo (`git ls-files` names `bun.lock`, `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`), proposing the matching frozen/immutable install command (`bun.lock` → `bun install --frozen-lockfile`). No committed lockfile → no `setup` key.
- D9: `docs/guide/setup.md` gains a `setup` bullet in the repo-config list plus a short paragraph: it runs before every printed check under a per-worktree lock kept under the git dir, and the init-akrogon proposal rule.
- D10: `tests/config.test.ts` is an existing test file; every commit touching it carries the `Test-Change:` trailer per `src/test-files.ts`.
