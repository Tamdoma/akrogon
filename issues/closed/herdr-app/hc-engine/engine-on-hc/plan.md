## Live surface checked at planning (throwaway core `akr-plan-eoh`, clean env, `cat` and `sh` only)

- L1 `hc ls --json` (CLI) returns `address, agent, cwd, name, state, turn` only: no `labels`, no `status`. `hc connect` `terminal.list` (`{"labels":{...}}` filter) and `hc get --json` return the full `Terminal` (labels, status, pid, foreground, parent, turn). `hc connect` reads JSON-RPC lines from stdin and exits 0 at EOF; no `hello` needed.
- L2 Any `hc` call (`ls`, `connect`) for a session whose socket is missing or stale starts a new core (seen: `nosuch.sock` created; a `kill -9`'d core restarted by `hc connect`). Cleaned up and checked.
- L3 Errors print `{"error":{"kind","message","hint"}}` on stderr with a non-zero exit (`blocked` exit 9, `name_taken` exit 1, `live` on `rm` of a running terminal).
- L4 Names are unique only among live terminals: after `hc kill`, a new terminal took the same name, and `hc rm <name>` then targeted the live one. Finished terminals keep their name in `hc ls --all` until `hc rm <address>`.
- L5 OSC 7501 payload is `key=value` pairs joined by `:` (`\e]7501;state=blocked:kind=permission:msg=...\a` gave `{"state":"blocked","kind":"permission"}`); a bare `working` is ignored.
- L6 A terminal's environment is the core's, not the `hc` client's (client `XDG_RUNTIME_DIR` differed, terminal saw the core's). A core started with a scratch `XDG_RUNTIME_DIR` breaks `systemd-run --user` inside its terminals ("Failed to connect to user scope bus"); `HC_RUNTIME_DIR` does not move the socket. An `hc` client reaches a core through a symlinked socket under its own `XDG_RUNTIME_DIR/herdr-core/`.
- L7 `hc send` to a program with no status returns `{"started":null,"status":null,"turn":0}`.
- L9 A core started from a test detaches from the test process (its parent becomes the user manager), so the suite's subreaper sweep never reaches it; red runs leaked cores until the fixture stopped every core in `afterAll` and swept cores of dead workers (`akt<pid36>-*` sockets) at its first use. Leaked cores found during planning were stopped and their sockets removed (checked).
- L10 Under the suite preload, `HOME` is a scratch folder and Bun's `os.userInfo().homedir` follows `HOME`; hc still writes state under the account's real home. The attended tiers read the real home from `getent passwd`.
- L8 Operator session `infra` document (read only, `doc.get`): spaces carry explicit names equal to the repo names (`akrogon`, `framework`, `pi-extensions`, ...); tab ids `tb<32 hex>`.
- Cleanup: every probe terminal killed, `akr-plan-eoh`, `fx1`, `fx2`, `akt-sym1`, `nosuch` cores stopped, their state and temp folders removed; checked no socket left.

## Decisions

- D1 Module: `src/hc.ts` holds the closed command list and nothing else exports hc: session discovery, liveness probe, `doc.get`, terminal list/get, run, send, keys, label, kill, rm, events, app home, `herdr-app ls`, `herdr-app do tab.rename`, `herdr-app do tab.close`. Every hc call sets `HC_SESSION=<session>` and removes `HC_TERMINAL_SOCKET`, `HC_TERMINAL_ID`, `HC_SCOPE`; every herdr-app call sets `HERDR_APP_HOME=<app home>`. Replies are parsed once with zod at this boundary (`terminalSchema`, `sendSchema`, `docSchema`, `hcErrorSchema`); stderr is parsed behind a guard and the raw text kept (LESSONS stderr line).
- D2 Session discovery: sessions are the `<name>.sock` entries without a dot under `${XDG_RUNTIME_DIR}/herdr-core/`. Before any hc call to a session, `hc.ts` connects to the socket from Bun (`net.connect`) and closes; `ENOENT`/`ECONNREFUSED` counts as stopped and the session is skipped, so akrogon never starts a core (L2). The repo's space is the space whose `name` equals the repo name in the session's `herdr-app` document (L8). None, several or unreadable sessions refuse with today's verdict strings (`no running session holds it`, `held by multiple sessions`, `uniqueness unknown`) and the same JSON reason fields (`searched`, `skipped_stopped`, `unreadable`, `duplicates`), memoized per process as today.
- D3 Listing terminals: `terminal.list` through one `hc connect` call per session, filtered by `{"akrogon":"1"}` server side (L1); `hc get --json <address>` for one terminal. The design's `hc ls --json` is replaced by this call because the CLI listing has no labels or status (Notes N2).
- D4 Labels: constant filter label `akrogon=1`; plus `akrogon.repo`, `akrogon.leaf` (leaf seats only), `akrogon.seat` (`a`/`b` for leaf seats, the slot letter for consultants), `herdr.space`, `herdr.tab`, and `akrogon.transcript` once resolved. Ownership check at the boundary: a seat terminal belongs to a leaf only when its labels match repo, leaf and seat and its address equals the one recorded in state; an event or report from another address is ignored.
- D5 Seat names: `<prefix>-<slug>-<a|b>`; above 32 characters `<prefix>-<head>-<4 hex of sha256(repo/slug)>-<a|b>` with the head cut to 22 characters and a trailing `-` dropped. Consultants `<prefix>-slot-<letter>`. hc calls address terminals by address, never by name (L4).
- D6 Tab id: minted deterministically per leaf as `ak` + 30 hex of sha256(`<repo>/<slug>`), stored in `state.tab`. A tab id holding `:` is an old herdr id (legacy marker, D17).
- D7 Prefix: `prefixes:` stays optional in the schema (deploy-listener-ready); dispatch and the start verb refuse a repo without a prefix or with a value another repo also holds, naming `prefixes`; `akrogon init` refuses when the map holds a duplicate value, naming both repos and `prefixes`. No new init flag (the operator fills the map, needs N1).
- D8 Start function `startSeat` in `src/seat.ts`, CLI verb `akrogon seat`:
  - Leaf seat: `akrogon seat <slug> <A|B> [--task <text>]` runs the same allocation as dispatch (worktree, `.env`, tab id) and starts that seat with the leaf's current phase task (the same prompt `next` builds), or with `--task` when given (the kinds tier uses it so a real harness gets a one-line instruction instead of a skill run); the engine calls the same function from dispatch.
  - Consultant or direct reviewer: `akrogon seat --slot <letter> --harness <name> --model <model> --effort <effort> [--task <text>]`, refused without `HC_TERMINAL_ID`.
  - It reads `HC_TERMINAL_ID` before stripping hc variables. Leaf seats: `--no-parent`, `systemd-run --user --scope ... --slice=<leaf slice> -- env -u <ten> AKROGON_BASE=... GIT_EDITOR=true TMPDIR=<leaf temp> NODE_DISABLE_COMPILE_CACHE=1 <harness argv> [<task>]` exactly as the design's literal interface, unit `<leaf slice base>-<seat name>-<8 hex random>.scope`. Consultants: `--parent <caller>`, labels `herdr.space` and `herdr.tab` of the caller's tab read from `doc.get` (only `herdr.space` when the caller sits in no tab), argv `env -u <ten> <harness argv> [<task>]`, cwd the caller's cwd.
  - pi gets a fresh `--session-id <uuid>` appended to its harness argv (session-id Q2).
  - Prints the address; on failure exits non-zero with the address.
- D9 Start proof (delivery Q1/Q1c): after `hc run` returns, follow `hc events --terminal <t> --json` (snapshot first) for up to 60 s: `working` or `turn >= 1` records `prompted: {turn, address}`; `finished` or status `error` fails the start (non-zero, address, screen); no proof by 60 s keeps the seat running, prints `started, not confirmed <address>` with the screen (`hc read`), and records `delivery_error.<seat> = {code: not_confirmed, address, turn, screen, at}` so no later pass resends while the turn is unchanged. After the proof, one read of `/proc/<pid>/cgroup` confirms the leaf scope (leaf seats).
- D10 agy start (config 2b and final check): kind `agy` gets no task in argv; start waits on events for `idle` turn 0 or the trust dialog (`blocked`, `kind: permission`, `msg: Trust this folder?`), presses `hc keys <t> enter` exactly once on the dialog, waits for `idle`, then one `hc send --json <t> <task>`; a reply `kind: unavailable` is sent again on the seat's next status event while the 60 s budget lasts; then the D9 proof.
- D11 Placement (start-and-pane Q2/N2): window state from `herdr-app ls` (stderr containing `no Herdr window` means closed; any other failure is an error). Open: wait (events, `doc` changes, bound 15 s, the "pane wait") until the document shows the terminal in tab `state.tab`; timeout kills the started terminal (`hc kill` then `hc rm`) and exits non-zero with the address; then `herdr-app do tab.rename --id <tab> --name <expected>`. Closed: return after the start proof with labels set. A failed rename warns and leaves the seat running. Expected name: `<slug> failed` for a failed leaf, the slug otherwise. Every engine pass that finds the window open renames each recorded leaf tab of the repo whose document name differs.
- D12 App home: `default` maps to `~/.config/herdr-app`, any other session to `~/.config/herdr-app-sessions/<session>`; a missing folder is an error naming the path; the caller's `HERDR_APP_HOME` is never read.
- D13 Delivery (delivery Q2/Q3, criterion 4/5): state per seat `seat.<A|B> = {session, address}`, `prompted.<A|B> = {turn, address}`, `prompts.<A|B>` (engine prompts this phase, reset by `commitMove`), `delivery_error.<A|B>` (new shape, D17). A pass on a live seat:
  1. status `working`, `blocked`, `error` or null: hands off (busy observation only).
  2. `idle`/`done` with `delivery_error` whose turn equals the seat's turn: nothing (watcher inspects first).
  3. `idle`/`done` with `delivery_error` whose turn is below the seat's turn: resettle as delivered (`prompted = {turn: error turn, address}`, error cleared), then continue to 4.
  4. `prompted` absent: send the phase task (`hc send --json`); `started: true` records `prompted = {turn: reply turn, address}`, `prompts += 1`; `started: false` records `delivery_error = {code: not_started, turn, status, screen, address, at}`.
  5. `prompted.turn` equals the seat's turn: nothing (that idle turn was already prompted).
  6. seat turn above `prompted.turn` and status not `done` after a phase that did not move: silent stop; when `prompts` is already 3 the leaf moves to `failed` with cause `attempts` and reason `seat <x> ended <n> turns without reporting` (n = prompts); otherwise re-prompt as 4.
  A dead or finished seat terminal is removed (`hc rm <address>`) and started again by D8 under its old name.
- D14 Phase runs next (engine-shape 3b): after `phase` commits, `akrogon.ts` runs `mergeWake` as today, then one automatic dispatch of its own leaf (`dispatchLeaf` picked=false, automatic=true, dependents when completed). The calling seat is `working`, so step 1 of D13 refuses it; the turn-end event prompts. A mid-turn or double prompt seen in tests is reported for the 3a swap.
- D15 Listener `akrogon listen` (`src/listen.ts`), unit `systemd/akrogon-listener.service` (`ExecStart=%h/.local/bin/akrogon listen`, `Restart=on-failure`, no `HC_SESSION`). It subscribes `hc events --json --label akrogon=1` per live session (one child per session, `HC_SESSION` pinned), and watches `${XDG_RUNTIME_DIR}/herdr-core/` with `fs.watch` for new sockets (no polling). Only after every subscription's snapshot line arrived does it run `akrogon pull --all` then `akrogon next --resume`. Wakes: a `turn` event, a `status` event with state `blocked`, or `finished`/`lost` of a terminal from the subscription → one `akrogon next --wake` pass; one pass at a time, wakes during a pass fold into one following pass. A stream end re-probes and re-subscribes that session when live, then runs `akrogon next --resume` (catch-up). `next --wake` is `--resume` without self-update: the automatic sweep of every unpaused repo's seated and merged leaves, reconcile and merge passes.
- D16 Watcher wakes (watcher Q1): `wakeWatcher(repo, reason)` in `src/hc.ts` callers: the listener (seat `finished`/`lost`, a `restarted` keep shell, seat `blocked`), `commitMove` to `failed`, and `observeBusy` at the 60-minute deadline. It lists live terminals labelled `akrogon.watch=<repo>` in the repo's session whose status is not null; none: nothing; two or more: one stderr JSON line naming them and nothing sent; one: under `<globalHome>/watch-<repo>.lock`, sends `/watch-issues tick <repo root>` by plain `hc send --json` only when that terminal's status is `idle` or `done` (a working watcher already has one in flight).
- D17 State: `stateSchema` gains `seat`, `prompts`, the new `prompted` object and the new `delivery_error` shape; the old `pane`, string `prompted`, `prompted_at` and old `delivery_error` shape stay accepted. A merged, done or closed leaf with legacy fields reads and completes, and no hc or herdr-app call is made with its old ids; any other leaf with legacy fields is refused at dispatch with `state predates hc: <slug> records old herdr pane ids`.
- D18 Transcript resolver `src/transcript.ts`, exported as `transcriptFor({session, address}): Promise<string | null>` (resolves, saves the label, returns the path; the kinds tier calls it directly) (`session-file.ts` deleted; its pi lookup moves here, `deliveredAfter` deleted): pid first, foreground pid only when pid holds none. claude: fd target `…/claude-<uid>/<mangled>/<id>/tasks` → `${CLAUDE_CONFIG_DIR of the process, else ~/.claude}/projects/<mangled>/<id>.jsonl`; codex: newest open `rollout-*.jsonl`; pi: argv `--session-id` → the single `*_<id>.jsonl` under `~/.pi/agent/sessions`; agy: the open `conversation_summaries.db`. - D19 Teardown: a seat restart, `akrogon stop` and a merged leaf's close end each seat terminal with `hc kill <address>` then `hc rm <address>`. Merged close then requests `herdr-app do tab.close --id <tab>` when the window is open and skips it when closed. `stop` also stops the leaf slice as today.
