# Brief: plan-is-contract-skills

## What
Prose only. Seven files change: `skills/implement-issue/SKILL.md`, `skills/implement-issue/brief-template.md`, `skills/check-issue/SKILL.md`, `skills/merge-issue/SKILL.md`, `skills/AREA.md`, `docs/guide/phases.html`, `docs/guide/files.html`. No command, test or worker-protocol change. Every rule agents follow today survives; only the second whole-leaf contract goes.

1. implement-issue reads. The leaf read sentence names `plan.md`, `design.md` and current review findings. The description line (line 3) promises eight-section worker sub-briefs instead of an eight-section brief for the leaf.
2. implement-issue implement. Before coding, and only when an implementation-only constraint is missing from `plan.md`, B appends one dated `## Implementation notes` section naming each constraint and the decision it refines; a locked decision is never changed there, and a conflict with one is a mismatch recorded for review. Then B implements the plan's checklist in order when config says `inline`, otherwise writes one sub-brief per unit from the template, one unit included, and delegates each sequentially by the worker protocol. The step "Write `<leaf>/implementation/brief.md` from the template" is gone.
3. implement-issue report. After the last check, B commits the code on the leaf branch, then writes `<leaf>/implementation/report.md` before handoff with changed files and reasons, commands run with pasted results and artifact paths, the base and committed head, known limitations, and unverified criteria; worker returns are folded in, not kept as separate report files. The report lives in the registered checkout, so the commit order is code first, report second.
4. implement-issue check.fix. Revising "the brief" becomes revising the plan notes and affected sub-briefs; the repair's before and after commits are appended to `report.md`.
5. implement-issue standalone. Unchanged: standalone has no plan, so its task brief still comes from the template at `implementation/brief.md`.
6. brief-template. The intro reads for worker sub-briefs and standalone task briefs and keeps its 1,500-word and 20-rule limit. The opening rule becomes: a delegated leaf writes `implementation/brief-1.md`, `brief-2.md` and so on, one per unit and one unit included, each with the eight sections and only its scope, with the binding facts for that scope copied in rather than pointed at; the leaf has no whole-leaf brief because `plan.md` is its contract; standalone writes one task brief with these sections. The eight sections and the four fill-in lines stay word for word.
7. check-issue. The read list becomes `plan.md` including its implementation notes, `design.md`, `implementation/report.md` and ponytail. The judgment sentence names the plan's decisions, criteria, change list and checklist, the design's exclusions, the report and live contracts. The report-gap rule stays as it is.
8. merge-issue. "implementation report" becomes `implementation/report.md`.
9. Guide and index. `docs/guide/phases.html` implement entry says B writes `implementation/report.md`; the `docs/guide/files.html` row names `implementation/report.md`; `skills/AREA.md` says the template gives the eight-section worker sub-brief.

## Why
Astra F2: B rewrites at implement the contract B synthesized at plan.synthesis. In `status-empty-open-fix` 5,298 bytes of plan became 5,311 bytes of brief with the same decisions and criteria, and the brief's only new content was the resolved test command and the filled report. The checker and merger read two versions of one instruction. Across the three registered repos 136 leaves carry a whole-leaf brief and 56 hold a report file under three names that no skill asks for. Operator answer 2026-09-14: "Least complexity, everything stays. The implementation has to be detailed and according to the rules. Just remove redundancies."

4. 7. Standalone, the worker protocol, the peer-question rule, the footer rules, the lesson rules and the template's 1,500-word and 20-rule limit read unchanged except the template's line 3 read-when clause (item 6).
