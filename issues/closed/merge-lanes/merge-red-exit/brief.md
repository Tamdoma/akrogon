# Brief: merge-red-exit

## What

In akrogon's merge turn the command alone moves a leaf off the line. A red verify, a gate refusal, a rebase conflict or a dirty worktree moves the leaf `merge -> check.repair`, clears its batch, records the attempt and stores an exit record (reason; red run id, refusal text or base; the evicted top), and the next queued leaf's turn starts in the same pass. A non-fast-forward push refusal is restacked once by the command; a second refusal clears the batch and leaves the leaf in `merge` at its place. Any other push error moves the leaf to `failed` with git's stderr. A `check.repair -> merge` move after a red exit whose HEAD equals the exit record's top needs no new leaf receipt. A leaf's first return to `merge` keeps its first `merge_stamp`; later returns get a new stamp. A leaf slice is kept while its leaf is in `merge` and holds a batch. The seat-owned merge path (a seat running `merged` or `check.fix` in `merge`, the batch `owner` seat branch, `wake=` prompts to a merge seat) is removed, and the skill text, `src/AREA.md` and the docs say the same as the command. When a leaf returns unchanged and fails again on a named unit it failed before that no cover reaches, the land run takes a base verdict on main in that turn: when main's tree at the merge-base already holds a whole-green row no suite runs, otherwise one base pass runs, so a new break on main opens a cover for every later leaf. It builds on leaf main-red-cover: the covered-head branch in `land` runs before any red hand-off, and it reads the base row this leaf's base pass writes.

## Why

Today a red or seat-needing merge run keeps the repo's single merge line while a seat reruns and repairs: in framework 2026-11-14..21 the line was busy 74.5 h, 45% of first runs were red, and in-line reruns cost 19.8 h (forks/red-exit.md Findings). The seat-owned path also let a wake start a new attempt over a refused push (about 97 min on 11-18) and let a lost B seat stall the line 2 h on 11-21 (forks/extras.md Findings). Signpost 5a: a failed merge leaves the line at once and is retested or repaired off it.

## Done-criteria

1. A red land run moves its leaf to `check.repair` with the exit record (reason red, red run id, evicted top), no batch, and a `red` row in `merge-attempts.jsonl`; the next queued leaf's land run is started by the land run's own wake with no other command run, and no seat is prompted while the red leaf was in `merge`. Proof: own test in `bun test` at the command boundary.
2. A gate refusal, a rebase conflict at the turn start (`mergeTurn`), a rebase conflict in the restack after a refused push (`land`), and a dirty worktree each move the leaf to `check.repair` with its reason and refusal text or base, and the next leaf's turn starts with no other command run. Proof: own tests in `bun test`.
3. A non-fast-forward push refusal is restacked once by the command; a second refusal clears the batch and the leaf stays in `merge` at its queue place; any other push error moves the leaf to `failed` with git's stderr in the reason, and the next leaf's turn starts. Proof: own tests in `bun test` against a local bare remote.
4. A wake arriving between a refused push and the command's restack starts no new attempt; with the red leaf's B seat dead or missing, the next holder starts without waiting on that seat, and that B is restarted when A is live or the cap has room. Proof: own tests in `bun test`.
5. `check.repair -> merge` after a red exit with HEAD equal to the exit record's top is allowed with no new green leaf receipt; with any other HEAD it still needs one; leaving `check.repair` clears the exit record; the `check.repair` prompt carries the exit record. Proof: own tests in `bun test`.
6. A leaf's first return to `merge` after its first entry keeps its first `merge_stamp` whatever the path (`check.repair`, `check.fix`, `failed`); its second and later returns get a new stamp; the count comes from `log.jsonl` moves into `merge`, with no new state field. Proof: own tests over `mergeQueue` order in `bun test`.
7. A leaf in `merge` whose batch is set keeps its leaf slice through reconcile when both of its seats are gone. Proof: own test in `bun test`.
8. A slot-run `akrogon phase` request for `merged` or `check.fix` on a leaf in `merge` is refused. Proof: own test in `bun test`.
9. A returning leaf whose new batch `holder.head` equals the `sha` of its previous red merge run, whose every failing unit is a named title, and of whose uncovered failing units at least one also failed on that previous red run, gets a base verdict in the same land run: when main's tree at the merge-base already holds a whole-green row, no suite runs, the units count as green on main and the leaf exits to `check.repair`; otherwise one base pass runs, reusing the recorded red head run, and when it shows every failing unit red on main the leaf lands in that turn by the existing known-red receipt, else it exits to `check.repair`. On an exit after the trigger held, the exit record names the base run or the green row that stood in for it. A leaf that changed its head, a run with a nameless failure, or a run whose failing units are all already covered gets no base pass. Proof: own tests in `bun test` at the command boundary.
10. The merge-issue, lifecycle-rules, check-issue (`## check.review` and `## check.repair`), implement-issue and watch-issues skill text, `src/AREA.md`, `docs/use/merge-and-announce.md`, `docs/reference/state-and-phases.md`, `docs/reference/checks.md` and `docs/reference/skills.md` state: no seat works in `merge`; in `check.repair` B judges the red from the kept log and the leaf's diff and may run the narrowest failing command through `akrogon run-check`, never a full suite; an untouched-diff red B judges not the leaf's fault returns to `merge` unchanged; a red B judges main-caused that the main-red cover does not reach takes the existing operator-only `failed` stop naming the main red, never `check.fix`; a second red on the same unit goes to `check.fix` only after criterion 9's base verdict found that unit green on main when its trigger holds, and otherwise by today's rule. Proof: the reviewing seat reads the named sections against forks/red-exit.md Taken 3 as copied in this leaf's design.
