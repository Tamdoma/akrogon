## Decisions

D1. Exit record. `state.merge_exit` (`mergeExitSchema`, strictObject, optional): `{ reason: 'red'|'gate'|'conflict'|'dirty', top?: string, run?: string, refusal?: string, base?: string, base_verdict?: string }`. `top` is the evicted top: the batch `top` (restacked top when a restack already ran; absent when nothing was ever applied). `run` the red verify run id; `refusal` the gate message; `base` the rebase target sha for conflict/dirty; `base_verdict` names the base run id or the whole-green row that stood in for it (Taken-8 exits only). Old `state.yaml` files carry no `merge_exit` and parse untouched; `batch.owner`/`wake`/`red`/`refusal`/`decision` stay optional in `batchSchema` so old batch records parse, but no code reads or writes them. An old `owner:'seat'` batch therefore reads as command-owned: `applied` records launch or relaunch a land run, unapplied records are rebuilt by `mergeTurn`; a `solo`-shaped applied record (`top` absent) exits to `check.repair` with reason `conflict` on the same path a fresh conflict takes.

D2. Where the record lives and clears. `commitMove` gains an optional `merge_exit` argument written onto the committed state; every committed move to a phase other than `check.repair` clears `merge_exit` (a `check.review -> check.repair` move carries none, so `merge_exit` only ever exists on a `check.repair` leaf that exited from `merge`). Cleared on `check.repair -> merge|check.fix|failed`; never set on `merge -> merged`.

D3. Batch cleared on every repair exit. `commitMove` sets `batch: undefined` when moving to `check.repair` (reachable only from `merge` today; `check.review -> check.repair` leaves hold no batch by invariant). The exit path also `appendAttempt(repo, slug, record, 'red', end)` inside the same locked commit — the 'red' outcome stands for "attempt ended off the line" for red, gate, conflict and dirty exits alike, matching brief criteria 1-2 which name a `red` row for each.

D4. The merge route keeps no seat. `routing.merge` becomes `{ skill: null, slots: [], next: ['merged', 'check.repair', 'failed'] }`. Consequences, all handled: `promptFor` never builds a merge prompt (merge leaves end in `dispatchLeaf` before `promptFor`, and no other caller reaches them); `waits_on` reports `[]` for merge leaves; `transition`'s required-slot check becomes "refuse a `--slot` when `required` is empty, require one when it is not" (today's `slot === undefined || !required.includes(slot)` under-requires when `required` is `[]`); `failureSchema.slot` becomes optional and `refuseEnclosingCompletion`/`transition`'s failed path write `slot ?? required[0]` which may be absent; `status`'s `merge` row and `merge-issue` references update per D12. `check.fix` drops out of `merge.next`: the command's exit goes to `check.repair`, and a seat's second-red judgement now ends in `check.fix` from `check.repair` (already routed) after item 9's base verdict.

D5. Seat moves refused, operator move kept. In `phaseCommand`, a `phase <slug> merged|check.fix` call carrying `--slot` on a leaf in `merge` throws `A seat cannot make merge calls: <requested> (criterion 8)`. `merged --check` on a merge leaf is refused outright (`--check` only exists for the seat protocol); `batchCheck` and `recordTested`'s `--check` caller die with it. Slot-less `phase <slug> merged` (operator completion) stays: it runs `batchPush`/`finishPush` as today, with `tested=false` (the `slot !== undefined` argument already encodes this — keep the parameter, it now always means "operator path"). `phase <slug> failed` keeps working with no `--slot` (D4).

D6. `land()` becomes the command mover. New flow, replacing `handOff`:

```
for (refusals = 0; ;):
  claim (StaleLandError tolerated as today)
  result = verify(repo.root, undefined, attempt, undefined, false)
  if result.code !== 0:
    if result.code === 1 && mainRedCover(sha, id): coverRun = id; goto gates
    if result.code === 1 && taken8Trigger(record, result):       # D10
      verdict = verify(repo.root, undefined, attempt, undefined, true)
      if verdict.code === 0: coverRun = headId; goto gates
      return repairExit(reason 'red', run headId, top, base_verdict baseVerdictOf(...))
    return repairExit(reason 'red', run redRunId, top)
  gates (unchanged landGates) -> throw => repairExit(reason 'gate', refusal msg, top)
  pushed = landPush(...)   # restack + rerun stays inside the loop
  'landed'    -> landedWake
  'restacked' -> refusals += 1; if refusals > 1: keepPlace()
  'rebase'    -> repairExit(conflict|dirty by worktree status, base built_on)
  'error'     -> commandFailed(git stderr)
```

`repairExit` (new, in `land.ts`): under the lock re-`landClaim` (stale tolerated → log + return, as `handOff` did), `appendAttempt(..., 'red', end)`, `commitMove(leaf, 'check.repair', slot null, { merge_exit })` — the move clears `batch` via D3; then `console.log('repair <slug> attempt=<id> reason=<reason>')`, `await mergeWake(global, repo)` (next holder's land unit starts in this wake), `await phaseWake(global, repo, slug)` (check.repair seat gets its prompt). `keepPlace` (second non-ff): under the lock clear `batch`, `appendAttempt(..., 'red', end)`, log `held <slug>`; then `mergeWake` so the next pass rebuilds the batch on the fetched base — the leaf keeps its queue place through `merge_stamp` (D8) and `mergeQueue`'s stamp ordering. `commandFailed` (push error): `appendAttempt(..., 'red', end)`, `commitMove(leaf, 'failed', slot null, { cause:'blocked', phase:'merge', reason: <git stderr> })`, then `mergeWake`; `announceFailed`/`renameTab` run inside `commitMove` as for seat failures.

D7. `mergeTurn` loses the seat branch. `recorded?.owner`, `dispatchMergeLeaf`, `mergeContext`, the `recorded.applied === true && top === undefined` solo dispatch all go. New branches: (a) `recorded?.applied === true && top !== undefined` → relaunch land when the unit is dead (today's command-owner branch, minus `owner` reads); (b) `recorded?.applied === true && top === undefined` (legacy solo record) → `repairExit` with reason `conflict` on `built_on`; (c) unbatched or unapplied holder → build the record as today, but when `buildStack` fails or `applyTop` returns false the leaf exits `merge -> check.repair` in the same locked pass: `appendAttempt('red')` + `commitMove` with `merge_exit { reason: 'conflict'|'dirty', base: builtOn }` (dirty = `git status --porcelain` non-empty in the worktree — the same read `applyTop` already does, so classify by re-running it after a failed apply; conflict = everything else), then `phaseWake` for the repair prompt. The `for (;;)` `mergePass` loop already sees the queue move on; the exit also calls `mergeWake`-equivalent inline by letting `mergePass` continue. `reconcileBatch` drops every `owner` reference.

D8. First return keeps `merge_stamp`. In `commitMove`, `to === 'merge'`: `merge_stamp` = `recorded.merge_stamp` when `recorded.merge_stamp !== undefined` and `log.jsonl` holds exactly one prior `to:'merge'` move for this slug (read via `readLog(repo.root)` before `logMove` appends this one), otherwise `new Date().toISOString()`. One rule, any path back (`check.repair`, `check.fix`, `failed`, `check.review`), count from the log, no new state field — Taken 6. (`mergeQueue` already falls back to log timestamps for stamp-less leaves.)

D9. `check.repair -> merge` receipt skip. In `transition`, the existing `check.repair -> merge` `requireGreenReceipt(head, 'leaf')` is skipped exactly when `state.merge_exit?.reason === 'red' && state.merge_exit.top === head` (criterion 5: only the red exit; a leaf that was edited, or exited for gate/conflict/dirty, still needs a receipt). The repair prompt: `promptFor` gains a `mergeExit` context string for `check.repair` only — ` merge-exit=red run=<id> top=<sha>` (or `refusal=`/`base=`/`base_verdict=` for the other reasons), built from `state.merge_exit`; `promptFor`'s signature already takes the state, so the context is derived inside it (a new small formatter `mergeExitContext(state)` next to `promptFor`); the old `mergeContext` parameter dies with merge prompts.

D10. Taken-8 base verdict inside the land run. After `verify` red (code 1, uncovered by `mainRedCover`), `taken8Trigger(record, result)` computes: (a) `record.holder.head` equals the `sha` of the leaf's newest completed merge-scope red run in `verify-runs.jsonl` whose sha ≠ current result sha — i.e. the previous attempt's tested commit became this branch head, so no edit happened between exits; (b) every `commands[].failures` entry of the current run names a real title (reject `(script)`, `(unnamed)`, `(no test name)`, `(log gone)` — same classification `src/flaky.ts` already applies); (c) at least one failing unit uncovered by `mainRedCover` also fails in that previous red run (same command + same name). All three hold → `verify(repo.root, undefined, attempt, undefined, true)` reuses the recorded red head run (`redRun` inside `verify`), skips the base pass when the merge-base tree already holds a whole-green row, else runs exactly one base pass (`compares` link). `verdict.code === 0` → proceed to gates with `coverRun = headId` (existing known-red receipt feeds `requireGreenReceipt`); code 1 → `repairExit` with `base_verdict` set to the base run id or the standing green row's run id (helper `baseVerdictOf(repo, headId)`: newest `VerifyRun` whose `compares === headId`, else the green row `greenRun` found at the merge-base tree, else omit). Changed head, nameless failure, or fully-covered failures → no trigger, plain red exit.

D11. Slice keep. `sliceKeepReason` gains, before the `unfinished leaf` branch: `if (leaf.state.phase === 'merge' && leaf.state.batch !== undefined) return 'merge batch'`. The land unit runs inside the leaf slice (`--slice=${leafSlice(repo, slug)}` in `launchLand`), so this keep is what protects a land run whose seats are gone.

D12. `status`/timing/`phaseCommand` leftovers. `status.ts`: `land`/`landAttempt` read `state.batch !== undefined` (drop `owner === 'command'`); `'merge job stopped'` logic keeps working (a dead unit still has `batch.recorded !== true`). `timing-report.ts`: `seatless` becomes `close.to === 'merged' || (visit.phase === 'merge' && close.slot === null)` — merge visits closed by the command's `check.repair`/`failed`/`merged` moves all carry `slot: null`. `akrogon.ts` retired-verb text drops the `merge-issue` path reference.

D13. Tests before product code (serial-solo). All criteria test files land in one `tests/` commit before any `src/` change; several existing tests are rewritten or deleted in the same commit since their behavior is removed (seat prompts, `--check`, solo, `wake=`). New behavior tests go in a new `tests/merge-red-exit.test.ts` plus targeted edits to `green-merge.test.ts`/`receipt-gates.test.ts`/`phase.test.ts`; obsolete files `batch-merge.test.ts` (seat `--check`/`check.fix`/`--attempt` protocol) and `batch-dispatch.test.ts` (merge-seat dispatch) are rewritten to the command-only cases they still cover or removed when nothing remains.

D14. `merge-issue` skill rewritten, not deleted. `routing.merge.skill` is `null`, so no prompt resolves to it; the file stays as the human/agent doc for the command-owned merge (the retired-verb message and docs link to it). Its content shrinks to: merge is command-run (`land`), the seat's only merge-era duties are gone, and the `check.repair` red judgement rules (Taken 3) live in check-issue.

## Open limitation

- A wake racing the cleared-batch window between `refusals>1` and the next `mergePass` sees no batch and rebuilds one — intended ("stays at its place"), not a second suite. The land unit's own wake is the only merge driver now, so the D1 race class is gone by construction.
- `log.jsonl` is the `merge_stamp` count source (Taken 6): a leaf whose log rows were pruned loses its first-entry privilege; the log is append-only in-tree so this needs no guard.
- `promptFor` embeds `merge_exit` fields space-joined (`refusal` text may hold spaces); the check-issue seat reads `state.merge_exit` as authoritative — the prompt string is the heads-up, `state.yaml` the record.
