## Fixes

- **F1. A clean rebase can hide a real flip.** A leaf changes one line in a file, then main changes a nearby comment with two unchanged lines between the edits. Git rebases the leaf cleanly and preserves its added and removed lines. The default `git diff` includes the changed comment as context, so `ownPatchId` writes different IDs and `flips` rejects the two receipts. Two real `verify --attempt` runs followed by `akrogon flaky` gave zero flips for the named red-to-green unit, where criterion 1 requires one. The current criterion test seeds matching IDs and the writer test repeats the same hash command on one side. The proof needs to exercise IDs the writer actually produces on both sides of the rebase. [Writer](/home/ivan/.akrogon/worktrees/akrogon/flaky-merge-flips/src/verify.ts:129) · [CLI evidence, `nearby`](implementation/check-review-flaky-cli-1795293035674-487988.log)
- **F2. A behavior-changing repair can be counted as a flake.** A leaf fixes a failed Bun assertion by changing its exported string from `'ready now'` to `'readynow'`, then rebases onto moved main. `git patch-id --stable` drops the space from both inputs, so the red and green receipts carry the same ID. The test goes green because of the repair, and `akrogon flaky` reports one flip where criterion 2 requires zero. The seeded mismatch test only covers already-different IDs. The proof needs to cover this changed-commit case through the writer. [CLI evidence, `whitespace`](implementation/check-review-flaky-cli-1795293035674-487988.log)
- **F3. A same-tree retry can count the same failure twice.** With two full checks, the merge run fails both. A retry on the same tree passes the named check while the other remains red, so a later merge run after main moves is still possible. The same-tree green consumes the pending red in `red` but leaves it in `mergeRed` because the trees match. The later green on the rebased tree consumes that stale red again. Three real merge receipts produced a count of two where D3 and criteria 2–3 require one. The existing non-consecutive fixture uses mismatched IDs and cannot catch this sequence. [CLI evidence, `same-tree-retry`](implementation/check-review-flaky-cli-1795293035674-487988.log)
- **F4. Existing same-tree flips disappear across leaf names.** D3/D7 add the leaf slug to the legacy key in `flips`, overriding criterion 3's promise that old rows count as before. The framework ledger has actual same-tree red/green merge pairs under different slugs, including `audit-ledger-seed` → `satellite-renderer-1-11-2` (runs `e8694734-4a6b-4812-b2da-211af554bd8d` and `d178a953-f31f-45ea-9c5e-e7142012d8db`). Both rows predate `patch_id`. A CLI reproduction verified identical same-tree receipts under two leaf names, then omitted the new optional field. The base reported one flip and the reviewed head returned an empty list. The same-tree proof currently uses a single leaf name. [CLI evidence, `fieldless-cross-leaf`](implementation/check-review-flaky-cli-1795293035674-487988.log)
