# Brief: realistic-review-bar

## What
Rewrite the review, repair and test rules in akrogon's skills and guide so that:
- a review Fix blocks only when it names a realistic input source, its consequence today, and the criterion, check or gap it hits, while failed `checks` commands and scenarios a done-criterion names always block;
- a leaf writes only the tests that prove its done-criteria and its real bug fixes, plus edge cases only where a concrete consequence warrants them, using the cheapest level that proves the property;
- deferred findings stay as Nits in the review file and the repair seat works on Fixes only.

Owned files: `skills/check-issue/SKILL.md`, `skills/implement-issue/ponytail.md` (only if it conflicts; `skills/check-issue/ponytail.md` is a symlink to it and stays a symlink) (A,B), `skills/implement-issue/SKILL.md`, `skills/implement-issue/brief-template.md`, `skills/plan-issue/SKILL.md` (only if it conflicts), `skills/chart-issues/assets/standing-design.md`, `docs/guide/phases.md`, `docs/guide/learn.md`, and any other `docs/` or `README.md` line that states the old rule.

## Why
Tamdoma/akrogon#43 and the operator's notes: reviewers block on handcrafted inputs no real build or user produces and on hypothetical maintenance, and leaves write tests that restate code. Framework `offer-join-deploy` looped 7 repair rounds on crafted parser inputs, and akrogon `epic-broadcast-once` went to repair with all 37 tests passing over a future-rename concern. Framework's last 20 leaves: 12 entered repair.

## Done-criteria
1. Every rule in `skills/check-issue/SKILL.md` that makes a finding a Fix (today `:35,37,41,43,45,47`) and the re-check rule (today `:53`) applies the fix-bar decision: a Fix names a realistic input source (real build, real user action or content, real integration, or untrusted input an attacker can send; a code trace or representative real output suffices), its consequence today, and the criterion, check or gap it hits; a handcrafted reproduction alone is a Nit; failed `checks` commands and scenarios a done-criterion names always block; a maintainability Fix needs a consequence today; rarity never downgrades a reachable security, data-loss or concurrency defect.
2. The same file applies the test-bar decision to review: a missing or bad test blocks only when a done-criterion has no test that would catch its failure, a realistic Fix has no test, or a test mocks the unit under test; assertion style, wording coupling that does not fail today, extra cases and coverage gaps are Nits.
3. The same file requires each Nit to state the reproduction or concern, why it is deferred, and what evidence would promote it to a Fix.
4. `skills/implement-issue/SKILL.md` and `brief-template.md` require only tests that prove each done-criterion (one test may prove several) plus a before/after proof per real bug fixed, extra negative or edge cases only for a named concrete consequence (broken required outcome, security boundary, data loss, unsafe mutation), extending existing tests before adding files; the report links each done-criterion and real bug fix to the test or evidence proving it; check.fix does required work for Fixes only and gives Nits no separate work or test.
5. `skills/chart-issues/assets/standing-design.md` drops the blanket "Mandatory negative and edge-case tests" rule in favor of criterion- and consequence-driven cases, and makes end-to-end evidence with an artifact required only when browser/runtime behavior or cross-component wiring cannot be shown by a smaller check or a criterion asks for it, keeping Playwright/trace rules for when browser proof is needed and the chain-trigger rules unchanged.
6. `docs/guide/phases.md`, `docs/guide/learn.md` and any other `docs/` or `README.md` line stating the old Fix or test rule describe the new rules; a sweep for the old rule by meaning (not only by exact phrase) finds no contradicting line in `skills/` or `docs/`, and out-of-scope hits are listed in the report.
7. A fresh agent that did not write the change, given only the new `skills/check-issue/SKILL.md` text and each case's recorded evidence, classifies five cases, and the report records its verdicts, reasons and the command or subagent used; each must match the expected outcome (A,B): framework `offer-join-deploy` F12 and F17 (Nit, no realistic source recorded), akrogon `epic-broadcast-once` review-B F1 (Nit, no consequence today), an untrusted form input that bypasses a sanitizer (Fix, attacker source), and a failed `bun test` (Fix, failed check).
8. `bun run format`, `bun run typecheck` and `bun test` pass.
