# Brief: seats-never-wait

## What

One section in the shared seat rules file `skills/lifecycle-rules.md` makes every lifecycle seat and implement worker run its commands unattended: no command that waits on a human, no hand-written poll or sleep loops (a slow command runs once in the foreground and the seat waits on its exit inside the turn), a harness denial treated as a formulation problem inside the same grant and identity rather than an operator blocker, and no env file path on a command line. The existing implement-issue wait rule moves into that section, the three seat-stop rules and the worker brief template point to it, and the `bun --env-file=<file>` example is replaced. Skill text only, no code. Delivers Tamdoma/akrogon#161.

## Why

On 2026-11-25 two Himne leaf seats lost time or failed over harness command gates. `wrangler-remote-bindings` got a returned claude denial on `akrogon run-check ... node --env-file=<repo>/.env.local ...`, read it as "a permission A cannot grant" and ended the leaf `failed`. In `chord-tap-editor` an implement worker wrote a 25-minute `while ss ... sleep 10` loop. Under the current launch profiles and host settings, every harness ends a would-be approval without a human: agy with host `toolPermission: always-proceed` (observed at charting), claude through `denyInsteadOfPrompting` from `src/seat.ts` (code and the Himne transcripts), codex `-a never` and pi with no approval layer (vendor docs). The remaining cause is seat behaviour, and only the seat instructions reach it. Host `ask` rules and extensions that wait on a UI choice stay the operator's and are a stated limit. The operator decision on #161 requires that seats never depend on a human approving a command, on all four harnesses, without added complexity. (A,C)

## Done-criteria

1. `skills/lifecycle-rules.md` holds one section, applying to every lifecycle seat and implement worker, that states: (a) a seat writes no command that waits on a human; (b) no hand-written poll or sleep loop: a slow command runs once in the foreground with the tool timeout set above its expected run time, and the seat waits on its exit inside the turn, never ending the turn to wait; (c) a harness denial of a command is re-expressed inside the same grant and identity (a simpler single command, the configured runner, the harness's own read or edit tool) and is never routed around a secret, `.env` or grant rule; only when no permitted formulation can answer the same criterion does the seat's `failed` stop apply, with the denial text verbatim in its record file; (d) a command line names no env file path: values come from the process environment `akrogon run-check` passes (declared `env` and `pass_env` names) or the leaf worktree's `.env` written from declared `env` names, read by the program itself, and a needed value that is not declared is a missing input under the existing `Missing:` rule.
