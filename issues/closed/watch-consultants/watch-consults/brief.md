# Brief: watch-consults

## What

`/watch-issues` consults one hc consultant per root cause on every failure it only notifies about today, exchanges every question and answer with it over `hc send` with turn files in a case folder outside the repo, waits for it with no give-up time, acts on the agreed fix within the operator stops, resumes the failed leaves itself, records each case, and asks the operator only for the stops (credentials, spend past a grant, a changed decision or lock, host tooling, force pushes or history rewrites, a fix that changes what was decided). The timer coalesces dues that queue during a long turn, and `watch-issues stop` and a lost watcher close the consultant.

## Why

Tamdoma/akrogon#146: the watch stops at hard failures and waits for the operator, which defeats watching while the operator is away. It consumes leaf consultant-seat's `akrogon seat --watch-consultant` (the consultant's start, name and labels) and leaf failed-merge-resume's restack of a failed merge leaf resumed after a base fix.

## Done-criteria

1. Live run: in a throwaway repo and hc session, a watching session meets a staged base-red failure that stops a leaf in `failed`, starts its consultant with `akrogon seat --watch-consultant` from the recipe in the session's machine config, writes the case brief under `<globalHome>/watch/<repo>/consults/<case-id>/`, exchanges at least one question and answer with it through turn files and `hc send` while staying in its own turn (the live-interaction property: a real harness watcher receiving its consultant's sends inside its own turn, which no recording proves) (C), receives a base fix pushed fast-forward to the throwaway remote, resumes the leaf with `akrogon phase` and `akrogon next`, writes `case.md` and the signature, sends the non-attention notices for the push and the move, and closes the consultant with `hc kill` and `hc rm`. The run uses the existing watch tier in `tests/e2e/watch-tier.ts`; its sessions run one after another because they share the tier's single `akr-e2e-watch` hc session, which `startWatchTier` refuses to start over leftovers. Proof: the attended e2e run's recorded screens, case folder and notice log, quoted in the implementation report.
2. The watch's choices in that run (root cause, fix or stop, resume target, agreement with the consultant) are the models' own: each is recorded with its reason and the evidence weighed in the case's `case.md` and turn files; the case record takes function checks (files exist, the signature parses, every turn file named in a send exists); the reviewing seat reads the choices. Unproven: the quality of a choice on other failures.
3. A failure whose next consult would carry the same signature as a closed case (anchor cause@phase or unknown, failing command, base SHA, leaf HEADs) starts no consultant, a case that ends on technical exhaustion or an unsettled disagreement leaves the leaf failed with one non-attention notice, and a case that ends on an operator stop sends one attention notice naming the stop (B). Proof: own tests of the signature read and compare in `bun test`.
4. While the watcher works through several tick boundaries, the timer holds the sent due and at most one unsent due, set to the latest boundary; when the watcher goes idle it sends that one due, and `tick.ts` accepts it. Proof: own tests of `timer.ts` in `bun test`.
5. `watch-issues stop` kills and removes the verified timer and then the watch's verified consultant (name, `akrogon.watch-consult` label, parent), prints `stopped <timer>` first and `stopped consultant <address>` only when one was closed, and treats an already absent consultant as closed. Proof: own tests of `stop.ts` in `bun test`.
6. When the timer finds that its watcher process left a surviving terminal, it kills and removes that watch's verified consultant before it exits. Proof: own tests of `timer.ts` in `bun test`.
7. Without `slots.consultant`, the watch keeps today's notify-only outcome for the failure and sends one non-attention notice per watch naming the missing key, and no attention notice for it. Proof: the skill text, read by the reviewing seat. Unproven: the absent-recipe path at runtime, since the live run's config holds the recipe (C).
