# Design: abandoned-capture-stop

## Binding decisions, verbatim

From issues/chart/killed-run-fixture/forks/killed-run-stop.md `## Taken`. These are A's picks under autopilot, 2026-10-28 (1a 2a 3a), not operator words.

- Q1 · 1a: `akrogon phase` refuses every non-failed move of a leaf (`--check` and one slot's completion included) while the leaf folder holds an abandoned capture pair with no non-blank `cleared-<run>.md` beside it, naming each pair and the clear step. Moves to `failed` and operator recovery from `failed` stay open. Containment on wrapper death is unchanged. The promise covers abandoned pairs (the wrapper died before publishing). Reason: the pair is already a per-run record written before launch, so the stop needs no new state, timer or credential and catches every way the wrapper dies. Rejected: 1b survive the wrapper (SIGKILL and reboot still leak, reverses #120 ownership); 1c automatic cleanup (watchdog lock 2026-09-18, no cleanup authority); 1d prose only (already existed, did not stop this).
- Q2 · 2a: one shared flock on one open file description. `checkedRun` opens capture-out for writing in place of its `writeFileSync`, locks that description with a one-shot `flock -s 3` helper inheriting the fd, and `spawnLogged` passes the same fd as the child's stdout in place of `Bun.file(capture.out)`, for nested and non-nested runs. The pair is live while the wrapper or any descendant holding stdout lives. The probe opens the existing capture-out without creating it and runs `flock -n -x` on that fd; a pair gone at probe time is finished, never abandoned. Reason: no gap from creation to unlink, readers take no lock, a reboot frees it. Rejected: admission records (nested runs have none, removed before the stop ends); an open-fd scan of /proc (a reader keeps a dead run live); a wrapper helper plus a separate child lock (startup gap).
- Q3 · 3a: the seat runs the leaf grant's own discovery, cleanup and authenticated absence read for that run, not only the IDs the pair printed, then writes a non-blank `cleared-<run>.md` beside the pair saying what it found, cleaned and read. Capture names and bytes stay. A later green run clears nothing. check-issue and implement-issue say: after a run-check printed no `check` line, recover before any rerun. Rejected: a rename (breaks printed paths); a new resolution command (a file does it).
- Lesson: the owning leaf retires `learnings/history/2026-10-28-killed-run-fixture-leak.md` under the lesson rule's Retire clause when that file is on its base, else records its absence.
- Off route (CHART.md): a test killed while its wrapper survives (it publishes a red `check` line, and through `sh -c` a signal end cannot be told from exit 128 or more); making a run survive its wrapper; the chart direct holder.

Recorded proof (fork Findings, 2026-10-28T13:07:29Z, bun 1.4.4, util-linux 2.42.4): a bun wrapper opens the capture for writing, runs `flock -s 3` with that fd as stdio index 3, then spawns a child with the same fd as stdout. `flock -n -x` reads busy while the wrapper and child live, busy after the wrapper is SIGKILLed with the child alive, free when both are dead even with a `tail -f` reader open, busy with the child dead and the wrapper alive, and free when both are dead. Limits: not run under `systemd-run --scope` or the guard's stop, and the pathname probe form recreates a missing file, which is why the probe uses an fd opened without create.

## Leaf architecture

Owned surfaces:

- `src/run-check.ts` `checkedRun`: create capture-out with an fd opened for writing and lock its description with a one-shot `flock -s 3` before `check_start`. Keep that fd open until after both unlinks, in the normal path, the refusal path and the throw path alike. Capture-err creation is unchanged.
- `src/run-check.ts` `spawnLogged`: take the locked capture-out fd from the caller and pass it as the child's stdout. Both the nested branch and the `runUnitArgv` branch pass it through `flock -s <owner .lock>` and `systemd-run --scope`, which keep stdio. The read fds (`outRead`, `errRead`) stay as they are and take no lock.
- A function beside them (name chosen by the plan) that lists a leaf folder's capture pairs, recursively, with no `cleared-<run>.md` holding non-blank content, and probes each capture-out through an fd opened without create (`O_RDONLY`), with a non-blocking exclusive flock. ENOENT means the pair is finished and is skipped.
- `src/phase.ts` `moveGuards`: call that function for the leaf's folder and throw an error naming each abandoned pair and the clear step. `transition`'s `failed` branch runs before `moveGuards` and stays unguarded. Operator recovery out of `failed` stays allowed. Open for the plan: `moveGuards` currently runs only for some paths (`transition` and `landGates`), so the plan names which paths reach it and confirms that one-slot completion and `--check` both pass through it.
- `skills/check-issue/SKILL.md` (`## check.review`, `## check.repair`) and `skills/implement-issue/SKILL.md` (`## implement`, `## check.fix`): add the recovery rule from criterion 6 beside the existing stop-run lines. These skill files are repo code under `skills/`, not `issues/`.
- `learnings/LESSONS.md` and `learnings/history/2026-10-28-killed-run-fixture-leak.md`, only when that history file exists on base (criterion 7).

Consumers of changed state:

- `src/evidence.ts` `locate`/`readMember` and `akrogon log`: capture names are unchanged and `cleared-<run>.md` is not a `.log`, so both keep working (criterion 3).
- `src/pack.ts` `packFolderLocked`: packs `*.log` only, so `cleared-<run>.md` stays a plain file. It is not git-ignored (`.gitignore` ignores `issues/open/**/*.log` only), so it is committed with the leaf's other records.
- `tests/durable-capture.test.ts`: the existing SIGKILL and normal-exit cases rely on capture creation and stdout contents. Open for the plan: confirm that the fd-passed stdout keeps the byte order and contents those cases assert.
- `src/flock.ts` `flockHold`: not reused for the capture lock, because its helper process owns a separate description, which leaves the startup gap B reproduced (F13).

Open for the plan: whether a run can be abandoned between `landGates` and `commandMerged`/`completeOwner` side effects (`closeSources`, pack, move), and if so where a recheck sits so that a refusal comes before those effects (B F8).

Exclusions: no change to `startRunGuard`, admission or containment. No cleanup of outside resources by akrogon. No gate on `akrogon verify` holders or chart direct holders.
