## Q1 names (leaf failure-names)

The name reader returns, for one red log:

1. Each real Bun title from a `(fail) <title>` line, unchanged and without its script prefix, as today.
2. `(unnamed) <script>` for a `(fail) (unnamed)` line whose stream has a script prefix, and `(unnamed)` when it has none.
3. `(script) <script>` for each failed script, read from `<chain> | Exited with code <n>` with n not 0, whose own stream printed no `(fail)` line. `<script>` is the innermost token of the chain, trimmed.
4. [corr] A failed chain that is a strict prefix of another failed chain is a wrapper and is dropped. Whether a stream printed a `(fail)` line is matched on the whole trimmed chain before the innermost token is taken.
5. [corr] A `Signaled:` line is ignored and gives no name. An accepted ancestor `Exited with code` line may give a coarse name; the log gets `(no test name)` only when no accepted name remains anywhere in it. (reworded after the check, B,C)
6. `(no test name)` when the log yields none of the above; `(log gone)` when no log can be read. Both unchanged.
7. [corr] A line that starts with `(fail) ` is unprefixed even when its title contains ` | (fail) `.
8. Names are deduplicated. No name comes from free text.

Stated cost: the same real title failing in two different scripts compares equal, as today (B's dissent). Two bare hook timeouts in one script share one name. A script that died by a signal with no failed wrapper, beside a named failure on another stream, adds no name, so that head takes the named branch as it does today (C's check, kept as cost: Bun prints the same line for healthy siblings it stopped).

## Leaf architecture

- Owned surfaces: src/flaky.ts (`failedTests` and its comment; the split of a pure text-to-names function from the log read is the plan's choice); the tests that show criteria 1 to 6 (tests/flaky.test.ts, tests/verify.test.ts, and tests/receipt-gates.test.ts only if a merge-scope pair is needed); skills/lifecycle-rules.md (`## Red check with no cause in the leaf's diff`); skills/chart-issues/assets/direct-route.md (landing step 3); docs/reference/checks.md; docs/reference/files.md; src/AREA.md; tests/docs-links.test.ts and tests/run-units.test.ts only where a phrase they assert changes.
- Literal interfaces: names `(script) <script>`, `(unnamed) <script>`, `(unnamed)`; unchanged `(no test name)`, `(log gone)`, real titles, the `akrogon flaky` line `<count> <last> <check> <name>`, the `verify known-red <sha>: pass|fail` line and exit codes, the record shape in `issues/verify-runs.jsonl`.
- Input shapes the reader rests on (observed at charting, issues/chart/failure-identity/forks/identity-rule.md P1, P2, P4): `<script padded> | Exited with code <n>`; nested `<outer padded> | <inner padded> | Exited with code <n>` followed later by the wrapper's own `<outer padded> | Exited with code <n>`; `<chain> | (fail) <title> [<ms>]`; `<chain> | (fail) (unnamed) [<ms>]`; `<chain> | Signaled: <SIG>`. The check log is the command's stdout followed by its stderr (`checkedRun`, src/run-check.ts); Bun prints all of these lines on stderr, so the reader never relies on order across the two.
- Reader mechanics that follow from the binding Q1 items and are fixed here (C): a `<chain>` is split on `|` into trimmed tokens, so the whole trimmed chain is that token tuple and a strict prefix is a strict token-tuple prefix, never a string prefix (`test:a` is not a prefix of `test:ab`). The wrapper drop of item 4 runs first, over every chain with a non-zero `Exited with code` line; only then are the remaining chains whose own stream printed a `(fail)` line left out of the `(script)` names. So `grp | sub | (fail) title`, `grp | sub | Exited with code 1`, `grp | Exited with code 1` yields `title` alone. `<script>` in `(unnamed) <script>` is the innermost trimmed token, as in `(script) <script>`: the recorded line `framework:verify:rest-a      | test:emdash-kit     | (fail) (unnamed) [7668.89ms]` yields `(unnamed) test:emdash-kit`.
- Changed state and its consumers: the set of names `failedTests` returns. `flips` (src/flaky.ts) emits one flip per name: decision, unchanged code, more precise lines. `knownRedReceipt` (src/verify.ts) requires every head name among the base names and refuses a head `(log gone)`: decision, unchanged code; a base whose log is gone returns only `(log gone)`, which no readable head name equals. `newRedUnits` (src/verify.ts) keys a unit by check, command and name: decision, unchanged code. `requireGreenReceipt` and the gates behind it (src/phase.ts, skills/chart-issues/scripts/direct-guards.ts) inherit `knownRedReceipt`. Open for the plan: whether any other reader matches the literal `(no test name)` or assumes one name per nameless log.
- Lookup miss: `failedTests` catches `LogError` kind `nomatch` today and returns `(log gone)`; in that branch only, it reads `resolve(repo.root, recorded)` when that is a regular file. `readLog`, `locate`, `readLogAcross` (src/evidence.ts) and the `akrogon log` command do not change. Open for the plan: whether `verify --holder <dir>` records an absolute log path for a holder outside the repo (the ledger rows seen at charting are absolute).
- Existing cases that stay: in tests/flaky.test.ts the prefixed title (`test:owner | (fail) browser owner > dies with run` listed as `browser owner > dies with run`), the deleted log, the packed archive, the corrupt archive and missing member errors; in tests/verify.test.ts the nameless cover of #133, the linked-pair refusal matrix, the notice deduplication, green resolution and recurrence cases. An expectation changes only where its fixture log holds an `Exited with code` line the new reader now names.

- Stated costs carried from the fork: the same real title failing in two different scripts compares equal, as today; two bare hook timeouts in one script share one name; a script that died by a signal with no failed wrapper adds no name.
