# Design: reset-name-restore

## Binding decisions, verbatim

### Signposts (issues/chart/door-name-after-reset/forks/signposts.md), A's picks under full autopilot, 2026-11-14: `1b 2a 3a 4a 5a 6a 7a`

- 1b: Keep a name the session already has, and give a door that has no name of its own the name of its tab. Foreclosed: keeping existing names only; rebuilding names from older sessions.
- 2a: When the session's own name and the tab name differ, the session's own name wins; the tab only fills a missing name. Foreclosed: the tab name on every reset.
- 3a: The name survives the door's own handover reset; a door that lost its name some other way gets it back at its next handover. Foreclosed: covering every way A becomes a fresh session.
- 4a: Claude now. Another harness is covered only where a probe shows a rename command; the rest is a stated limit. Foreclosed: every harness the reset supports.
- 5a: When the name cannot be read or set, write one log line and continue the handover. Foreclosed: stopping the handover with an error.
- 6a: Nothing is stored between sessions; the helper reads the live session and the tab at each reset. Foreclosed: storing the name in seats.yaml or the handover entry.
- 7a: Proofs are short throwaway haiku sessions run by the door at charting plus local stand-in tests. No real door is touched. This leaf runs no live session.
- Hard limits adopted with the picks: the name is the harness session name the operator reads, never only an hc or tab rename; "has a name of its own" is read from the session's own record, never from the hc title; no writes to a transcript file; slot A only; the operator-input cancel rule stays; no naming service or registry.

### Name restore (issues/chart/door-name-after-reset/forks/name-restore.md), A's picks under full autopilot, 2026-11-14, rebutted by B and C: `1a 2a 3a`

Q1 1a. The session's own name is the `customTitle` of the last `custom-title` record in the pre-reset transcript, read after the input check. When there is none, the name of the tab in the repo's resolved space whose terminals list A's address, read from the herdr-app document at that moment. Nothing is stored between sessions. Reason: signposts 1b, 2a, 6a. Rejected: the hc `title` (an auto title on an unnamed session); the `where` label (display text); claude's per-process session file (needs a pid the transcript code keeps private); the `herdr.tab` label route (same tab, one more input, dropped by C).

Q2 2a. Only when the session has no name of its own and a tab name was found, the helper sends `/rename <tab name>` as text to the old idle session, after the input check and before the reset keys; a send answering `started: false` gets one enter, as the start prompt does. It then waits until that rename turn has ended: A idle or done with a turn count above the one the send answered. Then the reset and start prompt run as today. A session with its own name gets no extra input, because claude carries the name across `/clear`. Reason: signpost 5a ranks the handover above the name, and this order adds nothing between the reset and the start prompt. Stated cost: it rests on claude carrying the name across `/clear` (seen on 2.1.322, 2.1.323, 2.1.325); if that stops, the log shows `sent` at every handover while names stay lost. Rejected: rename after the reset every time (B's map; an input stuck there glues to the start prompt and breaks the handover); both sides; keys (P3); a bare `/rename` (may call the model).

Q3 3a. One new stage `name`, logged at every handover, between `input-check` and `reset-keys`: `kept` with the name, `sent` with the name, or `skipped` with the reason (harness is not claude, no tab lists A or its name is blank, the name holds a control character or line break, or the name read or send failed). A skip continues the handover; only failures of the name stage are caught, by their own types, and reset, cancel and start-prompt failures keep today's paths. The helper does not confirm the name landed. One exception to "skip and continue": when the rename turn is still open at the bound, the helper logs the stop, types nothing more and exits non-zero, the same rule as `wait-turn-end: turn open`. Codex, pi and agy log `skipped`; handover.md states the limit. Reason: signposts 4a and 5a; the exception because typing a reset into an open turn is the glue case. Rejected: logging only when something was sent; stopping the handover whenever no name can be set (B's signposts dissent, recorded there).

Correction to Q3, adopted by A on 2026-11-14 after the leaf review (C D1, D2; final check by B and C in slots/name-restore-final-check-*.md): the skip reasons are only these three: the harness is not claude, no tab lists A or its name is blank, the name holds a control character or line break. The name stage catches nothing. A thrown error while reading the name or sending the rename keeps today's failing path: the error lands in the log, the helper exits non-zero and types nothing more. Reason: the transcript was already read by the input check; the tab read is a second document call that can fail by itself, but a core that fails it would likely fail the reset keys next, so ending there loses nothing (C); and a send that throws may have pasted `/rename <name>` without enter, onto which the reset keys would glue (C). This replaces "or the name read or send failed" and "only failures of the name stage are caught, by their own types". A blank `customTitle` counts as no name of its own (C). The thrown-error path is a second narrow exception to signpost 5a, beside the open-turn stop (C). (C)

Pitfalls avoided, binding: no name is sent as keys; no name with a control character or line break is sent; the reset is never typed into an open rename turn; the test stand-in runs `/rename <name>` as an hc turn with no model reply and carries the last name to the new transcript on `/clear`, as claude does; the tests read the name from the resulting transcript, not only the inputs; the operator-input cancel rule and its stated limit stay as they are.

## Standing design

/home/ivan/.claude/skills/chart-issues/assets/standing-design.md. Interpretation: criteria 1 to 5 are new behavior of one script, proven by the smallest test at its real boundary, which is the existing one: tests/door-reset.test.ts starts the helper as A starts it on a real hc test core against the stand-in tests/door-agent.ts. Extending the stand-in with `/rename` is fixture work, not machinery. A test of the stand-in's own name carry would be a vanity test and is not written (C). Claude's own behavior (the pasted `/rename` runs as the command, the name carries across `/clear`) was observed at charting on real claude (readiness.yaml proofs) and is not re-run by the leaf: no live session, no paid call, no grant. New behavior shows one deliberate break turning its test red (criterion 2). Existing tests that pin the stage list are updated to the new list with that reason, not deleted. No secret, no auth and no backend state is involved.

## Leaf architecture

- Owned surfaces: skills/chart-issues/scripts/door-reset.ts (the `name` stage and the header comment); tests/door-agent.ts (the claude stand-in's `/rename` handling and name carry on `/clear`); tests/door-reset.test.ts (the tests for criteria 1 to 5 and the stage list); skills/chart-issues/assets/handover.md (the stage description and limits). A shared export in src/transcript.ts or src/hc.ts is owned only if the plan needs one.
- Literal interfaces: the helper's arguments and launch line stay as they are. The log gains one line per run with `step: "name"` and `result` one of `kept`, `sent`, `skipped`, or the stop result at the bound, placed after `input-check` and before `reset-keys`; `kept` and `sent` carry the name, `skipped` carries the reason. The text sent is exactly `/rename <name>`. The claude record read is `{"type":"custom-title","customTitle":<string>}`, parsed with a schema at that boundary.
- Existing code reused, preconditions checked at d44920b8: `transcriptRecords(pre, from)` (src/transcript.ts) returns parsed records from an offset and is already imported by the helper for the input check; `docGet(session)` (src/hc.ts) returns each space's tabs as `{id, name, terminals}` with nested blocks flattened, and `repoSpace` already gives the helper the resolved space id; `send(session, address, text)` (src/hc.ts) returns `{started, status, turn}` and the `hc()` wrapper drops `HC_TERMINAL_ID`, so the text arrives without an `<hc from>` wrapper; `waitFor(session, address, until, ms)` (src/hc.ts) starts from a snapshot of the terminal, so a wait on idle alone can return on the state from before the rename (C's rebuttal).
- State the change alters, and its consumers: the stage order in the log. Consumer: the `STAGES` list and the stage-order assertions in tests/door-reset.test.ts, which the leaf updates. The door's skill text reads the log only as a record of why a reset failed (handover.md), which the leaf updates. No command in src/ parses the log.
- State the change alters: A's session receives one more input before the reset in the unnamed case. Consumer: the next handover's input check in door-reset.ts (`inputSchema.claude`), which reads only records written after that later helper started, so an earlier rename is before its boundary. Decision: no change to the input check.
- Test setup inside ownership (C): the test core's document gives the repo space no tabs and tests/hc-fixture.ts is not owned, so each test that needs a tab writes it itself through the exported `HcCore.rpc` (`doc.get`, then `doc.set` with a tab whose root lists A's address), named for criterion 2 and with `name: ''` for the blank case of criterion 3.
- Criterion 1 and the stand-in (C): in the `kept` case the helper sends nothing, so the leaf proves no rename input, the `kept` line with the last name, and the unchanged reset and start prompt. That the name then carries across `/clear` is claude's behavior, observed at charting (readiness.yaml), not something a stand-in test can prove.
- Exclusions: no change to how A is started, to `seats.yaml` (its `name` is the hc terminal name, a different field), to consultant terminals, to codex, pi or agy naming, or to any path under `issues/`. The release link that brings the changed skill text and script to running doors is the normal release step, not this leaf.
- Open for the plan: the exact wait condition for the rename turn's end, given how hc counts the turn of a pasted local command (charting saw `send` answer turn 1 and the terminal reach done at turn 2); which bound that wait uses (the existing `DOOR_RESET_TURN_BOUND_MS` or its own); how the stand-in reports the rename turn so the test can show the reset arrives after it.
