## Decisions

- D1 (criteria 1-3, boundary): the parent captures the session record's byte length after the identity check and before detaching, as `statSync(path).size`, and hands it to the child through a new `DOOR_RESET_BOUNDARY` env var (same carrier as `DOOR_RESET_CHILD`). The config schema gains `DOOR_RESET_BOUNDARY: z.coerce.number().int().nonnegative()`; `child` throws when it is absent. Unreadable record at capture is a parent refusal: `refused: pane <pane> session record unreadable: <detail>` on stderr, exit 1, no log, nothing sent. Resolves the design's "how the boundary passes" open question: env var, so argv stays 4 arguments and the usage line is unchanged.
- D2 (criteria 1-3, record paths): one `recordPath(kind, live, session)` helper in `door-reset.ts` resolves the record to read: claude via peer-wait's transcript glob, codex via `codexRollout`, pi via `live.agent_session.value` when `agent_session.kind === 'path'` (the session arg equals it; a `kind: 'id'` pi session is unreadable). peer-wait.ts exports its claude transcript locator (the glob logic inside `claudeTurnOpen` extracted as `export function claudeTranscript(session): string`) and `claudeTurnOpen` calls it; `codexRollout` is already exported; peer-wait behavior is unchanged. There is no existing pi locator to export; pi's session value already is the record path (confirmed on this machine's `~/.pi/agent/sessions/**.jsonl` and the seats.yaml comment "for pi, session is the session file path"), so door-reset uses it directly.
- D3 (criteria 1-3, detection): `operatorInputSeen(kind, path, boundary)` reads `readFileSync(path).subarray(boundary)` (byte slice, per the peer-ask boundary comment), splits lines, and reports true on the first post-boundary operator-input record:
  - claude: `type === 'user'` with `origin.kind === 'human'`, or `type === 'attachment'` with `attachment.type === 'queued_command'` and `attachment.origin.kind === 'human'`. A `user` entry with `origin.kind === 'task-notification'`, a `user` entry with no `origin` (tool result), compaction summaries and meta entries carry no human origin and do not count. A `queue-operation` `enqueue` alone is not input.
  - codex: `payload.type === 'task_started'` on an `event_msg`, or `type === 'response_item'` with `payload.type === 'message'` and `payload.role === 'user'`.
  - pi: `type === 'message'` with `message.role === 'user'` (`toolResult`, `assistant`, `system` roles and `session`, `model_change`, `thinking_level_change`, `compaction` types do not count).
  Input shapes copied from real records on this machine: `/home/ivan/.claude/projects/-home-ivan-Work/044ccb5a-e794-455d-ac0d-c4e4da487e08.jsonl` (queued_command, 2026-10-02), `/home/ivan/.claude/projects/-home-ivan-Work/d674fa89-28f3-44d7-acda-5339e3304d30.jsonl` (task-notification, 2026-10-05), `/home/ivan/.claude/projects/-home-ivan-Work-infra-akrogon/0218f863-24eb-4467-9613-f9f6f4e21171.jsonl` (human user entries, 2026-10-05), `/home/ivan/.codex/sessions/2026/10/11/rollout-2026-10-11T19-46-35-01a12c12-d6b0-7d82-aa14-7acddfe4a526.jsonl` (task_started, user messages, 2026-10-11), `/home/ivan/.pi/agent/sessions/--home-ivan-.akrogon-worktrees-akrogon-cost-rules--/2026-10-26T10-26-12-959Z_01a177bf-115f-744f-b22d-e9c72f434b49.jsonl` (message roles, 2026-10-26).
- D4 (criteria 1-3, check placement): `waitTurnEnd` runs, per poll, `binding` → `operatorInputSeen` → `turnEnded`; input returns `{ step: 'wait-turn-end', result: 'superseded' }`. The recheck gains the input check after its identity re-read and before `send-reset`: input returns `stop(log, 'recheck', 'superseded')`. The recheck stays the last check before the send; the window between it and `agent prompt` is the design's stated limit. `child` exits 1 on `superseded` like every non-send stop, and the parent prints `queued` unchanged (the handover entry names the log, so the operator or fresh A finds the result there).
- D5 (criterion 3, unreadable handling): inside `child`, every record read is wrapped so a locator error, a missing path (claude 0 or 2+ matches, codex null rollout, pi missing file or non-path session) or a `readFileSync` failure returns `stop(log, '<step>', 'record unreadable', { reason })` — `wait-turn-end` during the wait, `recheck` at the recheck — sending nothing. `turnEnded`'s claude/codex reads share this wrapper so a record deleted mid-wait is logged instead of crashing main's catch. The parent path keeps its own stderr refusal (D1).
