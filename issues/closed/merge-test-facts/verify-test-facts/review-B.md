## Fixes

- **F1. The scan changes existing failure names.** The old multiline regex recognizes JavaScript line terminators. The new scan splits only on LF, then uses anchors without multiline mode in `src/flaky.ts:48-50`. Bun 1.4.5 emits a literal U+2028 in a test title. The same captured output includes `first` in the old scan and drops it in the new scan. With a CRLF wrapper, the old scan still finds the named failures and the new scan returns `(no test name)`. Fresh receipts and `failedTests`' legacy log reads both use the new scan, so known-red matching and flaky reporting can lose failure units. This violates the brief's unchanged-`failures` contract and design decision 6. Keep the legacy name behavior and cover the real line-terminator case. Evidence is `check-review-b-bun-streams-1795578777102-2337248.log`.
- **F2. Timeout attachment can cross intervening lines of the same stream.** `src/flaky.ts:56-71` overwrites the last failure on another failure and never clears it after a pass, ordinary output or a consumed caret. A real Bun suite that fails an assertion, runs a passing test and prints an example timeout diagnostic from a subsequent test attributes that diagnostic to the assertion failure. This gives maintainers a false timeout after the log disappears. Criterion 2 and design decision 2 require the caret to be the immediate next line of its own stream. The planned decoy follows a pass in a stream with no earlier failure, so it misses stale state. Cover a same-stream intervening line alongside the existing interleaving proof. Evidence is `check-review-b-timeout-adjacency-1795578823379-2362062.log`.
- **F3. A non-numeric title suffix can make the entire ledger unreadable.** `src/flaky.ts:49-63` accepts dots alone as the numeric part of a timing bracket. Real Bun emits the untimed line `(pass) understands the output form [...ms]` for a fast test with that title. The scan emits NaN as a duration and a JSON round trip produces `ms: null`. The merge writer serializes the row and `readVerifyRuns` rejects it under the new schema, blocking later ledger reads, including verify and merge receipt selection. Criterion 1 excludes untimed lines and requires integer ms. Parse numeric timing suffixes without changing the legacy failure grammar. Cover the real untimed title and successful ledger readback. Evidence is `check-review-b-timeout-adjacency-1795578823379-2362062.log`, including `serialized verify row parses false`.
- **F4. A real timed pass can be read as a wrapped failure for durations.** `src/flaky.ts:49-55` tries the legacy failure regex before recognizing the pass marker at the start of the line. Real Bun emits `(pass) keeps text | (fail) in a title [10.09ms]`, and the duration is stored under `in a title`. This drops the test's real title from the merge timing record and can merge its timing with a different test. Criterion 1 and design decision 1 require the anchored Bun test title. Keep legacy `failures` as-is while timing the anchored result. Evidence is `check-review-b-bun-streams-1795578777102-2337248.log`.
- **F5. The file reference obscures which field the legacy readers use.** The insertion in `docs/reference/files.md:71` separates the original reference to `failures` from “read it before the log” with three new fields, ending on `attempt`. A maintainer using the file reference to decide which field survives log removal can read the legacy rule as applying to `attempt` or to all new facts. The consumers in `src/flaky.ts:172-179` and `src/verify.ts:298-308` consult `failures`. Keep that field's note with its definition. The criterion 7 test at `tests/docs-links.test.ts:310` also matches the prose phrase “does not parse under an older akrogon” and passes with the required merge scope and per-leg placement removed. Keep mechanical assertions on literal field references and verify the documentation's meaning by reading the row.
