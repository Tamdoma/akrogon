# Brief: proof-rules

## What
akrogon's standing design, chart shapes, plan, implement and review skills state four taken testing rules, each once, in at most 20 added lines in the whole diff: (1) each done-criterion is proven by the cheapest sufficient test that catches its failure; (2) a producer-consumer chain across leaves has one spine that each stage-owning leaf plugs its stage into, recorded from real output where a model or outside service runs; (3) a leaf with a slow or live run fixes other leaves' bugs in its branch, reruns only what changed and what consumes it, runs every check whose prerequisites are valid, and proves its result at the final commit; (4) a writer and its checker share one rule, and a check whose result depends on group size is tested at real size. No `src/` change, no check removed, no new file.

## Why
Tamdoma/akrogon#41: the framework epic satellite-network-simplify's last leaf, live-replay, found 17+ cross-leaf defects one multi-hour run at a time over two to three days. Its own locks multiplied each defect (a new leaf per bug, a from-scratch run after every fix, a checker that stopped at the first failure). Two stage leaves never put their stage in the existing spine. Hand-authored recordings hid shape mismatches. Most defects (#10-#17) were catchable by a small test in the leaf that caused them. No akrogon skill ties a test to its cost or places integration proof.

## Done-criteria
1. `skills/chart-issues/assets/standing-design.md` states rule (1), including that cheapest counts creation and upkeep and that a real model or outside call can be cheapest when that behavior is under test, and that a slow or live run names what no smaller test proves. (A,C)
2. The same file states rule (2): trigger (one leaf's output, meaning data, files, state or build input, consumed by code another leaf owns); own code runs real; model and outside stages replay output recorded from one real run with source, revision or date and capture command, re-recorded never hand-patched; a leaf changing a prompt, model, settings, output shape or outside call runs one real call through its consumer and checks and re-records; that real call names the property it proves, and an outside change that makes a recording unreliable also triggers re-recording (C); the spine runs in the consumer's blocking checks, and a stage labelled real that fakes its result does not count (C); hand-written negative and edge inputs stay allowed; no live model run per merge.
3. The same file states rule (3): in-branch fixes bounded by no locked decision, feature or acceptance rule change, each with a fail-first test in the owning code's own tests; rerun every changed stage and every consumer of its outputs (shared files, lockfile and env count as inputs; unsure means restart from a trustworthy point); run every check whose prerequisites are valid, mark the rest blocked, the run still fails, product gates still stop the product, and follow-on failures are grouped under their root (C); stand-ins only in a separate diagnostic run that never counts as proof; final proof valid at the final commit, with a clean full run only when reuse cannot be shown or fresh start, order or whole-run behavior is under test.
4. The same file states rule (4): one rule definition shared by writer and checker, a model writer's instructions state it, a kept second copy says why and has an agreement test, tests keep independent expected results; a check whose result depends on how many items or choices exist states what it needs for the target count (counting what renders) and is tested at real size with the real pool (pass) and a too-small pool (the design's refusal); a model-judged such check tests one known-acceptable and one known-unacceptable case at target size and states what stays unproven.
