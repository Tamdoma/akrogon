### Signposts (forks/signposts.md, Taken)

Chosen signposts options:

- 1a: Who must show a call has one right answer before a script may decide it? → The proposer of the script names the single-right-answer source (a literal contract, a schema, a granted bound in the operator's own words). Without one, the call is the model's. Under autopilot the door never invents a number on model output.
- 2a: How is a model's choice proven? → Split record from choice. The record (choice, reason, evidence weighed) gets function checks only: it exists, keys valid, reason not blank. The choice itself has no expected value in any test; the review seat reads it on a run the leaf already makes or a recording it already has. A judgment never triggers a paid call by itself.
- 3a: When may the review seat block on a recorded judgment? → Only when it names a concrete harm on the recorded evidence: a fact the evidence contradicts, a missed required input, a broken function, a keep-list breach. A different taste is a Nit. No operator stop follows a judgment disagreement.
- 4a: What does the lens cover? → Every artifact that decides pass, fail or the next step: tests, done-criteria, product runtime gates, capture drivers, operator stops and the door's own autopilot picks.
- 5a: What happens to proxies that already exist? → No sweep. The lens applies when work next touches one: a seat that hits an existing proxy blocking valid work removes it in its branch with the reason under the existing deletion line, the review seat judges the removal, keep-list checks are never removed this way, and a proxy named in an existing brief is routed back as a wrong criterion, not enforced.
- 6a: Which calls stay the operator's? → Only what the operator alone can grant or know: spend, destructive or public effects, security, credentials, and any call the operator named as theirs in the intake or signposts. Never a per-item quality stop.
