# Brief: model-choice-rule

## What

Edit akrogon's lifecycle rule texts so that, from charting onward and under autopilot, a script decides only what has one right answer, and what a model is asked to decide is the model's choice: made by the model doing the work, recorded with its reason and evidence when a done-criterion or next step depends on it, and judged by the reviewing seat. No count, share, similarity score, keyword or output-text match, or per-item operator stop stands in for that choice unless a named source (the operator's words for this outcome, an outside standard or provider limit, a schema or literal contract) supplies the value. Function checks on model output keep blocking, and a mechanical rejection always overrides a model approval.

Owned files: `skills/chart-issues/assets/standing-design.md`, `skills/chart-issues/assets/questions.md`, `skills/chart-issues/assets/shapes.md`, `skills/chart-issues/assets/autopilot.md`, `skills/plan-issue/SKILL.md`, `skills/implement-issue/SKILL.md`, `skills/check-issue/SKILL.md`, `skills/lesson-rule.md`, `skills/learn-issues/SKILL.md`, `skills/AREA.md`, `docs/reference/skills.md`. The edits are prose; no script, registry, ledger, scanner or test is added.

## Why

Leaves built through akrogon keep shipping deterministic checks that make decisions the model was asked to make (Tamdoma/akrogon#140): count thresholds, text matches on model wording and per-item operator stops. They block valid model output, break when wording changes and force paid re-recordings; the serp-wireframing leaf lost 3 of 5 paid captures to a THIN_READ gate and a driver that matched model wording. Earlier fixes removed named checks and left the rules that create new ones, so new charts rebuilt the pattern within days. The operator, 2026-11-17: "I don't want the deterministic code to suffocate agent decisions" and "We still need testing, but only for the most important crucial stuff."

## Done-criteria

1. Every rule site that meets a model's choice states, in its own section, what that seat does with the choice and with a sourceless proxy for it, consistent with the design's binding decisions, and no sentence left in the owned files still orders a test, case, deliberate break, operator stop or proxy for the choice part: the chart round's removers, the handoff audit and its two proof-form lists, autopilot's pick limits, the standing design lines (the new line plus the scoped test-only-as-proof, cheapest-sufficient-test, regression-guard, slow-run, fail-first and writer/checker lines), plan.synthesis, implement, check.fix, Standalone and the Direct form, check.review and check.repair, the lesson rule's Seed clause, learn-issues' description, Sort and Apply, and the two docs that restate the Sort outcomes. Judged by both reviewing seats reading `implementation/report.md`'s site table (each old site, its new text and why the old path to a proxy is closed) against the diff.
2. Under the new text the serp-wireframing chain (an evidence fork proposing `thin_min_usable_page1` and a per-page operator answer, the audit accepting both, plan writing a red-first case per condition, implement building a gate and a capture driver that reads the model's wording, review calling the over-constraint a Nit) is stopped: the report walks each of the six steps and names the sentence that now changes its outcome. Judged by both reviewing seats.
3. Under the new text these still block, each walked through in the report and judged by both reviewing seats: a blank required rationale on a recorded choice, a spend bound in a grant, a threshold taken from an outside standard (an accessibility minimum), a process bound (a repair-round or retry limit), and a literal marker command code parses (`Handed off <date>`).
4. Links in the changed files resolve, and the readiness.yaml example in shapes.md still parses against the readiness schema, on the leaf head.
5. The report states what stays unproven: whether the next real charts and leaves stop producing proxies, which only later work shows.
