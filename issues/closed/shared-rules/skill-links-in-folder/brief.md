# Brief: skill-links-in-folder

## What

Every markdown link in a skill folder opens without stepping out of that folder. The five skills that send a seat to the shared lesson rule as `../lesson-rule.md` (plan-issue, implement-issue, check-issue, learn-issues, chart-issues) each get a link file `lesson-rule.md` inside their own folder, a git symlink to `skills/lesson-rule.md` in the way `skills/check-issue/ponytail.md` links implement-issue's file, and each links it by the same-folder path. `skills/lesson-rule.md` stays the one text; its two relative links to other skills (the Checkable definition in learn-issues under Seed, seed-issue's owner rule under Home) become references in words, because the file is now read from five folders. The repo's link check reads every tracked markdown file under `skills/`, follows each link file by its own path, and reports a relative link that points outside its skill folder or to a missing file. Text inside a fenced block is an example, not a link.

## Why

A skill folder is installed as one folder link per agent program (`planSkillLinks` in `src/install.ts`), so a path that climbs out with `..` only opens for a reader that follows the folder link first. A shell does. The read tools of claude and pi shorten `..` as path text and then open a path that does not exist. Recorded cost, read 2026-11-11: of 24 pi session files since 2026-10-14 that hold a read-tool call on lesson-rule.md, 21 hold `ENOENT: no such file or directory, access '/home/ivan/.pi/agent/skills/lesson-rule.md'`, the latest on 2026-11-09; claude's Read tool answers "File does not exist" for `/home/ivan/.claude/skills/chart-issues/../lesson-rule.md`. A link file inside the folder opens in all three: 149 pi read-tool calls on `check-issue/ponytail.md` with no failed access. The link check today reads only `skills/<name>/SKILL.md` and resolves a link as path text from the source tree, where `..` lands on a real file, so it cannot see this failure. Two later leaves, `lifecycle-rules-source` and `door-step-files`, add files this check must reach.

## Done-criteria

1. Each of the five skills names the lesson rule by a path inside its own folder, and on a layout where each skill folder is linked on its own that path opens to the lesson rule's text for a reader that shortens `..` as path text. No relative link in any tracked markdown file under `skills/` points outside its skill folder.
2. The lesson rule exists once: `skills/lesson-rule.md` holds the text, each in-folder `lesson-rule.md` is a git link to it and not a copy, and the rule's meaning is unchanged; only its two links to other skills became references in words.
3. The repo's link check refuses a broken skill link. It accepts every link in the delivered tree's skill files, the in-folder link files included. A relative link that points outside its skill folder, or to a missing file, is reported when it stands in a `SKILL.md`, in a file under a skill's `assets/`, or in a shared file read through an in-folder link file; a link-shaped text inside a fenced block is not reported. Proof: the link check inside the existing `test` command, by its known-good result and by one deliberate break turning it red. (A,B)
4. `skills/AREA.md` states once that a file shared by several skills is reached through a link file inside each skill folder and never through `../`, and the pages that point readers at `skills/lesson-rule.md` (`docs/reference/skills.md`, `docs/use/learn-from-work.md`) still open.
