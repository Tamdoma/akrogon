Comparison is on canonical paths: the nonexistent store suffix resolves against its deepest existing ancestor, so a symlinked root or ancestor cannot bypass it; equality and prefix siblings (`/a/repo` vs `/a/repo2`) are covered. `init` resolves the store before writing anything. Delete init's in-checkout .gitignore addition and the setup.md sentence "Only a store inside the checkout is gitignored." Reason: lock Boundary 2a already forbids an in-checkout store; this removes the class instead of guarding a case, and it deletes code. Commands that never resolve the store (status, pull) keep working on a refused repo. No migrator: ensureWorktree's mismatch refusal already names moving a recorded worktree. Rejected: 1b consumer-only migration (class stays armed), 1c delete the key (external overrides are legitimate; 31 test uses), checkLocation at config read (live ancestor state in config parsing), readRepo placement (blocks status/pull on a broken repo). ## Leaf architecture

Owned surfaces: src/config.ts `worktreeStore`; src/init.ts init's store resolution and `.gitignore` additions; src/guard.ts `guard` own-modules message; docs/guide/setup.md `worktree_root` bullet; the tests proving the criteria and the fixtures that set an in-checkout `worktree_root`, including tests/sync.test.ts `remoteFixture` and tests/init.test.ts `rootCases` (A,C).

- `worktreeStore(repo: Repo): string` keeps its signature and default. For a configured value it expands as today, then throws an Error naming `worktree_root`, issues/config.yaml, the resolved store and the checkout when the canonical store equals or lies within the canonical `repo.root`. `worktreeStore` canonicalizes both operands itself (A,C): `readRepo` realpaths the root, but `initialize` builds its Repo from raw `git rev-parse --show-toplevel` output, so the check must not depend on the caller. A canonical path is the realpath of its deepest existing ancestor joined with the remaining suffix. Reuse `within` from src/config.ts for the containment test.
- Consumers that resolve the store and so refuse on a bad config: src/verify.ts `runOnce` (before `checkLocation`, so no checkout is created), src/batch.ts merge batch dir, src/next.ts `ensureWorktree`, allocate and the must-create check, src/reconcile.ts `reconcileNeedsPanes` and the sweep, src/sync.ts (`akrogon sync`), src/self-update.ts (per repo, after merge), src/config.ts `effectiveConfig` (`akrogon config`). Each needs no change: a throw is the intended stop. Commands that never call `worktreeStore` (status, pull) keep working, so the operator can fix the file; after the file is edited, the next command reads the new config.
- src/init.ts: call `worktreeStore` before `writeRepoConfig` and every other write, and delete the in-checkout entry from `additions` (the `worktreeRoot !== root && within(worktreeRoot, root)` line). Open for the plan: whether `relative` and `within` imports in init.ts become unused.
- src/guard.ts `guard` own-modules: the stderr line keeps `missing own node_modules: <path>` and adds the `setup` remedy. `checkLocation` and the `ancestors` verb are unchanged.
- src/reconcile.ts keeps `<root>/issues/worktrees` as a legacy root; no change.
- Open for the plan: whether a helper for the canonical deepest-existing-ancestor path already exists (src/guard.ts `offendingAncestor` walks ancestors similarly but returns an offender, not a path) or a small local one is needed.
- Exclusions: no lockfile-derived installer, no check of package.json at config read, no change to `checkLocation`, no automatic worktree migration, no edit to skills/init-akrogon (it proposes no `worktree_root`).
