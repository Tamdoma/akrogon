# Brief: one-attempt-per-pass

## What
`dispatchSlot` (`src/next.ts:348-428` on origin/main) loses its `while (true)` loop. One invocation of `akrogon next`, whether typed by the operator or fired by the existing herdr plugin events (`plugin/herdr-plugin.toml:10-27`, unchanged, no new trigger), performs for one seat at most one `herdr agent start` when the pane has no agent and at most one `herdr agent prompt`, then returns. A retryable herdr failure (`agent_blocked`, `agent_not_ready`, `agent_prompt_stalled`, `timeout`, `wait_timeout`, `agent_wait_timeout`) is recorded in the leaf state as `delivery_error[slot] = { command, code, message, pane, session, at, offset? }` and the pass returns; the next pass observes the pane fresh and tries again. `attempts[slot]` counts failed deliveries in the current phase: it is charged only when a delivery fails, a successful prompt resets it to 0 and clears `delivery_error`, and the pass that records the third consecutive failure moves the leaf to `failed` in the same pass with `cause: 'attempts'` and reason `prompt undelivered to seat <slot> after 3 passes: <code> <message> (pane <id>, session <ref>)`. An ambiguous `timeout` from the prompt call is settled against the seat's pi session file: before sending, the pass records the file's byte length; after a `timeout` it parses the complete JSONL records appended past that offset and looks for a user message whose text equals the prompt exactly; found means delivered (`prompted`, `prompted_at` set, no error); not found records `delivery_error` with that `offset`, and the next pass re-parses from the offset before it resends, so a late arrival is recognized. The session file comes from herdr's `agent_session` reference: a `path` kind is read directly, an `id` kind is looked up as `$HOME/.pi/agent/sessions/*/*_<id>.jsonl`. A non-retryable or unstructured herdr error on start or prompt no longer throws out of the pass: the leaf moves to `failed` with reason `seat <slot> unreachable: <code> <message> (pane <id>)`, where an unstructured failure yields code `exit <status>` and the trimmed stderr as message, and the pass continues with other leaves. Recovery is unchanged: any move out of `failed` restarts the phase for both seats because commitMove clears done, verdict, prompted, attempts and now `delivery_error`. No timer, no watcher, no new automatic pass, no fallback input path.

## Why
On 2026-09-19 a check pass reported three retryable prompt errors on the B pane within 22 seconds, twice, four minutes apart, and failed the leaf with `attempts exhausted` while the pane held a live pi with an empty input box; the same pane accepted prompts before and after. The immediate resend loop burned all three attempts on one transient condition, the error was discarded after a `console.warn`, and the log line named A's session for B's failure (`src/log.ts:12-15`). Operator 2026-09-19: "1a | 2a | 3a" on `issues/chart/seat-prompt-delivery/forks/delivery-retry.md`; no clocks, no watchers, no new automatic programs.

## Done-criteria
1. `bun test` passes with new tests in `tests/next.test.ts` using `dispatchFixture` and `fakeHerdr` (extended to script a per-call failure code and stderr where it cannot yet): a retryable prompt failure charges `attempts.B` from 0 to 1, records `delivery_error.B` with the herdr code, message, target pane and session reference, sets no `prompted.B`, and the fake herdr received exactly one `agent prompt` call in that pass.
2. Three consecutive failing passes move the leaf to `failed` during the third pass, with `failure.cause = attempts`, `failure.slot = B`, and a reason containing the last code, the pane id and the session reference; a success between failures resets `attempts.B` to 0 so no failure occurs; a pass that starts the agent and then observes it not idle charges nothing.
3. Timeout settlement, with the CLI run under a temporary `HOME` whose `.pi/agent/sessions/<dir>/<ts>_<id>.jsonl` the test writes: a `timeout` with an exact-text user record appended after the pre-send offset records `prompted.B` and no error; the same prompt text present only before the offset, or only inside an assistant or tool record, records `delivery_error.B` with `offset`; an incomplete trailing line is ignored without discarding earlier records; a record appended after the timeout is recognized by the next pass before any resend; a `path` kind reference is read directly; a missing file counts as absent.
4. A pane with no agent whose `agent start` fails with a retryable code charges one attempt, records `delivery_error`, and the pass returns without an `agent prompt` call; the next pass with a healthy fake starts and prompts.
5. A non-retryable herdr code, non-JSON stderr, and a malformed JSON error object on prompt each move the leaf to `failed` with a reason starting `seat B unreachable:`, do not throw, and a second eligible leaf in the same pass is still dispatched.
6. A successful prompt clears `delivery_error` and resets `attempts` for that slot; `commitMove` clears `delivery_error` on every move (test through `akrogon phase`).
7. `akrogon status` appends `<slot> prompt <code>` to the NOTE column for each slot with a recorded `delivery_error` whose own seat is not busy, even when the other seat is busy; a legacy state without the field shows nothing new; existing status tests pass unchanged.
8. `docs/reference-index.md` and `src/AREA.md` describe the one-attempt rule and the timeout settlement; `bun run typecheck` and `bun run format` pass.
