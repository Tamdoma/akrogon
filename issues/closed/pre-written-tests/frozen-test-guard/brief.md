# Brief: frozen-test-guard

## What
On every move from `plan.synthesis` to `implement`, `akrogon phase` records in `state.yaml` every path the leaf branch changed against the target at that head, each with its content id, or absent when planning deleted it (A,B,C). On every later phase move of that leaf, the command refuses, naming each path and the exact `Test-Change: <path> <source and reason>` line to add, when a recorded path's content at HEAD differs from its record, or when the branch adds a path matched by `src/test-files.ts` that the record does not hold. The refusal clears only when the last commit in `<target>..HEAD` that touched the path, or a later commit, carries a `Test-Change` trailer naming it; trailers in earlier commits, including the planner's, do not count (A,B,C). Today's rule for changed or deleted pre-existing test files stays.

Owned files: `src/phase.ts`, `src/state.ts`, their tests under `tests/`, and the lines that describe when a phase move needs a `Test-Change` trailer: `skills/implement-issue/SKILL.md` (today `:64` only; `:84` belongs to `test-proof-rules`) (A,C), `skills/merge-issue/SKILL.md` (today the trailer sentence in `:51`), `skills/check-issue/SKILL.md` (today `:47` and `:83`, only if they conflict), the command-owned field sentence in `skills/chart-issues/assets/shapes.md` (today `:276`) (A,B), `docs/guide/merge.md` (today `:11`), and any other `docs/` or `README.md` line stating the trailer rule.

## Why
Tamdoma/akrogon#78 and the busy-seat-notice chart: framework `formspark-build-wiring` spent 263 and 230 minutes in two check.fix rounds building and repairing about 2,000 lines of proof code that no guard saw. The guard only checks modified, deleted or retyped files (`src/phase.ts:351`), so an added test or proof file is free to change, and the formspark proof runner at `.claude/workflow/scripts/run-formspark-build-wiring-proof.ts` matches no segment in `src/test-files.ts:1-17`. A trailer anywhere on the branch authorizes every later change to that path today (`src/phase.ts:355-366`). The operator chose that the planner writes tests before any product code and the executing seats cannot bend them (fork test-authorship, Taken Q1). A recorded commit sha would not survive leaf rebases (`src/phase.ts:666,700`, `skills/merge-issue/SKILL.md:49-53`), so the record holds paths and content.

## Done-criteria
1. Every move from `plan.synthesis` to `implement`, including one after a return from `failed`, writes a record in `state.yaml` of every path the branch changed against the target at that head, each with its content id or an explicit absent value for a path planning deleted; a leaf whose planning changed nothing gets an empty record; a leaf with no record moves under today's guard unchanged (A,B,C).
2. On a later phase move of a leaf with a record, a recorded path whose content at HEAD differs from its record (including a recorded-absent path that now exists, or a recorded path now missing) is refused with the path and the exact `Test-Change:` line to add, and accepted once the last commit in `<target>..HEAD` touching that path, or a later commit, carries a trailer naming it; an earlier trailer for the same path does not count (A,B,C).
3. On a later phase move of a leaf with a record, a path matched by `src/test-files.ts` that the branch adds against the target and the record does not hold is refused and accepted the same way.
4. A recorded path outside the `src/test-files.ts` rule, such as a proof script under `scripts/`, is guarded exactly like a recorded test file.
5. Criteria 2-4 give the same result after the leaf branch is rebased onto a newer target; when the rebase itself changes a recorded path's content because the target also changed it, the move is refused until a later trailer-only commit names that path (A,C).
6. A changed or deleted test file that existed at the target still needs a trailer as today, and the merge stack citation checks (`src/phase.ts:421,427,904`) behave as today.
7. The skill, shapes and docs lines this leaf owns describe criteria 1-6, and a sweep of `skills/` and `docs/` by meaning finds no line contradicting them; out-of-scope hits are listed in the report.
