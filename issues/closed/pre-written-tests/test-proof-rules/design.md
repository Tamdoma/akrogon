## Leaf architecture

- One machinery definition, by function, stated once in `standing-design.md` and referenced elsewhere (A,B). It names what machinery does (runs proof across cases: runner, dispatcher, session or port pool, fixture factory), never a file count. Existing fixture and cleanup helpers, the repo's test runner, and temporary repo or directory setup inside a test are not machinery (`tests/phase.test.ts:13-23` is the allowed pattern). The prohibition covers machinery built to prove the leaf's own product; a prerequisite leaf whose delivered product is reusable machinery is allowed and proves it with one known-good case green and one deliberate break red (A,B).
- Charting (`chart-issues/SKILL.md`, `shapes.md:286`): the audit gains the refusal and the prerequisite-or-narrow rule, and requires the product leaf's `blocked-by` entry naming the rig leaf, since only then does the rig exist at the product leaf's `AKROGON_BASE` (`src/next.ts:1319` releases on completion) (A,C). The existing rule that a part a producer could merge with its own proof becomes a prerequisite leaf (`shapes.md:286`, "no count, size or duration trigger") applies to machinery explicitly. The handoff review's live-run line names the existing machinery each live criterion uses.
- Planning (`plan-issue/SKILL.md`): the tests step sits in `plan.synthesis` only, after `plan.md`, before the move to `implement`. `plan.positions` and `plan.rebuttal` write no tests. The proof table (`:61`) gains the test path, its command and its recorded red output per criterion. The command must use a runner or script present at `AKROGON_BASE` or be one direct invocation of the product; the planned test files themselves are new (A,B,C). A criterion proven by an existing test or `checks` command names it and gets no new test. Formatting comes from the leaf's `checks`, not a separate format command, since akrogon config has no `format` key (`src/config.ts`) (A,C). A planner commit that adds a case to an existing test file carries the trailer `implement-issue/SKILL.md:64` already requires, because the guard runs at the `plan.synthesis` → `implement` move (`src/phase.ts:282,351`) (A,C).
- Implementation (`implement-issue/SKILL.md`, `brief-template.md`, `worker-protocol.md`): replace "Write the smallest test set proving every done-criterion before code" and its brief-template twin (`:13`, `:31`) with "run the planned tests"; keep "extend existing tests before adding files" only for the planner. Worker mismatch reuses `worker-protocol.md:15`. The Q2 correction is A-only and cites the brief line or real output; it is never a worker step. The worker trailer sentence (`brief-template.md:45`) goes, since workers write no tests. The red-on-base expectation fix at `implement-issue/SKILL.md:38` is already A-only and stays.
- Modes: inline has state, a worktree and the guard, so it follows the same rules with A as the only seat. Direct and standalone have no state, record or guard (`src/next.ts:300-301`), so for them the rule is order only: tests from the brief first, committed, then code (A,C).
- Review (`check-issue/SKILL.md`): delete `:55`. Add to the Nit rule that a Nit gets no test and no new issue. Narrow `:79` to the Q4 reproduction rule; its last sentence ("a new test needs no cited source") is replaced, since every added test now needs a trailer; the same goes for `implement-issue/SKILL.md:76` and `merge-issue/SKILL.md:55`. The planned-command and no-skip check sits in the `:53` region, beside the criterion-test check, not at `:47`, which belongs to `frozen-test-guard` (A,C).
- Stops (`implement-issue/SKILL.md:36`, `check-issue/SKILL.md:75`): the existing red-criterion exit becomes the required path when machinery or environment cannot run, not an option after repairs. B's live-run handoff to A stays for proven product defects that need a live rerun.
