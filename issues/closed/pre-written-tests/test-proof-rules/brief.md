# Brief: test-proof-rules

## What
Rewrite akrogon's charting, planning, implementation and review rules so that:
- seat A writes the few tests a leaf must pass during `plan.synthesis`, from the brief and plan, and commits them on the leaf branch before any product code. After that, workers, implement A and repair seats write and edit no test, with two cited exceptions: A corrects one wrong expectation (operator Q2 2a), and the seat fixing a proven bug adds one reproduction test shown red before the fix (operator Q4 1a).
- a test exists only as the proof of a done-criterion or as that bug reproduction, and review stops asking for tests on "what if" cases that have no realistic source.
- no leaf builds machinery to prove its own product. Machinery is code whose job is to run proof rather than be the product: a runner, dispatcher, session or port pool, or fixture factory that orchestrates cases. A planned test may use the repo's existing test runner, fixture and cleanup helpers, and temporary repo or directory setup inside the test (A,B). Missing machinery is a prerequisite leaf whose delivered product is that machinery, proven by one known-good case passing and one deliberate break failing, and the product leaf lists it in `blocked-by` (A,B,C). Otherwise the door narrows the criterion. A leaf whose proof cannot run because its machinery or environment is unsuitable ends the pass with `failed --reason`.

Owned files: `skills/plan-issue/SKILL.md` (the `plan.synthesis` section, today `:59-69`), `skills/implement-issue/SKILL.md` (today `:36`, `:53-57`, `:76`, `:84`, and any inline, direct or standalone line that orders tests and code; not `:64`), `skills/implement-issue/brief-template.md`, `skills/implement-issue/worker-protocol.md` (today `:15`, `:25`), `skills/check-issue/SKILL.md` (today `:51-55`, `:75`, `:79`; not `:47` or `:83`), `skills/merge-issue/SKILL.md` (today `:55` only), `skills/chart-issues/assets/standing-design.md` (today `:8-10`, `:15`), `skills/chart-issues/SKILL.md` (the handoff review's live-run line), `skills/chart-issues/assets/shapes.md` (today the audit at `:286`; not `:276`), `docs/guide/phases.md`, and any other `docs/` or `README.md` line stating the old test-authorship or proof-machinery rule (A,C).

## Why
Tamdoma/akrogon#78 and the busy-seat-notice chart. Today the seat executing the code writes the tests that grade it: workers derive tests before code (`brief-template.md:31`) and inline A writes product and tests (`implement-issue/SKILL.md:57`). Review can add tests every round through the missing-test Fix (`check-issue/SKILL.md:55`). In framework `formspark-build-wiring` every unit test and check was green (selftest 3491/3491), and every red item was a live proof run through a rig the leaf built itself: about 2,000 lines across `run-formspark-build-wiring-proof.ts` (+1346), `lib/blueprint-run.ts` (+434) and `lib/blueprint-fixture.ts` (+378). Review findings F7-F12 were all defects in that rig, and its two check.fix rounds took 263 and 230 minutes against a 24-minute median over 353 framework leaves. The slowest leaves (emdash-launch 840, formspark-build-wiring 494, emdash-offer-join 488, offer-join-deploy 423 minutes) all built or repaired proof machinery inside the leaf. No rule names who builds a rig or requires one to exist before the leaf (`standing-design.md:9`). Research the chart used: tests written from the task before seeing the code caught 25% of injected faults vs 14% after (arXiv 2607.05139); locked tests stopped direct test edits (Busel, dev.to, 2026-10-10); more agent-written tests added cost without raising success (arXiv 2602.07900; Dan Luu, 2026-09). The operator asked for few, purposeful tests prepared beforehand by the main agent, never by the executing sub-agents, with everything kept inside the same leaf.

## Done-criteria
1. `skills/plan-issue/SKILL.md` has A, in `plan.synthesis` after writing `plan.md` and before moving to `implement`, write a test for each done-criterion that no existing test or `checks` command already proves, from the brief and plan only, at the smallest real boundary (one test may prove several criteria, and a case may extend an existing test file); run the leaf's `checks` commands so that every remaining failure is a planned test's intended red (A,C); show each new test red for the missing or intentionally broken behavior and record that output in `plan.md` beside its criterion; and commit them on the leaf branch with no product code, a commit adding a case to an existing test file carrying the `Test-Change` trailer today's rule requires (A,C). `plan.md` names the test and the command for each criterion.
2. `skills/plan-issue/SKILL.md` requires each criterion's proof command to use a runner or script that exists at `AKROGON_BASE`, or to be one direct invocation of the product, while the test files and inputs it runs may be new in the planner's commit (A,B,C); a plan that would need new proof machinery ends `plan.synthesis` with `failed --reason` naming the criterion and the missing machinery.
3. `skills/implement-issue/SKILL.md`, `brief-template.md` and `worker-protocol.md` say workers, implement A and check.fix A write and edit no test; sub-briefs give workers the planned tests and their command to run instead of tests to write; a worker that finds a planned test wrong returns a mismatch and waits; only A corrects one wrong expectation, in its own commit, with a `Test-Change` trailer citing the brief line or real output; a wrong criterion ends the pass with `failed --reason` naming the decision.
4. Inline mode follows criteria 1-3 with A as the only seat, under the same phase guard as delegated mode; direct and standalone modes, which have no state or guard, follow only the order: tests from the brief first, committed, then code (A,C).
5. `standing-design.md`, `implement-issue/SKILL.md` and `brief-template.md` state that a test exists only as the proof of a done-criterion or as the red-first reproduction of a real bug, and no longer allow adding edge or negative cases after planning on a named consequence alone; a consequential edge case is a done-criterion written at charting.
