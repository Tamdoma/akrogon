# Brief: peer-restart

## What
The chart-issues door gets one command that restarts its named consultants with an empty context: `bun <skill-folder>/scripts/peer-restart.ts <root> <A pane> <seat> <pane> [<seat> <pane>...]` (seat letters as recorded, active consultants in naming order) (B,C). Before closing anything it reads each seat's harness kind (`herdr agent list`) and launch argv (`herdr pane process-info`, the process whose pid equals `foreground_process_group_id`) and refuses unsafe launches (B,C). It then closes the consultant panes in reverse order, recreates them with the split sequence the skill already uses for created peers (first active consultant right of A at 0.65, each later one below the previous at 0.5, `--cwd <root>`) (C), starts each with `herdr agent start <name unique to this door and seat> --kind <same kind> --pane <new pane> -- <same argv[1:]>` (B), and prints one JSON line per seat with its state. The skill says when the door runs it, what authorizes closing supplied consultant panes, and what a failure means.

## Why
Consultants keep one session for the whole door pass, so every exchange re-reads finished charts (Tamdoma/akrogon#99: B 7.4M input for 19k output over three charts). The operator chose restarting panes over `/clear` plus warm-up messages.

## Done-criteria
1. Given seat B (codex, launched with `-c model_reasoning_effort=high`), seat C (pi, launched with an argument containing a space) and an unrelated live agent elsewhere, the command closes C then B, creates B right of A and C below the new B, starts each with the same kind and identical argv as separate arguments, leaves the unrelated agent untouched, prints `restarted` with the new pane for each seat letter, and exits 0; given only seat C (B dropped earlier), C keeps letter C and is created right of A (own test against the repo's fake herdr, in `bun test`) (B,C).
2. The command closes nothing, exits non-zero and names the seat and reason when a seat's pane has no unique foreground process-group leader, its argv restores or forks history (codex `resume`/`fork`; pi `--continue`/`-c`, `--resume`/`-r`, `--session`, `--session-id`, `--fork`; claude `--continue`/`-c`, `--resume`/`-r`, `--session-id`), or its agent name is held by a pane outside the restart (own test, one case per reason) (B,C).
3. A failure of close, split or start, including a failure after another consultant was already closed, stops all later steps, exits non-zero, prints the failed herdr command with herdr's error, and prints every seat's state: `restarted` with its new pane, `closed`, or `untouched` (own test, one case per failure point) (B,C).
4. SKILL.md, assets/questions.md and docs/guide/chart.md state: the door runs the command when it enters a chart before that chart's first consultant exchange, and again when it re-enters a chart after the consultants worked on another chart (one run before a shared opening map covers the map; A's own work or compaction alone never triggers it; only after every prompted exchange is collected, which the caller ensures and an idle pane does not prove (C); never for a dropped consultant); named consultant panes, supplied ones included, may be closed by this command only, as the operator-authorized exception to the rule that supplied panes are never moved; later briefs, waits and seat entries use the printed panes; a restarted seat's new seats.yaml entry keeps its letter and is appended when herdr shows its new session (pi at start, codex after its first exchange), never with a null session (B,C); a failed restart ends the turn when attended, and under autopilot every seat not `restarted` is dropped like a herdr prompt refusal with its printed state recorded (B,C).
