# Brief: chart-usage-table

## What
Each chart records its own usage, so the operator can see whether charts got cheaper and faster without a paid search through transcripts. At open the door writes a seat record into the chart: the open time and, per seat, pane, harness kind and session id. A read-only script, `skills/chart-issues/scripts/chart-usage.ts`, reads those sessions' transcripts for the chart's time window and writes a usage table into the chart, in tokens and minutes only. The door runs it before the handoff review and again when the chart ends, and the handoff review shows this chart's summary next to the summaries of earlier charts. The leaf branch owns `skills/chart-issues/`, the script's tests and fixtures under `tests/`, and the guide pages that list chart files. It changes nothing under `issues/`; tests use temporary chart folders.

## Why
Chart cost and time were measured by hand on 2026-10-06 with one-off scripts in the door's own session. That cost several dollars, and each chart's sessions had to be found by searching transcripts, because a chart does not record them. Transcripts provide the usage and timing records this leaf reports. The link from a chart to its sessions and the door's restatement count are captured separately. This leaf does not measure characters of leaf files written before and after review, grade quality or establish dollar savings (B).

## Done-criteria
1. `skills/chart-issues/SKILL.md` Open says: when the chart folder is created the door writes `<chart>/seats.yaml` holding the open time, which is the time the door began its first pass on this chart, before the opening map, (B) and, for A and each named peer, the pane, harness kind and session id as `herdr agent list` prints them, and adds an entry whenever a seat's session id changes. Before the chart folder exists the open time and the seat entries stay with the door's temporary files, and neither folder creation nor a replacement session resets the open time (B). Outside herdr the record holds the open time and no session, and the table says usage unmeasured. The door asks the operator nothing new.
2. `bun <skill-folder>/scripts/chart-usage.ts <chart-folder> [<until>]` reads `seats.yaml`, finds each seat's transcript by searching that harness's own home directory for the session id (C), counts the records from the open time to `<until>` (default: now), writes `<chart-folder>/USAGE.md` and prints this chart's summary line, the summary lines of the sibling chart folders that hold a `USAGE.md`, and an outcome word as its last line (C). It writes nothing else and calls no model. A second run replaces the table.
3. The table holds, per seat: harness kind, each model and effort value found in the transcript, turns, assistant messages counted apart from turns for a Claude seat (B), working minutes, tokens by the classes that harness records, and the first turn of the seat that starts inside the window on its own row, labelled first turn in window, with no such row for a seat's later sessions (B,C). The table says that this row is not the whole map cost when the map took more than one turn (B). It holds one row per operator message in A's transcript with its start time, the minutes until A's reply ended and each seat's output inside that span, labelled operator turns and never forks, plus the total operator wait. It holds the restatement count from `seats.yaml`. For a Claude session that has ended it also shows the dollar total that session recorded, labelled as a whole-session figure. It shows no other dollars. `USAGE.md` and the chart guide state that the window's tokens and minutes show that usage and elapsed time changed and not that dollar cost fell, that a whole-session dollar total can include other charts and is not this chart's cost, that subagent usage is not counted, and how a turn and the operator wait are defined (B,C).
4. No model name, effort level, price or rate is written in the script, the skill text or the guide. Model and effort appear in a table only as values read from a transcript.
5. Counting is exact on fixtures with independently known totals: a Claude message streamed as several records with one message id counts once; codex cumulative counters are read as differences and never summed; a codex counter reset is handled or reported as an explicit error; records outside the window are excluded; two sessions listed for one seat are added. Token totals match the known totals exactly. Timing fixtures cover tool-result and harness-generated user records, which start no operator turn, and an unfinished turn, which is labelled incomplete and given no invented end (B).
6. A session whose transcript is missing or lacks a needed field gives that seat a row saying usage unmeasured with the file and the field, the other seats are still measured, `USAGE.md` is written with that row, and the script prints `outcome partial` as its last line and exits 0. It exits non-zero only when `seats.yaml` does not parse or the chart folder is missing (C). `SKILL.md` says the door reports that line in the handoff review and continues: a failed measurement never holds a handoff.
7. The table and the printed lines hold ids, times, numbers and the model and effort values, and never message or tool text: a fixture whose message bodies carry a marker string produces output without that marker.
8. `SKILL.md` says: when the door records a fork's answer it adds to `restatements` in `seats.yaml` one for each restatement request it answered on that round, judged by meaning and with no word list, and the fork's Taken keeps the sentence saying how often the round was restated (B,C); the door runs the script right before the handoff review and shows the printed lines there; the door runs it again when it appends `Handed off`, `Held` or `Closed`.
9. `skills/chart-issues/assets/shapes.md` lists `seats.yaml` and `USAGE.md` in the chart records tree with one line each. `docs/guide/chart.md` and `docs/guide/files.md` are read for the list of chart files; a hit is updated, otherwise the implementation report states none was found.
10. One live run on the three sessions and the window recorded in the design gives the recorded reference totals exactly, or the implementation report names the record class that explains each difference. A transcript no longer on disk at that time is reported as such.
11. The destination's `test` check passes. `src/` and `issues/` are unchanged on the branch.
