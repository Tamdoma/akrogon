# Brief: peer-notes-single-writing

## What
The chart-issues skill text changes how A and the named peers exchange work, while the operator round keeps every part it has today. For a fork each peer returns blind notes and no longer a full round. A's merged file is compact notes, the peers rebut that file, and A writes the full operator round once, after the rebuttals. The round template gains register rules and a "How to choose" line. Every peer task travels as a brief file with a one-line prompt. At handoff, A corrects the reviewed draft leaf files and those files are moved to `issues/open/`, with no second writing. The human guide is updated to match. Repository copy only: `skills/chart-issues/` and `docs/guide/chart.md`.

## Why
After the 2026-10-05 skill updates a chart costs more and takes longer per fork. Measured on the charts of 2026-10-05 and 2026-10-06: each peer wrote a full formatted round per fork that A then rewrote, A wrote every round twice (file and chat) with 40-46% shared wording, the operator asked for a simpler restatement after nearly every round, and at handoff A wrote every leaf file twice (13.5k characters before peer review and 22.7k after on merge-turn). The operator keeps the door's behavior: named peers, blind exchange, one rebuttal, the same round.

## Done-criteria
1. `skills/chart-issues/assets/questions.md`, Blind peer exchange, the fork paragraph: the sentence "Each returned peer file is a full round, not a reaction to A." is replaced so that for a fork each returned peer file holds blind notes per question, the peer's own position and not a review of A, with five parts: the pick with its reason and cost, each rejected option with the reason, the evidence with tier, source and date, the pitfalls with what removes each, and any question the peer would ask that the fork does not ask. What a peer receives and what is excluded from it stay as they are. The opening-map sentence stays as it is.
2. `skills/chart-issues/SKILL.md`, Take, the named-peers sentence: it says A merges the completed independent notes, that A alone writes the formatted operator round, and that a merge tag cites only a line the peer wrote. The rebuttal, the focused final-shape check, the restatement exemption and the peer-wait clause stay.
3. `questions.md`, the paragraph starting "After all finish": the merged file is compact notes holding each option with its slot tags, reason and cost, the evidence lines, each pitfall with the step that removes it, open questions and the points where slots differ. Each named peer rebuts that file once. A writes the full operator round once, to the operator, after the rebuttals, with the rebuttals under the challenge check. No second full-round file is written, and the record is the merged notes plus the fork's Findings and Taken. The final-shape, restatement and direct-request sentences stay.
4. `questions.md`, the round template and the paragraph starting "Every round uses this shape": the template gains a "How to choose" line after the options, shown only when the options trade off, saying which answer is the safe one and when to pick the other. The paragraph gains the register rules in the skill's own words: everyday words, simpler than explaining to an 18-year-old who does not know the process; each process word explained the first time; each actor named by what it does for the operator and explained in one sentence on first use; each part says only what the decision needs while every part of the round and every number the decision depends on stays; time in minutes, and money in dollars only where a recorded figure exists, never from a rate the door assumes (C); file names, slot letters and token detail in a sentence only when they help the operator decide; before sending, A reads the round once against these rules and fixes what fails. No operator alias name and no word count appears.
5. `questions.md`, Blind peer exchange: every peer task (opening map, fork notes, rebuttal, focused final-shape check, leaf review) is a brief file, and the prompt is a one-line pointer naming the brief's absolute path and the peer's slot letter. The brief is finished before the prompt and not edited during the exchange, a new exchange gets a new brief or a new return path, the brief uses absolute paths and holds what the peer is to receive plus the exact return path, and briefs live under `<chart>/slots/` and stay in the chart, with the existing temporary-path rule before the chart folder exists. The sentence "Every peer prompt gives the exact output path." becomes: every peer brief gives the exact absolute return path, and the prompt names only the brief's absolute path and the slot letter (A,B,C). A fork-notes brief points at the note definition in the Blind peer exchange section of questions.md and does not restate its parts, while still giving the task, the permitted context and the return path (B,C). The confirmed-start check, the no-automatic-re-prompt rule and every wait rule stay.
6. `SKILL.md`, Handoff, the leaf-writing sentence: after the peers' review A corrects the scratchpad draft files, keeping one final scratchpad version per leaf with changed-line tags and any held disagreement carried into the leaf design, and those files are transferred by name into `issues/open/`, state last and prerequisites before dependents, after the existing collision and preflight checks. The contracts are not written a second time. Every proof, the presence check, the grants and both reviews stay.
7. `docs/guide/chart.md`, the peer paragraphs (near lines 162 and 201): peers return notes, A writes the round, and reviewed drafts are moved. `skills/AREA.md` and `README.md` are read for a sentence describing the peer exchange or leaf writing; a hit is updated, otherwise the implementation report states none was found.
8. No model name, effort level or price appears in any changed text. No new command, script, config field, file kind or lifecycle state. Reading the changed Take, Blind peer exchange and Handoff paragraphs in order gives one consistent procedure: brief, blind notes, merged notes, one rebuttal each, one round written by A, operator answer, and at handoff draft, review, correct, move.
9. The destination's `test` check passes, which proves the guide's links and the shapes example still hold after the text edits. `src/`, `tests/`, other skills and `issues/` are unchanged on the branch.
