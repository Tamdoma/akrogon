# Brief: core-skills

Chart skill version: 4

## What

Write the five family skills under `skills/`: `plan-issue` (sections positions, rebuttal, synthesis; synthesis also runs alone when `debate: no`; reads the top index and `learnings/LESSONS.md` as resources and writes the read-first list into the plan), `implement-issue` (the eight-section brief with the 2026-09-10 additions: needed interfaces in the change list, the mismatch rule in the worker's do-not, an advisory size line in the steps, a report naming changed files, tests, limitations and unverified criteria as a four-line fill-in skeleton at the end of the brief; the launch prompt carries one reminder line; a worker return whose report lacks any of the four contents is sent back to the worker, a worker turn, not a check.fix round; reads `implement` from `akrogon config` and with `inline` implements the brief itself in order with no worker; workers, `test_changed` against `AKROGON_BASE` read from `akrogon config`, the full suite once by B, a worker returns a mismatch instead of changing scope and B revises the brief, a red full suite becomes one more sub-brief, B repairs itself on the last allowed round, docs and area index lines updated, a lesson recorded when found; in this repo the brief carries the scenario-test rule from # Command Tests), `check-issue` (review with `--verdict`, blocks only for a real defect, Nits, re-check of the repair diff only, verifies docs, index lines and lesson claims, rejects mocks of the unit under test and wording tests, slot A's diagnosis paragraph appended to `plan.md` when `akrogon phase` prints `moved failed`), `merge-issue` (rebase, checks, fast-forward push, ancestry check after a lost push reply, findings into `review-A.md` and `check.fix` on conflict or red checks, same-line index conflict keeps both entries, `merged`, broadcast writer only when the command reports the issue complete), `broadcast-issue` (message rules for a cheap subagent, one message per completed issue, sent to the `broadcast` targets from `akrogon config`, the webhook read from `~/.config/akrogon/env` only and a loud failure when it is missing, no env file in the skill folder, one retry, no record). Each under 300 lines, 4k tokens, 20 rule sentences, must/never with a stated exception, references with read-when triggers, the compaction first lines, the printed `Last operation` and `Next` footer and its backup read (first 50 to 100 words of the other pane, confirm only), peer answers as files, Pocock's four lines, ponytail copied into implement and check. Delete `skills/consult-issue` and `skills/explain-issue`. `chart-issues`, `seed-issue`, `init-issues`, `create-issue`, `braindump-issues`, `consolidate-issues` stay until their own leaves.

## Why

The first automated leaf must run the complete loop, so every skill the routing table names exists before it (# Bootstrap, handoff 1-A).

## Done-criteria

1. Each of the five skills is under 300 lines, 4k tokens and 20 rule sentences, counted once by the operator, and its first lines say: after compaction re-read this file, the slug's brief or plan, and this phase's references.
2. Every phase section name matches the routing names in the design (plan.positions, plan.rebuttal, plan.synthesis, implement, check.review, check.fix, merge) and every section ends with `akrogon phase <slug> <next> --slot <A|B>` (check.review adds `--verdict`) and the two printed lines; no skill runs `akrogon next`, reads pane text for state, or parses YAML (it reads `akrogon config` output).
3. implement-issue writes `implementation/brief.md` with the eight sections under 1,500 words (section 4 with the worker's needed interfaces, section 5 with the mismatch rule, section 6 with an advisory size, section 8 ending with the four-line report skeleton). With `implement: subagents` from `akrogon config` it delegates each sub-brief to a subagent with the brief path, the worktree path and the one reminder line, sends back a return whose report lacks any of the four contents without touching `fix_rounds`, runs `test_changed` per worker with `AKROGON_BASE` from `akrogon config`, and handles mismatch returns as the design says. With `implement: inline` it implements the brief itself in order with no worker, running `test_changed` as it goes. In both modes it runs the full suite once, handles a red suite as the design says, updates affected docs and index lines, and records a lesson when it finds one; the brief's commands section lists `test_changed` only. Invoked with no leaf in the prompt, implement-issue runs standalone on the prompt text as the task in the current checkout: same brief, same worker protocol, changed tests, self-repair, no config, no state, no log, no checker (the template and protocol read nothing outside the skill folder).
4. check-issue judges the whole diff with ready, nits, or fix through `--verdict`, blocks only for a real defect (slot A reads its own positions-A.md and rebuttal-A.md first; a Fix cites a done criterion, a failing check or a reproducible defect; a finding grounded only in A's position is a Nit with its reason), re-checks the repair diff only, verifies docs, index lines and any lesson claim, rejects mocks of the unit under test and, in this repo, a test that asserts wording, and appends the diagnosis paragraph to `plan.md` when `akrogon phase` prints `moved failed`.
5. merge-issue's text (a Nit slot A still holds and finds reusable becomes one lesson line plus history file) rebases on the configured `<remote>/<default_branch>` (origin/main by default), reruns every `checks` command, pushes fast-forward only, checks ancestry on a lost reply, writes findings to `review-A.md` and moves to `check.fix` on conflict or red checks, runs `akrogon phase <slug> merged` after the push, and spawns the broadcast writer once only when that command prints `issue complete` (verified by text in this leaf; the live run is leaf `status`).
6. A fresh agent given only one skill and the prompt line `<skill> <slug> slot=<A|B> phase=<phase>` finds no reference to removed machinery (gates, audit phase, QA pass, driver, series, category, handoff file), checked by the operator reading each skill once.
7. The 32-line `AGENTS.md` from github.com/DietrichGebert/ponytail (the copy `ponytail.md` beside this brief in the leaf folder) is present verbatim as `ponytail.md` in `skills/implement-issue/` and `skills/check-issue/`; `skills/consult-issue` and `skills/explain-issue` are deleted.
