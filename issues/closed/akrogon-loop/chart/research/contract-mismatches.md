3. **Who writes `state.yaml`.** `skills/consult-issue/SKILL.md:276` and `:321` require creation through `createIssueState(execRoot, slug, created[, seedPath])` (`issues/.scripts/lifecycle.ts:773-781`), which hardcodes `phase: 'P-draft'` at line 778. `skills/chart-issues/assets/materialization-contract.md:81-90` and `skills/create-issue/SKILL.md:70-74` have the skill hand-write the YAML file directly. `createIssueState` is also not exposed on the CLI at all (`issues/.scripts/lifecycle.ts:2133-2139` lists only `--self-test`, `--audit-bridge`, `phase`, `resolve`, `status-read/write/verdict`, `transition`, `advance`), so the consult-issue instruction is unexecutable from a skill anyway.

4. **`state.yaml` field set.** `issues/.scripts/lifecycle.ts:27-33` and `:399-407` define the issue state as exactly `slug`, `phase`, `created`, optional `seed_path`, and `issues/.scripts/lifecycle.ts:768` rewrites the file from those four fields only on every transition. `skills/chart-issues/assets/materialization-contract.md:83-90` adds `priority` and `repo` as carried fields. ## Smallest change that makes one flow

Make the intake side emit the lifecycle's phase vocabulary and let the lifecycle side accept the intake's file names. Concretely: change `phase: consult-position` to `phase: P-draft` in `skills/chart-issues/assets/materialization-contract.md:86` (with `created` as the full git ISO timestamp, not a date), and add `priority` and `repo` as optional passthrough fields to `IssueState`, `parseIssueState`, and the two writers at `issues/.scripts/lifecycle.ts:27-33`, `:399-407`, `:768`, `:778` so a transition stops dropping them; then have `create-issue`/`chart-issues` also create the empty `planning/` and `implementation/` `plan.md` shells (seeded from `brief.md` + `design.md`) plus `a.md`/`b.md` scaffolds so `consult-issue`, `implement-issue`, and `check-issue` find their canonical inputs, or alternatively repoint those three skills' Canonical Input sections at `brief.md`/`design.md`. The series shape needs one pick, not a merge: either the intake writes the nested `issues/open/<series>/SERIES.md` + series `state.yaml` + `NN[ps]-` marker leaf directories that `parseSeriesRows`/`assertSeriesMatchesPhysical` already parse, or `parseSeriesRows` (`issues/.scripts/lifecycle.ts:618-642`) is rewritten for the flat `SERIES-<slug>.md` `Order | Leaf | Path | Dependency barrier` table. The park and approval disagreements resolve for free once phase parses, since `park.hold` is already config-gated off in `issues/config.yaml`; the remaining required edit is to `skills/create-issue/SKILL.md:79` and `:81`, which currently forbid the mid-flight holds the four downstream skills depend on.
