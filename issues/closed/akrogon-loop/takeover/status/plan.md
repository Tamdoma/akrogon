## Open limitations

- L1: The brief's manual takeover command requires timing clarification if the first review is already complete. Live `src/phase.ts` accepts `--verdict` only during `check.review`, refuses a slot already in done, and rejects `--verdict` during `merge` (although `merge -> check.fix` itself is allowed). Therefore `akrogon phase status check.fix --slot A --verdict fix` is valid only while A can still record its review, not after both ready verdicts advance the phase to merge. Do not change phase/routing in this leaf. If review naturally requests repair, this limitation does not affect the proof. Otherwise the operator must coordinate the allowed intervention before A's review transition. This plan does not claim the live proof is complete.
- L2: Status is an unlocked diagnostic read. Concurrent state/log writes may produce a brief state/log mismatch or an explicitly reported partial scan, and missing history cannot establish elapsed phase time. Do not introduce locks, retries, a watcher or another state store to conceal this limitation.
