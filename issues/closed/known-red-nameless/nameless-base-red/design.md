## Binding decisions, verbatim

### Signposts (issues/chart/known-red-nameless/forks/signposts.md), operator's answers, 2026-11-09: "1a | 2a | 3a | 4a | 5a | 6a"

- 1a: The 2026-10-10 lock (issues/chart/red-base-wait/forks/comparison.md Q2 2a: a red that names no test is "unverified, never known-red, and blocks"; foreclosed "command-exit comparison; crash exemption") reopens narrowly: a configured check whose red names no test may be covered by the same red on its base. A missing log or an unfinished run still never covers. Foreclosed: keeping the lock whole; the same non-zero exit covering any command.
- 2a: The leaf must still prove its own change by its done-criteria; untouched work hidden by the same base failure does not stop it. A red the leaf's diff could have caused is never covered. Foreclosed: every hidden unit must run first; hidden work waived whenever the red is covered.
- 3a: The command checks function only (same command, both red, both runs complete, both logs present) and the seat judges the cause from the two logs and the diff, as it does today for named test failures. Different checkout paths in the output do not disqualify. Foreclosed: the command deciding alone by identical output and exit.
- 4a: No new configuration: no per-check kind or marker a consumer repo must set.
- 5a: Every existing known-red route for a configured check (implement end, review, merge, direct landing) follows the one changed rule. Nothing else moves: done-criterion proofs stay blocking, and the herdr-setup check and its stopped leaf stay outside this chart.
- 6a: No paid calls and no live changes: local tests on isolated fixtures, red before and green after. No replay on the herdr-setup leaf.

### Coverage rule (issues/chart/known-red-nameless/forks/coverage-rule.md), A's picks under autopilot, 2026-11-09, checked by B: "1a 2a 3d"

Q1 1a. `knownRedReceipt` stops refusing a red head entry for `(no test name)` and still refuses `(log gone)`. Everything else in it stays: the whole eligible head row, exact `name` and `command`, a completed base run linked through `compares` at the current merge-base, base entry red and not blocked, every head name among the base names, blocked head entries skipped, at least one red entry. Results: a nameless head is covered by a nameless red base entry of the same command (new); a nameless head against a named base, a named head against a nameless base, and a gone log on either side are not covered; named pairs are unchanged. `failedTests`, `flips`, `newRedUnits`, `verifyRunSchema`, `runOnce` and scheduling do not change. No new configuration, receipt field or output comparison.
Rejected: a uniform gate without name comparison (hands the working machine refusal of a named mismatch to judgment alone); equal exit codes (different failures share exits, and the October lock foreclosed exit comparison).

Q2 2a. One rule in the known-red paragraph of skills/implement-issue (Shared context), skills/check-issue (check.review), skills/merge-issue (red verify) and landing step 3 of skills/chart-issues `## Direct route`. A known-red exit 0 counts as passing only when the seat's judgment agrees, and the judgment is runner completeness and causal fit, meaning one of: the red command logged a real test name and that name also fails on the base (unchanged); or the red command's log names no test on the head and on the base, and the seat, having read both logs whole, finds that the head shows no failure the base lacks, judged in substance and never as exact text, that the command ended by its own verdict and was not killed, timed out or crashed, and that the leaf's diff holds no plausible cause. A command that ended by its own verdict with an ordinary error, a missing input or a load diagnostic is not excluded for naming no tests. When both logs exist but show too little to establish a cause, the seat withholds agreement and the existing blocking path applies. In both cases the leaf's own done-criteria proofs must pass on their own; a cover never stands in for them.
Rejected: a blanket test-runner exclusion (a second classification with no setting behind it).

Q3 3d. The sentence "A check recorded `blocked` in a verify receipt did not run, so the check named as its blocker is fixed first" gains one exception in the same four places: when the blocker is a known-red the judgment agrees with (named or nameless), the blocked check stays recorded as not run, is named as not run in the seat's record and never reported as passing, and does not by itself stop the leaf. A done-criterion whose proof is a blocked check cannot be shown, so that leaf stops under its existing rule. A blocked entry never covers on the base (unchanged code). No blocked command is run by the seat or by `--known-red`.
Stated cost: while the base check is red, a leaf can pass review and land without its `full` checks or `merge_checks` having run on it.
Rejected: the blocked rule unchanged (leaves akrogon, `full: [test]`, and framework, `merge_checks`, stopped by the reported class); the seat running blocked checks itself; `--known-red` running them.

Pitfalls avoided, binding: a gone log never covers; the name reader and its reporting consumers are untouched; every seat path keeps receipt eligibility and recorded causal agreement as two obligations; a blocked check is never reported as passing; every refusal case that stays true under this rule is kept.

Each skill states the rule in its own seat's terms (its own record file), as the paragraphs do today.
- Open for the plan: whether `noTestNames` stays as a one-entry list or the guard names `(log gone)` directly; whether the existing fixture helpers produce a nameless failing script and a merge-scope pair as they are; which doc-phrase assertions in tests/docs-links.test.ts touch the changed sentences.
