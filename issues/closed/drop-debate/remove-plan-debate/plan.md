## Decisions

- **D1 Historical phase enum.** `src/routing.ts` exports `retiredPhaseSchema = z.enum(['plan.positions', 'plan.rebuttal'])`, `historicalPhaseSchema` (every live phase plus the retired two) with the one-line comment that it exists because `issues/log.jsonl` history is never rewritten, `HistoricalPhase`, and `historicalSlots(phase: HistoricalPhase, rounds: number): readonly Slot[]`, which returns `['A', 'B']` for a retired phase from a small `Record<RetiredPhase, readonly Slot[]>` table and `requiredSlots(phase, rounds)` for a live phase. `phaseSchema`, `routing` and `failed.next` lose both retired phases.
- **D2 History schemas.** `logSchema.from`/`to` (`src/log.ts`), every phase field of `timingEventSchema` (`src/timing.ts`, both `seat.phase`, `checkCore.phase` and `visit_start.phase`) and `failureSchema.phase` (`src/state.ts`) use `historicalPhaseSchema`. `stateSchema.phase`, `routing`, `transition` and the `akrogon phase` argument parse keep `phaseSchema`.
- **D3 Legacy key strip.** One exported helper in `src/config.ts` returns a parsed YAML object without a named key and passes any non-object through untouched for the strict schema to refuse. `src/config.ts` also exports `parseRepoConfig(raw)` = `repoSchema.parse(<helper>(raw, 'rebuttal'))`, called by `readRepo` and by `initialize` in `src/init.ts` for both the proposal and the existing config. `readState` calls `stateSchema.parse(<helper>(parsed, 'debate'))`. `stateSchema` loses `debate`, `repoSchema` loses `rebuttal`. `saveState` needs no change: the loaded `State` has no `debate`, so the next save writes none.
- **D4 `effectiveConfig`.** It prints the parsed config spread and names no `rebuttal`, so it needs no edit; the strip in D3 removes the line from `akrogon config` output. The akrogon repo's own `issues/config.yaml` keeps its `rebuttal: true` line (design: nothing under `issues/` is touched); it loads through the strip.
- **D5 Guards.** Delete the "Destination contradicts rebuttal config" guard in `src/phase.ts` `transition` and the "Debate leaf skipped its debate" guard in `src/next.ts`, plus any import those leave unused (`existsSync`/`resolve` in `src/next.ts` stay if other code uses them).
- **D6 Open for the plan: other `Phase` consumers of log or timing values.** Found: `src/timing-report.ts` `Visit.phase` takes `HistoricalPhase` and `visitGaps` calls `historicalSlots`. All other readers only compare a historical value with a live one, which typechecks unchanged: `visitOf`/`currentVisit` in `src/timing.ts` keep a `Phase` parameter (every caller passes a live state phase), `src/status.ts:182`, `src/turn.ts:114`, the `plan.` prefix grouping at `src/timing-report.ts:345`, and `skills/watch-issues/scripts/observe.ts:208` (prints `failure.phase` as text). `src/run-check.ts` `LeafTarget.phase` comes from live `state.phase` and stays `Phase`. `bun run typecheck` is the enforcement: any further consumer that assigns a historical value into a `Phase` slot fails it and takes `HistoricalPhase`.
