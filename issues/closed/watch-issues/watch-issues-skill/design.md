# Design: watch-issues-skill

## Binding decisions, verbatim
From `issues/chart/watch-issues/forks/watch-policy.md`, Taken 2026-09-19 (operator answers quoted there):
- Q1: every leaf under `issues/open` of the registered repo, re-read at each fire; repo-scoped `akrogon next --all` from the registered root allowed. Foreclosed: captured set, run manifest.
- Q2: 20 minutes.
- Q3: one skill owning its job; `/watch-issues` creates the job when none exists for that root with prompt `/watch-issues tick <root>`; `tick` never creates; `stop` deletes; a tick never recreates a deleted or expired job. Foreclosed: `/loop` as the documented start, a second skill.
- Q4: unlimited judged recovery bounded by the move log; every required seat quiescent and state re-read before a move; human prerequisite never recovered. Foreclosed: killing, send-keys, lead `phase failed`, state edits.
- Q5: stop on empty readable open tree or all remaining leaves human-blocked and shown; a merged leaf under open gets one `next` and its error reported. Foreclosed: renewal.
- Q6: no ledger; unknown history means no recovery claim; `failure.delivery` decides re-notification. Foreclosed: snapshot script, history file.
From `issues/chart/watch-issues/forks/seat-loops.md`, Taken 2026-09-19: Q1-A loop evidence for every harness and for subagents through the parent screen; stop then resteer (`esc`, settled wait, pane read, one corrective prompt), mid-turn steer only when tools are visibly completing; akrogon's event pass re-prompts the phase and charges the attempt, the watcher writes nothing; once per seat, then notify. `esc` on a seat confirmed looping is the operator's explicit exception to the no-kill lock. Foreclosed: `phase failed` for a loop, a second stop, harness test matrix.
Locks: herdr only, no webhooks; never kill a working process; never open `.env`; no core watcher, timer or poll in akrogon (`issues/chart/seat-stall-detection/CHART.md`).

Standing design: `/home/ivan/.claude/skills/chart-issues/assets/standing-design.md`. Interpretation: no auth, no secrets, no user-visible flow; the skill never reads the env file; tests are fixture-driven with negative cases (unreadable state, missing pane); the walk-through in criterion 5 is the end-to-end artifact, run against a scratch `AKROGON_HOME`, never the live store.

## Leaf architecture
Owned: `skills/watch-issues/SKILL.md`, `package.json`, `bun.lock`, `tsconfig.json`, `scripts/observe.ts`, `scripts/observe.test.ts`; one install test case. Convention: `skills/broadcast-issue` (skill-local package, `bun <skill-folder>/scripts/<name>.ts`, `bun install --cwd`).

`observe.ts <root>`: reads `issues/open/**/state.yaml` through a zod schema with the same field names as `src/state.ts` (phase, repo, attempts, blocked-by, pane, busy_since, busy_notified, failure optional), refuses a state whose `repo` is not the key registered for `<root>` (`akrogon config`), calls `herdr agent list` once (command path injectable for tests) and joins on `pane_id`, prints one line per leaf, e.g. `slug=one-attempt-per-pass phase=implement attempts=A0,B1 blocked= A=w8:pB6/idle B=w8:pB7/working+0h14m notified=` and for failed `failed=attempts@check.review delivery=shown reason="fix rounds exhausted"` or `failed=unknown`. Read-only; no state write. Exit non-zero with the cause on unreadable or invalid state, wrong repo, or a herdr call that exits non-zero or returns non-JSON; a pane absent from the list prints `status -`.

SKILL.md sections. Invocations: `/watch-issues`, `/watch-issues tick <root>`, `/watch-issues stop`; Claude Code only, ends with one sentence when CronCreate is absent; job identity is the exact prompt `/watch-issues tick <root>`; zero/one/several behavior per invocation as in the brief; start never creates a job when its own check already satisfied the stop rule. Observe: the script under a Bash timeout; `herdr agent read <pane> --lines 60` for one seat when the evidence warrants it; `issues/log.jsonl` filtered by repo and slug for the recovery bound. Judge, one rule per case:
- waiting: at least one required unfinished seat idle or absent, phase not merged or failed: `akrogon next <slug>`; the command guards the other seats. Several such leaves: `akrogon next --all` from the root.
- merged still under open: `akrogon next <slug>` once; if it stays, report the completion error and keep the watch.
- failed, `failure.reason` names a credential, permission, operator decision or external step, or the record is `unknown`: no recovery; when `failure.delivery` is not `shown` and this fire has not yet shown it, `herdr notification show "<repo>/<slug> needs you" --body "<reason>" --sound request`; either evidence counts as shown for the stop rule; after a lost context carry the notice may repeat.
- failed otherwise: re-read state; every required seat of `failure.phase` idle or absent; compute the cycle count from the log (unknown history means notify-only); when the two most recent recoveries were both unproductive, notify and leave; else `akrogon phase <slug> <failure.phase>` then `akrogon next <slug>`.
- busy: `herdr agent read <pane> --lines 80` for every busy seat, judged against the brief. Working normally, or waiting on a long command: no action. Looping (same command or edit three or more times with the same result, three or more consecutive errors, edit-undo) or a concrete action outside the brief, or a hung tool with concrete evidence (fatal message, exited process): stop and resteer once: `herdr agent send-keys <pane> esc`; `herdr agent wait <pane> --timeout 10000`; read the pane: idle seat, empty input, same session, else notify; `herdr agent prompt <pane> "<evidence>; the brief wants <target>; next: <step>"`, naming a looping subagent so the parent corrects it with its own controls. Akrogon's event pass re-prompts the phase itself. Same seat still looping on the next fire: notify with the evidence, no second stop. A mid-turn steer (`herdr agent prompt` without `esc`) may be tried first only when the pane shows tools completing. Insufficient evidence on screen: say so, no action.
- command error from `next` or `phase`: re-run `observe.ts`, report, no further mutation this fire.
Stop: after judging, when `observe.ts` prints no leaf, or every leaf is failed on a human prerequisite with delivery evidence shown: CronList, delete the one job with the exact prompt, say so; several matches are reported, none deleted. Never list: kill an agent process, close a pane, `esc` twice on one seat per watch, `phase failed`, edit `state.yaml`, worktrees or `issues/`, open `.env`, answer a seat, create a job from a tick, Bash timeout on `next` or `phase`. Reply: at most five lines per fire.

Excluded: any change under `src/`, `plugin/`, other skills; the ad hoc `tick.sh`; the #18 artifact copy; any question-answering path (seats never ask); persisting a notification result (the skill cannot write `failure.delivery`, so dedup beyond the context carry is accepted as absent). Dependencies: none; the handed-off `seat-prompt-delivery` leaf changes what a pass does on delivery failure but this skill only calls `next` and reads the failure record, so it needs no ordering.
