# Brief: watch-issues-skill

## What
A new skill `skills/watch-issues/` (`SKILL.md`, `package.json`, `bun.lock`, `tsconfig.json`, `scripts/observe.ts`, `scripts/observe.test.ts`) that the operator invokes in a Claude Code lead session at a registered repo root before stepping away. Three invocations share one job identity, the exact prompt `/watch-issues tick <absolute-root>` (root quoted when it holds spaces):
- `/watch-issues`: one check; when the check does not already satisfy the stop rule and CronList shows zero jobs with that prompt, create it with CronCreate (`*/20 * * * *`, recurring) and report the id and the 7-day expiry; one existing job is reported, several are reported without creating or deleting.
- `/watch-issues tick <root>`: one check; never creates a job.
- `/watch-issues stop`: delete the one job with that prompt; zero reports already stopped; several are reported without deleting.

A check runs `bun <skill-folder>/scripts/observe.ts <root>` (read-only: every `state.yaml` under `issues/open` parsed with the command's field names, joined with one `herdr agent list` call, one line per leaf: slug, phase, attempts, blocked-by, per seat pane id, live status, busy age and whether the core busy notice was sent, and for a failed leaf its cause, phase, delivery and reason, or `failure=unknown` for a legacy record), then judges with the rules in SKILL.md: `akrogon next <slug>` when at least one required unfinished seat is idle or absent, `akrogon next --all` from the root when several leaves wait; recover a failed leaf with `akrogon phase <slug> <failure.phase>` then `next` when the reason is not a human prerequisite, the record is complete, every required seat of that phase is idle after a fresh read, and the move log does not show two consecutive unproductive recoveries; for a busy seat, read its last 80 lines against the brief and, on a loop (same command or edit three or more times with the same result, three or more consecutive errors, edit-undo) or a concrete action outside the brief, stop and resteer it: `herdr agent send-keys <pane> esc`, wait for a settled state, confirm an idle seat with an empty input by reading the pane, then one corrective prompt naming the evidence, the brief's target and the next step (a subagent by name, corrected through its parent); akrogon's own event pass re-prompts the phase and charges the attempt; a seat still looping on the next fire is notified, never stopped twice; a mid-turn steering message may be tried first only when the seat's tools are visibly completing; notify with `herdr notification show ... --sound request` on anything else it may not act on; delete its own job when the open tree is empty or every remaining leaf is failed on a human prerequisite that has been shown. It never kills an agent process, closes a pane, edits `state.yaml`, worktrees or `issues/`, opens the env file, answers a seat, runs `phase failed`, or creates a job from a tick. `akrogon install` links it like every other skill; no installer change.

## Why
Overnight the only thing that caught every stall was an ad hoc cron in the lead session (Tamdoma/akrogon#25). Core detection is ruled out (charts `seat-stall-detection`, `stall-notifier-removal`). The operator wants the same judgment as one opt-in skill for the rare nights they cannot react, with the fewest moving parts: no ledger, no snapshot script, no second orchestrator.

## Done-criteria
1. `bun test` from the repo root passes with `scripts/observe.test.ts`: fixture trees (waiting, mixed A working and B idle, busy with and without core notice, failed blocked, failed attempts, legacy failed without a failure record, merged still under open) and a fake herdr produce the documented one line per leaf; a missing pane prints `status -`; an unreadable or schema-invalid `state.yaml`, a state whose `repo` is not the root's key, and a non-zero or non-JSON herdr response each exit non-zero naming the cause, never an empty inventory.
2. `bun run typecheck` and `bun run test` in `skills/watch-issues` pass; `bun install --cwd skills/watch-issues --frozen-lockfile` succeeds.
3. SKILL.md carries, in prose an implementer can follow without this chart: the three invocations with their zero/one/several job behavior; the judgment rules for waiting, merged-under-open, failed human prerequisite, failed otherwise, busy, looping or off-scope seat (evidence, the stop-and-resteer sequence with the pane read before prompting, the once-per-seat bound, subagents through the parent, all harnesses), and command error; the recovery bound computed from `issues/log.jsonl` (all records for the repo and slug in order; a `failed -> P` move whose next record for that slug is `P -> failed` is an unproductive cycle; two consecutive cycles end recovery and notify; missing or malformed history means unknown, so notify-only); the notification evidence rule (persisted `failure.delivery: shown` or this fire's own `shown` response counts; a lost context carry means the notice may repeat, accepted); the quiescence prerequisite with a fresh state read; the stop rule with one `akrogon next` for a merged leaf under open and the error reported when it stays; the Claude Code requirement and the refusal to claim a watch elsewhere; the Bash timeout rule (read-only commands only; `akrogon next` and `akrogon phase` unbounded, an interrupted mutation re-read before anything else); and the never list.
4. `akrogon install` in a scratch `HOME` links `skills/watch-issues` into the four harness roots with no code change (existing install test extended or a new case).
5. A recorded walk-through in the implementation report against temporary registered repos (fixture config rewritten to scratch paths, every herdr call including notification and tab rename routed to a fake command, cron simulated by invoking the tick rules by hand): one failed-attempts leaf recovered, the same leaf failing again from the same phase recovered a second time, a third identical failure notify-only; progress between two failures resets the count; one failed-blocked leaf never recovered; mixed A working and B idle dispatches B; a looping seat in a fake pane transcript yields the esc, wait, read, prompt sequence once and a notification on the next fire; an empty open tree reaches the stop rule. Real CronCreate and CronDelete behavior is checked by the operator on first use, not by this leaf.

Credentials: none. Human prerequisites: none.
