In practice

12 · A working day

What you actually do, hour by hour

Morning

start

Open herdr. The plugin runs akrogon pull --all and akrogon next --all. Merged leaves from yesterday are cleaned up, new GitHub issues land in issues/seeds/, and every ready leaf starts up to the seat limit. If you would rather choose what starts, set max_active: 0 before opening herdr, then raise it and run akrogon next <folder> yourself.

Bring your checkout up to date with the code that merged overnight:

akrogon sync

Adding work

any time

In your own agent session, run /chart-issues. It imports pulled seeds, asks what it must, and writes the leaf. A small clear item goes straight to handoff. Or write the two files by hand. Then akrogon sync. The next hook call, or akrogon next, picks it up.

Watching

glance, do not stare
akrogon status                 # this repo's open leaves, phase, age, blockers; every repo when run outside one
akrogon status rename-flag     # one leaf's state and last ten log lines
akrogon status --charts        # every chart: taken/total forks, fog items, stage, age
                               # status also lists parked issues per repo
herdr plugin log list --plugin akrogon   # why the hook did or did not act

Or read the tab. A on the left, B on the right. Or read the leaf folder: plan.md, review-A.md, review-B.md.

Answering

when asked

An agent showing a startup dialog or a permission prompt is blocked on a human. Answer it in the pane. The hook sees the status change and continues. No attempt is counted against the leaf.

A failed leaf shows a herdr notification. Read review-A.md and the last paragraph of plan.md, fix the brief if the brief was the problem, then:

akrogon phase rename-flag implement

Evening

stop

Close herdr, or just leave it. Every leaf's phase is in its file. Nothing is lost. Tomorrow's startup sweep resumes from the files. The last tab that merged closes itself. If one is still open, the startup sweep closes it.

Run akrogon sync once more so the day's issue files are on the remote.

12 · Use cases

The questions that come up, answered

I have one epic and one normal issue. Can they run in parallel?

Yes, by default. Every ready leaf in every repo competes for the same seats. If the epic has three unblocked leaves and the global max_active is 3, the epic can take all three and the issue waits for the first merge. Set the optional max_active in that repo's issues/config.yaml to cap its share. The tool does not balance between folders.

I only want this epic to use the free seats

akrogon park --all
akrogon unpark search

Park everything, then unpark the one epic. Parked folders sit in issues/parked/ and no sweep touches them, not the hook and not the startup next --all. When the epic is done, akrogon unpark --all brings the rest back. Running leaves cannot be parked, so park before you start the day. To keep one leaf inside an epic from starting, give it a blocker or set hand_built: true.

I want to stop today and do it in a different order tomorrow

Nothing is remembered between runs except state.yaml. Edit the blocked-by lists of the leaves that have not started. Add a slug to make one wait, remove a slug to free one. Then run next. Two limits: a leaf that already has a tab keeps running whatever you edit, and you can only name leaves, so to make issue 2 wait for a whole epic, name the epic's last leaf.

I want to run one leaf by hand

Set hand_built: true. next skips it. Do the work yourself in a branch, and move its phase with the same akrogon phase commands the agents use. Useful for the first leaf of a new repo, before you trust the loop there.

I want to send a leaf back

Edit phase in state.yaml to implement, then akrogon next <slug>. The state file is the only truth. If the leaf is failed, use akrogon phase <slug> implement instead, which also resets the fix counter.

I want to stop one running leaf

Close its tab. Nothing restarts it until the next next, and that will reopen a tab and re-prompt the current phase. If you want it to stay stopped, add a blocker or set hand_built: true first.

I want to pause everything

Set max_active: 0 in the global config. Running leaves finish their current phase and then nothing new is prompted for leaves without a tab. Leaves that already have tabs keep going.

Two leaves touched the same lines

Nothing to do. The merge rebase conflicts, the leaf goes to check.fix, B resolves it in the same worktree, A re-checks the repair, then merges.

A skill needs changing

Skills only change through akrogon leaves in the akrogon repo. File a seed there. Once merged, every agent on the machine sees the new text at its next prompt, because the skill folders are symlinks.
