14 · When things go wrong

What you see, what it means, what to do

You seeIt meansDo
Startup dialog in a paneThe agent is blocked on a prompt only a human can answer.Answer it. The hook continues. No attempt is counted.
attempts climbing to 2The prompt did not take, twice.Look at the pane. The third try goes to the other pane as a stand-in. After that the leaf fails.
phase: failedThree fix rounds, or three prompt failures.Read the reviews and A's diagnosis at the end of plan.md. Fix the brief if needed. akrogon phase <slug> implement.
Leaf never startsA blocker is not merged, it is hand-built, or every seat is taken.akrogon next <slug> prints the exact reason.
Push rejected at mergeAnother leaf landed first.Nothing. A fetches, rebases, retries.
Merge conflictTwo leaves touched the same lines.Nothing. It goes to check.fix, B resolves, A re-checks.
"Transition refused"The agent called phase twice.Nothing. The first call worked.
"Issue files on leaf branch"B committed something under issues/ on the branch.B removes it from the branch and writes it in the checkout instead. The skill text tells it so.
"Uncommitted work in …"B tried to hand off with a dirty worktree.B commits. The rule exists because two leaves once passed review with all work uncommitted, and the cleanup deleted it.
Rebase conflicts on akrogon syncYour checkout and the remote both changed the same file.Resolve, then git add -A && GIT_EDITOR=true git rebase --continue && git push. With the code-only rule this should no longer happen for issue files.
Broadcast did not arriveThe webhook env is missing, or the merge pane closed before sending.Check ~/.config/akrogon/env. Send it by hand with the sender script from the skill folder, using the issue's briefs.
A lingering tab or worktree after mergeThe startup sweep has not run yet.akrogon next --all, or restart herdr.
"Unrelated worktree"A folder at the worktree path belongs to a different repo.Remove it by hand. A worktree parked mid-rebase is fine and is dispatched normally.
