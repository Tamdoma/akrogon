# Chart issues

Dependency: the installed `akrogon` command. This door runs under No autopilot by default, not a lifecycle phase; only the operator's words can switch it to Semi-autopilot or Full autopilot for a session (`## Autopilot`).

The lifecycle rules this door shares with the other seats live in [lifecycle-rules.md](lifecycle-rules.md). The door's record file for its paid charting-probe budget — n, m and the reason — is the fork's `## Charting proofs` record, with logs kept in the chart's `direct/` capture holder. The door sizes and raises that budget like a seat.

## Shared context

Ground in docs first.
Challenge fuzzy terms.
Verify with a concrete scenario.
Check the live surface.

Read [questions](assets/questions.md) before an operator round, [shapes](assets/shapes.md) before creating a chart or handing off, and [standing design](assets/standing-design.md) when preparing leaf designs.

Ask operator questions in printed chat text, never through a question tool. Decision rounds, including prerequisite and handoff choices, follow [questions](assets/questions.md) and include a reply key.

## Open

In the first reply, name each operator-supplied consultant terminal by its hc address in naming order — the first named consultant is B, then C, D and so on — and say that supplied consultants are used as given, never moved, killed or restarted, or say single slot when none is named, and name the mode and who answers the signposts; under autopilot the first reply follows [autopilot.md](assets/autopilot.md) for its other contents; read `akrogon config` and use its registered repo root for chart and handoff writes, resolving worktrees through their shared Git common directory rather than their inert issues copy. An unregistered repo can be charted locally, but handoff requires a registered destination; registration and initialization are outside this door.

The door is inside hc when `HC_TERMINAL_ID` is set and `hc get $HC_TERMINAL_ID` answers; outside hc the door says it is outside hc and continues single slot or with supplied consultants. The door's address is `$HC_TERMINAL_ID` as A reads it at the moment of each use; a recorded address in a summary, `seats.yaml` or the Mode record is history, never routing; and A resolves the value and writes the literal, never the variable name, into briefs and helper arguments — a literal `$HC_TERMINAL_ID` in a brief expands to the consultant's own terminal. Every rule in this file, questions.md and handover.md that names the door's or A's address uses this definition, covering the column helper calls including `--save` and `--restart`, each brief's report step, A's `transcript.ts` lookup, Mode and seat entries, the door-reset.ts target argument and the handover start prompt. When the operator asks for consultants without naming terminals and the door is inside hc, the door creates them, asking once for the model and effort of every created consultant and for its harness except C, whose harness defaults to `pi`; an operator-named harness, model or effort wins. Each created consultant starts at its first exchange with `akrogon seat --slot <x> --harness <harness> --model <model> --effort <effort> --task "You are slot <X>. Read and follow <brief path>"`, run from the door's terminal: it starts as a child of the door named `<prefix>-slot-<x>`, in the door's tab and folder and unboxed, prints its address, and its 60 s start proof is the first ask's delivery proof; a failed start ends the turn with the printed result reported. After a consultant is added or removed the door runs `herdr-consultant-column <door address> <consultant address>...` over the door-created consultants in seat-letter order, which lays the door out on the left and one column of consultants on the right at equal heights. Supplied consultants are never passed to the column helper, never moved, killed or restarted, and keep their context. A column helper exit saying the door is not in a tab, when the helper was called with the live address, is recorded once in the round's log and the round continues; any other non-zero exit is a check-in for A, never a stop.

Door-created consultants restart with an empty context when the door enters a chart, before that chart's first consultant exchange, and again when it re-enters a chart after the consultants worked on another chart; one run before a shared opening map covers the map, A's own work or compaction alone never triggers it, it runs only after every prompted exchange is collected (the caller ensures this and an idle consultant does not prove it), and a dropped consultant is never restarted. For each door-created consultant still active the door runs `herdr-consultant-column --save <door address> <consultant address>...`, `hc kill <address>`, `hc rm <address>`, the same `akrogon seat --slot` with the seat's recorded recipe and the next exchange's task, then `herdr-consultant-column --restart <door address> <consultant address>...` with the new address in the old one's place, so the operator's dragged sizes stay; it never touches A, supplied consultants or other terminals. A restarted seat's new seats.yaml entry keeps its letter, with its new address and its transcript path once known, never with an unknown path. A failed restart ends the turn with the printed result reported; under autopilot each seat whose restart failed is dropped with that result recorded under `consultant:`.

At open, capture the current UTC time immediately before starting `akrogon pull`. Use it as the pull time for the decision check. Report an unregistered or non-GitHub repo and continue charting, while any other failed refresh blocks a drain relying on that refresh rather than permitting stale mirrored intake; independent operator notes can continue.

Read the configured `grounding.index` top file, relevant linked areas and `learnings/LESSONS.md` as resources and report absent resources as gaps. Reusable findings get one mechanism/date/history-path line in LESSONS.md and a case/evidence/learning file at `learnings/history/<date>-<slug>.md` ([lesson rule](lesson-rule.md)), with historical lessons treated as observations rather than rules. A mirrored GitHub seed holds a decision section when a heading line starts with the full form `## Operator decision (<name>, <date>)`. Use a name and a date in `YYYY-MM-DD` form, separated by a comma and space. Any suffix starts after the closing parenthesis. A line inside a fenced code block is not a heading (the door's reading), so a quoted template or example never counts. The lock is the text under that heading up to the next `## ` heading: the body is free, `Not in scope:` and `Done when:` are locked when present and never required, and sub-headings inside it use `### `. A mention in prose is not a marker, text the section points to is not locked, and operator notes and legacy `issues/open/<slug>.md` paths never count. A decision-like heading that does not match is named in the opening map as "marked differently, not taken". Right after the pull, for each seed holding a decision section, the door reads the issue with `gh api graphql -f query='query{repository(owner:"<owner>",name:"<repo>"){issue(number:<n>){author{login} lastEditedAt userContentEdits(first:50){totalCount nodes{editor{login} editedAt}}}}}'`, then for each distinct login runs `gh api repos/<owner/repo>/collaborators/<login>/permission --jq .permission`. The section counts when the author and every body editor read `admin` or `write` (`maintain` reads as `write` in that field), using `permission`, never `role_name`. Any other permission, a failed read, `totalCount` above 50 (the door's reading: the edit list is longer than the read returns, so the read failed), or a body edit at or after the pull time makes the section "marked, not taken" with the reason. Compare `lastEditedAt` to the recorded pull start at GitHub’s timestamp precision. An edit with the same timestamp may have landed during the pull. A body edit at or after the pull time or a failed read gets one retry at that open. Capture a fresh pull time before the retry and repeat the pull and checks. The opening map names the deciding login. The permission read is proven only with an admin caller; a write-level caller and the Moderate role mapping are unobserved.

Each counting section becomes one fork file at import, right after the account check, in the seed-decision fork shape in [shapes](assets/shapes.md): taken, never asked. It is shown first in the opening map, in the signposts round's opening paragraph, in every consultant brief's carries as a lock, at the handoff review, and under autopilot in the pass-end line. A line saying the decision settles another open fork is labelled the door's reading (A's under autopilot), and the operator may correct it. Taken stays taken: the account check is not re-run on a later open. A section that does not count is plain intake in every mode, with no fork file and the reason in INTAKE.md `## Agent findings` and the opening map; under No autopilot the operator may take it in words in the door, which writes the fork the same way with the section verbatim and the operator's words and date, labelled taken in the door, while silence leaves it not taken; under autopilot it is an ordinary fork per [autopilot.md](assets/autopilot.md). A decision section that appears after import is read at the next door open, never mid-chart, by comparing each GitHub source's current mirror with its INTAKE.md copy. While the chart is open the door runs the same test and check, appends a dated `## Source` block to INTAKE.md with the first copy untouched, and writes the fork as above; a taken fork it contradicts goes to the finding rule in `## Take`, and a replaced section that counts is a dated correction under the decision's `## Taken`. When the chart is handed off or closed, or the identity is in a leaf's `sources`, the new section is named only, and under autopilot also in the pass-end line. A taken section later removed from the seed leaves the fork taken: the door names the absence as a fact, and only the operator's words change it.

At open, name each skipped GitHub identity that is still open on GitHub and offer `akrogon close <owner/repo#n> --by <text>` for it. During the pass, run that command for any identity the chart records as delivered or duplicate, passing what delivered it: the delivering leaf slug and commit, or the other identity. A confirmed full match with no other owner whose work is undelivered is exempt and stays open as `sources` until its completion owner delivers. One further exception: a report whose close depends on a step on main that can only follow a leaf's merge is withheld from closing `sources`, and the door closes it after making and verifying the edit, not at leaf completion.

The seat record holds the open time, the time the door began its first pass on this chart, before the opening map, and one entry per seat holding the hc address, the hc name (null for A and supplied consultants), the launch recipe (`harness`, plus `model` and `effort` for door-created consultants) and `session`, the transcript path `bun <skill-folder>/scripts/transcript.ts <address>` prints, covering A and each named consultant. The chart folder and `<chart>/seats.yaml` are written at Open; neither a later chart folder nor a replacement session resets the open time. After every prompted consultant in an exchange is collected or dropped, including the first exchange after a start or restart, the door reads `transcript.ts` for itself and each consultant and appends an entry with the same seat letter whenever that seat's address or transcript path changes. These lookups wait until collection finishes because the resolver's `hc get` consumes child news. An unknown path (`-`) is never recorded and never counts as the same conversation; older recorded paths stay usable for usage only. The same record keeps `spans`, one span opened when the door begins work on a chart and closed on handoff, close or hold, when the chart waits on an approval, need or prerequisite, or before switching to another chart, once every outstanding consultant turn is collected, held open while the door waits on this chart's consultants and reopened as a new span on re-entry, so only the last span may be open, the first chart's first span covers the shared opening map so the map counts once, and a record without `spans` reads as a legacy window. On a handover continuation fresh A appends its A seat entry with its transcript path and opens its first span before chart work. Outside hc the record holds the open time and no seat, and the usage table says `usage unmeasured`. The door asks the operator nothing new for this record.

The signposts round sets the session's direction: the ranked priorities, the hard limits and the order or drop of the session's charts that steer every map and every later pick. It runs once per door session, after intake import and the consultant restart and before any map, and map briefs carry its answers. One consultant exchange adds missed angles first. The latest earlier signposts record on the same repo is offered as proposed answers, which the operator answers "same" or changes. The round's light shape and its unanswered, correction and conflict rules live in questions.md, the record and copy rules in shapes.md, and who answers it in `## Autopilot`. The signposts rule applies to door sessions opened after it lands.

One needs sheet travels with the signposts round, asked once per door session covering every handed chart and completed before the first map: its rows are every foreseeable operator-only need and authorization the session's charting will require — keys, logins, files, accounts, resources and permissions, human-only actions, grants for live changes, fixture retention, secret-save and closes that need an operator decision (delivered-identity closes the door runs under Open are not rows) — answered only by the operator and never A's pick under autopilot, or "none" when empty. Rows stay pending without blocking charting: only the affected proofs and the handoff wait on them, and a pending row is never re-asked as a question. A route whose authority cannot be named by then is unavailable under the sheet. A chart added to the session after the signposts round by a changed-list yes gets its rows asked with that proposal, before its charting. The door runs a paid charting probe with `akrogon run-check --holder <absolute-chart-folder>/direct -- <argv>...`, the probe's budget inside the argv, and records the budget and its reason in the fork's `## Charting proofs` section. Handoff relies on the required proof, and has no separate budget gate.

## Drain

Show a proportional territory map before grilling, including material forks, practitioner questions and pitfalls over the work's lifetime, what each option could break or invite later and not only now, grounded in inspected surfaces; when peers are named, A and each named peer map independently before A merges with attribution, using the blind file exchange in questions; waits on consultants follow the exchange wait in questions.

A round takes one fork, the next answerable fork first, preferring the one whose answer reshapes the most remaining forks; a destination with one fork costs one round.

Propose the split by destination and speed of resolution before writing: independently checkable outcomes sharing a destination can be parallel leaves of one issue, independent issues run side by side, and only an actual dependency orders work, never file overlap or presentation preference.

Write one chart folder per destination. Rounds work one chart at a time and never mix charts: when the current chart hands off, closes, is held or waits on an asynchronous approval, need (a pending needs-sheet row included) or human-only prerequisite (a presented round or handoff review is not such a wait), the door moves on without asking for a selection to the chart the operator names, else to the first chart not waiting in the session's signposts order, else a chart whose wait has cleared, else the open chart not waiting whose CHART.md was first committed earliest, else the next seed when the door imports seeds, else the pass ends, and a dropped chart or seed named in the session's signposts is not charted this session; a chart whose forks are all taken is handed off without waiting for charts that still hold one. A move-on to a named next chart is a handover: the door appends the handover entry and resets A per [handover.md](assets/handover.md). A direct single item whose map finds no open fork and no fog writes the same chart structure and proceeds to the handoff review immediately, where the route is chosen. Under autopilot the drain takes only the handed list per [autopilot.md](assets/autopilot.md), with no oldest-chart or seed steps and nothing new imported.

## Take

Research precedes every question except the signposts round, which has no research line, and is redone when an answer reshapes one. Before a round, gather for each question the strongest source available in the tier order in questions: operator-placed material, a named practitioner, primary documentation or code, and the model's own knowledge only together with the searches that found nothing stronger. A question about this repository's own mechanism cites the inspected file and line and the documentation of the tool it calls; a question about anything outside it names an outside source or the recorded failure to find one. Research decides which questions are asked, which pitfalls the options are built to avoid and which option is recommended, never the answer, and a recommendation that contradicts a practitioner source shows the contradiction in the question.

With named peers, A owns interviewing and recording, sends only intake, current Question and carries, related fork paths, locks and verbatim operator corrections while developing its own view, then merges the completed independent notes with agreeing-slot tags such as `(A)`, `(B,C)`, `(A,B,C)`, `(A,B,C,D)`, a merge tag citing only a line the peer wrote, and obtains one disagreement-only rebuttal from each peer; A alone then writes the formatted operator round and presents it with the rebuttals under the challenge check; each peer answers direct operator requests in its own terminal and runs one focused check before A records later corrections: all mechanism or contract corrections from one operator reply (under autopilot, one pick) for one fork go into one proposed final shape with the corrections marked and are sent to every named peer, per the final-shape rule in questions; waits on consultants follow the exchange wait in questions.

Record operator answers and their reasons in fork files. After each answer, re-read Fog and move newly sharp material questions into their own fork files, removing only that material from Fog. Reshape the remaining forks and update CHART.md's ordered Open forks list before selecting and researching the next fork; handoff becomes ready only when no material question or fog requires the implementer to guess, with small optional prototypes explicitly chosen as measurements whose scratch code is discarded.

A seed decision taken under [Open](#open) is charted around, never asked again. A finding against it is a fact with evidence and a concrete consequence if the decision is built as written, at the Fix bar of check-issue `## check.review`; a simpler design, a preference, an untried alternative or a doubt is not one. The door runs no research into whether the decision is right: findings come only from work it does anyway, the map, open-fork research, Take proofs and leaf writing. A blocking finding, where the decision cannot be written or proven as decided (a named surface is gone, a done-test proof fails, the shapes audit refuses the done-test, or it clashes with a lock), is its own open fork asked as keep or change, and the door may offer the smallest change labelled the door's. Any other finding, where the decision is buildable but something real still goes wrong, goes under the decision fork's `## Findings` and is shown once as keep or change; silence keeps, and a keep is not raised again. A change is a dated correction under the decision's `## Taken`, and charting around the decision continues meanwhile. A seed decision that contradicts an earlier autopilot pick by A supersedes it: the pick stays, marked superseded, and that fork is re-answered around the decision. A round reply that contradicts a taken seed decision has the clash shown before it is recorded. Two readings apply only when the decision's text supports both and the leaf differs between them; under No autopilot the door asks one question. When the person at the door contradicts a colleague's decision, the person at the door wins, recorded as a dated correction naming both. A conflict between operator answers follows [questions](assets/questions.md), and autopilot's handling of findings and readings follows [autopilot.md](assets/autopilot.md).

Every external operation a brief names, whether API method and path, CLI command or launch flag, and every key part of a kept done-criterion — a clause whose pass rests on something existing before the leaf builds, an outside system's acceptance, an existing checker's verdict, existing data or recordings — gets one real observation run with the identity the leaf will use before handoff, by the smallest call that reaches it, free before paid — a paid call runs only through `akrogon run-check --holder <absolute-chart-folder>/direct -- <argv>...` with its budget in the argv, the budget and its reason recorded in the fork's `## Charting proofs` record. A proof counts only for the property it observed, which its `limits` records: a provider dry-run or validate call counts only for the property the provider documents it proves, run with the real identity and target, and when a decision locks a setting of an outside tool (a config key, file setting, flag or environment variable) its proof uses that same key, location and value and observes the property the decision relies on, a proof of a different form such as the CLI flag for a locked config key not counting for it. A clause needing an existing checker to accept output the leaf builds is split: its existing input or contract assumption is observed at charting, while acceptance of the new output stays the leaf's own done-criterion proof. Every observation, free ones included, is recorded in the fork with the command, inputs, identity reference without secret values, version, date, observed result, cleanup result and limits stating what the call does not prove, linked from the leaf's `proofs` records in `readiness.yaml`; writes use the smallest reversible call on a throwaway target with checked cleanup, and standing-design's cheapest-sufficient-test rule picks the call. Every operation and every key part kept in the contract needs its proof before handoff: a declined probe, or no safe sufficient one, cuts the contract to what is proven at the handoff review, naming what was cut and where it lands — a prerequisite leaf under the missing-machinery rule, an exclusion in each dependent's design, or an Off route entry — and the cut removes that proof obligation, a cut operation dropping out of the brief's What. A cut that removes the chart's useful outcome is a scope question that parks the chart for the operator under the existing approval-that-is-not-a-grant wait, never answered by A. There is no waiver: nothing unproven is handed off as promised.

As soon as a genuinely human-only prerequisite appears, show it under Pitfalls avoided as the step that removes its trap, with its owner, exact action and pending status until done, and record completion before opening a leaf or starting a direct attempt. Needs are not such a prerequisite but are anticipated, never discovered by a blocked seat: the door asks one needs sheet per door session with the signposts round before the first map (rules in `## Open`), listing every need across the session's handed charts, each with purpose, consuming leaves, exact permissions and resources, official source and date checked, destination (keys and values to the declared holder's env, files to their paths, approvals to authorization records) and what done looks like; the canonical record is `## Needs` in the session's forks/signposts.md original, one line per row with status (pending, supplied, late), re-copied verbatim to the session's charts like any correction. The operator completes rows at their own pace. Charting proceeds while rows are pending, subject to the affected proofs and handoff requirements. The door checks presence on each draft `readiness.yaml` and runs the proofs, and a failed proof yields a specific repair step; handoff stores the steps in `inputs[].steps`, so `akrogon status` prints a still-missing need and `akrogon next` refuses dispatch. The operator creates every missing outside-account key in one batch before handoff, from the door's list; a leaf that creates something with its own key stores that key itself, declared up front in `produces`, and dependents wait on it through `blocked-by`.

Each leaf's `grants` records one scoped grant during charting, covering live changes, inside the bounds the sheet's rows recorded — a field the operator was not asked to approve is not approved, and the record binds only inside what was approved — before the first covered proof and confirmed at handoff review: approval provenance; the verified principal and account with credential name and holding repo, never the value; targets by name or ID; leaf-created fixtures by account, purpose, ownership marker, naming rule and count, with created IDs linked to the leaf before change or deletion; operations including transitive helpers, checks and cleanup; explicit destructive, public, billing, DNS and retention effects; bounds; the stop line for what stays human; and lifetime. The door runs `akrogon pack <chart>` before appending `Closed`, `Held` or `Handed off` when `<chart>/direct` holds a log. After valid lifecycle handoff append `Handed off <YYYY-MM-DD>` on its own line to CHART.md, retaining the chart and source inputs in place; command dispatch remains the authority, so the handoff runs no `akrogon next` or chart phase transition and the door moves to the next chart as Drain states. The door makes and verifies a needed step on main during the pass when its precondition exists, and a waiting edit blocked on a leaf's merge or an unsourced chart follows the shapes.md records. The markers are `Handed off <YYYY-MM-DD>`, `Closed <YYYY-MM-DD>`, and `Held <YYYY-MM-DD>`, each beginning its own line, with the last marker in the file authoritative. The door runs the usage script again when it appends `Handed off`, `Held` or `Closed`.

## Direct route

The direct route is a second ending for the handoff: the door implements one small settled chart itself in a worktree, as seat A of a real leaf the command creates, B — the first named peer — reviews, and the merge queue lands it like any leaf. It needs no repo setting: the door offers it at its own discretion whenever the chart is eligible, and the operator can always decline.

Direct is not offered, and the review names the refusal in one line and the handoff goes to the lifecycle, when any of these holds:

- the draft needs `inputs`, `grants`, `produces` or `retained`;
- a done-criterion needs a live run or outside call during implementation (charting proofs do not count);
- more than one outcome or an unfinished dependency exists (door judgment);
- a human prerequisite is pending;
- B is not named;
- the door is not inside hc;
- the door is running under Semi-autopilot or Full autopilot (`## Autopilot`).

When eligible, the review asks one route question with the door's recommendation and a reply key: lifecycle or direct. The door may recommend lifecycle for a risky small job. Explicit direct authorization already given in the session is the answer. The chosen Build route, Direct or Lifecycle, is recorded in CHART.md as the `Route:` line. When direct is chosen:

1. Write `ISSUE.md` under `issues/open/<chart-slug>/` and `brief.md`, `design.md` and `readiness.yaml` under `issues/open/<chart-slug>/<slug>/`, the standalone-issue handoff shape with the chart slug as the owner. Create refuses if that owner holds another leaf or exists under `issues/closed` or `issues/parked`, or if the leaf slug is already taken by any open or closed leaf.
2. Run `akrogon direct <slug> --reviewer <B address> [--source <owner/repo#n>]...`, one `--source` per delivered identity. The command probes the caller and reviewer live, creates the unlocked worktree and writes `state.yaml` with `phase: implement` and `direct: true`, seat A the caller and seat B the reviewer, no tab. Re-running it rewrites only the two seats.
3. Implement in the worktree with `implement-issue <slug> slot=A phase=implement leaf=issues/open/<chart-slug>/<slug>`, writing `<leaf>/plan.md` and `<leaf>/implementation/report.md` in the leaf folder, and finish each implement round with `akrogon phase <slug> check.review --slot A`.
4. Send `check-issue <slug> slot=B phase=check.review leaf=<absolute leaf folder> worktree=<absolute worktree> base=<ref>` with the door's hc report line. B records the sole verdict at every round. On `fix`, the door moves from `check.repair` with `akrogon phase <slug> check.fix --slot A`, repairs with the implement-issue `check.fix` form and returns the leaf to review. After a red land exit the door may run `akrogon phase <slug> merge --slot A` if HEAD still matches the recorded red top. Other land repairs go through `check.fix` and B's re-check.
5. When `merge` starts, stay in the turn and recheck at a bounded interval. Run `akrogon next <slug>` at each check so a dead land unit relaunches. The land run verifies, pushes the default branch, closes the leaf's sources and moves the owner to `issues/closed/`. On re-entry after a lost turn, read the leaf first and resume from its recorded phase.
6. On `merged`, the command sends the broadcast task to B when the repo has a configured target. Check `akrogon status <slug>` and wait for `broadcast pending` to clear and B's broadcast turn to end before reusing or restarting B. Run `akrogon next <slug>` during the wait. If the broadcast is pending and B is gone or stays busy, run `akrogon direct <slug> --reviewer <idle consultant address>` and then `akrogon next <slug>`. If B disappears after the prompt starts, its broadcast turn has ended. Run `akrogon pack <chart>` when `<chart>/direct` holds a log, write the landed SHA into the `Direct attempt` section and append `Closed`.
7. For abandon or growth stop, `akrogon direct-drop <slug> --chart <chart folder>` stops the leaf's runs, removes the worktree and branch and moves the owner folder to `<chart>/direct/<owner>`, preserving the chart's existing captures. Drop refuses for a leaf in `merge` or `merged`, if that owner destination already exists, or from inside a run-check capture of the owner. Run `akrogon pack <chart>` when `<chart>/direct` holds a log, then append `Held` for abandon. A growth stop to the lifecycle hands off a fresh slug. A task that outgrows the route mid-pass stops the leaf `failed` under implement-issue's stop rule, and the operator chooses between these continuations.

## Autopilot

Autopilot is a non-default mode the operator switches on in words for one door session. The door session is the logical session, from the operator's first message in the door until the operator starts a new door run; it survives pass end while autopilot waits, replies, compaction and handovers to a same-session or fresh A, none of which asks the signposts again, and a chart resumed in a later door run takes that run's signposts, never a chart folder's earlier ones. In this file and its assets, "under autopilot" covers Semi-autopilot and Full autopilot together. Three modes form the Charting mode category, read from the operator's words with their scope rather than a fixed phrase: No autopilot, the default, where the operator answers the signposts and every fork; Semi-autopilot, where the operator answers the signposts once and A answers every fork after; and Full autopilot, where A answers both. Words that delegate only the signposts while the operator keeps the forks match none of the three modes, so the door asks which mode is meant.
Old record words: `manual` and `attended` read as `no autopilot`, `on autopilot` as `on semi-autopilot`, `continue attended` as `continue no autopilot`, and `autopilot signposts` as `full autopilot`. `continue autopilot` reads as `continue full autopilot` when the chart's mode record holds an earlier `on` entry recording full autopilot (`on full autopilot` or `on autopilot signposts`), and as `continue semi-autopilot` otherwise, including an earlier `on` entry with no mode word and no earlier `on` entry at all.

Semi-autopilot and Full autopilot start only from the operator's words in the door's own terminal, at door start or later naming a chart; the words carry the mode, the handed work and the consultants or none. Outside hc the door says autopilot cannot start.

Every mode change (on, off, changed list, "continue <mode value>") is appended to the mode record with its time, and the door reads the latest entry before continuing: the same A transcript path continues after compaction, while a different or unknown path starts under No autopilot until the operator says `continue <mode value>`, which resumes the same handed list with lost consultants still lost.

The door reads [autopilot.md](assets/autopilot.md) when the session's mode is Semi-autopilot or Full autopilot.

## Handover

A handover resets A's terminal into a fresh session for the next chart. It triggers when Drain moves on to a named next chart — the current chart handed off, closed, held, or waiting on an approval, need or prerequisite — after the outgoing chart's records are written, every consultant turn is collected and its span is closed; never at first entry, inside a chart, at a presented round or handoff review, after compaction, or at pass end.

Any session that receives a start prompt, before any other chart work, continues the handover only when the prompt names the live address it reads per the `## Open` door-address definition and next chart and matches the latest Mode entry, which must be an unconsumed handover, and its own transcript path from `bun <skill-folder>/scripts/transcript.ts <A address>` differs from the path on that entry; when the path is unknown (`-`) or equal to the entry's, it runs the script once more, and if that answer is the same it says `handover not continued: <unknown or same> transcript` and stops, leaving the entry unconsumed (a reset that did not happen lands the start prompt in the old conversation, which stops here). Its resume entry follows the session's mode: a session under No autopilot appends `continue no autopilot (handover <time>)`, and a session whose mode record shows Semi-autopilot or Full autopilot appends the autopilot resume entry per [autopilot.md](assets/autopilot.md). It records its A seat with its transcript path — a folder created for the handover holds no seats.yaml until fresh A writes it on entry — and opens its first span before chart work. Without that start prompt or when it does not match, a new session starts under No autopilot in no chart.

The door reads [handover.md](assets/handover.md) when Drain moves on to a named next chart.

## Printed footer

End each door pass with the actual result and reason no automatic pass follows, printed rather than saved:

```text
Last operation: <what this pass wrote or observed>
Next: none <awaiting operator answer, dispatch, or named blocker>
```

The pass that queued a handover prints `Next: none handover queued to a fresh A in <A address>`.

The footer is printed only when the turn ends, and never while a prompted peer's turn is open.
