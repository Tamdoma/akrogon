# Handover

Read when Drain moves on to a named next chart.

Old A appends the handover entry `handover <time> <log>: attended next <chart>; consultants <surviving>; signposts <path>; instructions <verbatim with provenance and scope, or none>` to the next chart's Mode record, the mode line carrying A's hc address and transcript path — the reset log path, the next chart, the surviving consultants, the path of the session's signposts record so fresh A continues with it, and every conversation-only operator instruction still in force verbatim with its provenance and scope, or `none`. When the next chart has no folder, old A creates its CHART.md, holding `pending map by fresh A (<seed path, legacy path or operator note reference>)` under Destination plus the Mode record and no INTAKE.md, plus a verbatim copy of the session's `forks/signposts.md` naming the chart that holds the original — the one added file, an exception to "creates only its CHART.md" and to the autopilot folder contents — until fresh A writes the Destination after its map. As its last action old A runs `hc run --bg --no-notify --rm --no-parent -- sh -c 'log=$1; shift; exec bun "$@" >>"$log" 2>&1' sh <log> <skill-folder>/scripts/door-reset.ts <A address> <log> "<start prompt>"` from the registered repo root and ends its turn, `<log>` being `door-reset.log` in the next chart's folder, which exists by then; the shell sends everything the helper prints, its errors included, to `<log>`, so a helper that fails before or between its stages still leaves why there. The start prompt is plain text, never a slash command (codex rejects an unknown `/` command): `Run the chart-issues skill (<absolute skill folder>/SKILL.md): continue handover <time> door <A address> next <absolute chart folder>`.

The helper waits on hc events for A's turn to end, types the reset as keys into A's terminal (`/clear` for claude and agy, `/new` for codex and pi), then sends the start prompt, pressing enter once if it sits unsubmitted; each stage logs one line to `<log>`, and a stage that fails logs its result and stops. The helper confirms nothing after the reset: its `start-prompt` line means the prompt was sent, not that the reset worked. The session that receives the start prompt is the check.

Operator input recorded in A's transcript after the helper started cancels the reset: `superseded` is logged and nothing more is sent. The helper reads the transcript once, after A's turn ended, since a submitted input is a record that stays. The input record per kind: a claude `user` entry or `queued_command` attachment with `origin.kind` `human`, a codex `task_started` or role-`user` `response_item` message, a pi role-`user` `message`, an agy user-input step (type 14) in its conversation database. Stated limit: text typed into A but not submitted is not seen.

Handover is supported for claude and agy (`/clear`), codex and pi (`/new`); every other kind and runs outside hc keep same-session behavior. Stated limit: a `/clear` or `/new` the operator types into a door or supplied consultant is not detected, so that seat's usage may count its old transcript until akrogon's next reset or restart. The modes differ only in the trigger and next-chart selection, the created folder's contents and the resume entry's name.
