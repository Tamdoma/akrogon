### Standing design lines

- Never mock auth.
- Server-side authorization on every non-public path.
- State changes as real backend mutations.
- No hardcoded secrets.
- No vanity tests.
- A test exists only as the proof of a done-criterion or as the red-first reproduction of a proven bug; a consequential negative or edge case is a done-criterion written at charting, never a case added after planning on a named consequence alone.
- End to end evidence with an artifact is required only when browser or runtime behavior or cross-component wiring cannot be shown by a smaller check or when a criterion asks for it. Browser flows use Playwright only: headless Chromium, trace on, no video, installed as a consumer-repo dev dependency by the first leaf needing it. Non-browser flows use a real request or invocation. The blocking `checks` commands judge the exit code and the implementation report records the artifact path as evidence.
- Each done-criterion is proven by the cheapest sufficient test that catches its failure, where cheapest counts creation plus upkeep; a real model or outside call can be cheapest when that behavior is under test, and a slow or live run names what no smaller test could prove. Machinery is code whose job is to run proof rather than be the product: a runner, dispatcher, session or port pool, or a fixture factory that orchestrates cases; the repo's existing test runner, fixture and cleanup helpers, and temporary repo or directory setup inside a test are not machinery. No leaf builds or extends machinery to prove its own product; machinery a leaf's proof needs and lacks is delivered by a prerequisite leaf whose product is that machinery, proven by one known-good case passing and one deliberate break failing.
- Prefer the smallest test at the real boundary (CLI, HTTP, browser, DB): unit or property tests only where logic matters and they catch bugs more cheaply, end to end only where smaller tests miss browser, runtime or wiring bugs.
- Delete a false or outdated expectation with its reason; delete a duplicate only after naming the test that still catches the same bug; judge a batch of deletions as a batch; keep every test that guards a real past regression.
- A test never keeps a hand-copied list of another file's entries (scripts, files, catalog members) to compare against; it reads that source and asserts the property that must hold, such as each entry reached once or nothing dropped since the base.
- A bug fix shows its test failing before and passing after; new behavior shows one deliberate break turning its test red; no mutation score.
- A proof with a model or outside stage runs its own scripts, consumers and checks real on the current head, while each model or outside stage replays output recorded from one real run with source, revision or date and the capture command, kept as a committed fixture or a preserved path named in the report and re-recorded never hand-patched; committing a recording is test input, while building replay support is machinery. A fresh call is made only when a model-facing input changed (prompt, instructions or templates, model pin, settings, input data, tool or provider contract, output contract), the recording is missing or unreliable, or the criterion names fresh-start, order, live-interaction or whole-run behavior, and it is the smallest fresh interaction through the real consumers that proves the property and re-records; an input whose effect on a model stage is unknown is investigated, never silently reused. A fresh call runs only under a covering grant, never as a silent fallback, and otherwise the seat takes the operator-blocker stop.
- A chain trigger is one leaf's output (data, files, state or build input) consumed by code another leaf owns: its stages follow the recorded-output rule above. The spine runs in the consumer's own suite inside the destination's full verify, a stage labelled real that fakes its result does not count, hand-written negative and edge inputs stay allowed, and no merge requires a live model run.
- A slow or live-run leaf fixes another leaf's bug in-branch only when no locked decision changes, no new feature is added and no acceptance rule changes; each such fix gets a fail-first test in the owning code's own tests. It reruns every changed stage plus every consumer of its outputs under the recorded-output rule above (shared files, lockfile and env count as inputs), runs every check whose prerequisites are valid and marks the rest blocked while the run still fails and product gates still stop the product, and groups follow-on failures under their root. Stand-ins run only in a separate diagnostic run that never counts as proof, the final proof runs its deterministic stages and consumers at the final commit over recordings still valid under that rule, and a clean full run is required only when the criterion names whole-run behavior. A live-run done-criterion uses only existing machinery and requires its sessions to run side by side, each with its own working root and log, unless the brief names the shared resource that forces them to run one after another, and a seat that finds an unnamed shared resource holds a criterion that cannot pass within the leaf and ends the pass `failed` under the existing red-criterion exit.
- Writer and checker share one rule definition: a model writer's instructions state the checker's rule, a kept second copy says why and has an agreement test, and tests keep independent expected results. A group-size-dependent check states what it needs for the target count counting what renders, and is tested at real target size with the real pool (must pass) and with a too-small pool (must get the design's refusal). A model-judged such check tests one known-acceptable and one known-unacceptable case at target size and states what stays unproven.
- Leaf work is agent-owned. A step physically requiring the operator is a human-only prerequisite completed before the leaf opens. Credential access alone never qualifies. An unforeseen physical blocker ends the attempt and informs the operator.
- Every secret including production lives in the consumer repo's gitignored .env. The operator explicitly accepts that agents can read it. No secret vault, broker, or off-machine credential pile exists.

Each leaf design names this file's installed path and writes its own interpretation of these rules.
