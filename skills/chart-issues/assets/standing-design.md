### Standing design lines

- Never mock auth.
- Server-side authorization on every non-public path.
- State changes as real backend mutations.
- No hardcoded secrets.
- No vanity tests.
- A test exists only as the proof of a done-criterion or as the red-first reproduction of a proven bug; a consequential negative or edge case is a done-criterion with one right answer written at charting, never a case added after planning on a named consequence alone.
- End to end evidence with an artifact is required only when browser or runtime behavior or cross-component wiring cannot be shown by a smaller check or when a criterion asks for it. Browser flows use Playwright only: headless Chromium, trace on, no video, installed as a consumer-repo dev dependency by the first leaf needing it. Non-browser flows use a real request or invocation. The blocking `checks` commands judge the exit code and the implementation report records the artifact path as evidence.
- Each done-criterion is proven by the cheapest sufficient test that catches its failure, where cheapest counts creation plus upkeep; a real model or outside call can be cheapest when that behavior is under test, and a slow or live run names what no smaller test could prove. This covers mechanical behavior and a model choice's record; the choice itself is read, not tested, and never buys a paid call. Machinery is code whose job is to run proof rather than be the product: a runner, dispatcher, session or port pool, or a fixture factory that orchestrates cases; the repo's existing test runner, fixture and cleanup helpers, and temporary repo or directory setup inside a test are not machinery. No leaf builds or extends machinery to prove its own product; machinery a leaf's proof needs and lacks is delivered by a prerequisite leaf whose product is that machinery, proven by one known-good case passing and one deliberate break failing.
- A script decides only what has one right answer: a file, key, state or reference exists and is valid; nothing required is blank; a value sits inside a bound whose source is named (the operator's words for this outcome, an outside standard or provider limit, a schema or literal contract); text that runs literally (a command, number, fixed reference or a marker command code parses) matches; process bounds (rounds, waves, retries, timeouts) hold; and security, spend and destructive effects stay inside their grants. A mechanical rejection always overrides a model approval. What a model is asked to decide (quality, sufficiency, relevance, similarity, wording, intent, which items apply and the like) is the model's choice: the model doing the work makes it, and when a done-criterion or next step depends on it, records the choice, its reason and the evidence it weighed in an artifact the work already writes; no count, share, similarity score, keyword or output-text match, or per-item operator stop stands in for it. Whoever proposes a script check on model output names its one-right-answer source; without one the call is the model's, and under autopilot the door's own pick never supplies that source. A number standing in for a model's choice with no named source decides nothing; a script may compute it and hand it to the model as evidence. A model-choice done-criterion says who decides, on what evidence and where the choice and reason are recorded. Its record, when it is a product artifact, takes function checks only (it exists, keys and states are valid, references resolve, the reason is not blank, never the reason's length, words or format); a record in a seat's own lifecycle file is read by the reviewing seat with no case. The choice itself takes no test, case or deliberate break holding an expected value: the reviewing seat reads it on a run the leaf makes anyway or a recording it already has, a choice never buys a paid call by itself, and the leaf states what stays unproven. A capture driver or gate advances on product state, the record's presence or the recorded choice's key value, never on model wording.
- Prefer the smallest test at the real boundary (CLI, HTTP, browser, DB): unit or property tests only where logic matters and they catch bugs more cheaply, end to end only where smaller tests miss browser, runtime or wiring bugs.
- Delete a false or outdated expectation with its reason; delete a duplicate only after naming the test that still catches the same bug; judge a batch of deletions as a batch; keep every test that guards a real past regression, though a proxy for a model's choice is a false expectation under this line even when added after a past regression.
- A test never keeps a hand-copied list of another file's entries (scripts, files, catalog members) to compare against; it reads that source and asserts the property that must hold, such as each entry reached once or nothing dropped since the base.
- A bug fix shows its test failing before and passing after; new behavior shows one deliberate break turning its test red; both apply to mechanical behavior and a choice's record, never to the choice itself; no mutation score.
- A proof with a model or outside stage runs its own scripts, consumers and checks real on the current head, while each model or outside stage replays output recorded from one real run with source, revision or date and the capture command, kept as a committed fixture or a preserved path named in the report and re-recorded never hand-patched; committing a recording is test input, while building replay support is machinery. The fresh-call trigger — when a fresh paid run is needed — lives in [skills/lifecycle-rules.md](../lifecycle-rules.md) under `## Grant reuse and paid sessions`.
- A chain trigger is one leaf's output (data, files, state or build input) consumed by code another leaf owns: its stages follow the recorded-output rule above and lifecycle-rules' fresh-call trigger. The spine runs in the consumer's own suite inside the destination's full verify, a stage labelled real that fakes its result does not count, hand-written negative and edge inputs stay allowed, and no merge requires a live model run.
- A slow or live-run leaf fixes another leaf's bug in-branch only when no locked decision changes, no new feature is added and no acceptance rule changes (a removal under the implement-issue proxy exception is not an acceptance-rule change); each such fix gets a fail-first test in the owning code's own tests. It reruns every changed stage plus every consumer of its outputs under the recorded-output rule above and lifecycle-rules' fresh-call trigger (shared files, lockfile and env count as inputs), runs every check whose prerequisites are valid and marks the rest blocked while the run still fails and product gates still stop the product, and groups follow-on failures under their root. Stand-ins run only in a separate diagnostic run that never counts as proof, the final proof runs its deterministic stages and consumers at the final commit over recordings still valid under that rule, and a clean full run is required only when the criterion names whole-run behavior. A live-run done-criterion uses only existing machinery and requires its sessions to run side by side, each with its own working root and log, unless the brief names the shared resource that forces them to run one after another, and a seat that finds an unnamed shared resource holds a criterion that cannot pass within the leaf and ends the pass `failed` under the existing red-criterion exit.
- Writer and checker of a mechanical rule share one rule definition: a model writer's instructions state the checker's rule, a kept second copy says why and has an agreement test, and tests keep independent expected results. A group-size-dependent check states what it needs for the target count counting what renders, and is tested at real target size with the real pool (must pass) and with a too-small pool (must get the design's refusal). A rule needing a model's judgment has no script checker.
- Leaf work is agent-owned. A step physically requiring the operator is a human-only prerequisite completed before the leaf opens. Credential access alone never qualifies. An unforeseen physical blocker ends the attempt and informs the operator.
- Every secret including production lives in the consumer repo's gitignored .env. The operator explicitly accepts that agents can read it. No secret vault, broker, or off-machine credential pile exists.

Each leaf design names this file's installed path and writes its own interpretation of these rules.
