# Watch issues

Operator-invoked watch over every leaf under `issues/open` of the registered repo, re-read at each fire. `<root>` is the registered repo root. All akrogon commands run with cwd `<root>`.

## Invocations

The same on every harness — claude, codex, pi and agy. The operator sends `watch-issues <root>` (claude alias `/watch-issues <root>`) to start, `watch-issues stop <root>` (claude alias `/watch-issues stop <root>`) to stop, and the watch sends its own ticks as `watch-issues tick timer=<address> pid=<pid> due=<n> <root>`. `<root>` is the registered repo root and the cwd of every akrogon command. One watch runs per repo: an hc terminal named `<prefix>-watch` in the repo's session sends one tick every 20 minutes.

- `watch-issues <root>`: run `bun <skill-folder>/scripts/start.ts <root>` and read its line. `started <address>` or `running <address>` runs the one check of `akrogon status` at `<root>` — the check still runs on a paused repo, since starting the watch is not an act on a leaf — then reports the line. `refused` or `conflict` is reported with no check, and nothing was started.
- `watch-issues tick timer=<address> pid=<pid> due=<n> <root>`: run `bun <skill-folder>/scripts/tick.ts <tick tail>` — the tail is everything after `tick`, verbatim — and read its line. `accept` runs the one check: the script already verified the timer and set its `akrogon.watch-due` receipt first. `no-watch` or `stopped` is reported and runs no check; a tick never starts or recreates a timer. A tick that is the first prompt of its conversation while a verified timer is live means a reset ended the watching conversation: it runs the stop steps below, replies with their result and runs no check, and for codex and pi `/new` this stop is attempted, not guaranteed. A compaction summary before the tick is not a reset, and another prompt after a reset before the first tick spends that chance, leaving the watch running until `watch-issues stop`. While the watcher is busy, the timer keeps the latest unsent tick. When the watcher is idle, that tick runs one check.
- `watch-issues stop <root>`: run `bun <skill-folder>/scripts/stop.ts <root>` and report its output: `stopped <timer>`, then `stopped consultant <address>` on a second line when it closed one. It works from any terminal in the session.
- A standalone `<hc from="...">` turn for a case turn already read or a closed case, and any wake matching no case, is recorded and ignored: it runs no check and opens no case.

The watch ends on `watch-issues stop`, on the watching agent's exit, on the watcher terminal finishing or changing its foreground (the timer stops itself when the terminal is reused or its transcript changes), or on a reset the harness shows. It never ends on its own otherwise. Stated limits: hc has no guarded send to a watcher showing `done`, so a prompt typed into the watcher terminal when a tick is due can receive the tick — claude and agy then run the check inside that turn, and on codex that prompt's task is dropped and must be retyped; a shell-launched agent that exits right as a tick goes out can leave the tick text in the shell, with or without a held draft (a tick hc holds behind an unfinished draft can likewise reach the shell or a program started there), and a replacement agent running this skill refuses it by the tick's `pid=`; codex and pi `/new` may leave the watch running into the new conversation.

## Observe

A check begins by running `akrogon status` at `<root>`. When it reports the repo paused (`<repo> (paused)` list mark or `paused: <name>` slug line), that check observes nothing and acts on nothing: run no observe script, `next`, `phase` or `hc` seat command, and report paused.

Run `bun <skill-folder>/scripts/observe.ts <root>` under a Bash timeout. Its first stdout line is `session=<name>`, the hc session holding the repo's space; then readable leaf lines sorted by slug, followed by `unreadable=<path> error=<message>` lines sorted by path for unreadable states, foreign-repo leaves and unreadable directories. It prints only the `session=` line when there are no readable leaves or failures. When no session can be resolved it exits non-zero, prints the refusal on stderr and no leaf lines.

`OBSERVE_AKROGON` overrides the akrogon binary for tests only.

Every `hc` command below that names a seat runs as `HC_SESSION=<name> hc ...` with the session from that line.

Line format, stable field order:

`slug=<slug> phase=<phase> attempts=A<n>,B<n> blocked=<comma-list|empty> A=<address|->/<status|->[ busy=HhMMm][ logA=<path|->] B=<address|->/<status|->[ busy=HhMMm][ logB=<path|->] notified=<seats-with-busy_notified|empty>` and for `phase=failed` either ` failed=<cause>@<phase> delivery=<value|-> reason="<reason>"` or ` failed=unknown` when no failure record exists. The address is the one state records for the seat. The status is hc's status of the terminal at that address carrying the leaf's akrogon labels: `unknown` when it reports none (hands off), `-` when no such terminal is live, it has exited or hc's keep shell replaced it. ` logA=` and ` logB=` appear only when that seat's status is `working`; the path is the transcript akrogon's resolver finds, and `-` means no usable log.

When the evidence warrants a closer look, run `HC_SESSION=<name> hc read <address>` for a `working` seat, `HC_SESSION=<name> hc read <address> --lines 80` otherwise. Read `issues/log.jsonl` filtered to this repo and slug in order for the recovery bound. Only read-only commands run under a Bash timeout; `next`/`phase` never do, and an interrupted mutation is re-read before anything else.

## Judge

Required seats by phase: plan.synthesis A, implement A, check.review A+B (B only when `fix_rounds > 0`), check.repair B, check.fix A; merge, merged and failed need none. For a direct leaf implement, check.repair, check.fix, merge and failed need A, and check.review needs B at every round; a direct seat never carries the leaf's akrogon labels, so its status reads `unknown` and the busy and steer rules below leave it alone. Unfinished means not in `done`.

- Waiting: phase is not merged or failed and at least one required unfinished seat is idle or absent. When `blocked=` names a leaf that is not merged in the readable inventory under `issues/open`, run no `akrogon next` for it: explicit `next <slug>` throws on unmerged prerequisites and `next --all` leaves it waiting on its own, so report it as waiting on that prerequisite. A `blocked=` name matching no leaf under `issues/open` is reported as a gap, never assumed merged or unmerged. Otherwise run `akrogon next <slug>`; the command guards the other seats. When several unblocked leaves wait, run `akrogon next --all` from the root instead.
- Merged still under open: read the state files beneath the leaf's top-level owner folder under `issues/open`, an issue or an epic. If any is not merged, report waiting on siblings and run no `next` for this leaf. If all are merged, run `akrogon next <slug>` once this fire, then re-observe; a failed command follows the command-error rule, and remaining under open alone is not an error. If sibling state cannot be read, report that gap rather than assume completion.
- Failed on a human prerequisite, or record is unknown: `failure.reason` names a credential, permission, operator decision or external step, or the line ends with `failed=unknown`. A reason naming a defect in another leaf's work is this class, except a reason attributing the defect to an unmerged owner, which is judged under failed-otherwise instead. This class never recovers on its own: it opens a consult case under `## Consult`, and the leaf resumes only after the case's verified fix or the consultant's evidence that the named prerequisite is met.
- Failed otherwise: re-read state first. Recover only when every required seat of `failure.phase` is idle or absent. Compute the cycle count from `issues/log.jsonl` filtered to this repo and slug in order: a `failed -> P` record whose next record for that slug is `P -> failed` is one unproductive cycle; two consecutive cycles end recovery. Missing or malformed log means unknown history, a consult trigger. When the two most recent recoveries were both unproductive, the leaf opens a consult case under `## Consult` instead of another recovery. Otherwise run `akrogon phase <slug> <failure.phase>` then `akrogon next <slug>`.
- Busy: judge every busy seat against the leaf brief. For each busy seat, `log<seat>=<path>` in the observe line runs `bun <skill-folder>/scripts/log-tail.ts <path>` and the existing loop bar is judged on those lines with `HC_SESSION=<name> hc read <address>` as secondary context; `log<seat>=-` means judge the seat from its screen and report `no log` for it; a non-zero `log-tail.ts` exit means judge the seat from its screen and report `log unreadable: <stderr message>` for it. `#<hash>` marks the same command; `old#`/`new#` mark an edit's old and new text, so an edit whose `old#`/`new#` swap is the undo; `#-` never counts as the same command; `running` means no result record yet. A read failure alone never justifies a steer, and every other seat is still judged this fire. Working normally, or waiting on a long command: no action. Act only on loop evidence (same command or edit three or more times with the same result, three or more consecutive errors, an edit-undo cycle), a concrete action outside the brief, or a hung tool with concrete evidence such as a fatal message or an exited process. This rule covers all harnesses the same way; subagents have no terminal, so judge them through the parent screen and correct them through the parent. Stop and resteer once per seat per watch. The seat's kind is the harness name in `argv` from `HC_SESSION=<name> hc get --json <address>`. Stop keys by kind: claude, pi and agy stop on `hc interrupt`. Codex is notify-only: it moves a long command to a background terminal, `hc interrupt` prints `outcome` `still_working`, and a second `esc` leaves hc status `working` with the screen showing `■ Conversation interrupted` and `1 background terminal running`. A kind not listed, or a seat whose `reported` is `false`, gets `HC_SESSION=<name> hc keys <address> esc` then `HC_SESSION=<name> hc wait <address> --timeout 10`; a listed kind gets `HC_SESSION=<name> hc interrupt <address> --json`, which must print `outcome` `stopped`. Then confirm all of these with `hc get --json` and `hc read`: status `idle` or `done`, the same address, `labels."akrogon.transcript"` equal to the `log<seat>=` path judged, and an empty input line. Any failed confirmation, a notify-only kind or a `log<seat>=-` seat means notify instead of prompting. Then send one corrective prompt with `HC_SESSION=<name> hc send --json <address> "<evidence>; the brief wants <target>; next: <step>"`, notifying instead when it prints `started: false`, naming the evidence, the brief target, the next step, and a looping subagent by name so the parent corrects it with its own controls. The existing akrogon pass re-prompts the phase itself. A mid-turn steer without the stop may be tried first only when the screen shows tools completing. Text typed but not submitted may not show on the screen, so the empty-input check cannot see it. The same seat still looping on the next fire is notified with the evidence, never stopped a second time. Insufficient evidence on screen is reported as such with no action.
- Command error from `next` or `phase`: run the observe script again, report the error, and take no further mutation this fire.

## Consult

A check that meets a consult trigger opens a case for it, one case per root cause, worked one at a time inside the check's turn, with at most one consultant live per watch.

- Trigger: a leaf in `phase=failed` that the Judge's rules only notify on — the human-prerequisite or defect class, `failed=unknown`, a missing or malformed `issues/log.jsonl`, or the two-cycle recovery cap. A `merge -> check.fix` bounce alone never triggers. Pick the anchor: a failed leaf, an unblocked one first, never one whose `blocked=` prerequisite is failed. Other failed leaves attach to the case only when the same defect explains each; the grouping and its reason are recorded in the case. After a verified fix the watch re-observes: a leaf still `failed` stays in the same case unless a different cause is found, which opens a new case.
- Signature gate: before opening a case, run `bun <skill-folder>/scripts/consults.ts match <root> --anchor <slug|unknown> --cause <cause|unknown> --phase <phase|unknown> --command <failing command|-> --leaf <slug>...` — for `failed=unknown` that is `--anchor unknown --cause unknown --phase unknown --command '-'` with the leaf still in `--leaf`. Fetch the remote first; the script compares the anchor's signature (cause@phase, failing command, `<remote>/<default_branch>` tip, each leaf's HEAD) against recorded cases. `closed <dir>` means the identical signature already closed a case: open no new one while it is unchanged, report the recorded case and leave the leaf `failed`; after the signature changes, the watch judges whether the change bears on the recorded blocker and records the reason before a new case opens. `open <dir>` rejoins that case: continue its exchange when its consultant is live, else start one on it. `clear` opens a new case with `bun <skill-folder>/scripts/consults.ts new <root> <same flags>`, which prints the case folder `<stateHome>/watch/<repo>/consults/<case-id>` under the run's `AKROGON_HOME` or `~/.akrogon`, outside the watched repo. `bun <skill-folder>/scripts/consults.ts dir <root>` prints the cases root and refuses with `inside the watched repo` when it resolves under `<root>`; a refusal is reported and opens nothing.
- Open: write the case's `brief.md` from `<skill-folder>/consultant-brief.md` carrying this watcher's literal hc address, the case ID, the anchor and attached leaves with their observe lines and artifact paths (state.yaml, brief, design, review-B.md, worktree, verify log), the operator stop list and the locks, never `.env` values. Write `case.md` for people and `status` `open` before the consultant starts; the record opens before any work is authorized. Run `bun <skill-folder>/scripts/consults.ts start <root> <timer-address> "<task pointing at brief.md>"` for every launch, using the timer address from start or the tick. It runs `akrogon seat --watch-consultant --task <task>` under the same lock as `stop.ts` and prints the consultant's address. The consultant is a child of the watcher named `<prefix>-watch-consult`. A `stopped <timer-address>` result ends work on the case under Stop mid-case. Any other failed or unconfirmed start keeps the case open; the next tick starts a fresh consultant on it, and one non-attention notice per case says so.
- Exchange: the start task only points at `brief.md`; every later message either way is `hc send`. The watch writes `turn-<n>-watch.md` in the case before each send and the consultant writes `turn-<n>-consultant.md` before its own, `n` from 1, each file written before the `hc send` that names it. A message's sender is hc's `from`: the wait JSON `from` on a `reason: message` wake, or, when the wait returned first for another reason such as `children`, the address in the `<hc from="<address> <name>">` tag the message arrives in as the next input; it is never taken from the message text, and a message with no `from` is the operator's. The watch answers every consultant turn with its own turn file and send before acting on it: its agreement with the root cause, the fix and the resume target, or its question or disagreement. A case ends on a verified fix only once a watch turn file records that agreement.
- Wait: inside the same turn, loop `HC_SESSION=<name> hc wait <watcher-address> --children any --timeout 180 --json` with no give-up. Use the same literal watcher address as in the case brief. The consultant's state is read only from the wait JSON, never `hc get` between waits — a parent's read swallows the child's news, so the next wait would sleep through its stop. A wake from the consultant reads the next expected turn file. A wake carrying operator words is the operator's: it is handled first and wins, an explicit stop included. Any other wake is recorded and ignored. A timeout is a check-in: re-read each child in the JSON and wait again.
- Liveness: a consultant that stopped without its expected turn file gets one `hc send` nudge naming the missing file. A second silent stop, or an error, an exit or `blocked` in the wait JSON — its dialog is never answered — closes it: save its screen to the case, `hc kill` then `hc rm`. Before a replacement starts, reconcile the worktree, the remote tip and the leaf states, record what was already done and carry it in the replacement's brief. At most one replacement per case per tick, and only while the timer child is live in the wait JSON; a failing replacement keeps the case open, the next tick starts a fresh consultant on it, and one non-attention notice per case says so.
- Stop mid-case: the timer child showing exited in the wait JSON, or operator stop words in a wake, ends the case work at once: close the consultant first with `hc kill` + `hc rm`, its screen saved, then read and record the remote tip and the leaf states; no successor starts.
- Fix authority and proof: the consultant fixes the base in a detached worktree under `<case>/worktree` taken from freshly fetched `<remote>/<default_branch>`, commits only the base repair, proves it by the failing command, the repo's `checks` and its `merge_checks` — run as `akrogon verify --holder <case>` with the case worktree as cwd — and pushes `HEAD:refs/heads/<default_branch>` fast-forward only, never `--force`, never in the repo root. A non-fast-forward refusal fetches, accepts the new base when it already fixes the failure, else rebases, re-proves and pushes again, each attempt re-proven with no fixed count. In a leaf worktree the consultant commits only while every seat of that leaf is idle or absent and the worktree is clean on entry, inside the leaf's decided brief and design; uncommitted seat work is kept, never discarded, and the consultant does not commit there — it advises, and the leaf resumes for its own seat. A fix stands when the failing command, `checks` and `merge_checks` pass on the fix tree, the push is fast-forward and no stop-list line is crossed.
- Loop end: a case ends on a verified fix, a stop-list need, or no permitted check left. For a disagreement, run the smallest permitted check that tells the two predictions apart. If no permitted check remains, record why and both views when they differ. Leave the leaf `failed` and send one non-attention notice naming the case. If a stop-list need ends the case, leave the leaf `failed` and send one attention notice naming the case and the specific stop. A leaf that leaves `failed` by the operator's own action closes its case, and `case.md` says it was resumed. At case end, save the consultant's screen, then run `hc kill` and `hc rm` before resuming any leaf or sending the case's notices. Tolerate not_found. Run the resume below when applicable, then end the case with `bun <skill-folder>/scripts/consults.ts close <root> <case>`, the only way to end one, never a hand-written `status`: it runs `git worktree remove` on each worktree under the case, trims the folder to `case.md`, `signature.json`, `status` and the turn files, and writes `closed`. When git refuses a removal for modified or untracked files, it exits non-zero, deletes nothing more and leaves `status` `open`: the case is not ended, so keep or commit that work and run `close` again. Send the notices and reply with the case path.
- Resume: after a verified fix, the consultant's evidence the named prerequisite is met, or advice handing the work back to the leaf's own seat, close the consultant under Loop end, then re-observe; when every required seat of the target is idle or absent run `akrogon phase <slug> <target>` then `akrogon next <slug>`. The target is `check.fix` when `failure.phase` is `merge`, `check.repair` or `check.review` — `check.review` is never a direct target — else `failure.phase`. For `failed=unknown` the target is the `from` of the last `P -> failed` record in `issues/log.jsonl`; with none, the watch and consultant pick it from the leaf's artifacts and record why, or the case closes with signature `unknown` and one non-attention notice.
- Record: the case folder is the record, kept after the case: `case.md` for people with `signature.json` and `status` (`open`, `closed`) machine-readable beside it, `status` written by `close` after the opening `open`. Send one non-attention `akrogon notice` per push to main and per leaf move. Every notice runs as `akrogon notice --title "<case-id>: <what happened>" --body "<case path and detail>"`. Add `--attention` only for a stop-list need. A case writes no rows in `issues/log.jsonl`.

## Never

- Kill an agent process.
- Kill or remove an hc terminal — allowed only for the verified watch timer on `watch-issues stop` and when a tick's `pid=` mismatches.
- Kill and remove the watch's own verified consultant — except under the `## Consult` liveness, stop and end rules.
- Stop one seat twice per watch.
- Use `hc send --force`.
- Run `phase failed`.
- Edit `state.yaml`, worktrees or `issues/`.
- Open `.env`.
- Answer a leaf seat.
- Put a Bash timeout on `next`/`phase`.

## Reply

Reply with at most five lines per fire, naming what was seen and what was done; a case the fire opened, rejoined, worked or closed names its case folder path.
